# EDB*Wrap 핵심 개념 (EDB*Wrap key concepts) — EPAS 18

> 원문: [EPAS v18 — Security guide › Protecting proprietary source code › EDB*Wrap key concepts](https://www.enterprisedb.com/docs/epas/latest/epas_security_guide/03_edb_wrap/edb_wrap_key_concepts/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 유틸리티명·명령·코드는 원문 그대로 보존했습니다.

EDB*Wrap 프로그램은 SPL 또는 PL/pgSQL 소스 코드를 담은 평문(plaintext) 파일을, 거의 읽을 수 없는 형태의 동일한 코드를 담은 파일로 변환합니다. 코드의 난독화된 형태를 얻으면 그 코드를 PostgreSQL 서버로 보낼 수 있으며, 서버는 이러한 프로그램을 난독화된 형태로 저장합니다. EDB*Wrap이 코드를 가리기는 하지만, 테이블 정의는 여전히 노출됩니다.

래핑(wrap)하는 모든 것은 난독화된 형태로 저장됩니다. 전체 패키지를 래핑하면 패키지 본문(body) 소스뿐 아니라, 패키지 헤더에 포함된 프로토타입과 패키지 본문에 포함된 함수·프로시저도 난독화된 형태로 저장됩니다.

`CREATE PACKAGE` 구문을 래핑하면 다른 개발자에게 패키지 API를 숨기게 됩니다. 사용자가 패키지 본문에 정의된 패키지 프로토타입과 기타 공용 변수를 볼 수 있도록, 패키지 본문은 래핑하되 패키지 헤더는 래핑하지 않으려고 할 수 있습니다. 패키지가 포함하는 프로토타입을 사용자가 볼 수 있게 하려면, `edbwrap` 입력 파일에서 `CREATE PACKAGE` 구문은 생략하고 `CREATE PACKAGE BODY` 구문만 EDBWrap으로 난독화합니다. 패키지 헤더 소스는 평문으로 저장되고, 패키지 본문 소스와 패키지 함수·프로시저는 난독화됩니다.

![image](https://www.enterprisedb.com/docs/static/cd437e0a071f0500168dccb928a2fcf3/87254/epas_tools_utility_edb_wrap.png)

래핑된 소스 코드와 프로그램은 언래핑(unwrap)하거나 디버그할 수 없습니다. 리버스 엔지니어링은 가능하지만 매우 어렵습니다.

전체 소스 파일이 하나의 단위로 래핑됩니다. 래핑된 파일에 포함된 모든 `psql` 메타 명령(meta-command)은 파일이 실행될 때 인식되지 않습니다. psql 메타 명령을 포함하는 난독화된 파일을 실행하면 구문 오류가 발생합니다. `edbwrap`은 SQL 소스 코드를 검증하지 않습니다. 평문 형태에 구문 오류가 있어도 `edbwrap`은 이를 보고하지 않습니다. 대신 난독화된 형태를 실행하려고 할 때 서버가 오류를 보고하고 전체 파일을 중단합니다.
