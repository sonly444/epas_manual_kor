# 소스 코드 난독화 (Obfuscating source code) — EPAS 18

> 원문: [EPAS v18 — Security guide › Protecting proprietary source code › Obfuscating source code](https://www.enterprisedb.com/docs/epas/latest/epas_security_guide/03_edb_wrap/obfuscating_source_code/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·옵션·SQL·코드·출력은 원문 그대로 보존했습니다.

EDB*Wrap은 단일 입력 소스 파일을 받아 그 내용을 난독화하고 단일 출력 파일을 반환하는 명령줄 유틸리티입니다. `edbwrap` 유틸리티를 호출할 때는 난독화할 소스 코드를 담은 파일의 이름을 제공해야 합니다. `edbwrap`이 코드의 난독화된 형태를 쓸 파일의 이름도 지정할 수 있습니다.

## 명령줄 스타일 개요 (Overview of the command-line styles)

`edbwrap`은 세 가지 서로 다른 명령줄 스타일을 제공합니다. 첫 번째 스타일은 Oracle의 `wrap` 유틸리티와 호환됩니다.

```shell
edbwrap iname=<input_file> [oname=<output_file>]
```

`iname=input_file` 인수는 입력 파일의 이름을 지정합니다. `input_file`에 확장자가 없으면 `edbwrap`은 `input_file.sql`이라는 파일을 검색합니다.

선택적 `oname=output_file` 인수는 출력 파일의 이름을 지정합니다. `output_file`에 확장자가 없으면 `edbwrap`은 이름에 `.plb`를 추가합니다.

출력 파일 이름을 지정하지 않으면 `edbwrap`은 입력 파일 이름에서 파생된 이름의 파일에 씁니다. `edbwrap`은 입력 파일 이름에서 접미사(일반적으로 `.sql`)를 제거하고 `.plb`를 추가합니다.

`edbwrap`은 다른 두 가지 명령줄 스타일도 제공합니다.

```shell
edbwrap --iname <input_file> [--oname <output_file>]
edbwrap -i <input_file> [-o <output_file>]
```

명령줄 스타일을 혼합하여 사용할 수 있습니다. 입력 및 출력 파일 이름을 파생하는 규칙은 사용하는 스타일과 관계없이 동일합니다.

`edbwrap`이 난독화된 코드를 담은 파일을 생성하면, 일반적으로 `edb-psql`과 같은 클라이언트 애플리케이션을 사용하여 그 파일을 PostgreSQL 서버에 입력합니다. 서버는 난독화된 코드를 한 줄씩 실행하고 SPL 및 PL/pgSQL 프로그램의 소스 코드를 래핑된 형태로 저장합니다.

요약하면, EDB*Wrap으로 코드를 난독화하려면 다음과 같이 합니다.

1. 소스 코드 파일을 생성합니다.
2. EDB*Wrap을 호출하여 코드를 난독화합니다.
3. 평문 형태인 것처럼 파일을 가져옵니다(import).

## 소스 코드 파일 생성 (Creating the source code file)

EDB*Wrap 유틸리티를 사용하기 위해, `list_emp` 프로시저의 소스 코드를 평문 형태로 생성합니다.

```sql
[bash] cat listemp.sql
CREATE OR REPLACE PROCEDURE list_emp
IS
     v_empno         NUMBER(4);
     v_ename         VARCHAR2(10);
     CURSOR emp_cur IS
         SELECT empno, ename FROM emp ORDER BY empno;
BEGIN
     OPEN emp_cur;
     DBMS_OUTPUT.PUT_LINE('EMPNO    ENAME');
     DBMS_OUTPUT.PUT_LINE('-----    -------');
     LOOP
         FETCH emp_cur INTO v_empno, v_ename;
         EXIT WHEN emp_cur%NOTFOUND;
         DBMS_OUTPUT.PUT_LINE(v_empno || '     ' || v_ename);
     END LOOP;
     CLOSE emp_cur;
END;
/
```

`edb-psql`과 같은 클라이언트 애플리케이션으로 `list_emp` 프로시저를 가져옵니다.

```sql
[bash] edb-psql edb
Welcome to edb-psql 8.4.3.2, the EnterpriseDB interactive terminal.
Type:  \copyright for distribution terms
       \h for help with SQL commands
       \? for help with edb-psql commands
       \g or terminate with semicolon to execute query
       \q to quit

edb=# \i listemp.sql
CREATE PROCEDURE
```

`pg_proc` 시스템 테이블을 검사하여 서버에 저장된 평문 소스 코드를 봅니다.

```sql
edb=# SELECT prosrc FROM pg_proc WHERE proname = 'list_emp';
__EDBwrapped__
                             prosrc
--------------------------------------------------------------

     v_empno         NUMBER(4);
      v_ename         VARCHAR2(10);
      CURSOR emp_cur IS
          SELECT empno, ename FROM emp ORDER BY empno;
  BEGIN
      OPEN emp_cur;
      DBMS_OUTPUT.PUT_LINE('EMPNO    ENAME');
      DBMS_OUTPUT.PUT_LINE('-----    -------');
      LOOP
          FETCH emp_cur INTO v_empno, v_ename;
          EXIT WHEN emp_cur%NOTFOUND;
          DBMS_OUTPUT.PUT_LINE(v_empno || '     ' || v_ename);
      END LOOP;
      CLOSE emp_cur;
  END
(1 row)

edb=# quit
```

## EDB*Wrap 호출 (Invoking EDB*Wrap)

EDB*Wrap으로 평문 파일을 난독화합니다.

```shell
[bash] edbwrap -i listemp.sql
EDB*Wrap Utility: Release 8.4.3.2

Copyright (c) 2004-2021 EnterpriseDB Corporation.  All Rights Reserved.

Using encoding UTF8 for input
Processing listemp.sql to listemp.plb

Examining the contents of the output file (listemp.plb) file reveals
that the code is obfuscated:

[bash] cat listemp.plb
$__EDBwrapped__$
```

래핑된 파일의 두 번째 줄에는 인코딩 이름이 포함됩니다. 이 경우 인코딩은 UTF8입니다. 파일을 난독화할 때 `edbwrap`은 로케일(locale)을 검사하여 입력 파일의 인코딩을 추론합니다. 예를 들어 로케일이 `en_US.utf8`로 설정된 상태에서 `edbwrap`을 실행하면, `edbwrap`은 입력 파일이 UTF8로 인코딩되었다고 가정합니다. `edbwrap`을 실행한 후에는 반드시 출력 파일을 검사하십시오. 래핑된 파일에 포함된 로케일이 입력 파일의 인코딩과 일치하지 않으면, 로케일을 변경하고 입력 파일을 다시 래핑하십시오.

## 난독화된 코드를 PostgreSQL 서버로 가져오기 (Importing the obfuscated code to the PostgreSQL server)

평문 코드에 사용하는 것과 동일한 도구를 사용하여 난독화된 코드를 PostgreSQL 서버로 가져올 수 있습니다.

```sql
[bash] edb-psql edb
Welcome to edb-psql 8.4.3.2, the EnterpriseDB interactive terminal.
Type:  \copyright for distribution terms
       \h for help with SQL commands
       \? for help with edb-psql commands
       \g or terminate with semicolon to execute query
       \q to quit

edb=# \i listemp.plb
CREATE PROCEDURE
```

pg_proc 시스템 테이블에는 난독화된 코드가 포함됩니다.

```text
edb=# SELECT prosrc FROM pg_proc WHERE proname = 'list_emp';
```

`pg_dump`를 사용하여 데이터베이스를 백업할 때, 래핑된 프로그램은 아카이브 파일에서 난독화된 상태로 유지됩니다.

Postgres 서버가 생성하는 감사 로그는 래핑된 프로그램을 평문 형태로 표시한다는 점에 유의하십시오. 프로그램이 실행될 때 생성되는 SQL 오류 메시지에서도 소스 코드가 평문으로 표시됩니다.

> **참고**
> 다음 구문으로 생성된 객체의 본문은 난독화된 형태로 저장되지 않습니다.
>
> ```sql
> CREATE [OR REPLACE] TYPE type_name AS OBJECT
> CREATE [OR REPLACE] TYPE type_name UNDER type_name
> CREATE [OR REPLACE] TYPE BODY type_name
> ```
