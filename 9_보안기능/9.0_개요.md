# 보안 기능 구현 (Implementing Security Features) — EDB Postgres Advanced Server 18

> 원문: [EPAS v18 Documentation — Implementing security features](https://www.enterprisedb.com/docs/epas/latest/epas_security_guide/)
> EPAS v18 공식 문서의 한글 번역입니다. 기능·파라미터·명령·함수 이름은 원문 그대로 보존했습니다.
> ※ 본 섹션은 GS 인증 보안 항목의 근거 문서로 활용됩니다.

EPAS가 오픈소스 PostgreSQL 보안 위에 추가로 제공하는 기능들입니다. 하위 구성: 투명 데이터 암호화(TDE) / EDB 감사 로깅 / SQL 인젝션 방어(SQL/Protect) / SSL 인증서 생성(sslutils) / 소스 코드 보호(EDB\*Wrap) / 사용자 프로필 관리 / 데이터 마스킹(Data Redaction) / 데이터 접근 제어(Virtual Private Database).

---

## 1. 투명 데이터 암호화 (Transparent Data Encryption, TDE)

데이터베이스의 기저 파일(underlying files)을 암호화합니다. 개별 테이블스페이스와 로그가 각각 자체 키로 암호화됩니다.

- **주요 이점**: 애플리케이션 변경이나 접근 정책 수정 없이 투명하게 동작, 최소한의 성능 오버헤드, 추가 저장 용량 불필요, 관리 편의성 유지.
- **지원 버전**: EDB Postgres Advanced Server 및 EDB Postgres Extended Server 15 이상. 고가용성(HA) 배포와 호환.
- **키 관리**: 암호화 활성화·암호화 파일 관리의 기술 세부는 전용 [TDE 문서](https://www.enterprisedb.com/docs/tde/latest/)에서 다룸.

> 참고: TDE 활성화 시, 데이터 암호화 보장을 위해 EDB\*Loader의 직접 경로 로딩(direct path loading)이 방지됩니다(릴리스 18.4).

---

## 2. EDB 감사 로깅 (EDB Audit Logging)

데이터베이스·보안 관리자, 감사자, 운영자가 데이터베이스 활동을 추적·분석할 수 있게 감사 로그 파일을 생성합니다.

기록 대상(예): 데이터베이스 연결 수립, 데이터베이스 객체의 생성·수정·삭제, 인증 실패 시도.

- **구성 위치**: `postgresql.conf` 또는 `postgresql.auto.conf`.
- **주요 파라미터**:
  - `edb_audit`: 감사 로깅 활성화 및 로그 형식 지정(`none`/`csv`/`xml`).
  - `edb_audit_statement`: 감사할 SQL 구문 유형 지정.
  - `edb_audit_connect` / `edb_audit_disconnect`: 연결/연결 종료 감사.
  - `edb_audit_destination`: 로그 대상(파일/syslog).
  - `edb_audit_directory`: 로그 디렉터리.
  - `edb_audit_nested_statements`: 함수·프로시저 내부에서 실행되는 중첩 구문까지 감사(18.1 추가).
  - `edb_audit_tag`: 감사 로그에 태그 부착.
- **부가 기능**: 오류 코드·명령 태그를 이용한 필터링, 로그 내 비밀번호 마스킹(password redaction), Audit Archiver를 통한 로그 관리. `COPY` 명령 로깅 및 카탈로그 테이블 감사도 지원(18.1).

## 3. SQL 인젝션 공격 방어 (SQL/Protect)

들어오는 쿼리를 검사하여 흔한 SQL 인젝션 프로파일을 탐지합니다. 방어 책임을 애플리케이션 개발자에서 DBA로 옮기는, 표준 정책을 넘어서는 보조 보안 계층입니다.

- 위험 쿼리 탐지, 악성 인젝션 시도 차단.
- 보호 대상 역할(protected roles)을 지정하며, 모니터링(passive)·능동(active) 모드로 동작.
- 관련 확장·뷰: `edb_sql_protect` (구성·상태 조회). 하위 구성: SQL/Protect 개요, 구성, 유지 관리, 백업·복원.
- 탐지 유형(일반): 미승인 릴레이션 접근, 유틸리티 명령, SQL 항진명제(tautology), 무한정 DML 등.

## 4. SSL 인증서 생성 (sslutils)

EDB Postgres Enterprise Manager 서버가 사용할 SSL 인증서 생성 함수를 제공하는 확장입니다. 설치 패키지: `edb-as<xx>-server-sslutils` RPM(`<xx>`는 EPAS 버전).

제공 함수:
- `openssl_rsa_generate_key`: 비트 길이 정수를 받아 RSA 개인 키 생성.
- `openssl_rsa_key_to_csr`: RSA 키 파일명·common name·country·state·city·organization unit·email 등 7개 텍스트 파라미터로 CSR 생성.
- `openssl_csr_to_crt`: CSR과 선택적 CA 자격증명(텍스트 3개)으로 자체 서명 인증서 또는 CA 인증서 생성.
- `openssl_rsa_generate_crl`: CA 인증서·개인 키 경로(텍스트 2개)로 기본 CRL(인증서 폐기 목록) 생성.

## 5. 독점 소스 코드 보호 (EDB\*Wrap)

함수, 저장 프로시저, 트리거, 패키지의 SPL 소스 코드를 난독화하여 무단 열람으로부터 보호합니다.

- **명령**: `edbwrap` 유틸리티. 배포 전에 코드를 래핑하며, 래핑된 코드는 일반 SPL 객체처럼 데이터베이스 내에서 정상 실행됩니다.
- 세부는 "Obfuscating source code" 절 참조.

---

## 6. 사용자 프로필 관리 (Managing user profiles)

슈퍼유저가 명명된 **프로필(profile)** 을 생성하여 사용자의 데이터베이스 접근 제한(비밀번호 정책 등)을 정의합니다. `CREATE PROFILE` / `ALTER PROFILE` / `DROP PROFILE` 로 관리하고, 역할에 연결합니다.

주요 프로필 파라미터(비밀번호·계정 정책):
- `FAILED_LOGIN_ATTEMPTS`: 계정 잠금 전 허용 로그인 실패 횟수.
- `PASSWORD_LOCK_TIME`: 잠금 유지 기간.
- `PASSWORD_LIFE_TIME`: 비밀번호 유효 기간.
- `PASSWORD_GRACE_TIME`: 만료 후 유예 기간.
- `PASSWORD_REUSE_TIME` / `PASSWORD_REUSE_MAX`: 비밀번호 재사용 제한(기간/횟수).
- `PASSWORD_VERIFY_FUNCTION`: 비밀번호 복잡도 검증 함수 지정.
- `PASSWORD_ALLOW_HASHED`: 해시된 비밀번호 허용 여부.
- `INACTIVE_ACCOUNT_TIME`: 지정 일수 동안 미로그인 시 계정 자동 잠금(18.1 추가).

관련 작업: 프로필 생성/변경/삭제, 기존 역할에 프로필 연결, 잠긴 계정 해제(`ALTER USER`/`ALTER ROLE`), 프로필과 함께 새 역할 생성, 프로필 관리 함수 백업.

---

## 7. 데이터 마스킹 (Data Redaction)

특정 사용자에게 표시되는 시점에 민감 데이터를 동적으로 변경(마스킹)하여 노출을 제한합니다. 저장된 데이터 자체는 변경되지 않고, 표시 계층에서만 접근 수준에 따라 마스킹됩니다.

- **정책 관리**: `CREATE REDACTION POLICY`(생성), `ALTER REDACTION POLICY`(수정), `DROP REDACTION POLICY`(삭제). 특정 테이블 컬럼과 대상 역할·조건에 적용.
- **시스템 카탈로그**: 활성 정책을 추적·관리하는 데이터 마스킹 카탈로그 제공.
- **활용 예**: 주민번호 등 PII, 신용카드·금융 데이터, 독점 비즈니스 정보 보호, 공유 데이터베이스의 역할 기반 데이터 가시성 제어.

---

## 8. 데이터 접근 제어 (Virtual Private Database, VPD)

보안 정책으로 정의된 특정 행(row) 단위까지 세분화된 접근 제어(행 수준 보안)를 제공합니다.

- **정책 함수(Policy Functions)**: 특정 입력 파라미터·반환값을 갖는 SPL 함수로 보안 정책을 인코딩. SQL·PL/pgSQL·SPL로 작성 가능.
- **DBMS_RLS 패키지**: 정책 생성·삭제·활성화·비활성화 프로시저 제공.
- **핵심 이점**: 객체 수준 `GRANT`을 넘어서는 행 수준 접근 제어, `INSERT`/`UPDATE`/`DELETE`/`SELECT` 명령별 동적 정책, 애플리케이션 코드 수정 없는 투명한 강제 적용. `EXEMPT ACCESS POLICY` 권한을 부여받지 않는 한 슈퍼유저도 정책을 우회할 수 없음.
- **적용 범위**: 테이블(뷰·시노님에도 정책 적용 가능).
