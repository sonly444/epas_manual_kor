# 공통 유지 관리 작업 (Common maintenance operations) — EPAS 18

> 원문: [EPAS v18 — Security guide › Protecting against SQL injection attacks › Common maintenance operations](https://www.enterprisedb.com/docs/epas/latest/epas_security_guide/02_protecting_against_sql_injection_attacks/03_common_maintenance_operations/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 함수·컬럼·SQL·출력은 원문 그대로 보존했습니다.

이 작업을 수행하려면 슈퍼유저로 연결되어 있어야 합니다. 검색 경로에 `sqlprotect` 스키마를 포함하십시오.

## 보호된 역할 목록에 역할 추가 (Adding a role to the protected roles list)

보호된 역할 목록에 역할을 추가합니다. 이 예처럼 `protect_role('rolename')`을 실행합니다.

```sql
edb=# SELECT protect_role('newuser');
```

출력

```text
 protect_role
--------------
(1 row)
```

## 보호된 역할 목록에서 역할 제거 (Removing a role from the protected roles list)

보호된 역할 목록에서 역할을 제거하려면 다음 함수 중 하나를 사용합니다.

```sql
unprotect_role('rolename')

unprotect_role(roleoid)
```

OID를 사용하는 함수 변형은, 역할을 보호된 역할 목록에서 제거하기 전에 `DROP ROLE` 또는 `DROP USER` SQL 구문으로 역할을 제거한 경우에 유용합니다. SQL/Protect 릴레이션에 대한 쿼리가 사용자 이름으로 `unknown (OID=16458)`과 같은 값을 반환하면, `unprotect_role(roleoid)` 형식의 함수를 사용하여 삭제된 역할의 항목을 보호된 역할 목록에서 제거합니다.

이 함수들을 사용하여 역할을 제거하면 역할의 보호된 릴레이션 목록도 함께 제거됩니다.

제거된 역할의 통계를 삭제하려면 아래 "통계 삭제"의 `drop_stats` 함수를 사용합니다.

제거된 역할의 위반 쿼리를 삭제하려면 아래 "위반 쿼리 삭제"의 `drop_queries` 함수를 사용합니다.

이 예는 `unprotect_role` 함수를 보여줍니다.

```sql
edb=# SELECT unprotect_role('newuser');
```

출력

```text
 unprotect_role
----------------
(1 row)
```

또는 OID `16693`을 지정하여 역할을 제거할 수 있습니다.

```sql
edb=# SELECT unprotect_role(16693);
```

출력

```text
 unprotect_role
----------------
(1 row)
```

## 역할의 보호 유형 설정 (Setting the types of protection for a role)

역할이 특정 유형의 SQL 인젝션 공격으로부터 보호되는지 여부를 변경할 수 있습니다.

역할에 대한 보호를 활성화 또는 비활성화하려는 SQL 인젝션 공격 유형에 해당하는 `edb_sql_protect`의 컬럼 Boolean 값을 변경합니다.

`edb_sql_protect`를 업데이트하는 구문의 `WHERE` 절에서 다음 컬럼을 반드시 한정하십시오.

- **dbid.** 변경을 수행하는 데이터베이스의 OID.
- **roleid.** Boolean 설정을 변경하는 역할의 OID.

예를 들어 특정 역할이 유틸리티 명령을 발행할 수 있도록 하려면 `allow_utility_cmds` 컬럼을 업데이트합니다.

```sql
UPDATE edb_sql_protect SET allow_utility_cmds = TRUE WHERE dbid =
13917 AND roleid = 16671;
```

`edb_sql_protect` 또는 `list_protected_users`를 쿼리하여 변경이 이루어졌는지 확인할 수 있습니다. 다음 쿼리에서 `allow_utility_cmds` 컬럼이 이제 `t`를 포함하는 점에 유의하십시오.

```sql
edb=# SELECT dbid, roleid, allow_utility_cmds FROM edb_sql_protect;
```

출력

```text
 dbid   | roleid | allow_utility_cmds
--------+--------+--------------------
 13917  | 16671  | t
(1 row)
```

업데이트된 규칙은 변경 이후 역할이 시작한 새 세션에 적용됩니다.

## 보호된 릴레이션 목록에서 릴레이션 제거 (Removing a relation from the protected relations list)

SQL/Protect가 특정 역할에 대해 특정 릴레이션이 접근 가능함을 학습한 경우, 나중에 그 릴레이션을 역할의 보호된 릴레이션 목록에서 제거할 수 있습니다.

다음 함수 중 하나를 사용하여 `edb_sql_protect_rel` 테이블에서 항목을 삭제합니다.

```sql
unprotect_rel('rolename', 'relname')
unprotect_rel('rolename', 'schema', 'relname')
unprotect_rel(roleoid, reloid)
```

`relname`으로 지정된 릴레이션이 현재 검색 경로에 없으면, 두 번째 함수 형식을 사용하여 릴레이션의 스키마를 지정합니다.

세 번째 함수 형식은 텍스트 이름 대신 역할과 릴레이션의 OID를 각각 지정할 수 있게 합니다.

이 예는 역할 `appuser`의 보호된 릴레이션 목록에서 `public.emp` 릴레이션을 제거합니다.

```sql
edb=# SELECT unprotect_rel('appuser', 'public', 'emp');
```

출력

```text
 unprotect_rel
---------------
(1 row)
```

이 쿼리는 `emp` 릴레이션에 대한 항목이 더 이상 없음을 보여줍니다.

```sql
edb=# SELECT * FROM list_protected_rels;
```

출력

```text
 Database | Protected User | Schema |    Name     | Type  |    Owner
----------+----------------+--------+-------------+-------+--------------
 edb      | appuser        | public | dept        | Table | enterprisedb
 edb      | appuser        | public | appuser_tab | Table | appuser
(2 rows)
```

이제 역할이 그 릴레이션을 사용하려고 하면 SQL/Protect는 (`edb_sql_protect.level` 설정에 따라) 경고를 발행하거나 접근을 완전히 차단합니다.

## 통계 삭제 (Deleting statistics)

다음 함수 중 하나를 사용하여 `edb_sql_protect_stats` 뷰에서 통계를 삭제할 수 있습니다.

```sql
drop_stats('rolename')

drop_stats(roleoid)
```

OID를 사용하는 함수 형식은, `drop_stats('rolename')`으로 역할의 통계를 삭제하기 전에 `DROP ROLE` 또는 `DROP USER` SQL 구문으로 역할을 제거한 경우에 유용합니다. `edb_sql_protect_stats`에 대한 쿼리가 사용자 이름으로 `unknown (OID=16458)`과 같은 값을 반환하면, `drop_stats(roleoid)` 형식의 함수를 사용하여 삭제된 역할의 통계를 `edb_sql_protect_stats`에서 제거합니다.

이 예는 `drop_stats` 함수를 보여줍니다.

```sql
edb=# SELECT drop_stats('appuser');
```

출력

```text
 drop_stats
------------
(1 row)
```

```sql
edb=# SELECT * FROM edb_sql_protect_stats;
```

출력

```text
 username  | superusers | relations | commands | tautology | dml
-----------+------------+-----------+----------+-----------+-----
(0 rows)
```

이 예는 역할이 통계를 삭제하기 전에 드롭된 경우 `drop_stats(roleoid)` 형식의 함수를 사용합니다.

```sql
edb=# SELECT * FROM edb_sql_protect_stats;
```

출력

```text
      username       | superusers | relations | commands | tautology | dml
---------------------+------------+-----------+----------+-----------+-----
 unknown (OID=16693) |          0 |         5 |        3 |         1 |   0
 appuser             |          0 |         5 |        2 |         1 |   0
(2 rows)
```

```sql
edb=# SELECT drop_stats(16693);
```

출력

```text
 drop_stats
------------

(1 row)
```

```sql
edb=# SELECT * FROM edb_sql_protect_stats;
```

출력

```text
 username | superusers | relations | commands | tautology | dml
----------+------------+-----------+----------+-----------+-----
 appuser  |          0 |         5 |        2 |         1 |   0
(1 row)
```

## 위반 쿼리 삭제 (Deleting offending queries)

다음 함수 중 하나를 사용하여 `edb_sql_protect_queries` 뷰에서 위반 쿼리를 삭제할 수 있습니다.

```sql
drop_queries('rolename')

drop_queries(roleoid)
```

OID를 사용하는 함수 변형은, `drop_queries('rolename')`으로 역할의 위반 쿼리를 삭제하기 전에 `DROP ROLE` 또는 `DROP USER` SQL 구문으로 역할을 제거한 경우에 유용합니다. `edb_sql_protect_queries`에 대한 쿼리가 사용자 이름으로 `unknown (OID=16454)`와 같은 값을 반환하면, `drop_queries(roleoid)` 형식의 함수를 사용하여 삭제된 역할의 위반 쿼리를 `edb_sql_protect_queries`에서 제거합니다.

이 예는 `drop_queries` 함수를 보여줍니다.

```sql
edb=# SELECT drop_queries('appuser');
```

출력

```text
 drop_queries
--------------
           5
(1 row)
```

```sql
edb=# SELECT * FROM edb_sql_protect_queries;
```

출력

```text
 username  | ip_address | port | machine_name | date_time | query
-----------+------------+------+--------------+-----------+-------
(0 rows)
```

이 예는 역할이 쿼리를 삭제하기 전에 드롭된 경우 `drop_queries(roleoid)` 형식의 함수를 사용합니다.

```sql
edb=# SELECT username, query FROM edb_sql_protect_queries;
```

출력

```text
      username       |                    query
---------------------+----------------------------------------------
 unknown (OID=16454) | CREATE TABLE appuser_tab_2 (f1 INTEGER);
 unknown (OID=16454) | INSERT INTO appuser_tab_2 VALUES (2);
 unknown (OID=16454) | CREATE TABLE appuser_tab_3 (f1 INTEGER);
 unknown (OID=16454) | INSERT INTO appuser_tab_2 VALUES (1);
 unknown (OID=16454) | SELECT * FROM appuser_tab_2 WHERE 'x' = 'x';
(5 rows)
```

```sql
edb=# SELECT drop_queries(16454);
```

출력

```text
 drop_queries
--------------
          5
(1 row)
```

```sql
edb=# SELECT * FROM edb_sql_protect_queries;
```

출력

```text
 username | ip_address | port | machine_name | date_time | query
----------+------------+------+--------------+-----------+-------
(0 rows)
```

## 모니터링 비활성화 및 활성화 (Disabling and enabling monitoring)

SQL/Protect 모니터링을 끄려면 `postgresql.conf` 파일을 수정하여 `edb_sql_protect.enabled` 파라미터를 `off`로 설정합니다. 파일을 저장한 후, 설정을 적용하기 위해 서버 구성을 다시 로드합니다.

SQL/Protect 모니터링을 켜려면 `postgresql.conf` 파일을 수정하여 `edb_sql_protect.enabled` 파라미터를 `on`으로 설정합니다. 파일을 저장한 다음, 설정을 적용하기 위해 서버 구성을 다시 로드합니다.
