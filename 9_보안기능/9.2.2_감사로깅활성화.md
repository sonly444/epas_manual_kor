# 감사 로깅 활성화 (Enabling audit logging) — EPAS 18

> 원문: [EPAS v18 — Security guide › Using EDB audit logging › Enabling audit logging](https://www.enterprisedb.com/docs/epas/latest/epas_security_guide/05_edb_audit_logging/03_enabling_audit_logging/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 파라미터·명령·SQL·코드·감사 로그 출력은 원문 그대로 보존했습니다.

EDB Postgres Advanced Server는 연결, 연결 해제, DDL·DCL·DML 구문, 오류를 추적할 수 있는 포괄적인 감사 기능을 제공합니다.

## 핵심 구성 파라미터 (Core Configuration Parameters)

감사를 활성화하고 관리하려면 구성 파일에서 다음 파라미터를 설정합니다.

| 파라미터 | 설명 | 적용 범위 |
|---|---|---|
| edb_audit | `xml`, `csv`, `json`으로 설정하여 감사를 활성화합니다. | 클러스터 수준 전용. |
| edb_audit_connect | `all`로 설정하여 연결을 로깅합니다. | 클러스터 수준 전용. (ALTER ROLE/DATABASE 미지원). |
| edb_audit_disconnect | `all`로 설정하여 연결 해제를 로깅합니다. | 클러스터 수준 전용. (ALTER ROLE/DATABASE 미지원). |
| edb_audit_statement | DDL, DML, DCL 등 캡처되는 SQL 구문을 제어합니다. | 전역 기본값이며 하위 수준에서 재정의 가능. |
| edb_audit_directory | 감사 로그 파일 위치를 설정합니다. | 클러스터 수준 전용. |
| edb_audit_rotation_day | 로테이션 일정을 설정합니다. | 클러스터 수준 전용. |

자세한 내용은 [감사할 SQL 구문 선택](https://www.enterprisedb.com/docs/epas/latest/epas_security_guide/05_edb_audit_logging/02_selecting_sql_statements_to_audit/)을 참고하십시오.

## 파라미터 적용 범위 및 재정의 매트릭스 (Parameter scope and override matrix)

ALTER 명령을 통해 세분화된 재정의를 지원하는 파라미터는 다음 매트릭스를 참고하십시오.

| 파라미터 | 클러스터(전역) | ALTER DATABASE | ALTER ROLE | ALTER ROLE IN DATABASE |
|---|---|---|---|---|
| edb_audit_connect | Yes | No | No | No |
| edb_audit_disconnect | Yes | No | No | No |
| edb_audit_statement | Yes | Yes | Yes | Yes |

## 예제 (Examples)

다음은 이 기법의 예입니다.

데이터베이스 클러스터는 `postgresql.conf` 파일에 표시된 대로 `edb_audit_statement`를 `all`로 설정하여 구성됩니다.

```ini
logging_collector = 'on'
edb_audit_statement = 'all'     # Statement type to be audited:
                                # none, dml, insert, update, delete, truncate,
                                # select, error, rollback, ddl, create, drop,
                                # alter, grant, revoke, set, all
                                # {select | update | delete | insert}@groupname
```

`edb_audit_statement` 파라미터에 대해 다음 설정으로 데이터베이스와 역할을 구성합니다.

- 데이터베이스 `auditdb`: `ddl`, `insert`, `update`, `delete`
- 역할 `admin`: `select`, `truncate`, `set`
- 데이터베이스 `auditdb`의 역할 `admin`: `create table`, `insert`, `update`

다음은 데이터베이스와 역할을 생성하고 변경하는 과정을 보여줍니다.

```sql
$ psql edb enterprisedb
Password for user enterprisedb:
psql.bin (18.1.0)
Type "help" for help.

edb=# SHOW edb_audit_statement;
```

출력

```text
 edb_audit_statement
---------------------
 all
(1 row)
```

```sql
edb=# CREATE DATABASE auditdb;
CREATE DATABASE
edb=# ALTER DATABASE auditdb SET edb_audit_statement TO 'ddl, insert, update, delete';
ALTER DATABASE
edb=# CREATE ROLE admin WITH LOGIN SUPERUSER PASSWORD 'password';
CREATE ROLE
edb=# ALTER ROLE admin SET edb_audit_statement TO 'select, truncate';
ALTER ROLE
edb=# ALTER ROLE admin IN DATABASE auditdb SET edb_audit_statement TO 'create table, insert, update';
ALTER ROLE
```

다음은 세 가지 경우에 대해 변경된 내용과 결과 감사 로그 파일을 보여줍니다.

### 경우 1: 역할 `enterprisedb`가 데이터베이스 `auditdb`에서 변경 (Case 1)

`ddl`, `insert`, `update`, `delete` 구문만 감사됩니다.

```sql
$ psql auditdb enterprisedb
Password for user enterprisedb:
psql.bin (18.1.0)
Type "help" for help.

auditdb=# SHOW edb_audit_statement;
```

출력

```text
     edb_audit_statement
-----------------------------
 ddl, insert, update, delete
(1 row)
```

```sql
auditdb=# CREATE TABLE audit_tbl (f1 INTEGER PRIMARY KEY, f2 TEXT);
CREATE TABLE
auditdb=# INSERT INTO audit_tbl VALUES (1, 'Row 1');
INSERT 0 1
auditdb=# UPDATE audit_tbl SET f2 = 'Row A' WHERE f1 = 1;
UPDATE 1
auditdb=# SELECT * FROM audit_tbl;                  <== 감사되지 않아야 함
```

출력

```text
 f1 |  f2
----+-------
  1 | Row A
(1 row)
```

```sql
auditdb=# TRUNCATE audit_tbl;                       <== 감사되지 않아야 함
TRUNCATE TABLE
```
