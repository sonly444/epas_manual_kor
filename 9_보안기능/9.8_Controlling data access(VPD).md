# 데이터 접근 제어 (Virtual Private Database, VPD) — EPAS 18 Security

> 원문: [EPAS v18 — Security › Controlling data access](https://www.enterprisedb.com/docs/epas/latest/epas_security_guide/03_virtual_private_database/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 패키지·권한·명령 이름은 원문 그대로 보존했습니다.

Virtual Private Database는 보안 정책을 사용하는 *세분화된 접근 제어(fine-grained access control)* 메커니즘입니다. 이 방식으로 보안 정책이 정의한 대로 특정 행(row) 단위까지 데이터 접근을 제어할 수 있습니다.

보안 정책은 *정책 함수(policy functions)* — 특정 입력 파라미터와 반환 값을 갖는 SPL 함수 — 에 인코딩됩니다. 보안 정책 자체는 정책 함수와 데이터베이스 객체(일반적으로 테이블) 사이의 명명된 연관(named association)입니다.

EDB Postgres Advanced Server에서 정책 함수는 SQL, PL/pgSQL, SPL 등 지원 언어로 작성할 수 있습니다.

> **참고**: 현재 EDB Postgres Advanced Server Virtual Private Database는 데이터베이스 객체로 테이블을 지원합니다. 뷰(view)나 시노님(synonym)에도 정책을 적용할 수 있습니다.

## Virtual Private Database의 장점
- `GRANT` 명령으로 부여되는 데이터베이스 객체 수준 권한을 넘어, 행(row) 수준의 세분화된 보안 제공.
- SQL 명령 유형(`INSERT`, `UPDATE`, `DELETE`, `SELECT`)에 따라 서로 다른 보안 정책 허용.
- 세션 사용자 신원 같은 요인에 근거하여 SQL 명령별로 보안 정책이 동적으로 달라질 수 있음.
- 보안 정책 적용은 데이터베이스 객체에 접근하는 모든 애플리케이션에 투명하며, 애플리케이션 수정이 필요 없음.
- 정책을 활성화한 후에는 `EXEMPT ACCESS POLICY` 시스템 권한을 통하지 않는 한 어떤 애플리케이션(슈퍼유저 포함)도 정책을 우회할 수 없음.

> **참고**: "보안 정책을 우회할 수 있는 유일한 방법은 사용자에게 `EXEMPT ACCESS POLICY` 시스템 권한이 부여된 경우뿐입니다." 이 권한은 사용자를 모든 데이터베이스 정책에서 면제시키므로 부여 시 극도로 주의하십시오.

`DBMS_RLS` 패키지는 정책을 생성·제거·활성화·비활성화하는 프로시저를 제공합니다.

> 참고: `DBMS_RLS` 패키지의 개별 프로시저(`ADD_POLICY`, `DROP_POLICY`, `ENABLE_POLICY`, `REFRESH_POLICY` 등) 상세와 VPD 정책 함수 예제 전체는 참조(13) 섹션의 `DBMS_RLS` 및 본 페이지 하위 예제에서 다룹니다. 요청 시 개별 전문 번역으로 추가하겠습니다.
