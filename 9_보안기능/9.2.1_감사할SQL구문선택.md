# 감사할 SQL 구문 선택 (Selecting SQL statements to audit) — EPAS 18

> 원문: [EPAS v18 — Security guide › Using EDB audit logging › Selecting SQL statements to audit](https://www.enterprisedb.com/docs/epas/latest/epas_security_guide/05_edb_audit_logging/02_selecting_sql_statements_to_audit/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 파라미터·명령·SQL·코드·감사 로그 출력은 원문 그대로 보존했습니다.

`edb_audit_statement`는 감사할 SQL 구문을 제어하기 위해 쉼표로 구분된 하나 이상의 값을 포함할 수 있습니다. 일반적인 형식은 다음과 같습니다.

```ini
edb_audit_statement = 'value_1[, value_2]...'
```

쉼표로 구분된 값은 쉼표 뒤의 공백 문자를 포함하거나 생략할 수 있습니다. 값은 소문자와 대문자를 임의로 조합하여 지정할 수 있습니다.

## 파라미터 개요 (Overview of the parameters)

기본 파라미터 값은 다음과 같습니다.

- `all` — 모든 구문을 감사·로깅합니다(구문에 대한 오류 메시지 포함).
- `none` — 모든 감사·로깅을 비활성화합니다. `none` 값은 목록에 포함된 다른 어떤 값보다 우선합니다.
- `ddl` — 모든 데이터 정의 언어(DDL) 구문(`CREATE`, `ALTER`, `DROP`)과 `GRANT`·`REVOKE` 데이터 제어 언어(DCL) 구문을 감사합니다.
- `dml` — 모든 데이터 조작 언어(DML) 구문(`INSERT`, `UPDATE`, `DELETE`, `TRUNCATE`)을 감사합니다.
- `select` — `SELECT` 구문을 감사합니다.
- `set` — `SET` 구문을 감사합니다.
- `rollback` — `ROLLBACK` 구문을 감사합니다.
- `error` — 발생하는 모든 오류 메시지를 로깅합니다. 그렇지 않으면 `all`을 사용하는 경우를 제외하고, 앞의 다른 파라미터 값과 관련된 SQL 구문에서 발생하는 오류에 대한 메시지는 로깅되지 않습니다.
- `{ select | update | delete | insert }@groupname` — 지정한 테이블에 대해 `(@)` 포함 및 `(-)` 제외 그룹을 사용하여, 특정 DML 구문(`SELECT`, `UPDATE`, `DELETE`, `INSERT`)에 대해 객체를 선택적으로 감사합니다. 자세한 내용은 [객체 감사(Object auditing)](https://www.enterprisedb.com/docs/epas/latest/epas_security_guide/05_edb_audit_logging/09_object_auditing/)를 참고하십시오.

"DDL 및 DCL 구문"에서는 감사할 특정 DDL·DCL 구문을 선택하기 위한 추가 파라미터 값을 설명합니다. "DML 구문"에서는 감사할 특정 DML 구문을 선택하기 위한 추가 파라미터 값을 설명합니다.

`edb_audit_statement` 파라미터에 지원되지 않는 값이 포함되면, 설정을 데이터베이스 서버에 적용할 때 오류가 발생합니다. 예를 들어 다음 예에서는 `create materialized vw`가 오류를 유발합니다. 올바른 값은 `create materialized view`입니다. 오류는 데이터베이스 서버 로그 파일에서 확인할 수 있습니다.

```text
2017-07-16 11:20:39 EDT LOG:  invalid value for parameter
"edb_audit_statement": "create materialized vw, create sequence, grant"
2017-07-16 11:20:39 EDT FATAL:  configuration file "/var/lib/edb/as18/data/
postgresql.conf" contains errors
```

## DDL 및 DCL 구문 (DDL and DCL statements)

DDL·DCL 구문을 감사할 때, `edb_audit_statement` 파라미터에 포함할 수 있는 값에 다음 일반 규칙이 적용됩니다.

- `edb_audit_statement` 파라미터에 `ddl` 또는 `all`이 포함되면 모든 DDL 구문이 감사됩니다. 또한 DCL 구문 `GRANT`와 `REVOKE`가 감사됩니다.
- `edb_audit_statement`가 `none`으로 설정되면 어떤 DDL·DCL 구문도 감사되지 않습니다.
- `edb_audit_statement` 파라미터에 값을 조합하여 포함함으로써 감사할 특정 유형의 DDL·DCL 구문을 선택할 수 있습니다.

DDL 구문에 대한 `edb_audit_statement` 파라미터 값을 지정하려면 다음 구문을 사용합니다.

```text
{ create | alter | drop } [ <object_type> ]
```

`object_type`은 다음 중 하나입니다.

- `ACCESS METHOD`
- `AGGREGATE`
- `CAST`
- `COLLATION`
- `CONVERSION`
- `DATABASE`
- `EVENT TRIGGER`
- `EXTENSION`
- `FOREIGN TABLE`
- `FUNCTION`
- `INDEX`
- `LANGUAGE`
- `LARGE OBJECT`
- `MATERIALIZED VIEW`
- `OPERATOR`
- `OPERATOR CLASS`
- `OPERATOR FAMILY`
- `POLICY`
- `PUBLICATION`
- `ROLE`
- `RULE`
- `SCHEMA`
- `SEQUENCE`
- `SERVER`
- `SUBSCRIPTION`
- `TABLE`
- `TABLESPACE`
- `TEXT SEARCH CONFIGURATION`
- `TEXT SEARCH DICTIONARY`
- `TEXT SEARCH PARSER`
- `TEXT SEARCH TEMPLATE`
- `TRANSFORM`
- `TRIGGER`
- `TYPE`
- `USER MAPPING`
- `VIEW`

SQL 명령에서 사용되는 객체 유형에 대한 설명은 [PostgreSQL 코어 문서](https://www.postgresql.org/docs/current/static/sql-commands.html)에서 확인할 수 있습니다.

파라미터 값에서 `object_type`이 생략되면, 지정된 모든 명령 구문(`create`, `alter`, `drop`)이 감사됩니다.

DCL 구문에 대한 `edb_audit_statement` 파라미터 값을 지정하려면 다음 구문을 사용합니다.

```text
{ grant | revoke }
```

### 예제 (Examples)

이 예에서 `edb_audit_connect`와 `edb_audit_statement`는 다음과 같은 비기본값으로 설정됩니다.

```ini
logging_collector = 'on'
edb_audit_connect = 'all'
edb_audit_statement = 'create, alter, error'
```

따라서 `CREATE`와 `ALTER` 명령으로 호출된 SQL 구문만 감사됩니다. 오류 메시지도 감사 로그에 포함됩니다.

마찬가지로 스키마 `edb`와 테이블 `department`·`dept`에 대한 `CREATE` 구문이 감사됩니다.

이 예에서 `edb_audit_connect`와 `edb_audit_statement`는 다음과 같은 비기본값으로 설정됩니다.

```ini
logging_collector = 'on'
edb_audit_connect = 'all'
edb_audit_statement = 'create view,create materialized view,create sequence,grant'
```

따라서 `CREATE VIEW`, `CREATE MATERIALIZED VIEW`, `CREATE SEQUENCE`, `GRANT` 명령으로 호출된 SQL 구문만 감사됩니다.

```ini
logging_collector = 'on'
edb_audit_connect = 'all'
edb_audit_statement = 'none'
```

`ADMIN` 또는 `SYSDBA`로 연결하는 사용자의 세션은 완전히 감사할 수 있습니다. 관리자 사용자가 `ADMINUSER`로 데이터베이스 `auditdb`에 연결되어 있습니다. 다음 `ALTER USER` 명령은 `ADMINUSER`를 감사하도록 지정합니다.

```sql
ALTER USER adminuser SET edb_audit_statement = "all";
```

`edb_audit_statement` 파라미터를 `all`로 설정하면 관리자 사용자의 모든 SQL 구문을 감사할 수 있습니다.

## DML 구문 (DML statements)

DML 구문을 감사할 때, `edb_audit_statement` 파라미터에 포함할 수 있는 값에 다음 일반 규칙이 적용됩니다.

- `edb_audit_statement` 파라미터에 `dml` 또는 `all`이 포함되면 모든 DML 구문이 감사됩니다.
- `edb_audit_statement`가 `none`으로 설정되면 어떤 DML 구문도 감사되지 않습니다.
- `edb_audit_statement` 파라미터에 값을 조합하여 포함함으로써 감사할 특정 유형의 DML 구문을 선택할 수 있습니다.

SQL `INSERT`, `UPDATE`, `DELETE`, `TRUNCATE` 구문에 대한 `edb_audit_statement` 파라미터 값을 지정하려면 다음 구문을 사용합니다.

```text
{ insert | update | delete | truncate }
```

```ini
logging_collector = 'on'
edb_audit_connect = 'all'
edb_audit_statement = 'UPDATE, DELETE, error'
```
