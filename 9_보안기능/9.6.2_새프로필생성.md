# 새 프로필 생성 (Creating a new profile) — EPAS 18

> 원문: [EPAS v18 — Security guide › Managing user profiles › Creating a new profile](https://www.enterprisedb.com/docs/epas/latest/epas_security_guide/04_profile_management/01_creating_a_new_profile/)
> 하위 페이지 [Creating a password function](https://www.enterprisedb.com/docs/epas/latest/epas_security_guide/04_profile_management/01_creating_a_new_profile/01_creating_a_password_function/)을 이 파일 하단에 함께 수록했습니다.
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·파라미터·SQL·코드·출력은 원문 그대로 보존했습니다.

`CREATE PROFILE` 명령을 사용하여 새 프로필을 생성합니다. 구문은 다음과 같습니다.

```sql
CREATE PROFILE <profile_name>
       [LIMIT {<parameter value>} ... ];
```

`LIMIT` 절과 공백으로 구분된 하나 이상의 파라미터/값 쌍을 포함하여 EDB Postgres Advanced Server가 적용하는 규칙을 지정합니다.

## 파라미터 (Parameters)

- `profile_name`은 프로필의 이름을 지정합니다.
- `parameter`는 프로필로 제한되는 속성을 지정합니다.
- `value`는 파라미터 제한값을 지정합니다.

EDB Postgres Advanced Server는 각 `parameter`에 대해 다음 `value`를 지원합니다.

**`FAILED_LOGIN_ATTEMPTS`** — 서버가 `PASSWORD_LOCK_TIME`으로 지정된 시간 동안 계정을 잠그기 전까지 사용자가 시도할 수 있는 로그인 실패 횟수를 지정합니다. 지원 값:

- `0`보다 큰 `INTEGER` 값.
- `DEFAULT` — `DEFAULT` 프로필에 지정된 `FAILED_LOGIN_ATTEMPTS` 값.
- `UNLIMITED` — 연결하는 사용자가 무제한으로 로그인 실패를 시도할 수 있습니다.

**`PASSWORD_LOCK_TIME`** — `FAILED_LOGIN_ATTEMPTS`로 인해 잠긴 계정을 서버가 잠금 해제하기 전까지 경과해야 하는 시간을 지정합니다. 지원 값:

- 0 이상의 `NUMERIC` 값. 하루의 소수 부분을 지정하려면 소수 값을 지정합니다. 예를 들어 `4.5` 값은 4일 12시간을 지정합니다.
- `DEFAULT` — `DEFAULT` 프로필에 지정된 `PASSWORD_LOCK_TIME` 값.
- `UNLIMITED` — 데이터베이스 슈퍼유저가 수동으로 잠금을 해제할 때까지 계정이 잠깁니다.

**`PASSWORD_LIFE_TIME`** — 사용자에게 새 비밀번호를 제공하라는 메시지가 표시되기 전까지 현재 비밀번호를 사용할 수 있는 일수를 지정합니다. `PASSWORD_LIFE_TIME` 절을 사용할 때 `PASSWORD_GRACE_TIME` 절을 포함하여, 비밀번호 만료 후 역할의 연결이 거부되기 전까지 경과하는 일수를 지정합니다. `PASSWORD_GRACE_TIME`을 지정하지 않으면 `PASSWORD_GRACE_TIME`의 기본값으로 지정된 날에 비밀번호가 만료되며, 사용자는 새 비밀번호를 제공할 때까지 어떤 명령도 실행할 수 없습니다. 지원 값:

- 0 이상의 `NUMERIC` 값. 하루의 소수 부분을 지정하려면 소수 값을 지정합니다. 예를 들어 `4.5` 값은 4일 12시간을 지정합니다.
- `DEFAULT` — `DEFAULT` 프로필에 지정된 `PASSWORD_LIFE_TIME` 값.
- `UNLIMITED` — 비밀번호에 만료일이 없습니다.

**`PASSWORD_GRACE_TIME`** — 비밀번호가 만료된 후 사용자가 비밀번호를 변경하도록 강제되기 전까지의 유예 기간 길이를 지정합니다. 유예 기간이 만료되면 사용자는 연결할 수 있지만, 만료된 비밀번호를 갱신할 때까지 어떤 명령도 실행할 수 없습니다. 지원 값:

- 0 이상의 `NUMERIC` 값. 하루의 소수 부분을 지정하려면 소수 값을 지정합니다. 예를 들어 `4.5` 값은 4일 12시간을 지정합니다.
- `DEFAULT` — `DEFAULT` 프로필에 지정된 `PASSWORD_GRACE_TIME` 값.
- `UNLIMITED` — 유예 기간이 무한합니다.

**`PASSWORD_REUSE_TIME`** — 사용자가 비밀번호를 재사용하기 전에 기다려야 하는 일수를 지정합니다. `PASSWORD_REUSE_TIME`과 `PASSWORD_REUSE_MAX` 파라미터를 함께 사용합니다. 이 파라미터 중 하나에 유한한 값을 지정하고 다른 하나가 `UNLIMITED`이면, 이전 비밀번호를 절대 재사용할 수 없습니다. 두 파라미터가 모두 `UNLIMITED`로 설정되면 비밀번호 재사용에 제한이 없습니다. 지원 값:

- 0 이상의 `NUMERIC` 값. 하루의 소수 부분을 지정하려면 소수 값을 지정합니다. 예를 들어 `4.5` 값은 4일 12시간을 지정합니다.
- `DEFAULT` — `DEFAULT` 프로필에 지정된 `PASSWORD_REUSE_TIME` 값.
- `UNLIMITED` — 제한 없이 비밀번호를 재사용할 수 있습니다.

**`PASSWORD_REUSE_MAX`** — 비밀번호를 재사용할 수 있기 전에 발생해야 하는 비밀번호 변경 횟수를 지정합니다. `PASSWORD_REUSE_TIME`과 `PASSWORD_REUSE_MAX` 파라미터를 함께 사용합니다. 이 파라미터 중 하나에 유한한 값을 지정하고 다른 하나가 `UNLIMITED`이면, 이전 비밀번호를 절대 재사용할 수 없습니다. 두 파라미터가 모두 `UNLIMITED`로 설정되면 비밀번호 재사용에 제한이 없습니다. 지원 값:

- 0 이상의 `INTEGER` 값.
- `DEFAULT` — `DEFAULT` 프로필에 지정된 `PASSWORD_REUSE_MAX` 값.
- `UNLIMITED` — 제한 없이 비밀번호를 재사용할 수 있습니다.

**`PASSWORD_VERIFY_FUNCTION`** — 비밀번호 복잡성을 지정합니다. 지원 값:

- PL/SQL 함수의 이름.
- `DEFAULT` — `DEFAULT` 프로필에 지정된 `PASSWORD_VERIFY_FUNCTION` 값.
- `NULL`

**`PASSWORD_ALLOW_HASHED`** — 암호화된 비밀번호를 허용할지 여부를 지정합니다. `TRUE`를 지정하면 시스템은 사용자가 클라이언트 측에서 해시로 계산된 암호화 비밀번호를 지정하여 비밀번호를 변경하도록 허용합니다. `FALSE`를 지정하면 유효성 검사를 위해 비밀번호를 평문 형태로 지정해야 합니다. 그렇지 않으면 서버가 암호화된 비밀번호를 받을 때 오류가 발생합니다. 지원 값:

- Boolean 값 `TRUE/ON/YES/1` 또는 `FALSE/OFF/NO/0`.
- `DEFAULT` — `DEFAULT` 프로필에 지정된 `PASSWORD_ALLOW_HASHED` 값.

> **참고**
> - `PASSWORD_ALLOW_HASHED`는 Oracle 호환 파라미터가 아닙니다.
> - 프로필을 제거하려면 `DROP PROFILE` 명령을 사용합니다.

## 예제 (Examples)

다음 명령은 `acctg`라는 프로필을 생성합니다. 이 프로필은 사용자가 다섯 번의 시도 내에 올바른 비밀번호로 인증하지 못하면 계정이 하루 동안 잠기도록 지정합니다.

```sql
CREATE PROFILE acctg LIMIT
       FAILED_LOGIN_ATTEMPTS 5
       PASSWORD_LOCK_TIME 1;
```

다음 명령은 `sales`라는 프로필을 생성합니다. 이 프로필은 사용자가 90일마다 비밀번호를 변경해야 하도록 지정합니다.

```sql
CREATE PROFILE sales LIMIT
       PASSWORD_LIFE_TIME 90
       PASSWORD_GRACE_TIME 3;
```

사용자가 프로필에 지정된 90일이 지나기 전에 비밀번호를 변경하지 않으면 로그인 시 경고가 표시됩니다. 유예 기간이 지나면 계정은 비밀번호를 변경할 때까지 어떤 명령도 실행할 수 없습니다.

다음 명령은 `accts`라는 프로필을 생성합니다. 이 프로필은 사용자가 비밀번호를 마지막으로 사용한 후 180일 이내에는 재사용할 수 없고, 비밀번호를 재사용하기 전에 최소 다섯 번 변경해야 하도록 지정합니다.

```sql
CREATE PROFILE accts LIMIT
       PASSWORD_REUSE_TIME 180
       PASSWORD_REUSE_MAX 5;
```

다음 명령은 `resources`라는 프로필을 생성합니다. 이 프로필은 제공된 비밀번호가 복잡성 표준을 충족하는지 검증하는 `password_rules`라는 사용자 정의 함수를 호출합니다.

```sql
CREATE PROFILE resources LIMIT
       PASSWORD_VERIFY_FUNCTION password_rules;
```

# 비밀번호 함수 생성 (Creating a password function) — 하위 페이지

> 원문: [EPAS v18 — Security guide › Managing user profiles › Creating a new profile › Creating a password function](https://www.enterprisedb.com/docs/epas/latest/epas_security_guide/04_profile_management/01_creating_a_new_profile/01_creating_a_password_function/)

`PASSWORD_VERIFY_FUNCTION`을 지정할 때, 사용자가 비밀번호를 변경할 때 적용할 보안 규칙을 지정하는 사용자 지정 함수를 제공할 수 있습니다. 예를 들어 새 비밀번호가 최소 *n*자 이상이어야 하고 특정 값을 포함할 수 없다고 규정하는 규칙을 지정할 수 있습니다.

비밀번호 함수는 다음 시그니처를 갖습니다.

```sql
<function_name> (<user_name> VARCHAR2,
                 <new_password> VARCHAR2,
                 <old_password> VARCHAR2) RETURN boolean
```

여기서:

- `user_name`은 사용자의 이름입니다.

- `new_password`는 새 비밀번호입니다.

- `old_password`는 사용자의 이전 비밀번호입니다. 함수에서 이 파라미터를 참조하는 경우:

  - 데이터베이스 슈퍼유저가 비밀번호를 변경하면 세 번째 파라미터는 항상 `NULL`입니다.
  - `CREATEROLE` 속성을 가진 사용자가 비밀번호를 변경하면, 구문에 `REPLACE` 절이 포함된 경우 이 파라미터로 이전 비밀번호가 전달됩니다. `REPLACE` 절은 `CREATEROLE` 권한을 가진 사용자에게는 선택적 구문입니다.
  - 데이터베이스 슈퍼유저가 아니고 `CREATEROLE` 속성도 없는 사용자가 비밀번호를 변경하면, 세 번째 파라미터에 역할의 이전 비밀번호가 담깁니다.

함수는 Boolean 값을 반환합니다. 함수가 `true`를 반환하고 예외를 발생시키지 않으면 비밀번호가 수락됩니다. 함수가 `false`를 반환하거나 예외를 발생시키면 비밀번호가 거부됩니다. 함수가 예외를 발생시키면 지정된 오류 메시지가 사용자에게 표시됩니다. 함수가 예외를 발생시키지 않고 `false`를 반환하면 다음 오류 메시지가 표시됩니다.

`ERROR: password verification for the specified password failed`

함수는 데이터베이스 슈퍼유저가 소유해야 하며 `sys` 스키마에 위치해야 합니다.

## 예제 (Example)

이 예는 프로필과 사용자 지정 함수를 생성합니다. 그런 다음 함수를 프로필에 연결합니다.

이 `CREATE PROFILE` 명령은 `acctg_pwd_profile`이라는 프로필을 생성합니다.

```sql
CREATE PROFILE acctg_pwd_profile;
```

다음 명령은 스키마 한정된 `verify_password`라는 함수를 생성합니다.

```sql
CREATE OR REPLACE FUNCTION sys.verify_password(user_name varchar2,
new_password varchar2, old_password varchar2)
RETURN boolean IMMUTABLE
IS
BEGIN
  IF (length(new_password) < 5)
  THEN
    raise_application_error(-20001, 'too short');
  END IF;

  IF substring(new_password FROM old_password) IS NOT NULL
  THEN
    raise_application_error(-20002, 'includes old password');
  END IF;

  RETURN true;
END;
```

함수는 먼저 비밀번호가 최소 다섯 자 이상인지 확인한 다음, 새 비밀번호를 이전 비밀번호와 비교합니다. 새 비밀번호가 다섯 자 미만이거나 이전 비밀번호를 포함하면 함수는 오류를 발생시킵니다.

다음 구문은 `verify_password` 함수의 소유권을 `enterprisedb` 데이터베이스 슈퍼유저로 설정합니다.

```sql
ALTER FUNCTION verify_password(varchar2, varchar2, varchar2) OWNER TO
enterprisedb;
```

그런 다음 `verify_password` 함수를 프로필에 연결합니다.

```sql
ALTER PROFILE acctg_pwd_profile LIMIT PASSWORD_VERIFY_FUNCTION
verify_password;
```

다음 구문은 먼저 테스트 사용자(`alice`)를 생성한 다음, 그녀의 역할에 유효하지 않은 비밀번호와 유효한 비밀번호를 연결하려고 시도하여 함수가 작동하는지 확인합니다.

```sql
CREATE ROLE alice WITH LOGIN PASSWORD 'temp_password' PROFILE
acctg_pwd_profile;
```

그런 다음 `alice`가 데이터베이스에 연결하여 비밀번호를 변경하려고 하면, 프로필 함수가 설정한 규칙을 준수해야 합니다. `CREATEROLE`이 없는 비슈퍼유저는 비밀번호를 변경할 때 `REPLACE` 절을 포함해야 합니다.

```sql
edb=> ALTER ROLE alice PASSWORD 'hey';
ERROR:  missing REPLACE clause
```

새 비밀번호는 최소 다섯 자 이상이어야 합니다.

```sql
edb=> ALTER USER alice PASSWORD 'hey' REPLACE 'temp_password';
ERROR:  EDB-20001: too short
CONTEXT:  edb-spl function verify_password(character varying,character
varying,character varying) line 5 at procedure/function invocation statement
```

새 비밀번호가 허용되면 명령이 오류 없이 완료됩니다.

```sql
edb=> ALTER USER alice PASSWORD 'hello' REPLACE 'temp_password';
ALTER ROLE
```

`alice`가 비밀번호를 변경하기로 하면, 새 비밀번호는 이전 비밀번호를 포함해서는 안 됩니다.

```sql
edb=> ALTER USER alice PASSWORD 'helloworld' REPLACE 'hello';
ERROR:  EDB-20002: includes old password
CONTEXT:  edb-spl function verify_password(character varying,character
varying,character varying) line 10 at procedure/function invocation statement
```

검증 함수를 제거하려면 `password_verify_function`을 `NULL`로 설정합니다.

```sql
ALTER PROFILE acctg_pwd_profile LIMIT password_verify_function NULL;
```

그러면 모든 비밀번호 제약이 해제됩니다.

```sql
edb=# ALTER ROLE alice PASSWORD 'hey';
ALTER ROLE
```
