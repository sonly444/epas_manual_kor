# 객체 감사 (Auditing objects) — EPAS 18

> 원문: [EPAS v18 — Security guide › Using EDB audit logging › Auditing objects](https://www.enterprisedb.com/docs/epas/latest/epas_security_guide/05_edb_audit_logging/09_object_auditing/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 파라미터·명령·SQL·코드·로그 출력은 원문 그대로 보존했습니다.

객체 수준 감사(object-level auditing)는 지정한 테이블에 대해 특정 데이터 조작 언어(DML) 구문(`SELECT`, `UPDATE`, `DELETE`, `INSERT`)에 대해 객체를 선택적으로 감사할 수 있게 합니다. 객체 수준 감사는 또한 `edb_audit_statement` 파라미터에 `(@)` 또는 `(-)`를 지정하여 특정 그룹을 포함하거나 제외할 수 있게 합니다. DML 구문에 대한 자세한 내용은 [감사할 SQL 구문 선택](https://www.enterprisedb.com/docs/epas/latest/epas_security_guide/05_edb_audit_logging/02_selecting_sql_statements_to_audit/)을 참고하십시오.

`SELECT`, `UPDATE`, `DELETE`, `INSERT` 구문에 대한 `edb_audit_statement` 파라미터 값을 지정하려면 다음 구문을 사용합니다.

```text
{ select | update | delete | insert }{@ | -}groupname
```

## 예제 (Example)

이 예에서 `edb_audit_connect`와 `edb_audit_statement`는 다음과 같은 비기본값으로 설정됩니다.

```ini
logging_collector = 'on'
edb_audit_connect = 'all'
edb_audit = 'csv'
edb_audit_statement = 'select, insert, update, delete'
```

`SELECT`, `INSERT`, `UPDATE`, `DELETE` 명령으로 호출된 SQL 구문이 감사됩니다.

발생하는 데이터베이스 세션은 다음과 같습니다.

`enterprisedb` 사용자와 `edb` 데이터베이스에 대해 `edb_audit_statement` 파라미터를 `'select@low_security@high_security, insert@high_security-low_security, update-low_security@high_security, delete@low_security-high_security'`로 설정하면, 감사 로그 파일에서 그룹에 대해 `(@)` 포함 및 `-` 제외를 적용하여 `SELECT`, `INSERT`, `UPDATE`, `DELETE` 구문을 감사할 수 있습니다.

로그 파일의 테이블에 대해:

- `select@low_security@high_security`는 `low_security`와 `high_security` 감사 그룹의 `SELECT` 구문을 감사합니다.
- `insert@high_security-low_security`는 `high_security`의 `INSERT` 구문을 감사하고 `low_security` 감사 그룹의 insert 구문을 제외합니다.
- `update-low_security@high_security`는 `high_security`의 `UPDATE` 구문을 감사하고 `low_security` 감사 그룹의 update 구문을 제외합니다.
- `delete@low_security-high_security`는 로그 파일의 테이블에 대해 `low_security`의 `DELETE` 구문을 감사하고 `high_security` 감사 그룹의 delete 구문을 제외합니다.

## 시스템 카탈로그 테이블 감사 (Auditing system catalog tables)

EPAS 버전 18부터 슈퍼유저는 이제 시스템 카탈로그 테이블(`pg_catalog` 테이블)에 대한 감사를 활성화할 수 있습니다. 이전에는 이러한 테이블에 감사 파라미터를 설정하려고 하면 권한 오류가 발생했습니다. 이 개선으로 슈퍼유저는 `edb_audit_group` 파라미터를 사용하여 시스템 테이블에 대한 감사를 구성할 수 있습니다.

```sql
edb=# alter table pg_class set (edb_audit_group='low_security');
```

출력

```text
ALTER TABLE
```

예:

```sql
# edb_audit_statement 설정:
edb=# show edb_audit_statement ;
```

출력

```text
                   edb_audit_statement
----------------------------------------------------------
 select-low_security@high_security,insert, update, delete
(1 row)
```

low_security 그룹에 대해 pg_class 테이블의 감사를 활성화합니다.

```sql
edb=# alter table pg_class  set (edb_audit_group='low_security');
```

출력

```text
ALTER TABLE
```

pg_class 테이블에 select 구문을 실행합니다.

```sql
# edb_audit_statement가 low_security로만 설정되어 있으므로 이 구문은 감사되지 않습니다:
edb=# select * from pg_class limit 2 ;
```

```sql
# high_security 그룹에 대해 pg_class 테이블에 설정:
edb=# alter table pg_class  set (edb_audit_group='high_security');
```

출력

```text
ALTER TABLE
```

```sql
# 이 구문은 감사되고 정보가 로그 파일에 추가됩니다:
edb=# select * from pg_class limit 2 ;
```
