# 향상된 호환 기능 (Enhanced Compatibility Features) — EPAS 18 Working with Oracle Data

> 원문: [EPAS v18 — Working with Oracle data › Enhanced compatibility features](https://www.enterprisedb.com/docs/epas/latest/working_with_oracle_data/02_enhanced_compatibility_features/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·파라미터·패키지 이름은 원문 그대로 보존했습니다.

EDB Postgres Advanced Server는 Oracle 애플리케이션이 지원하는 구문에 대한 호환성을 제공하는 확장 기능을 포함합니다. 지원되는 호환 기능에 대한 추가 정보는 "Oracle 개발자를 위한 데이터베이스 호환성"을 참조하십시오.

## 호환 기능 활성화 (Enabling compatibility features)

호환 기능을 활성화하는 여러 설치 방법:

- 클러스터 초기화 전에 EDB Postgres Advanced Server 서비스 구성 파일의 `INITDBOPTS` 변수에 `--redwood-like`를 지정.
- `initdb`로 클러스터를 초기화할 때 `--redwood-like` 파라미터 포함.

설치 옵션에 대한 자세한 내용은 "Oracle 데이터베이스 호환 구성 파라미터"와 "EDB Postgres Advanced Server 설치 관리"를 참조하십시오.

> **참고**: 데이터베이스 링크(Database link)는 Oracle 호환성을 요구하므로 PostgreSQL 호환 모드에서는 지원되지 않습니다.

## 저장 프로시저 언어 (Stored procedural language)

EDB Postgres Advanced Server는 사용자 정의 프로시저·함수·트리거·패키지를 작성할 수 있는 고생산성 절차적 언어를 지원합니다. 이 언어는 SQL 언어·내장 패키지를 보완하고, 매끄러운 개발·테스트 환경을 제공하며, 재사용 가능한 코드를 만들 수 있게 합니다. (상세: `11_애플리케이션프로그래밍/10_5_SPL/`)

## 옵티마이저 힌트 (Optimizer hints)

`DELETE`, `INSERT`, `SELECT`, `UPDATE` 명령을 호출하면 서버가 여러 실행 계획을 생성합니다. 이를 분석하여 일반적으로 가장 짧은 시간에 결과 집합을 반환하는 계획을 선택합니다. 계획 선택은 데이터 처리 연산의 추정 실행 비용, `postgresql.conf`의 Query Tuning 섹션 파라미터 값, `ANALYZE` 명령이 수집한 컬럼 통계에 따라 달라집니다.

원칙적으로 쿼리 플래너는 가장 비용이 낮은 계획을 선택합니다. *옵티마이저 힌트*로 계획 선택에 영향을 줄 수 있습니다. 옵티마이저 힌트는 `DELETE`/`INSERT`/`SELECT`/`UPDATE` 명령 바로 뒤에 주석 형태 구문으로 임베드된 하나 이상의 지시입니다. 주석 내 키워드가 서버에 특정 계획을 사용/회피하도록 지시합니다. (상세: `11_애플리케이션프로그래밍/11_7_코드최적화/`)

## 데이터 딕셔너리 뷰 (Data dictionary views)

EDB Postgres Advanced Server는 Oracle 데이터 딕셔너리 뷰와 호환되는 방식으로 데이터베이스 객체 정보를 제공하는 뷰 집합을 포함합니다. (상세: `14_참조/14_4_Oracle호환참조/14_4_4_카탈로그뷰/`)

## dblink_ora

dblink_ora는 OCI 기반 데이터베이스 링크를 제공하여 EDB Postgres Advanced Server에서 Oracle 시스템에 저장된 데이터를 `SELECT`/`INSERT`/`UPDATE`/`DELETE`할 수 있게 합니다. (상세: `12_2_dblink_ora/`)

## 프로필 관리 (Profile management)

EDB Postgres Advanced Server는 프로필 관리를 위한 호환 SQL 구문을 지원합니다. 프로필 관리 명령으로 슈퍼유저가 명명된 *프로필*을 생성·관리할 수 있습니다. 프로필은 유사한 인증 요구를 공유하는 역할 그룹을 쉽게 관리하게 하는 속성 집합으로, password·md5 인증을 보강하는 비밀번호 관리 규칙을 정의합니다: 로그인 실패 횟수 계산, 과도한 실패로 계정 잠금, 비밀번호 만료 표시, 만료 후 유예 기간 정의, 비밀번호 복잡도 규칙, 비밀번호 재사용 제한.

프로필 생성 후 사용자와 연결하며, 요구가 바뀌면 프로필을 수정해 연결된 각 사용자에 적용합니다. 사용자가 연결하면 서버가 그 로그인 역할의 프로필을 강제합니다. 프로필은 클러스터의 모든 데이터베이스가 공유하며, 클러스터는 여러 프로필을 가질 수 있습니다. (상세: `09_보안기능/09_6_사용자프로필관리/`)

## Open Client Library

Open Client Library는 Oracle Call Interface와의 애플리케이션 상호운용을 제공합니다. 과거 "락인(locked in)"된 애플리케이션이 코드 변경을 최소화(또는 무변경)하여 EDB Postgres Advanced Server 또는 Oracle 데이터베이스와 작동할 수 있습니다. EDB 구현은 C로 작성되었습니다. (상세: `12_3_OCL.md`, [EDB OCL Connector](https://www.enterprisedb.com/docs/ocl_connector/15/))

## 유틸리티 (Utilities)

호환 구문 상세는 "도구, 유틸리티 및 구성 요소"(본 번역 `13_도구유틸리티/`)를 참조하십시오.

### EDB*Plus

EDB\*Plus는 Oracle 개발자·사용자에게 친숙한 명령줄 인터페이스를 제공하는 유틸리티입니다. SQL 명령, SPL 익명 블록, EDB\*Plus 명령을 수용하며, 데이터베이스 객체 질의·저장 프로시저 실행·SQL 출력 서식화·배치 스크립트 실행·OS 명령 실행·출력 기록을 할 수 있습니다.

### EDB*Loader

EDB\*Loader는 Oracle 데이터베이스 호환 인터페이스를 제공하는 고성능 대량 데이터 로더입니다. Oracle SQL\*Loader 파라미터의 부분집합으로 입력 소스(주로 파일)의 데이터를 하나 이상의 테이블에 적재합니다. 기능: Oracle SQL\*Loader 로딩 방식(일반·직접·병렬 직접 경로) 지원, 호환 컨트롤 파일 지시자 구문, 구분자/고정폭 필드, bad 파일, 다중 대상 테이블, discard 파일, 표준 입력·원격 로딩. (상세: `08_데이터베이스관리/07_3_EDB_Loader/`)

### EDB*Wrap

EDB\*Wrap 유틸리티는 함수·저장 프로시저·트리거·패키지 등 독점 소스 코드를 무단 열람으로부터 보호합니다. SPL·PL/pgSQL 평문 소스를 읽기 거의 불가능한 형태로 변환하며, 서버는 이를 난독화 형태로 저장합니다. 다만 테이블 정의는 여전히 노출됩니다. 패키지 전체를 래핑하면 본문·헤더 프로토타입·포함 함수/프로시저가 모두 난독화 저장됩니다. (상세: `09_보안기능/08_5_EDB_Wrap/`)

### DRITA (Dynamic Runtime Instrumentation Tools Architecture)

> **폐기(Deprecation)**: EPAS 17 릴리스와 함께 DRITA는 폐기되었으며 EPAS 18에는 포함되지 않습니다. 이는 [EDB PWR](https://www.enterprisedb.com/docs/pwr/latest/)와 [`edb_wait_states`](https://www.enterprisedb.com/docs/pg_extensions/wait_states/) 확장 도입에 따른 것으로, 이들은 DRITA보다 향상된 진단 기능을 제공하며 Oracle AWR 리포트에 더 가까운 진단 경험을 제공합니다.

## ECPGPlus

EDB는 PostgreSQL 프리컴파일러 ECPG를 확장하여 ECPGPlus를 만들었습니다. C 애플리케이션에 임베디드 SQL 명령을 포함할 수 있으며, 컴파일 시 SQL을 구문 검사하고 C로 변환합니다. EPAS 연결 시 Pro\*C 구문을 지원하며 Oracle Dynamic SQL – Method 4(ODS-M4), Pro\*C 호환 익명 블록, Oracle 호환 `CALL` 문을 지원합니다. (상세: `13_도구유틸리티/13_1_앱개발자도구/13_1_2_ECPGPlus.md`)

## 테이블 파티셔닝 (Table partitioning)

파티션 테이블에서는 논리적으로 큰 하나의 테이블이 더 작은 물리 조각으로 나뉩니다. 이점:

- 자주 접근하는 행 대부분이 단일/소수 파티션에 있을 때 쿼리 성능이 크게 향상. 파티션 컬럼을 인덱스 앞에서 생략할 수 있어 인덱스 크기가 줄고 자주 쓰는 부분이 메모리에 들어갈 가능성이 커짐.
- 쿼리·업데이트가 단일 파티션의 큰 비율에 접근할 때, 전체 테이블에 흩어진 랜덤 액세스 대신 파티션 순차 스캔으로 성능이 향상될 수 있음.
- 파티셔닝 설계에 요구사항을 반영하면 파티션 추가/제거로 대량 적재/해제 구현 가능. `ALTER TABLE`이 대량 연산보다 빠르고, 대량 `DELETE`가 유발하는 `VACUUM` 오버헤드를 피함.
- 드물게 쓰는 데이터를 더 저렴하거나 느린 스토리지로 이전 가능.

테이블 파티셔닝은 테이블이 그렇지 않으면 매우 커질 때만 가치가 있습니다. 이득이 생기는 정확한 지점은 애플리케이션에 따라 다르며, 테이블 크기가 서버 물리 메모리를 초과할 때가 좋은 추정치입니다. (상세: `11_애플리케이션프로그래밍/11_6_테이블파티셔닝/`)
