# SQL Profiler 사용 (Using SQL Profiler) — EPAS 18 성능 관리

> 원문: [EPAS v18 — Managing performance › Using SQL Profiler](https://www.enterprisedb.com/docs/epas/latest/managing_performance/03_sql_profiler/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 이름·명령은 원문 그대로 보존했습니다.

비효율적인 SQL 코드는 데이터베이스 성능 문제의 주요 요인입니다. 데이터베이스 관리자와 개발자에게 주어진 과제는 크고 복잡한 시스템 안에서 이러한 코드를 식별하고 개선하는 것입니다. SQL Profiler는 성능이 나쁜 SQL 코드를 찾아 최적화하는 것을 지원합니다.

## SQL Profiler의 주요 기능 및 이점

- **온디맨드 트레이스(On-demand traces)**. 파라미터를 수동으로 설정하고 트레이스를 시작하여 언제든지 SQL 트레이스를 캡처할 수 있습니다.

- **예약 트레이스(Scheduled traces)**. 현재 시점이 적절하지 않다면, 트레이스 파라미터를 지정하고 나중에 실행되도록 예약할 수도 있습니다.

- **트레이스 저장(Save traces)**. 트레이스를 실행하고 나중에 검토하기 위해 저장할 수 있습니다.

- **트레이스 필터(Trace filters)**. 데이터베이스별·사용자별로 SQL 캡처를 선택적으로 필터링하거나, 모든 사용자가 모든 데이터베이스에 대해 보낸 모든 SQL 문을 캡처할 수 있습니다.

- **트레이스 출력 분석기(Trace output analyzer)**. 그래픽 테이블을 통해 실행 시간(duration)이나 구문(statement)별로 쿼리를 빠르게 정렬·필터링할 수 있습니다. 그래픽 또는 텍스트 기반의 `EXPLAIN` 계획이 쿼리 경로와 조인을 보여 줍니다.

- **EDB Query Advisor 연동(EDB Query Advisor integration)**. 느린 쿼리를 찾아 최적화한 후, Query Advisor가 성능을 더욱 개선하기 위해 기반 테이블에 인덱스를 생성하도록 추천하게 할 수 있습니다.
