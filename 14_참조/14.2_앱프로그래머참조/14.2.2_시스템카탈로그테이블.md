# 시스템 카탈로그 테이블 (System catalog tables) — EPAS 18

> 원문: [EPAS v18 — Reference › Application programmer reference › System catalog tables](https://www.enterprisedb.com/docs/epas/latest/reference/application_programmer_reference/03_system_catalog_tables/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 테이블·컬럼 이름은 원문 그대로 보존했습니다.

다음 시스템 카탈로그 테이블은 데이터베이스 객체의 정의를 담고 있습니다. 시스템 테이블의 레이아웃은 변경될 수 있습니다. 시스템 테이블에 저장된 정보에 의존하는 애플리케이션을 작성하는 경우, 기존 카탈로그 뷰를 사용하거나 카탈로그 뷰를 생성하여 시스템 테이블 변경으로부터 애플리케이션을 격리하십시오.

## dual

`dual`은 Oracle 데이터베이스와의 호환성을 위해서만 제공되는 단일 행, 단일 컬럼 테이블입니다.

| 컬럼 | 타입 | 수정자 | 설명 |
|------|------|--------|------|
| `dummy` | `VARCHAR2(1)` | | 호환성을 위해서만 제공됨. |

## edb_dir

`edb_dir` 테이블은 `CREATE DIRECTORY` 명령으로 생성된 디렉터리를 가리키는 각 별칭(alias)마다 한 행을 포함합니다. 디렉터리는 사용자가 호스트 파일 시스템에 제한적으로 접근할 수 있게 하는 경로명의 별칭입니다.

디렉터리를 사용하여 사용자를 파일 시스템의 특정 디렉터리 트리 안에 제한할 수 있습니다. 예를 들어, `UTL_FILE` 패키지는 사용자가 호스트 파일 시스템의 파일과 디렉터리를 읽고 쓸 수 있는 함수를 제공합니다. 그러나 데이터베이스 관리자가 `CREATE DIRECTORY` 명령을 통해 접근 권한을 부여한 경로에만 접근을 허용합니다.

| 컬럼 | 타입 | 수정자 | 설명 |
|------|------|--------|------|
| `dirname` | `"name"` | `not null` | 별칭의 이름. |
| `dirowner` | `oid` | `not null` | 별칭을 소유한 사용자의 `OID`. |
| `dirpath` | `text` | | 접근이 부여된 디렉터리 이름. |
| `diracl` | `aclitem[]` | | 별칭에 접근할 수 있는 사용자를 결정하는 접근 제어 목록. |

## edb_password_history

`edb_password_history` 테이블은 각 비밀번호 변경마다 한 행을 포함합니다. 이 테이블은 클러스터의 모든 데이터베이스에 공유됩니다.

| 컬럼 | 타입 | 참조 | 설명 |
|------|------|------|------|
| `passhistroleid` | `oid` | `pg_authid.oid` | 역할의 `ID`. |
| `passhistpassword` | `text` | | `password_encryption`에 따라 암호화된 역할 비밀번호. |
| `passhistpasswordsetat` | `timestamptz` | | 비밀번호가 설정된 시각. |

## edb_policy

`edb_policy` 테이블은 각 정책마다 한 행을 포함합니다.

| 컬럼 | 타입 | 수정자 | 설명 |
|------|------|--------|------|
| `policyname` | `name` | `not null` | 정책 이름. |
| `policygroup` | `oid` | `not null` | 현재 사용되지 않음. |
| `policyobject` | `oid` | `not null` | 이 정책으로 보호되는 테이블의 `OID`(`object_schema` + `object_name`). |
| `policykind` | `char` | `not null` | 이 정책으로 보호되는 객체의 종류: 테이블은 'r', 뷰는 'v', 시노님은 =. 현재 항상 'r'. |
| `policyproc` | `oid` | `not null` | 정책 함수의 `OID`(`function_schema` + `policy_function`). |
| `policyinsert` | `boolean` | `not null` | 정책이 `INSERT` 문에 의해 적용되면 True. |
| `policyselect` | `boolean` | `not null` | 정책이 `SELECT` 문에 의해 적용되면 True. |
| `policydelete` | `boolean` | `not null` | 정책이 `DELETE` 문에 의해 적용되면 True. |
| `policyupdate` | `boolean` | `not null` | 정책이 `UPDATE` 문에 의해 적용되면 True. |
| `policyindex` | `boolean` | `not null` | 현재 사용되지 않음. |
| `policyenabled` | `boolean` | `not null` | 정책이 활성화되어 있으면 True. |
| `policyupdatecheck` | `boolean` | `not null` | `UPDATE` 문으로 갱신된 행이 정책을 만족해야 하면 True. |
| `policystatic` | `boolean` | `not null` | 현재 사용되지 않음. |
| `policytype` | `integer` | `not null` | 현재 사용되지 않음. |
| `policyopts` | `integer` | `not null` | 현재 사용되지 않음. |
| `policyseccols` | `int2vector` | `not null` | `sec_relevant_cols`에 나열된 컬럼의 컬럼 번호. |

## edb_profile

`edb_profile` 테이블은 사용 가능한 프로파일에 대한 정보를 저장합니다. `edb_profiles`는 클러스터의 모든 데이터베이스에 공유됩니다.

| 컬럼 | 타입 | 참조 | 설명 |
|------|------|------|------|
| `oid` | `oid` | | 행 식별자(숨김 속성. 명시적으로 선택해야 함). |
| `prfname` | `name` | | 프로파일의 이름. |
| `prffailedloginattempts` | `integer` | | 프로파일이 허용하는 실패한 로그인 시도 횟수. -1은 기본 프로파일 값 사용, -2는 실패한 로그인 시도에 제한 없음을 의미. |
| `prfpasswordlocktime` | `integer` | | 프로파일과 연관된 비밀번호 잠금 시간(초). -1은 기본 프로파일 값 사용, -2는 계정을 영구 잠금을 의미. |
| `prfpasswordlifetime` | `integer` | | 프로파일과 연관된 비밀번호 수명(초). -1은 기본 프로파일 값 사용, -2는 비밀번호가 만료되지 않음을 의미. |
| `prfpasswordgracetime` | `integer` | | 프로파일과 연관된 비밀번호 유예 시간(초). -1은 기본 프로파일 값 사용, -2는 비밀번호가 만료되지 않음을 의미. |
| `prfpasswordreusetime` | `integer` | | 비밀번호를 재사용하기 전에 사용자가 기다려야 하는 초. -1은 기본 프로파일 값 사용, -2는 이전 비밀번호를 재사용할 수 없음을 의미. |
| `prfpasswordreusemax` | `integer` | | 비밀번호를 재사용하기 전에 발생해야 하는 비밀번호 변경 횟수. -1은 기본 프로파일 값 사용, -2는 이전 비밀번호를 재사용할 수 없음을 의미. |
| `prfpasswordallowhashed` | `integer` | | 암호화된 비밀번호 사용 허용 여부를 지정. 가능한 값은 `true/on/yes/1`, `false/off/no/0`, `DEFAULT`. |
| `prfpasswordverifyfuncdb` | `oid` | `pg_database.oid` | 비밀번호 검증 함수가 존재하는 데이터베이스의 `OID`. |
| `prfpasswordverifyfunc` | `oid` | `pg_proc.oid` | 프로파일과 연관된 비밀번호 검증 함수의 `OID`. |

## edb_variable

`edb_variable` 테이블은 각 패키지 수준 변수(패키지에 선언된 각 변수)마다 한 행을 포함합니다.

| 컬럼 | 타입 | 수정자 | 설명 |
|------|------|--------|------|
| `varname` | `"name"` | `not null` | 변수의 이름. |
| `varpackage` | `oid` | `not null` | 패키지를 저장하는 `pg_namespace` 행의 `OID`. |
| `vartype` | `oid` | `not null` | 변수의 타입을 정의하는 `pg_type` 행의 `OID`. |
| `varaccess` | `"char"` | `not null` | 변수가 패키지 외부에서 보이면 `+`, 패키지 내에서만 보이면 `-`. 참고: 공용 변수는 패키지 헤더에 선언되고, 전용 변수는 패키지 본문에 선언됨. |
| `varsrc` | `text` | | 변수의 기본값 표현식을 포함한 변수 선언의 소스를 포함. |
| `varseq` | `smallint` | `not null` | 패키지에서 변수가 선언된 순서. |

## pg_synonym

`pg_synonym` 테이블은 `CREATE SYNONYM` 명령 또는 `CREATE PUBLIC SYNONYM` 명령으로 생성된 각 시노님마다 한 행을 포함합니다.

| 컬럼 | 타입 | 수정자 | 설명 |
|------|------|--------|------|
| `synname` | `"name"` | `not null` | 시노님의 이름. |
| `synnamespace` | `oid` | `not null` | `synowner`를 대체. 시노님이 저장된 `pg_namespace` 행의 `OID`를 포함. |
| `synowner` | `oid` | `not null` | 시노님을 소유한 사용자의 `OID`. |
| `synobjschema` | `"name"` | `not null` | 참조된 객체가 정의된 스키마. |
| `synobjname` | `"name"` | `not null` | 참조된 객체의 이름. |
| `synlink` | `text` | | 참조된 객체가 정의된 데이터베이스 링크의 선택적 이름. |

## product_component_version

`product_component_version` 테이블은 기능 호환성에 대한 정보를 포함합니다. 애플리케이션은 설치 중 또는 런타임에 이 테이블을 조회하여 애플리케이션이 사용하는 기능이 이 배포판에서 사용 가능한지 확인할 수 있습니다.

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `product` | `character varying(74)` | 제품의 이름. |
| `version` | `character varying(74)` | 제품의 버전 번호. |
| `status` | `character varying(74)` | 릴리스의 상태. |
