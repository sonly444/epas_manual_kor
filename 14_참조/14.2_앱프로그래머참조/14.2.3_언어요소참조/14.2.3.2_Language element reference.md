# Language element reference  — EPAS 18 언어 요소 참조

> 원문: [EPAS v18 — Reference › Application programmer reference › Language element reference › ECPGPlus statements](https://www.enterprisedb.com/docs/epas/latest/reference/application_programmer_reference/07_reference/ecpgplus_statements/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 문(statement) 이름·구문·키워드·코드는 원문 그대로 보존했습니다.

내장 SQL 문(embedded SQL statement)은 클라이언트 애플리케이션이 서버와 상호작용할 수 있게 합니다. 내장 지시자(embedded directive)는 ECPGPlus 컴파일러에 대한 명령입니다.

C 프로그램에 모든 EDB Postgres Advanced Server SQL 문을 내장할 수 있습니다. 각 문은 반드시 `EXEC SQL` 키워드로 시작하고 세미콜론(;)으로 종료해야 합니다. C 프로그램에서 SQL 문은 다음 형식을 취합니다.

```sql
EXEC SQL <sql_command_body>;
```

여기서 `sql_command_body`는 표준 SQL 문을 나타냅니다. SQL 문이 값 표현식을 기대하는 곳이면 어디든 호스트 변수를 사용할 수 있습니다.

ECPGPlus는 일부 문에 대해 PostgreSQL 서버 측 구문을 확장합니다. 구문 차이는 아래 참조 정보에 표시됩니다.

## ALLOCATE DESCRIPTOR

SQL 디스크립터 영역을 할당하려면 `ALLOCATE DESCRIPTOR` 문을 사용합니다.

```sql
EXEC SQL [FOR <array_size>] ALLOCATE DESCRIPTOR <descriptor_name>
    [WITH MAX <variable_count>];
```

여기서:

- `array_size`는 디스크립터에 할당할 배열 요소 수를 지정하는 변수입니다. `array_size`는 `INTEGER` 값이거나 호스트 변수일 수 있습니다.
- `descriptor_name`은 디스크립터의 이름을 포함하는 호스트 변수 또는 디스크립터의 이름입니다. 이 값은 식별자, 따옴표로 묶인 문자열 리터럴, 또는 호스트 변수 형식을 취할 수 있습니다.
- `variable_count`는 디스크립터의 최대 호스트 변수 수를 지정합니다. `variable_count`의 기본값은 `100`입니다.

다음 코드 조각은 배열 `(emp_array)`로 처리할 수 있는 `emp_query`라는 디스크립터를 할당합니다.

```sql
EXEC SQL FOR :emp_array ALLOCATE DESCRIPTOR emp_query;
```

## CALL

서버에서 프로시저나 함수를 호출하려면 `CALL` 문을 사용합니다. `CALL` 문은 EDB Postgres Advanced Server에서만 작동합니다. `CALL` 문은 두 가지 형식이 있습니다. 첫 번째 형식은 함수를 호출하는 데 사용됩니다.

```sql
EXEC SQL CALL <program_name> '('[<actual_arguments>]')'
  INTO [[:<ret_variable>][: <ret_indicator>]];
```

두 번째 형식은 프로시저를 호출하는 데 사용됩니다.

```sql
EXEC SQL CALL <program_name> '('[<actual_arguments>]')';
```

여기서:

- `program_name`은 `CALL` 문이 호출하는 저장 프로시저 또는 함수의 이름입니다. 프로그램 이름은 스키마 한정, 패키지 한정, 또는 둘 다 가능합니다. 프로그램이 위치한 스키마나 패키지를 지정하지 않으면 ECPGPlus는 `search_path` 값을 사용하여 프로그램을 찾습니다.
- `actual_arguments`는 프로그램이 요구하는 쉼표로 구분된 인수 목록을 지정합니다. 각 `actual_argument`는 프로그램이 기대하는 형식 인수(formal argument)에 대응합니다. 각 형식 인수는 `IN` 파라미터, `OUT` 파라미터, 또는 `INOUT` 파라미터일 수 있습니다.
- `:ret_variable`은 프로그램이 함수인 경우 반환되는 값을 받는 호스트 변수를 지정합니다.
- `:ret_indicator`는 프로그램이 함수인 경우 반환되는 인디케이터 값을 받는 호스트 변수를 지정합니다.

예를 들어, 다음 문은 `:ename` 호스트 변수에 포함된 값으로 `get_job_desc` 함수를 호출하고 그 함수가 반환한 값을 `:job` 호스트 변수에 캡처합니다.

```sql
EXEC SQL CALL get_job_desc(:ename)
  INTO :job;
```

## CLOSE

커서를 닫고 커서가 현재 사용 중인 리소스를 해제하려면 `CLOSE` 문을 사용합니다. 클라이언트 애플리케이션은 닫힌 커서에서 행을 페치할 수 없습니다. `CLOSE` 문의 구문은 다음과 같습니다.

```sql
EXEC SQL CLOSE [<cursor_name>];
```

여기서 `cursor_name`은 문에 의해 닫히는 커서의 이름입니다. 커서 이름은 식별자 또는 호스트 변수 형식을 취할 수 있습니다.

`OPEN` 문은 커서를 초기화합니다. 초기화되면, 커서를 다시 열지 않는 한 커서 결과 집합은 변경되지 않습니다. 커서를 다시 열기 전에 `CLOSE`할 필요는 없습니다.

`emp_cursor`라는 커서를 수동으로 닫으려면 다음 명령을 사용합니다.

```sql
EXEC SQL CLOSE emp_cursor;
```

애플리케이션이 종료되면 커서는 자동으로 닫힙니다.

## COMMIT

현재 트랜잭션을 완료하여 모든 변경 사항을 영구적으로 만들고 다른 사용자에게 보이게 하려면 `COMMIT` 문을 사용합니다. 구문은 다음과 같습니다.

```sql
EXEC SQL [AT <database_name>] COMMIT [WORK]
         [COMMENT <'text'>] [COMMENT <'text'> RELEASE];
```

여기서 `database_name`은 작업이 위치한 데이터베이스의 이름 또는 데이터베이스의 이름을 포함하는 호스트 변수입니다. 이 값은 따옴표 없는 문자열 리터럴 또는 호스트 변수 형식을 취할 수 있습니다.

호환성을 위해 ECPGPlus는 `COMMENT` 절을 오류 없이 받아들이지만 `COMMENT` 절에 포함된 텍스트를 저장하지 않습니다.

커밋 수행 후 현재 연결을 닫으려면 `RELEASE` 절을 포함합니다.

예를 들어, 다음 명령은 `dept` 데이터베이스에서 수행된 모든 작업을 커밋하고 현재 연결을 닫습니다.

```sql
EXEC SQL AT dept COMMIT RELEASE;
```

기본적으로 문은 클라이언트 애플리케이션이 `COMMIT` 문을 수행할 때만 커밋됩니다. 클라이언트 애플리케이션이 `AUTOCOMMIT` 기능을 호출하도록 지정하려면 ECPGPlus 호출 시 `-t` 옵션을 포함합니다. 다음 문으로 클라이언트 애플리케이션의 `AUTOCOMMIT` 기능을 제어할 수도 있습니다.

```sql
EXEC SQL SET AUTOCOMMIT TO ON
```

그리고

```sql
EXEC SQL SET AUTOCOMMIT TO OFF
```

## CONNECT

데이터베이스에 대한 연결을 설정하려면 `CONNECT` 문을 사용합니다. `CONNECT` 문은 두 가지 형식으로 제공됩니다. 하나는 Oracle 데이터베이스와 호환되고, 다른 하나는 그렇지 않습니다.

첫 번째 형식은 Oracle 데이터베이스와 호환됩니다.

```sql
EXEC SQL CONNECT
  {{:<user_name> IDENTIFIED BY :<password>}  | :<connection_id>}
  [AT <database_name>]
  [USING :database_string]
  [ALTER AUTHORIZATION :new_password];
```

여기서:

- `user_name`은 클라이언트 애플리케이션이 서버에 연결하는 데 사용하는 역할을 포함하는 호스트 변수입니다.
- `password`는 그 역할과 연관된 비밀번호를 포함하는 호스트 변수입니다.
- `connection_id`는 데이터베이스에 연결하는 데 사용되는 슬래시로 구분된 사용자 이름과 비밀번호를 포함하는 호스트 변수입니다.

연결이 설정되는 데이터베이스를 지정하려면 `AT` 절을 포함합니다. `database_name`은 클라이언트가 연결하는 데이터베이스의 이름입니다. 값을 변수 또는 문자열 리터럴 형식으로 지정합니다.

연결을 설정할 데이터베이스를 식별하는 null 종료 문자열을 포함하는 호스트 변수를 지정하려면 `USING` 절을 포함합니다.

`ALTER AUTHORIZATION` 절은 구문 호환성을 위해서만 지원됩니다. ECPGPlus는 `ALTER AUTHORIZATION` 절을 파싱하고 경고를 보고합니다.

`CONNECT` 문의 첫 번째 형식을 사용하여, 클라이언트 애플리케이션은 연결하는 역할의 신원을 포함하는 `user`라는 호스트 변수와 연관된 비밀번호를 포함하는 `password`라는 호스트 변수를 사용하여 다음 명령으로 연결을 설정할 수 있습니다.

```text
EXEC SQL CONNECT :user IDENTIFIED BY :password;
```

클라이언트 애플리케이션은 `:connection_id`라는 단일 호스트 변수를 사용하여 연결을 설정하는 데 `CONNECT` 문의 첫 번째 형식을 사용할 수도 있습니다. 다음 예에서 `connection_id`는 사용자의 슬래시로 구분된 역할 이름과 연관된 비밀번호를 포함합니다.

```sql
EXEC SQL CONNECT :connection_id;
```

`CONNECT` 문의 두 번째 형식의 구문은 다음과 같습니다.

```sql
EXEC SQL CONNECT TO <database_name>
[AS <connection_name>] [<credentials>];
```

여기서 `credentials`는 다음 중 하나입니다.

```sql
USER user_name password
USER user_name IDENTIFIED BY password
USER user_name USING password
```

두 번째 형식에서:

`database_name`은 클라이언트가 연결하는 데이터베이스의 이름 또는 신원입니다. `database_name`을 변수 또는 다음 형식 중 하나의 문자열 리터럴로 지정합니다.

```text
<database_name>[@<hostname>][:<port>]

tcp:postgresql://<hostname>[:<port>][/<database_name>][options]

unix:postgresql://<hostname>[:<port>][/<database_name>][options]
```

여기서:

- `hostname`은 데이터베이스가 위치한 서버의 이름 또는 IP 주소입니다.

- `port`는 서버가 수신 대기하는 포트입니다.

    기본 역할 이름을 사용하여 기본 데이터베이스와 연결을 설정하기 위해 `DEFAULT` 값을 지정할 수도 있습니다. 대상 데이터베이스로 `DEFAULT`를 지정하면 `connection_name`이나 `credentials`를 포함하지 마십시오.

- `connection_name`은 데이터베이스에 대한 연결의 이름입니다. `connection_name`은 식별자 형식(즉, 문자열 리터럴이나 변수가 아님)을 취합니다. 각 연결에 고유한 `connection_name`을 제공하여 여러 연결을 열 수 있습니다.

    연결 이름을 지정하지 않으면 `ecpglib`가 연결에 `DEFAULT`라는 이름을 할당합니다. 모든 `EXEC SQL` 문에서 이름(`DEFAULT`)으로 연결을 참조할 수 있습니다.

- `CURRENT`는 가장 최근에 열린 연결 또는 가장 최근의 `SET CONNECTION TO` 문에서 언급된 연결입니다. `EXEC SQL` 문에서 연결을 이름으로 참조하지 않으면 ECPG는 연결 이름을 `CURRENT`로 가정합니다.

- `user_name`은 EDB Postgres Advanced Server 데이터베이스와 연결을 설정하는 데 사용되는 역할입니다. 지정된 역할의 권한이 연결을 통해 수행되는 모든 명령에 적용됩니다.

- `password`는 지정된 `user_name`과 연관된 비밀번호입니다.

다음 코드 조각은 `CONNECT` 문의 두 번째 형식을 사용하여 역할 `alice`와 그 역할과 연관된 비밀번호 `1safepwd`를 사용하여 `edb`라는 데이터베이스에 연결을 설정합니다.

```sql
EXEC SQL CONNECT TO edb AS acctg_conn
  USER 'alice' IDENTIFIED BY '1safepwd';
```

연결의 이름은 `acctg_conn`입니다. `SET CONNECTION` 문을 사용하여 연결 이름을 변경할 때 연결 이름을 사용할 수 있습니다.

## DEALLOCATE DESCRIPTOR

할당된 디스크립터가 사용 중인 메모리를 해제하려면 `DEALLOCATE DESCRIPTOR` 문을 사용합니다. 문의 구문은 다음과 같습니다.

```sql
EXEC SQL DEALLOCATE DESCRIPTOR <descriptor_name>
```

여기서 `descriptor_name`은 디스크립터의 이름입니다. 이 값은 따옴표로 묶인 문자열 리터럴 또는 호스트 변수 형식을 취할 수 있습니다.

다음 예는 `emp_query`라는 디스크립터를 해제합니다.

```sql
EXEC SQL DEALLOCATE DESCRIPTOR emp_query;
```

## DECLARE CURSOR

커서를 정의하려면 `DECLARE CURSOR` 문을 사용합니다. 문의 구문은 다음과 같습니다.

```sql
EXEC SQL [AT <database_name>] DECLARE <cursor_name> CURSOR FOR
(<select_statement> | <statement_name>);
```

여기서:

- `database_name`은 커서가 작동하는 데이터베이스의 이름입니다. 이 값은 식별자 또는 호스트 변수 형식을 취할 수 있습니다. 데이터베이스 이름을 지정하지 않으면 `database_name`의 기본값은 기본 데이터베이스입니다.
- `cursor_name`은 커서의 이름입니다.
- `select_statement`은 커서 결과 집합을 정의하는 `SELECT` 문의 텍스트입니다. `SELECT` 문은 `INTO` 절을 포함할 수 없습니다.
- `statement_name`은 커서 결과 집합을 정의하는 SQL 문 또는 블록의 이름입니다.

다음 예는 `employees`라는 커서를 선언합니다.

```sql
EXEC SQL DECLARE employees CURSOR FOR
  SELECT
    empno, ename, sal, comm
  FROM
    emp;
```

커서는 `emp` 테이블에 저장된 각 직원 레코드에 대한 직원 번호, 직원 이름, 급여, 커미션을 포함하는 결과 집합을 생성합니다.

## DECLARE DATABASE

후속 SQL 문(예: `CONNECT` 문)에서 사용할 데이터베이스 식별자를 선언하려면 `DECLARE DATABASE` 문을 사용합니다. 구문은 다음과 같습니다.

```sql
EXEC SQL DECLARE <database_name> DATABASE;
```

여기서 `database_name`은 데이터베이스의 이름을 지정합니다.

다음 예는 `acctg` 데이터베이스에 대한 식별자를 선언하는 것을 보여줍니다.

```sql
EXEC SQL DECLARE acctg DATABASE;
```

`acctg`를 데이터베이스 식별자로 선언하는 명령을 호출한 후, 연결을 설정할 때 또는 `AT` 절에서 이름으로 `acctg` 데이터베이스를 참조할 수 있습니다.

이 문은 아무 효과가 없으며 Pro*C 호환성을 위해서만 제공됩니다.

## DECLARE STATEMENT

SQL 문에 대한 식별자를 선언하려면 `DECLARE STATEMENT` 지시자를 사용합니다. EDB Postgres Advanced Server는 `DECLARE STATEMENT` 지시자의 두 버전을 지원합니다.

```sql
EXEC SQL [<database_name>] DECLARE <statement_name> STATEMENT;
```

그리고

```sql
EXEC SQL DECLARE STATEMENT <statement_name>;
```

여기서:

- `statement_name`은 문과 연관된 식별자를 지정합니다.
- `database_name`은 데이터베이스의 이름을 지정합니다. 이 값은 식별자 또는 식별자를 포함하는 호스트 변수 형식을 취할 수 있습니다.

`DECLARE STATEMENT` 지시자를 포함하는 일반적인 사용 순서는 다음과 같습니다.

```sql
EXEC SQL DECLARE give_raise STATEMENT;      // give_raise is now a statement
handle (not prepared)
EXEC SQL PREPARE give_raise FROM :stmtText; // give_raise is now associated
with a statement
EXEC SQL EXECUTE give_raise;
```

이 문은 아무 효과가 없으며 Pro*C 호환성을 위해서만 제공됩니다.

## DELETE

테이블에서 하나 이상의 행을 삭제하려면 `DELETE` 문을 사용합니다. ECPGPlus `DELETE` 문의 구문은 SQL 문의 구문과 동일하지만, 표현식이 허용되는 곳이면 어디든 파라미터 마커와 호스트 변수를 사용할 수 있습니다. 구문은 다음과 같습니다.

```sql
[FOR <exec_count>] DELETE FROM [ONLY] <table> [[AS] <alias>]
  [USING <using_list>]
  [WHERE <condition> | WHERE CURRENT OF <cursor_name>]
  [{RETURNING|RETURN} * | <output_expression> [[AS] <output_name>]
[, ...] INTO <host_variable_list> ]
```

- 문이 실행되는 횟수를 지정하려면 `FOR exec_count` 절을 포함합니다. 이 절은 `VALUES` 절이 배열 또는 배열에 대한 포인터를 참조하는 경우에만 유효합니다.
- `table`은 기존 테이블의 (선택적으로 스키마 한정된) 이름입니다. 처리를 지정된 테이블로 제한하려면 `ONLY` 절을 포함합니다. `ONLY` 절을 포함하지 않으면 명명된 테이블에서 상속하는 테이블도 처리됩니다.
- `alias`는 대상 테이블의 대체 이름입니다.
- `using_list`는 테이블 표현식 목록으로, 다른 테이블의 컬럼이 `WHERE` 조건에 나타날 수 있게 합니다.
- 삭제할 행을 지정하려면 `WHERE` 절을 포함합니다. 문에 `WHERE` 절을 포함하지 않으면 `DELETE`는 테이블의 모든 행을 삭제하고 테이블 정의는 그대로 둡니다.
- `condition`은 `BOOLEAN` 타입 값을 반환하는 표현식, 호스트 변수, 또는 파라미터 마커입니다. `condition`이 true를 반환하는 행이 삭제됩니다.
- `cursor_name`은 `WHERE CURRENT OF` 절에서 사용할 커서의 이름입니다. 삭제할 행은 이 커서에서 가장 최근에 페치된 행입니다. 커서는 `DELETE` 문의 대상 테이블에 대한 비그룹화 쿼리여야 합니다. Boolean 조건을 포함하는 `DELETE` 문에서 `WHERE CURRENT OF`를 지정할 수 없습니다.

`RETURN/RETURNING` 절은 각 행이 삭제된 후 `DELETE` 명령이 반환하는 `output_expression` 또는 `host_variable_list`를 지정합니다.

- `output_expression`은 각 행이 삭제된 후 `DELETE` 명령이 계산하고 반환할 표현식입니다. `output_name`은 반환된 컬럼의 이름입니다. 모든 컬럼을 반환하려면 *를 포함합니다.
- `host_variable_list`는 호스트 변수와 선택적 인디케이터 변수의 쉼표로 구분된 목록입니다. 각 호스트 변수는 `RETURNING` 절에서 해당 값을 받습니다.

예를 들어, 다음 문은 `sal` 컬럼이 호스트 변수 `:max_sal`에 지정된 값보다 큰 값을 포함하는 `emp` 테이블의 모든 행을 삭제합니다.

```sql
DELETE FROM emp WHERE sal > :max_sal;
```

`DELETE` 문 사용에 대한 자세한 내용은 PostgreSQL 코어 문서를 참조하십시오.

## DESCRIBE

준비된 문(prepared statement)이 요구하는 입력 값의 수 또는 준비된 문이 반환하는 출력 값의 수를 찾으려면 `DESCRIBE` 문을 사용합니다. `DESCRIBE` 문은 애플리케이션을 작성하는 시점에 형태를 알 수 없는 SQL 문을 분석하는 데 사용됩니다.

`DESCRIBE` 문은 `SQLDA` 디스크립터를 채웁니다. SQL 디스크립터를 채우려면 `ALLOCATE DESCRIPTOR`와 `DESCRIBE...DESCRIPTOR` 문을 사용합니다.

```sql
EXEC SQL DESCRIBE BIND VARIABLES FOR <statement_name> INTO <descriptor>;
```

```sql
EXEC SQL DESCRIBE SELECT LIST FOR <statement_name> INTO <descriptor>;
```

여기서:

- `statement_name`은 준비된 SQL 문 또는 PL/SQL 블록과 연관된 식별자입니다.
- `descriptor`는 `SQLDA*` 타입의 C 변수 이름입니다. `sqlald()`를 호출하여 디스크립터를 위한 공간을 할당하고 `DESCRIBE` 문을 실행하기 전에 디스크립터를 초기화해야 합니다.

`DESCRIBE` 문의 첫 번째 형식을 실행하면, ECPG는 주어진 디스크립터를 문이 *요구하는* 각 입력 변수의 설명으로 채웁니다. 예를 들어, 두 개의 디스크립터가 주어진 경우:

```sql
SQLDA *query_values_in;
SQLDA *query_values_out;
```

`emp` 테이블에서 정보를 반환하는 쿼리를 준비할 수 있습니다.

```sql
EXEC SQL PREPARE get_emp FROM
  "SELECT ename, empno, sal FROM emp WHERE empno = ?";
```

명령은 파라미터 마커(?)를 위한 입력 변수 하나가 필요합니다.

```sql
EXEC SQL DESCRIBE BIND VARIABLES
  FOR get_emp INTO query_values_in;
```

이 문의 바인드 변수를 설명한 후, 디스크립터를 검사하여 필요한 변수 수와 각 변수의 타입을 찾을 수 있습니다.

두 번째 형식을 실행하면, ECPG는 주어진 디스크립터를 문이 반환하는 각 값의 설명으로 채웁니다. 예를 들어, 다음 문은 세 개의 값을 반환합니다.

```sql
EXEC SQL DESCRIBE SELECT LIST
  FOR get_emp INTO query_values_out;
```

이 문의 select 목록을 설명한 후, 디스크립터를 검사하여 반환된 값의 수와 각 값의 이름 및 타입을 찾을 수 있습니다.

문을 실행하기 전에 각 입력 값에 대한 변수와 각 출력 값에 대한 변수를 바인딩해야 합니다. 입력 값에 바인딩하는 변수는 문이 사용하는 실제 값을 지정합니다. 출력 값에 바인딩하는 변수는 문을 실행할 때 ECPGPlus에 값을 어디에 넣을지 알려줍니다.

이것은 `DESCRIBE DESCRIPTOR` 문에 대한 대체 Pro*C 호환 구문입니다.

## DESCRIBE DESCRIPTOR

SQL 문에 대한 정보를 검색하고 그 정보를 SQL 디스크립터에 저장하려면 `DESCRIBE DESCRIPTOR` 문을 사용합니다. `DESCRIBE DESCRIPTOR`를 사용하기 전에 `ALLOCATE DESCRIPTOR` 문으로 디스크립터를 할당해야 합니다. 구문은 다음과 같습니다.

```sql
EXEC SQL DESCRIBE [INPUT | OUTPUT] <statement_identifier>
  USING [SQL] DESCRIPTOR <descriptor_name>;
```

여기서:

- `statement_name`은 준비된 SQL 문의 이름입니다.
- `descriptor_name`은 디스크립터의 이름입니다. `descriptor_name`은 따옴표로 묶인 문자열 값 또는 디스크립터의 이름을 포함하는 호스트 변수일 수 있습니다.

`INPUT` 절을 포함하면, ECPGPlus는 주어진 디스크립터를 문이 요구하는 각 입력 변수의 설명으로 채웁니다.

예를 들어, 두 개의 디스크립터가 주어진 경우:

```sql
EXEC SQL ALLOCATE DESCRIPTOR query_values_in;
EXEC SQL ALLOCATE DESCRIPTOR query_values_out;
```

`emp` 테이블에서 정보를 반환하는 쿼리를 준비할 수 있습니다.

```sql
EXEC SQL PREPARE get_emp FROM
  "SELECT ename, empno, sal FROM emp WHERE empno = ?";
```

명령은 파라미터 마커(?)를 위한 입력 변수 하나가 필요합니다.

```sql
EXEC SQL DESCRIBE INPUT get_emp USING 'query_values_in';
```

이 문의 바인드 변수를 설명한 후, 디스크립터를 검사하여 필요한 변수 수와 각 변수의 타입을 찾을 수 있습니다.

`INPUT` 절을 지정하지 않으면, `DESCRIBE DESCRIPTOR`는 지정된 디스크립터를 문이 반환하는 값으로 채웁니다.

`OUTPUT` 절을 포함하면, ECPGPlus는 주어진 디스크립터를 문이 반환하는 각 값의 설명으로 채웁니다.

예를 들어, 다음 문은 세 개의 값을 반환합니다.

```sql
EXEC SQL DESCRIBE OUTPUT FOR get_emp USING 'query_values_out';
```

이 문의 select 목록을 설명한 후, 디스크립터를 검사하여 반환된 값의 수와 각 값의 이름 및 타입을 찾을 수 있습니다.

## DISCONNECT

서버에 대한 연결을 닫으려면 `DISCONNECT` 문을 사용합니다. 구문은 다음과 같습니다.

```sql
EXEC SQL DISCONNECT [<connection_name>][CURRENT][DEFAULT][ALL];
```

여기서 `connection_name`은 연결을 설정하는 데 사용된 `CONNECT` 문에 지정된 연결 이름입니다. 연결 이름을 지정하지 않으면 현재 연결이 닫힙니다.

ECPGPlus가 가장 최근에 사용한 연결을 닫도록 지정하려면 `CURRENT` 키워드를 포함합니다.

ECPGPlus가 `DEFAULT`라는 연결을 닫도록 지정하려면 `DEFAULT` 키워드를 포함합니다. 연결을 열 때 이름을 지정하지 않으면 ECPGPlus는 연결에 `DEFAULT` 이름을 할당합니다.

모든 활성 연결을 닫으려면 `ALL` 키워드를 포함합니다.

다음 예는 `hr` 데이터베이스에 연결하는 `hr_connection`이라는 연결을 만든 다음 그 연결에서 연결을 끊습니다.

```c
/* client.pgc*/
int main()
{
    EXEC SQL CONNECT TO hr AS connection_name;
    EXEC SQL DISCONNECT connection_name;
    return(0);
}
```

## EXECUTE

`EXEC SQL PREPARE` 문을 사용하여 이전에 준비된 문을 실행하려면 `EXECUTE` 문을 사용합니다. 구문은 다음과 같습니다.

```sql
EXEC SQL [FOR <array_size>] EXECUTE <statement_name>
  [USING {DESCRIPTOR <SQLDA_descriptor>
  |: <host_variable> [[INDICATOR] :<indicator_variable>]}];
```

여기서:

- `array_size`는 처리할 행 수를 지정하는 정수 값 또는 정수 값을 포함하는 호스트 변수입니다. `FOR` 절을 생략하면 배열의 각 멤버에 대해 한 번씩 문이 실행됩니다.
- `statement_name`은 `EXEC SQL PREPARE` 문을 사용하여 문이 생성될 때 문에 할당된 이름을 지정합니다.

준비된 문의 파라미터에 값을 제공하려면 `USING` 절을 포함합니다.

- 파라미터에 SQLDA 디스크립터 값을 제공하려면 `DESCRIPTOR` `SQLDA_descriptor` 절을 포함합니다.
- 파라미터에 사용자 지정 값을 제공하려면 `host_variable`(및 선택적 `indicator_variable`)을 사용합니다.

다음 예는 `emp` 테이블에 레코드를 삽입하는 준비된 문을 만듭니다.

```sql
EXEC SQL PREPARE add_emp (numeric, text, text, numeric) AS
    INSERT INTO emp VALUES($1, $2, $3, $4);
```

준비된 문을 호출할 때마다 문에 새로운 파라미터 값을 제공합니다.

```sql
EXEC SQL EXECUTE add_emp USING 8000, 'DAWSON', 'CLERK', 7788;
EXEC SQL EXECUTE add_emp USING 8001, 'EDWARDS', 'ANALYST', 7698;
```

## EXECUTE DESCRIPTOR

SQL 디스크립터를 사용하여 `EXEC SQL PREPARE` 문으로 이전에 준비된 문을 실행하려면 `EXECUTE` 문을 사용합니다. 구문은 다음과 같습니다.

```sql
EXEC SQL [FOR <array_size>] EXECUTE <statement_identifier>
  [USING [SQL] DESCRIPTOR <descriptor_name>]
  [INTO [SQL] DESCRIPTOR <descriptor_name>];
```

여기서:

- `array_size`는 처리할 행 수를 지정하는 정수 값 또는 정수 값을 포함하는 호스트 변수입니다. `FOR` 절을 생략하면 배열의 각 멤버에 대해 한 번씩 문이 실행됩니다.
- `statement_identifier`는 `EXEC SQL PREPARE` 문으로 문에 할당된 식별자를 지정합니다.
- `descriptor_name`은 디스크립터의 이름(작은따옴표로 묶인 문자열 리터럴로) 또는 디스크립터의 이름을 포함하는 호스트 변수를 지정합니다.

준비된 문이 요구하는 입력 파라미터에 값을 지정하려면 `USING` 절을 포함합니다.

준비된 문이 반환한 결과를 `EXECUTE` 문이 기록할 디스크립터를 지정하려면 `INTO` 절을 포함합니다.

다음 예는 디스크립터 `stmtText`에 포함된 값을 사용하여 준비된 문 `give_raise`를 실행합니다.

```sql
EXEC SQL PREPARE give_raise FROM :stmtText;
EXEC SQL EXECUTE give_raise USING DESCRIPTOR :stmtText;
```

## EXECUTE...END EXEC

익명 블록(anonymous block)을 클라이언트 애플리케이션에 내장하려면 `EXECUTE…END-EXEC` 문을 사용합니다. 구문은 다음과 같습니다.

```sql
EXEC SQL [AT <database_name>] EXECUTE <anonymous_block> END-EXEC;
```

여기서:

- `database_name`은 데이터베이스 식별자 또는 데이터베이스 식별자를 포함하는 호스트 변수입니다. `AT` 절을 생략하면 문은 현재 기본 데이터베이스에서 실행됩니다.
- `anonymous_block`은 PL/pgSQL 또는 SPL 문과 선언의 인라인 시퀀스입니다. 블록에 호스트 변수와 선택적 인디케이터 변수를 포함할 수 있습니다. 그러한 각 변수는 `IN/OUT` 값으로 처리됩니다.

다음 예는 익명 블록을 실행합니다.

```sql
EXEC SQL EXECUTE
  BEGIN
    IF (current_user = :admin_user_name) THEN
      DBMS_OUTPUT.PUT_LINE('You are an administrator');
    END IF;
END-EXEC;
```

**참고:** `EXECUTE…END EXEC` 문은 EDB Postgres Advanced Server에서만 지원됩니다.

## EXECUTE IMMEDIATE

SQL 명령을 포함하는 문자열을 실행하려면 `EXECUTE IMMEDIATE` 문을 사용합니다. 구문은 다음과 같습니다.

```sql
EXEC SQL [AT <database_name>] EXECUTE IMMEDIATE <command_text>;
```

여기서:

- `database_name`은 데이터베이스 식별자 또는 데이터베이스 식별자를 포함하는 호스트 변수입니다. `AT` 절을 생략하면 문은 현재 기본 데이터베이스에서 실행됩니다.
- `command_text`는 `EXECUTE IMMEDIATE` 문이 실행하는 명령입니다.

이 동적 SQL 문은 클라이언트 애플리케이션을 작성할 때 SQL 문의 텍스트를 모르는 경우에 유용합니다. 예를 들어, 클라이언트 애플리케이션이 신뢰할 수 있는 사용자에게 실행할 문을 프롬프트할 수 있습니다. 사용자가 문의 텍스트를 문자열 값으로 제공한 후, `EXECUTE IMMEDIATE` 명령으로 문이 실행됩니다.

문 텍스트는 호스트 변수에 대한 참조를 포함할 수 없습니다. 문이 파라미터 마커를 포함하거나 하나 이상의 값을 반환할 수 있으면 `PREPARE`와 `DESCRIBE` 문을 사용합니다.

다음 예는 `:command_text` 호스트 변수에 포함된 명령을 실행합니다.

```sql
EXEC SQL EXECUTE IMMEDIATE :command_text;
```

## FETCH

커서에서 SQLDA 디스크립터 또는 호스트 변수의 대상 목록으로 행을 반환하려면 `FETCH` 문을 사용합니다. `FETCH` 문을 사용하여 커서에서 정보를 검색하기 전에 `DECLARE`와 `OPEN` 문을 사용하여 커서를 준비해야 합니다. 문 구문은 다음과 같습니다.

```sql
EXEC SQL [FOR <array_size>] FETCH <cursor>
  { USING DESCRIPTOR <SQLDA_descriptor> }|{ INTO <target_list> };
```

여기서:

- `array_size`는 페치할 행 수를 지정하는 정수 값 또는 정수 값을 포함하는 호스트 변수입니다. `FOR` 절을 생략하면 배열의 각 멤버에 대해 한 번씩 문이 실행됩니다.
- `cursor`는 행을 페치하는 커서의 이름 또는 커서의 이름을 포함하는 호스트 변수입니다.

`USING` 절을 포함하면 `FETCH` 문은 지정된 SQLDA 디스크립터를 서버가 반환한 값으로 채웁니다.

`INTO` 절을 포함하면 `FETCH` 문은 `target_list`에 지정된 호스트 변수(및 선택적 인디케이터 변수)를 채웁니다.

다음 코드 조각은 `emp` 테이블에서 `직원 번호`, `이름`, `급여`를 검색하는 `employees`라는 커서를 선언합니다.

```sql
EXEC SQL DECLARE employees CURSOR FOR
    SELECT empno, ename, esal FROM emp;
EXEC SQL OPEN emp_cursor;
EXEC SQL FETCH emp_cursor INTO :emp_no, :emp_name, :emp_sal;
```

## FETCH DESCRIPTOR

커서에서 SQL 디스크립터로 행을 검색하려면 `FETCH DESCRIPTOR` 문을 사용합니다. 구문은 다음과 같습니다.

```sql
EXEC SQL [FOR <array_size>] FETCH <cursor>
  INTO [SQL] DESCRIPTOR <descriptor_name>;
```

여기서:

- `array_size`는 페치할 행 수를 지정하는 정수 값 또는 정수 값을 포함하는 호스트 변수입니다. `FOR` 절을 생략하면 배열의 각 멤버에 대해 한 번씩 문이 실행됩니다.
- `cursor`는 행을 페치하는 커서의 이름 또는 커서의 이름을 포함하는 호스트 변수입니다. 클라이언트는 `FETCH DESCRIPTOR` 문을 호출하기 전에 커서를 `DECLARE`하고 `OPEN`해야 합니다.
- `descriptor_name`은 디스크립터의 이름(작은따옴표로 묶인 문자열 리터럴로) 또는 디스크립터의 이름을 포함하는 호스트 변수를 지정합니다. 사용 전에 디스크립터는 `ALLOCATE DESCRIPTOR` 문을 사용하여 할당되어야 합니다.

준비된 문이 반환한 결과를 `EXECUTE` 문이 기록할 SQL 디스크립터를 지정하려면 `INTO` 절을 포함합니다.

다음 예는 결과 집합의 특정 행의 설명과 값을 담는 `row_desc`라는 디스크립터를 할당합니다. 그런 다음 준비된 문(`my_cursor`)에 대한 커서를 선언하고 열고, 결과 집합의 행을 반복하면서 `FETCH`를 사용하여 커서에서 다음 행을 디스크립터로 검색합니다.

```sql
EXEC SQL ALLOCATE DESCRIPTOR 'row_desc';
EXEC SQL DECLARE my_cursor CURSOR FOR query;
EXEC SQL OPEN my_cursor;

for( row = 0; ; row++ )
{
  EXEC SQL BEGIN DECLARE SECTION;
    int col;
EXEC SQL END DECLARE SECTION;
EXEC SQL FETCH my_cursor INTO SQL DESCRIPTOR 'row_desc';
```

## GET DESCRIPTOR

디스크립터에서 정보를 검색하려면 `GET DESCRIPTOR` 문을 사용합니다. `GET DESCRIPTOR` 문은 두 가지 형식이 있습니다. 첫 번째 형식은 디스크립터의 값(또는 컬럼)의 수를 반환합니다.

```sql
EXEC SQL GET DESCRIPTOR <descriptor_name>
  :<host_variable> = COUNT;
```

두 번째 형식은 특정 값(`VALUE column_number` 절로 지정)에 대한 정보를 반환합니다.

```sql
EXEC SQL [FOR <array_size>] GET DESCRIPTOR <descriptor_name>
  VALUE <column_number> {:<host_variable> = <descriptor_item> {,…}};
```

여기서:

- `array_size`는 처리할 행 수를 지정하는 정수 값 또는 정수 값을 포함하는 호스트 변수입니다. `array_size`를 지정하면 `host_variable`은 그 크기의 배열이어야 합니다. 예를 들어 `array_size`가 `10`이면 `:host_variable`은 10개 멤버의 `host_variables` 배열이어야 합니다. `FOR` 절을 생략하면 배열의 각 멤버에 대해 한 번씩 문이 실행됩니다.
- `descriptor_name`은 디스크립터의 이름을 작은따옴표로 묶인 문자열 리터럴 또는 디스크립터의 이름을 포함하는 호스트 변수로 지정합니다.

디스크립터에서 검색되는 정보를 지정하려면 `VALUE` 절을 포함합니다.

- `column_number`는 디스크립터에서 변수의 위치를 식별합니다.
- `host_variable`은 항목의 값을 받는 호스트 변수의 이름을 지정합니다.
- `descriptor_item`은 검색된 디스크립터 항목의 타입을 지정합니다.

ECPGPlus는 다음 `descriptor_item` 타입을 구현합니다.

- `TYPE`
- `LENGTH`
- `OCTET_LENGTH`
- `RETURNED_LENGTH`
- `RETURNED_OCTET_LENGTH`
- `PRECISION`
- `SCALE`
- `NULLABLE`
- `INDICATOR`
- `DATA`
- `NAME`

다음 코드 조각은 `GET DESCRIPTOR` 문을 사용하여 사용자가 제공한 문자열에 입력된 컬럼 수를 얻는 것을 보여줍니다.

```sql
EXEC SQL ALLOCATE DESCRIPTOR parse_desc;
EXEC SQL PREPARE query FROM :stmt;
EXEC SQL DESCRIBE query INTO SQL DESCRIPTOR parse_desc;
EXEC SQL GET DESCRIPTOR parse_desc :col_count = COUNT;
```

예제는 사용자가 제공한 문자열 `:stmt`의 구문을 확인하기 위해 `PREPARE` 문을 사용하기 전에 `parse_desc`라는 SQL 디스크립터를 할당합니다. `DESCRIBE` 문은 사용자가 제공한 문자열을 디스크립터 `parse_desc`로 이동합니다. `EXEC SQL GET DESCRIPTOR` 호출은 디스크립터를 조회하여 결과 집합의 컬럼 수 `(:col_count)`를 알아냅니다.

## INSERT

테이블에 하나 이상의 행을 추가하려면 `INSERT` 문을 사용합니다. ECPGPlus `INSERT` 문의 구문은 SQL 문의 구문과 동일하지만, 값이 허용되는 곳이면 어디든 파라미터 마커와 호스트 변수를 사용할 수 있습니다. 구문은 다음과 같습니다.

```sql
[FOR <exec_count>] INSERT INTO <table> [(<column> [, ...])]
  {DEFAULT VALUES |
   VALUES ({<expression> | DEFAULT} [, ...])[, ...] | <query>}
  [RETURNING * | <output_expression> [[ AS ] <output_name>] [, ...]]
```

문이 실행되는 횟수를 지정하려면 `FOR exec_count` 절을 포함합니다. 이 절은 `VALUES` 절이 배열 또는 배열에 대한 포인터를 참조하는 경우에만 유효합니다.

- `table`은 기존 테이블의 (선택적으로 스키마 한정된) 이름을 지정합니다.
- `column`은 테이블의 컬럼 이름입니다. 컬럼 이름은 서브필드 이름 또는 배열 첨자로 한정될 수 있습니다. 모든 컬럼에 기본값을 사용하려면 `DEFAULT VALUES` 절을 지정합니다.
- `expression`은 해당 컬럼에 할당되는 표현식, 값, 호스트 변수, 또는 파라미터 마커입니다. 해당 컬럼을 기본값으로 채우려면 `DEFAULT`를 지정합니다.
- `query`는 삽입할 행을 제공하는 `SELECT` 문을 지정합니다.
- `output_expression`은 각 행이 삽입된 후 `INSERT` 명령이 계산하고 반환하는 표현식입니다. 표현식은 테이블의 모든 컬럼을 참조할 수 있습니다. 삽입된 행의 모든 컬럼을 반환하려면 *를 지정합니다.
- `output_name`은 반환된 컬럼에 사용할 이름을 지정합니다.

다음 예는 `employees` 테이블에 행을 추가합니다.

```sql
INSERT INTO emp (empno, ename, job, hiredate)
    VALUES ('8400', :ename, 'CLERK', '2011-10-31');
```

**참고:** `INSERT` 문은 `ename` 컬럼의 값을 지정하는 데 호스트 변수 `:ename`을 사용합니다.

`INSERT` 문 사용에 대한 자세한 내용은 PostgreSQL 코어 문서를 참조하십시오.

## OPEN

커서를 열려면 `OPEN` 문을 사용합니다. 구문은 다음과 같습니다.

```sql
EXEC SQL [FOR <array_size>] OPEN <cursor> [USING <parameters>];
```

`parameters`는 다음 중 하나입니다.

```sql
DESCRIPTOR <SQLDA_descriptor>
```

또는

```sql
<host_variable> [ [ INDICATOR ] <indicator_variable>, … ]
```

여기서:

- `array_size`는 페치할 행 수를 지정하는 정수 값 또는 정수 값을 포함하는 호스트 변수입니다. `FOR` 절을 생략하면 배열의 각 멤버에 대해 한 번씩 문이 실행됩니다.
- `cursor`는 열리는 커서의 이름입니다.
- `parameters`는 `DESCRIPTOR SQLDA_descriptor` 또는 커서를 초기화하는 `host variables`와 선택적 `indicator variables`의 쉼표로 구분된 목록입니다. `SQLDA_descriptor`를 지정하는 경우 디스크립터는 `DESCRIBE` 문으로 초기화되어야 합니다.

`OPEN` 문은 `parameters`에 제공된 값을 사용하여 커서를 초기화합니다. 초기화되면, 커서가 닫히고 다시 열리지 않는 한 커서 결과 집합은 변경되지 않습니다. 애플리케이션이 종료되면 커서는 자동으로 닫힙니다.

다음 예는 `emp` 테이블을 쿼리하는 `employees`라는 커서를 선언합니다. 이름이 호스트 변수 `:emp_name`에 저장된 사용자 제공 값과 일치하는 직원의 `직원 번호`, `이름`, `급여`, `커미션`을 반환합니다.

```sql
EXEC SQL DECLARE employees CURSOR FOR
  SELECT
    empno, ename, sal, comm
  FROM
    emp
  WHERE ename = :emp_name;
EXEC SQL OPEN employees;
...
```

커서를 선언한 후, 예제는 `OPEN` 문을 사용하여 커서의 내용을 클라이언트 애플리케이션에서 사용할 수 있게 합니다.

## OPEN DESCRIPTOR

SQL 디스크립터로 커서를 열려면 `OPEN DESCRIPTOR` 문을 사용합니다. 구문은 다음과 같습니다.

```sql
EXEC SQL [FOR <array_size>] OPEN <cursor>
  [USING [SQL] DESCRIPTOR <descriptor_name>]
  [INTO [SQL] DESCRIPTOR <descriptor_name>];
```

여기서:

- `array_size`는 페치할 행 수를 지정하는 정수 값 또는 정수 값을 포함하는 호스트 변수입니다. `FOR` 절을 생략하면 배열의 각 멤버에 대해 한 번씩 문이 실행됩니다.
- `cursor`는 열리는 커서의 이름입니다.
- `descriptor_name`은 커서를 초기화하는 쿼리를 포함하는 SQL 디스크립터의 이름을 작은따옴표로 묶인 문자열 리터럴 형식 또는 SQL 디스크립터의 이름을 포함하는 호스트 변수로 지정합니다.

예를 들어, 다음 문은 호스트 변수 `:employees`를 사용하여 `emp_cursor`라는 커서를 엽니다.

```sql
EXEC SQL OPEN emp_cursor USING DESCRIPTOR :employees;
```

## PREPARE

준비된 문(prepared statement)은 클라이언트 애플리케이션이 작업을 여러 번 수행해야 할 때 유용합니다. 문은 실행될 때마다가 아니라 한 번만 파싱, 작성, 계획됩니다. 이 방식은 반복적인 처리 시간을 절약합니다.

SQL 문 또는 PL/pgSQL 블록을 실행을 위해 준비하려면 `PREPARE` 문을 사용합니다. 이 문은 두 가지 형식으로 제공됩니다. 첫 번째 형식은 다음과 같습니다.

```sql
EXEC SQL [AT <database_name>] PREPARE <statement_name>
  FROM <sql_statement>;
```

두 번째 형식은 다음과 같습니다.

```sql
EXEC SQL [AT <database_name>] PREPARE <statement_name>
  AS <sql_statement>;
```

여기서:

- `database_name`은 문이 실행되는 데이터베이스 식별자 또는 데이터베이스 식별자를 포함하는 호스트 변수입니다. `AT` 절을 생략하면 문은 현재 기본 데이터베이스에 대해 실행됩니다.
- `statement_name`은 준비된 SQL 문 또는 PL/SQL 블록과 연관된 식별자입니다.
- `sql_statement`는 `SELECT` 문, 작은따옴표로 묶인 문자열 리터럴, 또는 SQL 문의 텍스트를 포함하는 호스트 변수 형식을 취할 수 있습니다.

준비된 문에 변수를 포함하려면, `PREPARE`할 때 변경될 수 있는 문 값에 대해 자리 표시자(`$1, $2, $3` 등)를 대체합니다. 문을 `EXECUTE`할 때 각 파라미터에 값을 제공합니다. 자리 표시자를 대체하는 순서대로 값을 제공합니다.

다음 예는 `emp` 테이블에 레코드를 삽입하는 `add_emp`라는 준비된 문을 만듭니다.

```sql
EXEC SQL PREPARE add_emp (int, text, text, numeric) AS
    INSERT INTO emp VALUES($1, $2, $3, $4);
```

문을 호출할 때마다 문에 새로운 파라미터 값을 제공합니다.

```sql
EXEC SQL EXECUTE add_emp(8003, 'Davis', 'CLERK', 2000.00);
EXEC SQL EXECUTE add_emp(8004, 'Myer', 'CLERK', 2000.00);
```

**참고:** 클라이언트 애플리케이션은 문이 실행되는 각 세션에서 `PREPARE` 문을 발행해야 합니다. 준비된 문은 현재 세션 동안만 지속됩니다.

## ROLLBACK

현재 트랜잭션을 중단하고 트랜잭션이 수행한 모든 갱신을 폐기하려면 `ROLLBACK` 문을 사용합니다. 구문은 다음과 같습니다.

```sql
EXEC SQL [AT <database_name>] ROLLBACK [WORK]
  [ { TO [SAVEPOINT] <savepoint> } | RELEASE ]
```

여기서 `database_name`은 문이 실행되는 데이터베이스 식별자 또는 데이터베이스 식별자를 포함하는 호스트 변수입니다. `AT` 절을 생략하면 문은 현재 기본 데이터베이스에 대해 실행됩니다.

지정된 `savepoint` 이후에 실행된 명령을 중단하려면 `TO` 절을 포함합니다. `SAVEPOINT` 문을 사용하여 `savepoint`를 정의합니다. `TO` 절을 생략하면 `ROLLBACK` 문은 트랜잭션을 중단하고 모든 갱신을 폐기합니다.

애플리케이션이 `EXEC SQL COMMIT RELEASE`를 실행하고 연결을 닫도록 하려면 `RELEASE` 절을 포함합니다.

전체 트랜잭션을 롤백하려면 다음 문을 사용합니다.

```sql
EXEC SQL ROLLBACK;
```

이 문을 호출하면 트랜잭션이 중단되어 모든 변경 사항이 취소되고 모든 savepoint가 지워지며 모든 트랜잭션 잠금이 해제됩니다. savepoint를 포함한다고 가정합니다(다음 예의 `my_savepoint`).

```sql
EXEC SQL ROLLBACK TO SAVEPOINT my_savepoint;
```

`my_savepoint` 이후에 발생한 트랜잭션의 부분만 롤백됩니다. `my_savepoint`는 유지되지만, `my_savepoint` 이후에 생성된 모든 savepoint는 지워집니다.

지정된 savepoint로 롤백하면 savepoint 이후에 획득한 모든 잠금이 해제됩니다.

## SAVEPOINT

*savepoint*를 정의하려면 `SAVEPOINT` 문을 사용합니다. savepoint는 트랜잭션의 마커입니다. `ROLLBACK` 문을 사용하여 현재 트랜잭션을 중단하고 서버의 상태를 지정된 savepoint 이전 조건으로 되돌릴 수 있습니다. `SAVEPOINT` 문의 구문은 다음과 같습니다.

```sql
EXEC SQL [AT <database_name>] SAVEPOINT <savepoint_name>
```

여기서:

- `database_name`은 savepoint가 위치한 데이터베이스 식별자 또는 데이터베이스 식별자를 포함하는 호스트 변수입니다. `AT` 절을 생략하면 문은 현재 기본 데이터베이스에 대해 실행됩니다.
- `savepoint_name`은 savepoint의 이름입니다. `savepoint_name`을 재사용하면 원래 savepoint가 폐기됩니다.

savepoint는 트랜잭션 블록에서만 설정할 수 있습니다. 트랜잭션 블록은 여러 savepoint를 포함할 수 있습니다.

`my_savepoint`라는 savepoint를 만들려면 다음 문을 포함합니다.

```sql
EXEC SQL SAVEPOINT my_savepoint;
```

## SELECT

ECPGPlus는 `INTO host_variables` 절을 제공하여 `SQL SELECT` 문의 지원을 확장합니다. 이 절은 EDB Postgres Advanced Server 데이터베이스에서 지정된 정보를 호스트 변수로 선택할 수 있게 합니다. `SELECT` 문의 구문은 다음과 같습니다.

```sql
EXEC SQL [AT <database_name>]
SELECT
  [ <hint> ]
  [ ALL | DISTINCT [ ON( <expression>, ...) ]]
  select_list INTO <host_variables>
  
  [ FROM from_item [, from_item ]...]
  [ WHERE condition ]
  [ hierarchical_query_clause ]
  [ GROUP BY expression [, ...]]
  [ HAVING condition ]
  [ { UNION [ ALL ] | INTERSECT | MINUS } (subquery) ]
  [ ORDER BY expression [order_by_options]]
  [ LIMIT { count | ALL }]
  [ OFFSET start [ ROW | ROWS ] ]
  [ FETCH { FIRST | NEXT } [ count ] { ROW | ROWS } ONLY ]
  [ FOR { UPDATE | SHARE } [OF table_name [, ...]][NOWAIT ][...]]
```

여기서:

- `database_name`은 테이블이 위치한 데이터베이스의 이름 또는 데이터베이스의 이름을 포함하는 호스트 변수입니다. 이 값은 따옴표 없는 문자열 리터럴 또는 호스트 변수 형식을 취할 수 있습니다.
- `host_variables`는 `SELECT` 문이 채우는 호스트 변수 목록입니다. `SELECT` 문이 단일 행 이상을 반환하면 `host_variables`는 배열이어야 합니다.

ECPGPlus는 PostgreSQL 코어 문서에 문서화된 대로 SQL `SELECT` 문의 추가 절을 지원합니다.

`INTO host_variables` 절을 사용하려면 `SELECT` 문을 지정할 때 정의된 호스트 변수의 이름을 포함합니다. 예를 들어, 다음 `SELECT` 문은 직원 이름과 급여 목록으로 `:emp_name`과 `:emp_sal` 호스트 변수를 채웁니다.

```sql
EXEC SQL SELECT ename, sal
  INTO :emp_name, :emp_sal
  FROM emp
  WHERE empno = 7988;
```

향상된 `SELECT` 문은 값이 허용되는 모든 절에 파라미터 마커(물음표)를 포함할 수도 있게 합니다. 예를 들어, 다음 쿼리는 `WHERE` 절에 파라미터 마커를 포함합니다.

```sql
SELECT * FROM emp WHERE dept_no = ?;
```

이 `SELECT` 문은 런타임에 `dept_no` 파라미터 마커에 값을 제공할 수 있게 합니다.

## SET CONNECTION

주어진 클라이언트 애플리케이션에서 둘 이상의 연결이 필요할 수 있는 이유는 최소 세 가지입니다.

- 서로 다른 문에 대해 서로 다른 권한을 원할 수 있습니다.
- 동일한 클라이언트에서 여러 데이터베이스와 상호작용해야 할 수 있습니다.
- 클라이언트 애플리케이션의 여러 실행 스레드는 연결을 동시에 공유할 수 없습니다.

`SET CONNECTION` 문의 구문은 다음과 같습니다.

```sql
EXEC SQL SET CONNECTION <connection_name>;
```

여기서 `connection_name`은 데이터베이스에 대한 연결의 이름입니다.

`SET CONNECTION` 문을 사용하려면 `CONNECT` 문의 두 번째 형식을 사용하여 데이터베이스에 대한 연결을 엽니다. `connection_name`을 지정하려면 `AS` 절을 포함합니다.

기본적으로 현재 스레드는 현재 연결을 사용합니다. 현재 스레드가 사용할 기본 연결을 지정하려면 `SET CONNECTION` 문을 사용합니다. 기본 연결은 연결 이름을 명시적으로 지정하지 않는 `EXEC SQL` 문을 실행할 때만 사용됩니다. 예를 들어, 다음 문은 `AT connection_name` 절을 포함하지 않으므로 기본 연결을 사용합니다.

```sql
EXEC SQL DELETE FROM emp;
```

이 문은 `AT connection_name` 절을 사용하여 연결 이름을 지정하므로 기본 연결을 사용하지 않습니다.

```sql
EXEC SQL AT acctg_conn DELETE FROM emp;
```

예를 들어, 클라이언트 애플리케이션이 다음 방식 중 하나를 사용하여 여러 연결을 만들고 유지한다고 가정합니다.

```sql
EXEC SQL CONNECT TO edb AS acctg_conn
  USER 'alice' IDENTIFIED BY 'acctpwd';
```

```sql
EXEC SQL CONNECT TO edb AS hr_conn
  USER 'bob' IDENTIFIED BY 'hrpwd';
```

`SET CONNECTION` 문으로 연결 간에 전환할 수 있습니다.

```sql
SET CONNECTION acctg_conn;
```

또는

```sql
SET CONNECTION hr_conn;
```

서버는 연결하는 클라이언트가 사용할 수 있는 권한을 결정할 때 연결과 연관된 권한을 사용합니다. `acctg_conn` 연결을 사용할 때 클라이언트는 역할 `alice`와 연관된 권한을 가집니다. `hr_conn`을 사용하여 연결할 때 클라이언트는 `bob`과 연관된 권한을 가집니다.

## SET DESCRIPTOR

호스트 변수 또는 정수 값 형식으로 클라이언트 애플리케이션이 제공한 정보를 사용하여 디스크립터 영역에 값을 할당하려면 `SET DESCRIPTOR` 문을 사용합니다. 이 문은 두 가지 형식으로 제공됩니다. 첫 번째 형식은 다음과 같습니다.

```sql
EXEC SQL [FOR <array_size>] SET DESCRIPTOR <descriptor_name>
  VALUE <column_number> <descriptor_item> = <host_variable>;
```

두 번째 형식은 다음과 같습니다.

```sql
EXEC SQL [FOR <array_size>] SET DESCRIPTOR <descriptor_name>
  COUNT = integer;
```

여기서:

- `array_size`는 페치할 행 수를 지정하는 정수 값 또는 정수 값을 포함하는 호스트 변수입니다. `FOR` 절을 생략하면 배열의 각 멤버에 대해 한 번씩 문이 실행됩니다.
- `descriptor_name`은 디스크립터의 이름을 작은따옴표로 묶인 문자열 리터럴 또는 디스크립터의 이름을 포함하는 호스트 변수로 지정합니다.

디스크립터에 저장된 정보를 설명하려면 `VALUE` 절을 포함합니다.

- `column_number`는 디스크립터 내에서 변수의 위치를 식별합니다.
- `descriptor_item`은 디스크립터 항목의 타입을 지정합니다.
- `host_variable`은 항목의 값을 포함하는 호스트 변수의 이름을 지정합니다.

ECPGPlus는 다음 `descriptor_item` 타입을 구현합니다.

- `TYPE`
- `LENGTH`
- `[REF] INDICATOR`
- `[REF] DATA`
- `[REF] RETURNED LENGTH`

예를 들어, 클라이언트 애플리케이션이 동적으로 생성된 쿼리에 대해 사용자에게 프롬프트할 수 있습니다.

```c
query_text = promptUser("Enter a query");
```

동적으로 생성된 쿼리를 실행하려면, 먼저 쿼리를 준비(쿼리 구문 파싱 및 검증)한 다음 `EXEC SQL DESCRIBE INPUT` 문을 사용하여 쿼리에서 발견된 입력 파라미터를 설명해야 합니다.

```sql
EXEC SQL ALLOCATE DESCRIPTOR query_params;
EXEC SQL PREPARE emp_query FROM :query_text;

EXEC SQL DESCRIBE INPUT emp_query
  USING SQL DESCRIPTOR 'query_params';
```

쿼리를 설명한 후, `query_params` 디스크립터는 쿼리가 요구하는 각 파라미터에 대한 정보를 포함합니다.

이 예에서는 사용자가 다음을 입력했다고 가정합니다.

```sql
SELECT ename FROM emp WHERE sal > ? AND job = ?;,
```

이 경우 디스크립터는 두 개의 파라미터를 설명합니다. 하나는 `sal > ?`, 다른 하나는 `job = ?`입니다.

쿼리의 파라미터 마커(물음표) 수, 따라서 쿼리를 실행하기 전에 제공해야 하는 값의 수를 알아내려면 다음을 사용합니다.

```sql
EXEC SQL GET DESCRIPTOR … :host_variable = COUNT;
```

그런 다음 `EXEC SQL GET DESCRIPTOR`를 사용하여 각 파라미터의 이름을 검색할 수 있습니다. `EXEC SQL GET DESCRIPTOR`를 사용하여 파라미터 수와 함께 디스크립터에서 각 파라미터의 타입을 검색할 수도 있습니다. 또는 각 `value`를 문자열 형식으로 제공하면 ECPG가 그 문자열을 필요한 데이터 타입으로 변환합니다.

첫 번째 파라미터의 데이터 타입은 `numeric`입니다. 두 번째 파라미터의 타입은 `varchar`입니다. 첫 번째 파라미터의 이름은 `sal`입니다. 두 번째 파라미터의 이름은 `job`입니다.

다음으로, 각 파라미터를 반복하면서 사용자에게 값을 프롬프트하고 그 값을 호스트 변수에 저장합니다. `GET DESCRIPTOR … COUNT`를 사용하여 쿼리의 파라미터 수를 찾을 수 있습니다.

```sql
EXEC SQL GET DESCRIPTOR 'query_params'
  :param_count = COUNT;

for(param_number = 1;
    param_number <= param_count;
    param_number++)
{
```

`GET DESCRIPTOR`를 사용하여 파라미터의 이름을 `param_name` 호스트 변수로 복사합니다.

```sql
EXEC SQL GET DESCRIPTOR 'query_params'
  VALUE :param_number :param_name = NAME;

reply = promptUser(param_name);
if (reply == NULL)
 reply_ind = 1; /* NULL */
else
 reply_ind = 0; /* NOT NULL */
```

각 파라미터에 `value`를 연결하려면 `EXEC SQL SET DESCRIPTOR` 문을 사용합니다. 예:

```sql
EXEC SQL SET DESCRIPTOR 'query_params'
  VALUE :param_number DATA = :reply;
EXEC SQL SET DESCRIPTOR 'query_params'
  VALUE :param_number INDICATOR = :reply_ind;
}
```

이제 `EXEC SQL EXECUTE DESCRIPTOR` 문을 사용하여 서버에서 준비된 문을 실행할 수 있습니다.

## UPDATE

테이블에 저장된 데이터를 수정하려면 `UPDATE` 문을 사용합니다. 구문은 다음과 같습니다.

```sql
EXEC SQL [AT <database_name>][FOR <exec_count>]
    UPDATE [ ONLY ] table [ [ AS ] alias ]
    SET {column = { expression | DEFAULT } |
        (column [, ...]) = ({ expression|DEFAULT } [, ...])} [, ...]
    [ FROM from_list ]
    [ WHERE condition | WHERE CURRENT OF cursor_name ]
    [ RETURNING * | output_expression [[ AS ] output_name] [, ...] ]
```

여기서 `database_name`은 테이블이 위치한 데이터베이스의 이름 또는 데이터베이스의 이름을 포함하는 호스트 변수입니다. 이 값은 따옴표 없는 문자열 리터럴 또는 호스트 변수 형식을 취할 수 있습니다.

문이 실행되는 횟수를 지정하려면 `FOR exec_count` 절을 포함합니다. 이 절은 `SET` 또는 `WHERE` 절이 배열을 포함하는 경우에만 유효합니다.

ECPGPlus는 PostgreSQL 코어 문서에 문서화된 대로 SQL `UPDATE` 문의 추가 절을 지원합니다.

값을 지정하는 모든 절에서 호스트 변수를 사용할 수 있습니다. 호스트 변수를 사용하려면 문서화된 `UPDATE` 절과 연관된 값에 정의된 변수를 대체합니다.

다음 `UPDATE` 문은 직원(`:ename` 호스트 변수로 식별)의 직무 설명을 `:new_job` 호스트 변수에 포함된 값으로 변경합니다. 현재 급여에 `:increase` 호스트 변수 값을 곱하여 직원의 급여를 인상합니다.

```sql
EXEC SQL UPDATE emp
  SET job = :new_job, sal = sal * :increase
  WHERE ename = :ename;
```

향상된 `UPDATE` 문은 입력 값이 허용되는 모든 절에 파라미터 마커(물음표)를 포함할 수도 있게 합니다. 예를 들어, `WHERE` 절에 파라미터 마커를 사용하여 같은 update 문을 작성할 수 있습니다.

```sql
EXEC SQL UPDATE emp
  SET job = ?, sal = sal * ?
  WHERE ename = :ename;
```

이 `UPDATE` 문은 `job` 컬럼의 새 값을 사용자에게 프롬프트하고 `:ename`으로 지정된 직원의 `sal` 컬럼을 증가시킬 양을 제공할 수 있게 합니다.

## WHENEVER

클라이언트 애플리케이션이 SQL 오류나 경고를 만났을 때 취하는 동작을 지정하려면 `WHENEVER` 문을 사용합니다. 구문은 다음과 같습니다.

```sql
EXEC SQL WHENEVER <condition> <action>;
```

다음 표는 `action`을 트리거할 수 있는 다양한 조건을 설명합니다.

| 조건 | 설명 |
|------|------|
| `NOT FOUND` | 서버는 행을 반환하지 않는 `SELECT`를 만나거나 `FETCH`가 결과 집합의 끝에 도달하면 `NOT FOUND` 조건을 반환합니다. |
| `SQLERROR` | 서버는 SQL 문이 반환한 심각한 오류를 만나면 `SQLERROR` 조건을 반환합니다. |
| `SQLWARNING` | 서버는 SQL 문이 반환한 치명적이지 않은 경고를 만나면 `SQLWARNING` 조건을 반환합니다. |

다음 표는 클라이언트가 `condition`을 만났을 때 발생하는 동작을 설명합니다.

| 동작 | 설명 |
|------|------|
| `CALL function [([args])]` | 명명된 `function`을 호출. |
| `CONTINUE` | 다음 문으로 진행. |
| `DO BREAK` | C break 문을 발행. break 문은 `loop` 또는 `switch` 문에 나타날 수 있음. 실행되면 break 문은 `loop` 또는 `switch` 문을 종료. |
| `DO CONTINUE` | C `continue` 문을 발행. `continue` 문은 루프에만 존재할 수 있음. 실행되면 제어 흐름이 루프 상단으로 돌아가게 함. |
| `DO function ([args])` | 명명된 `function`을 호출. |
| `GOTO label` 또는 `GO TO label` | label을 포함하는 문으로 진행. |
| `SQLPRINT` | 표준 오류에 메시지를 출력. |
| `STOP` | 실행 중지. |

다음 코드 조각은 클라이언트 애플리케이션이 경고를 만나면 메시지를 출력하고 오류를 만나면 애플리케이션을 중단합니다.

```sql
EXEC SQL WHENEVER SQLWARNING SQLPRINT;
EXEC SQL WHENEVER SQLERROR STOP;
```

문제를 사용자에게 경고한 후 클라이언트가 처리를 계속하도록 지정하려면 다음 코드를 포함합니다.

```sql
EXEC SQL WHENEVER SQLWARNING SQLPRINT;
```

쿼리가 행을 반환하지 않거나 커서가 결과 집합의 끝에 도달할 때 함수를 호출하려면 다음 코드를 포함합니다.

```sql
EXEC SQL WHENEVER NOT FOUND CALL error_handler(__LINE__);
```
