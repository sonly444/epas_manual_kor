# 대소문자 구분 (Case sensitivity) — EPAS 18 SPL 참조

> 원문: [EPAS v18 — SPL reference › Basic SPL elements › Case sensitivity](https://www.enterprisedb.com/docs/epas/latest/reference/application_programmer_reference/stored_procedural_language_reference/01_basic_spl_elements/02_case_sensitivity/)
> EPAS v18 공식 문서의 한글 전문 번역입니다. 코드·키워드·함수/파라미터 이름은 원문 그대로 보존했습니다.

SPL 프로그램의 키워드(keyword)와 사용자 정의 식별자(user-defined identifier)는 **대소문자를 구분하지 않습니다(case insensitive)**. 예를 들어 다음 문장은 모두 동일하게 해석됩니다.

```sql
DBMS_OUTPUT.PUT_LINE('Hello World');
dbms_output.put_line('Hello World');
Dbms_Output.Put_Line('Hello World');
DBMS_output.Put_line('Hello World');
```

반면에 문자(character) 상수와 문자열(string) 상수는 **대소문자를 구분합니다**. 또한 EDB Postgres Advanced Server 데이터베이스나 외부 소스에서 조회한 데이터도 대소문자가 그대로 유지됩니다.

다음 두 예제가 이 차이를 보여줍니다.

다음 문장은:

```sql
DBMS_OUTPUT.PUT_LINE('Hello World!');
```

다음을 출력합니다.

```
Hello World!
```

다음 문장은:

```sql
DBMS_OUTPUT.PUT_LINE('HELLO WORLD!');
```

다음을 출력합니다.

```
HELLO WORLD!
```

즉, 프로시저 이름과 그 사용 형태(대소문자)는 구분하지 않지만, 함수에 전달되는 실제 문자열 내용은 원래의 대소문자가 그대로 출력에 보존됩니다.
