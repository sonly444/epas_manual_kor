# EDB*Loader 제어 파일 파라미터 (EDB*Loader Control File Parameters) — EPAS 18 Reference

> 원문: [EPAS v18 — Reference › Database administrator reference › EDB*Loader control file parameters](https://www.enterprisedb.com/docs/epas/latest/reference/database_administrator_reference/edb_loader_control_file_parameters/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 파라미터·명령·코드 이름은 원문 그대로 보존했습니다.

[EDB*Loader 제어 파일을 작성](https://www.enterprisedb.com/docs/epas/latest/database_administration/02_edb_loader/building_the_control_file/)할 때 다음 파라미터를 사용합니다.

## OPTIONS param=value

`OPTIONS` 절을 사용하여 EDB*Loader 지시어(directive)를 나타내는 `param=value` 쌍을 지정합니다. `OPTIONS` 절과 `edbldr` 호출 시 명령줄 양쪽에 파라미터를 지정하면 명령줄 설정이 적용됩니다.

다음 파라미터/값 쌍 중 하나 이상을 지정합니다:

- `DIRECT= { FALSE | TRUE }`

`DIRECT`를 `TRUE`로 설정하면 EDB*Loader는 일반 경로 로드(conventional path load) 대신 직접 경로 로드(direct path load)를 수행합니다. `DIRECT`의 기본값은 `FALSE`입니다.

복제된 테이블에 데이터를 로드할 때는 `DIRECT=true`로 설정하지 마십시오. EDB*Loader로 복제된 테이블에 데이터를 로드하면서 `DIRECT=true`로 설정하면, 인덱스가 테이블에 있는 행을 누락하거나 삭제된 행에 대한 참조를 포함할 수 있습니다. 복제된 테이블에 데이터를 로드하는 직접 삽입(direct insert)은 지원되지 않습니다. 직접 경로 로드에 대한 정보는 [Direct path load](https://www.enterprisedb.com/docs/epas/latest/database_administration/02_edb_loader/invoking_edb_loader/direct_path_load/)를 참고하십시오.

- `ERRORS=error_count`

`error_count`는 EDB*Loader 세션을 중단하기 전에 허용되는 오류 수를 지정합니다. 기본값은 `50`입니다.

- `FREEZE= { FALSE | TRUE }`

`FREEZE`를 `TRUE`로 설정하면 행을 `frozen` 상태로 데이터를 복사합니다. 현재 및 미래의 모든 트랜잭션에 보이는 것이 보장된 튜플은 트랜잭션 ID 순환(wraparound)을 방지하기 위해 frozen으로 표시됩니다. frozen 튜플에 대한 자세한 내용은 [PostgreSQL 코어 문서](https://www.postgresql.org/docs/current/static/routine-vacuuming.html)를 참고하십시오.

`FREEZE` 옵션을 사용할 때는 제어 파일에서 데이터 로딩 유형으로 `TRUNCATE`를 지정해야 합니다. `FREEZE`는 직접 로딩에서는 지원되지 않습니다. 기본적으로 `FREEZE`는 `FALSE`입니다.

- `PARALLEL= { FALSE | TRUE }`

`PARALLEL`을 `TRUE`로 설정하면 이 EDB*Loader 세션이 병렬 직접 경로 로드에 참여하는 여러 동시 EDB*Loader 세션 중 하나임을 나타냅니다. `PARALLEL`의 기본값은 `FALSE`입니다.

`PARALLEL`이 `TRUE`일 때는 `DIRECT` 파라미터도 `TRUE`로 설정해야 합니다. 병렬 직접 경로 로드에 대한 자세한 내용은 [Parallel direct path load](https://www.enterprisedb.com/docs/epas/latest/database_administration/02_edb_loader/invoking_edb_loader/parallel_direct_path_load/)를 참고하십시오.

- `ROWS=n`

`n`은 다음 `n`개 행 세트를 로드하기 전에 EDB*Loader가 커밋하는 행 수를 지정합니다. `ROWS` 파라미터가 지정된 로드 중에 EDB*Loader가 유효하지 않은 행을 만나면, 오류를 만나기 전에 커밋된 행들은 대상 테이블에 남아 있습니다.

- `SKIP=skip_count`

`skip_count`는 로딩이 시작되기 전에 입력 데이터 파일 시작 부분에서 건너뛸 레코드 수를 지정합니다. 기본값은 `0`입니다.

- `SKIP_INDEX_MAINTENANCE={ FALSE | TRUE }`

`SKIP_INDEX_MAINTENANCE`가 `TRUE`이면 직접 경로 로드의 일부로 인덱스 유지 관리가 수행되지 않으며, 로드된 테이블의 인덱스가 유효하지 않음(invalid)으로 표시됩니다. `SKIP_INDEX_MAINTENANCE`의 기본값은 `FALSE`입니다.

##### 참고 (Note)

병렬 직접 경로 로드 중에는 대상 테이블 인덱스가 갱신되지 않습니다. 로드 완료 후 유효하지 않음으로 표시됩니다.

`REINDEX` 명령을 사용해 인덱스를 재구축할 수 있습니다. `REINDEX` 명령에 대한 자세한 내용은 [PostgreSQL 코어 문서](https://www.postgresql.org/docs/current/static/sql-reindex.html)를 참고하십시오.

## charset

`CHARACTERSET` 절을 사용하여 `data_file`의 문자 집합 인코딩을 식별합니다. 여기서 `charset`은 문자 집합 이름입니다. 데이터 파일 인코딩이 제어 파일 인코딩과 다르면 이 절이 필요합니다. 제어 파일 인코딩은 항상 `edbldr`이 호출되는 클라이언트의 인코딩이어야 합니다.

`charset` 설정 예로는 `UTF8`, `SQL_ASCII`, `SJIS`가 있습니다. 클라이언트-데이터베이스 문자 집합 변환에 대한 자세한 내용은 [PostgreSQL 코어 문서](https://www.postgresql.org/docs/current/static/multibyte.html)를 참고하십시오.

## data_file

`target_table`에 로드할 데이터를 포함하는 파일입니다. 데이터 파일의 각 레코드는 `target_table`에 삽입할 행에 해당합니다.

파일 이름에 확장자를 포함하지 않으면 EDB*Loader는 파일이 `.dat` 확장자를 가진다고 가정합니다(예: `mydatafile.dat`).

> **참고:** `edbldr` 호출 시 명령줄에 `DATA` 파라미터를 지정하면, 명령줄 `DATA` 파라미터가 제공하는 파일이 대신 사용됩니다. `INFILE` 절과 명령줄 `DATA` 파라미터를 모두 생략하면, 데이터 파일 이름은 제어 파일 이름과 같지만 `.dat` 확장자를 가진다고 가정합니다.

## stdin

로드할 데이터를 EDB*Loader에 직접 파이프하기 위해 표준 입력을 사용하려면 `stdin`(모두 소문자)을 지정합니다. 이 기법은 로드할 대량의 레코드를 생성하는 데이터 소스에 유용합니다.

## bad_file

오류로 인해 로드할 수 없는 `data_file` 레코드를 받는 파일입니다. bad 파일은 거부되거나 잘못된 레코드를 수집하기 위해 생성됩니다.

EDB Postgres Advanced Server 버전 12 이상에서는 잘못되거나 거부된 레코드가 있는 경우에만 bad 파일이 생성됩니다. 그러나 동일한 이름과 위치의 기존 bad 파일이 있고 새 버전의 `edbldr` 호출 후 bad 레코드가 생성되지 않으면 기존 bad 파일은 그대로 유지됩니다.

파일 이름에 확장자를 포함하지 않으면 EDB*Loader는 파일이 `.bad` 확장자를 가진다고 가정합니다(예: `mybadfile.bad`).

> **참고:** `edbldr` 호출 시 명령줄에 `BAD` 파라미터를 지정하면, 명령줄 `BAD` 파라미터가 제공하는 파일이 대신 사용됩니다.

## discard_file

어느 테이블에도 로드되지 않는 입력 데이터 레코드를 받는 파일입니다. 이 입력 데이터 레코드는 `WHEN` 절이 있는 테이블에 대한 선택 기준을 하나도 충족하지 못하고 `WHEN` 절이 없는 테이블이 없기 때문에 폐기됩니다. 모든 레코드는 `WHEN` 절이 없는 테이블의 선택 기준을 충족합니다.

파일 이름에 확장자를 포함하지 않으면 EDB*Loader는 파일이 `.dsc` 확장자를 가진다고 가정합니다(예: `mydiscardfile.dsc`).

> **참고:** `edbldr` 호출 시 명령줄에 `DISCARD` 파라미터를 지정하면, 명령줄 `DISCARD` 파라미터가 제공하는 파일이 대신 사용됩니다.

## max_discard_recs

EDB*Loader 세션을 종료하기 전에 입력 데이터 레코드가 만날 수 있는 최대 폐기 레코드 수입니다. `max_discard_recs`가 지정하는 정수 값 앞에 `DISCARDMAX`나 `DISCARDS` 키워드를 사용할 수 있습니다.

예를 들어 `max_discard_recs`가 `0`이면 첫 번째 폐기 레코드를 만났을 때 EDB*Loader 세션이 종료됩니다. `max_discard_recs`가 `1`이면 두 번째 폐기 레코드를 만났을 때 종료됩니다.

`max_discard_recs` 초과로 EDB*Loader 세션이 종료되면, 이전에 데이터베이스에 로드된 입력 데이터 레코드는 유지됩니다. 롤백되지 않습니다.

## INSERT, UPDATE, APPEND, REPLACE, TRUNCATE

대상 테이블에 데이터를 로드하는 방법을 지정합니다. `INSERT`, `APPEND`, `REPLACE`, `TRUNCATE` 중 하나를 지정하면 모든 테이블에 대한 기본 동작이 설정되어 기본값 `INSERT`를 재정의합니다.

- `INSERT`

데이터가 빈 테이블에 로드됩니다. 테이블이 처음에 비어 있지 않으면 EDB*Loader는 예외를 던지고 데이터를 로드하지 않습니다.

##### 참고 (Note)

테이블에 행이 있으면 EDB*Loader를 호출하기 전에 `TRUNCATE` 명령으로 테이블을 비워야 합니다. `TRUNCATE` 명령 대신 `DELETE` 명령으로 테이블을 비우면 EDB*Loader는 예외를 던집니다. Oracle SQL*Loader는 `DELETE`나 `TRUNCATE` 명령 중 하나로 테이블을 비우는 것을 허용합니다.

- `UPDATE`

입력 데이터의 키 컬럼을 기준으로 기존 테이블의 행을 찾아 지정한 컬럼 값을 갱신합니다. 매칭되는 행이 없으면 INSERT되지 않고 무시되며, 키 조건에 여러 행이 매칭되면 오류가 발생할 수 있습니다.

- `APPEND`

데이터가 테이블의 기존 행에 추가됩니다. 테이블은 처음에 비어 있을 수도 있습니다.

- `REPLACE`

`REPLACE`와 `TRUNCATE` 키워드는 기능적으로 동일합니다. EDB*Loader가 새 데이터를 로드하기 전에 테이블을 truncate합니다.

##### 참고 (Note)

`REPLACE` 연산의 결과로 테이블의 삭제 트리거는 발동되지 않습니다.

- `TRUNCATE`

EDB*Loader가 새 데이터를 로드하기 전에 테이블을 truncate합니다. `TRUNCATE` 연산의 결과로 테이블의 삭제 트리거는 발동되지 않습니다.

## PRESERVE BLANKS

`PRESERVE BLANKS` 옵션은 구분(delimited) 필드와 미리 정해진 크기 필드 모두에 대해 앞뒤 공백을 유지합니다.

`NO PRESERVE BLANKS`의 경우, 필드가 구분되면 앞 공백만 생략됩니다. 뒤 공백이 있으면 그대로 유지됩니다. `NO PRESERVE BLANKS`의 미리 정해진 크기 필드의 경우, 뒤 공백은 생략되고 앞 공백은 그대로 유지됩니다.

> **참고:** `PRESERVE BLANKS`나 `NO PRESERVE BLANKS`를 명시적으로 제공하지 않으면 기본 동작은 `NO PRESERVE BLANKS`입니다. 이 옵션은 표의 문자(ideographic) 공백에는 작동하지 않습니다.

## target_table

데이터를 로드할 테이블 이름입니다. 테이블 이름은 스키마 한정할 수 있습니다(예: `enterprisedb.emp`). 지정된 대상은 뷰일 수 없습니다.

## field_condition

다음 형태를 취하는 조건 절입니다:

```text
[ ( ] { (start:end) | column_name } { = | != | <> } 'val' [ ) ]
```

이 조건 절은 `INTO TABLE target_table` 절의 일부인 `WHEN` 절에 사용됩니다. 또한 구문 다이어그램에서 `field_def`로 표시된 필드 정의의 일부인 `NULLIF` 절에도 사용됩니다.

`start`와 `end`는 상수 `val`과 비교할 필드의 시작과 끝을 표시하는 `data_file`의 컬럼 위치를 지정하는 양의 정수입니다. 각 레코드의 첫 문자는 `start` 값 `1`로 시작합니다.

`column_name`은 구문 다이어그램의 `field_def`로 정의된 데이터 파일 필드 정의에 할당된 이름을 지정합니다.

(`start`:`end`) 또는 `column_name`을 사용하여 `val`로 지정된 값과 비교해 참 또는 거짓으로 평가할 `data_file`의 레코드 부분을 정의합니다.

`field_condition` 텍스트(특히 `val` 문자열)에 사용되는 모든 문자는 데이터베이스 인코딩에서 유효해야 합니다. 데이터 변환을 위해 EDB*Loader는 먼저 `val` 문자열의 문자를 데이터베이스 인코딩으로, 그다음 데이터 파일 인코딩으로 변환합니다.

`WHEN field_condition [ AND field_condition ]` 절에서, 주어진 레코드에 대해 이러한 모든 조건이 `TRUE`로 평가되면 EDB*Loader는 그 레코드를 `target_table`에 삽입하려고 시도합니다. 삽입 연산이 실패하면 레코드는 `bad_file`에 기록됩니다.

주어진 레코드에 대해 모든 `INTO TABLE` 절의 `WHEN` 절 중 어느 것도 `TRUE`로 평가되지 않는다고 가정합니다. EDB*Loader 세션에 discard 파일이 지정되었으면 그 레코드는 `discard_file`에 기록됩니다.

이 절에 대한 `field_condition`의 효과는 이 파라미터 목록의 `NULLIF` 절 설명을 참고하십시오.

## termstring

`data_file`의 각 필드를 구분하는 하나 이상의 문자 문자열입니다. 문자는 단일 바이트나 멀티바이트일 수 있습니다. 그러나 데이터베이스 인코딩에서 유효해야 합니다. 중간 문자 없이 `termstring`이 연속으로 두 번 나타나면 해당 컬럼이 null로 설정됩니다.

## enclstring

`data_file`의 필드 값을 묶는 데 사용하는 하나 이상의 문자 문자열입니다. 문자는 단일 바이트나 멀티바이트일 수 있으나 데이터베이스 인코딩에서 유효해야 합니다. `termstring`이 데이터의 일부로 나타나는 필드에 `enclstring`을 사용합니다.

## delimstring

`data_file`의 각 레코드를 구분하는 하나 이상의 문자 문자열입니다. 문자는 단일 바이트나 멀티바이트일 수 있으나 데이터베이스 인코딩에서 유효해야 합니다. 중간 문자 없이 `delimstring`이 연속으로 두 번 나타나면 해당 행이 테이블에 로드되지 않습니다. 또한 마지막 레코드(즉, 데이터 파일의 끝)를 `delimstring` 문자로 종료해야 합니다. 그렇지 않으면 마지막 레코드가 테이블에 로드되지 않습니다.

> **참고:** `RECORDS DELIMITED BY 'delimstring'` 절은 Oracle 데이터베이스와 호환되지 않습니다.

## TRAILING NULLCOLS

`TRAILING NULLCOLS`를 지정하면, 주어진 레코드에 대해 `data_file`에 데이터가 없는 컬럼 목록의 컬럼들은 행이 삽입될 때 null로 설정됩니다. 이 옵션은 컬럼 목록 끝의 하나 이상의 연속 컬럼에만 적용됩니다.

레코드 끝의 필드가 생략되고 `TRAILING NULLCOLS`를 지정하지 않으면, EDB*Loader는 레코드에 서식 오류가 있다고 가정하고 bad 파일에 기록합니다.

## column_name

`field_def`로 정의된 필드 값을 삽입할 `target_table`의 컬럼 이름입니다. 필드 정의가 `FILLER`나 `BOUNDFILLER` 절을 포함하면, `FILLER`와 `BOUNDFILLER` 절이 필드 데이터를 테이블 컬럼에 로드하는 것을 방지하므로 `column_name`이 테이블 컬럼 이름일 필요는 없으며 임의의 식별자 이름일 수 있습니다.

## CONSTANT val

필드 정의에서 할당되는 컬럼 데이터 타입과 타입 호환되는 상수를 지정합니다. `val` 주위에 작은따옴표나 큰따옴표를 사용할 수 있습니다. `val`에 공백이 있으면 따옴표로 묶어야 합니다.

`CONSTANT` 절을 사용하면 각 삽입된 행의 컬럼에 할당할 값이 결정됩니다. 동일한 필드 정의에 다른 절이 나타날 수 없습니다.

`data_file`의 필드를 구분하기 위해 `TERMINATED BY` 절을 사용하면, `CONSTANT` 절이 있는 필드 정의에 해당하는 구분 필드가 `data_file`에 없어야 합니다. 즉, EDB*Loader는 `CONSTANT` 절이 있는 필드 정의에 대해 `data_file`에 필드가 없다고 가정합니다.

## FILLER

필드 정의의 식별자가 테이블의 실제 컬럼 이름이면, 필드 정의로 정의된 필드의 데이터를 연관 컬럼에 로드하지 않도록 지정합니다. 이 경우 컬럼은 null로 설정됩니다. `FILLER`나 `BOUNDFILLER` 절 사용은 필드 정의를 실제 컬럼 이름으로 식별하지 않아도 되는 유일한 경우입니다.

`BOUNDFILLER` 절과 달리, `FILLER` 절로 정의된 식별자는 SQL 표현식에서 참조할 수 없습니다. `expr` 파라미터 설명을 참고하십시오.

## BOUNDFILLER

필드 정의의 식별자가 테이블의 실제 컬럼 이름이면, 필드 정의로 정의된 필드의 데이터를 연관 컬럼에 로드하지 않도록 지정합니다. 이 경우 컬럼은 null로 설정됩니다. `FILLER`나 `BOUNDFILLER` 절 사용은 필드 정의를 실제 컬럼 이름으로 식별하지 않아도 되는 유일한 경우입니다.

`FILLER` 절과 달리, SQL 표현식은 `BOUNDFILLER` 절로 정의된 식별자를 참조할 수 있습니다. `expr` 파라미터 설명을 참고하십시오.

## POSITION (start:end)

고정 폭 필드 데이터 파일에서 레코드 내 필드의 위치를 정의합니다. `start`와 `end`는 양의 정수입니다. 레코드의 첫 문자는 start 값 `1`을 갖습니다.

```sql
CHAR [(<length>)] | DATE [(<length>)] | TIMESTAMP [(<length>)] [ "<datemask>" ] |
INTEGER EXTERNAL [(<length>)] |
FLOAT EXTERNAL [(<length>)] | DECIMAL EXTERNAL [(<length>)] |
ZONED EXTERNAL [(<length>)] | ZONED [(<precision>[,<scale>])]
```

`data_file`의 데이터 필드 형식을 설명하는 필드 타입입니다.

> **참고:** 필드 타입 지정은 설명 목적으로 선택적이며, EDB*Loader가 필드 데이터를 테이블 컬럼에 성공적으로 삽입하는지 여부에는 영향을 주지 않습니다. 성공적인 로딩은 컬럼 데이터 타입과 필드 값의 호환성에 달려 있습니다. 예를 들어 데이터 타입 `NUMBER(7,2)`의 컬럼은 `2600`을 포함하는 필드를 성공적으로 받습니다. 그러나 필드에 `26XX` 같은 값이 있으면 삽입이 실패하고 레코드는 `bad_file`에 기록됩니다.

`ZONED` 데이터는 사람이 읽을 수 없습니다. `ZONED` 데이터는 각 자릿수가 별도의 니블/4비트 필드에 인코딩되는 내부 형식으로 저장됩니다. 각 `ZONED` 값에서 마지막 바이트는 상위 4비트에 단일 자릿수를, 하위 4비트에 부호를 포함합니다.

## length

연관 컬럼에 로드할 값의 길이를 지정합니다.

`POSITION` (`start`:`end`) 절을 `fieldtype(length)` 절과 함께 지정하면, 필드의 끝 위치는 지정된 `length` 값으로 재정의됩니다. 즉, 컬럼에 로드할 값의 길이는 `POSITION` (`start`:`end`) 절의 `end` 위치가 아니라 `start` 위치에서 시작하는 `length` 값으로 결정됩니다. 따라서 컬럼에 로드할 값은 `POSITION` (`start`:`end`)으로 정의된 필드보다 짧을 수도 있고, 지정된 `length` 크기에 따라 end 위치를 넘어갈 수도 있습니다.

`INTO TABLE` 절의 일부로 `FIELDS TERMINATED BY 'termstring'` 절을 지정하고 필드 정의가 `fieldtype(length)` 절을 포함하면 레코드가 수락됩니다. 그러나 지정된 `length` 값은 레코드의 그런 모든 필드를 둘러싸는 `termstring` 문자로 결정되는 필드 길이보다 크거나 같아야 합니다. 지정된 `length` 값이 그런 필드에 대해 둘러싸는 `termstring` 문자로 결정되는 필드 길이보다 작으면 레코드가 거부됩니다.

`FIELDS TERMINATED BY 'termstring'` 절을 지정하지 않고 `fieldtype(length)` 절을 포함하는 필드와 함께 `POSITION` (`start`:`end`) 절을 포함하지 않으면, 이 필드의 시작 위치는 앞 필드의 끝 위치 다음 문자에서 시작합니다. 앞 필드의 끝 위치는 다음 중 하나입니다:

- 앞 필드가 `fieldtype(length)` 절을 포함하면 그 `length` 값의 끝
- 필드가 `fieldtype(length)` 절 없이 `POSITION` (`start`:`end`) 절을 포함하면 그 `end` 파라미터

## precision

`precision`을 사용해 `ZONED` 값의 길이를 지정합니다. `ZONED`에 지정된 `precision` 값이 `POSITION` 절로 제공된 정보에 기반해 서버가 계산한 길이와 충돌하면, EDB*Loader는 `precision`에 지정된 값을 사용합니다.

## scale

`ZONED` 값에서 소수점 오른쪽의 자릿수를 지정합니다.

## datemask

날짜 필드의 일·월·연 구성 요소의 순서와 약어를 지정합니다.

> **참고:** 컬럼에 SQL 표현식과 함께 `DATE`나 `TIMESTAMP` 필드 타입을 지정하면, `DATE`나 `TIMESTAMP` 뒤 그리고 SQL 표현식 앞에 `datemask`를 지정해야 합니다. `expr` 파라미터 설명을 참고하십시오.

`TIMESTAMP` 필드 데이터 타입을 사용할 때 `time_stamp timestamp "yyyymmddhh24miss"`를 지정하면 `datemask`가 SQL 표현식으로 변환됩니다. 그러나 `time_stamp timestamp "select to_timestamp(:time_stamp, 'yyyymmddhh24miss')"`의 경우, EDB*Loader는 datemask와 SQL 표현식을 구분할 수 없습니다. 세 번째 필드(예의 SQL 표현식)를 datemask로 취급하고 유효하지 않은 SQL 표현식을 준비합니다. 여기서:

- `첫 번째 필드`는 컬럼 이름을 지정합니다.
- `두 번째 필드`는 데이터 타입을 지정합니다.
- `세 번째 필드`는 datemask를 지정합니다.

SQL 표현식을 제공하려면, 우회책으로 `TO_CHAR` 함수를 사용해 datemask와 SQL 표현식을 지정합니다:

```sql
time_stamp timestamp "yyyymmddhh24miss" "to_char(to_timestamp(:time_stamp, 'yyyymmddhh24miss'), 'yyyymmddhh24miss')"
```

`NULLIF field_condition [ AND field_condition ] ...`

`field_condition` 구문은 이 파라미터 목록의 `field_condition` 설명을 참고하십시오.

모든 필드 조건이 `TRUE`로 평가되면, 필드 정의에서 `column_name`으로 식별되는 컬럼이 null로 설정됩니다. 어떤 필드 조건이 `FALSE`로 평가되면, 컬럼은 필드 정의에 따라 일반적으로 발생하는 대로 적절한 값으로 설정됩니다.

## PRESERVE BLANKS (두 번째)

`PRESERVE BLANKS` 옵션은 `OPTIONALLY ENCLOSED BY` 절과 함께만 작동하며, 구분 필드와 미리 정해진 크기 필드 모두에 대해 앞뒤 공백을 유지합니다.

`NO PRESERVE BLANKS`의 경우, 필드가 구분되면 앞 공백만 생략됩니다. 뒤 공백이 있으면 그대로 유지됩니다. `NO PRESERVE BLANKS`의 미리 정해진 크기 필드의 경우, 뒤 공백은 생략되고 앞 공백은 그대로 유지됩니다.

> **참고:** `PRESERVE BLANKS`나 `NO PRESERVE BLANKS`를 제공하지 않으면 기본 동작은 `NO PRESERVE BLANKS`입니다. 이 옵션은 표의 문자 공백에는 작동하지 않습니다.

## expr

필드 정의에서 할당되는 컬럼 데이터 타입과 타입 호환되는 스칼라 값을 반환하는 SQL 표현식입니다. `expr` 주위에 큰따옴표를 사용합니다. `expr`은 `FILLER` 절이 있는 필드를 제외한 필드 목록의 어느 컬럼이든 참조할 수 있습니다. 컬럼 이름 앞에 콜론(`:`)을 붙입니다.

`expr`은 SQL `SELECT` 문으로 구성될 수도 있습니다. `SELECT` 문을 사용하는 경우:

- `SELECT` 문을 괄호로 묶습니다. 즉, `(SELECT ...)`.
- 선택 목록은 `SELECT` 키워드 다음에 하나의 표현식으로 구성되어야 합니다.
- 결과 집합은 둘 이상의 행을 반환해서는 안 됩니다. 행이 반환되지 않으면 결과 표현식의 반환 값은 null입니다.

다음은 `SELECT` 문의 구문입니다:

```sql
"(SELECT <expr> [ FROM <table_list> [ WHERE <condition> ] ])"
```

##### 참고 (Note)

`FROM table_list` 절을 생략하는 것은 Oracle 데이터베이스와 호환되지 않습니다. 테이블을 지정할 필요가 없으면 `FROM DUAL` 절을 사용하는 것이 Oracle 데이터베이스와 호환됩니다.
