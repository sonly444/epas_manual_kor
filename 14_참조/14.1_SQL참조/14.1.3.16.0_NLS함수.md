# NLS 함수 (NLS Functions) — EPAS 18 Reference

> 원문: [EPAS v18 — Reference › SQL reference › Functions and operators › NLS functions](https://www.enterprisedb.com/docs/epas/latest/reference/sql_reference/03_functions_and_operators/nls_functions/)

> ⚠️ 원래 단일 파일(14.1.3.16)이었으나 하위 4개 함수(NLS_UPPER·NLS_LOWER·NLS_INITCAP·NLSSORT)를 포함하도록 계층 구조로 재구성했습니다. 이 파일은 개요(14.1.3.16.0)입니다.

EDB Postgres Advanced Server 버전 17 이상은 NLS 함수를 지원합니다. 이 함수들은 NLS 구성 파일을 사용해 NLS 파라미터를 동등한 PostgreSQL 콜레이션(Collation)에 매핑합니다.

## NLS 구성 파일 (NLS config file)

`edb_redwood_nls.config` 파일은 NLS 파라미터와 동등한 콜레이션의 매핑 목록을 관리합니다. NLS 파라미터와 동등한 콜레이션은 구성 파일의 각 행에 쉼표로 구분되어 나열됩니다. 구성 파일에는 NLS 파라미터와 동등한 콜레이션 쌍의 기본 목록이 들어 있습니다. NLS 구성 파일은 `EPAS_INSTALLATION_DIRECTORY/share/postgresql/contrib/`에 위치합니다.

구성 파일은 단일 NLS 파라미터에 대해 여러 매핑을 포함할 수 있습니다. 기존 NLS 파라미터에 새 매핑을 추가할 수 있습니다. 가장 최근에 추가된 매핑이 NLS 함수 연산에 사용됩니다.

NLS 파라미터에 NLS 함수를 사용하기 전에, NLS 구성 파일에 새 매핑을 추가합니다:

- `NLS_parameter,<schema_name>.<collation>` 형식으로 구성 파일을 직접 편집하여, 또는
- `edb_nls_cf_insert` 함수를 사용하여. `edb_nls_cf_insert` 함수를 사용할 때는 파일에 올바른 쓰기 권한이 있는지 확인하는 것이 중요합니다. 적절한 권한이 없으면 파일 수정 시도가 실패하여 오류나 불완전한 구성을 초래할 수 있습니다.

여기서 `<schema_name>.<collation>`은 `pg_collation` 카탈로그에서 얻어 유효한 NLS 파라미터에 매핑합니다. 인코딩이 `-1`("모든 인코딩" 표현)인 콜레이션이나 데이터베이스 인코딩인 콜레이션만 허용됩니다.

NLS 구성 파일의 유효하지 않은 항목으로 인해 NOTICE 메시지가 발생하면, 가장 좋은 방법은 그 유효하지 않은 항목을 수동으로 제거하는 것입니다. 이 메시지는 보통 데이터베이스가 존재하지 않거나 구성 파일에 잘못 지정된 콜레이션을 참조하려 할 때 발생합니다.

NOTICE 메시지 예:

```text
예 1 -
NOTICE: invalid nls entry (XGERMAN.xyz-pqr) in nls config file at line number 83, skipping

예 2 -
NOTICE: pg collation not found for entry (XGERMAN,abc) in nls config file at line number 84, skipping
```

콜레이션 값은 플랫폼 의존적임을 인식하는 것이 중요합니다. 즉, 한 플랫폼에서 사용 가능한 콜레이션이 다른 플랫폼에는 없을 수 있습니다. 호환성 문제를 피하려면 항상 환경 내 `pg_collation` 테이블에 있는 콜레이션을 사용하십시오.

Postgres 콜레이션은 기본적으로 대소문자나 악센트를 구분하지 않는 것이 아닙니다. 따라서 `pg_collation` 테이블에서 얻는 콜레이션은 모두 대소문자/악센트를 구분합니다. 대소문자/악센트를 구분하지 않는 콜레이션을 수동으로 만들 수 있습니다. 자세한 내용은 [콜레이션이란?](https://www.postgresql.org/docs/current/collation.html)과 [콜레이션 생성 방법](https://www.postgresql.org/docs/current/sql-createcollation.html)을 참고하십시오.

각 클라이언트 세션은 NLS 함수 중 하나가 처음 호출될 때 구성 파일을 읽어 NLS 파라미터와 콜레이션 값을 인메모리 HASH 데이터 구조에 저장합니다. 파싱 로직은 각 행을 순차적으로 읽어 NLS 파라미터와 콜레이션 값을 분리한 뒤 올바른 데이터 구조에 저장합니다.

구성 파일을 수동으로 변경하면, 갱신된 매핑으로 작업하기 위해 모든 세션에서 NLS 구성 파일을 다시 로드하거나 세션을 재시작해야 합니다. `edb_nls_cf_insert` 함수를 사용해 세션에서 구성 파일을 수정하면 새 매핑으로 인메모리 HASH 데이터 구조가 갱신됩니다. 세션에서 이루어진 변경은 구성 파일이 다시 로드되거나 다른 세션이 재시작된 후에만 다른 세션에 영향을 줍니다.

NLS 구성 파일 관리에 사용 가능한 함수는 다음 표에 나열되어 있습니다:

| 함수 | 반환 타입 | 설명 |
| --- | --- | --- |
| `edb_nls_cf_insert(nls TEXT, collation TEXT)` | VOID | 주어진 NLS 파라미터와 매핑 콜레이션으로 NLS 구성 파일에 새 매핑 추가 |
| `edb_nls_cf_reload()` | VOID | NLS 구성 파일을 다시 로드하고 인메모리 HASH 데이터 구조의 NLS 파라미터와 매핑 콜레이션 갱신 |
| `edb_nls_cf_hash_dump(OUT nls TEXT, OUT collationid INT)` | RECORD | 클라이언트 세션에 NLS 파라미터와 매핑 콜레이션 HASH 내용 덤프 |
| `edb_nls_cf_dump(OUT nls TEXT, OUT collation TEXT)` | RECORD | 클라이언트 세션에 기존 NLS 구성 파일 내용 덤프 |

## 예제 (Examples)

이 예는 NLS 구성 파일에 새 매핑을 추가하는 방법을 보여줍니다:

```text
SELECT edb_nls_cf_insert('xgerman', '"pg_catalog"."de-x-icu"');
```

출력:

```text
 edb_nls_cf_insert
-------------------

(1 row)
```

이 예는 NLS 구성 파일을 다시 로드하는 방법을 보여줍니다:

```text
SELECT edb_nls_cf_reload();
```

출력:

```text
 edb_nls_cf_reload
-------------------

(1 row)
```
