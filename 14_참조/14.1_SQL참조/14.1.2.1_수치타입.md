## 개요 (Overview)

수치 타입은 4바이트 정수, 4바이트 및 8바이트 부동소수점 숫자, 고정 정밀도 소수(decimal)로 구성됩니다.

수치 타입 상수의 구문은 PostgreSQL 문서의 [Constants](https://www.postgresql.org/docs/current/sql-syntax-lexical.html#SQL-SYNTAX-CONSTANTS)에 설명되어 있습니다. 수치 타입은 대응하는 산술 연산자와 함수의 완전한 집합을 갖습니다. 자세한 내용은 [함수와 연산자](https://www.enterprisedb.com/docs/epas/latest/reference/sql_reference/03_functions_and_operators/)를 참고하십시오. 다음 절에서 각 타입을 상세히 설명합니다.

## 정수 타입 (Integer types)

`BIGINT`, `BINARY_INTEGER`, `INTEGER`, `PLS_INTEGER`, `SMALLINT`, `ROWID` 타입은 수치 타입 표에 명시된 대로 (소수부가 없는) 정수를 저장합니다. 허용 범위를 벗어난 값을 저장하려고 하면 오류가 발생합니다.

`INTEGER` 타입은 범위, 저장 크기, 성능 사이의 균형이 가장 좋아 일반적으로 선택됩니다. `SMALLINT` 타입은 일반적으로 디스크 공간이 매우 부족한 경우에만 사용됩니다. `BIGINT` 타입은 `INTEGER` 타입의 범위가 부족할 때 사용하도록 설계되었습니다.

## 임의 정밀도 숫자 (Arbitrary precision numbers)

`NUMBER` 타입은 거의 무제한의 정밀도 자릿수를 저장하고 계산을 정확하게 수행할 수 있습니다. 특히 통화 금액이나 정확성이 요구되는 기타 수량을 저장하는 데 권장됩니다. 다만 `NUMBER` 타입은 [부동소수점 타입](https://www.enterprisedb.com/docs/epas/latest/reference/sql_reference/02_data_types/01_numeric_types/#floating-point-types)에 비해 매우 느립니다.

`NUMBER`의 *스케일(scale)*은 소수점 오른쪽 소수부의 십진 자릿수입니다. `NUMBER`의 *정밀도(precision)*는 전체 수에서 유효 자릿수의 총 개수, 즉 소수점 양쪽 자릿수의 합입니다. 따라서 숫자 23.5141은 정밀도 6, 스케일 4를 갖습니다. 정수는 스케일이 0입니다.

`NUMBER` 타입의 정밀도와 스케일을 모두 구성할 수 있습니다. `NUMBER` 타입의 컬럼을 선언하려면 다음 구문을 사용합니다:

```sql
NUMBER(precision, scale)
```

정밀도(precision)는 양수여야 하고, 스케일(scale)은 0 또는 양수여야 합니다. 또는 다음 구문은 스케일 0을 선택합니다:

```sql
NUMBER(precision)
```

정밀도나 스케일 없이 `NUMBER`만 지정하면, 정밀도의 구현 한계까지 임의의 정밀도와 스케일의 수치 값을 저장할 수 있는 컬럼이 생성됩니다. 이런 종류의 컬럼은 입력 값을 특정 스케일로 강제 변환하지 않는 반면, 선언된 스케일이 있는 `NUMBER` 컬럼은 입력 값을 그 스케일로 강제 변환합니다. (SQL 표준은 기본 스케일 0, 즉 정수 정밀도로의 변환을 요구합니다. 최대 이식성을 위해서는 정밀도와 스케일을 명시적으로 지정하는 것이 좋습니다.)

값의 정밀도나 스케일이 컬럼의 선언된 정밀도나 스케일보다 크면, 시스템은 값을 반올림하려고 시도합니다. 선언된 한계를 충족하도록 값을 반올림할 수 없으면 오류가 발생합니다.

수치 값은 앞뒤에 불필요한 0 없이 물리적으로 저장됩니다. 따라서 컬럼의 선언된 정밀도와 스케일은 고정 할당량이 아니라 최댓값입니다. (이런 의미에서 `NUMBER` 타입은 `CHAR(N)`보다 `VARCHAR(N)`에 더 가깝습니다.) 실제 저장 요구량은 십진 4자리 그룹당 2바이트에 3~8바이트의 오버헤드를 더한 것입니다.

일반적인 수치 값 외에도, `NUMBER` 타입은 "숫자가 아님(not-a-number)"을 의미하는 특수 값 NaN을 허용합니다. NaN에 대한 모든 연산은 또 다른 NaN을 산출합니다. 이 값을 SQL 명령에서 상수로 작성할 때는 따옴표로 묶어야 합니다. 예: `UPDATE table SET x = 'NaN'`. 입력 시 문자열 `NaN`은 대소문자를 구분하지 않고 인식됩니다.

##### 참고 (Note)

"숫자가 아님" 개념의 대부분 구현에서 `NaN`은 (자기 자신 `NaN`을 포함해) 다른 어떤 수치 값과도 같지 않다고 간주됩니다. 수치 값을 정렬하고 트리 기반 인덱스에서 사용할 수 있도록, PostgreSQL은 `NaN` 값을 서로 같으며 모든 비-`NaN` 값보다 크다고 취급합니다.

`DECIMAL`과 `NUMBER` 타입은 동등합니다. 두 타입 모두 SQL 표준의 일부입니다.

값을 반올림할 때, `NUMBER` 타입은 동점(ties)을 0에서 먼 쪽으로 반올림하는 반면, (대부분의 머신에서) `REAL`과 `DOUBLE PRECISION` 타입은 동점을 가장 가까운 짝수로 반올림합니다. 예:

```sql
SELECT x,
  round(x::numeric) AS num_round,
  round(x::double precision) AS dbl_round
FROM generate_series(-3.5, 3.5, 1) as x;
  x   | num_round | dbl_round
------+-----------+-----------
 -3.5 |        -4 |        -4
 -2.5 |        -3 |        -2
 -1.5 |        -2 |        -2
 -0.5 |        -1 |        -0
  0.5 |         1 |         0
  1.5 |         2 |         2
  2.5 |         3 |         2
  3.5 |         4 |         4
(8 rows)
```

## 부동소수점 타입 (Floating-point types)

`REAL`과 `DOUBLE PRECISION` 데이터 타입은 *부정확한(inexact)*, 가변 정밀도 수치 타입입니다. 실제로 이 타입들은 보통 기반 프로세서·운영체제·컴파일러가 지원하는 범위 내에서 IEEE 표준 754 이진 부동소수점 산술(각각 단정밀도 및 배정밀도)의 구현입니다.

부정확하다는 것은 일부 값이 내부 형식으로 정확하게 변환되지 못하고 근사값으로 저장되어, 값을 저장했다가 다시 출력하면 약간의 차이가 나타날 수 있음을 의미합니다. 이러한 오류와 계산 과정에서 오류가 전파되는 방식을 관리하는 것은 수학과 컴퓨터 과학의 한 분야 전체에 해당하며, 다음 사항을 제외하고 여기서 더 논의하지 않습니다:

- (통화 금액처럼) 정확한 저장과 계산이 필요하면 대신 `NUMBER` 타입을 사용하십시오.
- 특히 경계 사례(무한대, 언더플로)의 특정 동작에 의존하는 등, 중요한 목적으로 이 타입들로 복잡한 계산을 하려면 구현을 신중히 평가하십시오.
- 두 부동소수점 값의 동등성 비교는 기대대로 동작하지 않을 수 있습니다.

대부분의 플랫폼에서 `REAL` 타입은 최소 `1E-37` ~ `1E+37` 범위와 최소 6자리 십진 정밀도를 갖습니다. `DOUBLE PRECISION` 타입은 일반적으로 약 `1E-307` ~ `1E+308` 범위와 최소 15자리 정밀도를 갖습니다. 너무 크거나 너무 작은 값은 오류를 일으킵니다. 입력 숫자의 정밀도가 너무 높으면 반올림이 발생할 수 있습니다. 0과 구별할 수 없을 만큼 0에 너무 가까운 숫자는 언더플로 오류를 일으킵니다.

일반적인 수치 값 외에도 부동소수점 타입에는 여러 특수 값이 있습니다:

- `Infinity`
- `-Infinity`
- `NaN`

이들은 각각 IEEE 754 특수 값 "무한대", "음의 무한대", "숫자가 아님"을 나타냅니다. (부동소수점 산술이 IEEE 754를 따르지 않는 머신에서는 이 값들이 기대대로 동작하지 않을 수 있습니다.) 이 값들을 SQL 명령에서 상수로 작성할 때는 따옴표로 묶어야 합니다. 예: `UPDATE table SET x = '-Infinity'`. 입력 시 이 문자열들은 대소문자를 구분하지 않고 인식됩니다.

##### 참고 (Note)

IEEE 754는 NaN이 (자기 자신 `NaN`을 포함해) 다른 어떤 부동소수점 값과도 같지 않아야 한다고 명시합니다. 부동소수점 값을 정렬하고 트리 기반 인덱스에서 사용할 수 있도록, PostgreSQL은 `NaN` 값을 서로 같으며 모든 비-`NaN` 값보다 크다고 취급합니다.

EDB Postgres Advanced Server는 부정확한 수치 타입을 지정하기 위한 SQL 표준 표기법 `FLOAT`과 `FLOAT(p)`도 지원합니다. 여기서 `p`는 이진 자릿수로 표현한 최소 허용 정밀도를 지정합니다. EDB Postgres Advanced Server는 `FLOAT(1)`~`FLOAT(24)`를 `REAL` 타입 선택으로, `FLOAT(25)`~`FLOAT(53)`을 `DOUBLE PRECISION` 선택으로 받아들입니다. 허용 범위를 벗어난 `p` 값은 오류를 일으킵니다. 정밀도를 지정하지 않은 `FLOAT`은 `DOUBLE PRECISION`을 의미합니다.

##### 참고 (Note)

real과 double precision이 가수부(mantissa)에 각각 정확히 24비트와 53비트를 갖는다는 가정은 IEEE 표준 부동소수점 구현에서는 맞습니다. 비-IEEE 플랫폼에서는 약간 다를 수 있지만, 단순화를 위해 모든 플랫폼에서 동일한 `p` 범위를 사용합니다.

## Serial 타입 (Serial types)

##### 참고 (Note)

이 절은 자동 증가 컬럼을 만드는 PostgreSQL 고유 방식을 설명합니다. 또 다른 방법은 [CREATE TABLE](https://www.postgresql.org/docs/11/sql-createtable.html)에 설명된 SQL 표준 아이덴티티 컬럼(identity column) 기능을 사용하는 것입니다.

`SMALLSERIAL`, `SERIAL`, `BIGSERIAL` 데이터 타입은 실제 타입이 아니라, 고유 식별자 컬럼을 만들기 위한 표기상의 편의일 뿐입니다(일부 다른 데이터베이스가 지원하는 `AUTO_INCREMENT` 속성과 유사). 현재 구현에서 다음과 같이 지정하는 것은:

```sql
CREATE TABLE tablename (
    colname SERIAL
);
```

다음과 같이 지정하는 것과 동등합니다:

```text
CREATE SEQUENCE tablename_colname_seq AS integer;
CREATE TABLE tablename (
    colname integer NOT NULL DEFAULT nextval('tablename_colname_seq')
);
ALTER SEQUENCE tablename_colname_seq OWNED BY tablename.colname;
```

따라서 정수 컬럼을 생성하고 그 기본값이 시퀀스 생성기에서 할당되도록 배치한 것입니다. NULL 값이 삽입되지 않도록 `NOT NULL` 제약이 적용됩니다. (대부분의 경우 실수로 중복 값이 삽입되는 것을 방지하기 위해 `UNIQUE`나 `PRIMARY KEY` 제약도 붙이고 싶겠지만, 이는 자동이 아닙니다.) 마지막으로, 컬럼이나 테이블이 삭제되면 시퀀스도 삭제되도록 시퀀스가 해당 컬럼에 "소유됨(owned by)"으로 표시됩니다.

##### 참고 (Note)

`SMALLSERIAL`, `SERIAL`, `BIGSERIAL`은 시퀀스를 사용해 구현되므로, 행이 삭제된 적이 없더라도 컬럼에 나타나는 값의 시퀀스에 "구멍(hole)"이나 간격이 있을 수 있습니다. 시퀀스에서 할당된 값은 그 값을 포함한 행이 테이블 컬럼에 성공적으로 삽입되지 않더라도 여전히 "소모"됩니다. 예를 들어 삽입 트랜잭션이 롤백되면 이런 일이 발생할 수 있습니다. 자세한 내용은 [`nextval()`](https://www.postgresql.org/docs/11/functions-sequence.html)을 참고하십시오.

시퀀스의 다음 값을 serial 컬럼에 삽입하려면, serial 컬럼이 기본값을 할당받도록 지정합니다. 이는 INSERT 문의 컬럼 목록에서 해당 컬럼을 제외하거나 `DEFAULT` 키워드를 사용하여 수행할 수 있습니다.

타입 이름 `SERIAL`과 `SERIAL4`는 동등합니다. 둘 다 정수 컬럼을 생성합니다. 타입 이름 `BIGSERIAL`과 `SERIAL8`도 bigint 컬럼을 생성한다는 점만 다르고 동일하게 동작합니다. 테이블 수명 동안 2147483648개(2의 31승)를 초과하는 식별자 사용이 예상되면 `BIGSERIAL`을 사용해야 합니다. 타입 이름 `SMALLSERIAL`과 `SERIAL2`도 `SMALLINT` 컬럼을 생성한다는 점만 다르고 동일하게 동작합니다.

`SERIAL` 컬럼에 대해 생성된 시퀀스는 소유 컬럼이 삭제될 때 자동으로 삭제됩니다. 컬럼을 삭제하지 않고 시퀀스를 삭제할 수 있지만, 이 경우 컬럼의 기본값 표현식이 강제로 제거됩니다.
