# 데이터 타입 서식 함수 (Data Type Formatting Functions) — EPAS 18 Reference

> 원문: [EPAS v18 — Reference › SQL reference › Functions and operators › Data type formatting functions](https://www.enterprisedb.com/docs/epas/latest/reference/sql_reference/03_functions_and_operators/07_data_type_formatting_functions/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 함수·패턴·코드 이름은 원문 그대로 보존했습니다.

EDB Postgres Advanced Server 서식 함수는 다양한 데이터 타입(날짜/시간, 정수, 부동소수점, numeric)을 서식화된 문자열로 변환하고, 서식화된 문자열을 특정 데이터 타입으로 변환하는 강력한 도구 집합을 제공합니다. 이 함수들은 모두 공통 호출 규약을 따릅니다. 첫 번째 인수는 서식화할 값이고, 두 번째 인수는 출력 또는 입력 형식을 정의하는 문자열 템플릿입니다.

## 데이터 타입 서식 함수 개요 (Overview)

| 함수 | 반환 타입 | 설명 | 예 | 결과 |
| --- | --- | --- | --- | --- |
| `TO_BLOB(raw)` | `BLOB` | `RAW` 값을 `BLOB` 값으로 변환 | `TO_BLOB('abc')` | `\x616263` |
| `TO_CLOB(string)` | `CLOB` | `CHAR`, `VARCHAR`, `VARCHAR2`, `NCHAR`, `NVARCHAR2`, `CLOB` 값을 `CLOB` 값으로 변환 | `TO_CLOB('aaaa')` | `aaaa` |
| `TO_CHAR(DATE [, format ])` | `VARCHAR2` | 날짜/시간을 `format` 출력의 문자열로 변환. 기본 형식은 DD-MON-YY | `TO_CHAR(SYSDATE::PG_CATALOG.DATE, 'MM/DD/YYYY')` | `07/25/2007` |
| `TO_CHAR(TIMESTAMP [, format ])` | `VARCHAR2` | 타임스탬프를 `format` 출력의 문자열로 변환. 기본 형식은 DD-MON-YY | `TO_CHAR(CURRENT_TIMESTAMP::TIMESTAMP, 'MM/DD/YYYY HH12:MI:SS AM')` | `08/13/2015 08:55:22 PM` |
| `TO_CHAR(TIMESTAMPTZ [, format])` | `VARCHAR2` | 타임스탬프를 `format` 출력의 문자열로 변환. 생략 시 기본 형식은 DD-MON-YY | `TO_CHAR(CURRENT_TIMESTAMP::TIMESTAMPTZ, 'MM/DD/YYYY HH12:MI:SS AM TZ')` | `03/11/2025 09:40:27 AM IST` |
| `TO_CHAR(INTEGER [, format ])` | `VARCHAR2` | 정수를 `format` 출력의 문자열로 변환 | `TO_CHAR(2412, '999,999S')` | `2,412+` |
| `TO_CHAR(NUMBER [, format ])` | `VARCHAR2` | 십진수를 `format` 출력의 문자열로 변환 | `TO_CHAR(10125.35, '999,999.99')` | `10,125.35` |
| `TO_CHAR(DOUBLE PRECISION, format)` | `VARCHAR2` | 부동소수점 숫자를 `format` 출력의 문자열로 변환 | `TO_CHAR (CAST(123.5282 AS REAL), '999.99')` | `123.53` |
| `TO_DATE(string [, format ])` | `TIMESTAMP` | 날짜 또는 타임스탬프 서식 문자열을 `TIMESTAMP` 데이터 타입으로 변환 | `TO_DATE('2007-07-04 13:39:10', 'YYYY-MM-DD HH24:MI:SS')` / `TO_DATE('2007-07-04','YYYY-MM-DD')` | `04-JUL-07 13:39:10` / `04-JUL-07 00:00:00` |
| `TO_DSINTERVAL(string)` | `INTERVAL DAY TO SECOND` | `CHAR`, `VARCHAR2`, `NCHAR`, `NVARCHAR2` 데이터 타입의 문자열을 INTERVAL DAY TO SECOND 타입으로 변환 | `TO_DSINTERVAL('80 13:30:00')` | `80 days 13:30:00` |
| `TO_NCHAR(string)` | `NVARCHAR2` | `문자열`, `CHAR`, `VARCHAR2`, `CLOB`, `NCLOB` 값을 국가 문자 집합(national character set)으로 변환 | `TO_NCHAR('test')` | `test` |
| `TO_NCHAR(number [, format])` | `NVARCHAR2` | 숫자 서식 문자열을 국가 문자 데이터 타입으로 변환 | `TO_NCHAR(7654321, 'C9G999G999D99')` | `7,654,321.00` |
| `TO_NCHAR(DATE  [, format ])` | `NVARCHAR2` | 날짜/시간을 국가 문자 데이터 타입의 서식 문자열로 변환 | `TO_NCHAR(timestamp '2022-04-20 17:31:12.66', 'Day: MONTH DD, YYYY')` | `Wednesday: APRIL     20, 2022` |
| `TO_NUMBER(string [, format ])` | `NUMBER` | 숫자 서식 문자열을 `NUMBER` 데이터 타입으로 변환 | `TO_NUMBER('2,412-', '999,999S')` | `-2412` |
| `TO_TIMESTAMP(string, format)` | `TIMESTAMPTZ` | 타임스탬프 서식 문자열을 TIMESTAMP WITH TIME ZONE 데이터 타입으로 변환 | `TO_TIMESTAMP('05 Dec 2000 08:30:25 pm', 'DD Mon YYYY hh12:mi:ss pm')` | `05-DEC-00 20:30:25 +05:30` |
| `TO_TIMESTAMP_TZ(string[, format])` | `TIMESTAMPTZ` | 타임스탬프 서식 문자열을 TIMESTAMP WITH TIME ZONE 데이터 타입으로 변환 | `TO_TIMESTAMP_TZ ('2003/12/13 10:13:18 -8:00', 'YYYY/MM/DD HH:MI:SS TZH:TZM')` | `13-DEC-03 23:43:18 +05:30` |
| `FROM_TZ(timestamp_value, timezone_value)` | `TIMESTAMPTZ` | 타임스탬프 값과 시간대를 TIMESTAMP WITH TIME ZONE 값으로 변환 | `FROM_TZ(TIMESTAMP '2017-08-08 08:09:10', 'Asia/Kolkata')` | `08-AUG-17 08:09:10 +05:30` |

##### 참고 (Note)

`TO_CHAR(TIMESTAMPTZ)` 함수는 버전 13부터 Oracle 호환이며 PostgreSQL 호환이 아닙니다. 그 결과 이전 버전과 비교해 일부 기능 차이가 관찰될 수 있습니다.

### 날짜와 시간 수정자 (Date and time modifiers)

특정 수정자를 어떤 템플릿 패턴에든 적용해 그 동작을 바꿀 수 있습니다. 예를 들어 `FMMonth`는 `FM` 수정자가 적용된 `Month` 패턴입니다. 이 표는 날짜/시간 서식의 수정자 패턴을 보여줍니다.

| 수정자 | 설명 | 예 |
| --- | --- | --- |
| `FM` 접두 | 채움 모드(패딩 공백과 0 억제) | `FMMonth` |
| `TH` 접미 | 대문자 서수 접미사 | `DDTH` |
| `th` 접미 | 소문자 서수 접미사 | `DDth` |
| `FX` 접두 | 고정 형식 전역 옵션(사용 노트 참고) | `FX Month DD Day` |
| `SP` 접미 | 철자 모드 | `DDSP` |

날짜/시간 서식 사용 노트:

- `FM`은 패턴의 출력을 고정 너비로 만들기 위해 추가되는 앞의 0과 뒤의 공백을 억제합니다.
- `TO_TIMESTAMP`, `TO_TIMESTAMP_TZ`, `TO_DATE`는 `FX` 옵션을 사용하지 않으면 입력 문자열의 여러 공백을 건너뜁니다. `FX`를 템플릿의 첫 항목으로 사용해야 합니다. 예:

```sql
TO_TIMESTAMP('2000 - JUN', 'YYYY-MON') is correct, but
TO_TIMESTAMP('2000    JUN', 'FXYYYY MON') and
TO_TIMESTAMP_TZ('2000    JUN', 'FXYYYY MON') returns an error
because TO_TIMESTAMP and TO_TIMESTAMP_TZ expects one space
only.
```

- `TO_CHAR` 템플릿에는 일반 텍스트가 허용되며 그대로 출력됩니다.
- 문자열에서 `timestamp`, `timestamptz`, `date`로의 변환에서 `YYY`, `YYYY`, `Y,YYY` 필드가 있으면 `CC` 필드는 무시됩니다. `CC`가 `YY`나 `Y`와 함께 사용되면 연도는 `(CC-1)*100+YY`로 계산됩니다.

이 표는 `TO_CHAR`와 `TO_DATE` 함수 사용 예 일부를 보여줍니다:

| 표현식 | 결과 |
| --- | --- |
| `TO_CHAR(CURRENT_TIMESTAMP, 'Day, DD  HH12:MI:SS')` | `'Tuesday  , 06  05:39:18'` |
| `TO_CHAR(CURRENT_TIMESTAMP, 'FM-Day, FMDD  HH12:MI:SS')` | `'Tuesday, 6  05:39:18'` |
| `TO_CHAR(-0.1, '99.99')` | `'  -.10'` |
| `TO_CHAR(-0.1, 'FM9.99')` | `'-.1'` |
| `TO_CHAR(0.1, '0.9')` | `' 0.1'` |
| `TO_CHAR(12, '9990999.9')` | `'    0012.0'` |
| `TO_CHAR(12, 'FM9990999.9')` | `'0012.'` |
| `TO_CHAR(485, '999')` | `' 485'` |
| `TO_CHAR(-485, '999')` | `'-485'` |
| `TO_CHAR(1485, '9,999')` | `' 1,485'` |
| `TO_CHAR(1485, '9G999')` | `' 1,485'` |
| `TO_CHAR(148.5, '999.999')` | `' 148.500'` |
| `TO_CHAR(148.5, 'FM999.999')` | `'148.5'` |
| `TO_CHAR(148.5, 'FM999.990')` | `'148.500'` |
| `TO_CHAR(148.5, '999D999')` | `' 148.500'` |
| `TO_CHAR(3148.5, '9G999D999')` | `' 3,148.500'` |
| `TO_CHAR(-485, '999S')` | `'485-'` |
| `TO_CHAR(-485, '999MI')` | `'485-'` |
| `TO_CHAR(485, '999MI')` | `'485 '` |
| `TO_CHAR(485, 'FM999MI')` | `'485'` |
| `TO_CHAR(-485, '999PR')` | `'<485>'` |
| `TO_CHAR(485, 'L999')` | `'$ 485'` |
| `TO_CHAR(485, 'RN')` | `'        CDLXXXV'` |
| `TO_CHAR(485, 'FMRN')` | `'CDLXXXV'` |
| `TO_CHAR(5.2, 'FMRN')` | `'V'` |
| `TO_CHAR(12, '99V999')` | `' 12000'` |
| `TO_CHAR(12.4, '99V999')` | `' 12400'` |
| `TO_CHAR(12.45, '99V9')` | `' 125'` |

이 표는 `TO_TIMESTAMP_TZ` 함수 사용 예 일부를 보여줍니다:

| 표현식 | 결과 |
| --- | --- |
| `TO_TIMESTAMP_TZ('12-JAN-2010', 'DD-MONTH-YYYY')` | `'12-JAN-10 00:00:00 +05:30'` |
| `TO_TIMESTAMP_TZ('03-APR-07 09:12:21 P.M','DD-MON-YY HH12:MI:SS A.M')` | `'03-APR-07 09:12:21 +05:30'` |
| `TO_TIMESTAMP_TZ('2003/12/13 10:13:18 -8:00', 'YYYY/MM/DD HH:MI:SS TZH:TZM')` | `'13-DEC-03 23:43:18 +05:30'` |
| `TO_TIMESTAMP_TZ('20-MAR-20 04:30:00 +08:00', 'DD-MON-YY HH:MI:SS TZH:TZM')` | `'20-MAR-20 02:00:00 +05:30'` |
| `TO_TIMESTAMP_TZ('10-Sep-02 14:10:10.123000', 'DD-MON-RR HH24:MI:SS.FF')` | `'10-SEP-02 14:10:10.123 +05:30'` |
| `TO_TIMESTAMP_TZ('20-MAR-20 04:30:00.123456 PM +03:00')` | `'20-MAR-20 09:30:00.123456 -04:00'` |

## 숫자 값에 사용 가능한 템플릿 패턴 (Available template patterns for numeric values)

이 표는 숫자 값 서식화에 사용 가능한 템플릿 패턴을 나열합니다:

| 패턴 | 설명 |
| --- | --- |
| `9` | 지정된 자릿수의 값 |
| `0` | 앞에 0이 채워진 값 |
| `. (period)` | 소수점 |
| `, (comma)` | 그룹(천 단위) 구분자 |
| `$` | 달러 기호 |
| `S` | 숫자에 고정된 부호(로케일 사용) |
| `L` | 통화 기호(로케일 사용) |

패턴 `9`는 9의 개수와 같은 자릿수의 값을 만듭니다. 자릿수가 없으면 서버는 해당 9를 무시합니다. `S` 패턴은 `+`를 지원하지 않고, `$` 패턴은 표현식에서 소수점을 지원하지 않습니다.

이 표는 `TO_NUMBER` 함수 사용 예 일부를 보여줍니다:

| 표현식 | 결과 |
| --- | --- |
| `TO_NUMBER('-65', 'S99')` | `' -65'` |
| `TO_NUMBER('$65', 'L99')` | `' 65'` |
| `TO_NUMBER('9678584', '9999999')` | `' 9678584'` |
| `TO_NUMBER('123,456,789', '999,999,999')` | `' 123456789'` |
| `TO_NUMBER('1210.73', '9999.99')` | `' 1210.73'` |
| `TO_NUMBER('1210.73')` | `' 1210.73'` |
| `TO_NUMBER('0101.010','FM99999999.99999')` | `' 101.010'` |

## 문자열 및 날짜 함수의 출력 형식 (Output formats for string and date functions)

출력 템플릿 문자열(`TO_CHAR`용)에서 특정 패턴은 인식되어 서식화할 값에서 적절히 서식화된 데이터로 대체됩니다. 템플릿 패턴이 아닌 텍스트는 그대로 복사됩니다. 마찬가지로 입력 템플릿 문자열(`TO_CHAR`을 제외한 모든 것)에서 템플릿 패턴은 입력 데이터 문자열에서 살펴볼 부분과 거기서 찾을 값을 식별합니다.

`TO_TIMESTAMP`, `TO_TIMESTAMP_TZ`, `TO_DATE`를 호출할 때 날짜·월·연도를 지정하지 않으면, 기본적으로 출력 형식은 현재 월 또는 현재 연도의 첫날을 고려합니다. 다음 예에서는 입력 문자열에 날짜·월·연도가 지정되지 않았습니다. `TO_TIMESTAMP`, `TO_TIMESTAMP_TZ`, `TO_DATE`는 현재 월과 현재 연도의 첫날이라는 기본값을 반환합니다.

```sql
edb=# select to_timestamp('12', 'HH');
```

출력:

```text
      to_timestamp
---------------------------
 01-MAY-20 12:00:00 +05:30
(1 row)
```

```sql
edb=# select to_timestamp_tz('12', 'HH');
```

출력:

```text
      to_timestamp_tz
---------------------------
 01-MAY-20 12:00:00 +05:30
(1 row)
```

```sql
edb=# select to_date('12', 'HH');
```

출력:

```text
      to_date
--------------------
 01-MAY-20 12:00:00
(1 row)
```

```text
edb=# select to_char(cast('30-JAN-20 05:37:14 PM +05:30' as timestamp with time zone), 'HH24SP') from dual;
```

출력:

```text
 to_char
---------
 twelve
(1 row)
```

```text
edb=# select to_char(cast('30-JAN-20 05:37:14 PM +05:30' as timestamp with time zone), 'MM-DD-YYYY HH24:MM:SS TZ') from dual;
```

출력:

```text
         to_char
-------------------------
 01-30-2020 17:01:14 IST
(1 row)
```

## TO_CHAR 함수의 IMMUTABLE 형태로 인덱스 생성 (Creating an index with the IMMUTABLE form of the TO_CHAR function)

특정 경우의 `TO_CHAR` 함수는 함수의 `IMMUTABLE` 형태를 사용하게 됩니다. 함수가 데이터베이스를 수정하지 않고 입력 파라미터에만 의존하여 동일하고 일관된 값을 반환하면 그 함수는 `IMMUTABLE`입니다. 즉, 구성 파라미터 설정, 로케일, 데이터베이스 내용 등이 함수가 반환하는 결과에 영향을 주지 않습니다.

함수 변동성 범주 `VOLATILE`, `STABLE`, `IMMUTABLE`에 대한 자세한 내용은 [함수 변동성 문서](https://www.postgresql.org/docs/current/static/xfunc-volatility.html)를 참고하십시오.

`IMMUTABLE` 함수의 특별한 이점은 `CREATE INDEX` 명령에서 그 함수를 기반으로 인덱스를 만들 수 있다는 것입니다.

`TO_CHAR` 함수가 `IMMUTABLE` 형태를 사용하려면 다음 조건을 충족해야 합니다:

- `TO_CHAR` 함수의 첫 번째 파라미터는 `TIMESTAMP` 데이터 타입이어야 합니다.
- `TO_CHAR` 함수의 두 번째 파라미터에 지정된 형식은 언어와 로케일 같은 요소에 따라 함수의 반환 값에 영향을 주어서는 안 됩니다. 예를 들어 `IMMUTABLE` 형태에는 `'YYYY-MM-DD HH24:MI:SS'` 형식을 사용할 수 있습니다. 함수 결과가 로케일 설정과 관계없이 순전히 숫자 형태로 표현된 날짜와 시간이기 때문입니다. 그러나 `IMMUTABLE` 형태에 `'DD-MON-YYYY'` 형식은 사용할 수 없습니다. 3자 월 약어가 로케일 설정에 따라 다른 결과를 반환할 수 있기 때문입니다.

비-immutable 함수를 초래하는 형식 패턴에는 철자로 표기되거나 약식인 월 `(MONTH, MON)`, 요일 `(DAY, DY)`, 오전/오후 표시자 `(AM, PM)`, 시대 표시자 `(BC, AD)`의 모든 변형이 포함됩니다.

이 예에서는 `TIMESTAMP` 컬럼이 있는 테이블을 생성합니다:

```sql
CREATE TABLE ts_tbl (ts_col TIMESTAMP);
```

이 예는 `TO_CHAR` 함수의 `IMMUTABLE` 형태로 인덱스를 성공적으로 생성하는 것을 보여줍니다:

```sql
edb=# CREATE INDEX ts_idx ON ts_tbl (TO_CHAR(ts_col,'YYYY-MM-DD HH24:MI:SS'));
CREATE INDEX
edb=# \dS ts_idx
```

출력:

```text
                                   Index "public.ts_idx"
 Column  |       Type        |                         Definition
---------+-------------------+------------------------------------------------------------
 to_char | character varying | to_char(ts_col, 'YYYY-MM-DD HH24:MI:SS'::character varying)
btree, for table "public.ts_tbl"
```

다음은 오류가 발생합니다. `TO_CHAR` 함수에 지정된 형식이 3자 월 약어 `MON`이 로케일 설정에 따라 다른 반환 값을 낳을 수 있어 `IMMUTABLE` 형태 사용을 막기 때문입니다:

```sql
edb=# CREATE INDEX ts_idx_2 ON ts_tbl (TO_CHAR(ts_col, 'DD-MON-YYYY'));
ERROR:  functions in index expression must be marked IMMUTABLE
```

### TO_CHAR, TO_NUMBER, SUBSTR 함수의 차이 (Difference TO_CHAR, TO_NUMBER, and SUBSTR functions)

Oracle 데이터베이스와 호환되는 모드로 클러스터를 만들려면 `INITDBOPTS` 변수를 사용해 데이터베이스를 초기화하십시오. PostgreSQL 모드로 생성된 클러스터는 호환성 기능을 포함하지 않습니다. PostgreSQL 모드로 새 클러스터를 만들려면, PostgreSQL과 유사한 동작을 제공하는 `"--no-redwood-compat"` 옵션을 사용하십시오.

다음 표에 나온 함수 중 하나를 포함하는 `SELECT` 문은 EDB Postgres Advanced Server와 PostgreSQL에서 표시된 결과를 반환합니다. `TO_CHAR`, `TO_NUMBER`, `SUBSTR` 함수의 차이가 나열되어 있습니다.

**TO_CHAR**: 주어진 형식에 따라 타임스탬프를 문자열로 변환합니다.

##### 참고 (Note)

- `'syear'`, `'syyyy'`, `'year'`, `'rrrr'`, `'sp'`, `'spth'`, `'scc'`, `'rr'`, `'ff'`, `'ff7'`, `'ff8'`, `'ff9'`, 그리고 소문자 `'of'`, `'tzh'`, `'tzm'` 패턴은 PostgreSQL에서 지원되지 않습니다.
- `'TH'` 수정자는 EDB Postgres Advanced Server에서 패딩 0을 더 적게 추가합니다.
- 접미사를 대문자로 표시하는 대문자 `'TH'` 패턴은 EDB Postgres Advanced Server에서 지원되지 않습니다. `'TH/th'` 패턴을 지정하면 접미사는 항상 소문자로 표시됩니다.
- 수정자는 `'FM'` 패턴에 나타날 수 있으며, 각 출현은 수정자의 효과를 토글합니다. PostgreSQL에서 `'FM'` 패턴의 효과를 끄려면 짝수 번, 켜려면 홀수 번 지정합니다. 그러나 EDB Postgres Advanced Server에서는 `'FM'` 패턴을 지정하면 항상 `'FM'` 효과가 켜집니다.

이 표는 `TO_CHAR(timestamp, text)` 함수의 예를 보여줍니다:

| `SELECT TO_CHAR(current_timestamp, 'syear');` | `twenty twenty one` | `s1ear` |

**TO_NUMBER**: 주어진 형식에 따라 문자열을 numeric으로 변환합니다.

##### 참고 (Note)

- PostgreSQL은 형식 옵션을 엄격하게 검사하지 않습니다. 반면 EDB Postgres Advanced Server는 입력 문자열이 시작 부분에 `'-'`나 `','`를 가진 몇 가지 경우를 제외하고 형식을 검사합니다. 형식 문자열의 해당 위치에 이 문자들에 대한 패턴을 제공할 필요는 없습니다.
- PostgreSQL에서는 입력 문자열의 모든 자릿수를 패턴과 일치시킬 필요가 없습니다. 유효한 패턴이 있는 자릿수만큼 입력 문자열에서 출력합니다. EDB Postgres Advanced Server는 입력 문자열에 있는 모든 자릿수에 대한 패턴을 제공하지 않으면 오류를 던집니다.
- PostgreSQL은 입력이나 형식 문자열에 있는 유효하지 않은 문자를 무시합니다. EDB Postgres Advanced Server는 오류를 던집니다. 이런 동작은 다양한 패턴 유형에서 많은 차이를 낳을 수 있습니다.
- `'PL'`, `'PR'`, `'SG'` 패턴은 EDB Postgres Advanced Server에서 지원되지 않습니다.

| `SELECT TO_NUMBER('1,11', '0,0');` | Invalid input syntax for type numeric: "111" | `11` |
| `SELECT TO_NUMBER('1-1', '0S0');` | Invalid format string: "0S0" | `-11` |
| `SELECT TO_NUMBER('1-1', '000');` | Invalid input syntax for type numeric: "1-1" | `11` |
| `SELECT TO_NUMBER('1.11', '000');` | Invalid input syntax for type numeric: "1.11" | `11` |

| `SELECT TO_NUMBER('01,000', '99G999');` / `SELECT TO_NUMBER('01,000', 'FM99G999');` | `1000` | `1000` / `100` |

**SUBSTR**: 문자 값의 부분 문자열을 반환합니다.

##### 참고 (Note)

- 문자열의 인덱스는 `1`부터 시작합니다. PostgreSQL에서 시작 파라미터가 0이고 한 문자만 가져오면 결과는 공백을 반환합니다. 두 문자를 가져오려 하면 시작 위치에 0이 지정되었으므로 한 문자를 보여줍니다. 그러나 EDB Postgres Advanced Server에서는 시작 파라미터가 0이면 내부적으로 `1`로 변환되어 검색을 시작합니다.
- PostgreSQL에서는 시작 파라미터에 음수 값이 허용되지 않습니다. EDB Postgres Advanced Server에서는 음수 값이 역방향 검색을 일으킵니다.
- PostgreSQL은 시작과 길이 파라미터에 numeric 값이 전달되면 오류를 던집니다. EDB Postgres Advanced Server는 이를 정수로 변환합니다.

이 표는 `SUBSTR(string, from, count)`, `SUBSTR(string, from)`, `SUBSTR(string, from, count)::bytea`, `SUBSTR(string, from)::bytea` 함수의 예를 보여줍니다:

| 예 | EDB Postgres Advanced Server | PostgreSQL |
| --- | --- | --- |
| `SELECT (SUBSTR('ABCDEFGH', 0, 1));` | `A` | 공백 반환 |
| `SELECT (SUBSTR('ABCD', -1, 1));` / `SELECT (SUBSTR('ABCD', -4, 1));` | `D` / `A` | 공백 반환 |
| `SELECT (SUBSTR('ABCD', 1, -1));` | 공백 반환 | ERROR: negative substring length not allowed |
| `SELECT (SUBSTR('ABCD', 1.1, 1));` | `A` | ERROR: function substr(unknown, numeric, integer) does not exist |
| `SELECT (SUBSTR('ABCD', 1, 1.1));` | `A` | ERROR: function substr(unknown, integer, numeric) does not exist |
| `SELECT (SUBSTR('ABCD', -1));` | `D` | `ABCD` |
| `SELECT (SUBSTR('ABCD', 1.1));` | `ABCD` | ERROR: function substr(unknown, numeric) does not exist |
| `SELECT (SUBSTR('ABCDEFGH', 0, 1))::bytea;` | `\x41` | `\x` |
| `SELECT (SUBSTR('ABCD', 5,1))::bytea;` | 공백 반환 | `\x` |
| `SELECT (SUBSTR('ABCDEFGH', -1, 1))::bytea;` | `\x48` | `\x` |
| `SELECT (SUBSTR('ABCD', -5, 1))::bytea;` | 공백 반환 | `\x` |
| `SELECT (SUBSTR('ABCD', 1, -1))::bytea;` | 공백 반환 | ERROR: negative substring length not allowed |
| `SELECT (SUBSTR('ABCD', 1.1, 1))::bytea;` | `\x41` | ERROR: function substr(unknown, numeric, integer) does not exist |
| `SELECT (SUBSTR('ABCD', 1, 1.1))::bytea;` | `\x41` | ERROR: function substr(unknown, integer, numeric) does not exist |
| `SELECT (SUBSTR('ABCD', 5))::bytea;` | 공백 반환 | `\x` |
| `SELECT (SUBSTR('ABCD', -1))::bytea;` | `\x44` | `\x41424344` |
| `SELECT (SUBSTR('ABCD', 1.1))::bytea;` | `\x41424344` | ERROR: function substr(unknown, numeric) does not exist |
