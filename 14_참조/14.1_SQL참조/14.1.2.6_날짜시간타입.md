## 개요 (Overview)

다음 날짜/시간 타입에 대한 논의는 테이블을 생성하거나 변경할 때마다 구성 파라미터 `edb_redwood_date`가 `TRUE`로 설정되어 있다고 가정합니다.

`DATE`가 데이터 정의 언어(DDL) 명령 `CREATE TABLE`이나 `ALTER TABLE`에서 컬럼의 데이터 타입으로 나타나면, 테이블 정의가 데이터베이스에 저장되는 시점에 `TIMESTAMP`로 변환됩니다. 따라서 날짜와 함께 시간 구성 요소도 컬럼에 저장됩니다.

`DATE`는 다음의 데이터 타입으로 나타날 수 있습니다:

- SPL 선언 섹션의 변수
- SPL 프로시저나 SPL 함수의 형식 파라미터(formal parameter)의 데이터 타입
- SPL 함수의 반환 타입

이 경우들에서는 항상 `TIMESTAMP`로 변환되므로 시간 구성 요소가 있으면 처리할 수 있습니다.

`TIMESTAMP`는 초(seconds) 필드에 유지되는 소수 자릿수를 지정하는 선택적 정밀도 값 `p`를 받습니다. `p`의 허용 범위는 0에서 6까지입니다. 기본값은 `6`입니다.

`TIMESTAMP` 값이 배정밀도 부동소수점 숫자로 저장되는 경우(기본값), 유효 정밀도 한계는 6보다 작을 수 있습니다. `TIMESTAMP` 값은 2000-01-01 자정 전후의 초 단위로 저장됩니다. 2000-01-01에서 몇 년 이내의 날짜에 대해서는 마이크로초 정밀도가 달성되지만, 더 먼 날짜에서는 정밀도가 저하됩니다. `TIMESTAMP` 값이 8바이트 정수로 저장되는 경우(컴파일 타임 옵션), 전체 값 범위에 걸쳐 마이크로초 정밀도가 가능합니다. 그러나 8바이트 정수 타임스탬프는 표에 나온 것보다 제한된 날짜 범위(기원전 4713년 ~ 서기 294276년)를 갖습니다.

`TIMESTAMP (p) WITH TIME ZONE`은 `TIMESTAMP (p)`와 유사하지만 시간대도 포함합니다.

## INTERVAL 타입 (INTERVAL types)

`INTERVAL` 값은 기간을 지정합니다. `INTERVAL` 타입 값은 데이터 값을 설명하는 필드들로 구성됩니다. 다음 표는 `INTERVAL` 타입에서 허용되는 필드를 나열합니다.

| 필드 이름 | 허용되는 INTERVAL 값 |
| --- | --- |
| `YEAR` | 정수 값(양수 또는 음수) |
| `MONTH` | 0 ~ 11 |
| `DAY` | 정수 값(양수 또는 음수) |
| `HOUR` | 0 ~ 23 |
| `MINUTE` | 0 ~ 59 |
| `SECOND` | 0 ~ 59.9(p), 여기서 9(p)는 소수 초의 정밀도 |

필드는 `YEARS`에서 `MONTHS`로, `DAYS`에서 `HOURS`, `MINUTES`, 그리고 `SECONDS`로 내림차순으로 제시되어야 합니다.

EDB Postgres Advanced Server는 Oracle 데이터베이스와 호환되는 두 가지 `INTERVAL` 타입을 지원합니다.

EDB Postgres Advanced Server가 지원하는 첫 번째 변형은 `INTERVAL DAY TO SECOND [(p)]`입니다. `INTERVAL DAY TO SECOND [(p)]`는 일, 시, 분, 초 단위로 시간 간격을 저장합니다. `p`는 `second` 필드의 정밀도를 지정합니다.

EDB Postgres Advanced Server는 다음 값을 1일, 2시간, 34분, 5.678초로 해석합니다:

`INTERVAL '1 2:34:5.678' DAY TO SECOND(3)`

EDB Postgres Advanced Server는 다음 값을 1일 23시간으로 해석합니다:

`INTERVAL '1 23' DAY TO HOUR`

EDB Postgres Advanced Server는 다음 값을 2시간 34분으로 해석합니다:

`INTERVAL '2:34' HOUR TO MINUTE`

EDB Postgres Advanced Server는 다음 값을 2시간 34분 56.13초로 해석합니다. 지정된 정밀도 때문에 소수 초가 13으로 반올림됩니다:

`INTERVAL '2:34:56.129' HOUR TO SECOND(2)`

EDB Postgres Advanced Server가 지원하는, Oracle 데이터베이스와 호환되는 두 번째 변형은 `INTERVAL YEAR TO MONTH`입니다. 이 변형은 연, 월 단위로 시간 간격을 저장합니다.

EDB Postgres Advanced Server는 다음 값을 12년 3개월로 해석합니다:

`INTERVAL '12-3' YEAR TO MONTH`

EDB Postgres Advanced Server는 다음 값을 12년 3개월로 해석합니다:

`INTERVAL '456' YEAR(2)`

EDB Postgres Advanced Server는 다음 값을 25년으로 해석합니다:

`INTERVAL '300' MONTH`

## 날짜/시간 입력 (Date/time input)

날짜와 시간 입력은 ISO 8601 SQL 호환 형식, Oracle 기본 `dd-MON-yy` 형식, 그리고 어느 구성 요소가 연·월·일인지 모호하지 않은 경우 여러 다른 형식으로도 허용됩니다. 그러나 모호성을 피하기 위해 `TO_DATE` 함수 사용을 강력히 권장합니다.

모든 날짜나 시간 리터럴 입력은 텍스트 문자열처럼 작은따옴표로 묶으십시오. 다음 SQL 표준 구문도 허용됩니다:

```sql
type 'value'
```

`type`은 `DATE` 또는 `TIMESTAMP`입니다. `value`는 날짜/시간 텍스트 문자열입니다.

### 날짜 (Dates)

다음 블록은 날짜에 대해 가능한 입력 형식 일부를 보여주며, 모두 1999년 1월 8일에 해당합니다:

```text
Example
January 8, 1999
1999-01-08
1999-Jan-08
Jan-08-1999
08-Jan-1999
08-Jan-99
Jan-08-99
19990108
990108
```

날짜 값을 `DATE`나 `TIMESTAMP` 컬럼 또는 변수에 할당할 수 있습니다. 날짜 값 뒤에 시간 값을 붙이지 않으면 시, 분, 초 필드는 0으로 설정됩니다.

### 시간 (Times)

날짜나 타임스탬프의 시간 구성 요소의 예 일부를 표에 나타냅니다.

| 예 | 설명 |
| --- | --- |
| `04:05:06.789` | ISO 8601 |
| `04:05:06` | ISO 8601 |
| `04:05` | ISO 8601 |
| `040506` | ISO 8601 |
| `04:05 AM` | 04:05와 동일; AM은 값에 영향 없음 |
| `04:05 PM` | 16:05와 동일; 입력 시(hour)는 12 이하여야 함 |

### 타임스탬프 (Time stamps)

타임스탬프의 유효한 입력은 날짜와 시간의 연결로 구성됩니다. 타임스탬프의 날짜 부분은 [날짜](https://www.enterprisedb.com/docs/epas/latest/reference/sql_reference/02_data_types/04_date_time_types/#dates)에 나온 예 중 아무 형식으로나 지정할 수 있습니다. 타임스탬프의 시간 부분은 [시간](https://www.enterprisedb.com/docs/epas/latest/reference/sql_reference/02_data_types/04_date_time_types/#times)의 표에 나온 예 중 아무 형식으로나 지정할 수 있습니다.

이 예는 Oracle 기본 형식을 따르는 타임스탬프를 보여줍니다:

`08-JAN-99 04:05:06`

이 예는 ISO 8601 표준을 따르는 타임스탬프를 보여줍니다:

`1999-01-08 04:05:06`

### 특수 값 (Special Values)

PostgreSQL은 편의를 위해 다음 표에 나온 여러 특수 날짜/시간 입력 값을 지원합니다. `infinity`와 `-infinity` 값은 시스템 내부에서 특수하게 표현되어 변경 없이 표시됩니다. 나머지는 읽을 때 일반 날짜/시간 값으로 변환되는 표기상의 축약형일 뿐입니다. (특히 `now` 및 관련 문자열은 읽는 즉시 특정 시간 값으로 변환됩니다.) 이 값들을 모두 SQL 명령에서 상수로 사용할 때는 작은따옴표로 묶어야 합니다.

| 입력 문자열 | 유효 타입 | 설명 |
| --- | --- | --- |
| epoch | date, timestamp | 1970-01-01 00:00:00+00 (Unix 시스템 시간 0) |
| infinity | date, timestamp | 다른 모든 타임스탬프보다 나중 |
| -infinity | date, timestamp | 다른 모든 타임스탬프보다 먼저 |
| now | date, time, timestamp | 현재 트랜잭션의 시작 시간 |
| today | date, timestamp | 오늘 자정(00:00) |
| tomorrow | date, timestamp | 내일 자정(00:00) |
| yesterday | date, timestamp | 어제 자정(00:00) |
| allballs | time | 00:00:00.00 UTC |

다음 SQL 호환 함수도 해당 데이터 타입에 대한 현재 시간 값을 얻는 데 사용할 수 있습니다:

`CURRENT_DATE` `CURRENT_TIME` `CURRENT_TIMESTAMP` `LOCALTIME` `LOCALTIMESTAMP`

이들은 SQL 함수이며 데이터 입력 문자열에서는 인식되지 않는다는 점에 유의하십시오.

##### 참고 (Note)

입력 문자열 `now`, `today`, `tomorrow`, `yesterday`는 대화형 SQL 명령에서 사용하기에 좋지만, 예를 들어 준비된 구문(prepared statement), 뷰, 함수 정의처럼 명령이 나중에 실행되도록 저장될 때는 놀라운 동작을 할 수 있습니다. 문자열이 특정 시간 값으로 변환되어, 그 값이 오래되어도 계속 사용될 수 있습니다. 그런 문맥에서는 대신 SQL 함수 중 하나를 사용하십시오. 예를 들어 `CURRENT_DATE + 1`이 `tomorrow::date`보다 안전합니다.

## 날짜/시간 출력 (Date/time output)

날짜/시간 타입의 기본 출력 형식은 다음 중 하나입니다:

- (`dd-MON-yy`), *Redwood 날짜 스타일(Redwood date style)*이라 불리며 Oracle 데이터베이스와 호환됨
- (`yyyy-mm-dd`) ISO 8601 형식이라 불림

사용하는 형식은 데이터베이스에 대한 애플리케이션 인터페이스에 따라 달라집니다. SQL Interactive 같은 JDBC를 사용하는 애플리케이션은 항상 날짜를 ISO 8601 형태로 표시합니다. PSQL 같은 다른 애플리케이션은 날짜를 Redwood 형태로 표시합니다.

다음 표는 Redwood와 ISO 8601 두 스타일의 출력 형식 예를 보여줍니다.

| 설명 | 예 |
| --- | --- |
| Redwood 스타일 | `31-DEC-05 07:37:16` |
| ISO 8601/SQL 표준 | `1997-12-17 07:37:16` |

## 내부 구현 (Internals)

EDB Postgres Advanced Server는 모든 날짜/시간 계산에 율리우스 날짜(Julian dates)를 사용합니다. 율리우스 날짜는 1년의 길이가 365.2425일이라는 가정에 기반하여 기원전 4713년 이후의 모든 날짜를 정확하게 예측하거나 계산합니다.

## 시간대 (Time Zones)

PostgreSQL은 역사적 시간대 규칙 정보를 위해 널리 사용되는 IANA(Olson) 시간대 데이터베이스를 사용합니다. 미래 시간에 대해서는, 특정 시간대에 대해 알려진 최신 규칙이 무기한 미래까지 계속 적용된다고 가정합니다.

PostgreSQL은 일반적인 사용에 대해 SQL 표준 정의와 호환되도록 노력합니다. 그러나 SQL 표준은 날짜와 시간 타입 및 기능이 기묘하게 섞여 있습니다. 두 가지 명백한 문제는:

- date 타입은 연관된 시간대를 가질 수 없지만 time 타입은 가질 수 있습니다. 현실 세계의 시간대는 오프셋이 일광 절약 시간 경계로 인해 연중 달라질 수 있으므로, 날짜뿐 아니라 시간과 함께 연관되지 않으면 거의 의미가 없습니다.
- 기본 시간대는 UTC로부터의 상수 숫자 오프셋으로 지정됩니다. 따라서 DST 경계를 넘어 날짜/시간 산술을 할 때 일광 절약 시간에 적응하는 것이 불가능합니다.

이러한 어려움을 해결하기 위해, 시간대를 사용할 때는 날짜와 시간을 모두 포함하는 날짜/시간 타입을 사용하는 것을 권장합니다. `time with time zone` 타입 사용은 권장하지 않습니다(레거시 애플리케이션 및 SQL 표준 준수를 위해 PostgreSQL이 지원하기는 합니다). PostgreSQL은 날짜나 시간만 포함하는 타입에 대해 로컬 시간대를 가정합니다.

모든 시간대 인식 날짜와 시간은 내부적으로 UTC로 저장됩니다. 클라이언트에 표시되기 전에 `TimeZone` 구성 파라미터로 지정된 시간대의 로컬 시간으로 변환됩니다.

PostgreSQL은 세 가지 다른 형태로 시간대를 지정할 수 있게 합니다:

- 전체 시간대 이름. 예: America/New_York. 인식되는 시간대 이름은 `pg_timezone_names` 뷰에 나열됩니다. PostgreSQL은 이 목적으로 널리 사용되는 IANA 시간대 데이터를 사용하므로 다른 소프트웨어도 동일한 시간대 이름을 인식합니다.
- 시간대 약어. 예: PST. 이러한 지정은 UTC로부터의 특정 오프셋만 정의하며, 일광 절약 전환 규칙 집합을 암시할 수 있는 전체 시간대 이름과 대조됩니다. 인식되는 약어는 `pg_timezone_abbrevs` 뷰에 나열됩니다. 구성 파라미터 `TimeZone`이나 `log_timezone`을 시간대 약어로 설정할 수는 없지만, 날짜/시간 입력 값과 `AT TIME ZONE` 연산자에서는 약어를 사용할 수 있습니다.
- PostgreSQL은 POSIX 스타일 시간대 지정도 허용합니다. 이 옵션은 보통 명명된 시간대 사용보다 바람직하지는 않지만, 적합한 IANA 시간대 항목이 없는 경우 필요할 수 있습니다.

요약하면, 약어와 전체 이름의 차이는 다음과 같습니다: 약어는 UTC로부터의 특정 오프셋을 나타내는 반면, 전체 이름 중 다수는 로컬 일광 절약 시간 규칙을 암시하므로 두 개의 가능한 UTC 오프셋을 갖습니다. 예를 들어 2014-06-04 12:00 America/New_York는 뉴욕의 정오 로컬 시간을 나타내며, 이 특정 날짜에는 동부 일광 절약 시간(UTC-4)이었습니다. 따라서 2014-06-04 12:00 EDT는 같은 시간 순간을 지정합니다. 그러나 2014-06-04 12:00 EST는 그 날짜에 일광 절약이 명목상 시행 중이었는지와 관계없이 동부 표준시(UTC-5)의 정오를 지정합니다.

문제를 복잡하게 하는 것은, 일부 관할 구역이 서로 다른 시기에 서로 다른 UTC 오프셋을 의미하기 위해 동일한 시간대 약어를 사용해 왔다는 점입니다. 예를 들어 모스크바에서 MSK는 어떤 해에는 UTC+3을, 다른 해에는 UTC+4를 의미했습니다. PostgreSQL은 이러한 약어를 지정된 날짜에 그것이 의미했던(또는 가장 최근에 의미했던) 대로 해석합니다. 그러나 위 EST 예처럼 이것이 그 날짜의 로컬 표준시와 반드시 같지는 않습니다.

모든 경우에 시간대 이름과 약어는 대소문자를 구분하지 않고 인식됩니다. (이는 일부 문맥에서는 대소문자를 구분하고 다른 문맥에서는 구분하지 않던 8.2 이전 PostgreSQL 버전에서의 변경 사항입니다.)

시간대 이름도 약어도 서버에 하드코딩되어 있지 않습니다. 이들은 설치 디렉터리의 `.../share/timezone/` 및 `.../share/timezonesets/` 아래에 저장된 구성 파일에서 얻습니다.

`TimeZone` 구성 파라미터는 `postgresql.conf` 파일에서, 또는 서버 구성을 사용하는 다른 표준 방법으로 설정할 수 있습니다. 또한 몇 가지 특수한 설정 방법이 있습니다:

- SQL 명령 `SET TIME ZONE`은 세션의 시간대를 설정합니다. 이는 더 SQL 스펙 호환적인 구문을 갖는 `SET TIMEZONE TO`의 다른 표기입니다.
- `PGTZ` 환경 변수는 libpq 클라이언트가 연결 시 서버에 `SET TIME ZONE` 명령을 보내는 데 사용됩니다.

## 인터벌 입력 (Interval Input)

인터벌 값은 다음의 상세 구문으로 작성할 수 있습니다:

```text
[@] quantity unit [quantity unit...] [direction]
```

여기서 `quantity`는 숫자(부호 있을 수 있음), `unit`은 `microsecond`, `millisecond`, `second`, `minute`, `hour`, `day`, `week`, `month`, `year`, `decade`, `century`, `millennium` 또는 이들 단위의 약어나 복수형, `direction`은 `ago` 또는 비어 있습니다. 골뱅이표(@)는 선택적 잡음 문자입니다. 서로 다른 단위의 양은 적절한 부호 처리와 함께 암시적으로 더해집니다. `ago`는 모든 필드를 부정합니다. 이 구문은 `IntervalStyle`이 `postgres_verbose`로 설정된 경우 인터벌 출력에도 사용됩니다.

일, 시, 분, 초의 양은 명시적 단위 표시 없이 지정할 수 있습니다. 예를 들어 '1 12:59:10'은 '1 day 12 hours 59 min 10 sec'와 동일하게 읽힙니다. 또한 연과 월의 조합은 대시로 지정할 수 있습니다. 예: '200-10'은 '200 years 10 months'와 동일하게 읽힙니다. (이 더 짧은 형태는 사실 SQL 표준이 허용하는 유일한 형태이며, `IntervalStyle`이 `sql_standard`로 설정된 경우 출력에 사용됩니다.)

인터벌 값은 표준 4.4.3.2절의 "지정자가 있는 형식(format with designators)"이나 4.4.3.3절의 "대안 형식(alternative format)"을 사용해 ISO 8601 시간 간격으로도 작성할 수 있습니다. 지정자가 있는 형식은 다음과 같습니다:

```text
P quantity unit [ quantity unit ...] [ T [ quantity unit ...]]
```

문자열은 P로 시작해야 하며, 시각(time-of-day) 단위를 도입하는 T를 포함할 수 있습니다. 다음 표는 사용 가능한 단위 약어를 제공합니다. 단위는 생략할 수 있고 임의 순서로 지정할 수 있지만, 일보다 작은 단위는 T 뒤에 나와야 합니다. 특히 M의 의미는 T 앞인지 뒤인지에 따라 달라집니다.

| 약어 | 의미 |
| --- | --- |
| Y | 연(Years) |
| M | 월(Months, 날짜 부분) |
| W | 주(Weeks) |
| D | 일(Days) |
| H | 시(Hours) |
| M | 분(Minutes) |
| S | 초(Seconds) |

대안 형식에서는:

```text
P [ years-months-days ] [ T hours:minutes:seconds ]
```

문자열은 P로 시작해야 하고, T가 인터벌의 날짜 부분과 시간 부분을 구분합니다. 값은 ISO 8601 날짜와 유사한 숫자로 주어집니다.

필드 지정과 함께 인터벌 상수를 작성할 때, 또는 필드 지정으로 정의된 인터벌 컬럼에 문자열을 할당할 때, 표시되지 않은 양의 해석은 필드에 따라 달라집니다. 예를 들어 `INTERVAL '1' YEAR`는 1년으로 읽히는 반면, `INTERVAL '1'`은 1초를 의미합니다. 또한 필드 지정이 허용하는 최하위 필드보다 "오른쪽"의 필드 값은 조용히 폐기됩니다. 예를 들어 `INTERVAL '1 day 2:03:04' HOUR TO MINUTE`를 작성하면 초 필드는 삭제되지만 일 필드는 삭제되지 않습니다.

SQL 표준에 따르면 인터벌 값의 모든 필드는 같은 부호를 가져야 하므로, 앞의 음수 부호는 모든 필드에 적용됩니다. 예를 들어 인터벌 리터럴 '-1 2:03:04'의 음수 부호는 일 부분과 시/분/초 부분 모두에 적용됩니다. PostgreSQL은 필드가 서로 다른 부호를 갖도록 허용하며, 전통적으로 텍스트 표현의 각 필드를 독립적으로 부호가 있는 것으로 취급하므로, 이 예에서 시/분/초 부분은 양수로 간주됩니다. `IntervalStyle`이 `sql_standard`로 설정되면 (추가 부호가 나타나지 않는 경우에만) 앞의 부호가 모든 필드에 적용되는 것으로 간주됩니다. 그렇지 않으면 전통적인 PostgreSQL 해석이 사용됩니다. 모호성을 피하려면, 어떤 필드가 음수인 경우 각 필드에 명시적 부호를 붙이는 것이 권장됩니다.

필드 값은 소수부를 가질 수 있습니다. 예: '1.5 weeks' 또는 '01:02:03.45'. 그러나 인터벌은 내부적으로 세 개의 정수 단위(월, 일, 마이크로초)만 저장하므로 소수 단위는 더 작은 단위로 넘겨져야 합니다. 월보다 큰 단위의 소수부는 정수 개월로 반올림됩니다. 예: '1.5 years'는 '1 year 6 mons'가 됩니다. 주와 일의 소수부는 한 달을 30일, 하루를 24시간으로 가정하여 정수 개의 일과 마이크로초로 계산됩니다. 예: '1.75 months'는 1 mon 22 days 12:00:00이 됩니다. 출력 시 소수로 표시되는 것은 초뿐입니다.

다음 표는 유효한 인터벌 입력의 예 일부를 보여줍니다.

| 예 | 설명 |
| --- | --- |
| 1-2 | SQL 표준 형식: 1년 2개월 |
| 3 4:05:06 | SQL 표준 형식: 3일 4시간 5분 6초 |
| 1 year 2 months 3 days 4 hours 5 minutes 6 seconds | 전통적 Postgres 형식: 1년 2개월 3일 4시간 5분 6초 |
| P1Y2M3DT4H5M6S | ISO 8601 "지정자가 있는 형식": 위와 같은 의미 |
| P0001-02-03T04:05:06 | ISO 8601 "대안 형식": 위와 같은 의미 |

내부적으로 인터벌 값은 월, 일, 마이크로초로 저장됩니다. 이는 한 달의 일수가 다양하고, 일광 절약 시간 조정이 관련되면 하루가 23시간 또는 25시간일 수 있기 때문입니다. 월과 일 필드는 정수인 반면 마이크로초 필드는 소수 초를 저장할 수 있습니다. 인터벌은 보통 상수 문자열이나 타임스탬프 뺄셈으로 생성되므로 이 저장 방식은 대부분의 경우 잘 동작하지만, 예상치 못한 결과를 낳을 수 있습니다:

```text
SELECT EXTRACT(hours from '80 minutes'::interval);
 date_part
-----------
         1

SELECT EXTRACT(days from '80 hours'::interval);
 date_part
-----------
         0
```

정상 범위를 초과하는 일과 시간을 조정하기 위해 `justify_days`와 `justify_hours` 함수를 사용할 수 있습니다.

## 인터벌 출력 (Interval Output)

`SET intervalstyle` 명령을 사용해 인터벌 타입의 출력 형식을 `sql_standard`, `postgres`, `postgres_verbose`, `iso_8601` 네 가지 스타일 중 하나로 설정할 수 있습니다. 기본값은 `postgres` 형식입니다. 이 절의 표는 각 출력 스타일의 예를 보여줍니다.

`sql_standard` 스타일은 인터벌 값이 표준의 제한(연-월만이거나 일-시간만이며, 양수와 음수 구성 요소가 섞이지 않음)을 충족하면 SQL 표준의 인터벌 리터럴 문자열 명세를 준수하는 출력을 생성합니다. 그렇지 않으면, 출력은 부호가 섞인 인터벌을 명확히 구분하기 위해 명시적 부호를 추가한 표준 연-월 리터럴 문자열 뒤에 일-시간 리터럴 문자열이 오는 형태가 됩니다.

`postgres` 스타일의 출력은 `DateStyle` 파라미터가 ISO로 설정되었을 때 8.4 이전 PostgreSQL 릴리스의 출력과 일치합니다.

`postgres_verbose` 스타일의 출력은 `DateStyle` 파라미터가 비-ISO로 설정되었을 때 8.4 이전 PostgreSQL 릴리스의 출력과 일치합니다.

`iso_8601` 스타일의 출력은 ISO 8601 표준에 설명된 "지정자가 있는 형식"과 일치합니다.

| 스타일 지정 | 연-월 인터벌 | 일-시간 인터벌 | 혼합 인터벌 |
| --- | --- | --- | --- |
| sql_standard | 1-2 | 3 4:05:06 | -1-2 +3 -4:05:06 |
| postgres | 1 year 2 mons | 3 days 04:05:06 | -1 year -2 mons +3 days -04:05:06 |
| postgres_verbose | @ 1 year 2 mons | @ 3 days 4 hours 5 mins 6 secs | @ 1 year 2 mons -3 days 4 hours 5 mins 6 secs ago |
| iso_8601 | P1Y2M | P3DT4H5M6S | P-1Y-2M3DT-4H-5M-6S |
