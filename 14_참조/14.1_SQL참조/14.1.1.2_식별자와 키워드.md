# 식별자와 키워드 (Identifiers and Key Words) — EPAS 18 Reference

> 원문: [EPAS v18 — Reference › SQL reference › SQL syntax › Identifiers and key words](https://www.enterprisedb.com/docs/epas/latest/reference/sql_reference/01_sql_syntax/02_identifiers_and_key_words/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·식별자·코드는 원문 그대로 보존했습니다.

`SELECT`, `UPDATE`, `VALUES` 같은 토큰은 *키워드(key word)*, 즉 SQL 언어에서 고정된 의미를 갖는 단어의 예입니다. `MY_TABLE`과 `A` 같은 토큰은 *식별자(identifier)*의 예입니다. 이들은 사용하는 명령에 따라 테이블, 컬럼 또는 기타 데이터베이스 객체의 이름을 식별합니다. 그래서 때때로 *이름(name)*이라고도 불립니다. 키워드와 식별자는 동일한 *어휘 구조(lexical structure)*를 가지므로, 언어를 알지 못하면 어떤 토큰이 식별자인지 키워드인지 알 수 없습니다.

SQL 식별자와 키워드는 반드시 문자(`a-z` 또는 `A-Z`) 또는 밑줄(`_`)로 시작해야 합니다. 식별자나 키워드의 이후 문자는 문자, 밑줄, 숫자(`0-9`), 하나 이상의 달러 기호(`$`), 또는 샵 기호(`#`)일 수 있습니다. 그러나 SQL 표준에 따르면 식별자에 달러 기호는 허용되지 않으므로, 이를 사용하면 애플리케이션의 이식성이 떨어질 수 있습니다. SQL 표준은 숫자를 포함하거나 밑줄로 시작하거나 끝나는 키워드를 앞으로 정의하지 않을 것입니다. 따라서 그러한 속성을 가진 식별자를 사용하면 향후 버전의 SQL과 충돌하지 않습니다.

식별자와 키워드 이름은 대소문자를 구분하지 않습니다. 따라서 다음 두 명령은 동등합니다:

```sql
UPDATE MY_TABLE SET A = 5;
```

동등한 명령은 다음과 같습니다:

```sql
uPDaTE my_TabLE SeT a = 5;
```

흔히 사용되는 관례는 키워드는 대문자로, 이름은 소문자로 작성하는 것입니다. 예:

```sql
UPDATE my_table SET a = 5;
```

두 번째 종류의 식별자는 *구분 식별자(delimited identifier)* 또는 *따옴표 식별자(quoted identifier)*입니다. 이는 임의의 문자 시퀀스를 큰따옴표(`"`)로 묶어 형성합니다. 구분 식별자는 항상 식별자이며 결코 키워드가 아닙니다. 따라서 `"select"`를 사용하여 `"select"`라는 이름의 컬럼이나 테이블을 참조할 수 있습니다. 따옴표 없는 `select`는 키워드로 간주되어 테이블이나 컬럼 이름이 와야 할 위치에 사용되면 구문 분석 오류를 일으킵니다. 위 예제는 다음과 같이 따옴표 식별자로 작성할 수 있습니다:

```sql
UPDATE "my_table" SET "a" = 5;
```

따옴표 식별자에는 숫자 코드 0인 문자를 제외한 모든 문자를 포함할 수 있습니다.

큰따옴표를 포함하려면 큰따옴표 두 개를 사용합니다. 이를 통해 공백이나 앰퍼샌드(&)를 포함하는 등, 그 외에는 만들 수 없는 테이블이나 컬럼 이름을 구성할 수 있습니다. 길이 제한은 여전히 적용됩니다.

식별자를 따옴표로 묶으면 대소문자를 구분하게 되는 반면, 따옴표 없는 이름은 항상 소문자로 변환됩니다. 예를 들어 식별자 `FOO`, `foo`, `"foo"`는 EDB Postgres Advanced Server에서 동일하게 간주되지만, `"Foo"`와 `"FOO"`는 이 세 개 및 서로 간에 다릅니다. 따옴표 없는 이름을 소문자로 변환하는 것은 Oracle 데이터베이스와 호환되지 않습니다. Oracle 구문에서는 따옴표 없는 이름이 대문자로 변환됩니다. 예를 들어 `foo`는 `"foo"`가 아니라 `"FOO"`와 동등합니다. 이식 가능한 애플리케이션을 작성하려면 특정 이름을 항상 따옴표로 묶거나 절대 묶지 마십시오.
