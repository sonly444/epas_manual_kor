## 개요 (Overview)

범위 타입은 어떤 요소 타입(범위의 서브타입subtype이라 함)의 값 범위를 나타내는 데이터 타입입니다. 예를 들어 `timestamp`의 범위는 회의실이 예약된 시간 범위를 나타내는 데 사용할 수 있습니다. 이 경우 데이터 타입은 `tsrange`(timestamp range의 약자)이고 `timestamp`가 서브타입입니다. 서브타입은 요소 값이 값 범위의 안, 앞, 뒤 중 어디에 있는지 잘 정의되도록 전순서(total order)를 가져야 합니다.

범위 타입은 단일 범위 값으로 많은 요소 값을 나타내고, 겹치는 범위 같은 개념을 명확하게 표현할 수 있어 유용합니다. 일정 관리 목적의 시간·날짜 범위 사용이 가장 명확한 예이지만, 가격 범위, 계측기의 측정 범위 등도 유용할 수 있습니다.

## 기본 제공 범위 타입 (Built-in range types)

PostgreSQL은 다음의 기본 제공 범위 타입을 제공합니다:

- `int4range` — `integer`의 범위
- `int8range` — `bigint`의 범위
- `numrange` — `numeric`의 범위
- `tsrange` — `timestamp without time zone`의 범위
- `tstzrange` — `timestamp with time zone`의 범위
- `daterange` — `date`의 범위

또한 사용자 정의 범위 타입을 정의할 수 있습니다. 자세한 내용은 [PostgreSQL 문서](https://www.postgresql.org/docs/9.3/sql-createtype.html)를 참고하십시오.

## 예제 (Examples)

```sql
CREATE TABLE reservation (room int, during tsrange);
INSERT INTO reservation VALUES
    (1108, '[2010-01-01 14:30, 2010-01-01 15:30)');

-- Containment
SELECT int4range(10, 20) @> 3;

-- Overlaps
SELECT numrange(11.1, 22.2) && numrange(20.0, 30.0);

-- Extract the upper bound
SELECT upper(int8range(15, 25));

-- Compute the intersection
SELECT int4range(10, 20) * int4range(15, 25);

-- Is the range empty?
SELECT isempty(numrange(1, 5));
```

## 포함 경계와 배제 경계 (Inclusive and exclusive bounds)

비어 있지 않은 모든 범위에는 하한(lower bound)과 상한(upper bound) 두 경계가 있습니다. 이 값들 사이의 모든 점이 범위에 포함됩니다. 포함 경계(inclusive bound)는 경계점 자체도 범위에 포함됨을 의미하는 반면, 배제 경계(exclusive bound)는 경계점이 범위에 포함되지 않음을 의미합니다.

범위의 텍스트 형태에서 포함 하한은 "`[`"로, 배제 하한은 "`(`"로 표현됩니다. 마찬가지로 포함 상한은 "`]`"로, 배제 상한은 "`)`"로 표현됩니다.

`lower_inc`와 `upper_inc` 함수는 각각 범위 값의 하한과 상한의 포함 여부를 테스트합니다.

## 무한(무경계) 범위 (Infinite (unbounded) ranges)

범위의 하한을 생략할 수 있으며, 이는 상한보다 작은 모든 점이 범위에 포함됨을 의미합니다. 마찬가지로 범위의 상한을 생략하면 하한보다 큰 모든 점이 범위에 포함됩니다. 하한과 상한을 모두 생략하면 요소 타입의 모든 값이 범위에 있는 것으로 간주됩니다.

하한이나 상한을 생략하는 것은 각각 하한이 "마이너스 무한대", 상한이 "플러스 무한대"라고 간주하는 것과 동등합니다. 그러나 이 무한 값들은 결코 범위의 요소 타입 값이 아니며 범위의 일부가 될 수 없다는 점에 유의하십시오. 따라서 포함 무한 경계라는 것은 존재하지 않습니다. 그런 것을 작성하려고 하면 자동으로 배제 경계로 변환됩니다.

또한 일부 요소 타입에는 "무한대(infinity)"라는 개념이 있지만, 범위 타입 메커니즘의 관점에서 그것은 그냥 또 다른 값일 뿐입니다. 예를 들어 timestamp 범위에서 `[today,]`는 `[today,)`와 같은 것을 의미합니다. 그러나 `[today,infinity]`는 `[today,infinity)`와 다른 것을 의미합니다. 후자는 특수 timestamp 값 infinity를 제외합니다.

`lower_inf`와 `upper_inf` 함수는 각각 범위의 무한 하한과 무한 상한을 테스트합니다.

## 범위 입출력 (Range input/output)

범위 값의 입력은 다음 패턴 중 하나를 따라야 합니다:

```sql
(lower-bound,upper-bound)
(lower-bound,upper-bound]
[lower-bound,upper-bound)
[lower-bound,upper-bound]
empty
```

괄호나 대괄호는 앞서 설명한 대로 하한과 상한이 배제인지 포함인지를 나타냅니다. 마지막 패턴은 empty로, 빈 범위(점을 포함하지 않는 범위)를 나타냅니다.

lower-bound는 서브타입에 유효한 입력인 문자열이거나, 하한이 없음을 나타내기 위해 비어 있을 수 있습니다. 마찬가지로 upper-bound는 서브타입에 유효한 입력인 문자열이거나, 상한이 없음을 나타내기 위해 비어 있을 수 있습니다.

각 경계 값은 큰따옴표(`"`)로 묶을 수 있습니다. 경계 값이 괄호, 대괄호, 쉼표, 큰따옴표, 백슬래시를 포함하는 경우, 이 문자들이 그렇지 않으면 범위 구문의 일부로 간주되므로 이렇게 묶는 것이 필요합니다. 큰따옴표로 묶인 경계 값 안에 큰따옴표나 백슬래시를 넣으려면 앞에 백슬래시를 붙이십시오. 또한 큰따옴표로 묶인 경계 값 안의 큰따옴표 쌍은 SQL 리터럴 문자열에서 작은따옴표에 대한 규칙과 유사하게 하나의 큰따옴표 문자를 나타내는 것으로 간주됩니다. 또는 따옴표 사용을 피하고 백슬래시 이스케이프를 사용해, 그렇지 않으면 범위 구문으로 간주될 모든 데이터 문자를 보호할 수 있습니다. 또한 빈 문자열인 경계 값을 작성하려면 `""`를 쓰십시오. 아무것도 쓰지 않으면 무한 경계를 의미하기 때문입니다.

범위 값 앞뒤에는 공백이 허용되지만, 괄호나 대괄호 사이의 공백은 하한이나 상한 값의 일부로 간주됩니다. 요소 타입에 따라 이것이 중요할 수도 있고 아닐 수도 있습니다.

예:

```sql
-- includes 3, does not include 7, and does include all points in between
SELECT '[3,7)'::int4range;

-- does not include either 3 or 7, but includes all points in between
SELECT '(3,7)'::int4range;

-- includes only the single point 4
SELECT '[4,4]'::int4range;

-- includes no points (and will be normalized to 'empty')
SELECT '[4,4)'::int4range;
```

## 범위 생성 (Constructing ranges)

각 범위 타입에는 범위 타입과 같은 이름의 생성자 함수가 있습니다. 생성자 함수를 사용하는 것은 경계 값의 추가 따옴표 처리를 피할 수 있어 범위 리터럴 상수를 작성하는 것보다 편리한 경우가 많습니다. 생성자 함수는 두 개 또는 세 개의 인수를 받습니다. 두 인수 형태는 표준 형태(하한 포함, 상한 배제)의 범위를 생성하고, 세 인수 형태는 세 번째 인수로 지정된 형태의 경계를 갖는 범위를 생성합니다. 세 번째 인수는 "`()`", "`(]`", "`[)`", "`[]`" 문자열 중 하나여야 합니다. 예:

```sql
-- The full form is: lower bound, upper bound, and text argument indicating
-- inclusivity/exclusivity of bounds.
SELECT numrange(1.0, 14.0, '(]');

-- If the third argument is omitted, '[)' is assumed.
SELECT numrange(1.0, 14.0);

-- Although '(]' is specified here, on display the value will be converted to
-- canonical form, since int8range is a discrete range type (see below).
SELECT int8range(1, 14, '(]');

-- Using NULL for either bound causes the range to be unbounded on that side.
SELECT numrange(NULL, 2.2);
```

## 이산 범위 타입 (Discrete range types)

이산 범위(discrete range)는 요소 타입이 integer나 date처럼 잘 정의된 "스텝(step)"을 갖는 범위입니다. 이런 타입에서는 두 요소 사이에 유효한 값이 없을 때 두 요소가 인접하다(adjacent)고 말할 수 있습니다. 이는 두 주어진 값 사이에서 다른 요소 값을 항상(또는 거의 항상) 식별할 수 있는 연속 범위(continuous range)와 대조됩니다. 예를 들어 `numeric` 타입에 대한 범위는 연속적이며, `timestamp`에 대한 범위도 그렇습니다. timestamp는 정밀도가 제한되어 이론적으로는 이산으로 취급할 수 있지만, 스텝 크기가 보통 관심사가 아니므로 연속으로 간주하는 것이 낫습니다.

이산 범위 타입을 생각하는 또 다른 방법은, 각 요소 값에 대해 "다음(next)" 또는 "이전(previous)" 값이라는 명확한 개념이 있다는 것입니다. 이를 알면 원래 주어진 값 대신 다음이나 이전 요소 값을 선택하여 범위 경계의 포함 표현과 배제 표현 사이를 변환할 수 있습니다. 예를 들어 integer 범위 타입에서 `[4,8]`과 `(3,9)`는 같은 값 집합을 나타냅니다. 그러나 numeric에 대한 범위에서는 그렇지 않습니다.

이산 범위 타입은 요소 타입에 대한 원하는 스텝 크기를 인식하는 *정규화(canonicalization)* 함수를 가져야 합니다. 정규화 함수는 범위 타입의 동등한 값들을, 특히 일관되게 포함 또는 배제인 경계로, 동일한 표현을 갖도록 변환하는 역할을 합니다. 정규화 함수가 지정되지 않으면, 서로 다른 서식의 범위는 실제로 같은 값 집합을 나타낼 수 있음에도 항상 같지 않은 것으로 취급됩니다.

기본 제공 범위 타입 `int4range`, `int8range`, `daterange`는 모두 하한을 포함하고 상한을 배제하는 정규 형태, 즉 `[)`를 사용합니다. 다만 사용자 정의 범위 타입은 다른 관례를 사용할 수 있습니다.

## 새 범위 타입 정의 (Defining new range types)

사용자는 자신만의 범위 타입을 정의할 수 있습니다. 이렇게 하는 가장 흔한 이유는 기본 제공 범위 타입에 없는 서브타입에 대한 범위를 사용하기 위해서입니다. 예를 들어 서브타입 `float8`의 새 범위 타입을 정의하려면:

```sql
CREATE TYPE floatrange AS RANGE (
    subtype = float8,
    subtype_diff = float8mi
);

SELECT '[1.234, 5.678]'::floatrange;
```

`float8`은 의미 있는 "스텝"이 없으므로 이 예에서는 정규화 함수를 정의하지 않습니다.

서브타입이 연속이 아니라 이산 값을 갖는 것으로 간주되면, `CREATE TYPE` 명령은 `canonical` 함수를 지정해야 합니다. 정규화 함수는 입력 범위 값을 받아, 다른 경계와 서식을 가질 수 있는 동등한 범위 값을 반환해야 합니다. 같은 값 집합을 나타내는 두 범위, 예를 들어 integer 범위 `[1, 7]`과 `[1, 8)`에 대한 정규 출력은 동일해야 합니다. 서로 다른 서식을 가진 두 동등한 값이 항상 같은 서식의 같은 값으로 매핑되기만 하면, 어느 표현을 정규 형태로 선택하든 상관없습니다. 포함/배제 경계 서식 조정 외에도, 정규화 함수는 원하는 스텝 크기가 서브타입이 저장할 수 있는 것보다 큰 경우 경계 값을 반올림할 수 있습니다. 예를 들어 timestamp에 대한 범위 타입을 1시간의 스텝 크기를 갖도록 정의할 수 있으며, 이 경우 정규화 함수는 1시간의 배수가 아닌 경계를 반올림하거나 대신 오류를 던져야 합니다.

자신만의 범위 타입을 정의하면, 주어진 범위에 어떤 값이 속하는지 결정하는 정렬 순서를 바꾸기 위해 다른 서브타입 B-트리 연산자 클래스나 콜레이션을 지정할 수도 있습니다.

또한 GiST나 SP-GiST 인덱스와 함께 사용하려는 범위 타입은 서브타입 차이(`subtype_diff`) 함수를 정의해야 합니다. `subtype_diff` 없이도 인덱스는 동작하지만, 차이 함수가 제공되는 경우보다 상당히 덜 효율적일 가능성이 높습니다. 서브타입 차이 함수는 서브타입의 두 입력 값을 받아, 예를 들어 `X` 빼기 `Y`를 `float8` 값으로 나타낸 그 차이를 반환합니다. 위 예에서는 일반 `float8` 빼기 연산자의 기반 함수를 사용할 수 있지만, 다른 서브타입에는 어떤 타입 변환이 필요합니다. 차이를 숫자로 나타내는 방법에 대해 창의적인 고려도 필요할 수 있습니다. 가능한 한, `subtype_diff` 함수는 선택된 연산자 클래스와 콜레이션이 암시하는 정렬 순서와 일치해야 합니다. 즉, 정렬 순서에 따라 첫 번째 인수가 두 번째보다 클 때마다 그 결과는 양수여야 합니다.

범위 타입 생성에 대한 자세한 내용은 [PostgreSQL 문서](https://www.postgresql.org/docs/9.3/sql-createtype.html)를 참고하십시오.

## 인덱싱 (Indexing)

범위 타입의 테이블 컬럼에 대해 GiST와 SP-GiST 인덱스를 만들 수 있습니다. 예를 들어 GiST 인덱스를 만들려면:

```sql
CREATE INDEX reservation_idx ON reservation USING gist (during);
```

GiST나 SP-GiST 인덱스는 다음 범위 연산자를 포함하는 쿼리를 가속할 수 있습니다: `=`, `&&`, `<@`, `@>`, `<<`, `>>`, `-|-`, `&<`, `&>`.

또한 범위 타입의 테이블 컬럼에 대해 B-트리와 해시 인덱스를 만들 수 있습니다. 이 인덱스 타입들에서 유일하게 유용한 범위 연산은 기본적으로 동등성뿐입니다. 대응하는 `<`와 `>` 연산자와 함께 범위 값에 대한 B-트리 정렬 순서가 정의되어 있지만, 그 순서는 다소 임의적이며 실제 세계에서 보통 유용하지 않습니다. 범위 타입의 B-트리와 해시 지원은 주로 실제 인덱스 생성보다는 쿼리 내부에서의 정렬과 해싱을 허용하기 위한 것입니다.

## 범위에 대한 제약 (Constraints on ranges)

`UNIQUE`는 스칼라 값에는 자연스러운 제약이지만, 범위 타입에는 보통 부적합합니다. 대신 배제 제약(exclusion constraint)이 더 적합한 경우가 많습니다. 배제 제약은 범위 타입에 대해 "겹치지 않음(non-overlapping)" 같은 제약을 지정할 수 있게 합니다. 예:

```sql
CREATE TABLE reservation (
    during tsrange,
    EXCLUDE USING gist (during WITH &&)
);
```

그 제약은 겹치는 값이 동시에 테이블에 존재하는 것을 방지합니다:

```sql
INSERT INTO reservation VALUES
    ('[2010-01-01 11:30, 2010-01-01 15:00)');
INSERT 0 1
```

[`btree_gist`](https://www.postgresql.org/docs/9.3/btree-gist.html) 확장을 사용해 일반 스칼라 데이터 타입에 배제 제약을 정의할 수 있으며, 이를 범위 배제와 결합하여 최대의 유연성을 얻을 수 있습니다. 예를 들어 `btree_gist`가 설치된 후 다음 제약은 회의실 번호가 같은 경우에만 겹치는 범위를 거부합니다:

```sql
CREATE EXTENSION btree_gist;
CREATE TABLE room_reservation (
    room text,
    during tsrange,
    EXCLUDE USING gist (room WITH =, during WITH &&)
);

INSERT INTO room_reservation VALUES
    ('123A', '[2010-01-01 14:00, 2010-01-01 15:00)');
INSERT 0 1

INSERT INTO room_reservation VALUES
    ('123A', '[2010-01-01 14:30, 2010-01-01 15:30)');
ERROR:  conflicting key value violates exclusion constraint "room_reservation_room_during_excl"
DETAIL:  Key (room, during)=(123A, ["2010-01-01 14:30:00","2010-01-01 15:30:00")) conflicts
with existing key (room, during)=(123A, ["2010-01-01 14:00:00","2010-01-01 15:00:00")).

INSERT INTO room_reservation VALUES
    ('123B', '[2010-01-01 14:30, 2010-01-01 15:30)');
INSERT 0 1
```
