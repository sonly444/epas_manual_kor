## 개요 (Overview)

SQL은 두 가지 기본 문자 타입 `CHARACTER VARYING(n)`과 `CHARACTER(n)`을 정의합니다. 여기서 `n`은 양의 정수입니다. 이 타입들은 최대 `n`자 길이의 문자열을 저장할 수 있습니다. `n` 값을 지정하지 않으면 `n`은 기본값 `1`입니다. `n`의 길이를 초과하는 값을 할당하면, 초과 문자가 모두 공백인 경우를 제외하고 오류가 발생합니다. 이 경우 문자열은 최대 길이로 절사됩니다. 저장할 문자열이 `n`보다 짧으면, `CHARACTER` 타입 값은 지정된 너비(`n`)까지 공백으로 채워져 그렇게 저장·표시되고, `CHARACTER VARYING` 타입 값은 더 짧은 문자열을 그대로 저장합니다.

값을 `CHARACTER VARYING(n)`이나 `CHARACTER(n)`으로 명시적으로 캐스트하면, 길이를 초과한 값이 오류 없이 n자로 절사됩니다.

표기법 `VARCHAR(n)`과 `CHAR(n)`은 각각 `CHARACTER VARYING(n)`과 `CHARACTER(n)`의 별칭입니다. 지정하는 경우 길이는 0보다 커야 하며 10485760을 초과할 수 없습니다. 길이 지정자 없는 `CHARACTER`는 `CHARACTER(1)`과 동등합니다. `CHARACTER VARYING`을 길이 지정자 없이 사용하면 이 타입은 임의 크기의 문자열을 허용합니다. 후자는 PostgreSQL 확장입니다.

또한 PostgreSQL은 임의 길이의 문자열을 저장하는 `TEXT` 타입을 제공합니다. `TEXT` 타입은 SQL 표준에 없지만 여러 다른 SQL 데이터베이스 관리 시스템도 이를 갖고 있습니다.

`CHARACTER` 타입 값은 지정된 너비 n까지 물리적으로 공백으로 채워져 그렇게 저장·표시됩니다. 그러나 뒤따르는 공백은 의미상 중요하지 않은 것으로 취급되어 두 `CHARACTER` 타입 값을 비교할 때 무시됩니다. 공백이 중요한 콜레이션(collation)에서는 이 동작이 예상치 못한 결과를 낳을 수 있습니다. 예를 들어 `SELECT 'a '::CHAR(2) collate "C" < E'a\n'::CHAR(2)`는 C 로케일이 공백을 개행보다 크다고 간주함에도 true를 반환합니다. `CHARACTER` 값을 다른 문자열 타입으로 변환할 때 뒤따르는 공백은 제거됩니다. `CHARACTER VARYING`과 `TEXT` 값에서는, 그리고 패턴 매칭(`LIKE` 및 정규 표현식)을 사용할 때는 뒤따르는 공백이 의미상 중요하다는 점에 유의하십시오.

이 데이터 타입들 중 어느 것에든 저장할 수 있는 문자는 데이터베이스 생성 시 선택되는 데이터베이스 문자 집합(character set)에 의해 결정됩니다. 특정 문자 집합과 관계없이, 코드가 0인 문자(때때로 `NUL`이라 불림)는 저장할 수 없습니다. 자세한 내용은 [Character Set Support](https://www.postgresql.org/docs/current/multibyte.html)를 참고하십시오.

짧은 문자열(최대 126바이트)의 저장 요구량은 1바이트에 실제 문자열을 더한 것이며, `CHARACTER`의 경우 공백 채움을 포함합니다. 더 긴 문자열은 1바이트 대신 4바이트의 오버헤드를 갖습니다. 긴 문자열은 시스템이 자동으로 압축하므로 디스크상의 물리적 요구량은 더 적을 수 있습니다. 매우 긴 값은 더 짧은 컬럼 값에 대한 빠른 접근을 방해하지 않도록 백그라운드 테이블에도 저장됩니다. 어떤 경우든 저장 가능한 가장 긴 문자열은 약 1 GB입니다. (데이터 타입 선언에서 n에 허용되는 최댓값은 그보다 작습니다. 멀티바이트 문자 인코딩에서는 문자 수와 바이트 수가 상당히 다를 수 있으므로 이를 변경하는 것은 유용하지 않습니다. 특정 상한 없이 긴 문자열을 저장하려면, 임의의 길이 제한을 만드는 대신 길이 지정자 없는 `TEXT`나 `CHARACTER VARYING`을 사용하십시오.)

##### 팁 (Tip)

이 세 타입 사이에는, 공백 채움 타입 사용 시 저장 공간이 늘어나는 것과 길이 제한 컬럼에 저장할 때 길이를 확인하는 몇 사이클의 추가 CPU를 제외하면 성능 차이가 없습니다. 일부 다른 데이터베이스 시스템에서는 `CHARACTER(n)`이 성능상 이점을 갖지만 PostgreSQL에는 그런 이점이 없습니다. 실제로 `CHARACTER(n)`은 추가 저장 비용 때문에 대개 셋 중 가장 느립니다. 대부분의 상황에서는 대신 `TEXT`나 `CHARACTER VARYING`을 사용해야 합니다.

문자열 리터럴의 구문에 대한 정보는 [문자열 상수에 관한 PostgreSQL 문서](https://www.postgresql.org/docs/current/sql-syntax-lexical.html#SQL-SYNTAX-STRINGS)를, 사용 가능한 연산자와 함수에 대한 정보는 [함수와 연산자](https://www.postgresql.org/docs/current/functions.html)를 참고하십시오.

예: 문자 타입 사용

```sql
CREATE TABLE test1 (a character(4));
INSERT INTO test1 VALUES ('ok');
SELECT a, char_length(a) FROM test1; -- (1)

  a   | char_length
------+-------------
 ok   |           2

CREATE TABLE test2 (b varchar(5));
INSERT INTO test2 VALUES ('ok');
INSERT INTO test2 VALUES ('good      ');
INSERT INTO test2 VALUES ('too long');
ERROR:  value too long for type character varying(5)
INSERT INTO test2 VALUES ('too long'::varchar(5)); -- explicit truncation
SELECT b, char_length(b) FROM test2;

   b   | char_length
-------+-------------
 ok    |           2
 good  |           5
 too l |           5
```

PostgreSQL에는 다음 표에 나온 두 가지 다른 고정 길이 문자 타입이 있습니다. 이들은 범용 용도가 아니라 내부 시스템 카탈로그에서만 사용하도록 의도된 것입니다. `NAME` 타입은 식별자를 저장하는 데 사용됩니다. 그 길이는 현재 64바이트(사용 가능한 63자에 종료 문자)로 정의되어 있지만, C 소스 코드에서는 상수 NAMEDATALEN을 사용해 참조해야 합니다. 길이는 컴파일 시점에 설정되며(따라서 특수 용도로 조정 가능), 기본 최대 길이는 향후 릴리스에서 변경될 수 있습니다. `"CHAR"` 타입(따옴표 주의)은 저장에 1바이트만 사용하여 단일 ASCII 문자만 저장할 수 있다는 점에서 `CHAR(1)`과 다릅니다. 이는 시스템 카탈로그에서 단순한 열거형 타입으로 사용됩니다.

## 특수 문자 타입 (Special Character Types)

| 이름 | 저장 크기 | 설명 |
| --- | --- | --- |
| "CHAR" | 1바이트 | 단일 바이트 내부 타입 |
| `NAME` | 64바이트 | 객체 이름을 위한 내부 타입 |

`CLOB` 타입에 큰 문자열을 저장할 수 있습니다. `CLOB`은 길이 제한이 지정되지 않는다는 점을 제외하면 `VARCHAR2`와 의미상 동등합니다. 일반적으로 최대 문자열 길이를 모를 때 `CLOB` 타입을 사용합니다.

`CLOB` 타입에 저장할 수 있는 가장 긴 문자열은 약 1 GB입니다.

##### 참고 (Note)

`CLOB` 데이터 타입은 실제로 PostgreSQL `TEXT` 데이터 타입을 기반으로 하는 `DOMAIN`입니다. `DOMAIN`에 대한 정보는 [PostgreSQL 코어 문서](https://www.postgresql.org/docs/current/static/sql-createdomain.html)를 참고하십시오.

따라서 `CLOB` 타입의 사용은 약 1 GB의 최대 크기 등 `TEXT`에 가능한 범위로 제한됩니다.

더 많은 양의 데이터에는 `CLOB` 데이터 타입 대신, `pg_largeobject` 시스템 카탈로그에 의존하는 PostgreSQL *대용량 객체(large objects)* 기능을 사용하십시오. 대용량 객체에 대한 정보는 [PostgreSQL 코어 문서](https://www.postgresql.org/docs/current/static/largeobjects.html)를 참고하십시오.
