# 이진 데이터 (Binary Data) — EPAS 18 Reference

> 원문: [EPAS v18 — Reference › SQL reference › Data types › Binary data](https://www.enterprisedb.com/docs/epas/latest/reference/sql_reference/02_data_types/03_binary_data/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 타입·코드 이름은 원문 그대로 보존했습니다.

| 이름          | 네이티브 | 별칭 | 설명                                                                                                                                                       |
| ------------- | -------- | ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BYTEA`     | ✅       |      | 가변 길이 이진 문자열, 실제 이진 문자열에 1 또는 4바이트를 더함                                                                                            |
| `BINARY`    |          | ✅   | `BYTEA`의 별칭. 길이 지정자를 지원하지 않는 가변 길이 이진 문자열                                                                                        |
| `BLOB`      |          | ✅   | `BYTEA`의 별칭. 최대 크기 1 GB의 가변 길이 이진 문자열. 이진 문자열이 127바이트 미만이면 실제 이진 문자열에 1바이트를, 127바이트 이상이면 4바이트를 더함 |
| `VARBINARY` |          | ✅   | `BYTEA`의 별칭. 길이 지정자를 지원하지 않는 가변 길이 이진 문자열                                                                                        |

**참고**

EPAS에서 `BINARY`와 `VARBINARY`는 모두 `BYTEA`의 별칭으로 처리됩니다. 별도의 고정 길이 제한을 적용하지 않으며, `BINARY(10)`또는 `VARBINARY(10)`과 같은 길이 지정자는 지원하지 않습니다.

## 개요 (Overview)

이진 문자열은 옥텟(octet, 바이트)의 시퀀스입니다. 이진 문자열은 두 가지 특성으로 문자열과 구별됩니다:

- 이진 문자열은 값이 0인 옥텟 및 기타 "출력 불가능한(non-printable)" 옥텟(32~126 범위 밖의 옥텟으로 정의됨)의 저장을 특별히 허용합니다.
- 이진 문자열에 대한 연산은 실제 바이트를 처리하는 반면, 문자열의 인코딩과 처리는 로케일 설정에 따라 달라집니다.

`BYTEA` 타입은 입력과 출력에 대해 "hex" 형식과 "escape" 형식의 두 가지를 지원합니다. 둘 다 입력 시 항상 허용됩니다. 출력 형식은 구성 파라미터 `bytea_output`에 따라 달라지며, 기본값은 hex입니다.

### Hex 형식 (Hex format)

hex 형식은 이진 데이터를 바이트당 두 개의 16진 숫자로 인코딩하며, 상위 니블(nibble)이 먼저 옵니다. 전체 문자열 앞에는 (escape 형식과 구별하기 위해) 시퀀스 `\x`가 붙습니다. 일부 문맥에서는 시작 백슬래시를 두 배로 하여 이스케이프해야 할 수 있습니다. 입력의 경우 16진 숫자는 대문자나 소문자 모두 가능하며, 숫자 쌍 사이에 공백이 허용됩니다(단, 숫자 쌍 내부나 시작 `\x` 시퀀스 안에서는 안 됨). hex 형식은 광범위한 외부 애플리케이션 및 프로토콜과 호환되고 escape 형식보다 변환이 빠른 경향이 있으므로 사용이 권장됩니다.

예:

```text
SET bytea_output = 'hex';

SELECT '\xDEADBEEF'::bytea;
   bytea
------------
 \xdeadbeef
```

### Escape 형식 (Escape format)

"escape" 형식은 bytea 타입에 대한 전통적인 PostgreSQL 형식입니다. 이는 이진 문자열을 ASCII 문자의 시퀀스로 표현하되, ASCII 문자로 표현할 수 없는 바이트를 특수 이스케이프 시퀀스로 변환하는 방식을 취합니다. 애플리케이션 관점에서 바이트를 문자로 표현하는 것이 의미가 있다면 이 표현이 편리할 수 있습니다. 그러나 실제로는 이진 문자열과 문자열의 구분을 흐리기 때문에 보통 혼란스럽습니다. 또한 이스케이프 메커니즘이 다루기 번거로울 수 있습니다. 따라서 대부분의 새 애플리케이션에서는 이 형식을 피하는 것이 좋습니다.

escape 형식으로 `BYTEA` 값을 입력할 때, 특정 값의 옥텟은 *반드시* 이스케이프해야 하는 반면 모든 옥텟 값은 이스케이프*할 수* 있습니다. 일반적으로 옥텟을 이스케이프하려면 세 자리 8진 값으로 변환한 뒤 앞에 백슬래시를 붙입니다. 백슬래시 자체(옥텟 십진 값 92)는 대안으로 이중 백슬래시로 표현할 수 있습니다. 다음 표는 반드시 이스케이프해야 하는 문자를 보여주고, 해당하는 경우 대안 이스케이프 시퀀스를 제공합니다.

| 십진 옥텟 값     | 설명                 | 이스케이프 입력 표현     | 예                | Hex 표현 |
| ---------------- | -------------------- | ------------------------ | ----------------- | -------- |
| 0                | 0 옥텟               | `'\000'`               | `'\000'::bytea` | \x00     |
| 39               | 작은따옴표           | `''''` 또는 `'\047'` | `''''::bytea`   | \x27     |
| 92               | 백슬래시             | `'\\'` 또는 `'\134'` | `'\\'::bytea`   | \x5c     |
| 0~31 및 127~255 | "출력 불가능한" 옥텟 | `'\xxx'` (8진 값)      | `'\001'::bytea` | \x01     |

출력 불가능한 옥텟을 이스케이프해야 하는 요구 사항은 로케일 설정에 따라 다릅니다. 경우에 따라 이스케이프하지 않고 둘 수 있습니다.

작은따옴표를 두 배로 해야 하는 이유는, SQL 명령의 모든 문자열 리터럴에 대해 그렇기 때문입니다. 일반 문자열 리터럴 파서는 가장 바깥쪽 작은따옴표를 소비하고 작은따옴표 쌍을 하나의 데이터 문자로 줄입니다. `BYTEA` 입력 함수가 보는 것은 작은따옴표 하나뿐이며, 이를 일반 데이터 문자로 취급합니다. 그러나 `BYTEA` 입력 함수는 백슬래시를 특수하게 취급하며, 표에 나온 다른 동작들은 그 함수에 의해 구현됩니다.

일부 문맥에서는, 일반 문자열 리터럴 파서도 백슬래시 쌍을 하나의 데이터 문자로 줄이기 때문에 위에 나온 것보다 백슬래시를 두 배로 해야 합니다.

`BYTEA` 옥텟은 기본적으로 hex 형식으로 출력됩니다. `bytea_output`을 escape로 변경하면, "출력 불가능한" 옥텟이 해당하는 세 자리 8진 값으로 변환되어 앞에 백슬래시 하나가 붙습니다. 대부분의 "출력 가능한" 옥텟은 다음 예처럼 클라이언트 문자 집합에서의 표준 표현으로 출력됩니다:

```text
SET bytea_output = 'escape';

SELECT 'abc \153\154\155 \052\251\124'::bytea;
     bytea
----------------
 abc klm *\251T
```

십진 값 92인 옥텟(백슬래시)은 출력에서 두 배가 됩니다. 다음 표에 세부 사항이 있습니다:

| 십진 옥텟 값     | 설명                 | 이스케이프 입력 표현      | 예                | 출력 결과 |
| ---------------- | -------------------- | ------------------------- | ----------------- | --------- |
| 92               | 백슬래시             | `\\`                    | `'\134'::bytea` | `\\`    |
| 0~31 및 127~255 | "출력 불가능한" 옥텟 | `'\xxx'` (8진 값)       | `'\001'::bytea` | `\001`  |
| 32~126           | "출력 가능한" 옥텟   | 클라이언트 문자 집합 표현 | `'\176'::bytea` | ~         |

사용하는 PostgreSQL 프런트엔드에 따라, `BYTEA` 문자열의 이스케이프 및 언이스케이프와 관련해 추가 작업이 필요할 수 있습니다. 예를 들어 인터페이스가 개행과 캐리지 리턴을 자동으로 변환하는 경우 이들도 이스케이프해야 할 수 있습니다.
