# CREATE INDEX — EPAS 18 Reference

## 이름 (Name)

`CREATE INDEX` — 새로운 인덱스를 정의합니다.

## 구문 개요 (Synopsis)

```sql
CREATE [ UNIQUE ] INDEX <name> ON <table>
  ( { <column> | ( <expression> ) | <constant> } )
  [ TABLESPACE <tablespace> ]
  ( { NOPARALLEL | PARALLEL [ <integer> ] } )
```

EDB Postgres Advanced Server는 PostgreSQL 기반의 확장 구문도 지원합니다. 잠금 없이 온라인으로 인덱스를 생성하려면 `CONCURRENTLY` 옵션을 사용합니다. `CONCURRENTLY`는 인덱스 이름 앞에 위치합니다.

```sql
CREATE [ UNIQUE ] INDEX [ CONCURRENTLY ] <name> ON <table> ( ... );
```

## 설명 (Description)

`CREATE INDEX`는 지정된 테이블에 `name`이라는 인덱스를 구성합니다. 인덱스는 주로 데이터베이스 성능을 향상시키는 데 사용됩니다. 그러나 부적절하게 사용하면 성능이 저하됩니다.

인덱스의 키 필드는 열 이름, 상수, 또는 괄호 안에 작성된 표현식으로 지정됩니다. 여러 필드를 지정하여 다중 열 인덱스(multicolumn index)를 생성할 수 있습니다.

인덱스 필드는 테이블 행의 하나 이상의 열 값에서 계산된 표현식일 수 있습니다. 이 기능을 사용하면 기본 데이터의 일부 변환을 기반으로 데이터에 빠르게 접근할 수 있습니다. 예를 들어, `UPPER(col)`에 대해 계산된 인덱스는 `WHERE UPPER(col) = 'JIM'` 절이 인덱스를 사용할 수 있게 합니다.

EDB Postgres Advanced Server는 B-tree 인덱스 방식을 제공합니다. B-tree 인덱스 방식은 Lehman-Yao 고동시성(high-concurrency) B-tree의 구현입니다.

기본적으로 인덱스는 `IS NULL` 절에 사용되지 않습니다.

인덱스 정의에 사용되는 모든 함수와 연산자는 immutable이어야 합니다. 즉, 그 결과는 인수에만 의존해야 하며, 다른 테이블의 내용이나 현재 시간과 같은 외부 영향에 절대 의존해서는 안 됩니다. 이 제한은 인덱스의 동작이 잘 정의되도록 보장합니다. 인덱스 표현식에서 사용자 정의 함수를 사용하려면 함수를 생성할 때 immutable로 표시합니다.

##### 참고 (Note) — 표현식 인덱스의 함수 immutability와 재구성

인덱스 표현식에 사용하는 함수는 위와 같이 immutable이어야 하며, `VOLATILE` 또는 `STABLE`로 표시된 함수는 원칙적으로 인덱스 표현식에 사용할 수 없습니다.

다만 인라인 가능한(inlinable) SQL 언어 함수는, 인덱스를 생성할 때 함수 호출이 그 본문(body) 표현식으로 인라인되어 확장된 뒤 변경 가능성(mutability)이 평가됩니다. 따라서 함수가 `VOLATILE`로 선언되어 있더라도 인라인된 본문이 불변(immutable) 표현식이면 표현식 인덱스가 생성될 수 있습니다.

이 경우 데이터 정합성에 유의해야 합니다. 표현식 인덱스는 인덱스를 빌드하는 시점에 계산된 표현식 결과를 인덱스에 저장하며, 인덱스 검색 시에는 저장된 값을 사용하고 표현식을 다시 계산하지 않습니다. 그러므로 인덱스를 생성한 뒤 함수 정의를 변경(예: `CREATE OR REPLACE FUNCTION`)하면, 인덱스에는 이전 정의로 계산된 값이 남아 있는 반면 순차 검색(sequential scan)은 새 정의로 값을 다시 계산하므로, 동일한 쿼리에 대해 인덱스 검색 결과와 순차 검색 결과가 서로 달라질 수 있습니다.

이러한 불일치를 방지하려면, 표현식 인덱스에 사용하는 함수는 `IMMUTABLE`로 선언하고 그 정의를 변경하지 않는 것을 원칙으로 하십시오. 부득이하게 함수 정의를 변경한 경우에는 해당 함수에 의존하는 표현식 인덱스를 `REINDEX`로 재구성하거나 삭제 후 재생성하여 데이터 정합성을 확보해야 합니다.

파티션된 테이블에 인덱스를 생성하면, `CREATE INDEX` 명령은 인덱스를 테이블의 서브파티션(subpartition)으로 전파합니다.

`PARALLEL` 절은 인덱스를 생성하는 동안 사용되는 병렬 처리 정도(degree of parallelism)를 지정합니다. `NOPARALLEL` 절은 병렬 처리를 기본값으로 재설정합니다. `reloptions`는 `parallel_workers` 파라미터를 `0`으로 표시합니다.

##### 참고 (Note)

생성 시 정의에 `PARALLEL` 절이 포함되었던 테이블에 `CREATE INDEX... PARALLEL` 명령을 사용하여 인덱스를 생성하면, 서버는 병렬 인덱스를 빌드할 때 `CREATE INDEX` 명령과 함께 제공된 `PARALLEL` 절을 사용합니다.

## 파라미터 (Parameters)

`UNIQUE`

인덱스가 생성될 때(데이터가 이미 존재하는 경우) 및 데이터가 추가될 때마다 시스템이 테이블에서 중복 값을 확인하도록 합니다. 중복 항목을 초래하는 데이터를 삽입하거나 업데이트하려는 시도는 오류를 발생시킵니다.

`CONCURRENTLY`

이 옵션을 사용하면 EDB Postgres Advanced Server는 테이블에 대한 동시 삽입·수정·삭제를 막는 잠금을 걸지 않고 인덱스를 빌드합니다. 반면 표준 인덱스 빌드는 인덱스가 완료될 때까지 테이블에 대한 쓰기(읽기는 제외)를 잠급니다. 이 옵션을 사용할 때 유의해야 할 몇 가지 주의 사항은 아래의 [온라인 인덱스 생성(CONCURRENTLY)](#온라인-인덱스-생성-concurrently) 절을 참고하십시오.

임시 테이블의 경우 다른 세션이 접근할 수 없고 비동시(non-concurrent) 인덱스 생성이 더 저렴하므로, `CREATE INDEX`는 항상 비동시로 수행됩니다.

`name`

생성할 인덱스의 이름입니다. 여기서는 스키마 이름을 생성할 수 없습니다. 인덱스는 항상 상위 테이블과 동일한 스키마에 생성됩니다.

`table`

인덱싱할 테이블의 이름(스키마로 한정될 수 있음)입니다.

`column`

테이블 내 열의 이름입니다.

`expression`

테이블의 하나 이상의 열을 기반으로 하는 표현식입니다. 일반적으로 구문에 나타난 것처럼 표현식을 괄호로 둘러싸서 작성해야 합니다. 그러나 표현식이 함수 호출 형태인 경우 괄호를 생략할 수 있습니다.

`constant`

인덱스 키로 사용할 수 있는 상수 값입니다.

일반적으로 모든 인덱싱된 열이 `NULL`인 행은 인덱스에 포함되지 않습니다. 이는 옵티마이저가 특정 쿼리에 대해 해당 인덱스를 사용할 수 없음을 의미합니다. 이 제한을 극복하기 위해 인덱스에 상수를 추가할 수 있으며, 이는 인덱스가 모든 인덱스 열이 `NULL`인 행을 절대 포함하지 않도록 강제합니다.

`tablespace`

인덱스를 생성할 테이블스페이스입니다. 지정하지 않으면 `default_tablespace`가 사용되며, `default_tablespace`가 빈 문자열이면 데이터베이스의 기본 테이블스페이스가 사용됩니다.

`PARALLEL`

병렬 처리 정도를 선택하려면 `PARALLEL`을 지정합니다. 병렬화된 인덱스를 생성하려면 `parallel_workers` 파라미터를 병렬 처리 정도와 동일하게 설정합니다. 또는 `PARALLEL`을 지정하되 병렬 처리 정도를 나열하지 않으면 인덱스는 기본 병렬 처리를 수락합니다.

`NOPARALLEL`

기본 실행을 위해 `NOPARALLEL`을 지정합니다.

`integer`

`integer`는 병렬 처리 정도를 나타내며, 인덱스에 대한 병렬 스캔을 수행하기 위해 병렬 연산에 사용되는 `parallel_workers`의 수입니다.

## 온라인 인덱스 생성 (CONCURRENTLY)

인덱스를 생성하면 데이터베이스의 정상적인 운영에 영향을 줄 수 있습니다. 일반적으로 EDB Postgres Advanced Server는 인덱싱할 테이블을 쓰기에 대해 잠그고, 테이블을 한 번 스캔하여 전체 인덱스 빌드를 수행합니다. 다른 트랜잭션은 여전히 테이블을 읽을 수 있지만, 테이블의 행을 삽입·수정·삭제하려고 하면 인덱스 빌드가 끝날 때까지 차단됩니다. 이는 운영 중인 프로덕션 데이터베이스에서는 심각한 영향을 줄 수 있습니다. 매우 큰 테이블은 인덱싱에 여러 시간이 걸릴 수 있고, 작은 테이블이라도 인덱스 빌드가 프로덕션 시스템에서 허용하기 어려운 시간 동안 쓰기 작업을 차단할 수 있습니다.

EDB Postgres Advanced Server는 쓰기를 잠그지 않고 인덱스를 빌드하는 방식을 지원합니다. 이 방식은 `CREATE INDEX`의 `CONCURRENTLY` 옵션을 지정하여 사용합니다. 이 옵션을 사용하면 서버는 테이블을 두 번 스캔해야 하며, 인덱스를 잠재적으로 수정하거나 사용할 수 있는 기존의 모든 트랜잭션이 종료될 때까지 기다려야 합니다. 따라서 이 방식은 표준 인덱스 빌드보다 총 작업량이 많고 완료까지 훨씬 오래 걸립니다. 그러나 인덱스를 빌드하는 동안 정상적인 작업을 계속할 수 있으므로, 프로덕션 환경에서 새 인덱스를 추가할 때 유용합니다. 물론 인덱스 생성으로 인해 발생하는 추가적인 CPU 및 I/O 부하는 다른 작업을 느리게 할 수 있습니다.

동시(concurrent) 인덱스 빌드에서는 먼저 한 트랜잭션에서 인덱스가 시스템 카탈로그에 "무효(invalid)" 인덱스로 등록되고, 이어서 두 번의 테이블 스캔이 각각 다른 트랜잭션에서 수행됩니다. 각 스캔 전에 인덱스 빌드는 테이블을 수정한 기존 트랜잭션이 종료될 때까지 기다려야 합니다. 두 번째 스캔 후에는 두 번째 스캔 시점보다 앞선 스냅샷을 가진 트랜잭션이 종료될 때까지 기다린 다음, 인덱스를 "유효(valid)"로 표시하여 사용할 수 있게 하고 `CREATE INDEX` 명령이 종료됩니다.

테이블을 스캔하는 동안 교착 상태(deadlock)나 고유 인덱스의 고유성 위반과 같은 문제가 발생하면 `CREATE INDEX` 명령은 실패하지만 "무효" 인덱스를 남깁니다. 이 인덱스는 불완전할 수 있으므로 쿼리에서는 무시되지만, 갱신 오버헤드는 계속 발생시킵니다. psql의 `\d` 명령은 이러한 인덱스를 `INVALID`로 보고합니다. 이 경우 권장하는 복구 방법은 해당 인덱스를 삭제한 뒤 `CREATE INDEX CONCURRENTLY`를 다시 수행하는 것입니다. (또 다른 방법은 `REINDEX INDEX CONCURRENTLY`로 인덱스를 재구성하는 것입니다.)

표현식 인덱스와 부분 인덱스의 동시 빌드도 지원됩니다.

정규(regular) 인덱스 빌드는 동일한 테이블에서 다른 정규 인덱스 빌드가 동시에 수행되는 것을 허용하지만, 한 테이블에서는 한 번에 하나의 동시 인덱스 빌드만 수행될 수 있습니다. 어느 경우든 인덱스를 빌드하는 동안 테이블의 스키마 수정은 허용되지 않습니다. 또 다른 차이점으로, 정규 `CREATE INDEX` 명령은 트랜잭션 블록 안에서 수행될 수 있지만 `CREATE INDEX CONCURRENTLY`는 그럴 수 없습니다.

파티션된 테이블의 인덱스에 대한 동시 빌드는 현재 지원되지 않습니다. 다만 각 파티션의 인덱스를 개별적으로 동시에 빌드한 뒤, 마지막에 파티션된 인덱스를 비동시로 생성하면 파티션된 테이블에 대한 쓰기가 잠기는 시간을 줄일 수 있습니다. 이 경우 파티션된 인덱스를 빌드하는 작업은 메타데이터 전용(metadata only) 작업입니다.

## 참고 사항 (Notes)

다중 열 인덱스에서 최대 32개의 필드를 지정할 수 있습니다.

## 예제 (Examples)

테이블 `emp`의 열 `ename`에 B-tree 인덱스를 생성하려면:

```sql
CREATE INDEX name_idx ON emp (ename);
```

동일한 인덱스를 생성하되 `index_tblspc` 테이블스페이스에 상주하도록 하려면:

```sql
CREATE INDEX name_idx ON emp (ename) TABLESPACE index_tblspc;
```

인덱스 정의에 상수 값(`1`)을 포함하여 모든 인덱싱된 열이 `NULL`인 행을 절대 포함하지 않는 인덱스를 생성할 수 있습니다:

```sql
CREATE INDEX emp_dob_idx on emp (emp_dob, 1);
```

병렬 처리 정도를 7로 설정하여 테이블 `emp`에 `name_idx` 인덱스를 생성하려면:

```sql
CREATE UNIQUE INDEX name_idx ON emp (ename) PARALLEL 7;
```

테이블에 대한 쓰기를 잠그지 않고(온라인으로) 인덱스를 생성하려면 `CONCURRENTLY`를 사용합니다:

```sql
CREATE INDEX CONCURRENTLY name_idx ON emp (ename);
```
