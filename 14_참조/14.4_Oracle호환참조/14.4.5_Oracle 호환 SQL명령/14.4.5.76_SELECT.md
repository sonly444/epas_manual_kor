> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·코드 이름은 원문 그대로 보존했습니다.

# SELECTv18

## 이름 (Name)

`SELECT` — 테이블 또는 뷰에서 행을 검색합니다.

## 구문 개요 (Synopsis)

```sql
SELECT [ optimizer_hint ] [ ALL | DISTINCT | UNIQUE ]
  * | expression [ AS output_name ] [, ...]
  FROM from_item [, ...]
  [ WHERE condition ]
  [ [ START WITH start_expression ]\
      CONNECT BY { PRIOR parent_expr = child_expr |\
        child_expr = PRIOR parent_expr }\
    [ ORDER SIBLINGS BY expression [ ASC | DESC ] [, ...] ] ]
  [ GROUP BY { expression | ROLLUP ( expr_list ) |\
      CUBE ( expr_list ) | GROUPING SETS ( expr_list ) } [, ...]\
      [ LEVEL ] ]
  [ HAVING condition [, ...] ]
  [ { UNION [ ALL ] | INTERSECT | MINUS } select ]
  [ ORDER BY expression [ ASC | DESC ] [, ...] ]
  [ FOR UPDATE [WAIT n|NOWAIT|SKIP LOCKED]]
```

여기서 `from_item`은 다음 중 하나일 수 있습니다:

```sql
table_name[@dblink ] [ alias ]
( select ) alias
from_item [ NATURAL ] join_type from_item
  [ ON join_condition | USING ( join_column [, ...] ) ]
```

## 설명 (Description)

`SELECT`은 하나 이상의 테이블에서 행을 검색합니다. `SELECT`의 일반적인 처리 과정은 다음과 같습니다:

1. `FROM` 목록의 모든 요소가 계산됩니다. (`FROM` 목록의 각 요소는 실제 테이블 또는 가상 테이블입니다.) `FROM` 목록에 둘 이상의 요소를 지정하면 이들은 교차 조인(cross join)됩니다. [`FROM` 절](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/71_select/#from-clause)을 참조하세요.
2. `WHERE` 절을 지정하면, 조건을 충족하지 않는 모든 행이 출력에서 제거됩니다. [`WHERE` 절](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/71_select/#where-clause)을 참조하세요.
3. `GROUP BY` 절을 지정하면, 출력이 하나 이상의 값과 일치하는 행 그룹으로 나뉩니다. `HAVING` 절은 주어진 조건을 충족하지 않는 그룹을 제거합니다. [`GROUP BY` 절](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/71_select/#group-by-clause) 및 [`HAVING` 절](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/71_select/#having-clause)을 참조하세요.
4. `UNION`, `INTERSECT`, `MINUS` 연산자를 사용하여 둘 이상의 `SELECT` 문의 출력을 결합해 단일 결과 집합을 형성할 수 있습니다. `UNION` 연산자는 두 결과 집합 중 하나 또는 둘 다에 있는 모든 행을 반환합니다. `INTERSECT` 연산자는 두 결과 집합 모두에 엄격하게 존재하는 모든 행을 반환합니다. `MINUS` 연산자는 첫 번째 결과 집합에는 있지만 두 번째 결과 집합에는 없는 행을 반환합니다. 세 가지 경우 모두 중복 행은 제거됩니다. `UNION` 연산자의 경우 `ALL`을 지정하면 중복이 제거되지 않습니다. [`UNION` 절](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/71_select/#union-clause), [`INTERSECT` 절](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/71_select/#intersect-clause), [`MINUS` 절](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/71_select/#minus-clause)을 참조하세요.
5. 실제 출력 행은 선택된 각 행에 대해 `SELECT` 출력 표현식을 사용하여 계산됩니다. [`SELECT` 목록](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/71_select/#select-list)을 참조하세요.
6. `CONNECT BY` 절은 계층적 관계를 가진 데이터를 선택하는 데 사용됩니다. 이러한 데이터는 행 간에 부모-자식 관계를 가집니다. [`CONNECT BY` 절](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/71_select/#connect-by-clause)을 참조하세요.
7. `ORDER BY` 절을 지정하면, 반환된 행이 지정된 순서로 정렬됩니다. 그렇지 않으면 시스템이 가장 빠르게 생성할 수 있는 순서로 행이 반환됩니다. [`ORDER BY` 절](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/71_select/#order-by-clause)을 참조하세요.
8. `DISTINCT | UNIQUE`는 결과에서 중복 행을 제거합니다. `ALL`(기본값)은 중복을 포함한 모든 후보 행을 반환합니다. [`DISTINCT | UNIQUE` 절](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/71_select/#distinct--unique-clause)을 참조하세요.
9. `FOR UPDATE` 절은 `SELECT` 문이 선택된 행을 동시 갱신으로부터 잠그도록 합니다. [`FOR UPDATE` 절](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/71_select/#for-update-clause)을 참조하세요.

테이블의 값을 읽으려면 해당 테이블에 대한 `SELECT` 권한이 있어야 합니다. `FOR UPDATE`를 사용하려면 `UPDATE` 권한도 필요합니다.

## 파라미터 (Parameters)

`optimizer_hint`

실행 계획을 선택하기 위한, 옵티마이저에 대한 주석 내장(comment-embedded) 힌트입니다. 옵티마이저 힌트에 대한 정보는 [Optimizer hints](https://www.enterprisedb.com/docs/epas/latest/application_programming/optimizing_code/05_optimizer_hints/)를 참조하세요.

## FROM 절 (FROM clause)

`FROM` 절은 `SELECT` 문을 위한 하나 이상의 소스 테이블을 지정합니다. 구문은 다음과 같습니다:

```sql
FROM source [, ...]
```

여기서 `source`는 다음 요소 중 하나일 수 있습니다:

`table_name[@dblink ]`

기존 테이블 또는 뷰의 이름(선택적으로 스키마로 한정 가능)입니다. `dblink`는 원격 데이터베이스를 식별하는 데이터베이스 링크 이름입니다. 데이터베이스 링크에 대한 정보는 [`CREATE DATABASE LINK`](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/21_create_public_database_link/#create_public_database_link) 명령을 참조하세요.

`alias`

별칭을 포함하는 `FROM` 항목의 대체 이름입니다. 간결함을 위해 또는 동일한 테이블을 여러 번 스캔하는 셀프 조인(self-join)에서 모호성을 제거하기 위해 별칭을 사용하세요. 별칭을 제공하면 테이블 또는 함수의 이름이 완전히 숨겨집니다. 예를 들어, `FROM foo AS f`가 주어지면 나머지 `SELECT`는 이 `FROM` 항목을 `foo`가 아니라 `f`로 참조해야 합니다.

`select`

`FROM` 절에 하위 `SELECT`(sub-`SELECT`)가 나타날 수 있습니다. 이는 마치 그 출력이 이 단일 `SELECT` 명령이 실행되는 동안 임시 테이블로 생성된 것처럼 작동합니다. 하위 `SELECT`를 괄호로 묶고 별칭을 제공하세요.

`join_type`

다음 중 하나입니다:

`[ INNER ] JOIN`

`LEFT [ OUTER ] JOIN`

`RIGHT [ OUTER ] JOIN`

`FULL [ OUTER ] JOIN`

`CROSS JOIN`

`INNER` 및 `OUTER` 조인 유형의 경우, 조인 조건을 지정해야 하는데, 즉 `NATURAL`, `ON join_condition`, `USING (join_column [, ...] )` 중 하나입니다. `CROSS JOIN`의 경우 이러한 절을 사용할 수 없습니다.

`JOIN` 절은 두 개의 `FROM` 항목을 결합합니다. 중첩 순서를 결정하려면 괄호를 사용하세요. 괄호가 없으면 `JOIN`은 왼쪽에서 오른쪽으로 중첩됩니다. 어느 경우든 `JOIN`은 `FROM` 항목을 구분하는 쉼표보다 더 강하게 결합됩니다.

`CROSS JOIN`과 `INNER JOIN`은 단순한 데카르트 곱(Cartesian product)을 생성하는데, 이는 두 항목을 `FROM`의 최상위 수준에 나열했을 때 얻는 것과 동일한 결과이지만 임의의 조인 조건으로 제한됩니다. `CROSS JOIN`은 `INNER JOIN ON (TRUE)`와 동등합니다. 즉, 한정(qualification)에 의해 제거되는 행이 없습니다. 이러한 조인 유형은 `FROM`과 `WHERE`를 사용하여 동일한 작업을 수행할 수 있으므로 표기상의 편의입니다.

`LEFT OUTER JOIN`은 한정된 데카르트 곱의 모든 행, 즉 조인 조건을 통과하는 모든 결합된 행을 반환합니다. 또한 조인 조건을 통과한 오른쪽 행이 없는 왼쪽 테이블의 각 행에 대해 한 개의 복사본을 반환합니다. 이 왼쪽 행은 오른쪽 열에 널(null) 값을 삽입하여 조인된 테이블의 전체 너비로 확장됩니다. 어떤 행이 일치하는지 결정할 때는 `JOIN` 절 자체의 조건만 고려됩니다. 외부 조건은 나중에 적용됩니다.

반대로 `RIGHT OUTER JOIN`은 모든 조인된 행에 더해, 일치하지 않는 각 오른쪽 행에 대해 왼쪽이 널로 확장된 한 개의 행을 반환합니다. 이는 왼쪽 입력과 오른쪽 입력을 교체하여 `LEFT OUTER JOIN`으로 변환할 수 있으므로 표기상의 편의입니다.

`FULL OUTER JOIN`은 모든 조인된 행, 일치하지 않는 각 왼쪽 행에 대해 오른쪽이 널로 확장된 한 개의 행, 그리고 일치하지 않는 각 오른쪽 행에 대해 왼쪽이 널로 확장된 한 개의 행을 반환합니다.

`ON join_condition`

`join_condition`은 조인에서 일치하는 것으로 간주되는 행을 지정하는, `BOOLEAN` 타입의 값을 반환하는 표현식(`WHERE` 절과 유사)입니다.

`USING (join_column [, ...] )`

`USING (a, b, ... )` 형식의 절은 `ON left_table.a = right_table.a AND left_table.b = right_table.b ....`의 약칭입니다. 또한 `USING`은 각 동등한 열 쌍 중 하나만 조인 출력에 포함되고 둘 다 포함되지는 않음을 의미합니다.

`NATURAL`

`NATURAL`은 두 테이블에서 동일한 이름을 가진 모든 열을 언급하는 `USING` 목록의 약칭입니다.

여러 소스를 지정하면 결과는 모든 소스의 데카르트 곱(교차 조인)이 됩니다. 일반적으로 반환되는 행을 데카르트 곱의 작은 부분 집합으로 제한하기 위해 한정 조건이 추가됩니다.

### 예제 (Example)

이 예제는 `dept` 테이블의 모든 항목을 선택합니다:

```sql
SELECT * FROM dept;
```

출력

```text
deptno |  dname      |  loc
-------+-------------+-----------
    10 |  ACCOUNTING |  NEW YORK
    20 |  RESEARCH   |  DALLAS
    30 |  SALES      |  CHICAGO
    40 | OPERATIONS  |  BOSTON
 (4 rows)
```

## WHERE 절 (WHERE clause)

선택적 `WHERE` 절은 다음 형식을 가집니다:

```sql
WHERE condition
```

여기서 `condition`은 `BOOLEAN` 타입의 결과로 평가되는 임의의 표현식입니다. 이 조건을 충족하지 않는 모든 행은 출력에서 제거됩니다. 실제 행 값이 임의의 변수 참조를 대체했을 때 `TRUE`를 반환하면 해당 행은 조건을 충족합니다.

### 예제 (Example)

```sql
SELECT d.deptno, d.dname, e.empno, e.ename, e.mgr, e.hiredate
    FROM emp e, dept d
    WHERE d.deptno = e.deptno;
```

## GROUP BY 절 (GROUP BY clause)

선택적 `GROUP BY` 절은 다음 형식을 가집니다:

```sql
GROUP BY { expression | ROLLUP ( expr_list ) |
  CUBE ( expr_list ) | GROUPING SETS ( expr_list ) } [, ...]
```

`GROUP BY`는 그룹화된 표현식에 대해 동일한 값을 공유하는 모든 선택된 행을 단일 행으로 압축합니다. `expression`은 입력 열 이름이거나 출력 열(`SELECT` 목록 항목)의 이름 또는 서수(ordinal number)일 수 있습니다. 또는 입력 열 값으로 구성된 임의의 표현식일 수도 있습니다. 모호한 경우, `GROUP BY` 이름은 출력 열 이름이 아니라 입력 열 이름으로 해석됩니다.

`ROLLUP`, `CUBE`, `GROUPING SETS`는 다차원 분석을 지원하기 위한 `GROUP BY` 절의 확장입니다.

집계 함수(aggregate function)가 사용되는 경우, 각 그룹을 구성하는 모든 행에 걸쳐 계산되어 각 그룹에 대해 별도의 값을 생성합니다. `GROUP BY` 없이는 집계가 선택된 모든 행에 걸쳐 계산된 단일 값을 생성합니다. `GROUP BY`가 있을 때, `SELECT` 목록 표현식이 집계 함수 내부를 제외하고 그룹화되지 않은 열을 참조하는 것은 유효하지 않습니다. 그룹화되지 않은 열에 대해서는 반환할 수 있는 값이 두 개 이상이기 때문입니다.

### 예제 (Example)

이 예제는 `emp` 테이블의 `sal` 열의 합계를 계산하고, 결과를 부서 번호별로 그룹화합니다:

```sql
SELECT deptno, SUM(sal) AS total
    FROM emp
    GROUP BY deptno;
```

출력

```text
 deptno |  total
--------+----------
     10 |  8750.00
     20 | 10875.00
     30 |  9400.00
(3 rows)
```

## HAVING 절 (HAVING clause)

선택적 `HAVING` 절은 다음 형식을 가집니다:

```sql
HAVING condition
```

여기서 `condition`은 `WHERE` 절에 지정된 것과 동일합니다.

`HAVING`은 지정된 조건을 충족하지 않는 그룹 행을 제거합니다. `HAVING`은 `WHERE`와 다릅니다. `WHERE`는 `GROUP BY`를 적용하기 전에 개별 행을 필터링하는 반면, `HAVING`은 `GROUP BY`가 생성한 그룹 행을 필터링합니다. `condition`에서 참조되는 각 열은, 참조가 집계 함수 내부에 나타나지 않는 한, 그룹화 열을 모호하지 않게 참조해야 합니다.

### 예제 (Example)

모든 직원의 `sal` 열을 합산하고, 결과를 부서 번호별로 그룹화한 다음, 10000 미만인 그룹 합계를 표시합니다:

```sql
SELECT deptno, SUM(sal) AS total
    FROM emp
    GROUP BY deptno
    HAVING SUM(sal) < 10000;
```

출력

```text
 deptno |  total
--------+---------
     10 | 8750.00
     30 | 9400.00
(2 rows)
```

## SELECT 목록 (SELECT List)

`SELECT` 목록(`SELECT` 키워드와 `FROM` 키워드 사이)은 `SELECT` 문의 출력 행을 형성하는 표현식을 지정합니다. 표현식은 `FROM` 절에서 계산된 열을 참조할 수 있으며, 일반적으로 그렇게 합니다. `AS output_name` 절을 사용하여 출력 열에 다른 이름을 지정할 수 있습니다. 이 이름은 주로 표시를 위해 열에 레이블을 붙이는 데 사용됩니다. `ORDER BY` 및 `GROUP BY` 절에서 열의 값을 참조하는 데 사용할 수도 있지만, `WHERE`나 `HAVING` 절에서는 사용할 수 없습니다. 그러한 절에서는 표현식을 그대로 써야 합니다.

표현식 대신 출력 목록에 \*를 써서 선택된 행의 모든 열에 대한 약칭으로 사용할 수 있습니다.

## UNION 절 (UNION clause)

`UNION` 절은 다음 형식을 가집니다:

```sql
select_statement UNION [ ALL ] select_statement
```

여기서 `select_statement`은 `ORDER BY` 또는 `FOR UPDATE` 절이 없는 임의의 `SELECT` 문입니다. 하위 표현식을 괄호로 묶으면 `ORDER BY`를 그 하위 표현식에 붙일 수 있습니다. 괄호가 없으면 이러한 절은 `UNION`의 오른쪽 입력 표현식이 아니라 `UNION`의 결과에 적용됩니다.

`UNION` 연산자는 관련된 `SELECT` 문이 반환하는 행의 집합 합집합(set union)을 계산합니다. 어떤 행이 두 결과 집합 중 적어도 하나에 나타나면 그 행은 두 결과 집합의 집합 합집합에 포함됩니다. `UNION`의 직접 피연산자를 나타내는 두 `SELECT` 문은 동일한 개수의 열을 생성해야 하며, 대응하는 열은 호환 가능한 데이터 타입을 가져야 합니다.

`UNION`의 결과는 `ALL` 옵션을 지정하지 않는 한 중복 행을 포함하지 않습니다. `ALL`은 중복 제거를 방지합니다.

괄호가 없으면, 동일한 `SELECT` 문 내의 여러 `UNION` 연산자는 왼쪽에서 오른쪽으로 평가됩니다.

현재는 `UNION` 결과에 대해서도, `UNION`의 임의의 입력에 대해서도 `FOR UPDATE`를 지정할 수 없습니다.

## INTERSECT 절 (INTERSECT clause)

`INTERSECT` 절은 다음 형식을 가집니다:

```sql
select_statement INTERSECT select_statement
```

여기서 `select_statement`은 `ORDER BY` 또는 `FOR UPDATE` 절이 없는 임의의 `SELECT` 문입니다.

`INTERSECT` 연산자는 관련된 `SELECT` 문이 반환하는 행의 집합 교집합(set intersection)을 계산합니다. 어떤 행이 두 결과 집합 모두에 나타나면 그 행은 두 결과 집합의 교집합에 포함됩니다.

`INTERSECT`의 결과는 중복 행을 포함하지 않습니다.

괄호가 없으면, 동일한 `SELECT` 문 내의 여러 `INTERSECT` 연산자는 왼쪽에서 오른쪽으로 평가됩니다. `INTERSECT`는 `UNION`보다 더 강하게 결합됩니다. 즉, `A UNION B INTERSECT C`는 `A UNION (B INTERSECT C)`로 읽힙니다.

## MINUS 절 (MINUS clause)

`MINUS` 절은 다음과 같은 일반적인 형식을 가집니다:

```sql
select_statement MINUS select_statement
```

여기서 `select_statement`은 `ORDER BY` 또는 `FOR UPDATE` 절이 없는 임의의 `SELECT` 문입니다.

`MINUS` 연산자는 왼쪽 `SELECT` 문의 결과에는 있지만 오른쪽 `SELECT` 문의 결과에는 없는 행의 집합을 계산합니다.

`MINUS`의 결과는 중복 행을 포함하지 않습니다.

괄호가 없으면, 동일한 `SELECT` 문 내의 여러 `MINUS` 연산자는 왼쪽에서 오른쪽으로 평가됩니다. `MINUS`는 `UNION`과 동일한 수준에서 결합됩니다.

## CONNECT BY 절 (CONNECT BY clause)

`CONNECT BY` 절은 계층적 쿼리를 수행할 때 행의 부모-자식 관계를 결정합니다. 다음과 같은 일반적인 형식을 가집니다:

```sql
CONNECT BY { PRIOR parent_expr = child_expr |
  child_expr = PRIOR parent_expr }
```

여기서 `parent_expr`은 후보 부모 행에서 평가됩니다. `FROM` 절이 반환한 어떤 행에 대해 `parent_expr = child_expr`이 `TRUE`로 평가되면, 그 행은 부모의 자식으로 간주됩니다.

`CONNECT BY` 절과 함께 다음의 선택적 절을 지정할 수 있습니다.

`START WITH start_expression`

`FROM` 절이 반환한 행 중 `start_expression`이 `TRUE`로 평가되는 행이 계층 구조의 루트 노드가 됩니다.

`ORDER SIBLINGS BY expression [ ASC | DESC ] [, ...]`

계층 구조의 형제 행(sibling rows)이 결과 집합에서 `expression`에 따라 정렬됩니다.

##### 참고 (Note)

EDB Postgres Advanced Server는 `CONNECT BY` 절에서 `AND` 또는 기타 연산자의 사용을 지원하지 않습니다.

## ORDER BY 절 (ORDER BY clause)

선택적 `ORDER BY` 절은 다음 형식을 가집니다:

```sql
ORDER BY expression [ ASC | DESC ] [, ...]
```

여기서 `expression`은 출력 열(`SELECT` 목록 항목)의 이름 또는 서수이거나, 입력 열 값으로 구성된 임의의 표현식일 수 있습니다.

`ORDER BY` 절은 지정된 표현식에 따라 결과 행을 정렬합니다. 두 행이 가장 왼쪽 표현식에 따라 동일하면 다음 표현식에 따라 비교되며, 이런 식으로 계속됩니다. 지정된 모든 표현식에 따라 동일하면 구현에 따라 달라지는(implementation-dependent) 순서로 반환됩니다.

서수는 결과 열의 서수적(왼쪽에서 오른쪽) 위치를 나타냅니다. 이 기능을 사용하면 고유한 이름이 없는 열을 기준으로 정렬을 정의할 수 있습니다. `AS` 절을 사용하여 결과 열에 항상 이름을 할당할 수 있으므로 이 기능이 반드시 필요한 것은 아닙니다.

`ORDER BY` 절에서 임의의 표현식을 사용할 수도 있으며, 여기에는 `SELECT` 결과 목록에 나타나지 않는 열도 포함됩니다. 따라서 다음 문은 유효합니다:

```sql
SELECT ename FROM emp ORDER BY empno;
```

이 기능의 제한 사항은, `UNION`, `INTERSECT`, `MINUS` 절의 결과에 적용되는 `ORDER BY` 절은 표현식이 아니라 출력 열 이름 또는 번호만 지정할 수 있다는 것입니다.

`ORDER BY` 표현식이 결과 열 이름과 입력 열 이름 모두와 일치하는 단순한 이름인 경우, `ORDER BY`는 이를 결과 열 이름으로 해석합니다. 이 동작은 동일한 상황에서 `GROUP BY`가 하는 선택과 반대입니다. 이 비일관성은 SQL 표준과 호환됩니다.

선택적으로 `ORDER BY` 절의 임의의 표현식 뒤에 키워드 `ASC`(오름차순) 또는 `DESC`(내림차순)를 추가할 수 있습니다. `ASC`가 기본값입니다.

널 값은 다른 어떤 값보다 높게 정렬됩니다. 다시 말해, 오름차순 정렬 순서에서는 널 값이 마지막에 정렬됩니다. 내림차순 정렬 순서에서는 널 값이 처음에 정렬됩니다.

문자열 데이터는 데이터베이스 클러스터가 초기화될 때 설정된 로케일별 정렬 순서(collation order)에 따라 정렬됩니다.

##### 참고 (Note)

`SELECT DISTINCT`를 지정하거나 `SELECT` 문에 `SELECT DISTINCT ...ORDER BY` 절이 포함된 경우, `ORDER BY`의 모든 표현식이 `SELECT DISTINCT` 쿼리의 select 목록에 존재해야 합니다.

## DISTINCT | UNIQUE 절 (DISTINCT | UNIQUE clause)

`SELECT` 문이 `DISTINCT` 또는 `UNIQUE`를 지정하면, 결과 집합에서 모든 중복 행이 제거됩니다. 각 중복 그룹에서 한 행이 유지됩니다. `DISTINCT` 절과 `UNIQUE` 절은 `SELECT` 문과 함께 사용될 때 동의어입니다. `ALL` 키워드는 그 반대, 즉 모든 행이 유지됨을 지정합니다(기본값).

`DISTINCT` 또는 `UNIQUE` 키워드를 포함하는 `SELECT` 문을 부적절하게 사용하여 발생하는 오류 메시지에는 `DISTINCT | UNIQUE` 키워드가 모두 포함됩니다:

```sql
psql: ERROR: FOR UPDATE is not allowed with DISTINCT/UNIQUE clause
```

## FOR UPDATE 절 (FOR UPDATE clause)

`FOR UPDATE` 절은 다음 형식을 가집니다:

```sql
FOR UPDATE [WAIT n|NOWAIT|SKIP LOCKED]
```

`FOR UPDATE`는 `SELECT` 문으로 검색된 행이 갱신을 위한 것처럼 잠기도록 합니다. 이는 현재 트랜잭션이 끝날 때까지 다른 트랜잭션이 행을 수정하거나 삭제하는 것을 방지합니다. 선택된 행을 `UPDATE`, `DELETE` 또는 `SELECT FOR UPDATE`하려고 시도하는 모든 트랜잭션은 현재 트랜잭션이 끝날 때까지 차단됩니다. 다른 트랜잭션의 `UPDATE`, `DELETE` 또는 `SELECT FOR UPDATE`가 이미 선택된 행 또는 행들을 잠갔다면, `SELECT FOR UPDATE`는 첫 번째 트랜잭션이 완료될 때까지 대기합니다. 그런 다음 갱신된 행을 잠그고 반환하거나, 행이 삭제되었다면 아무 행도 반환하지 않습니다.

집계와 같이 반환된 행을 개별 테이블 행과 명확하게 식별할 수 없는 컨텍스트에서는 `FOR UPDATE`를 사용할 수 없습니다.

잠금 기본 설정을 지정하려면 `FOR UPDATE` 옵션을 사용하세요:

- 다른 세션에 의해 잠긴 행을 `SELECT` 문이 대기할 초 수 또는 소수 초 수를 지정하려면 `WAIT n` 키워드를 포함하세요. 소수 초를 지정하려면 십진수 형식을 사용하세요. 예를 들어, `WAIT 1.5`는 1.5초를 대기합니다. 소수점 오른쪽으로 최대 네 자리까지 지정하세요.
- 현재 세션이 행을 잠글 수 없는 경우 즉시 오류를 보고하려면 `NOWAIT` 키워드를 포함하세요.
- 가능한 경우 행을 잠그고, 다른 세션에 의해 이미 잠긴 행은 건너뛰려면 `SKIP LOCKED`를 포함하세요.
