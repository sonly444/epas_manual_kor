# ALTER TABLE — EPAS 18 Reference

> 원문: [EPAS v18 — Reference › Oracle 호환 › 호환 SQL 명령 › ALTER TABLE](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/12_alter_table/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·코드 이름은 원문 그대로 보존했습니다.

## 이름 (Name)

`ALTER TABLE` — 테이블의 정의를 변경합니다.

## 구문 개요 (Synopsis)

```sql
ALTER TABLE <name>
  action [, ...]
ALTER TABLE <name>
  RENAME COLUMN <column> TO <new_column>
ALTER TABLE <name>
  RENAME TO <new_name>
ALTER TABLE <name>
  { NOPARALLEL | PARALLEL [ <integer> ] }
```

`action`은 다음 중 하나입니다:

```sql
ADD <column type> [ <column_constraint> [ ... ] ]
DROP COLUMN <column>
ADD <table_constraint>
DROP CONSTRAINT <constraint_name> [ CASCADE ]
```

## 설명 (Description)

`ALTER TABLE`은 기존 테이블의 정의를 변경합니다. 여러 하위 형식이 있습니다:

- `ADD column type`

이 형식은 `CREATE TABLE`과 동일한 구문을 사용하여 테이블에 열을 추가합니다.

- `DROP COLUMN`

이 형식은 테이블에서 열을 삭제합니다. 해당 열과 관련된 인덱스와 테이블 제약 조건도 함께 삭제됩니다.

- `ADD table_constraint`

이 형식은 테이블에 제약 조건을 추가합니다. 자세한 내용은 [CREATE TABLE](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/36_create_table/#create_table)을 참조하십시오.

- `DROP CONSTRAINT`

이 형식은 테이블의 제약 조건을 삭제합니다. 현재 테이블의 제약 조건은 고유한 이름을 가질 필요가 없으므로, 지정된 이름과 일치하는 제약 조건이 둘 이상 존재할 수 있습니다. 일치하는 모든 제약 조건이 삭제됩니다.

`RENAME`

`RENAME` 형식은 테이블(또는 인덱스, 시퀀스, 뷰)의 이름이나 테이블 내 열의 이름을 변경합니다. 저장된 데이터에는 영향을 주지 않습니다.

`PARALLEL` 절은 테이블의 병렬 처리 정도(degree of parallelism)를 설정합니다. `NOPARALLEL` 절은 값을 기본값으로 재설정합니다. `reloptions`는 `parallel_workers` 파라미터를 `0`으로 표시합니다.

슈퍼유저는 어떤 사용자의 테이블에든 트리거를 생성할 권한이 있지만, 일반 사용자는 자신이 소유한 테이블에만 트리거를 생성할 수 있습니다. 다만 테이블의 소유권이 변경되면, 트리거를 소유한 테이블 소유자와 매칭될 때 트리거의 암시적 객체(implicit object)의 소유권이 갱신됩니다.

`ALTER TRIGGER ...ON AUTHORIZATION` 명령을 사용하여 트리거의 암시적 객체 소유자를 변경할 수 있습니다. 자세한 내용은 [ALTER TRIGGER](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/13_alter_trigger/#alter_trigger)를 참조하십시오.

`ALTER TABLE`을 사용하려면 해당 테이블을 소유하고 있어야 합니다.

## 파라미터 (Parameters)

`name`

변경할 기존 테이블의 이름(스키마로 한정될 수 있음).

`column`

새 열 또는 기존 열의 이름.

`new_column`

기존 열의 새 이름.

`new_name`

테이블의 새 이름.

`type`

새 열의 데이터 타입.

`table_constraint`

테이블에 대한 새 테이블 제약 조건.

`constraint_name`

삭제할 기존 제약 조건의 이름.

`CASCADE`

삭제된 제약 조건에 의존하는 객체를 자동으로 삭제합니다.

`PARALLEL`

병렬 처리 정도를 선택하려면 `PARALLEL`을 지정합니다. 테이블에서 병렬 스캔을 수행할 때 `parallel_workers` 파라미터를 설정하여 병렬 처리 정도를 지정할 수도 있습니다. 병렬 처리 정도를 포함하지 않고 `PARALLEL`만 지정하면 인덱스는 기본 병렬 처리를 사용합니다.

`NOPARALLEL`

병렬 처리를 기본값으로 재설정하려면 `NOPARALLEL`을 지정합니다.

`integer`

`integer`는 병렬 처리 정도를 나타내며, 이는 테이블에서 병렬 스캔을 수행하기 위해 병렬 작업에 사용되는 `parallel_workers`의 수입니다.

## 참고 (Notes)

`ADD COLUMN`을 호출하면 테이블의 모든 기존 행이 해당 열의 기본값(`DEFAULT` 절을 지정하지 않은 경우 null)으로 초기화됩니다. null이 아닌 기본값을 가진 열을 추가하려면 테이블 전체를 다시 써야 합니다(rewrite). 큰 테이블의 경우 이 작업은 오래 걸릴 수 있으며, 일시적으로 두 배의 디스크 공간이 필요합니다. `CHECK` 또는 `NOT NULL` 제약 조건을 추가하려면 기존 행이 해당 제약 조건을 충족하는지 확인하기 위해 테이블을 스캔해야 합니다.

`DROP COLUMN` 형식은 열을 물리적으로 제거하지 않고 SQL 작업에서 보이지 않도록 만듭니다. 이후 테이블에서 수행되는 삽입 및 갱신 작업은 해당 열에 대해 null 값을 저장합니다. 따라서 열을 삭제하는 것은 빠르지만, 삭제된 열이 차지하던 공간이 회수되지 않기 때문에 테이블의 디스크 크기가 즉시 줄어들지는 않습니다. 이 공간은 기존 행이 갱신되면서 시간이 지남에 따라 회수됩니다.

시스템 카탈로그 테이블의 어떤 부분도 변경하는 것은 허용되지 않습니다. 유효한 파라미터에 대한 자세한 설명은 [CREATE TABLE](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/36_create_table/#create_table)을 참조하십시오.

## 예제 (Examples)

테이블에 `VARCHAR2` 타입의 열을 추가하려면:

```sql
ALTER TABLE emp ADD address VARCHAR2(30);
```

테이블에서 열을 삭제하려면:

```sql
ALTER TABLE emp DROP COLUMN address;
```

기존 열의 이름을 변경하려면:

```sql
ALTER TABLE emp RENAME COLUMN address TO city;
```

기존 테이블의 이름을 변경하려면:

```sql
ALTER TABLE emp RENAME TO employee;
```

테이블에 체크 제약 조건을 추가하려면:

```sql
ALTER TABLE emp ADD CONSTRAINT sal_chk CHECK (sal > 500);
```

테이블에서 체크 제약 조건을 제거하려면:

```sql
ALTER TABLE emp DROP CONSTRAINT sal_chk;
```

`emp` 테이블에서 병렬 처리 정도를 0으로 재설정하려면:

```sql
ALTER TABLE emp NOPARALLEL;
```

다음 예제는 `dept`라는 테이블을 생성한 다음, `dname` 열에 고유 키(unique key)를 정의하고 활성화하도록 `dept` 테이블을 변경합니다. `dept_dname_uq` 제약 조건은 `dname` 열을 고유 키로 지정합니다. `USING_INDEX` 절은 지정된 인덱스 구문으로 테이블 `dept`에 인덱스를 생성하여 고유 제약 조건을 활성화합니다.

```sql
CREATE TABLE dept (
   deptno          NUMBER(2),
   dname           VARCHAR2(14),
   loc             VARCHAR2(13)
);
```

```sql
ALTER TABLE dept
  ADD CONSTRAINT dept_dname_uq UNIQUE(dname)
     USING INDEX (CREATE UNIQUE INDEX idx_dept_dname_uq ON dept (dname));
```

다음 예제는 `emp`라는 테이블을 생성한 다음, `ename` 열에 기본 키(primary key)를 정의하고 활성화하도록 `emp` 테이블을 변경합니다. `emp_ename_pk` 제약 조건은 `ename` 열을 `emp` 테이블의 기본 키로 지정합니다. `USING_INDEX` 절은 지정된 인덱스 구문으로 테이블 `emp`에 인덱스를 생성하여 기본 키 제약 조건을 활성화합니다.

```sql
CREATE TABLE emp (
   empno           NUMBER(4) NOT NULL,
   ename           VARCHAR2(10),
   job             VARCHAR2(9),
   sal             NUMBER(7,2),
   deptno          NUMBER(2)
);
```

```sql
ALTER TABLE emp
  ADD CONSTRAINT emp_ename_pk PRIMARY KEY (ename)
     USING INDEX (CREATE INDEX idx_emp_ename_pk ON emp (ename));
```
