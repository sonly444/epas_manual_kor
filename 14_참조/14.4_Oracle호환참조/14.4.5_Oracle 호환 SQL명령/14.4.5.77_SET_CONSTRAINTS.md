# SET CONSTRAINTSv18

## 이름 (Name)

`SET CONSTRAINTS` — 현재 트랜잭션에 대한 제약 조건 검사 모드를 설정합니다.

## 구문 개요 (Synopsis)

```sql
SET CONSTRAINTS { ALL | name [, ...] } { DEFERRED | IMMEDIATE }
```

## 설명 (Description)

`SET CONSTRAINTS`는 현재 트랜잭션에서 제약 조건 검사의 동작을 설정합니다. `IMMEDIATE` 제약 조건은 각 문의 끝에서 검사됩니다. `DEFERRED` 제약 조건은 트랜잭션이 커밋될 때 검사됩니다. 각 제약 조건은 자체적인 `IMMEDIATE` 또는 `DEFERRED` 모드를 가집니다.

제약 조건을 생성할 때 세 가지 특성 중 하나를 부여합니다: `DEFERRABLE INITIALLY DEFERRED`, `DEFERRABLE INITIALLY IMMEDIATE`, 또는 `NOT DEFERRABLE`. 세 번째 부류는 항상 `IMMEDIATE`이며 `SET CONSTRAINTS` 명령의 영향을 받지 않습니다. 처음 두 부류는 모든 트랜잭션을 지정된 모드로 시작하지만, `SET CONSTRAINTS`를 사용하여 트랜잭션 내에서 그 동작을 변경할 수 있습니다.

제약 조건 이름 목록을 지정한 `SET CONSTRAINTS`는 그 제약 조건들의 모드만 변경합니다. 그 제약 조건들은 모두 지연 가능(deferrable)해야 합니다. 여러 제약 조건이 주어진 이름과 일치하면 모두 영향을 받습니다. `SET CONSTRAINTS ALL`은 모든 지연 가능한 제약 조건의 모드를 변경합니다.

`SET CONSTRAINTS`가 제약 조건의 모드를 `DEFERRED`에서 `IMMEDIATE`로 변경하면, 새 모드가 소급하여 적용됩니다. 일반적으로 트랜잭션 끝에서 검사되는 미처리 데이터 수정은 대신 `SET CONSTRAINTS`가 실행되는 동안 검사됩니다. 그러한 제약 조건이 위반되면 `SET CONSTRAINTS`는 실패하고 제약 조건 모드를 변경하지 않습니다. 따라서 `SET CONSTRAINTS`를 사용하여 트랜잭션의 특정 지점에서 제약 조건 검사가 발생하도록 강제할 수 있습니다.

현재는 외래 키(foreign key) 제약 조건만 이 설정의 영향을 받습니다. 검사(check) 및 고유(unique) 제약 조건은 결코 지연 가능하지 않습니다.

## 참고 (Notes)

이 명령은 현재 트랜잭션에서 제약 조건의 동작만 변경합니다. 이 명령을 트랜잭션 블록 외부에서 실행하면 아무런 효과가 없습니다.
