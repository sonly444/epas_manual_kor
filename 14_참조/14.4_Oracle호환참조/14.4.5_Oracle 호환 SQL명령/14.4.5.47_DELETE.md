# DELETE — EPAS 18 Reference

> 원문: [EPAS v18 — Reference › Oracle 호환 › 호환 SQL 명령 › DELETE](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/44_delete/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·코드 이름은 원문 그대로 보존했습니다.

## 이름 (Name)

`DELETE` — 테이블의 행을 삭제합니다.

## 구문 개요 (Synopsis)

```text
DELETE [ <optimizer_hint> ] [ FROM ] <table>[@<dblink> ]
  [ WHERE <condition> ]
  [ RETURNING <return_expression> [, ...]\
      { INTO { <record> | <variable> [, ...] }\
      | BULK COLLECT INTO <collection> [, ...] } ]
```

## 설명 (Description)

`DELETE`는 지정한 테이블에서 `WHERE` 절을 만족하는 행을 삭제합니다. `WHERE` 절을 생략하면 테이블의 모든 행이 삭제되어 빈 테이블이 됩니다. 테이블에서 삭제하려면 해당 테이블에 대한 `DELETE` 권한이 필요합니다. 또한 조건에서 값을 읽어오는 모든 테이블에 대해서는 `SELECT` 권한도 필요합니다.

EDB Postgres Advanced Server가 Oracle 호환 모드로 설치된 경우 `FROM` 키워드는 선택 사항입니다. EDB Postgres Advanced Server가 Postgres 모드로 설치된 경우에는 필수입니다.

##### 참고 (Note)

`TRUNCATE` 명령은 테이블의 모든 행을 더 빠르게 제거하는 방법입니다.

`RETURNING INTO { record | variable [, ...] }` 절은 `DELETE` 명령을 SPL 프로그램에서 사용할 때만 지정할 수 있습니다. `DELETE` 명령의 결과 집합은 하나를 초과하는 행을 포함할 수 없습니다. 초과하면 오류가 발생합니다. 결과 집합이 비어 있으면 대상 레코드 또는 변수의 내용은 null로 설정됩니다.

`RETURNING BULK COLLECT INTO collection [, ...]` 절은 `DELETE` 명령을 SPL 프로그램에서 사용할 때만 지정할 수 있습니다. `BULK COLLECT INTO` 절의 대상으로 둘 이상의 `collection`을 지정하는 경우, 각 `collection`은 단일 스칼라 필드로 구성되어야 합니다. 즉, `collection`은 레코드일 수 없습니다.

`DELETE` 명령의 결과 집합은 0개, 1개 또는 여러 개의 행을 포함할 수 있습니다. 결과 집합의 각 행에 대해 평가된 `return_expression`은 첫 번째 요소부터 시작하여 `collection`의 요소가 됩니다. `collection`에 기존에 있던 행은 모두 삭제됩니다. 결과 집합이 비어 있으면 `collection`도 비어 있게 됩니다.

## 파라미터 (Parameters)

`optimizer_hint`

실행 계획을 선택하도록 옵티마이저에 전달하는 주석 내장 힌트입니다.

`table`

기존 테이블의 이름(선택적으로 스키마로 한정할 수 있음)입니다.

`dblink`

원격 데이터베이스를 식별하는 데이터베이스 링크 이름입니다. 자세한 내용은 [`CREATE DATABASE LINK`](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/21_create_public_database_link/)를 참조하세요.

`condition`

삭제할 행을 결정하는 `BOOLEAN` 타입의 값을 반환하는 값 표현식입니다.

`return_expression`

`table`의 하나 이상의 컬럼을 포함할 수 있는 표현식입니다. `return_expression`에 `table`의 컬럼 이름을 지정하면, `return_expression`이 평가될 때 해당 컬럼에 대입되는 값은 삭제된 행의 값입니다.

`record`

평가된 `return_expression`을 대입할 필드를 가진 레코드입니다. 첫 번째 `return_expression`은 `record`의 첫 번째 필드에 대입되고, 두 번째 `return_expression`은 `record`의 두 번째 필드에 대입되는 식으로 진행됩니다. `record`의 필드 개수는 표현식의 개수와 정확히 일치해야 하며, 각 필드는 대입되는 표현식과 타입이 호환되어야 합니다.

`variable`

평가된 `return_expression`을 대입할 변수입니다. 둘 이상의 `return_expression`과 `variable`을 지정하는 경우, 첫 번째 `return_expression`은 첫 번째 `variable`에 대입되고, 두 번째 `return_expression`은 두 번째 `variable`에 대입되는 식으로 진행됩니다. `INTO` 키워드 뒤에 지정하는 변수의 개수는 `RETURNING` 키워드 뒤에 오는 표현식의 개수와 정확히 일치해야 하며, 변수는 대입되는 표현식과 타입이 호환되어야 합니다.

`collection`

평가된 `return_expression`으로부터 요소가 생성되는 컬렉션입니다. 단일 필드로 된 컬렉션이거나 레코드 타입의 컬렉션인 단일 컬렉션을 가질 수 있습니다. 또는 둘 이상의 컬렉션을 가질 수도 있습니다. 그 경우 각 컬렉션은 단일 필드로 구성되어야 합니다. 반환 표현식의 개수는 지정된 모든 컬렉션의 필드 개수 및 순서와 일치해야 합니다. 대응하는 각 `return_expression`과 `collection` 필드는 타입이 호환되어야 합니다.

## 예제 (Examples)

`jobhist` 테이블에서 직원 `7900`에 대한 모든 행을 삭제합니다.

```sql
DELETE FROM jobhist WHERE empno = 7900;
```

`jobhist` 테이블을 비웁니다.

```sql
DELETE FROM jobhist;
```
