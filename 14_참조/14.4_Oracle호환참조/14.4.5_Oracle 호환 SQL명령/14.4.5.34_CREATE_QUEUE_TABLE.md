# CREATE QUEUE TABLE v18

EDB Postgres Advanced Server는 `CREATE QUEUE TABLE SQL` 명령을 통해 Oracle에서 제공하지 않는 추가 구문을 제공합니다. 이 구문은 `DBMS_AQADM`과 함께 사용할 수 있습니다.

## 이름 (Name)

`CREATE QUEUE TABLE` — 큐 테이블(queue table)을 생성합니다.

## 구문 개요 (Synopsis)

큐 테이블을 정의하려면 `CREATE QUEUE TABLE`을 사용합니다.

```sql
CREATE QUEUE TABLE <name> OF <type_name> [ ( { <option_name option_value> } [, ... ] ) ]
```

가능한 `option_name`과 그에 해당하는 `option_value` 값은 다음과 같습니다.

- `SORT_LIST` — `option_value`를 `priority`, `enq_time`으로 지정합니다.
- `MULTIPLE_CONSUMERS` — `option_value`를 `FALSE`, `TRUE`로 지정합니다.
- `MESSAGE_GROUPING` — `option_value`를 `NONE`, `TRANSACTIONAL`로 지정합니다.
- `STORAGE_CLAUSE` — `option_value`를 `TABLESPACE tablespace_name`, `PCTFREE integer`, `PCTUSED integer`, `INITRANS integer`, `MAXTRANS integer`, `STORAGE storage_option`으로 지정합니다. `storage_option`의 값은 다음 중 하나 이상입니다: `MINEXTENTS integer`, `MAXEXTENTS integer`, `PCTINCREASE integer`, `INITIAL size_clause`, `NEXT`, `FREELISTS integer`, `OPTIMAL size_clause`, `BUFFER_POOL {KEEP|RECYCLE|DEFAULT}`.

`TABLESPACE` 옵션만 실제로 적용됩니다. 나머지는 모두 호환성을 위해 허용되지만 무시됩니다. 테이블을 생성할 테이블스페이스의 이름을 지정하려면 `TABLESPACE` 절을 사용합니다.

## 설명 (Description)

`CREATE QUEUE TABLE`을 사용하면 슈퍼유저 또는 `aq_administrator_role` 권한을 가진 사용자가 큐 테이블을 생성할 수 있습니다.

`CREATE QUEUE TABLE` 호출에 스키마 이름이 포함되어 있으면 큐 테이블은 지정된 스키마에 생성됩니다. 스키마 이름을 제공하지 않으면 큐 테이블은 현재 스키마에 생성됩니다.

큐 테이블의 이름은 동일한 스키마 내의 큐 테이블 중에서 고유해야 합니다.

## 파라미터 (Parameters)

`name`

새 큐 테이블의 이름(선택적으로 스키마로 한정).

`type_name`

큐 테이블의 각 항목에 대한 페이로드(payload)를 설명하는 기존 타입의 이름입니다. 타입 정의에 대한 정보는 [CREATE TYPE](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/39_create_type/)을 참조하세요.

`option_name option_value`

새 큐와 연관시킬 옵션의 이름과 그 옵션에 해당하는 값입니다. `CREATE QUEUE` 호출에 중복된 옵션 이름이 포함되어 있으면 서버가 오류를 반환합니다. 다음 값이 허용됩니다.

- `SORT_LIST` — `SORT_LIST` 옵션을 사용하여 큐의 디큐(dequeue) 순서를 제어합니다. 큐를 정렬하는 데 사용할 컬럼 이름을 오름차순으로 지정합니다. `enq_time`과 `priority`의 다음 조합이 가능한 값입니다.

`enq_time. priority`

`priority. enq_time`

`priority`

`enq_time`

- `MULTIPLE_CONSUMERS` — 메시지가 둘 이상의 소비자(consumer)를 가질 수 있는지(`TRUE`) 또는 메시지당 하나의 소비자로 제한되는지(`FALSE`)를 나타내는 `BOOLEAN` 값입니다.

- `MESSAGE_GROUPING` — 각 메시지를 개별적으로 디큐하려면 `none`을 지정하고, 하나의 트랜잭션 결과로 메시지를 큐에 추가하고 그룹으로 디큐하려면 `transactional`을 지정합니다.

- `STORAGE_CLAUSE` — `STORAGE_CLAUSE`를 사용하여 테이블 속성을 지정합니다. 가능한 값은 `TABLESPACE tablespace_name`, `PCTFREE integer`, `PCTUSED integer`, `INITRANS integer`, `MAXTRANS integer`, `STORAGE storage_option`입니다. `storage_option`의 가능한 값은 다음과 같습니다.

`MINEXTENTS integer`

`MAXEXTENTS integer`

`PCTINCREASE integer`

`INITIAL size_clause`

`NEXT`

`FREELISTS integer`

`OPTIMAL size_clause`

`BUFFER_POOL {KEEP|RECYCLE|DEFAULT}`


`TABLESPACE` 옵션만 실제로 적용됩니다. 나머지는 모두 호환성을 위해 허용되지만 무시됩니다. 테이블을 생성할 테이블스페이스의 이름을 지정하려면 `TABLESPACE` 절을 사용합니다.

## 예제 (Examples)

큐 테이블을 생성하기 전에 사용자 정의 타입을 먼저 생성해야 합니다. 이 타입은 테이블의 컬럼과 데이터 타입을 설명합니다. 다음 명령은 `work_order`라는 타입을 생성합니다.

```sql
CREATE TYPE work_order AS (name VARCHAR2, project TEXT, completed BOOLEAN);
```

다음 명령은 `work_order` 타입을 사용하여 `work_order_table`이라는 큐 테이블을 생성합니다.

```sql
CREATE QUEUE TABLE work_order_table OF work_order (sort_list (enq_time, priority));
```
