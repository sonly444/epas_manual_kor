# IMPORT FOREIGN SCHEMA — EPAS 18 Reference

> 원문: [EPAS v18 — Reference › Oracle 호환 › 호환 SQL 명령 › IMPORT FOREIGN SCHEMA](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/65a_import_foreign_schema/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·코드 이름은 원문 그대로 보존했습니다.

## 이름 (Name)

`IMPORT FOREIGN SCHEMA` — 외부 서버(foreign server) 또는 데이터베이스 링크로부터 외부 스키마(foreign schema)를 임포트합니다.

## 구문 개요 및 파라미터 (Synopsis and parameters)

명령 구문, 파라미터 및 기능에 대해서는 [IMPORT FOREIGN SCHEMA](https://www.postgresql.org/docs/current/sql-importforeignschema.html)를 참조하십시오.

NOT NULL 제약 조건은 기본적으로 임포트됩니다. NOT NULL 제약 조건을 임포트하지 않으려면 `import_not_null` 옵션을 사용하십시오.

## 설명 (Description)

Foreign Data Wrapper 또는 데이터베이스 링크로 원격 데이터베이스에 대한 액세스를 생성한 후에는 `IMPORT FOREIGN SCHEMA`로 외부 스키마를 임포트할 수 있습니다. [데이터베이스 링크 생성 예제](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/21_create_public_database_link/#examples)에서 설명한 대로 `edb_dblink_oci` 연결로 생성한 데이터베이스 링크로 외부 스키마를 임포트할 수 있습니다.

그러면 임포트한 스키마 객체를 원격이 아닌 로컬에서 액세스할 수 있습니다.

## 예제 (Examples)

이 예제는 `IMPORT FOREIGN SCHEMA` 명령을 사용하여 Oracle 서버에서 `IMP`라는 이름의 데이터베이스 스키마를 EDB Postgres Advanced Server로 임포트합니다. 임포트된 테이블 정의를 담을 대상 스키마는 `tmp_schema`라고 하며, `oci_link`라는 `edb_dblink_oci` 연결을 사용합니다.

### 사전 요구 사항 (Prerequisites)

- `connstr` 정보를 준비해 두었는지 확인하십시오.

- 다음 예제와 같이 [서버(server)](https://www.postgresql.org/docs/current/sql-createserver.html)와 [사용자 매핑(user mapping)](https://www.postgresql.org/docs/current/sql-createusermapping.html)을 생성하십시오. 또는 [public 데이터베이스 링크를 생성](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/21_create_public_database_link/)할 수도 있습니다.


### 스키마 임포트 (Import schemas)

1. Oracle 데이터베이스에 연결하는 [서버를 생성](https://www.postgresql.org/docs/current/sql-createserver.html)합니다(여기서는 `oci_link`라고 함). foreign data wrapper와 Oracle 서비스에 도달하는 데 필요한 연결 문자열을 지정하십시오.


```sql
CREATE SERVER oci_link FOREIGN DATA WRAPPER oci_dblink OPTIONS (connstr :ORACLE_SERVICE);
```



여기서 `ORACLE_SERVICE`는 임포트를 수행하려는 Oracle 서비스의 이름에 대한 환경 변수입니다.

2. 스키마를 임포트하려는 Oracle 데이터베이스 사용자에게 EDB Postgres의 `edb` 사용자를 매핑합니다. 앞에서 생성한 `oci_link` 연결을 사용하고, Oracle의 사용자와 비밀번호를 지정하십시오.


```sql
CREATE USER MAPPING FOR edb SERVER oci_link OPTIONS ("user" 'a', password 'c');
```



여기서 `'a'`는 외부 스키마에 액세스할 수 있는 Oracle 사용자 이름이고 `'c'`는 그 비밀번호입니다.

3. 임포트된 객체를 배치할 스키마를 생성합니다.


```sql
CREATE SCHEMA tmp_schema;
```

4. `oci_link` 연결을 사용하여 소스 데이터베이스에서 `IMP` 스키마를 EDB Postgres Advanced의 `tmp_schema`로 임포트합니다.


```sql
IMPORT FOREIGN SCHEMA "IMP" FROM SERVER oci_link INTO tmp_schema;
```



이 명령은 Oracle 서버에 존재하는 테이블을 나타내는 외부 테이블(foreign table)을 생성합니다.

기본적으로 외부 서버의 특정 스키마에 존재하는 모든 테이블과 뷰가 임포트됩니다. 선택적으로 테이블 목록을 지정된 하위 집합으로 제한하거나 특정 테이블을 제외할 수 있습니다.

5. 임포트된 외부 테이블이 예상하는 모든 스키마 객체를 포함하는지 확인합니다.


```sql
SELECT * FROM tmp_schema."FOO";
```



출력(Output)


```text
    a | b | c | d
   ---+--------+------------+-----
    1 | 1.1000 | ABC | XYZ
(1 row)
```


```sql
SELECT * FROM tmp_schema."Foo";
```



출력(Output)


```text
    a | b | c | d
   ---+--------+------------+-----
    2 | 2.2000 | PQR | STU
(1 row)
```


```sql
SELECT * FROM tmp_schema."V1";
```



출력(Output)


```text
    a | b | c | d
   ---+--------+------------+-----
    1 | 1.1000 | ABC | XYZ
(1 row)
```
