# CREATE SEQUENCE v18

## 이름 (Name)

`CREATE SEQUENCE` — 새 시퀀스 생성기(sequence generator)를 정의합니다.

## 구문 개요 (Synopsis)

```sql
CREATE SEQUENCE <name> [ INCREMENT BY <increment> ]
  [ { NOMINVALUE | MINVALUE <minvalue> } ]
  [ { NOMAXVALUE | MAXVALUE <maxvalue> } ]
  [ START WITH <start> ] [ CACHE <cache> | NOCACHE ] [ CYCLE ]
```

## 설명 (Description)

`CREATE SEQUENCE`는 시퀀스 번호 생성기를 생성합니다. 이 과정은 지정된 이름을 가진 특수한 단일 행 테이블을 생성하고 초기화하는 것을 포함합니다. 생성기는 이를 생성한 사용자가 소유합니다.

스키마 이름을 포함하면 시퀀스는 지정된 스키마에 생성됩니다. 그렇지 않으면 현재 스키마에 생성됩니다. 시퀀스 이름은 동일한 스키마 내의 다른 시퀀스, 테이블, 인덱스, 뷰의 이름과 달라야 합니다.

시퀀스를 생성한 후에는 `NEXTVAL`과 `CURRVAL` 함수를 사용하여 이를 조작합니다. 이 함수들은 [SQL reference](https://www.enterprisedb.com/docs/epas/latest/reference/sql_reference/03_functions_and_operators/09_sequence_manipulation_functions/)에 문서화되어 있습니다.

## 파라미터 (Parameters)

`name`

생성할 시퀀스의 이름(선택적으로 스키마로 한정).

`increment`

선택적 절 `INCREMENT BY increment`는 새 값을 만들기 위해 현재 시퀀스 값에 더할 값을 지정합니다. 오름차순 시퀀스를 만들려면 양수 값을 사용하고, 내림차순 시퀀스를 만들려면 음수 값을 사용합니다. 기본값은 `1`입니다.

`NOMINVALUE | MINVALUE minvalue`

선택적 절 `MINVALUE minvalue`는 시퀀스가 생성할 수 있는 최솟값을 결정합니다. 기본값은 오름차순 시퀀스의 경우 1이고 내림차순 시퀀스의 경우 -263-1입니다. 이 동작을 기본값으로 설정하려면 `NOMINVALUE` 키워드를 사용할 수 있습니다.

`NOMAXVALUE | MAXVALUE maxvalue`

선택적 절 `MAXVALUE maxvalue`는 시퀀스의 최댓값을 결정합니다. 기본값은 오름차순 시퀀스의 경우 263-1이고 내림차순 시퀀스의 경우 -1입니다. 이 동작을 기본값으로 설정하려면 `NOMAXVALUE` 키워드를 사용할 수 있습니다.

`start`

선택적 절 `START WITH start`는 시퀀스가 임의의 위치에서 시작할 수 있게 합니다. 기본 시작 값은 오름차순 시퀀스의 경우 `minvalue`이고 내림차순 시퀀스의 경우 `maxvalue`입니다.

`cache`

선택적 절 `CACHE cache`는 더 빠른 접근을 위해 미리 할당하여 메모리에 저장할 시퀀스 번호의 개수를 지정합니다. 최솟값은 `1`이며 이것이 기본값이기도 합니다. 이 설정은 한 번에 하나의 값만 생성하며, 즉 `NOCACHE`입니다.

`CYCLE`

`CYCLE` 옵션은 오름차순 또는 내림차순 시퀀스가 각각 `maxvalue` 또는 `minvalue`에 도달했을 때 시퀀스가 순환(wrap around)하도록 합니다. 한계에 도달하면 다음에 생성되는 번호는 각각 `minvalue` 또는 `maxvalue`가 됩니다.

`CYCLE`을 생략하면 시퀀스가 최댓값에 도달한 후 `NEXTVAL`을 호출하면 오류가 반환됩니다. 기본 동작을 사용하려면 `NO CYCLE` 키워드를 사용할 수 있습니다. 다만 이 용어는 Oracle 데이터베이스와 호환되지 않습니다.

## 참고 사항 (Notes)

시퀀스는 큰 정수(big integer) 산술을 기반으로 하므로 범위는 8바이트 정수의 범위(-9223372036854775808 ~ 9223372036854775807)를 초과할 수 없습니다. 일부 오래된 플랫폼은 8바이트 정수에 대한 컴파일러 지원이 없을 수 있습니다. 이 경우 시퀀스는 일반 `INTEGER` 산술(범위 -2147483648 ~ +2147483647)을 사용합니다.

여러 세션에서 동시에 사용될 시퀀스 객체에 대해 `1`보다 큰 `cache` 설정을 사용하면 예기치 않은 결과가 발생할 수 있습니다. 각 세션은 시퀀스 객체에 한 번 접근하는 동안 연속된 시퀀스 값을 할당하여 캐시하고, 그에 따라 시퀀스 객체의 마지막 값을 증가시킵니다. 그런 다음 해당 세션에서 `NEXTVAL`을 사용하는 다음 `cache-1`번의 호출은 시퀀스 객체를 건드리지 않고 미리 할당된 값을 반환합니다. 따라서 세션에서 할당되었지만 사용되지 않은 번호는 해당 세션이 종료될 때 손실됩니다. 그 결과 시퀀스에 "구멍(hole)"이 생깁니다.

또한 여러 세션이 서로 다른 시퀀스 값을 할당하는 것은 보장되지만, 모든 세션을 고려했을 때 값이 순서에서 벗어나 생성될 수 있습니다. 예를 들어 `cache` 설정이 `10`인 경우, 세션 A가 값 1..10을 예약하고 `NEXTVAL=1`을 반환할 수 있습니다. 그런 다음 세션 A가 `NEXTVAL=2`를 생성하기 전에 세션 B가 값 11..20을 예약하고 `NEXTVAL=11`을 반환할 수 있습니다. 따라서 `cache` 설정이 `1`인 경우 `NEXTVAL` 값이 순차적으로 생성된다고 가정하는 것이 안전합니다. `cache` 설정이 `1`보다 큰 경우에는 `NEXTVAL` 값이 모두 서로 다르다고만 가정할 수 있고 순차적으로 생성된다고 가정할 수는 없습니다. 또한 마지막 값은 `NEXTVAL`에 의해 이미 반환되었는지 여부와 관계없이 어떤 세션이든 예약한 가장 최근 값을 반영합니다.

## 예제 (Examples)

101에서 시작하는 `serial`이라는 오름차순 시퀀스를 생성합니다.

```sql
CREATE SEQUENCE serial START WITH 101;
```

이 시퀀스에서 다음 번호를 선택합니다.

```sql
SELECT serial.NEXTVAL FROM DUAL;
```

출력

```text
 nextval
---------
     101
(1 row)
```

`NOCACHE` 옵션을 사용하여 `supplier_seq`라는 시퀀스를 생성합니다.

```sql
CREATE SEQUENCE supplier_seq
    MINVALUE 1
    START WITH 1
    INCREMENT BY 1
    NOCACHE;
```

이 시퀀스에서 다음 번호를 선택합니다.

```sql
SELECT supplier_seq.NEXTVAL FROM DUAL;
```

출력

```text
 nextval
---------
       1
(1 row)
```
