# REVOKEv18

## 이름 (Name)

`REVOKE` — 접근 권한을 제거합니다.

## 구문 개요 (Synopsis)

```sql
REVOKE { { SELECT | INSERT | UPDATE | DELETE | REFERENCES }
  [,...] | ALL [ PRIVILEGES ] }
  ON tablename
  FROM { username | groupname | PUBLIC } [, ...]
  [ CASCADE | RESTRICT ]

REVOKE { { CREATE | DROP | READ | WRITE } }
  ON DIRECTORY dirname
  FROM { username }

REVOKE { SELECT | ALL [ PRIVILEGES ] }
  ON sequencename
  FROM { username | groupname | PUBLIC } [, ...]
  [ CASCADE | RESTRICT ]

REVOKE { EXECUTE | ALL [ PRIVILEGES ] }
  ON FUNCTION progname
    ( [ [ argmode ] [ argname ] argtype ] [, ...] )
  FROM { username | groupname | PUBLIC } [, ...]
  [ CASCADE | RESTRICT ]

REVOKE { EXECUTE | ALL [ PRIVILEGES ] }
  ON PROCEDURE progname
    [ ( [ [ argmode ] [ argname ] argtype ] [, ...] ) ]
  FROM { username | groupname | PUBLIC } [, ...]
  [ CASCADE | RESTRICT ]

REVOKE { EXECUTE | ALL [ PRIVILEGES ] }
  ON PACKAGE packagename
  FROM { username | groupname | PUBLIC } [, ...]
  [ CASCADE | RESTRICT ]

REVOKE role [, ...] FROM { username | groupname | PUBLIC }
  [, ...]
  [ CASCADE | RESTRICT ]

REVOKE { CONNECT | RESOURCE | DBA } [, ...]
  FROM { username | groupname } [, ...]

REVOKE CREATE [ PUBLIC ] DATABASE LINK
  FROM { username | groupname }

REVOKE DROP PUBLIC DATABASE LINK
  FROM { username | groupname }

REVOKE EXEMPT ACCESS POLICY
  FROM { username | groupname }
```

## 설명 (Description)

`REVOKE` 명령은 하나 이상의 롤(role)에 부여된 권한을 취소합니다. 키워드 `PUBLIC`은 모든 롤로 암묵적으로 정의된 그룹을 가리킵니다.

권한 유형의 의미는 [`GRANT`](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/64_grant/)를 참조하세요.

롤은 다음의 합계를 가집니다:

- 직접 부여된 권한
- 현재 소속되어 있는 임의의 롤에 부여된 권한
- `PUBLIC`에 부여된 권한

따라서 예를 들어, `PUBLIC`에서 `SELECT` 권한을 취소한다고 해서 반드시 모든 롤이 해당 객체에 대한 `SELECT` 권한을 잃는 것은 아닙니다. 직접 또는 다른 롤로부터 권한을 부여받은 롤은 여전히 그 권한을 가집니다.

권한이 grant option과 함께 부여된 경우, 해당 권한에 대한 grant option은 권한과 함께 취소됩니다.

어떤 사용자가 grant option과 함께 권한을 보유하고 이를 다른 사용자에게 부여한 경우, 그 다른 사용자가 보유한 권한을 _종속 권한(dependent privileges)_ 이라고 합니다. 첫 번째 사용자가 보유한 권한 또는 grant option이 취소되면, `CASCADE`가 지정된 경우 모든 종속 권한도 함께 취소됩니다. `CASCADE` 옵션이 없으면 취소 작업은 실패합니다. 이 재귀적 취소는 이 `REVOKE` 명령의 대상까지 추적 가능한 사용자 체인을 통해 부여된 권한에만 영향을 미칩니다. 영향을 받는 사용자는 다른 사용자를 통해서도 권한을 부여받은 경우 그 권한을 유지할 수 있습니다.

##### 참고 (Note)

`CASCADE` 옵션은 Oracle 데이터베이스와 호환되지 않습니다. 기본적으로 Oracle은 항상 종속 권한을 연쇄적으로(cascade) 취소합니다. EDB Postgres Advanced Server에서는 `REVOKE` 명령이 성공하려면 `CASCADE` 키워드가 필요합니다.

롤의 멤버십을 취소할 때는 `GRANT OPTION`을 `ADMIN OPTION`이라고 부릅니다. 동작은 유사합니다.

## 참고 (Notes)

사용자는 자신이 직접 부여한 권한만 취소할 수 있습니다. 예를 들어, 사용자 A가 grant option과 함께 권한을 사용자 B에게 부여하고, 사용자 B가 이를 사용자 C에게 부여한 경우, 사용자 A는 C로부터 권한을 직접 취소할 수 없습니다. 대신 사용자 A는 사용자 B로부터 grant option을 취소하고 `CASCADE` 옵션을 사용하여 사용자 C로부터 권한을 취소할 수 있습니다. 또 다른 예로, A와 B 둘 다 동일한 권한을 `C`에게 부여한 경우, A는 자신의 부여는 취소할 수 있지만 B의 부여는 취소할 수 없습니다. C는 여전히 그 권한을 가지고 있습니다.

객체의 소유자가 아닌 사용자가 해당 객체에 대한 권한을 취소하려고 시도할 때, 사용자가 객체에 대한 권한을 가지고 있지 않으면 명령이 실패합니다. 일부 권한이라도 사용 가능한 경우 명령은 진행되지만, 사용자가 grant option을 가진 권한만 취소합니다. `REVOKE ALL PRIVILEGES` 형식은 grant option을 하나도 보유하지 않은 경우 경고 메시지를 발생시킵니다. 다른 형식은 명령에 지정된 권한 중 어느 하나에 대한 grant option을 보유하지 않은 경우 경고를 발생시킵니다. 원칙적으로 이러한 설명은 객체 소유자에게도 적용됩니다. 그러나 소유자는 항상 모든 grant option을 보유한 것으로 취급되므로 이러한 경우는 결코 발생할 수 없습니다.

슈퍼유저가 `GRANT` 또는 `REVOKE` 명령을 실행하면, 해당 명령은 영향을 받는 객체의 소유자가 실행한 것처럼 수행됩니다. 모든 권한은 궁극적으로 객체 소유자로부터 나오므로(grant option 체인을 통해 간접적으로일 수도 있음), 슈퍼유저는 모든 권한을 취소할 수 있습니다. 이를 위해 `CASCADE` 사용이 필요할 수 있습니다.

영향을 받는 객체의 소유자가 아닌 롤도 `REVOKE`를 사용할 수 있습니다. 그 롤은 객체를 소유한 롤의 멤버이거나, 객체에 대해 `WITH GRANT OPTION` 권한을 보유한 롤의 멤버여야 합니다. 이 경우 명령은 객체를 소유하거나 `WITH GRANT OPTION` 권한을 보유한 상위 롤이 실행한 것처럼 수행됩니다. 예를 들어, 테이블 t1이 롤 g1에 의해 소유되고 롤 u1이 g1의 멤버인 경우, u1은 g1에 의해 부여된 것으로 기록된 t1에 대한 권한을 취소할 수 있습니다. 여기에는 u1이 부여한 것뿐만 아니라 롤 g1의 다른 멤버가 부여한 것도 포함됩니다.

`REVOKE`를 실행하는 롤이 둘 이상의 롤 멤버십 경로를 통해 간접적으로 권한을 보유한 경우, 명령을 수행하는 상위 롤은 지정되지 않습니다. 이러한 경우 `REVOKE`를 수행할 특정 롤이 되기 위해 `SET ROLE`을 사용하는 것이 모범 사례입니다. 그렇지 않으면 의도한 것과 다른 권한을 취소하거나 아무것도 취소하지 못할 수 있습니다.

##### 참고 (Note)

EDB Postgres Advanced Server의 `ALTER ROLE` 명령은 공용 또는 사설 데이터베이스 링크를 생성하는 데 필요한 시스템 권한 또는 세분화된 접근 제어 정책(`DBMS_RLS`)으로부터의 면제를 취소하는 구문도 지원합니다. `ALTER ROLE` 구문은 기능적으로 각각의 `REVOKE` 명령과 동등하며 Oracle 데이터베이스와 호환됩니다.

## 예제 (Examples)

`emp` 테이블에 대한 public의 insert 권한을 취소합니다:

```sql
REVOKE INSERT ON emp FROM PUBLIC;
```

`salesemp` 뷰에 대한 사용자 `mary`의 모든 권한을 취소합니다. 이는 실제로 "내가 부여한 모든 권한을 취소한다"는 의미입니다.

```sql
REVOKE ALL PRIVILEGES ON salesemp FROM mary;
```

`test1` 디렉터리에 대한 사용자 `betty`의 write 권한을 취소합니다.

```sql
REVOKE WRITE ON test1 FROM betty;
```

사용자 `joe`로부터 롤 `admins`의 멤버십을 취소합니다:

```sql
REVOKE admins FROM joe;
```

사용자 `joe`로부터 `CONNECT` 권한을 취소합니다:

```sql
REVOKE CONNECT FROM joe;
```

사용자 `joe`로부터 `CREATE DATABASE LINK` 권한을 취소합니다:

```sql
REVOKE CREATE DATABASE LINK FROM joe;
```

사용자 `joe`로부터 `EXEMPT ACCESS POLICY` 권한을 취소합니다:

```sql
REVOKE EXEMPT ACCESS POLICY FROM joe;
```
