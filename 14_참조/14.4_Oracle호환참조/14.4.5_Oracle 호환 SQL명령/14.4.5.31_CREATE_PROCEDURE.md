# CREATE PROCEDURE — EPAS 18 Reference

> 원문: [EPAS v18 — Reference › Oracle 호환 › 호환 SQL 명령 › CREATE PROCEDURE](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/28_create_procedure/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·코드 이름은 원문 그대로 보존했습니다.

## 이름 (Name)

`CREATE PROCEDURE` — 새로운 저장 프로시저(stored procedure)를 정의합니다.

## 구문 개요 (Synopsis)

```sql
CREATE [OR REPLACE] PROCEDURE <name> [ (<parameters>) ]
   [
          IMMUTABLE
        | STABLE
        | VOLATILE
        | DETERMINISTIC
        | [ NOT ] LEAKPROOF
        | CALLED ON NULL INPUT
        | RETURNS NULL ON NULL INPUT
        | STRICT
        | [ EXTERNAL ] SECURITY INVOKER
        | [ EXTERNAL ] SECURITY DEFINER
        | AUTHID DEFINER
        | AUTHID CURRENT_USER
        | PARALLEL { UNSAFE | RESTRICTED | SAFE }
        | COST <execution_cost>
        | ROWS <result_rows>
        | SET <configuration_parameter>
          { TO <value> | = <value> | FROM CURRENT }
   ...]
{ IS | AS }
    [ PRAGMA AUTONOMOUS_TRANSACTION; ]
    [ <declarations> ]
  BEGIN
    <statements>
  END [ <name> ];
```

## 설명 (Description)

`CREATE PROCEDURE`는 새로운 저장 프로시저를 정의합니다. `CREATE OR REPLACE PROCEDURE`는 새 프로시저를 생성하거나 기존 정의를 대체합니다.

스키마 이름을 포함하면 프로시저는 지정된 스키마에 생성됩니다. 그렇지 않으면 현재 스키마에 생성됩니다. 새 프로시저의 이름은 동일한 스키마에서 동일한 입력 인수 타입을 갖는 기존 프로시저와 일치할 수 없습니다. 그러나 입력 인수 타입이 다른 프로시저는 이름을 공유할 수 있습니다. 이를 _오버로딩(overloading)_ 이라고 합니다.

##### 참고 (Note)

프로시저 오버로딩은 EDB Postgres Advanced Server 기능입니다. 저장된 독립형(standalone) 프로시저의 오버로딩은 Oracle 데이터베이스와 호환되지 않습니다.

기존 프로시저의 정의를 업데이트하려면 `CREATE OR REPLACE PROCEDURE`를 사용합니다. 이 방법으로는 프로시저의 이름이나 인수 타입을 변경할 수 없습니다. 그 구문은 새롭고 별개의 프로시저를 생성합니다. `OUT` 파라미터를 사용할 때는 프로시저를 삭제하지 않고서는 `OUT` 파라미터의 타입을 변경할 수 없습니다.

## 파라미터 (Parameters)

`name`

프로시저의 식별자입니다.

`parameters`

정형 파라미터(formal parameter) 목록입니다.

`declarations`

변수, 커서, 타입 또는 서브프로그램 선언입니다. 서브프로그램 선언을 포함하는 경우, 다른 모든 변수, 커서, 타입 선언 뒤에 선언합니다.

`statements`

SPL 프로그램 문입니다. `BEGIN - END` 블록은 `EXCEPTION` 섹션을 포함할 수 있습니다.

`IMMUTABLE`

`STABLE`

`VOLATILE`

이 속성들은 쿼리 옵티마이저에 프로시저의 동작에 대한 정보를 제공합니다. 이 속성 중 하나만 지정할 수 있습니다.

- `IMMUTABLE`을 사용하면 프로시저가 데이터베이스를 수정할 수 없으며 동일한 인수 값이 주어졌을 때 항상 동일한 결과에 도달함을 나타냅니다. 데이터베이스 조회를 수행하지 않으며 인수 목록에 직접 존재하는 정보만 사용합니다. 이 절을 포함하면, 모두 상수 인수로 이루어진 프로시저 호출을 프로시저 값으로 즉시 대체할 수 있습니다.

- `STABLE`을 사용하면 프로시저가 데이터베이스를 수정할 수 없으며 단일 테이블 스캔 내에서 동일한 인수 값에 대해 일관되게 동일한 결과를 반환함을 나타냅니다. 그러나 그 결과는 SQL 문 간에 변경될 수 있습니다. 데이터베이스 조회, 파라미터 변수(예: 현재 시간대) 등에 의존하는 프로시저에 이 선택을 사용합니다.

- `VOLATILE`(기본값)을 사용하면 프로시저 값이 단일 테이블 스캔 내에서도 변경될 수 있어 최적화를 수행할 수 없음을 나타냅니다. 호출이 최적화로 제거되는 것을 방지하기 위해, 결과가 예측 가능하더라도 부작용(side effect)이 있는 함수는 volatile로 분류해야 합니다.


`DETERMINISTIC`

`DETERMINISTIC`은 `IMMUTABLE`의 동의어입니다. `DETERMINISTIC` 프로시저는 데이터베이스를 수정할 수 없으며 동일한 인수 값이 주어졌을 때 항상 동일한 결과에 도달합니다. 데이터베이스 조회를 수행하지 않으며 인수 목록에 직접 존재하는 정보만 사용합니다. 이 절을 포함하면, 모두 상수 인수로 이루어진 프로시저 호출을 프로시저 값으로 즉시 대체할 수 있습니다.

`[ NOT ] LEAKPROOF`

`LEAKPROOF` 프로시저는 부작용이 없으며 프로시저를 호출하는 데 사용된 값에 대한 정보를 드러내지 않습니다.

`CALLED ON NULL INPUT`

`RETURNS NULL ON NULL INPUT`

`STRICT`

- `CALLED ON NULL INPUT`(기본값)을 사용하면 일부 인수가 `NULL`일 때 프로시저를 정상적으로 호출합니다. 필요한 경우 `NULL` 값을 확인하고 적절하게 대응합니다.

- `RETURNS NULL ON NULL INPUT` 또는 `STRICT`를 사용하면 인수 중 하나라도 `NULL`일 때 프로시저가 항상 `NULL`을 반환함을 나타냅니다. 이 절을 지정하면 `NULL` 인수가 있을 때 프로시저가 실행되지 않습니다. 대신 `NULL` 결과가 가정됩니다.


`[ EXTERNAL ] SECURITY DEFINER`

프로시저가 그것을 생성한 사용자의 권한으로 실행되도록 지정하려면 `SECURITY DEFINER`(기본값)를 사용합니다. 키워드 `EXTERNAL`은 SQL 준수를 위해 허용되지만 선택 사항입니다.

`[ EXTERNAL ] SECURITY INVOKER`

프로시저를 호출하는 사용자의 권한으로 프로시저를 실행하려면 `SECURITY INVOKER` 절을 사용합니다. 키워드 `EXTERNAL`은 SQL 준수를 위해 허용되지만 선택 사항입니다.

`AUTHID DEFINER`

`AUTHID CURRENT_USER`

- `AUTHID DEFINER` 절은 `[EXTERNAL] SECURITY DEFINER`의 동의어입니다. `AUTHID` 절을 생략하거나 `AUTHID DEFINER`를 지정하면, 프로시저 소유자의 권한이 데이터베이스 객체에 대한 접근 권한을 결정합니다.

- `AUTHID CURRENT_USER` 절은 `[EXTERNAL] SECURITY INVOKER`의 동의어입니다. `AUTHID CURRENT_USER`를 지정하면, 프로시저를 실행하는 현재 사용자의 권한이 접근 권한을 결정합니다.


`PARALLEL { UNSAFE | RESTRICTED | SAFE }`

`PARALLEL` 절은 병렬 순차 스캔(병렬 모드)의 사용을 활성화합니다. 병렬 순차 스캔은 직렬 순차 스캔과 대조적으로, 쿼리 중에 여러 워커(worker)를 사용하여 릴레이션을 병렬로 스캔합니다.

- `UNSAFE`(기본값)로 설정되면 프로시저는 병렬 모드에서 실행할 수 없습니다. 이러한 프로시저가 존재하면 직렬 실행 계획이 강제됩니다.

- `RESTRICTED`로 설정되면 프로시저는 병렬 모드에서 실행할 수 있지만, 실행은 병렬 그룹 리더로 제한됩니다. 특정 릴레이션에 대한 조건(qualification)에 병렬 제한(parallel restricted) 요소가 있으면 해당 릴레이션은 병렬 처리 대상으로 선택되지 않습니다.

- `SAFE`로 설정되면 프로시저는 제한 없이 병렬 모드에서 실행할 수 있습니다.


`COST execution_cost`

`execution_cost`는 `cpu_operator_cost` 단위로 프로시저의 예상 실행 비용을 나타내는 양수입니다. 프로시저가 집합(set)을 반환하는 경우, 이는 반환되는 행당 비용입니다. 값이 클수록 플래너가 필요 이상으로 자주 함수를 평가하는 것을 피하려고 합니다.

`ROWS result_rows`

`result_rows`는 플래너가 프로시저가 반환할 것으로 예상하는 행 수를 나타내는 양수입니다. 이 옵션은 프로시저가 집합을 반환하도록 선언된 경우에만 허용됩니다. 기본값은 1000개 행입니다.

`SET configuration_parameter { TO value | = value | FROM CURRENT }`

`SET` 절은 프로시저에 진입할 때 지정된 구성 파라미터를 지정된 값으로 설정하고, 프로시저가 종료될 때 이전 값으로 복원되도록 합니다. `SET FROM CURRENT`는 프로시저에 진입할 때 적용할 값으로 세션의 현재 파라미터 값을 저장합니다.

`SET` 절이 프로시저에 연결되어 있으면, 프로시저 내부에서 동일한 변수에 대해 실행된 `SET LOCAL` 명령의 효과가 프로시저로 제한됩니다. 구성 파라미터의 이전 값은 프로시저 종료 시 복원됩니다. 일반 `SET` 명령(`LOCAL` 없이)은 이전의 `SET LOCAL` 명령과 유사하게 `SET` 절을 재정의합니다. 그러한 명령의 효과는 현재 트랜잭션이 롤백되지 않는 한 프로시저 종료 후에도 지속됩니다.

`PRAGMA AUTONOMOUS_TRANSACTION`

`PRAGMA AUTONOMOUS_TRANSACTION`은 프로시저를 자율 트랜잭션(autonomous transaction)으로 설정하는 지시문입니다.

##### 참고 (Note)

- `STRICT`, `LEAKPROOF`, `PARALLEL`, `COST`, `ROWS`, `SET` 키워드는 EDB Postgres Advanced Server를 위한 확장 기능을 제공하며 Oracle에서는 지원되지 않습니다.
- `IMMUTABLE`, `STABLE`, `STRICT`, `LEAKPROOF`, `COST`, `ROWS`, `PARALLEL { UNSAFE | RESTRICTED | SAFE }` 속성은 EDB SPL 프로시저에서만 지원됩니다.
- 기본적으로 저장 프로시저는 `SECURITY DEFINERS`로 생성됩니다. plpgsql로 정의된 저장 프로시저는 `SECURITY INVOKERS`로 생성됩니다.

## 예제 (Examples)

이 프로시저는 `emp` 테이블의 직원을 나열합니다:

```sql
CREATE OR REPLACE PROCEDURE list_emp
IS
    v_empno         NUMBER(4);
    v_ename         VARCHAR2(10);
    CURSOR emp_cur IS
        SELECT empno, ename FROM emp ORDER BY empno;
BEGIN
    OPEN emp_cur;
    DBMS_OUTPUT.PUT_LINE('EMPNO    ENAME');
    DBMS_OUTPUT.PUT_LINE('-----    -------');
    LOOP
        FETCH emp_cur INTO v_empno, v_ename;
        EXIT WHEN emp_cur%NOTFOUND;
        DBMS_OUTPUT.PUT_LINE(v_empno || '     ' || v_ename);
    END LOOP;
    CLOSE emp_cur;
END;

EXEC list_emp;
```

출력

```text
EMPNO    ENAME
-----    -------
7369     SMITH
7499     ALLEN
7521     WARD
7566     JONES
7654     MARTIN
7698     BLAKE
7782     CLARK
7788     SCOTT
7839     KING
7844     TURNER
7876     ADAMS
7900     JAMES
7902     FORD
7934     MILLER
```

이 프로시저는 `IN OUT` 및 `OUT` 인수를 사용하여, 주어진 직원 번호를 사용한 검색을 기반으로 직원의 번호, 이름, 직무를 반환합니다. 찾지 못하면 주어진 이름을 사용하여 검색합니다. 익명 블록이 이 프로시저를 호출합니다.

```sql
CREATE OR REPLACE PROCEDURE emp_job (
    p_empno         IN OUT emp.empno%TYPE,
    p_ename         IN OUT emp.ename%TYPE,
    p_job           OUT    emp.job%TYPE
)
IS
    v_empno         emp.empno%TYPE;
    v_ename         emp.ename%TYPE;
    v_job           emp.job%TYPE;
BEGIN
    SELECT ename, job INTO v_ename, v_job FROM emp WHERE empno = p_empno;
    p_ename := v_ename;
    p_job   := v_job;
    DBMS_OUTPUT.PUT_LINE('Found employee # ' || p_empno);
EXCEPTION
    WHEN NO_DATA_FOUND THEN
        BEGIN
            SELECT empno, job INTO v_empno, v_job FROM emp
                WHERE ename = p_ename;
            p_empno := v_empno;
            p_job   := v_job;
            DBMS_OUTPUT.PUT_LINE('Found employee ' || p_ename);
        EXCEPTION
            WHEN NO_DATA_FOUND THEN
                DBMS_OUTPUT.PUT_LINE('Could not find an employee with ' ||
                    'number, ' || p_empno || ' nor name, '  || p_ename);
                p_empno := NULL;
                p_ename := NULL;
                p_job   := NULL;
        END;
END;

DECLARE
    v_empno      emp.empno%TYPE;
    v_ename      emp.ename%TYPE;
    v_job        emp.job%TYPE;
BEGIN
    v_empno := 0;
    v_ename := 'CLARK';
    emp_job(v_empno, v_ename, v_job);
    DBMS_OUTPUT.PUT_LINE('Employee No: ' || v_empno);
    DBMS_OUTPUT.PUT_LINE('Name       : ' || v_ename);
    DBMS_OUTPUT.PUT_LINE('Job        : ' || v_job);
END;
```

출력

```text
Found employee CLARK
Employee No: 7782
Name       : CLARK
Job        : MANAGER
```

이 예제는 프로시저 선언에서 `AUTHID DEFINER` 및 `SET` 절을 사용합니다. `update_salary` 프로시저는 프로시저가 실행되는 동안 프로시저를 정의한 롤의 권한을 프로시저를 호출하는 롤에 전달합니다.

```sql
CREATE OR REPLACE PROCEDURE update_salary(id INT, new_salary NUMBER)
  SET SEARCH_PATH = 'public' SET WORK_MEM = '1MB'
  AUTHID DEFINER IS
BEGIN
  UPDATE emp SET salary = new_salary WHERE emp_id = id;
END;
```

`SET` 절을 포함하여 프로시저의 검색 경로(search path)를 `public`으로, 작업 메모리(work memory)를 `1MB`로 설정합니다. 다른 프로시저, 함수, 객체는 이러한 설정의 영향을 받지 않습니다.

이 예제에서 `AUTHID DEFINER` 절은 그렇지 않으면 프로시저의 문을 실행할 수 없을 수도 있는 롤에 일시적으로 권한을 부여합니다. 프로시저를 호출하는 롤과 연결된 권한을 사용하려면, `AUTHID DEFINER` 절을 `AUTHID CURRENT_USER` 절로 대체합니다.
