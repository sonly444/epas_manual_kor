# CREATE PUBLIC DATABASE LINK — EPAS 18 Reference

> 원문: [EPAS v18 — Reference › Oracle 호환 › 호환 SQL 명령 › CREATE PUBLIC DATABASE LINK](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/21_create_public_database_link/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·코드 이름은 원문 그대로 보존했습니다.

## 이름 (Name)

`CREATE [PUBLIC] DATABASE LINK` — 데이터베이스 링크를 생성합니다.

## 구문 개요 (Synopsis)

```sql
CREATE [ PUBLIC ] DATABASE LINK <name>
  CONNECT TO { CURRENT_USER |
               <username> IDENTIFIED BY '<password>'}
  USING { postgres_fdw '<fdw_connection_string>' |
        [ oci ] '<oracle_connection_string>' }
```

## 설명 (Description)

`CREATE DATABASE LINK`는 데이터베이스 링크를 생성합니다. 데이터베이스 링크는 `DELETE`, `INSERT`, `SELECT`, `UPDATE` 명령에서 원격 데이터베이스의 테이블이나 뷰를 참조할 수 있게 해주는 객체입니다. 데이터베이스 링크는 SQL 명령에서 참조하는 테이블이나 뷰 이름 뒤에 `@dblink`를 붙여 참조하며, 여기서 `dblink`는 데이터베이스 링크의 이름입니다.

데이터베이스 링크는 _public(공개)_ 또는 _private(비공개)_ 일 수 있습니다. 공개 데이터베이스 링크는 모든 사용자가 사용할 수 있는 링크입니다. 비공개 데이터베이스 링크는 해당 데이터베이스 링크의 소유자만 사용할 수 있습니다. 공개 데이터베이스 링크를 생성하려면 `PUBLIC` 옵션을 지정합니다. 그렇지 않으면 비공개 데이터베이스 링크가 생성됩니다.

`CREATE DATABASE LINK` 명령을 사용하면 데이터베이스 링크 이름과 주어진 연결 속성이 `pg_catalog.edb_dblink`라는 이름의 EDB Postgres Advanced Server 시스템 테이블에 저장됩니다. 주어진 데이터베이스 링크를 사용할 때, 이 데이터베이스 링크를 정의하는 `edb_dblink` 항목을 포함하는 데이터베이스를 _로컬 데이터베이스(local database)_ 라고 합니다. `edb_dblink` 항목에 연결 속성이 정의된 서버 및 데이터베이스를 _원격 데이터베이스(remote database)_ 라고 합니다. `edb_dblink_oci`를 사용하면 `SELECT`, `INSERT`, `UPDATE`, `DELETE` 문을 통해 원격 Oracle 테이블 및 뷰에 접근할 수 있습니다.

데이터베이스 링크에 대한 참조를 포함하는 SQL 명령을 실행할 때는 로컬 데이터베이스에 연결되어 있어야 합니다. SQL 명령이 실행되면 `@dblink` 참조가 붙은 테이블이나 뷰에 접근하기 위해 원격 데이터베이스에 대한 적절한 인증 및 연결이 이루어집니다.

##### 참고 (Note) — Oracle 호환성 (Oracle compatibility)

- EDB Postgres Advanced Server 17의 경우, CREATE DATABASE LINK 명령은 Oracle 버전 10g Release 2, 11g Release 2, 12c Release 1, 18c Release 1, 19c, 21c, 23과 함께 사용하기 위해 모든 마이너 버전에 대해 테스트 및 인증되었습니다.

##### 참고 (Note)

- 데이터베이스 링크를 사용하여 스탠바이 데이터베이스 서버의 원격 데이터베이스에 접근할 수는 없습니다. 스탠바이 데이터베이스 서버는 고가용성, 부하 분산, 복제를 위한 것입니다.

Postgres 데이터베이스 서버의 고가용성, 부하 분산, 복제에 대한 정보는 [PostgreSQL 핵심 문서](https://www.postgresql.org/docs/current/static/high-availability.html)를 참조하세요.

- `edb_dblink_oci.rescans` GUC를 `postgresql.conf` 파일에서 서버 수준으로 `SCROLL` 또는 `SERIALIZABLE`로 설정할 수 있습니다. `SET` 명령을 사용하여 세션 수준에서도 설정할 수 있습니다. 그러나 dblink 연결 캐싱으로 인해 기존 dblink 연결에는 이 설정이 적용되지 않습니다.

- 4000자를 초과하는 LOB 데이터에 대해 `SELECT`를 실행할 때는, 임시 PGA 메모리를 확보하고 `PGA_AGGREGATE_LIMIT`를 초과하는 것을 피하기 위해 `edb_dblink_oci.rescans=serializable`을 사용하는 것을 권장합니다.


`edb_dblink_oci`는 `SCROLL`과 `SERIALIZABLE` 두 가지 유형의 rescan을 모두 지원합니다. 기본값은 `SERIALIZABLE`로 설정되어 있습니다. `SERIALIZABLE`로 설정되면 `edb_dblink_oci`는 Oracle 측에서 `SERIALIZABLE` 트랜잭션 격리 수준을 사용하며, 이는 PostgreSQL의 `REPEATABLE READ`에 해당합니다. 단일 PostgreSQL 문이 여러 개의 Oracle 쿼리로 이어질 수 있으므로 이것이 필요합니다. 따라서 일관된 결과를 제공하기 위해 직렬화 가능(serializable) 격리 수준을 사용합니다.

`ADD`, `UPDATE`, `DELETE` 문과 같은 장시간 실행되는 DML 트랜잭션과 동시에 테이블을 수정할 때 직렬화 실패가 발생할 수 있습니다. 이러한 실패가 발생하면 OCI는 `ORA-08177: can't serialize access for this transaction`을 보고하며, 애플리케이션은 트랜잭션을 재시도해야 합니다.

`SCROLL` rescan은 빠르지만, 각 반복마다 현재 행 위치가 `1`로 재설정됩니다. `SERIALIZABLE` rescan은 `SCROLL` rescan보다 성능상 이점이 있습니다.

## 파라미터 (Parameters)

`PUBLIC`

모든 사용자가 사용할 수 있는 공개 데이터베이스 링크를 생성합니다. 이 파라미터를 생략하면 데이터베이스 링크는 비공개가 되며, 해당 데이터베이스 링크의 소유자만 사용할 수 있습니다.

`name`

데이터베이스 링크의 이름입니다.

`username`

원격 데이터베이스에 연결하는 데 사용할 사용자 이름입니다.

`CURRENT_USER`

원격 서버에 연결을 설정할 때 링크를 사용하는 롤과 연결된 사용자 매핑을 사용하려면 `CURRENT_USER`를 포함합니다.

`password`

`username`의 비밀번호입니다.

`postgres_fdw`

원격 EDB Postgres Advanced Server 데이터베이스에 대한 연결로 외부 데이터 래퍼(foreign data wrapper) `postgres_fdw`를 지정합니다. 데이터베이스에 `postgres_fdw`가 설치되어 있지 않은 경우, `CREATE EXTENSION` 명령을 사용하여 `postgres_fdw`를 설치합니다. 자세한 내용은 [PostgreSQL 핵심 문서](https://www.postgresql.org/docs/current/static/sql-createextension.html)의 `CREATE EXTENSION` 명령을 참조하세요.

`fdw_connection_string`

`postgres_fdw` 외부 데이터 래퍼에 대한 연결 정보를 지정합니다.

`oci`

원격 Oracle 데이터베이스에 대한 연결을 지정합니다. 이것이 기본 동작입니다.

`oracle_connection_string`

oci 연결에 대한 연결 정보를 지정합니다.

##### 참고 (Note)

비공개 데이터베이스 링크를 생성하려면 `CREATE DATABASE LINK` 권한이 필요합니다. 공개 데이터베이스 링크를 생성하려면 `CREATE PUBLIC DATABASE LINK` 권한이 필요합니다.

## OCI 데이터베이스 링크를 위한 Oracle instant client 설정 (Setting up an Oracle instant client for OCI database link)

`edb_dblink_oci`를 사용하려면 데이터베이스 링크를 생성하려는 EDB Postgres Advanced Server 데이터베이스를 실행하는 호스트에 Oracle instant client를 다운로드하여 설치해야 합니다.

instant client는 [여기](http://www.oracle.com/technetwork/database/features/instant-client/index-097480.html)에서 다운로드할 수 있습니다.

### Linux용 Oracle instant client (Oracle instant client for Linux)

다음 지침은 EDB Postgres Advanced Server를 실행하는 Linux 호스트에 적용됩니다.

EDB Postgres Advanced Server를 실행하는 Linux 호스트에 `libaio` 라이브러리(Linux 네이티브 비동기 I/O 기능)가 설치되어 있는지 확인하세요.

다음 명령으로 `libaio` 라이브러리를 설치할 수 있습니다:

```shell
yum install libaio
```

다운로드한 Oracle instant client에 버전 번호 접미사가 없는 `libclntsh.so` 파일이 포함되어 있지 않은 경우, 다운로드한 버전의 라이브러리 파일을 가리키는 `libclntsh.so`라는 이름의 심볼릭 링크를 생성합니다. 이를 위해 instant client 디렉터리로 이동하여 다음 명령을 실행합니다:

```shell
ln -s libclntsh.so.<version> libclntsh.so
```

여기서 `version`은 `libclntsh.so` 라이브러리의 버전 번호입니다. 예:

```shell
ln -s libclntsh.so.12.1 libclntsh.so
```

원격 Oracle 데이터베이스로의 데이터베이스 링크를 참조하는 SQL 명령을 실행할 때, EDB Postgres Advanced Server는 EDB Postgres Advanced Server 호스트에서 Oracle instant client 라이브러리가 어디에 있는지 알아야 합니다.

`LD_LIBRARY_PATH` 환경 변수는 `libclntsh.so` 파일을 포함하는 Oracle 클라이언트 설치 디렉터리로의 경로를 포함해야 합니다. 예를 들어, `libclntsh.so`를 포함하는 설치 디렉터리가 `/tmp/instantclient`인 경우 다음을 사용합니다:

```shell
export LD_LIBRARY_PATH=/tmp/instantclient:$LD_LIBRARY_PATH
```

또는 `postgresql.conf` 파일에서 `oracle_home` 구성 파라미터 값을 설정할 수 있습니다. `oracle_home` 구성 파라미터는 `LD_LIBRARY_PATH` 환경 변수의 대안입니다. `oracle_home` 구성 파라미터에 대한 자세한 내용은 [구성 파라미터](https://www.enterprisedb.com/docs/epas/latest/reference/database_administrator_reference/01_introduction/05_oracle_home/)를 참조하세요.

`ORACLE_HOME` 환경 변수를 설정해야 하며 Oracle home 디렉터리로의 경로를 포함해야 합니다. 예:

```text
export ORACLE_HOME=/opt/product/version/dbhomeXE
```

##### 참고 (Note)

EDB Postgres Advanced Server를 시작하거나 재시작하기 위해 `pg_ctl` 유틸리티를 실행하기 전에 `LD_LIBRARY_PATH` 또는 `oracle_home` 구성 파라미터 중 하나와 `ORACLE_HOME` 환경 변수를 설정해야 합니다.

`pg_ctl`을 직접 호출하여 EDB Postgres Advanced Server를 시작하거나 재시작하는 사용자 계정(예: `enterprisedb`)으로 현재 세션을 실행하는 경우, `pg_ctl`을 호출하기 전에 `LD_LIBRARY_PATH` 환경 변수 또는 `oracle_home` 구성 파라미터와 `ORACLE_HOME` 환경 변수를 설정하세요.

`enterprisedb` 사용자 계정의 홈 디렉터리 아래에 있는 `.bash_profile` 파일에서 `LD_LIBRARY_PATH`와 `ORACLE_HOME` 환경 변수를 설정할 수 있습니다. 즉, `~enterprisedb/.bash_profile` 파일에서 `LD_LIBRARY_PATH`와 `ORACLE_HOME`을 설정합니다. 이 설정은 `enterprisedb`로 로그인할 때 `LD_LIBRARY_PATH`와 `ORACLE_HOME`이 설정되도록 보장합니다.

`systemctl` 또는 `service` 명령과 함께 Linux 서비스 스크립트를 사용하여 EDB Postgres Advanced Server를 시작하거나 재시작하는 경우, 스크립트가 `pg_ctl` 유틸리티를 호출할 때 유효하도록 `LD_LIBRARY_PATH`와 `ORACLE_HOME`을 설정해야 합니다.

예를 들어, EDB Postgres Advanced Server에 대한 환경 변수를 설정하려면 `/etc/systemd/system/edb-as-14.service`라는 파일을 생성할 수 있습니다. 파일에 `/lib/systemd/system/edb-as-14.service`를 포함합니다.

`LD_LIBRARY_PATH=/tmp/instantclient`인 경우, 다음과 같이 지정하여 환경 변수를 포함합니다:

```shell
[Service]
Environment=LD_LIBRARY_PATH=/tmp/instantclient:$LD_LIBRARY_PATH
Environment=ORACLE_HOME=/tmp/instantclient
```

systemd를 다시 로드합니다:

```shell
systemctl daemon-reload
```

EDB Postgres Advanced Server 서비스를 재시작합니다:

```shell
systemctl restart edb-as-14
```

`LD_LIBRARY_PATH` 설정을 포함하기 위해 수정해야 하는 스크립트 파일은 EDB Postgres Advanced Server 버전과 설치된 Linux 시스템에 따라 다릅니다.

### Windows용 Oracle instant client (Oracle instant client for Windows)

다음 지침은 EDB Postgres Advanced Server를 실행하는 Windows 호스트에 적용됩니다.

원격 Oracle 데이터베이스로의 데이터베이스 링크를 참조하는 SQL 명령을 실행할 때, EDB Postgres Advanced Server는 EDB Postgres Advanced Server 호스트에서 Oracle instant client 라이브러리가 어디에 있는지 알아야 합니다.

`oci.dll` 파일을 포함하는 Oracle 클라이언트 설치 디렉터리를 포함하도록 Windows `PATH` 시스템 환경 변수를 설정합니다.

또는 `postgresql.conf` 파일에서 `oracle_home` 구성 파라미터 값을 설정할 수 있습니다. `oracle_home` 구성 파라미터에 지정된 값은 Windows `PATH` 환경 변수를 재정의합니다.

`postgresql.conf` 파일에서 `oracle_home` 구성 파라미터를 설정하려면 다음 줄을 추가합니다:

```ini
oracle_home = 'lib_directory'
```

`lib_directory`를 `oci.dll`을 포함하는 Windows 디렉터리 이름으로 대체합니다. 예:

```ini
oracle_home = 'C:/tmp/instantclient_10_2'
```

`PATH` 환경 변수 또는 `oracle_home` 구성 파라미터를 설정한 후, 변경 사항을 적용하려면 서버를 재시작해야 합니다. Windows 서비스 콘솔에서 서버를 재시작하세요.

##### 참고 (Note)

`tnsnames.ora`가 페일오버 모드로 구성되어 있고 client:server 장애가 발생하면, 클라이언트 연결은 보조 서버(일반적으로 백업 서버)와 설정됩니다. 이후 기본 서버가 재개되면, 클라이언트는 새 세션이 설정될 때까지 보조 서버와의 연결을 유지합니다. 새 클라이언트 연결은 기본 서버와 자동으로 설정됩니다. 기본 서버와 보조 서버가 동기화되지 않은 경우, 보조 서버에 연결을 설정한 클라이언트와 이후 기본 서버에 연결한 클라이언트가 서로 다른 데이터베이스 뷰를 볼 수 있습니다.

## 예제 (Examples)

### OCI 데이터베이스 링크 생성 (Creating an OCI database link)

이 예제는 `CREATE DATABASE LINK` 명령을 사용하여 `edb_dblink_oci` 연결을 통해 EDB Postgres Advanced Server 인스턴스를 Oracle 서버에 연결하는 `chicago`라는 이름의 데이터베이스 링크를 생성합니다. 연결 정보는 EDB Postgres Advanced Server가 비밀번호가 `mypassword`인 사용자 `admin`으로 Oracle에 로그인하도록 지시합니다. `oci` 옵션을 포함하면 EDB Postgres Advanced Server에 이것이 `edb_dblink_oci` 연결임을 알립니다. 연결 문자열 `'//127.0.0.1/acctg'`는 서버 주소와 데이터베이스 이름을 지정합니다.

```sql
CREATE DATABASE LINK chicago
  CONNECT TO admin IDENTIFIED BY 'mypassword'
  USING oci '//127.0.0.1/acctg';
```

##### 참고 (Note)

연결 문자열에서 IP 주소 대신 호스트 이름을 지정할 수 있습니다.

### postgres_fdw 데이터베이스 링크 생성 (Creating a postgres_fdw database link)

이 예제는 `CREATE DATABASE LINK` 명령을 사용하여 `bedford`라는 이름의 데이터베이스 링크를 생성합니다. 이 데이터베이스 링크는 `postgres_fdw` 외부 데이터 래퍼 연결을 통해 EDB Postgres Advanced Server 인스턴스를 다른 EDB Postgres Advanced Server 인스턴스에 연결합니다. 연결 정보는 EDB Postgres Advanced Server가 비밀번호 `mypassword`로 사용자 `admin`으로 로그인하도록 지시합니다. `postgres_fdw` 옵션을 포함하면 EDB Postgres Advanced Server에 이것이 `postgres_fdw` 연결임을 알립니다. 연결 문자열 `'host=127.0.0.1 port=5444 dbname=marketing'`은 서버 주소와 데이터베이스 이름을 지정합니다.

```sql
CREATE DATABASE LINK bedford
  CONNECT TO admin IDENTIFIED BY 'mypassword'
  USING postgres_fdw 'host=127.0.0.1 port=5444 dbname=marketing';
```

##### 참고 (Note)

연결 문자열에서 IP 주소 대신 호스트 이름을 지정할 수 있습니다.

### 데이터베이스 링크의 사용자 매핑 및 비밀번호 관리 (Managing user mappings and passwords for database links)

`OCI`(`dblink_ora` 사용) 또는 `postgres_fdw`를 사용하여 데이터베이스 링크를 생성하면, 원격 서버 연결의 비밀번호가 로컬 데이터베이스의 `pg_user_mapping` 시스템 테이블에 안전하게 저장됩니다. 안전하게 유지하기 위해 비밀번호는 난독화된 형식으로 저장되며 연결이 설정될 때 역난독화됩니다. 따라서 슈퍼유저조차도 읽을 수 없습니다.

이 난독화는 `USER MAPPING`이 생성된 로컬 Postgres 사용자 이름에 연결됩니다. 따라서 이 `user`만 변경/삭제하면(예: `ALTER USER MAPPING ... OPTIONS (set/drop user)` 사용) 해당 데이터베이스 링크에 대해 `pg_user_mapping`에 저장된 기존 난독화된 비밀번호가 무효화되어, 일관되지 않은 상태나 연결 실패가 발생할 수 있습니다.

문제를 방지하고 연결을 유지하기 위해, 기존 데이터베이스 링크와 연결된 사용자 이름을 변경해야 하는 경우:

- 사용자 이름만 변경하는 대신 사용자 이름과 비밀번호를 모두 변경합니다:


    ```sql
    ALTER USER MAPPING FOR edb SERVER oracle_server OPTIONS (set user 'new_user', set password 'new_password');
    ```

- 또는 기존 사용자 이름/비밀번호 조합을 삭제하고 새 사용자 이름/비밀번호 조합을 추가할 수 있습니다:


    ```sql
    ALTER USER MAPPING FOR edb SERVER oracle_server OPTIONS (DROP 'user'. DROP 'password');
    ALTER USER MAPPING FOR edb SERVER oracle_server OPTIONS (ADD USER 'new_user', ADD password 'new_password');
    ```

## OCI 데이터베이스 링크에 대한 푸시다운 (Push down for an OCI database link)

OCI 데이터베이스 링크를 사용하여 원격 Oracle 데이터베이스에서 SQL 문을 실행할 때, 때때로 외부 서버에서 처리의 _푸시다운(pushdown)_ 이 발생합니다.

푸시다운은 SQL 문이 실행된 로컬 클라이언트 대신 외부, 즉 원격 서버에서 처리가 발생하는 것을 의미합니다. 데이터가 로컬 클라이언트로 반환되기 전에 원격 서버에서 처리되므로 푸시다운은 성능 향상을 가져올 수 있습니다.

OCI 데이터베이스 링크는 다음에 대한 푸시다운을 지원합니다:

- WHERE 절
- JOIN 연산
- AGGREGATE 함수
- ORDER BY 절

푸시다운이 발생하려면 몇 가지 기본 조건이 충족되어야 합니다. 조인 연산에 관련된 테이블은 동일한 외부 서버에 속해야 하며 외부 서버에 대해 동일한 연결 정보를 사용해야 합니다. 이 연결 정보는 `CREATE DATABASE LINK` 명령으로 정의된 동일한 데이터베이스 링크입니다.

SQL 문에 푸시다운을 사용할지 여부를 확인하려면 `EXPLAIN` 명령을 사용하여 실행 계획을 표시하세요. `EXPLAIN` 명령에 대한 정보는 [PostgreSQL 핵심 문서](https://www.postgresql.org/docs/current/static/sql-explain.html)를 참조하세요.

`edb_dbLink_oci_pushdown.config` 구성 파일을 사용하여 푸시다운을 제한할 수 있습니다. 이 파일에서 원격 서버로 푸시다운할 수 있는 함수 및 연산자 목록을 정의할 수 있습니다. 요구 사항에 따라 목록을 쉽게 추가하거나 수정할 수 있습니다.

이 파일은 원격 서버로 푸시다운이 허용되는 집계(aggregate), 함수(function), 연산자(operator)로 객체를 나열합니다. 각 항목을 한 줄에 배치합니다. 각 항목에는 두 개의 열이 있어야 합니다:

- ROUTINE(함수, 집계, 프로시저) 또는 OPERATOR일 수 있는 객체 유형.
- 두 번째 열은 인수와 함께 스키마로 한정된 객체 이름입니다.

다음 쿼리를 사용하여 두 번째 열의 형식을 지정할 수 있습니다:

ROUTINE의 경우:

```sql
SELECT pronamespace::regnamespace || '.' || oid::regprocedure FROM pg_proc
WHERE proname = '<routine_name>'
```

OPERATOR의 경우:

```sql
SELECT oprnamespace::regnamespace || '.' || oid::regoperator FROM pg_operator
WHERE oprname = '<operator_name>'
```

`edb_dbLink_oci_pushdown.config` 파일 예:

```shell
ROUTINE pg_catalog.sum(bigint)
ROUTINE pg_catalog.sum(smallint)
ROUTINE pg_catalog.to_number(text)
ROUTINE pg_catalog.to_number(text,text)
OPERATOR pg_catalog.=(integer,integer)
OPERATOR pg_catalog.=(text,text)
OPERATOR pg_catalog.=(smallint,integer)
OPERATOR pg_catalog.=(bigint,integer)
OPERATOR pg_catalog.=(numeric,numeric)
```

SQL 문에 푸시다운이 사용되는지 확인하려면 `EXPLAIN` 명령을 사용하여 실행 계획을 표시하세요.

## 데이터베이스 링크에서 외부 테이블 생성 (Creating a foreign table from a database link)

##### 참고 (Note)

이 절차는 Oracle 데이터베이스와 호환되지 않습니다.

데이터베이스 링크를 생성한 후, 이 데이터베이스 링크를 기반으로 외부 테이블(foreign table)을 생성할 수 있습니다. 그러면 데이터베이스 링크 구문을 사용하는 대신 외부 테이블 이름으로 원격 테이블을 참조하여 접근하는 데 외부 테이블을 사용할 수 있습니다. 데이터베이스 링크를 사용하려면 SQL 명령에서 참조하는 테이블이나 뷰 이름 뒤에 `@dblink`를 붙여야 하며, 여기서 `dblink`는 데이터베이스 링크의 이름입니다.

이 기법은 원격 Oracle 접근을 위한 oci-dblink 연결이나 원격 Postgres 접근을 위한 `postgres_fdw` 연결 모두에 사용할 수 있습니다.

이 예제는 원격 Oracle 테이블에 접근하기 위한 외부 테이블을 생성합니다.

다음은 Oracle 데이터베이스에 연결하기 위한 `oralink`라는 이름의 데이터베이스 링크를 생성합니다:

```sql
CREATE PUBLIC DATABASE LINK oralink CONNECT TO edb IDENTIFIED BY 'password'
USING '//127.0.0.1:1521/xe';
```

다음 쿼리는 데이터베이스 링크를 표시합니다:

```sql
SELECT lnkname, lnkuser, lnkconnstr FROM pg_catalog.edb_dblink;
```

출력

```text
 lnkname | lnkuser |     lnkconnstr
---------+---------+---------------------
 oralink | edb     | //127.0.0.1:1521/xe
(1 row)
```

데이터베이스 링크를 생성하면 EDB Postgres Advanced Server는 해당하는 외부 서버(foreign server)를 생성합니다. 다음 쿼리는 외부 서버를 표시합니다:

```sql
SELECT srvname, srvowner, srvfdw, srvtype, srvoptions FROM
pg_foreign_server;
```

출력

```text

---------+----------+--------+---------+-------------------------------
 oralink |       10 |  14005 |         | {connstr=//127.0.0.1:1521/xe}
(1 row)
```

외부 서버에 대한 자세한 내용은 [PostgreSQL 핵심 문서](https://www.postgresql.org/docs/current/static/sql-createserver.html)의 `CREATE SERVER` 명령을 참조하세요.

외부 테이블을 생성합니다:

```sql
CREATE FOREIGN TABLE emp_ora (
    empno           NUMERIC(4),
    ename           VARCHAR(10),
    job             VARCHAR(9),
    mgr             NUMERIC(4),
    hiredate        TIMESTAMP WITHOUT TIME ZONE,
    sal             NUMERIC(7,2),
    comm            NUMERIC(7,2),
    deptno          NUMERIC(2)
)
  SERVER oralink
  OPTIONS (table_name 'emp', schema_name 'edb'
);
```

`CREATE FOREIGN TABLE` 명령에서 다음에 유의하세요:

- `CREATE FOREIGN TABLE` 명령 끝의 `SERVER` 절에 지정된 이름은 외부 서버의 이름이며, 이 예제에서는 `oralink`입니다. 이 이름은 `pg_foreign_server`에 대한 쿼리의 `srvname` 열에서 볼 수 있습니다.
- 테이블 이름과 스키마 이름은 `OPTIONS` 절에서 `table` 및 `schema` 옵션으로 지정됩니다.
- `CREATE FOREIGN TABLE` 명령에 지정된 열 이름은 원격 테이블의 열 이름과 일치해야 합니다.
- 일반적으로 `CONSTRAINT` 절은 외부 테이블에서 수락되거나 적용될 수 없습니다. 이들은 원격 테이블에 정의되어 있는 것으로 가정됩니다.

`CREATE FOREIGN TABLE` 명령에 대한 자세한 내용은 [PostgreSQL 핵심 문서](https://www.postgresql.org/docs/current/static/sql-createforeigntable.html)를 참조하세요.
