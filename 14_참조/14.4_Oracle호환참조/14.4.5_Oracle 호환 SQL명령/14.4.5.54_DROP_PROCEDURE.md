# DROP PROCEDURE — EPAS 18 Reference

> 원문: [EPAS v18 — Reference › Oracle 호환 › 호환 SQL 명령 › DROP PROCEDURE](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/50_drop_procedure/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·코드 이름은 원문 그대로 보존했습니다.

## 이름 (Name)

`DROP PROCEDURE` — 프로시저를 제거합니다.

## 구문 개요 (Synopsis)

```sql
DROP PROCEDURE [ IF EXISTS ] <name>
  [ ([ [ <argmode> ] [ <argname> ] <argtype> ] [, ...]) ]
  [ CASCADE | RESTRICT ]
```

## 설명 (Description)

`DROP PROCEDURE`는 기존 프로시저의 정의를 제거합니다. 이 명령을 실행하려면 슈퍼유저이거나 해당 프로시저의 소유자여야 합니다. 오버로드된 프로시저의 경우, 프로시저에 대한 모든 입력(`IN`, `IN OUT`) 인자 데이터 타입을 지정해야 합니다.

##### 참고 (Note)

이 요구 사항은 Oracle 데이터베이스와 호환되지 않습니다. Oracle에서는 프로시저 이름만 지정합니다. EDB Postgres Advanced Server에서는 프로시저 이름의 오버로드를 허용합니다. 따라서 오버로드된 프로시저의 EDB Postgres Advanced Server `DROP PROCEDURE` 명령에서는 입력 인자 데이터 타입으로 주어지는 프로시저 시그니처가 필요합니다.

`IF EXISTS`, `CASCADE`, `RESTRICT` 파라미터는 Oracle 데이터베이스와 호환되지 않습니다. EDB Postgres Advanced Server에서만 이들을 사용합니다.

## 파라미터 (Parameters)

`IF EXISTS`

프로시저가 존재하지 않아도 오류를 발생시키지 않도록 지정합니다. 대신 알림(notice)이 발행됩니다.

`name`

기존 프로시저의 이름(선택적으로 스키마로 한정할 수 있음)입니다.

`argmode`

인자의 모드로 `IN`, `IN OUT`, `OUT` 중 하나입니다. 기본값은 `IN`입니다. 프로시저의 정체성을 결정하는 데는 입력 인자만 필요하므로 `DROP PROCEDURE`는 `OUT` 인자를 무시합니다. `IN` 및 `IN OUT` 인자만 나열하세요.

!!! Note
`argmode` 지정은 Oracle 데이터베이스와 호환되지 않습니다. EDB Postgres Advanced Server에만 적용됩니다.

`argname`

인자의 이름입니다. 프로시저의 정체성을 결정하는 데는 인자 데이터 타입만 필요하므로 `DROP PROCEDURE`는 인자 이름을 무시합니다.

!!! Note
`argname` 지정은 Oracle 데이터베이스와 호환되지 않습니다. EDB Postgres Advanced Server에만 적용됩니다.

`argtype`

프로시저 인자의 데이터 타입입니다.

!!! Note
`argtype` 지정은 Oracle 데이터베이스와 호환되지 않습니다. EDB Postgres Advanced Server에만 적용됩니다.

`CASCADE`

프로시저에 의존하는 객체와, 그 객체에 의존하는 모든 객체를 함께 삭제합니다.

`RESTRICT`

프로시저에 의존하는 객체가 있으면 프로시저 삭제를 막습니다. 이것이 기본값입니다.

## 예제 (Examples)

이 예제는 `select_emp` 프로시저를 제거합니다.

```sql
DROP PROCEDURE select_emp;
```
