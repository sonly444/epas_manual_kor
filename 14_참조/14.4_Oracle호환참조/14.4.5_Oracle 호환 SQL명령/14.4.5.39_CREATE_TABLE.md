# CREATE TABLE v18

## 이름 (Name)

`CREATE TABLE` — 새 테이블을 정의합니다.

## 구문 개요 (Synopsis)

```sql
CREATE [ GLOBAL TEMPORARY | UNLOGGED ] TABLE <table_name> (
  { <column_name> <data_type> [ DEFAULT <default_expr> ]
  [ <column_constraint> [ ... ] ] | <table_constraint> } [, ...]
  )
  [ WITH ( ROWIDS [= <value> ] ) ]
  [ ON COMMIT { PRESERVE ROWS | DELETE ROWS } ]
  [ TABLESPACE <tablespace> ]
  { NOPARALLEL | PARALLEL [ <integer> ] }
```

여기서 `column_constraint`는 다음과 같습니다.

```sql
[ CONSTRAINT <constraint_name> ]
{ NOT NULL |
  NULL |
  UNIQUE [ USING INDEX TABLESPACE <tablespace> ] |
  PRIMARY KEY [ USING INDEX TABLESPACE <tablespace> ] |
  CHECK (<expression>) |
  REFERENCES <reftable> [ ( <refcolumn> ) ]
    [ ON DELETE <action> ] }
[ DEFERRABLE | NOT DEFERRABLE ] [ INITIALLY DEFERRED |\
  INITIALLY IMMEDIATE ]
```

여기서 `table_constraint`는 다음과 같습니다.

```sql
[ CONSTRAINT <constraint_name> ]
{ UNIQUE ( <column_name> [, ...] )
    [ USING INDEX [ <create_index_statement> ] TABLESPACE <tablespace> ] |
  PRIMARY KEY ( <column_name> [, ...] )
    [ USING INDEX [ <create_index_statement> ] TABLESPACE <tablespace> ] |
  CHECK ( <expression> ) |
  FOREIGN KEY ( <column_name> [, ...] )
      REFERENCES <reftable> [ ( <refcolumn> [, ...] ) ]
    [ ON DELETE <action> ] }
[ DEFERRABLE | NOT DEFERRABLE ]
[ INITIALLY DEFERRED | INITIALLY IMMEDIATE ]
```

## 설명 (Description)

`CREATE TABLE`은 현재 데이터베이스에 빈 테이블을 생성합니다. 테이블을 생성한 사용자가 테이블을 소유합니다.

스키마 이름을 제공하면 테이블은 지정된 스키마에 생성됩니다. 그렇지 않으면 현재 스키마에 생성됩니다. 임시 테이블(temporary table)은 특수한 스키마에 존재하므로, 임시 테이블을 생성할 때는 스키마 이름을 제공할 수 없습니다. 테이블 이름은 동일한 스키마 내의 어떤 테이블, 시퀀스, 인덱스, 뷰의 이름과도 달라야 합니다.

`CREATE TABLE`은 또한 테이블의 한 행에 해당하는 복합 타입(composite type)을 나타내는 데이터 타입도 생성합니다. 따라서 테이블은 동일한 스키마 내의 기존 데이터 타입과 같은 이름을 가질 수 없습니다.

`PARALLEL` 절은 테이블의 병렬 처리 정도(degree of parallelism)를 설정합니다. `PARALLEL` 절을 지정하지 않으면 서버가 릴레이션 크기를 기준으로 값을 결정합니다.

`NOPARALLEL` 절은 병렬 처리를 기본 실행으로 재설정하며, `reloptions`는 `parallel_workers` 파라미터를 `0`으로 표시합니다.

테이블은 1600개를 초과하는 컬럼을 가질 수 없습니다. 실제로는 튜플 길이 제약 때문에 유효 한계가 더 낮습니다.

선택적 제약 조건 절은 삽입 또는 갱신 작업이 성공하기 위해 새 행이나 갱신된 행이 충족해야 하는 제약 조건 또는 테스트를 지정합니다. 제약 조건은 다양한 방식으로 테이블의 유효한 값 집합을 정의하는 데 도움을 주는 SQL 객체입니다.

테이블 제약 조건과 컬럼 제약 조건을 정의할 수 있습니다. 컬럼 제약 조건은 컬럼 정의의 일부입니다. 테이블 제약 조건 정의는 특정 컬럼에 묶이지 않으며 둘 이상의 컬럼을 포함할 수 있습니다. 모든 컬럼 제약 조건을 테이블 제약 조건으로 작성할 수도 있습니다. 제약 조건이 하나의 컬럼에만 영향을 미치는 경우 컬럼 제약 조건은 표기상의 편의일 뿐입니다.

##### 참고 (Note)

EDB Postgres Advanced Server는 `CREATE FOREIGN TABLE` 구문에서 `WITH (ROWIDS)` 또는 `WITH (ROWIDS=true)` 옵션을 지정하여 외부 테이블(foreign table)에 rowid를 생성할 수 있게 합니다. `WITH (ROWIDS)` 또는 `WITH (ROWIDS=true)` 옵션을 지정하면 외부 테이블에 rowid 컬럼이 추가됩니다. `CREATE FOREIGN TABLE`에 대한 정보는 [PostgreSQL 코어 문서](https://www.postgresql.org/docs/current/sql-createforeigntable.html)를 참조하세요.

## 파라미터 (Parameters)

`GLOBAL TEMPORARY`

테이블을 임시 테이블로 생성합니다. 임시 테이블은 세션이 끝날 때 또는 선택적으로 현재 트랜잭션이 끝날 때 삭제됩니다. (`ON COMMIT` 파라미터를 참조하세요.) 임시 테이블이 존재하는 동안에는, 스키마로 한정된 이름으로 참조하지 않는 한, 같은 이름을 가진 기존 영구 테이블은 현재 세션에서 보이지 않습니다. 또한 임시 테이블은 이를 생성한 세션 외부에서는 보이지 않습니다. 글로벌 임시 테이블의 이 측면은 Oracle 데이터베이스와 호환되지 않습니다. 임시 테이블에 생성된 모든 인덱스도 임시입니다.

`UNLOGGED`

테이블을 언로그드 테이블(unlogged table)로 생성합니다. 언로그드 테이블에 기록된 데이터는 미리 쓰기 로그(WAL)에 기록되지 않으므로 일반 테이블보다 빠릅니다. 언로그드 테이블에 생성된 인덱스는 언로그드입니다. 언로그드 테이블의 내용은 대기(standby) 서버로 복제되지 않습니다. 언로그드 테이블은 충돌에 안전하지 않습니다(not crash-safe). 충돌이나 종료 후에는 잘립니다(truncate).

`table_name`

생성할 테이블의 이름(선택적으로 스키마로 한정).

`column_name`

새 테이블에 생성할 컬럼의 이름입니다.

`data_type`

컬럼의 데이터 타입입니다. 배열 지정자(array specifier)를 포함할 수 있습니다. EDB Postgres Advanced Server에 포함된 데이터 타입에 대한 자세한 정보는 [SQL reference](https://www.enterprisedb.com/docs/epas/latest/reference/sql_reference/02_data_types/)를 참조하세요.

`DEFAULT default_expr`

`DEFAULT` 절은 이 절이 나타나는 컬럼 정의의 컬럼에 대한 기본 데이터 값을 할당합니다. 값은 변수가 없는(variable-free) 임의의 표현식입니다. 서브쿼리와 현재 테이블의 다른 컬럼에 대한 상호 참조는 허용되지 않습니다. 기본 표현식의 데이터 타입은 컬럼의 데이터 타입과 일치해야 합니다.

기본 표현식은 해당 컬럼에 대한 값을 지정하지 않는 모든 삽입 작업에서 사용됩니다. 컬럼에 대한 기본값을 지정하지 않으면 기본값은 `null`입니다.

`CONSTRAINT constraint_name`

컬럼 또는 테이블 제약 조건에 대한 선택적 이름입니다. 지정하지 않으면 시스템이 이름을 생성합니다.

`NOT NULL`

컬럼이 null 값을 포함할 수 없습니다.

`NULL`

컬럼이 null 값을 포함할 수 있습니다. 이것이 기본값입니다.

이 절은 비표준 SQL 데이터베이스와의 호환성을 위해서만 제공됩니다. 새 애플리케이션에서는 사용을 권장하지 않습니다.

`UNIQUE` — 컬럼 제약 조건.

`UNIQUE (column_name [, ...] )` — 테이블 제약 조건.

`UNIQUE` 제약 조건은 테이블의 서로 다른 하나 이상의 컬럼 그룹이 고유한 값만 포함할 수 있음을 지정합니다. 고유 테이블 제약 조건의 동작은 컬럼 제약 조건의 동작과 동일합니다. 다만 고유 테이블 제약 조건은 여러 컬럼에 걸칠 수 있습니다.

고유 제약 조건의 목적상 null 값은 서로 같지 않은 것으로 간주됩니다.

각 고유 테이블 제약 조건은 테이블에 대해 정의된 다른 고유 또는 기본 키 제약 조건이 지정한 컬럼 집합과는 다른 컬럼 집합의 이름을 지정해야 합니다. 그렇지 않으면 동일한 제약 조건이 두 번 나열된 것입니다.

`PRIMARY KEY` — 컬럼 제약 조건.

`PRIMARY KEY ( column_name [, ...] )` — 테이블 제약 조건.

기본 키(primary key) 제약 조건은 테이블의 어떤 컬럼이든 고유하고 중복되지 않으며 null이 아닌 값만 포함할 수 있음을 지정합니다. 기술적으로 `PRIMARY KEY`는 `UNIQUE`와 `NOT NULL`의 조합입니다. 다만 컬럼 집합을 기본 키로 식별하는 것은 스키마 설계에 대한 메타데이터도 제공합니다. 기본 키는 다른 테이블이 이 컬럼 집합을 행에 대한 고유 식별자로 사용할 수 있음을 암시합니다.

컬럼 제약 조건이든 테이블 제약 조건이든 테이블에 대해 하나의 기본 키만 지정할 수 있습니다.

기본 키 제약 조건을 사용하여 동일한 테이블에 정의된 어떤 고유 제약 조건이 지정한 컬럼 집합과도 다른 컬럼 집합의 이름을 지정합니다.

`CHECK (expression)`

`CHECK` 절은 삽입 또는 갱신 작업이 성공하기 위해 새 행이나 갱신된 행이 충족해야 하는 부울(Boolean) 결과를 생성하는 표현식을 지정합니다. `TRUE` 또는 "unknown(알 수 없음)"으로 평가되는 표현식은 성공합니다. 삽입 또는 갱신 작업의 어떤 행이든 `FALSE` 결과를 생성하면 오류 예외가 발생하고 삽입 또는 갱신은 데이터베이스를 변경하지 않습니다. 컬럼 제약 조건으로 지정된 체크 제약 조건은 해당 컬럼의 값만 참조해야 합니다. 테이블 제약 조건에 나타나는 표현식은 여러 컬럼을 참조할 수 있습니다.

현재 `CHECK` 표현식은 서브쿼리를 포함하거나 현재 행의 컬럼 이외의 변수를 참조할 수 없습니다.

`REFERENCES` reftable [`( refcolumn`) ] [`ON DELETE action` ] — 컬럼 제약 조건.

`FOREIGN KEY ( column [, ...] ) REFERENCES reftable [ ( refcolumn  [, ...] ) ] [ ON DELETE action ]` — 테이블 제약 조건.

이 절들은 외래 키(foreign-key) 제약 조건을 지정합니다. 이 제약 조건은 새 테이블의 컬럼 그룹이 참조되는 테이블의 어떤 행의 참조 컬럼의 값과 일치하는 값만 포함하도록 요구합니다. `refcolumn`을 생략하면 `reftable`의 기본 키가 사용됩니다. 참조되는 컬럼은 참조되는 테이블의 고유 또는 기본 키 제약 조건의 컬럼이어야 합니다.

또한 참조되는 컬럼의 데이터가 변경될 때 이 테이블의 컬럼 데이터에 특정 작업이 수행됩니다. `ON DELETE` 절은 참조되는 테이블에서 참조된 행이 삭제될 때 수행할 작업을 지정합니다. 제약 조건이 지연 가능(deferrable)하더라도 참조 작업(referential action)은 지연할 수 없습니다. 각 절에 대해 다음과 같은 작업이 가능합니다.

- `CASCADE`

삭제된 행을 참조하는 모든 행을 삭제하거나, 참조하는 컬럼의 값을 참조되는 컬럼의 새 값으로 갱신합니다.

- `SET NULL`

참조하는 컬럼을 `NULL`로 설정합니다.

참조되는 컬럼이 자주 변경되는 경우, 외래 키 컬럼과 연관된 참조 작업이 더 효율적으로 수행되도록 외래 키 컬럼에 인덱스를 추가하는 것이 좋습니다.


`DEFERRABLE`

`NOT DEFERRABLE`

이 파라미터는 제약 조건을 지연할 수 있는지 여부를 제어합니다. 지연 불가능한 제약 조건은 모든 명령 직후에 검사됩니다. 지연 가능한 제약 조건의 검사는 `SET CONSTRAINTS` 명령을 사용하여 트랜잭션이 끝날 때까지 연기할 수 있습니다. `NOT DEFERRABLE`이 기본값입니다. 현재 외래 키 제약 조건만 이 절을 받아들입니다. 다른 모든 제약 조건 유형은 지연할 수 없습니다.

`INITIALLY IMMEDIATE`

`INITIALLY DEFERRED`

제약 조건이 지연 가능한 경우, 이 절은 제약 조건을 검사할 기본 시점을 지정합니다. 제약 조건이 `INITIALLY IMMEDIATE`이면 각 문 이후에 검사됩니다. 이것이 기본값입니다. 제약 조건이 `INITIALLY DEFERRED`이면 트랜잭션이 끝날 때만 검사됩니다. `SET CONSTRAINTS` 명령을 사용하여 제약 조건 검사 시점을 변경할 수 있습니다.

`WITH ( ROWIDS [= value ] )`

테이블에 대한 `ROWIDS` 옵션은 `value`가 `TRUE/ON/1` 또는 `FALSE/OFF/0`인 것을 포함합니다. `TRUE/ON/1`로 설정하면 새 테이블에 `ROWID` 컬럼이 생성됩니다. `ROWID`는 `1`에서 시작하는 시퀀스를 기반으로 하는 자동 증가 값이며 테이블의 각 행에 할당됩니다. 기본값은 항상 `TRUE`입니다.

기본적으로 `ROWID` 컬럼에 고유 인덱스가 생성됩니다. `ROWID` 컬럼에서는 `ALTER` 및 `DROP` 작업이 제한됩니다.

`ON COMMIT`

`ON COMMIT`을 사용하여 트랜잭션 블록이 끝날 때 임시 테이블의 동작을 제어할 수 있습니다. 옵션은 다음과 같습니다.

- `PRESERVE ROWS`

트랜잭션이 끝날 때 특별한 조치를 취하지 않습니다. 이것이 기본 동작입니다. 이 측면은 Oracle 데이터베이스와 호환되지 않습니다. Oracle 기본값은 `DELETE ROWS`입니다.

- `DELETE ROWS`

각 트랜잭션 블록이 끝날 때 임시 테이블의 모든 행이 삭제됩니다. 본질적으로 각 커밋 시 자동 `TRUNCATE`가 수행됩니다.


`TABLESPACE tablespace`

`tablespace`는 새 테이블이 생성되는 테이블스페이스의 이름입니다. 지정하지 않으면 `default tablespace`가 사용되며, `default_tablespace`가 빈 문자열이면 데이터베이스의 기본 테이블스페이스가 사용됩니다.

`USING INDEX [ create_index_statement ] TABLESPACE tablespace`

이 절은 `UNIQUE` 또는 `PRIMARY KEY` 제약 조건과 연관된 인덱스가 생성되는 테이블스페이스를 선택할 수 있게 합니다. 지정하지 않으면 `default tablespace`가 사용되며, `default_tablespace`가 빈 문자열이면 데이터베이스의 기본 테이블스페이스가 사용됩니다.

`create_index_statement` 옵션을 지정하면 데이터베이스 서버가 고유 또는 기본 키 제약 조건을 가능하게 하는 인덱스를 생성합니다. 제약 조건에 지정된 컬럼과 인덱스의 컬럼은 동일해야 하지만, 나타나는 순서는 다를 수 있습니다.

`PARALLEL`

테이블의 병렬 처리 정도를 지정하려면 `PARALLEL` 절을 포함합니다. 테이블의 병렬 스캔을 수행하기 위해 `parallel_workers` 파라미터를 병렬 처리 정도와 동일하게 설정합니다. 또는 `PARALLEL`을 지정하되 병렬 처리 정도를 포함하지 않으면 인덱스가 기본 병렬 처리를 사용합니다.

`NOPARALLEL`

기본 실행을 위해 `NOPARALLEL`을 지정합니다.

`integer`

`integer`는 병렬 처리 정도를 나타내며, 이는 테이블의 병렬 스캔을 수행하기 위해 병렬 작업에 사용되는 `parallel_workers`의 수입니다.

## 참고 사항 (Notes)

EDB Postgres Advanced Server는 고유성을 강제하기 위해 각 고유 제약 조건과 기본 키 제약 조건에 대해 인덱스를 생성합니다. 따라서 기본 키 컬럼에 대해 명시적인 인덱스를 생성할 필요가 없습니다. 자세한 정보는 [`CREATE INDEX`](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/24_create_index/)를 참조하세요.

## 예제 (Examples)

`dept` 테이블과 `emp` 테이블을 생성합니다.

```sql
CREATE TABLE dept (
    deptno          NUMBER(2) NOT NULL CONSTRAINT dept_pk PRIMARY KEY,
    dname           VARCHAR2(14),
    loc             VARCHAR2(13)
);
CREATE TABLE emp (
    empno           NUMBER(4) NOT NULL CONSTRAINT emp_pk PRIMARY KEY,
    ename           VARCHAR2(10),
    job             VARCHAR2(9),
    mgr             NUMBER(4),
    hiredate        DATE,
    sal             NUMBER(7,2),
    comm            NUMBER(7,2),
    deptno          NUMBER(2) CONSTRAINT emp_ref_dept_fk
                        REFERENCES dept(deptno)
);
```

`dept` 테이블에 대한 고유 테이블 제약 조건을 정의합니다. 테이블의 하나 이상의 컬럼에 대해 고유 테이블 제약 조건을 정의할 수 있습니다.

```sql
CREATE TABLE dept (
    deptno          NUMBER(2) NOT NULL CONSTRAINT dept_pk PRIMARY KEY,
    dname           VARCHAR2(14) CONSTRAINT dept_dname_uq UNIQUE,
    loc             VARCHAR2(13)
);
```

체크 컬럼 제약 조건을 정의합니다.

```sql
CREATE TABLE emp (
    empno           NUMBER(4) NOT NULL CONSTRAINT emp_pk PRIMARY KEY,
    ename           VARCHAR2(10),
    job             VARCHAR2(9),
    mgr             NUMBER(4),
    hiredate        DATE,
    sal             NUMBER(7,2) CONSTRAINT emp_sal_ck CHECK (sal > 0),
    comm            NUMBER(7,2),
    deptno          NUMBER(2) CONSTRAINT emp_ref_dept_fk
                        REFERENCES dept(deptno)
);
```

체크 테이블 제약 조건을 정의합니다.

```sql
CREATE TABLE emp (
    empno           NUMBER(4) NOT NULL CONSTRAINT emp_pk PRIMARY KEY,
    ename           VARCHAR2(10),
    job             VARCHAR2(9),
    mgr             NUMBER(4),
    hiredate        DATE,
    sal             NUMBER(7,2),
    comm            NUMBER(7,2),
    deptno          NUMBER(2) CONSTRAINT emp_ref_dept_fk
                        REFERENCES dept(deptno),
    CONSTRAINT new_emp_ck CHECK (ename IS NOT NULL AND empno > 7000)
);
```

`jobhist` 테이블에 대한 기본 키 테이블 제약 조건을 정의합니다. 테이블의 하나 이상의 컬럼에 대해 기본 키 테이블 제약 조건을 정의할 수 있습니다.

```sql
CREATE TABLE jobhist (
    empno           NUMBER(4) NOT NULL,
    startdate       DATE NOT NULL,
    enddate         DATE,
    job             VARCHAR2(9),
    sal             NUMBER(7,2),
    comm            NUMBER(7,2),
    deptno          NUMBER(2),
    chgdesc         VARCHAR2(80),
    CONSTRAINT jobhist_pk PRIMARY KEY (empno, startdate)
);
```

이 예제는 `job` 컬럼에 리터럴 상수 기본값을 할당하고, `hiredate`의 기본값을 행이 삽입되는 날짜로 만듭니다.

```sql
CREATE TABLE emp (
    empno           NUMBER(4) NOT NULL CONSTRAINT emp_pk PRIMARY KEY,
    ename           VARCHAR2(10),
    job             VARCHAR2(9) DEFAULT 'SALESMAN',
    mgr             NUMBER(4),
    hiredate        DATE DEFAULT SYSDATE,
    sal             NUMBER(7,2),
    comm            NUMBER(7,2),
    deptno          NUMBER(2) CONSTRAINT emp_ref_dept_fk
                        REFERENCES dept(deptno)
);
```

테이블스페이스 `diskvol1`에 `dept` 테이블을 생성합니다.

```sql
CREATE TABLE dept (
    deptno          NUMBER(2) NOT NULL CONSTRAINT dept_pk PRIMARY KEY,
    dname           VARCHAR2(14),
    loc             VARCHAR2(13)
) TABLESPACE diskvol1;
```

이 `PARALLEL` 예제는 `sales` 테이블을 생성하고 병렬 처리 정도를 6으로 설정합니다.

```sql
CREATE TABLE sales (deptno number) PARALLEL 6 WITH (FILLFACTOR=66);
```

이 `NOPARALLEL` 예제는 `sales_order` 테이블을 생성하고 병렬 처리 정도를 0으로 설정합니다.

```sql
CREATE TABLE sales_order (deptno number) NOPARALLEL WITH (FILLFACTOR=66);
```

이 예제는 `dept`라는 테이블을 생성합니다. 이 정의는 `dname` 컬럼에 고유 키를 생성합니다. `dept_dname_uq` 제약 조건은 `dname` 컬럼을 고유 키로 식별합니다. 앞의 문에는 `USING_INDEX` 절이 포함되어 있으며, 이는 고유 제약 조건을 가능하게 하는 인덱스 문을 통해 `dept` 테이블에 명시적으로 인덱스를 생성합니다.

```sql
CREATE TABLE dept (
    deptno          NUMBER(2) NOT NULL,
    dname           VARCHAR2(14),
    loc             VARCHAR2(13),
    CONSTRAINT dept_dname_uq UNIQUE(dname)
       USING INDEX (CREATE UNIQUE INDEX idx_dept_dname_uq ON dept(dname))
);
```

이 예제는 `emp`라는 테이블을 생성합니다. 이 정의는 `ename` 컬럼에 기본 키를 생성합니다. `emp_ename_pk` 제약 조건은 `ename` 컬럼을 `emp` 테이블의 기본 키로 식별합니다. 앞의 문에는 `USING_INDEX` 절이 포함되어 있으며, 이는 기본 제약 조건을 가능하게 하는 인덱스 문을 통해 `emp` 테이블에 명시적으로 인덱스를 생성합니다.

```sql
CREATE TABLE emp (
    empno           NUMBER(4) NOT NULL,
    ename           VARCHAR2(10),
    job             VARCHAR2(9),
    sal             NUMBER(7,2),
    deptno          NUMBER(2),
    CONSTRAINT emp_ename_pk PRIMARY KEY (ename)
        USING INDEX (CREATE INDEX idx_emp_ename_pk ON emp (ename))
);
```
