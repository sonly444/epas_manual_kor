> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·코드 이름은 원문 그대로 보존했습니다.

# CREATE TYPE v18

## 이름 (Name)

`CREATE TYPE` — 새 사용자 정의 타입을 정의합니다. 새 타입은 객체 타입(object type), 컬렉션 타입(중첩 테이블 타입 또는 varray 타입), 또는 복합 타입(composite type)일 수 있습니다.

## 구문 개요 (Synopsis)

### 객체 타입 (Object Type)

```sql
CREATE [ OR REPLACE ] TYPE <name>
  [ AUTHID { DEFINER | CURRENT_USER } ]
  { IS | AS } OBJECT
( { <attribute> { <datatype> | <objtype> | <collecttype> } }
    [, ...]
  [ <method_spec> ] [, ...]
) [ [ NOT ] { FINAL | INSTANTIABLE } ] ...
```

여기서 `method_spec`은 다음과 같습니다.

```sql
[ [ NOT ] { FINAL | INSTANTIABLE } ] ...
[ OVERRIDING ]
  <subprogram_spec>
```

여기서 `subprogram_spec`은 다음과 같습니다.

```sql
{ MEMBER | STATIC }
{ PROCEDURE <proc_name>
    [ ( [ SELF [ IN | IN OUT ] <name> ]\
        [, <argname> [ IN | IN OUT | OUT ] <argtype>\
                     [ DEFAULT <value> ]\
        ] ...)\
    ]
|
  FUNCTION <func_name>
    [ ( [ SELF [ IN | IN OUT ] <name> ]\
        [, <argname> [ IN | IN OUT | OUT ] <argtype>\
                     [ DEFAULT <value> ]\
        ] ...)\
    ]
  RETURN <rettype>
}
```

### 중첩 테이블 타입 (Nested table type)

```sql
CREATE [ OR REPLACE ] TYPE <name> { IS | AS } TABLE OF
  { <datatype> | <objtype> | <collecttype> }
```

### Varray 타입 (Varray type)

```sql
CREATE [ OR REPLACE ] TYPE <name> { IS | AS }
  { VARRAY | VARYING ARRAY } (<maxsize>) OF { <datatype> | <objtype> }
```

### 복합 타입 (Composite type)

```sql
CREATE [ OR REPLACE ] TYPE <name> { IS | AS }
( [ attribute <datatype> ][, ...]
)
```

## 설명 (Description)

`CREATE TYPE`은 새 데이터 타입을 정의합니다. 생성할 수 있는 타입은 객체 타입, 중첩 테이블 타입, varray 타입, 또는 복합 타입입니다. 중첩 테이블과 varray 타입은 _컬렉션(collection)_ 으로 알려진 타입 범주에 속합니다.

복합 타입은 Oracle 데이터베이스와 호환되지 않습니다. 다만 SPL 프로그램은 다른 타입과 함께 복합 타입에 접근할 수 있습니다.

## 파라미터 (Parameters)

`name`

생성할 타입의 이름(선택적으로 스키마로 한정).

`DEFINER | CURRENT_USER`

객체 타입에서 참조되는 데이터베이스 객체에 대한 접근 허용 여부를 결정할 때, 객체 타입 소유자의 권한(`DEFINER`)을 사용할지 아니면 객체 타입의 메서드를 실행하는 현재 사용자의 권한(`CURRENT_USER`)을 사용할지를 지정합니다. `DEFINER`가 기본값입니다.

`attribute`

객체 타입 또는 복합 타입의 속성(attribute) 이름입니다.

`datatype`

객체 타입 또는 복합 타입의 속성을 정의하거나, 생성 중인 컬렉션 타입의 요소를 정의하는 데이터 타입입니다.

`objtype`

객체 타입의 속성 또는 생성 중인 컬렉션 타입의 요소를 정의하는 객체 타입의 이름입니다.

`collecttype`

객체 타입의 속성 또는 생성 중인 컬렉션 타입의 요소를 정의하는 컬렉션 타입의 이름입니다.

`FINAL`

`NOT FINAL`

객체 타입의 경우, 해당 객체 타입에서 하위 타입(subtype)을 파생할 수 있는지 여부를 지정합니다. `FINAL`(객체 타입에서 하위 타입을 파생할 수 없음)이 기본값입니다.

`method_spec`의 경우, 하위 타입에서 메서드를 재정의(override)할 수 있는지 여부를 지정합니다. `NOT FINAL`(하위 타입에서 메서드를 재정의할 수 있음)이 기본값입니다.

`INSTANTIABLE`

`NOT INSTANTIABLE`

객체 타입의 경우, 이 객체 타입의 객체 인스턴스를 생성할 수 있는지 여부를 지정합니다. `INSTANTIABLE`(이 객체 타입의 인스턴스를 생성할 수 있음)이 기본값입니다. `NOT INSTANTIABLE`을 지정하는 경우 `NOT FINAL`도 함께 지정해야 합니다. 객체 타입의 어떤 메서드에 대한 `method_spec`이 `NOT INSTANTIABLE` 한정자를 포함하는 경우, 객체 타입은 객체 타입 명세의 닫는 괄호 뒤에 `NOT INSTANTIABLE`과 `NOT FINAL`을 붙여 정의해야 합니다.

`method_spec`의 경우, 객체 타입 정의가 메서드에 대한 구현을 제공하는지 여부를 지정합니다. `INSTANTIABLE`(객체 타입에 대한 `CREATE TYPE BODY` 명령이 메서드의 구현을 제공함)이 기본값입니다. `NOT INSTANTIABLE`을 지정하면 객체 타입에 대한 `CREATE TYPE BODY` 명령은 메서드의 구현을 포함할 수 없습니다.

`OVERRIDING`

`OVERRIDING`을 지정하면 `method_spec`은 상위 타입(supertype)에 정의된 것과 동일한 이름, 동일한 수의 동일한 이름의 메서드 인수, 동일한 데이터 타입, 동일한 순서, 그리고 (메서드가 함수인 경우) 동일한 반환 타입을 가진 동일한 이름의 메서드를 재정의합니다.

`MEMBER`

`STATIC`

하위 프로그램이 객체 인스턴스에 대해 동작하는 경우 `MEMBER`를 지정합니다. 하위 프로그램이 특정 객체 인스턴스와 독립적으로 동작하는 경우 `STATIC`을 지정합니다.

`proc_name`

생성할 프로시저의 이름입니다.

`SELF [ IN | IN OUT ] name`

멤버 메서드의 경우, 데이터 타입이 정의 중인 객체 타입인 `SELF`라는 암묵적인 내장 파라미터가 있습니다. `SELF`는 현재 메서드를 호출하고 있는 객체 인스턴스를 참조합니다. 파라미터 목록에서 `SELF`를 `IN` 또는 `IN OUT` 파라미터로 명시적으로 선언할 수 있습니다. 명시적으로 선언하는 경우 `SELF`는 파라미터 목록의 첫 번째 파라미터여야 합니다. `SELF`를 명시적으로 선언하지 않으면 그 파라미터 모드는 멤버 프로시저의 경우 `IN OUT`으로, 멤버 함수의 경우 `IN`으로 기본 설정됩니다.

`argname`

인수의 이름입니다. 인수는 메서드 본문에서 이 이름으로 참조됩니다.

`argtype`

메서드 인수의 데이터 타입입니다. 인수 타입은 기본 데이터 타입이거나 중첩 테이블 또는 객체 타입과 같은 사용자 정의 타입일 수 있습니다. 어떤 기본 타입에도 길이를 지정하지 마십시오. 예를 들어 `VARCHAR2(10)`이 아니라 `VARCHAR2`를 지정합니다.

`DEFAULT value`

메서드 호출에서 값을 제공하지 않는 경우 입력 인수에 대한 기본값을 제공합니다. `IN OUT` 또는 `OUT` 모드의 인수에는 `DEFAULT`를 지정할 수 없습니다.

`func_name`

생성할 함수의 이름입니다.

`rettype`

반환 데이터 타입이며, `argtype`에 나열된 타입 중 하나일 수 있습니다. `rettype`에는 길이를 지정하지 마십시오.

`maxsize`

varray에 허용되는 최대 요소 수입니다.

## 예제 (Examples)

### 객체 타입 생성 (Creating an object type)

객체 타입 `addr_obj_typ`를 생성합니다.

```sql
CREATE OR REPLACE TYPE addr_obj_typ AS OBJECT (
    street          VARCHAR2(30),
    city            VARCHAR2(20),
    state           CHAR(2),
    zip             NUMBER(5)
);
```

멤버 메서드 `display_emp`를 포함하는 객체 타입 `emp_obj_typ`를 생성합니다.

```sql
CREATE OR REPLACE TYPE emp_obj_typ AS OBJECT (
    empno           NUMBER(4),
    ename           VARCHAR2(20),
    addr            ADDR_OBJ_TYP,
    MEMBER PROCEDURE display_emp (SELF IN OUT emp_obj_typ)
);
```

정적 메서드 `get_dname`을 포함하는 객체 타입 `dept_obj_typ`를 생성합니다.

```sql
CREATE OR REPLACE TYPE dept_obj_typ AS OBJECT (
    deptno          NUMBER(2),
    STATIC FUNCTION get_dname (p_deptno IN NUMBER) RETURN VARCHAR2,
    MEMBER PROCEDURE display_dept
);
```

### 컬렉션 타입 생성 (Creating a collection type)

데이터 타입 `NUMBER(8,2)`의 중첩 테이블 타입 `budget_tbl_typ`를 생성합니다.

```sql
CREATE OR REPLACE TYPE budget_tbl_typ IS TABLE OF NUMBER(8,2);
```

### 복합 타입 생성 및 사용 (Creating and using a composite type)

이 예제는 익명 블록(anonymous block)에서 접근하는 복합 타입을 사용합니다.

이 예제는 복합 타입을 생성합니다.

```sql
CREATE OR REPLACE TYPE emphist_typ AS (
    empno           NUMBER(4),
    ename           VARCHAR2(10),
    hiredate        DATE,
    job             VARCHAR2(9),
    sal             NUMBER(7,2)
);
```

다음 코드는 복합 타입에 접근하는 익명 블록을 보여줍니다.

```sql
DECLARE
    v_emphist       EMPHIST_TYP;
BEGIN
    v_emphist.empno    := 9001;
    v_emphist.ename    := 'SMITH';
    v_emphist.hiredate := '01-AUG-17';
    v_emphist.job      := 'SALESMAN';
    v_emphist.sal      := 8000.00;
    DBMS_OUTPUT.PUT_LINE('   EMPNO: ' || v_emphist.empno);
    DBMS_OUTPUT.PUT_LINE('   ENAME: ' || v_emphist.ename);
    DBMS_OUTPUT.PUT_LINE('HIREDATE: ' || v_emphist.hiredate);
    DBMS_OUTPUT.PUT_LINE('     JOB: ' || v_emphist.job);
    DBMS_OUTPUT.PUT_LINE('     SAL: ' || v_emphist.sal);
END;

   EMPNO: 9001
   ENAME: SMITH
HIREDATE: 01-AUG-17 00:00:00
     JOB: SALESMAN
     SAL: 8000.00
```

이 예제는 패키지 본문(package body)에 선언된 사용자 정의 레코드 타입에서 접근하는 복합 타입을 사용합니다.

다음은 복합 타입을 생성합니다.

```sql
CREATE OR REPLACE TYPE salhist_typ AS (
    startdate       DATE,
    job             VARCHAR2(9),
    sal             NUMBER(7,2)
);
```

다음은 패키지 명세(package specification)를 정의합니다.

```sql
CREATE OR REPLACE PACKAGE emp_salhist
IS
    PROCEDURE fetch_emp (
        p_empno     IN NUMBER
    );
END;
```

다음은 패키지 본문을 정의합니다.

```sql
CREATE OR REPLACE PACKAGE BODY emp_salhist
IS
    TYPE emprec_typ IS RECORD (
        empno       NUMBER(4),
        ename       VARCHAR(10),
        salhist     SALHIST_TYP
    );
    TYPE emp_arr_typ IS TABLE OF emprec_typ INDEX BY BINARY_INTEGER;
    emp_arr         emp_arr_typ;

    PROCEDURE fetch_emp (
        p_empno     IN NUMBER
    )
    IS
        CURSOR emp_cur IS SELECT e.empno, e.ename, h.startdate, h.job, h.sal
            FROM emp e, jobhist h
            WHERE e.empno = p_empno
              AND e.empno = h.empno;

        i           INTEGER := 0;
    BEGIN
        DBMS_OUTPUT.PUT_LINE('EMPNO  ENAME    STARTDATE  JOB         ' ||
        'SAL        ');
        DBMS_OUTPUT.PUT_LINE('-----  -------  ---------  ---------   ' ||
        '---------');

        FOR r_emp IN emp_cur LOOP
            i := i + 1;
            emp_arr(i) := (r_emp.empno, r_emp.ename,
                (r_emp.startdate, r_emp.job, r_emp.sal));
        END LOOP;

        FOR i IN 1 .. emp_arr.COUNT LOOP
            DBMS_OUTPUT.PUT_LINE(emp_arr(i).empno || '   ' ||
                RPAD(emp_arr(i).ename,8) || ' ' ||
                TO_CHAR(emp_arr(i).salhist.startdate,'DD-MON-YY') || '  ' ||
                RPAD(emp_arr(i).salhist.job,10) || ' ' ||
                TO_CHAR(emp_arr(i).salhist.sal,'99,999.99'));
        END LOOP;
    END;
END;
```

패키지 본문의 `TYPE emprec_typ IS RECORD` 데이터 구조 선언에서 `salhist` 필드는 `CREATE TYPE salhist_typ` 문으로 생성된 `SALHIST_TYP` 복합 타입으로 정의됩니다.

연관 배열(associative array) 정의 `TYPE emp_arr_typ IS TABLE OF emprec_typ`는 `SALHIST_TYP` 복합 타입으로 정의된 `salhist` 필드를 포함하는 레코드 타입 데이터 구조 `emprec_typ`를 참조합니다.

이 예제는 `emp` 테이블과 `jobhist` 테이블의 조인으로부터 배열을 로드한 다음 배열 내용을 표시하는 패키지 프로시저를 호출합니다.

```sql
EXEC emp_salhist.fetch_emp(7788);
```

출력

```text
EMPNO  ENAME    STARTDATE  JOB         SAL
-----  -------  ---------  ---------   ---------
7788   SCOTT    19-APR-87  CLERK        1,000.00
7788   SCOTT    13-APR-88  CLERK        1,040.00
7788   SCOTT    05-MAY-90  ANALYST      3,000.00

EDB-SPL Procedure successfully completed
```

## 참고 사항 (Notes)

패키지에 한해서만, 패키지 명세 또는 패키지 본문에서 `TYPE IS RECORD` 문으로 선언된 사용자 정의 레코드 타입에 복합 타입을 포함할 수 있습니다. 이 중첩 구조는 함수, 프로시저, 트리거와 같은 다른 SPL 프로그램에서는 허용되지 않습니다.

`CREATE TYPE` 명령에서 스키마 이름을 포함하면 타입은 지정된 스키마에 생성됩니다. 그렇지 않으면 현재 스키마에 생성됩니다. 기존 타입의 정의를 갱신하려는 경우가 아니라면, 새 타입의 이름은 동일한 스키마 내의 어떤 기존 타입과도 일치할 수 없습니다. 갱신하려는 경우에는 `CREATE OR REPLACE TYPE`을 사용합니다.

`OR REPLACE` 옵션을 사용하여 기존 객체 타입의 속성을 추가, 삭제, 또는 수정할 수 없습니다. `DROP TYPE` 명령을 사용하여 먼저 기존 객체 타입을 삭제하십시오. `OR REPLACE` 옵션을 사용하여 기존 객체 타입의 메서드를 추가, 삭제, 또는 수정할 수 있습니다.

PostgreSQL 형식의 `ALTER TYPE ALTER ATTRIBUTE` 명령을 사용하여 기존 객체 타입의 속성 데이터 타입을 변경할 수 있습니다. 다만 `ALTER TYPE` 명령은 객체 타입에 속성을 추가하거나 삭제할 수 없습니다.

타입을 생성하는 사용자가 타입의 소유자가 됩니다.
