# DROP TABLE — EPAS 18 Reference

> 원문: [EPAS v18 — Reference › Oracle 호환 › 호환 SQL 명령 › DROP TABLE](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/57_drop_table/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·코드 이름은 원문 그대로 보존했습니다.

## 이름 (Name)

`DROP TABLE` — 테이블을 제거합니다.

## 구문 개요 (Synopsis)

```sql
DROP TABLE <name> [CASCADE | RESTRICT | CASCADE CONSTRAINTS]
```

## 설명 (Description)

`DROP TABLE`은 데이터베이스에서 테이블을 제거합니다. 오직 소유자만이 테이블을 제거할 수 있습니다. 테이블을 제거하지 않고 테이블의 행만 비우려면 `DELETE`를 사용하십시오. `DROP TABLE`은 대상 테이블의 인덱스, 룰(rule), 트리거, 제약 조건을 모두 제거합니다.

## 파라미터 (Parameters)

`name`

삭제할 테이블의 이름입니다(선택적으로 스키마로 한정할 수 있습니다).

`RESTRICT`

`RESTRICT` 키워드를 포함하면 다른 객체가 해당 테이블에 의존하고 있을 경우 테이블 삭제를 막습니다. 이것이 기본 동작입니다. 테이블에 의존하는 객체가 있으면 `DROP TABLE` 명령은 오류를 보고합니다.

`CASCADE`

`CASCADE` 절을 포함하면 해당 테이블에 의존하는 모든 객체를 삭제합니다.

`CASCADE CONSTRAINTS`

`CASCADE CONSTRAINTS` 절을 포함하면 지정된 테이블에 의존하는 제약 조건을 삭제하며, 다른 객체 유형은 제외합니다.

## 예제 (Examples)

이 예제는 의존성이 없는 `emp`라는 이름의 테이블을 삭제합니다.

```sql
DROP TABLE emp;
```

`DROP TABLE` 명령의 결과는 테이블에 의존성이 있는지 여부에 따라 달라집니다. 삭제 동작(drop behavior)을 지정하여 결과를 제어할 수 있습니다. 예를 들어, `items` 테이블이 `orders` 테이블에 의존하는 두 개의 테이블 `orders`와 `items`를 생성한다고 가정해 봅시다.

```sql
CREATE TABLE orders
  (order_id int PRIMARY KEY, order_date date, …);
CREATE TABLE items
  (order_id REFERENCES orders, quantity int, …);
```

EDB Postgres Advanced Server는 `orders` 테이블을 삭제할 때, 지정한 삭제 동작에 따라 다음 작업 중 하나를 수행합니다.

- `DROP TABLE orders RESTRICT`를 지정하면, EDB Postgres Advanced Server는 오류를 보고합니다.
- `DROP TABLE orders CASCADE`를 지정하면, EDB Postgres Advanced Server는 `orders` 테이블과 `items` 테이블을 삭제합니다.
- `DROP TABLE orders CASCADE CONSTRAINTS`를 지정하면, EDB Postgres Advanced Server는 `orders` 테이블을 삭제하고 `items` 테이블에서 외래 키 명세를 제거합니다. `items` 테이블은 삭제하지 않습니다.
