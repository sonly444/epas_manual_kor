# CREATE SCHEMA v18

## 이름 (Name)

`CREATE SCHEMA` — 새 스키마를 정의합니다.

## 구문 개요 (Synopsis)

```sql
CREATE SCHEMA AUTHORIZATION <username> <schema_element> [ ... ]
```

## 설명 (Description)

`CREATE SCHEMA` 명령의 이 변형은 `username`이 소유하고 하나 이상의 객체로 채워진 스키마를 생성합니다. 스키마와 객체 생성은 단일 트랜잭션에서 이루어지므로, 스키마를 포함한 모든 객체가 생성되거나 아무것도 생성되지 않거나 둘 중 하나입니다. Oracle 데이터베이스를 사용하는 경우에는 새 스키마가 생성되지 않습니다. 이 명령을 사용하기 전에 `username`, 따라서 스키마가 존재해야 합니다.

스키마는 본질적으로 네임스페이스입니다. 스키마는 테이블과 뷰 같은 이름이 지정된 객체를 포함하며, 이 객체의 이름은 다른 스키마에 존재하는 다른 객체의 이름과 중복될 수 있습니다. 이름이 지정된 객체는 이름 앞에 스키마 이름을 접두어로 붙여 한정하거나, 원하는 스키마를 포함하는 검색 경로(search path)를 설정하여 접근할 수 있습니다. 한정되지 않은 객체는 현재 스키마에 생성됩니다. 현재 스키마는 검색 경로의 맨 앞에 있는 스키마입니다. 그 값을 확인하려면 `CURRENT_SCHEMA` 함수를 사용합니다.

##### 참고 (Note)

검색 경로(search path) 개념과 `CURRENT_SCHEMA` 함수는 Oracle 데이터베이스와 호환되지 않습니다.

`CREATE SCHEMA`에는 스키마 내에 객체를 생성하는 하위 명령이 포함됩니다. 이 하위 명령들은 스키마를 생성한 후 발행되는 별도의 명령과 동일하게 취급됩니다. 생성된 모든 객체는 지정된 사용자가 소유합니다.

## 파라미터 (Parameters)

`username`

새 스키마를 소유할 사용자의 이름입니다. 스키마도 이 이름을 갖게 됩니다. 슈퍼유저만 자신 이외의 사용자가 소유하는 스키마를 생성할 수 있습니다. EDB Postgres Advanced Server에서는 롤 `username`이 이미 존재해야 하지만 스키마는 존재하지 않아야 합니다. Oracle에서는 사용자와 스키마가 모두 존재해야 합니다.

`schema_element`

스키마 내에 생성할 객체를 정의하는 SQL 문입니다. `CREATE TABLE`, `CREATE VIEW`, `GRANT`가 `CREATE SCHEMA`의 절로 허용됩니다. 다른 종류의 객체는 스키마를 생성한 후 별도의 명령으로 생성할 수 있습니다.

## 참고 사항 (Notes)

스키마를 생성하는 슈퍼유저가 아닌 사용자는 현재 데이터베이스에 대한 `CREATE` 권한을 가지고 있어야 합니다.

EDB Postgres Advanced Server에서 `CREATE SCHEMA` 명령의 다른 형식은 Oracle 데이터베이스와 호환되지 않습니다.

## 예제 (Examples)

```sql
CREATE SCHEMA AUTHORIZATION enterprisedb
    CREATE TABLE empjobs (ename VARCHAR2(10), job VARCHAR2(9))
    CREATE VIEW managers AS SELECT ename FROM empjobs WHERE job = 'MANAGER'
    GRANT SELECT ON managers TO PUBLIC;
```
