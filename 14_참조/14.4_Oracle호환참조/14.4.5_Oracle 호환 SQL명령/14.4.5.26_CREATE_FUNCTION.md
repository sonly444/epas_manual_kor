# CREATE FUNCTION — EPAS 18 Reference

> 원문: [EPAS v18 — Reference › Oracle 호환 › 호환 SQL 명령 › CREATE FUNCTION](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/23_create_function/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·코드 이름은 원문 그대로 보존했습니다.

## 이름 (Name)

`CREATE FUNCTION` — 새로운 함수를 정의합니다.

## 구문 개요 (Synopsis)

```sql
CREATE [ OR REPLACE ] FUNCTION <name> [ (<parameters>) ]
  RETURN <data_type>
   [
          IMMUTABLE
        | STABLE
        | VOLATILE
        | DETERMINISTIC
        | [ NOT ] LEAKPROOF
        | CALLED ON NULL INPUT
        | RETURNS NULL ON NULL INPUT
        | STRICT
        | [ EXTERNAL ] SECURITY INVOKER
        | [ EXTERNAL ] SECURITY DEFINER
        | AUTHID DEFINER
        | AUTHID CURRENT_USER
        | PARALLEL { UNSAFE | RESTRICTED | SAFE }
        | COST <execution_cost>
        | ROWS <result_rows>
        | SET configuration_parameter
          { TO <value> | = <value> | FROM CURRENT }
   ...]
{ IS | AS }
    [ PRAGMA AUTONOMOUS_TRANSACTION; ]
    [ <declarations> ]
  BEGIN
    <statements>
  END [ <name> ];
```

## 설명 (Description)

`CREATE FUNCTION`은 새로운 함수를 정의합니다. `CREATE OR REPLACE FUNCTION`은 새 함수를 생성하거나 기존 정의를 대체합니다.

스키마 이름을 포함하면 함수는 지정된 스키마에 생성됩니다. 그렇지 않으면 현재 스키마에 생성됩니다. 새 함수의 이름은 동일한 스키마에서 동일한 입력 인수 타입을 갖는 기존 함수와 일치할 수 없습니다. 그러나 입력 인수 타입이 다른 함수는 이름을 공유할 수 있습니다. 이를 _오버로딩(overloading)_ 이라고 합니다.

##### 참고 (Note)

함수 오버로딩은 EDB Postgres Advanced Server 기능입니다. 저장된 독립형(standalone) 함수의 오버로딩은 Oracle 데이터베이스와 호환되지 않습니다.

기존 함수의 정의를 업데이트하려면 `CREATE OR REPLACE FUNCTION`을 사용합니다. 이 방법으로는 함수의 이름이나 인수 타입을 변경할 수 없습니다. (그 구문은 대신 새 함수를 생성합니다.) `CREATE OR REPLACE FUNCTION`은 또한 기존 함수의 반환 타입을 변경할 수 없습니다. 그렇게 하려면 함수를 삭제하고 다시 생성해야 합니다. 또한 `OUT` 파라미터의 타입은 먼저 함수를 삭제해야만 변경할 수 있습니다.

함수를 생성하는 사용자가 함수의 소유자가 됩니다.

## 파라미터 (Parameters)

`name`

함수의 식별자입니다.

`parameters`

정형 파라미터(formal parameter) 목록입니다.

`data_type`

함수의 `RETURN` 문에서 반환되는 값의 데이터 타입입니다.

`declarations`

변수, 커서, 타입 또는 서브프로그램 선언입니다. 서브프로그램 선언을 포함하려면 다른 모든 변수, 커서, 타입 선언 뒤에 선언합니다.

`statements`

SPL 프로그램 문입니다. `BEGIN - END` 블록은 `EXCEPTION` 섹션을 포함할 수 있습니다.

`IMMUTABLE`

`STABLE`

`VOLATILE`

이 속성들은 쿼리 옵티마이저에 함수의 동작에 대한 정보를 제공합니다. 이 속성 중 하나만 지정할 수 있습니다.

- `IMMUTABLE`을 사용하면 함수가 데이터베이스를 수정할 수 없으며 동일한 인수 값이 주어졌을 때 항상 동일한 결과에 도달해야 함을 나타냅니다. 이 속성은 데이터베이스 조회를 수행하지 않으며 인수 목록에 있는 정보만 사용합니다. 이 절을 포함하면, 모두 상수 인수로 이루어진 함수 호출을 함수 값으로 즉시 대체할 수 있습니다.

- `STABLE`을 사용하면 함수가 데이터베이스를 수정할 수 없으며 단일 테이블 스캔 내에서 동일한 인수 값에 대해 일관되게 동일한 결과를 반환함을 나타냅니다. 그러나 그 결과는 SQL 문 간에 변경될 수 있습니다. 데이터베이스 조회, 파라미터 변수(예: 현재 시간대) 등에 의존하는 함수에 이 선택을 사용합니다.

- `VOLATILE`(기본값)을 사용하면 함수 값이 단일 테이블 스캔 내에서도 변경될 수 있어 최적화를 수행할 수 없음을 나타냅니다. 결과가 예측 가능하더라도 부작용(side effect)이 있는 함수는 volatile로 분류합니다. 이 설정은 호출이 최적화로 제거되는 것을 방지합니다.


`DETERMINISTIC`

`DETERMINISTIC`은 `IMMUTABLE`의 동의어입니다. `DETERMINISTIC` 함수는 데이터베이스를 수정할 수 없으며 동일한 인수 값이 주어졌을 때 항상 동일한 결과에 도달합니다. 데이터베이스 조회를 수행하지 않으며 인수 목록에 직접 존재하는 정보만 사용합니다. 이 절을 포함하면, 모두 상수 인수로 이루어진 함수 호출을 함수 값으로 즉시 대체할 수 있습니다.

`[ NOT ] LEAKPROOF`

`LEAKPROOF` 함수는 부작용이 없으며 함수를 호출하는 데 사용된 값에 대한 정보를 드러내지 않습니다.

`CALLED ON NULL INPUT`

`RETURNS NULL ON NULL INPUT`

`STRICT`

- `CALLED ON NULL INPUT`(기본값)을 사용하면 일부 인수가 `NULL`일 때 프로시저를 정상적으로 호출합니다. 필요한 경우 `NULL` 값을 확인하고 적절하게 대응합니다.

- `RETURNS NULL ON NULL INPUT` 또는 `STRICT`를 사용하면 인수 중 하나라도 `NULL`일 때 프로시저가 항상 `NULL`을 반환함을 나타냅니다. 이 절을 사용하면 `NULL` 인수가 있을 때 프로시저가 실행되지 않습니다. 대신 `NULL` 결과가 가정됩니다.


`[ EXTERNAL ] SECURITY DEFINER`

`SECURITY DEFINER`(기본값)는 함수가 그것을 생성한 사용자의 권한으로 실행되도록 지정합니다. 선택적 키워드 `EXTERNAL`은 SQL 준수를 위해 허용됩니다.

`[ EXTERNAL ] SECURITY INVOKER`

`SECURITY INVOKER` 절을 사용하면 함수를 호출하는 사용자의 권한으로 함수를 실행합니다. 선택적 키워드 `EXTERNAL`은 SQL 준수를 위해 허용됩니다.

`AUTHID DEFINER`

`AUTHID CURRENT_USER`

- `AUTHID DEFINER` 절은 `[EXTERNAL] SECURITY DEFINER`의 동의어입니다. `AUTHID` 절을 생략하거나 `AUTHID DEFINER`를 지정하면, 함수 소유자의 권한이 데이터베이스 객체에 대한 접근 권한을 결정합니다.

- `AUTHID CURRENT_USER` 절은 `[EXTERNAL] SECURITY INVOKER`의 동의어입니다. `AUTHID CURRENT_USER`를 지정하면, 함수를 실행하는 현재 사용자의 권한이 접근 권한을 결정합니다.


`PARALLEL { UNSAFE | RESTRICTED | SAFE }`

`PARALLEL` 절은 병렬 순차 스캔(병렬 모드)의 사용을 활성화합니다. 병렬 순차 스캔은 직렬 순차 스캔과 대조적으로, 쿼리 중에 여러 워커(worker)를 사용하여 릴레이션을 병렬로 스캔합니다.

- `UNSAFE`(기본값)로 설정되면 함수는 병렬 모드에서 실행할 수 없습니다. SQL 문에 이러한 함수가 존재하면 직렬 실행 계획이 강제됩니다.

- `RESTRICTED`로 설정되면 함수는 병렬 모드에서 실행할 수 있지만, 실행은 병렬 그룹 리더로 제한됩니다. 특정 릴레이션에 대한 조건(qualification)에 병렬 제한(parallel restricted) 요소가 있으면 해당 릴레이션은 병렬 처리 대상으로 선택되지 않습니다.

- `SAFE`로 설정되면 함수는 제한 없이 병렬 모드에서 실행할 수 있습니다.


`COST execution_cost`

`execution_cost`는 `cpu_operator_cost` 단위로 함수의 예상 실행 비용을 나타내는 양수입니다. 함수가 집합(set)을 반환하는 경우, 이는 반환되는 행당 비용입니다. 값이 클수록 플래너가 필요 이상으로 자주 함수를 평가하는 것을 피하려고 합니다.

`ROWS result_rows`

`result_rows`는 플래너가 함수가 반환할 것으로 예상하는 행 수를 나타내는 양수입니다. 이 옵션은 함수가 집합을 반환하도록 선언된 경우에만 허용됩니다. 기본 가정은 `1000`개 행입니다.

`SET configuration_parameter { TO value | = value | FROM CURRENT }`

`SET` 절은 함수에 진입할 때 지정된 구성 파라미터를 지정된 값으로 설정하고, 함수가 종료될 때 이전 값으로 복원되도록 합니다. `SET FROM CURRENT`는 함수에 진입할 때 적용할 값으로 세션의 현재 파라미터 값을 저장합니다.

`SET` 절이 함수에 연결되어 있으면, 함수 내부에서 동일한 변수에 대해 실행된 `SET LOCAL` 명령의 효과가 함수로 제한됩니다. 구성 파라미터의 이전 값은 함수 종료 시 복원됩니다. 일반 `SET` 명령(`LOCAL` 없이)은 이전의 `SET LOCAL` 명령과 유사하게 `SET` 절을 재정의합니다. 그러한 명령의 효과는 현재 트랜잭션이 롤백되지 않는 한 프로시저 종료 후에도 지속됩니다.

`PRAGMA AUTONOMOUS_TRANSACTION`

`PRAGMA AUTONOMOUS_TRANSACTION`은 함수를 자율 트랜잭션(autonomous transaction)으로 설정하는 지시문입니다.

##### 참고 (Note)

`STRICT`, `LEAKPROOF`, `PARALLEL`, `COST`, `ROWS`, `SET` 키워드는 EDB Postgres Advanced Server를 위한 확장 기능을 제공하며 Oracle에서는 지원되지 않습니다.

## 참고 사항 (Notes)

EDB Postgres Advanced Server는 함수 오버로딩을 허용합니다. 즉, 여러 다른 함수에 동일한 이름을 사용할 수 있습니다. 그러나 이들은 서로 구별되는 입력(`IN`, `IN OUT`) 인수 데이터 타입을 가져야 합니다.

## 예제 (Examples)

함수 `emp_comp`은 두 개의 숫자를 입력으로 받아 계산된 값을 반환합니다. `SELECT` 명령은 함수의 사용을 보여줍니다.

```sql
CREATE OR REPLACE FUNCTION emp_comp (
    p_sal           NUMBER,
    p_comm          NUMBER
) RETURN NUMBER
IS
BEGIN
    RETURN (p_sal + NVL(p_comm, 0)) * 24;
END;
```

```sql
SELECT ename "Name", sal "Salary", comm "Commission", emp_comp(sal, comm)
    "Total Compensation"  FROM emp;
```

출력

```text

--------+---------+------------+--------------------

 ALLEN  | 1600.00 |     300.00 |           45600.00

 JONES  | 2975.00 |            |           71400.00
 MARTIN | 1250.00 |    1400.00 |           63600.00
 BLAKE  | 2850.00 |            |           68400.00
 CLARK  | 2450.00 |            |           58800.00
 SCOTT  | 3000.00 |            |           72000.00
 KING   | 5000.00 |            |          120000.00
```

함수 `sal_range`는 급여가 지정된 범위에 속하는 직원 수를 반환합니다. 다음 익명 블록은 처음 두 호출에서 인수의 기본값을 사용하여 함수를 여러 번 호출합니다:

```sql
CREATE OR REPLACE FUNCTION sal_range (
    p_sal_min       NUMBER DEFAULT 0,
    p_sal_max       NUMBER DEFAULT 10000
) RETURN INTEGER
IS
    v_count         INTEGER;
BEGIN
    SELECT COUNT(*) INTO v_count FROM emp
        WHERE sal BETWEEN p_sal_min AND p_sal_max;
    RETURN v_count;
END;

BEGIN
    DBMS_OUTPUT.PUT_LINE('Number of employees with a salary: ' ||
        sal_range);
    DBMS_OUTPUT.PUT_LINE('Number of employees with a salary of at least '
        || '$2000.00: ' || sal_range(2000.00));
    DBMS_OUTPUT.PUT_LINE('Number of employees with a salary between '
        || '$2000.00 and $3000.00: ' || sal_range(2000.00, 3000.00));

END;

Number of employees with a salary: 14
Number of employees with a salary of at least $2000.00: 6
Number of employees with a salary between $2000.00 and $3000.00: 5
```

이 예제는 함수 선언에서 `AUTHID CURRENT_USER` 절과 `STRICT` 키워드를 사용합니다:

```sql
CREATE OR REPLACE FUNCTION dept_salaries(dept_id int) RETURN NUMBER
  STRICT
  AUTHID CURRENT_USER
BEGIN
  RETURN QUERY (SELECT sum(salary) FROM emp WHERE deptno = id);
END;
```

전달된 입력 파라미터 중 하나라도 `NULL`이면 `NULL`을 반환하도록 `STRICT` 키워드를 포함합니다. `NULL` 값이 전달되면 함수가 실행되지 않습니다.

`dept_salaries` 함수는 함수를 호출하는 롤의 권한으로 실행됩니다. 현재 사용자가 `emp` 테이블을 조회하는 `SELECT` 문(직원 급여를 표시하기 위한)을 수행할 권한이 없으면, 함수는 오류를 보고합니다. 함수를 정의한 롤과 연결된 권한을 사용하려면, `AUTHID CURRENT_USER` 절을 `AUTHID DEFINER` 절로 대체합니다.

## 기타 프래그마(패키지 사양에 선언됨) (Other Pragmas (declared in a package specification))

`PRAGMA RESTRICT_REFERENCES`

EDB Postgres Advanced Server는 `PRAGMA RESTRICT_REFERENCES`를 참조하는 구문을 수락하지만 무시합니다.
