# CREATE PROFILE — EPAS 18 Reference

> 원문: [EPAS v18 — Reference › Oracle 호환 › 호환 SQL 명령 › CREATE PROFILE](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/29_create_profile/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·코드 이름은 원문 그대로 보존했습니다.

## 이름 (Name)

`CREATE PROFILE` — 프로파일을 생성합니다.

## 구문 개요 (Synopsis)

```sql
CREATE PROFILE <profile_name>
       [LIMIT {<parameter value>} ... ];
```

## 설명 (Description)

`CREATE PROFILE`은 프로파일을 생성합니다. EDB Postgres Advanced Server가 적용하는 규칙을 지정하려면 `LIMIT` 절과 공백으로 구분된 하나 이상의 `parameter/value` 쌍을 포함합니다.

EDB Postgres Advanced Server는 `DEFAULT`라는 이름의 기본 프로파일을 생성합니다. `CREATE ROLE` 명령을 사용하여 롤을 생성하면, 새 롤은 `DEFAULT` 프로파일과 연결됩니다. 이전 버전의 EDB Postgres Advanced Server에서 EDB Postgres Advanced Server 10으로 업그레이드하는 경우, 업그레이드 프로세스는 업그레이드된 버전의 롤을 `DEFAULT` 프로파일로 생성합니다.

`CREATE PROFILE`을 사용하려면 슈퍼유저여야 합니다.

EDB Postgres Advanced Server가 적용하는 규칙을 지정하려면 `LIMIT` 절과 공백으로 구분된 하나 이상의 `parameter/value` 쌍을 포함합니다.

## 파라미터 (Parameters)

`profile_name`

프로파일의 이름입니다.

`parameter`

모니터링할 규칙에 대한 비밀번호 속성입니다.

`value`

서버가 조치를 취하기 전에 `parameter`가 도달해야 하는 값입니다.

EDB Postgres Advanced Server는 각 파라미터에 대해 다음 값들을 지원합니다:

`FAILED_LOGIN_ATTEMPTS`는 서버가 `PASSWORD_LOCK_TIME`에 지정된 시간 동안 사용자의 계정을 잠그기 전에 사용자가 할 수 있는 실패한 로그인 시도 횟수를 지정합니다. 지원되는 값은 다음과 같습니다:

- `0`보다 큰 `INTEGER` 값.
- `DEFAULT` — `DEFAULT` 프로파일에 지정된 `FAILED_LOGIN_ATTEMPTS` 값.
- `UNLIMITED` — 연결하는 사용자는 무제한의 실패한 로그인 시도를 할 수 있습니다.

`PASSWORD_LOCK_TIME`은 `FAILED_LOGIN_ATTEMPTS` 때문에 잠긴 계정을 서버가 잠금 해제하기 전에 경과해야 하는 시간을 지정합니다. 지원되는 값은 다음과 같습니다:

- `0` 이상의 `NUMERIC` 값. 하루의 소수 부분을 지정하려면 소수 값을 지정합니다. 예를 들어, 4일 12시간을 지정하려면 값 `4.5`를 사용합니다.
- `DEFAULT` — `DEFAULT` 프로파일에 지정된 `PASSWORD_LOCK_TIME` 값.
- `UNLIMITED` — 데이터베이스 슈퍼유저가 수동으로 잠금 해제할 때까지 계정이 잠깁니다.

`PASSWORD_LIFE_TIME`은 사용자에게 새 비밀번호를 제공하라는 메시지가 표시되기 전에 현재 비밀번호를 사용할 수 있는 일수를 지정합니다. `PASSWORD_LIFE_TIME` 절을 사용할 때 `PASSWORD_GRACE_TIME` 절을 포함하여 비밀번호가 만료된 후 사용자가 비밀번호 변경을 강제받기까지 경과할 일수를 지정합니다. `PASSWORD_GRACE_TIME`을 지정하지 않으면, 비밀번호는 `PASSWORD_GRACE_TIME`의 기본값에 지정된 날에 만료되며, 사용자는 새 비밀번호가 제공될 때까지 어떤 명령도 실행할 수 없습니다. 지원되는 값은 다음과 같습니다:

- `0` 이상의 `NUMERIC` 값. 하루의 소수 부분을 지정하려면 소수 값을 지정합니다. 예를 들어, 4일 12시간을 지정하려면 값 `4.5`를 사용합니다.
- `DEFAULT` — `DEFAULT` 프로파일에 지정된 `PASSWORD_LIFE_TIME` 값.
- `UNLIMITED` — 비밀번호에 만료일이 없습니다.

`PASSWORD_GRACE_TIME`은 비밀번호가 만료된 후 사용자가 비밀번호 변경을 강제받기까지의 유예 기간의 길이를 지정합니다. 유예 기간이 만료되면, 사용자는 연결할 수 있지만 만료된 비밀번호를 업데이트할 때까지 어떤 명령도 실행할 수 없습니다. 지원되는 값은 다음과 같습니다:

- `0` 이상의 `NUMERIC` 값. 하루의 소수 부분을 지정하려면 소수 값을 지정합니다. 예를 들어, 4일 12시간을 지정하려면 값 `4.5`를 사용합니다.
- `DEFAULT` — `DEFAULT` 프로파일에 지정된 `PASSWORD_GRACE_TIME` 값.
- `UNLIMITED` — 유예 기간이 무한합니다.

`PASSWORD_REUSE_TIME`은 사용자가 비밀번호를 재사용하기 전에 기다려야 하는 일수를 지정합니다. `PASSWORD_REUSE_TIME`과 `PASSWORD_REUSE_MAX` 파라미터를 함께 사용합니다. 이 파라미터 중 하나에 유한한 값을 지정하고 다른 하나가 `UNLIMITED`이면, 이전 비밀번호는 절대 재사용할 수 없습니다. 두 파라미터 모두 `UNLIMITED`로 설정되면 비밀번호 재사용에 제한이 없습니다. 지원되는 값은 다음과 같습니다:

- `0` 이상의 `NUMERIC` 값. 하루의 소수 부분을 지정하려면 소수 값을 지정합니다. 예를 들어, 4일 12시간을 지정하려면 값 `4.5`를 사용합니다.
- `DEFAULT` — `DEFAULT` 프로파일에 지정된 `PASSWORD_REUSE_TIME` 값.
- `UNLIMITED` — 비밀번호를 제한 없이 재사용할 수 있습니다.

`PASSWORD_REUSE_MAX`는 비밀번호를 재사용할 수 있기 전에 발생해야 하는 비밀번호 변경 횟수를 지정합니다. `PASSWORD_REUSE_TIME`과 `PASSWORD_REUSE_MAX` 파라미터를 함께 사용합니다. 이 파라미터 중 하나에 유한한 값을 지정하고 다른 하나가 `UNLIMITED`이면, 이전 비밀번호는 절대 재사용할 수 없습니다. 두 파라미터 모두 `UNLIMITED`로 설정되면 비밀번호 재사용에 제한이 없습니다. 지원되는 값은 다음과 같습니다:

- `0` 이상의 `INTEGER` 값.
- `DEFAULT` — `DEFAULT` 프로파일에 지정된 `PASSWORD_REUSE_MAX` 값.
- `UNLIMITED` — 비밀번호를 제한 없이 재사용할 수 있습니다.

`PASSWORD_VERIFY_FUNCTION`은 비밀번호 복잡성을 지정합니다. 지원되는 값은 다음과 같습니다:

- PL/SQL 함수의 이름.
- `DEFAULT` — `DEFAULT` 프로파일에 지정된 `PASSWORD_VERIFY_FUNCTION` 값.
- `NULL`

`PASSWORD_ALLOW_HASHED`는 암호화된 비밀번호를 사용할 수 있는지 여부를 지정합니다. `TRUE`를 지정하면, 시스템은 사용자가 클라이언트 측에서 계산된 해시 암호화 비밀번호를 지정하여 비밀번호를 변경할 수 있도록 허용합니다. 그러나 `FALSE`를 지정하면, 검증을 위해 비밀번호를 평문(plain-text) 형태로 지정해야 합니다. 그렇지 않으면 서버가 암호화된 비밀번호를 수신할 때 오류가 발생합니다. 지원되는 값은 다음과 같습니다:

- `BOOLEAN` 값 `TRUE/ON/YES/1` 또는 `FALSE/OFF/NO/0`.
- `DEFAULT` — `DEFAULT` 프로파일에 지정된 `PASSWORD_ALLOW_HASHED` 값.

##### 참고 (Note)

`PASSWORD_ALLOW_HASHED`는 Oracle과 호환되지 않습니다.

비밀번호를 확인할 때 문제를 피하려면 PASSWORD_VERIFY_FUNCTION을 PASSWORD_ALLOW_HASHED와 함께 사용하세요. 비밀번호가 해시된 형태로 수락되는 대신 제대로 확인될 수 있도록 PASSWORD_ALLOW_HASHED가 false로 설정되어 있는지 확인하세요.

`INACTIVE_ACCOUNT_TIME`은 계정이 자동으로 잠기기 전에 비활성(성공적인 로그인 없이) 상태로 유지될 수 있는 일수를 정의합니다. 이 파라미터는 사용되지 않는 계정을 비활성화하고 휴면 계정이 악용될 위험을 줄여 보안을 강화합니다. 사용자 계정이 비활성으로 인해 잠기면, 슈퍼유저만 잠금 해제할 수 있습니다. 비활성은 `pg_authid`의 `rollastlogin` 열에서 결정됩니다. 이 값이 NULL이면 대신 롤의 생성 날짜가 사용됩니다. 지원되는 값은 다음과 같습니다:

- `DEFAULT` — `DEFAULT` 프로파일에 지정된 `INACTIVE_ACCOUNT_TIME` 값.
- `UNLIMITED` — 비활성으로 인해 계정이 절대 잠기지 않습니다.
- 15에서 24855 사이의 임의의 값.

## 참고 사항 (Notes)

프로파일을 제거하려면 `DROP PROFILE` 명령을 사용합니다.

## 예제 (Examples)

이 명령은 `acctg`라는 이름의 프로파일을 생성합니다. 이 프로파일은 사용자가 다섯 번의 시도에서 올바른 비밀번호로 인증하지 못하면 계정이 하루 동안 잠기도록 지정합니다:

```sql
CREATE PROFILE acctg LIMIT
       FAILED_LOGIN_ATTEMPTS 5
       PASSWORD_LOCK_TIME 1;
```

이 명령은 `sales`라는 이름의 프로파일을 생성합니다. 이 프로파일은 사용자가 90일마다 비밀번호를 변경해야 함을 지정합니다:

```sql
CREATE PROFILE sales LIMIT
       PASSWORD_LIFE_TIME 90
       PASSWORD_GRACE_TIME 3;
```

사용자가 프로파일에 지정된 90일이 지나기 전에 비밀번호를 변경하지 않으면, 로그인 시 경고가 발생합니다. 3일의 유예 기간 후에는 비밀번호를 변경할 때까지 계정이 어떤 명령도 호출할 수 없습니다.

이 명령은 `accts`라는 이름의 프로파일을 생성합니다. 이 프로파일은 사용자가 비밀번호의 마지막 사용으로부터 180일 이내에 비밀번호를 재사용할 수 없으며, 재사용하기 전에 최소 다섯 번 비밀번호를 변경해야 함을 지정합니다:

```sql
CREATE PROFILE accts LIMIT
       PASSWORD_REUSE_TIME 180
       PASSWORD_REUSE_MAX 5;
```

이 명령은 `resources`라는 이름의 프로파일을 생성합니다. 이 프로파일은 제공된 비밀번호가 복잡성에 대한 표준을 충족하는지 검증하는 `password_rules`라는 이름의 사용자 정의 함수를 호출합니다:

```sql
CREATE PROFILE resources LIMIT
       PASSWORD_VERIFY_FUNCTION password_rules;
```
