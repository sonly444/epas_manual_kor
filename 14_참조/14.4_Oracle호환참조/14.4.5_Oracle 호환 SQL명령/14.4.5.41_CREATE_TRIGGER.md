# CREATE TRIGGER v18

## 이름 (Name)

`CREATE TRIGGER` — 단순 트리거(simple trigger)를 정의합니다.

## 구문 개요 (Synopsis)

```sql
CREATE [ OR REPLACE ] TRIGGER <name>
  { BEFORE | AFTER | INSTEAD OF }
  { INSERT | UPDATE | DELETE | TRUNCATE }
      [ OR { INSERT | UPDATE | DELETE | TRUNCATE} ] [, ...]
    ON <table>
  [ REFERENCING { OLD AS <old> | NEW AS <new> } ...]
  [ FOR EACH ROW ]
  [ WHEN <condition> ]
  [ DECLARE\
      [ PRAGMA AUTONOMOUS_TRANSACTION; ]\
      <declaration>; [, ...] ]
    BEGIN
      <statement>; [, ...]
  [ EXCEPTION\
    { WHEN <exception> [ OR <exception> ] [...] THEN\
        <statement>; [, ...] } [, ...]\
  ]
    END
```

## 이름 (Name)

`CREATE TRIGGER` — 복합 트리거(compound trigger)를 정의합니다.

## 구문 개요 (Synopsis)

```sql
CREATE [ OR REPLACE ] TRIGGER <name>
  FOR { INSERT | UPDATE | DELETE | TRUNCATE }
        [ OR { INSERT | UPDATE | DELETE | TRUNCATE } ] [, ...]
           ON <table>
       [ REFERENCING { OLD AS <old> | NEW AS <new> } ...]
       [ WHEN <condition> ]
       COMPOUND TRIGGER
       [ <private_declaration>; ] ...
       [ <procedure_or_function_definition> ] ...
       <compound_trigger_definition>
        END
```

여기서 `private_declaration`은 어떤 프로시저나 함수든 접근할 수 있는 프라이빗 변수의 식별자입니다. 프라이빗 변수는 0개, 1개, 또는 여러 개일 수 있습니다. `private_declaration`은 다음 중 하나일 수 있습니다.

- 변수 선언(Variable declaration)
- 레코드 선언(Record declaration)
- 컬렉션 선언(Collection declaration)
- `REF CURSOR` 및 커서 변수 선언
- 레코드, 컬렉션, `REF CURSOR` 커서에 대한 `TYPE` 정의
- 예외(Exception)
- 객체 변수 선언(Object variable declaration)

여기서 `procedure_or_function_definition` :=

```text
procedure_definition | function_definition
```

여기서 `procedure_definition` :=

```sql
PROCEDURE proc_name[ argument_list ]
  [ options_list ]
  { IS | AS }
    procedure_body
  END [ proc_name ];
```

여기서 `procedure_body` :=

```sql
[ declaration; ] [, ...]
BEGIN
  statement; [...]
[ EXCEPTION\
   { WHEN exception [OR exception] [...]] THEN statement; }
   [...]
]
```

여기서 `function_definition` :=

```sql
FUNCTION func_name [ argument_list ]
  RETURN rettype [ DETERMINISTIC ]
  [ options_list ]
  { IS | AS }
    function_body
  END [ func_name ] ;
```

여기서 `function_body` :=

```sql
[ declaration; ] [, ...]
BEGIN
  statement; [...]
[ EXCEPTION\
  { WHEN exception [ OR exception ] [...] THEN statement; }\
  [...]\
]
```

여기서 `compound_trigger_definition` :=

```sql
{ compound_trigger_event } { IS | AS }
  compound_trigger_body
END [ compound_trigger_event ] [ ... ]
```

여기서 `compound_trigger_event` :=

```sql
[ BEFORE STATEMENT | BEFORE EACH ROW | AFTER EACH ROW | AFTER STATEMENT  | INSTEAD OF EACH ROW ]
```

여기서 `compound_trigger_body` :=

```sql
[ declaration; ] [, ...]
BEGIN
  statement; [...]
[ EXCEPTION\
   { WHEN exception [OR exception] [...] THEN statement; }\
   [...]\
]
```

## 설명 (Description)

`CREATE TRIGGER`는 새 트리거를 정의합니다. `CREATE OR REPLACE TRIGGER`는 트리거를 생성하거나 기존 정의를 교체합니다.

`CREATE TRIGGER` 키워드를 사용하여 새 트리거를 생성하는 경우, 새 트리거의 이름은 동일한 테이블에 정의된 기존 트리거와 일치할 수 없습니다. 트리거는 트리거링 이벤트가 정의된 테이블과 동일한 스키마에 생성됩니다.

기존 트리거의 정의를 갱신하는 경우 `CREATE OR REPLACE TRIGGER` 키워드를 사용합니다.

Oracle과 호환되는 구문을 사용하여 트리거를 생성하면 트리거는 `SECURITY DEFINER` 함수로 실행됩니다.

## 파라미터 (Parameters)

`name`

생성할 트리거의 이름입니다.

`BEFORE | AFTER`

트리거가 트리거링 이벤트 이전에 실행될지 이후에 실행될지를 결정합니다.

`INSTEAD OF`

갱신 가능한 뷰(updatable view)를 수정합니다. 트리거는 기저 테이블을 적절히 갱신하기 위해 실행됩니다. `INSTEAD OF` 트리거는 갱신되거나 수정되는 뷰의 각 행에 대해 실행됩니다.

`INSERT | UPDATE | DELETE | TRUNCATE`

트리거링 이벤트를 정의합니다.

`table`

트리거링 이벤트가 발생하는 테이블 또는 뷰의 이름입니다.

`condition`

트리거가 실행될지를 결정하는 부울(Boolean) 표현식입니다. `condition`이 `TRUE`로 평가되면 트리거가 실행됩니다.

- 단순 트리거 정의에 `FOR EACH ROW` 키워드가 포함되어 있으면 `WHEN` 절은 `OLD.column_name` 또는 `NEW.column_name`을 작성하여 이전 또는 새 행 값의 컬럼을 참조할 수 있습니다. `INSERT` 트리거는 `OLD`를 참조할 수 없고, `DELETE` 트리거는 `NEW`를 참조할 수 없습니다.

- 복합 트리거 정의에 `WHEN` 절을 가진 문 수준(statement-level) 트리거가 포함되어 있으면, 트리거는 `WHEN` 절의 표현식을 평가하지 않고 실행됩니다. 마찬가지로 복합 트리거 정의에 `WHEN` 절을 가진 행 수준(row-level) 트리거가 포함되어 있으면, 표현식이 `TRUE`로 평가될 경우 트리거가 실행됩니다.

- 트리거에 `INSTEAD OF` 키워드가 포함되어 있으면 `WHEN` 절을 포함할 수 없습니다. `WHEN` 절은 서브쿼리를 포함할 수 없습니다.


`REFERENCING { OLD AS old | NEW AS new } ...`

이전 행과 새 행을 참조하는 `REFERENCING` 절입니다. 이 절은 `old`를 `old`라는 이름의 식별자 또는 모두 소문자로 저장되는 동등한 것으로만 대체할 수 있다는 점에서 제한됩니다. 예로는 `REFERENCING OLD AS old`, `REFERENCING OLD AS OLD`, `REFERENCING OLD AS "old"`가 있습니다. 또한 `new`는 `new`라는 이름의 식별자 또는 모두 소문자로 저장되는 동등한 것으로만 대체할 수 있습니다. 예로는 `REFERENCING NEW AS new`, `REFERENCING NEW AS NEW`, `REFERENCING NEW AS "new"`가 있습니다.

`REFERENCING NEW AS New OLD AS Old`처럼 `REFERENCING` 절에서 `OLD AS old`와 `NEW AS new` 구문 중 하나 또는 둘 다를 지정할 수 있습니다.

이 절은 `old` 또는 `new` 이외의 식별자를 사용할 수 없다는 점에서 Oracle 데이터베이스와 호환되지 않습니다.

`FOR EACH ROW`

트리거링 이벤트에 의해 영향을 받는 모든 행에 대해 트리거를 한 번씩 실행할지 아니면 SQL 문당 한 번만 실행할지를 결정합니다. 이 파라미터를 지정하면 트리거는 영향을 받는 모든 행에 대해 한 번씩 실행됩니다(행 수준 트리거). 그렇지 않으면 트리거는 문 수준 트리거입니다.

`PRAGMA AUTONOMOUS_TRANSACTION`

`PRAGMA AUTONOMOUS_TRANSACTION`은 트리거를 자율 트랜잭션(autonomous transaction)으로 설정하는 지시어(directive)입니다.

`declaration`

변수, 타입, `REF CURSOR`, 또는 하위 프로그램(subprogram) 선언입니다. 하위 프로그램 선언을 포함하는 경우, 다른 모든 변수, 타입, `REF CURSOR` 선언 이후에 선언합니다.

`statement`

SPL 프로그램 문입니다. `DECLARE - BEGIN - END` 블록은 SPL 문으로 간주됩니다. 따라서 트리거 본문은 중첩된 블록을 포함할 수 있습니다.

`exception`

`NO_DATA_FOUND` 및 `OTHERS`와 같은 예외 조건 이름입니다.

## 예제 (Examples)

이 예제는 트리거링 문(테이블 `emp`에 대한 insert, update, delete)이 실행된 후에 실행되는 문 수준 트리거를 보여줍니다.

```sql
CREATE OR REPLACE TRIGGER user_audit_trig
    AFTER INSERT OR UPDATE OR DELETE ON emp
DECLARE
    v_action        VARCHAR2(24);
BEGIN
    IF INSERTING THEN
        v_action := ' added employee(s) on ';
    ELSIF UPDATING THEN
        v_action := ' updated employee(s) on ';
    ELSIF DELETING THEN
        v_action := ' deleted employee(s) on ';
    END IF;
    DBMS_OUTPUT.PUT_LINE('User ' || USER || v_action ||
        TO_CHAR(SYSDATE,'YYYY-MM-DD'));
END;
```

이 예제는 테이블 `emp`에서 각 행이 삽입, 갱신, 또는 삭제되기 전에 실행되는 행 수준 트리거입니다.

```sql
CREATE OR REPLACE TRIGGER emp_sal_trig
    BEFORE DELETE OR INSERT OR UPDATE ON emp
    FOR EACH ROW
DECLARE
    sal_diff       NUMBER;
BEGIN
    IF INSERTING THEN
        DBMS_OUTPUT.PUT_LINE('Inserting employee ' || :NEW.empno);
        DBMS_OUTPUT.PUT_LINE('..New salary: ' || :NEW.sal);
    END IF;
    IF UPDATING THEN
        sal_diff := :NEW.sal - :OLD.sal;
        DBMS_OUTPUT.PUT_LINE('Updating employee ' || :OLD.empno);
        DBMS_OUTPUT.PUT_LINE('..Old salary: ' || :OLD.sal);
        DBMS_OUTPUT.PUT_LINE('..New salary: ' || :NEW.sal);
        DBMS_OUTPUT.PUT_LINE('..Raise     : ' || sal_diff);
    END IF;
    IF DELETING THEN
        DBMS_OUTPUT.PUT_LINE('Deleting employee ' || :OLD.empno);
        DBMS_OUTPUT.PUT_LINE('..Old salary: ' || :OLD.sal);
    END IF;
END;
```

이 예제는 테이블 `emp`에 복합 트리거 `hr_trigger`를 정의하여 직원 급여의 변경을 기록하는 복합 트리거를 보여줍니다.

`emp`라는 테이블을 생성합니다.

```sql
CREATE TABLE emp(EMPNO INT, ENAME TEXT, SAL INT, DEPTNO INT);
CREATE TABLE
```

`hr_trigger`라는 복합 트리거를 생성합니다. 이 트리거는 네 가지 타이밍 포인트를 각각 사용하여 `INSERT`, `UPDATE`, 또는 `DELETE` 문으로 급여를 수정합니다. 전역 선언 섹션에서 초기 급여는 `10,000`으로 선언됩니다.

```sql
CREATE OR REPLACE TRIGGER hr_trigger
  FOR INSERT OR UPDATE OR DELETE ON emp
    COMPOUND TRIGGER
  -- Global declaration.
  var_sal NUMBER := 10000;

  BEFORE STATEMENT IS
  BEGIN
    var_sal := var_sal + 1000;
    DBMS_OUTPUT.PUT_LINE('Before Statement: ' || var_sal);
  END BEFORE STATEMENT;

  BEFORE EACH ROW IS
  BEGIN
    var_sal := var_sal + 1000;
    DBMS_OUTPUT.PUT_LINE('Before Each Row: ' || var_sal);
  END BEFORE EACH ROW;

  AFTER EACH ROW IS
  BEGIN
    var_sal := var_sal + 1000;
    DBMS_OUTPUT.PUT_LINE('After Each Row: ' || var_sal);
  END AFTER EACH ROW;

  AFTER STATEMENT IS
  BEGIN
    var_sal := var_sal + 1000;
    DBMS_OUTPUT.PUT_LINE('After Statement: ' || var_sal);
  END AFTER STATEMENT;

END hr_trigger;

Output: Trigger created.
```

테이블 `emp`에 레코드를 `INSERT`합니다.

```sql
INSERT INTO emp (EMPNO, ENAME, SAL, DEPTNO) VALUES(1111,'SMITH', 10000, 20);
```

`INSERT` 문은 다음과 같은 출력을 생성합니다.

출력

```text
Before Statement: 11000
Before each row: 12000
After each row: 13000
After statement: 14000
INSERT 0 1
```

`UPDATE` 문은 특정 사원 번호에 대해 급여를 `15000`으로 설정하여 직원 급여 레코드를 갱신합니다.

```sql

```


```sql

```

`DELETE` 문은 다음과 같은 출력을 생성합니다.

`TRUNCATE` 문은 `emp` 테이블에서 모든 레코드를 제거합니다.

```sql
CREATE OR REPLACE TRIGGER hr_trigger
FOR TRUNCATE ON emp
    COMPOUND TRIGGER
  -- Global declaration.
var_sal NUMBER := 10000;
BEFORE STATEMENT IS
BEGIN
    var_sal := var_sal + 1000;
    DBMS_OUTPUT.PUT_LINE('Before Statement: ' || var_sal);
END BEFORE STATEMENT;

AFTER STATEMENT IS
BEGIN
    var_sal := var_sal + 1000;
    DBMS_OUTPUT.PUT_LINE('After Statement: ' || var_sal);
END AFTER STATEMENT;

END hr_trigger;
```


##### 참고 (Note)

`TRUNCATE` 문은 `BEFORE STATEMENT` 또는 `AFTER STATEMENT` 타이밍 포인트에서만 사용할 수 있습니다.

이 예제는 `emp` 테이블에 `hr_trigger`라는 복합 트리거를 생성합니다. 이것은 `INSERT`, `UPDATE`, 또는 `DELETE` 문이 `emp` 테이블에 영향을 줄 때마다 직원 급여를 확인하고 출력하는 `WHEN` 조건입니다. 데이터베이스는 행 수준 트리거에 대해 `WHEN` 조건을 평가하며, `WHEN` 조건이 `TRUE`로 평가되면 트리거가 행당 한 번씩 실행됩니다. 문 수준 트리거는 `WHEN` 조건과 관계없이 실행됩니다.

```sql
CREATE OR REPLACE TRIGGER hr_trigger
FOR INSERT OR UPDATE OR DELETE ON emp
REFERENCING NEW AS new OLD AS old
WHEN (old.sal > 5000 OR new.sal < 8000)
    COMPOUND TRIGGER

BEFORE STATEMENT IS
BEGIN
    DBMS_OUTPUT.PUT_LINE('Before Statement');
END BEFORE STATEMENT;

BEFORE EACH ROW IS
BEGIN
    DBMS_OUTPUT.PUT_LINE('Before Each Row: ' || :OLD.sal ||' ' || :NEW.sal);
END BEFORE EACH ROW;

AFTER EACH ROW IS
BEGIN
    DBMS_OUTPUT.PUT_LINE('After Each Row: ' || :OLD.sal ||' ' || :NEW.sal);
END AFTER EACH ROW;

AFTER STATEMENT IS
BEGIN
    DBMS_OUTPUT.PUT_LINE('After Statement');
END AFTER STATEMENT;

END hr_trigger;
```
