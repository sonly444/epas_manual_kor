# ALL_CONSTRAINTS — EPAS 18 Oracle 카탈로그뷰

> 원문: [EPAS v18 — Reference › Oracle compatibility › Catalog views › Oracle catalog views › ALL_CONSTRAINTS](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_cat_views/oracle_compatible_views/04_all_constraints/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 뷰·컬럼 이름은 원문 그대로 보존했습니다.

`ALL_CONSTRAINTS` 뷰는 현재 사용자가 접근할 수 있는 테이블에 설정된 제약 조건에 대한 정보를 제공합니다.

| 컬럼                  | 타입        | 설명                                                                                                                                                                                                                                                                                                    |
| --------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `owner`             | `TEXT`    | 제약 조건 소유자의 사용자 이름.                                                                                                                                                                                                                                                                         |
| `schema_name`       | `TEXT`    | 제약 조건이 속한 스키마의 이름.                                                                                                                                                                                                                                                                         |
| `constraint_name`   | `TEXT`    | 제약 조건의 이름.                                                                                                                                                                                                                                                                                       |
| `constraint_type`   | `TEXT`    | 제약 조건 유형. 가능한 값:`C` – 체크 제약 조건; `F` – 외래 키 제약 조건; `P` – 기본 키 제약 조건; `U` – 고유 키 제약 조건; `R` – 참조 무결성 제약 조건; `V` – 뷰에 대한 제약 조건; `O` – 뷰에 대한 read-only 제약 조건; `N` – NOT NULL 제약 조건; `X` – exclusion 제약 조건. |
| `table_name`        | `TEXT`    | 제약 조건이 속한 테이블의 이름.                                                                                                                                                                                                                                                                         |
| `search_condition`  | `TEXT`    | 체크 제약 조건에 적용되는 검색 조건.  (※ 2026-09-03 : constraint_type이 'P', 'F', 'N' 인 경우 선생 6자가 누락되어 표시되는 오류가 있습니다. 추 후 릴리즈에서 개선될 예정입니다. )                                                                                                                                                                                                                                                                   |
| `r_owner`           | `TEXT`    | 참조 제약 조건이 참조하는 테이블의 소유자.                                                                                                                                                                                                                                                              |
| `r_constraint_name` | `TEXT`    | 참조된 테이블에 대한 제약 조건 정의의 이름.                                                                                                                                                                                                                                                             |
| `delete_rule`       | `TEXT`    | 참조 제약 조건의 삭제 규칙. 가능한 값:`C` – cascade; `R` – restrict; `A` – no action; `N` – set null; `D` – set default. 참조 제약 조건이 아닌 경우 `" "`가 반환됩니다.                                                                                                                |
| `deferrable`        | `BOOLEAN` | 제약 조건이 지연 가능(deferrable)한지 여부(`T` 또는 `F`).                                                                                                                                                                                                                                           |
| `deferred`          | `BOOLEAN` | 제약 조건이 지연(deferred)되었는지 여부(`T` 또는 `F`).                                                                                                                                                                                                                                              |
| `index_owner`       | `TEXT`    | 인덱스 소유자의 사용자 이름.                                                                                                                                                                                                                                                                            |
| `index_name`        | `TEXT`    | 인덱스의 이름.                                                                                                                                                                                                                                                                                          |
| `constraint_def`    | `TEXT`    | 제약 조건의 정의.                                                                                                                                                                                                                                                                                       |

`delete_rule`의 반환값은 다음과 같습니다.

- `C` — `ON DELETE CASCADE`
- `R` — `ON DELETE RESTRICT`
- `A` — `ON DELETE NO ACTION` 또는 `ON DELETE` 절 생략
- `N` — `ON DELETE SET NULL`
- `D` — `ON DELETE SET DEFAULT`
- `" "` — 외래키가 아닌 제약 조건

## constraint_type 값 `N` (NOT NULL 제약 조건)

`constraint_type` 컬럼은 NOT NULL 제약 조건에 대해 값 `N`을 반환합니다. EPAS 18은 PostgreSQL 18을 기반으로 하며, PostgreSQL 18부터 NOT NULL 제약 조건이 시스템 카탈로그 `pg_constraint`에 정식 항목으로 저장되고 `contype` 컬럼에 `n`(not-null constraint) 값이 추가되었습니다. `ALL_CONSTRAINTS`/`DBA_CONSTRAINTS`/`USER_CONSTRAINTS` 뷰는 이 값을 대문자 `N`으로 매핑하여 표기합니다.

- PostgreSQL 18의 `pg_constraint.contype` 값: `c` = check constraint, `f` = foreign key constraint, `n` = not-null constraint, `p` = primary key constraint, `u` = unique constraint, `t` = constraint trigger, `x` = exclusion constraint — 참고: [PostgreSQL 18 — 52.13. pg_constraint](https://www.postgresql.org/docs/current/catalog-pg-constraint.html)
- Oracle 데이터 사전에서는 NOT NULL을 별도 유형으로 두지 않고 체크 제약(`C`)으로 표기하지만, EPAS 18은 PostgreSQL 18의 동작에 따라 `N`으로 구분하여 표기합니다.

### 확인 예시 (Verification example)

NOT NULL 컬럼이 포함된 테이블을 생성한 뒤 뷰를 조회하면 `constraint_type`이 `N`으로 표시됩니다.

```sql
-- NOT NULL 컬럼을 가진 테이블 생성
CREATE TABLE emp_demo (
    empno  NUMBER(4)     NOT NULL,
    ename  VARCHAR2(10)
);

-- 제약 조건 유형 조회
SELECT constraint_name, constraint_type, table_name
  FROM ALL_CONSTRAINTS
 WHERE table_name = 'EMP_DEMO';
```

실행 결과(예시):

```text
     constraint_name       | constraint_type | table_name
---------------------------+-----------------+------------
 EMP_DEMO_EMPNO_NOT_NULL   | N               | EMP_DEMO
(1 row)
```

> `constraint_name`은 시스템이 생성한 이름으로 환경에 따라 다르게 표시될 수 있습니다.
