# DBMS_ALERT — EPAS 18 내장 패키지

> 원문: [EPAS v18 — Reference › Oracle compatibility › Built-in packages › DBMS_ALERT](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_bip_guide/03_built-in_packages/01_dbms_alert/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 패키지·프로시저·역할 이름은 원문 그대로 보존했습니다.

`DBMS_ALERT` 패키지를 사용하면 알림(alert)을 등록하고, 보내고, 받을 수 있습니다. 다음 표는 지원되는 프로시저 목록입니다.

| 함수/프로시저 | 반환 유형 | 설명 |
| --- | --- | --- |
| `REGISTER(name)` | 해당 없음 | `name`이라는 이름의 알림을 받을 수 있도록 등록합니다. |
| `REMOVE(name)` | 해당 없음 | `name`이라는 이름의 알림에 대한 등록을 제거합니다. |
| `REMOVEALL` | 해당 없음 | 모든 알림에 대한 등록을 제거합니다. |
| `SIGNAL(name, message)` | 해당 없음 | `name`이라는 이름의 알림을 `message`와 함께 시그널링합니다. |
| `WAITANY(name OUT, message OUT, status OUT, timeout)` | 해당 없음 | 등록된 알림 중 아무거나 발생하기를 기다립니다. |
| `WAITONE(name, message OUT, status OUT, timeout)` | 해당 없음 | 지정한 알림 `name`이 발생하기를 기다립니다. |

EDB Postgres Advanced Server의 `DBMS_ALERT` 구현은 Oracle 버전에 비하면 부분 구현입니다. 표에 나열된 함수와 프로시저만 지원됩니다.

EDB Postgres Advanced Server는 최대 500개의 동시 알림을 허용합니다. `postgresql.conf` 파일에 있는 `dbms_alert.max_alerts` GUC 변수를 사용하여 시스템에서 허용되는 최대 동시 알림 수를 지정할 수 있습니다.

`dbms_alert.max_alerts` 변수의 값을 설정하려면, 기본적으로 `/opt/PostgresPlus/14AS/data`에 위치한 `postgresql.conf` 파일을 원하는 편집기로 엽니다. 다음과 같이 `dbms_alert.max_alerts` 매개변수를 편집합니다.

```ini
dbms_alert.max_alerts = alert_count
```

`alert_count`

`alert_count`는 최대 동시 알림 수를 지정합니다. 기본적으로 `dbms_alert.max_alerts`의 값은 `100`입니다. 이 기능을 비활성화하려면 `dbms_alert.max_alerts`를 `0`으로 설정합니다.

`dbms_alert.max_alerts` GUC가 올바르게 동작하려면 `custom_variable_classes` 매개변수에 `dbms_alerts`가 포함되어 있어야 합니다.

```ini
custom_variable_classes = 'dbms_alert, …'
```

`postgresql.conf` 파일 매개변수를 편집한 후에는 변경 사항을 적용하기 위해 서버를 재시작해야 합니다.

## REGISTER

`REGISTER` 프로시저는 현재 세션이 지정한 알림을 통지받을 수 있도록 합니다.

```sql
REGISTER(<name> VARCHAR2)
```

### 매개변수 (Parameters)

`name`

등록할 알림의 이름입니다.

### 예제 (Examples)

이 익명 블록은 `alert_test`라는 이름의 알림을 등록한 다음 시그널을 기다립니다.

```sql
DECLARE
    v_name           VARCHAR2(30) := 'alert_test';
    v_msg            VARCHAR2(80);
    v_status         INTEGER;
    v_timeout        NUMBER(3) := 120;
BEGIN
    DBMS_ALERT.REGISTER(v_name);
    DBMS_OUTPUT.PUT_LINE('Registered for alert ' || v_name);
    DBMS_OUTPUT.PUT_LINE('Waiting for signal...');
    DBMS_ALERT.WAITONE(v_name,v_msg,v_status,v_timeout);
    DBMS_OUTPUT.PUT_LINE('Alert name   : ' || v_name);
    DBMS_OUTPUT.PUT_LINE('Alert msg    : ' || v_msg);
    DBMS_OUTPUT.PUT_LINE('Alert status : ' || v_status);
    DBMS_OUTPUT.PUT_LINE('Alert timeout: ' || v_timeout || ' seconds');
    DBMS_ALERT.REMOVE(v_name);
END;

Registered for alert alert_test
Waiting for signal...
```

## REMOVE

`REMOVE` 프로시저는 지정한 알림에 대한 세션의 등록을 해제합니다.

```sql
REMOVE(<name> VARCHAR2)
```

### 매개변수 (Parameters)

`name`

등록을 해제할 알림의 이름입니다.

## REMOVEALL

`REMOVEALL` 프로시저는 모든 알림에 대한 세션의 등록을 해제합니다.

```sql
REMOVEALL
```

## SIGNAL

`SIGNAL` 프로시저는 지정한 알림의 발생을 시그널링합니다.

```sql
SIGNAL(<name> VARCHAR2, <message> VARCHAR2)
```

### 매개변수 (Parameters)

`name`

알림의 이름입니다.

`message`

이 알림과 함께 전달할 정보입니다.

### 예제 (Examples)

이 익명 블록은 `alert_test`에 대한 알림을 시그널링합니다.

```sql
DECLARE
    v_name   VARCHAR2(30) := 'alert_test';
BEGIN
    DBMS_ALERT.SIGNAL(v_name,'This is the message from ' || v_name);
    DBMS_OUTPUT.PUT_LINE('Issued alert for ' || v_name);
END;
Issued alert for alert_test
```

## WAITANY

`WAITANY` 프로시저는 등록된 알림 중 아무거나 발생하기를 기다립니다.

```sql
WAITANY(<name> OUT VARCHAR2, <message> OUT VARCHAR2,
  <status> OUT INTEGER, <timeout> NUMBER)
```

### 매개변수 (Parameters)

`name`

알림의 이름을 받는 변수입니다.

`message`

`SIGNAL` 프로시저가 보낸 메시지를 받는 변수입니다.

`status`

작업이 반환하는 상태 코드입니다. 가능한 값은 다음과 같습니다: `0` – 알림 발생; `1` – 타임아웃 발생.

`timeout`

알림을 기다리는 시간(초)입니다.

### 예제 (Examples)

이 익명 블록은 `WAITANY` 프로시저를 사용하여 `alert_test` 또는 `any_alert`라는 이름의 알림을 받습니다.

```sql
DECLARE
    v_name           VARCHAR2(30);
    v_msg            VARCHAR2(80);
    v_status         INTEGER;
    v_timeout        NUMBER(3) := 120;
BEGIN
    DBMS_ALERT.REGISTER('alert_test');
    DBMS_ALERT.REGISTER('any_alert');
    DBMS_OUTPUT.PUT_LINE('Registered for alert alert_test and any_alert');
    DBMS_OUTPUT.PUT_LINE('Waiting for signal...');
    DBMS_ALERT.WAITANY(v_name,v_msg,v_status,v_timeout);
    DBMS_OUTPUT.PUT_LINE('Alert name   : ' || v_name);
    DBMS_OUTPUT.PUT_LINE('Alert msg    : ' || v_msg);
    DBMS_OUTPUT.PUT_LINE('Alert status : ' || v_status);
    DBMS_OUTPUT.PUT_LINE('Alert timeout: ' || v_timeout || ' seconds');
    DBMS_ALERT.REMOVEALL;
END;

Registered for alert alert_test and any_alert
Waiting for signal...
```

두 번째 세션의 익명 블록이 `any_alert`에 대한 시그널을 발행합니다.

```sql
DECLARE
    v_name   VARCHAR2(30) := 'any_alert';
BEGIN
    DBMS_ALERT.SIGNAL(v_name,'This is the message from ' || v_name);
    DBMS_OUTPUT.PUT_LINE('Issued alert for ' || v_name);
END;

Issued alert for any_alert
```

제어가 첫 번째 익명 블록으로 돌아가고 나머지 코드가 실행됩니다.

```text
Registered for alert alert_test and any_alert
Waiting for signal...
Alert name   : any_alert
Alert msg    : This is the message from any_alert
Alert status : 0
Alert timeout: 120 seconds
```

## WAITONE

`WAITONE` 프로시저는 지정한 등록된 알림이 발생하기를 기다립니다.

```sql
WAITONE(<name> VARCHAR2, <message> OUT VARCHAR2,
  <status> OUT INTEGER, <timeout> NUMBER)
```

### 매개변수 (Parameters)

`name`

알림의 이름입니다.

`message`

`SIGNAL` 프로시저가 보낸 메시지를 받는 변수입니다.

`status`

작업이 반환하는 상태 코드입니다. 가능한 값은 다음과 같습니다: `0` – 알림 발생; `1` – 타임아웃 발생.

`timeout`

알림을 기다리는 시간(초)입니다.

### 예제 (Examples)

이 익명 블록은 `WAITANY` 예제에서 사용한 것과 유사하지만, `WAITONE` 프로시저를 사용하여 `alert_test`라는 이름의 알림을 받는다는 점이 다릅니다.

```sql
DECLARE
    v_name           VARCHAR2(30) := 'alert_test';
    v_msg            VARCHAR2(80);
    v_status         INTEGER;
    v_timeout        NUMBER(3) := 120;
BEGIN
    DBMS_ALERT.REGISTER(v_name);
    DBMS_OUTPUT.PUT_LINE('Registered for alert ' || v_name);
    DBMS_OUTPUT.PUT_LINE('Waiting for signal...');
    DBMS_ALERT.WAITONE(v_name,v_msg,v_status,v_timeout);
    DBMS_OUTPUT.PUT_LINE('Alert name   : ' || v_name);
    DBMS_OUTPUT.PUT_LINE('Alert msg    : ' || v_msg);
    DBMS_OUTPUT.PUT_LINE('Alert status : ' || v_status);
    DBMS_OUTPUT.PUT_LINE('Alert timeout: ' || v_timeout || ' seconds');
    DBMS_ALERT.REMOVE(v_name);
END;

Registered for alert alert_test
Waiting for signal...
```

두 번째 세션의 익명 블록이 `alert_test`에 대한 시그널을 보냅니다.

```sql
DECLARE
    v_name   VARCHAR2(30) := 'alert_test';
BEGIN
    DBMS_ALERT.SIGNAL(v_name,'This is the message from ' || v_name);
    DBMS_OUTPUT.PUT_LINE('Issued alert for ' || v_name);
END;

Issued alert for alert_test
```

첫 번째 세션에 알림이 전달되고, 제어가 익명 블록으로 돌아가며, 나머지 코드가 실행됩니다.

```text
Registered for alert alert_test
Waiting for signal...
Alert name   : alert_test
Alert msg    : This is the message from alert_test
Alert status : 0
Alert timeout: 120 seconds
```

## 종합 예제 (Comprehensive example)

다음 예제는 `dept` 테이블 또는 `emp` 테이블이 변경될 때 알림을 보내기 위해 두 개의 트리거를 사용합니다. 익명 블록이 이 알림들을 수신 대기하다가 알림을 받으면 메시지를 표시합니다.

다음은 `dept` 및 `emp` 테이블에 대한 트리거입니다.

```sql
CREATE OR REPLACE TRIGGER dept_alert_trig
    AFTER INSERT OR UPDATE OR DELETE ON dept
DECLARE
    v_action        VARCHAR2(25);
BEGIN
    IF INSERTING THEN
        v_action := ' added department(s) ';
    ELSIF UPDATING THEN
        v_action := ' updated department(s) ';
    ELSIF DELETING THEN
        v_action := ' deleted department(s) ';
    END IF;
    DBMS_ALERT.SIGNAL('dept_alert',USER || v_action || 'on ' ||
        SYSDATE);
END;

CREATE OR REPLACE TRIGGER emp_alert_trig
    AFTER INSERT OR UPDATE OR DELETE ON emp
DECLARE
    v_action        VARCHAR2(25);
BEGIN
    IF INSERTING THEN
        v_action := ' added employee(s) ';
    ELSIF UPDATING THEN
        v_action := ' updated employee(s) ';
    ELSIF DELETING THEN
        v_action := ' deleted employee(s) ';
    END IF;
    DBMS_ALERT.SIGNAL('emp_alert',USER || v_action || 'on ' ||
        SYSDATE);
END;
```

이 익명 블록은 다른 세션에서 `dept` 및 `emp` 테이블에 대한 업데이트가 발생하는 동안 한 세션에서 실행됩니다.

```sql
DECLARE
    v_dept_alert     VARCHAR2(30) := 'dept_alert';
    v_emp_alert      VARCHAR2(30) := 'emp_alert';
    v_name           VARCHAR2(30);
    v_msg            VARCHAR2(80);
    v_status         INTEGER;
    v_timeout        NUMBER(3) := 60;
BEGIN
    DBMS_ALERT.REGISTER(v_dept_alert);
    DBMS_ALERT.REGISTER(v_emp_alert);
    DBMS_OUTPUT.PUT_LINE('Registered for alerts dept_alert and emp_alert');
    DBMS_OUTPUT.PUT_LINE('Waiting for signal...');
    LOOP
        DBMS_ALERT.WAITANY(v_name,v_msg,v_status,v_timeout);
        EXIT WHEN v_status != 0;
        DBMS_OUTPUT.PUT_LINE('Alert name   : ' || v_name);
        DBMS_OUTPUT.PUT_LINE('Alert msg    : ' || v_msg);
        DBMS_OUTPUT.PUT_LINE('Alert status : ' || v_status);
        DBMS_OUTPUT.PUT_LINE('------------------------------------' ||
            '-------------------------');
    END LOOP;
    DBMS_OUTPUT.PUT_LINE('Alert status : ' || v_status);
    DBMS_ALERT.REMOVEALL;
END;

Registered for alerts dept_alert and emp_alert
Waiting for signal...
```

다음 변경은 사용자 mary가 수행합니다.

```sql
INSERT INTO dept VALUES (50,'FINANCE','CHICAGO');
INSERT INTO emp (empno,ename,deptno) VALUES (9001,'JONES',50);
INSERT INTO emp (empno,ename,deptno) VALUES (9002,'ALICE',50);
```

다음 변경은 사용자 john이 수행합니다.

```sql
INSERT INTO dept VALUES (60,'HR','LOS ANGELES');
```

다음은 트리거로부터 시그널을 받는 익명 블록이 표시하는 출력입니다.

```text
Registered for alerts dept_alert and emp_alert
Waiting for signal...
Alert name   : dept_alert
Alert msg    : mary added department(s) on 25-OCT-07 16:41:01
Alert status : 0
-------------------------------------------------------------
Alert name   : emp_alert
Alert msg    : mary added employee(s) on 25-OCT-07 16:41:02
Alert status : 0
-------------------------------------------------------------
Alert name   : dept_alert
Alert msg    : john added department(s) on 25-OCT-07 16:41:22
Alert status : 0
-------------------------------------------------------------
Alert status : 1
```
