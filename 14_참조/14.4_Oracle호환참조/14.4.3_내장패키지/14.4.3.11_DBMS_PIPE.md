# DBMS_PIPE — EPAS 18 내장 패키지

> 원문: [EPAS v18 — Reference › Oracle compatibility › Built-in packages › DBMS_PIPE](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_bip_guide/03_built-in_packages/10_dbms_pipe/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 패키지·프로시저·역할 이름은 원문 그대로 보존했습니다.

`DBMS_PIPE` 패키지를 사용하면 동일한 데이터베이스 클러스터에 연결된 세션 내에서 또는 세션 간에 파이프를 통해 메시지를 보낼 수 있습니다.

다음 표는 `DBMS_PIPE` 패키지에서 사용할 수 있는 프로시저와 함수를 보여줍니다.

| 함수/프로시저 | 반환 타입 | 설명 |
| --- | --- | --- |
| `CREATE_PIPE(pipename [, maxpipesize ] [, private ])` | `INTEGER` | `private`가 `true`(기본값)이면 private 파이프를, `false`이면 public 파이프를 명시적으로 생성합니다. |
| `NEXT_ITEM_TYPE` | `INTEGER` | 수신된 메시지에서 다음 항목의 데이터 타입을 판별합니다. |
| `PACK_MESSAGE(item)` | 해당 없음 | `item`을 세션의 로컬 메시지 버퍼에 넣습니다. |
| `PURGE(pipename)` | 해당 없음 | 지정된 파이프에서 수신되지 않은 메시지를 제거합니다. |
| `RECEIVE_MESSAGE(pipename [, timeout ])` | `INTEGER` | 지정된 파이프에서 메시지를 가져옵니다. |
| `REMOVE_PIPE(pipename)` | `INTEGER` | 명시적으로 생성된 파이프를 삭제합니다. |
| `RESET_BUFFER` | 해당 없음 | 로컬 메시지 버퍼를 재설정합니다. |
| `SEND_MESSAGE(pipename [, timeout ] [, maxpipesize ])` | `INTEGER` | 파이프로 메시지를 보냅니다. |
| `UNIQUE_SESSION_NAME` | `VARCHAR2` | 고유한 세션 이름을 얻습니다. |
| `UNPACK_MESSAGE(item OUT)` | 해당 없음 | 메시지에서 다음 데이터 항목을 타입이 호환되는 변수 `item`으로 가져옵니다. |

파이프는 _암시적(implicit)_ 또는 _명시적(explicit)_ 으로 분류됩니다. 이전에 `CREATE_PIPE` 함수로 생성되지 않은 파이프 이름을 참조하면 암시적 파이프가 생성됩니다. 예를 들어 존재하지 않는 파이프 이름을 사용하여 `SEND_MESSAGE` 함수를 실행하면 해당 이름으로 새 암시적 파이프가 생성됩니다. 명시적 파이프는 첫 번째 매개변수가 새 파이프의 파이프 이름을 지정하는 `CREATE_PIPE` 함수를 사용하여 생성됩니다.

파이프는 또한 _private_ 또는 _public_ 으로 분류됩니다. 파이프를 생성한 사용자만 private 파이프에 접근할 수 있습니다. 슈퍼유저조차도 다른 사용자가 생성한 private 파이프에는 접근할 수 없습니다. `DBMS_PIPE` 패키지에 접근할 수 있는 모든 사용자는 public 파이프에 접근할 수 있습니다.

세 번째 매개변수를 `FALSE`로 설정한 `CREATE_PIPE` 함수를 사용해야만 public 파이프를 생성할 수 있습니다. 세 번째 매개변수를 `TRUE`로 설정하거나 세 번째 매개변수를 생략하여 `CREATE_PIPE` 함수로 private 파이프를 생성할 수 있습니다. 모든 암시적 파이프는 private입니다.

메시지의 개별 데이터 항목 또는 행은 먼저 현재 세션에 고유한 _로컬 메시지 버퍼(local message buffer)_ 에 구성됩니다. `PACK_MESSAGE` 프로시저는 세션의 로컬 메시지 버퍼에 메시지를 구성합니다. 그런 다음 `SEND_MESSAGE` 함수를 사용하여 파이프를 통해 메시지를 보냅니다.

메시지 수신은 반대 작업을 포함합니다. `RECEIVE_MESSAGE` 함수를 사용하여 지정된 파이프에서 메시지를 가져옵니다. 메시지는 세션의 로컬 메시지 버퍼에 기록됩니다. 그런 다음 `UNPACK_MESSAGE` 프로시저를 사용하여 메시지 버퍼의 메시지 데이터 항목을 프로그램 변수로 전송합니다. 파이프에 여러 메시지가 있으면 `RECEIVE_MESSAGE`는 FIFO(선입선출) 순서로 메시지를 가져옵니다.

각 세션은 `PACK_MESSAGE` 프로시저로 생성된 메시지와 `RECEIVE_MESSAGE` 함수로 검색된 메시지에 대해 별도의 메시지 버퍼를 유지합니다. 따라서 메시지는 동일한 세션에서 구성하고 수신할 수 있습니다. 그러나 연속적인 `RECEIVE_MESSAGE` 호출이 이루어지면 마지막 `RECEIVE_MESSAGE` 호출의 메시지만 로컬 메시지 버퍼에 보존됩니다.
