# CREATE_QUEUE_TABLE

큐 테이블을 생성하려면 `CREATE_QUEUE_TABLE` 프로시저를 사용합니다. 시그니처는 다음과 같습니다.

```sql
CREATE_QUEUE_TABLE (
  <queue_table> IN VARCHAR2,
  <queue_payload_type> IN VARCHAR2,
  <storage_clause> IN VARCHAR2 DEFAULT NULL,
  <sort_list> IN VARCHAR2 DEFAULT NULL,
  <multiple_consumers> IN BOOLEAN DEFAULT FALSE,
  <message_grouping> IN BINARY_INTEGER DEFAULT NONE,
  <comment> IN VARCHAR2 DEFAULT NULL,
  <auto_commit> IN BOOLEAN DEFAULT TRUE,
  <primary_instance> IN BINARY_INTEGER DEFAULT 0,
  <secondary_instance> IN BINARY_INTEGER DEFAULT 0,
  <compatible> IN VARCHAR2 DEFAULT NULL,
  <secure> IN BOOLEAN DEFAULT FALSE)
```

## 매개변수 (Parameters)

`queue_table`

큐 테이블의 (선택적으로 스키마로 한정된) 이름입니다.

`queue_payload_type`

큐 테이블에 저장되는 데이터의 사용자 정의 유형입니다. `RAW` 데이터 유형을 지정하려면 `RAW` 유형을 식별하는 사용자 정의 유형을 생성해야 합니다.

`storage_clause`

`storage_clause` 매개변수를 사용하여 큐 테이블의 속성을 지정합니다. `TABLESPACE` 옵션만 적용됩니다. 나머지는 모두 호환성을 위해 허용되며 무시됩니다. 테이블을 생성할 테이블스페이스의 이름을 지정하려면 `TABLESPACE` 절을 사용합니다.

`storage_clause`는 다음 중 하나 이상이 될 수 있습니다.

```sql
TABLESPACE tablespace_name, PCTFREE integer, PCTUSED integer,
INITRANS integer, MAXTRANS integer or STORAGE storage_option.
```

`storage_option`은 다음 중 하나 이상이 될 수 있습니다.

```sql
MINEXTENTS integer, MAXEXTENTS integer, PCTINCREASE integer, INITIAL
size_clause, NEXT, FREELISTS integer, OPTIMAL size_clause, BUFFER_
POOL {KEEP|RECYCLE|DEFAULT}.
```

`sort_list`

`sort_list`는 큐의 디큐(dequeue) 순서를 제어합니다. 큐를 오름차순으로 정렬하는 데 사용할 열의 이름을 지정합니다. 현재 허용되는 값은 `enq_time`과 `priority`의 다음 조합입니다.

- `enq_time, priority`

- `priority, enq_time`

- `priority`

- `enq_time`


`multiple_consumers`

`multiple_consumers` 큐 테이블은 지원되지 않습니다.

`message_grouping`

지정하는 경우 `message_grouping`은 반드시 `NONE`이어야 합니다.

`comment`

`comment` 매개변수를 사용하여 큐 테이블에 대한 주석을 제공합니다.

`auto_commit`

`auto_commit`은 호환성을 위해 허용되지만 무시됩니다.

`primary_instance`

`primary_instance`는 호환성을 위해 허용되고 저장되지만 무시됩니다.

`secondary_instance`

`secondary_instance`는 호환성을 위해 허용되지만 무시됩니다.

`compatible`

`compatible`은 호환성을 위해 허용되지만 무시됩니다.

`secure`

`secure`는 호환성을 위해 허용되지만 무시됩니다.

## 예제 (Example)

다음 익명 블록은 먼저 이름(`VARCHAR2`)과 프로젝트 설명(`TEXT`)을 담는 속성을 가진 유형(`work_order`)을 생성합니다. 그런 다음 이 블록은 해당 유형을 사용하여 큐 테이블을 생성합니다.

```sql
BEGIN

CREATE TYPE work_order AS (name VARCHAR2, project TEXT, completed BOOLEAN);

EXEC DBMS_AQADM.CREATE_QUEUE_TABLE
      (queue_table => 'work_order_table',
       queue_payload_type => 'work_order',
       comment => 'Work order message queue table');

END;
```

큐 테이블의 이름은 `work_order_table`이며 `work_order` 유형의 페이로드를 포함합니다. 주석에는 이것이 `Work order message queue table`임이 기록되어 있습니다.
