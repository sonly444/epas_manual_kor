# DBMS_PRIVILEGE_CAPTURE — EPAS 18 내장 패키지

> 원문: [EPAS v18 — Reference › Oracle compatibility › Built-in packages › DBMS_PRIVILEGE_CAPTURE](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_bip_guide/03_built-in_packages/10_dbms_privilege_capture/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 패키지·프로시저·역할·파라미터 이름은 원문 그대로 보존했습니다.

EDB Postgres Advanced Server는 사용자의 권한 사용을 캡처하고 분석하는 기능을 지원합니다.

권한 사용을 캡처하고 분석하는 방법은 두 가지가 있습니다.

- Oracle과 호환되는 `DBMS_PRIVILEGE_CAPTURE` 패키지 사용
- SQL 명령 사용

SQL 명령에 대한 자세한 내용은 [SQL 참조](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/)를 참고하십시오.

- [CREATE CAPTURE PRIVILEGES POLICY](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/19a_create_capture_privilege/)
- [ALTER CAPTURE PRIVILEGES POLICY](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/01_alter_capture_privilege/)
- [DROP CAPTURE PRIVILEGES POLICY](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/44a_drop_capture_privilege/)

`DBMS_PRIVILEGE_CAPTURE` 패키지는 데이터베이스 권한 분석을 위한 인터페이스를 제공합니다.

`DBMS_PRIVILEGE_CAPTURE` 패키지에서 사용할 수 있는 프로시저는 다음과 같습니다.

| 함수/프로시저       | 함수 또는 프로시저 | 반환 타입 | 설명                                               |
| ------------------- | ------------------ | --------- | -------------------------------------------------- |
| `CREATE_CAPTURE`  | 프로시저           | n/a       | 권한 사용 분석 조건을 지정하는 정책을 생성합니다.  |
| `ENABLE_CAPTURE`  | 프로시저           | n/a       | 특정 권한 분석 정책의 권한 사용 캡처를 시작합니다. |
| `DISABLE_CAPTURE` | 프로시저           | n/a       | 특정 권한 분석 정책의 권한 사용 캡처를 중지합니다. |
| `DROP_CAPTURE`    | 프로시저           | n/a       | 캡처된 데이터와 함께 권한 분석 정책을 제거합니다.  |
| `GENERATE_RESULT` | 프로시저           | n/a       | 권한 분석 데이터로 데이터 딕셔너리 뷰를 채웁니다.  |
| `DELETE_RUN`      | 프로시저           | n/a       | 권한 분석 캡처 실행(run)을 삭제합니다.             |

이 패키지를 사용하면 사용자에게 부여된 시스템 권한과 객체 권한의 사용을 캡처하는 정책을 생성할 수 있습니다. 이를 통해 사용자가 권한을 실제로 사용하고 있는지 여부를 판단할 수 있습니다. 분석 후에는 사용되지 않는 권한을 회수하여 사용자에게 과도하게 부여된 권한의 수를 줄일 수 있습니다.

슈퍼유저 또는 `CAPTURE_ADMIN` 역할을 가진 비슈퍼유저가 `DBMS_PRIVILEGE_CAPTURE` 패키지에 접근할 수 있습니다.

## postgresql.conf 파일의 파라미터 구성

기능을 활성화하려면 `postgresql.conf` 파일에서 다음 파라미터 값을 0보다 크게 설정합니다.

```ini
edb_max_capture_privileges_policies = 2
```

이 파라미터는 클러스터 수준에서 생성할 수 있는 정책의 최대 개수를 제한합니다. 기본값은 `0`입니다. 이 파라미터를 0보다 큰 값으로 설정하십시오. 또한 `edb_max_capture_privileges_policies` 값을 1보다 크게 설정하더라도 데이터베이스당 하나의 정책만 활성화할 수 있습니다. 이 파라미터 값을 변경한 후에는 서버를 재시작해야 합니다.

권한 캡처 기능은 각 정책마다 하나의 백그라운드 워커 프로세스(background worker process)를 사용합니다. 따라서 `edb_max_capture_privileges_policies`에 설정할 수 있는 값은 클러스터에서 사용 가능한 백그라운드 워커 프로세스 수를 지정하는 `max_worker_processes` 값에 의해 제한되며, 다음 조건을 만족해야 합니다.

```text
edb_max_capture_privileges_policies + 1 <= max_worker_processes
```

즉, `edb_max_capture_privileges_policies`에 설정하는 값은 `max_worker_processes - 1` 이하여야 합니다. 이 조건을 만족하지 않으면 권한 캡처 정책이 정상적으로 동작하지 않을 수 있으므로, 필요한 경우 `max_worker_processes` 값을 함께 늘려야 합니다. `max_worker_processes`는 클러스터 범위 파라미터이며 변경 후 서버를 재시작해야 적용됩니다.

```ini
edb_capture_privileges_hash_entries = 2000
```

이 파라미터는 각 권한 정책에 대한 해시 테이블 크기를 설정합니다. 설정한 값만큼의 권한 사용 레코드가 캡처되면 `DBA_USED_PRIVS` 및 `DBA_UNUSED_PRIVS` 시스템 카탈로그로 플러시됩니다. 최솟값은 `1`이고 기본값은 `2000`입니다. 이 파라미터 값을 변경한 후에는 서버를 재시작해야 합니다.

## CREATE_CAPTURE

`CREATE_CAPTURE` 프로시저는 권한 사용 분석 조건을 지정하는 권한 분석 정책을 생성합니다. 또한 선택적으로 권한 사용을 분석할 역할과, 권한 사용을 분석할 조건을 지정합니다.

```sql
DBMS_PRIVILEGE_CAPTURE.CREATE_CAPTURE (
    name        IN VARCHAR2,
    description IN VARCHAR2 DEFAULT NULL,
    type        IN NUMBER DEFAULT G_DATABASE,
    roles       IN ROLE_NAME_LIST DEFAULT ROLE_NAME_LIST(),
    condition   IN VARCHAR2 DEFAULT NULL);
```

### 파라미터

`name`

권한 분석 정책의 이름. 최대 30자 크기의 문자열입니다.

`description`

정책에 대한 설명. 최대 1024자입니다.

`type`

권한 분석 정책의 유형. 가능한 값은 다음과 같습니다.

- `G_DATABASE` — 슈퍼유저를 포함하여 데이터베이스 내 모든 사용자의 권한 사용을 캡처합니다.
- `G_ROLE` — 권한이 지정된 역할 또는 역할 목록에 포함되어 있는 경우 해당 권한 사용을 캡처합니다.
- `G_CONTEXT` — `condition` 파라미터로 지정한 컨텍스트가 참(true)으로 평가되는 경우 권한 사용을 캡처합니다.
- `G_ROLE_AND_CONTEXT` — 권한이 지정된 역할 목록에 포함되고 `condition` 파라미터로 지정한 조건이 참인 경우 권한 사용을 캡처합니다.

`roles`

권한을 분석할 역할. `type`이 `G_ROLE` 또는 `G_ROLE_AND_CONTEXT`인 경우 필수입니다.

`condition`

최대 4000자를 포함하는 불리언(Boolean) 표현식. `type`이 `G_CONTEXT` 또는 `G_ROLE_AND_CONTEXT`인 경우 필수입니다.

## ENABLE_CAPTURE

`ENABLE_CAPTURE` 프로시저는 지정한 권한 분석 정책에 대해 권한 분석 기록을 시작하며, 선택적으로 이 정책에 대한 캡처 실행(run)을 제공합니다. 정책이 활성화되면 정책 조건에 해당하는 모든 권한 사용이 기록됩니다.

```sql
DBMS_PRIVILEGE_CAPTURE.ENABLE_CAPTURE (
   name      IN VARCHAR2,
   run_name  IN VARCHAR2 DEFAULT NULL);
```

### 파라미터

`name`

활성화할 권한 분석 정책의 이름.

`run_name`

이 정책과 연결할 캡처 실행(run)의 이름으로 128자 미만입니다. 특수 문자는 큰따옴표로 묶으십시오.

## DISABLE_CAPTURE

`DISABLE_CAPTURE` 프로시저는 지정한 권한 분석 정책에 대한 권한 사용 기록을 중지합니다. 정책이 비활성화되면 정책 조건에 해당하는 권한 사용은 더 이상 기록되지 않습니다.

```sql
DBMS_PRIVILEGE_CAPTURE.DISABLE_CAPTURE (
    name  IN VARCHAR2,
    run_name IN VARCHAR2 DEFAULT NULL
    );
```

### 파라미터

`name`

비활성화할 권한 분석 정책의 이름.

`run_name`

캡처 실행(run)의 이름.

## DROP_CAPTURE

`DROP_CAPTURE` 프로시저는 권한 분석 정책을 기록된 데이터와 함께 제거합니다. 정책이 제거되면 해당 정책과 연결되어 이전에 기록된 모든 권한 사용 데이터가 삭제됩니다.

```sql
DBMS_PRIVILEGE_CAPTURE.DROP_CAPTURE (
    name  IN VARCHAR2);
```

### 파라미터

`name`

제거할 권한 분석 정책의 이름.

## GENERATE_RESULT

`GENERATE_RESULT` 프로시저는 권한 분석 데이터로 데이터 딕셔너리 뷰를 채웁니다.

```sql
DBMS_PRIVILEGE_CAPTURE.GENERATE_RESULT (
    name         IN VARCHAR2,
    run_name     IN VARCHAR2 DEFAULT NULL,
    dependency   IN BOOLEAN DEFAULT NULL /* This is just for redwood compatibility */);
```

### 파라미터

`name`

데이터 딕셔너리 뷰를 채울 대상 권한 분석 정책의 이름.

`run_name`

권한 분석 정책과 연결된 캡처 실행(run)의 이름. 이 파라미터를 생략하면 생성된 모든 실행(run)의 레코드가 분석됩니다. 특정 실행의 레코드를 분석하려면 이 파라미터를 지정하십시오.

`dependency`

이 파라미터는 Oracle 호환성을 위해 추가되었습니다. 값은 불리언 Y(예) 또는 N(아니오)입니다.

## DELETE_RUN

`DELETE_RUN` 프로시저는 권한 분석 캡처 실행(run)을 삭제합니다.

```sql
DBMS_PRIVILEGE_CAPTURE.DELETE_RUN (
    name      IN VARCHAR2,
    run_name  IN VARCHAR2);
```

### 파라미터

`name`

캡처 실행(run)이 연결된 권한 분석 정책의 이름.

`run_name`

캡처 실행(run)의 이름.

## 예제

권한 분석 기능을 활성화하려면 `postgresql.conf` 파일에서 파라미터를 0보다 큰 값으로 설정합니다.

```ini
edb_max_capture_privileges_policies = 2
```

슈퍼유저로 로그인하거나 비슈퍼유저에게 `CAPTURE_ADMIN` 역할을 부여합니다.

```sql
GRANT CAPTURE_ADMIN TO user1;
```

테이블을 생성합니다.

```sql
CREATE TABLE tab1 (a INT);
```

### 데이터베이스 대상 정책 (Policy on database)

```sql
## 데이터베이스에 권한 분석 정책 생성:
BEGIN
    DBMS_PRIVILEGE_CAPTURE.CREATE_CAPTURE (
        name         => 'policy_on_database',
        type         => DBMS_PRIVILEGE_CAPTURE.G_DATABASE);

    DBMS_PRIVILEGE_CAPTURE.ENABLE_CAPTURE (
        name         => 'policy_on_database');
END;

## 테이블에 데이터 삽입:
INSERT INTO tab1 VALUES(1);
SELECT * FROM tab1;

## 정책 비활성화:
DBMS_PRIVILEGE_CAPTURE.DISABLE_CAPTURE(
    name            => 'policy_on_database');
END;

## `GENERATE_RESULT` 프로시저를 실행하여 딕셔너리 뷰 채우기:
BEGIN
  DBMS_PRIVILEGE_CAPTURE.GENERATE_RESULT(
    name   => 'policy_on_database');
END;
```

### 컨텍스트 대상 정책 (Policy on context)

```sql
## 함수 생성:
CREATE OR REPLACE FUNCTION func1(i INTEGER) RETURNS INTEGER AS $$
  BEGIN
     RETURN i + 1;
  END;
$$ LANGUAGE plpgsql;

## 컨텍스트 대상 정책 생성:
BEGIN
	DBMS_PRIVILEGE_CAPTURE.CREATE_CAPTURE(
		name			=> 'policy_on_db_context',
		type			=> DBMS_PRIVILEGE_CAPTURE.G_CONTEXT,
		condition		=> '1=1');

	DBMS_PRIVILEGE_CAPTURE.ENABLE_CAPTURE(
		name			=> 'policy_on_db_context');
END;

## 객체 접근:
SELECT func1(1);
DELETE FROM tab1;

## 정책 비활성화:

		name			=> 'policy_on_db_context');
```

### 역할 대상 정책 (Policy on role)

```sql
## 역할 생성 및 역할에 권한 부여:
CREATE ROLE ROLE1;
GRANT SELECT, UPDATE, DELETE on tab1 to user1;

## 역할 대상 권한 분석 정책 생성:
BEGIN
	DBMS_PRIVILEGE_CAPTURE.create_capture(
		name			=> 'policy_on_role',
		type			=> DBMS_PRIVILEGE_CAPTURE.G_ROLE,
		roles			=> ROLE_NAME_LIST('role1'));

	DBMS_PRIVILEGE_CAPTURE.enable_capture(
		name			=> 'policy_on_role',
		run_name		=> 'run1');
END;

## 역할을 설정하고 테이블에서 데이터 삭제:
SET ROLE role1;
DELETE FROM tab1;
SET ROLE edb;

## 정책 비활성화:
BEGIN
	DBMS_PRIVILEGE_CAPTURE.disable_capture(
		name			=> 'policy_on_role');
END;

## Generate_result 프로시저를 실행하여 딕셔너리 뷰 채우기:
BEGIN
  DBMS_PRIVILEGE_CAPTURE.generate_result(
    name   => 'policy_on_role');
END;
```

데이터 딕셔너리 뷰를 조회하여 캡처된 정책 정보를 확인합니다.
