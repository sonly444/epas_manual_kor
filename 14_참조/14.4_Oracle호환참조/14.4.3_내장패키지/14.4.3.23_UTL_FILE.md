# UTL_FILE — EPAS 18 내장 패키지
> 원문: [EPAS v18 — Reference › Oracle compatibility › Built-in packages › UTL_FILE](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_bip_guide/03_built-in_packages/20_utl_file/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 패키지·프로시저·함수 이름은 원문 그대로 보존했습니다.

# UTL_FILE

`UTL_FILE` 패키지는 운영 체제 파일 시스템의 파일을 읽고 씁니다. 슈퍼유저가 아닌 사용자가 이 패키지의 함수나 프로시저를 사용하려면, 먼저 슈퍼유저가 `UTL_FILE` 패키지에 대한 `EXECUTE` 권한을 부여해야 합니다. 예를 들어, 다음 명령은 사용자 `mary`에게 권한을 부여합니다.

```sql
GRANT EXECUTE ON PACKAGE SYS.UTL_FILE TO mary;
```

또한 `UTL_FILE` 함수나 프로시저가 정상적으로 처리되려면 다음이 필요합니다.

- `UTL_FILE` 패키지에 대한 `EXECUTE` 권한. 이 권한은 패키지의 모든 API를 호출하는 데 필요합니다.

- 수행하는 작업에 따라, 다음 표에 자세히 설명된 대로 디렉터리에 대한 `READ` 또는 `WRITE` 권한.

| 작업 | 필요한 권한 |
| --- | --- |
| 읽기 모드로 파일 열기 | `READ` |
| 추가 또는 쓰기 모드로 파일 생성 또는 열기 | `WRITE` |
| 파일 복사 | 원본 디렉터리에 대한 `READ` 및 대상 디렉터리에 대한 `WRITE` |
| 파일 제거 | `WRITE` |
| 파일 이름 변경 | 원본 디렉터리와 대상 디렉터리에 대한 `WRITE` |

다음은 사용자에게 디렉터리에 대한 `WRITE` 권한을 부여하는 예입니다.

```sql
GRANT WRITE ON directory tmp TO user1;
```

유사한 절차를 사용하여 디렉터리에 대한 권한을 취소할 수 있습니다.

쓰거나 읽을 파일을 참조하는 데는 파일 핸들이 사용됩니다. _파일 핸들(file handle)_ 은 `UTL_FILE` 패키지의 public 변수 `UTL_FILE.FILE_TYPE`으로 정의됩니다. `FILE_TYPE` 타입의 변수를 선언하여 `FOPEN` 함수 호출로 반환되는 파일 핸들을 받아야 합니다. 그런 다음 이 파일 핸들은 해당 파일에 대한 이후의 모든 작업에 사용됩니다.

파일 시스템의 디렉터리에 대한 참조는 `CREATE DIRECTORY` 명령을 사용하여 디렉터리에 할당된 디렉터리 이름 또는 별칭을 사용하여 이루어집니다.

`UTL_FILE` 패키지에서 사용할 수 있는 프로시저와 함수는 다음 표에 나열되어 있습니다.

| 함수/프로시저 | 반환 타입 | 설명 |
| --- | --- | --- |
| `FCLOSE(file IN OUT)` | 해당 없음 | `file`로 식별되는 지정된 파일을 닫습니다. |
| `FCLOSE_ALL` | 해당 없음 | 열려 있는 모든 파일을 닫습니다. |
| `FCOPY(location, filename, dest_dir, dest_file [, start_line] [, end_line ])` | 해당 없음 | `location`으로 식별되는 디렉터리의 `filename`을 디렉터리 `dest_dir`의 파일 `dest_file`로, `start_line`부터 `end_line`까지 복사합니다. |
| `FFLUSH(file)` | 해당 없음 | 버퍼의 데이터를 `file`로 식별되는 파일에 디스크로 강제로 씁니다. |
| `FGETATTR(location, filename, fexists OUT, file_length OUT, block_size OUT)` | 해당 없음 | `filename`과 `location`이 주어졌을 때 파일의 속성을 가져옵니다. |
| `FGETPOS(file)` | `INTEGER` | 열린 파일에서 상대 오프셋 위치를 바이트 단위의 정수로 반환합니다. |
| `FOPEN(location, filename, open_mode [, max_linesize ])` | `FILE_TYPE` | `location`으로 식별되는 디렉터리에서 파일 `filename`을 엽니다. |
| `FOPEN_NCHAR(location, filename, open_mode [, max_linesize])` | `FILE_TYPE` | 유니코드 문자 집합 데이터를 읽거나 쓰기 위해 `location`으로 식별되는 디렉터리에서 파일 `filename`을 엽니다. |
| `FREMOVE(location, filename)` | 해당 없음 | 파일 시스템에서 지정된 파일을 제거합니다. |
| `FRENAME(location, filename, dest_dir, dest_file [, overwrite ])` | 해당 없음 | 지정된 파일의 이름을 변경합니다. |
| `FSEEK(file IN OUT [, absolute_offset IN] [, relative_offset IN])` | 해당 없음 | 지정된 바이트 수만큼 주어진 파일 내에서 파일 포인터를 이동합니다. |
| `GET_LINE(file, buffer OUT [, len ])` | 해당 없음 | `file`로 식별되는 파일에서 한 줄의 텍스트를 변수 `buffer`로 읽어 들입니다. `[, len ]`이 지정되면 읽은 바이트 수만큼 파일 포인터를 그에 맞게 조정합니다. |
| `GET_LINE_NCHAR(file, buffer OUT [, len ])` | 해당 없음 | `file`로 식별되는 파일에서 한 줄의 텍스트를 변수 `buffer`로 읽어 들이고 유니코드로 변환합니다. `[, len ]`이 지정되면 파일 끝(end-of-file) 종료 문자를 무시하고 읽은 바이트 수만큼 파일 포인터를 그에 맞게 조정합니다. |
| `GET_NEXTLINE(file, buffer OUT)` | 해당 없음 | `file`로 식별되는 파일에서 다음 텍스트 줄을 읽어 변수 `buffer`에 저장합니다. |
| `GET_RAW(file, buffer OUT [, len ])` | `BYTEA` | 파일에서 `RAW` 문자열 값을 읽어 읽기 버퍼에 보관하고, 파일 끝 종료 문자를 무시하고 읽은 바이트 수만큼 파일 포인터를 그에 맞게 조정합니다. |
| `IS_OPEN(file)` | `BOOLEAN` | 주어진 파일이 열려 있는지 여부를 판별합니다. |
| `NEW_LINE(file [, lines ])` | 해당 없음 | 파일에 줄 끝(end-of-line) 문자 시퀀스를 씁니다. |
| `PUT(file, buffer)` | 해당 없음 | `buffer`를 주어진 파일에 씁니다. `PUT`은 줄 끝 문자 시퀀스를 쓰지 않습니다. |
| `PUT_LINE(file, buffer [, autoflush ])` | 해당 없음 | `buffer`를 주어진 파일에 씁니다. `PUT_LINE`은 줄 끝 문자 시퀀스를 씁니다. |
| `PUT_LINE_NCHAR (file, buffer)` | 해당 없음 | `buffer`를 유니코드 형식으로 주어진 파일에 씁니다. `PUT_LINE_NCHAR`은 줄 끝 문자 시퀀스를 씁니다. |
| `PUTF(file, format [, arg1 ] [, ...])` | 해당 없음 | 형식화된 문자열을 주어진 파일에 씁니다. `format`에서 치환할 최대 다섯 개의 치환 파라미터 `arg1,...arg5`를 지정할 수 있습니다. `PUTF`는 줄 끝 문자 시퀀스를 쓰지 않습니다. |
| `PUTF_NCHAR(file, format [, arg1] [, arg2] [...])` | 해당 없음 | 형식화된 문자열을 유니코드로 주어진 파일에 씁니다. `PUTF_NCHAR`은 줄 끝 문자 시퀀스를 쓰지 않습니다. `format`에서 치환할 최대 다섯 개의 치환 파라미터 `arg1,...arg5`를 지정할 수 있습니다. |
| `PUT_NCHAR(file, buffer)` | 해당 없음 | `buffer`를 주어진 파일에 쓰고 데이터를 유니코드로 변환합니다. `PUT_NCHAR`은 줄 끝 문자 시퀀스를 쓰지 않습니다. |
| `PUT_RAW(file, buffer [, autoflush ])` | 해당 없음 | `RAW` 데이터 값을 입력으로 받아 그 값들을 출력 버퍼에 씁니다. `PUT_RAW`는 줄 끝 문자 시퀀스를 쓰지 않습니다. |

## utl_file.umask로 파일 권한 설정하기

`UTL_FILE` 함수나 프로시저가 파일을 생성할 때 기본 파일 권한은 다음과 같습니다.

```shell
-rw------- 1 enterprisedb enterprisedb 21 Jul 24 16:08 utlfile
```

`enterprisedb` 그룹에 속한 사용자와 다른 모든 사용자에게는 모든 권한이 거부됩니다. `enterprisedb` 사용자만 생성된 파일에 대한 읽기 및 쓰기 권한을 갖습니다.

`UTL_FILE` 함수와 프로시저가 생성하는 파일에 다른 파일 권한 집합을 적용하려면 `utl_file.umask` 구성 파라미터를 설정합니다.

`utl_file.umask` 파라미터는 Linux `umask` 명령과 유사한 방식으로 _파일 모드 생성 마스크(file mode creation mask)_ (또는 간단히 _마스크(mask)_)를 설정합니다. 이 파라미터는 EDB Postgres Advanced Server `UTL_FILE` 패키지에서만 사용됩니다.

##### 참고 (Note)

`utl_file.umask` 파라미터는 Windows 시스템에서 지원되지 않습니다.

`utl_file.umask`에 지정하는 값은 Linux `umask` 명령에 유효한 3자리 또는 4자리 8진수 문자열입니다. 이 설정은 `UTL_FILE` 함수와 프로시저가 생성하는 파일의 권한을 결정합니다. (파일 권한 및 `umask` 명령 사용에 대한 정보는 Linux 또는 Unix 시스템에 관한 정보 자료를 참조하세요.)

### 예제 (Example)

이 예제는 `utl_file.umask`로 파일 권한을 설정합니다.

먼저, `UTL_FILE` 패키지가 사용할 파일 시스템의 디렉터리를 설정합니다. 해당 운영 체제 계정 `enterprisedb` 또는 `postgres`가 디렉터리에서 읽고 쓸 수 있는지 확인하세요.

```shell
mkdir /tmp/utldir
chmod 777 /tmp/utldir
```

생성한 파일 시스템 디렉터리를 사용하여 디렉터리 데이터베이스 객체를 만들기 위해 `psql`에서 `CREATE DIRECTORY` 명령을 실행합니다. 디렉터리를 생성하려면 `CREATE ANY DIRECTORY` 시스템 권한이 있어야 합니다.

```sql
CREATE DIRECTORY utldir AS '/tmp/utldir';
```

`utl_file.umask` 구성 파라미터를 설정합니다. 다음 설정은 파일 소유자에게 모든 권한을 허용합니다. 그룹 사용자와 다른 사용자에게는 실행 권한을 제외한 모든 권한이 허용됩니다.

```sql
SET utl_file.umask TO '0011';
```

`utl_file.umask` 파라미터를 원하는 값으로 설정한 동일한 세션에서 `UTL_FILE` 함수와 프로시저를 실행합니다.

```sql
DECLARE
    v_utlfile       UTL_FILE.FILE_TYPE;
    v_directory     VARCHAR2(50) := 'utldir';
    v_filename      VARCHAR2(20) := 'utlfile';
BEGIN
    v_utlfile := UTL_FILE.FOPEN(v_directory, v_filename, 'w');
    UTL_FILE.PUT_LINE(v_utlfile, 'Simple one-line file');
    DBMS_OUTPUT.PUT_LINE('Created file: ' || v_filename);
    UTL_FILE.FCLOSE(v_utlfile);
END;
```

결과 파일의 권한 설정을 보면, 파일 소유자 외에도 그룹 사용자와 다른 사용자가 파일에 대한 읽기 및 쓰기 권한을 갖고 있음을 알 수 있습니다.

```shell
$ pwd
/tmp/utldir
$ ls -l
total 4
-rw-rw-rw- 1 enterprisedb enterprisedb 21 Jul 24 16:04 utlfile
```

`ALTER ROLE` 명령을 사용하여 역할별로 이 파라미터를 설정할 수도 있습니다. `ALTER DATABASE` 명령으로 단일 데이터베이스에 대해 설정하거나, `postgresql.conf` 파일에서 설정하여 전체 데이터베이스 서버 인스턴스에 대해 설정할 수 있습니다.

## FCLOSE

`FCLOSE` 프로시저는 열려 있는 파일을 닫습니다.

```sql
FCLOSE(<file> IN OUT FILE_TYPE)
```

### 파라미터 (Parameters)

`file`

닫을 파일의 파일 핸들을 포함하는 `FILE_TYPE` 타입의 변수입니다.

## FCLOSE_ALL

`FLCLOSE_ALL` 프로시저는 열려 있는 모든 파일을 닫습니다. 닫을 열린 파일이 없더라도 프로시저는 정상적으로 실행됩니다.

```sql
FCLOSE_ALL
```

## FCOPY

`FCOPY` 프로시저는 텍스트를 한 파일에서 다른 파일로 복사합니다.

```sql
FCOPY(<location> VARCHAR2, <filename> VARCHAR2, <dest_dir> VARCHAR2, <dest_file> VARCHAR2
  [, <start_line> PLS_INTEGER] [, <end_line> PLS_INTEGER ])
```

### 파라미터 (Parameters)

`location`

`pg_catalog.edb_dir.dirname`에 저장된, 복사할 파일이 있는 디렉터리의 디렉터리 이름입니다.

`filename`

복사할 원본 파일의 이름입니다.

`dest_dir`

`pg_catalog.edb_dir.dirname`에 저장된, 파일을 복사할 대상 디렉터리의 디렉터리 이름입니다.

`dest_file`

대상 파일의 이름입니다.

`start_line`

원본 파일에서 복사를 시작할 줄 번호입니다. 기본값은 `1`입니다.

`end_line`

원본 파일에서 복사할 마지막 줄의 줄 번호입니다. 기본값은 `NULL`이며, 원본 파일의 마지막 줄까지 텍스트를 복사합니다.

### 예제 (Examples)

이 예제는 `emp` 테이블의 직원 목록을 쉼표로 구분한 목록이 들어 있는 파일 `C:\TEMP\EMPDIR\empfile.csv`의 복사본을 만듭니다. 그런 다음 복사본 `empcopy.csv`가 나열됩니다.

```sql
CREATE DIRECTORY empdir AS 'C:/TEMP/EMPDIR';

DECLARE
    v_empfile       UTL_FILE.FILE_TYPE;
    v_src_dir       VARCHAR2(50) := 'empdir';
    v_src_file      VARCHAR2(20) := 'empfile.csv';
    v_dest_dir      VARCHAR2(50) := 'empdir';
    v_dest_file     VARCHAR2(20) := 'empcopy.csv';
    v_emprec        VARCHAR2(120);
    v_count         INTEGER := 0;
BEGIN
    UTL_FILE.FCOPY(v_src_dir,v_src_file,v_dest_dir,v_dest_file);
    v_empfile := UTL_FILE.FOPEN(v_dest_dir,v_dest_file,'r');
    DBMS_OUTPUT.PUT_LINE('The following is the destination file, ''' ||
        v_dest_file || '''');
    LOOP
        UTL_FILE.GET_LINE(v_empfile,v_emprec);
        DBMS_OUTPUT.PUT_LINE(v_emprec);
        v_count := v_count + 1;
    END LOOP;
    EXCEPTION
        WHEN NO_DATA_FOUND THEN
            UTL_FILE.FCLOSE(v_empfile);
            DBMS_OUTPUT.PUT_LINE(v_count || ' records retrieved');
        WHEN OTHERS THEN
            DBMS_OUTPUT.PUT_LINE('SQLERRM: ' || SQLERRM);
            DBMS_OUTPUT.PUT_LINE('SQLCODE: ' || SQLCODE);
END;
```

## FFLUSH

`FFLUSH` 프로시저는 쓰기 버퍼에서 아직 기록되지 않은 데이터를 파일로 플러시합니다.

```sql
FFLUSH(<file> FILE_TYPE)
```

### 파라미터 (Parameters)

`file`

### 예제 (Examples)

```sql
DECLARE

    CURSOR emp_cur IS SELECT * FROM emp ORDER BY empno;
BEGIN
    v_empfile := UTL_FILE.FOPEN(v_directory,v_filename,'w');
    FOR i IN emp_cur LOOP
        UTL_FILE.PUT(v_empfile,i.empno);
        UTL_FILE.PUT(v_empfile,',');
        UTL_FILE.PUT(v_empfile,i.ename);
        UTL_FILE.PUT(v_empfile,',');
        UTL_FILE.PUT(v_empfile,i.job);
        UTL_FILE.PUT(v_empfile,',');
        UTL_FILE.PUT(v_empfile,i.mgr);
        UTL_FILE.PUT(v_empfile,',');
        UTL_FILE.PUT(v_empfile,i.hiredate);
        UTL_FILE.PUT(v_empfile,',');
        UTL_FILE.PUT(v_empfile,i.sal);
        UTL_FILE.PUT(v_empfile,',');
        UTL_FILE.PUT(v_empfile,i.comm);
        UTL_FILE.PUT(v_empfile,',');
        UTL_FILE.PUT(v_empfile,i.deptno);
```

## FGETATTR

`FGETATTR` 함수는 주어진 파일의 속성을 가져옵니다. `filename`과 `location` 값을 입력하면 파일 존재 여부를 반환합니다.
파일이 존재하면 `file_length`와 `block_size` 값도 반환합니다.
파일이 존재하지 않거나 오류가 발생하면 속성은 `NULL`로 반환됩니다.

```sql
FGETATTR(<location> VARCHAR2, <filename> VARCHAR2, <fexists> OUT BOOLEAN, <file_length> OUT NUMBER, <block_size> OUT BINARY_INTEGER)
```

### 파라미터 (Parameters)

`location`

`pg_catalog.edb_dir.dirname`에 저장된, 속성을 가져올 파일이 있는 디렉터리의 이름입니다.

`filename`

속성을 가져올 파일의 이름입니다.

`exists`

파일 존재 여부에 대한 보고입니다.

`file_length`

파일의 크기(바이트)입니다.

`block_size`

파일의 시스템 블록 크기(바이트)입니다.

### 예제 (Examples)

이 예제는 파일 `empfile.csv`의 속성을 가져옵니다.

```sql
DECLARE
   l_file_exists BOOLEAN;
   l_file_len    NUMBER;
   l_blocksize   BINARY_INTEGER;
   f utl_file.file_type;
   v_empfile       UTL_FILE.FILE_TYPE;
   v_directory     VARCHAR2(50) := 'empdir';
   v_filename      VARCHAR2(20) := 'empfile.csv';

BEGIN
   utl_file.fgetattr(
     location    => v_directory,
     filename    => v_filename,
     fexists     => l_file_exists,
     file_length => l_file_len,
     block_size  => l_blocksize);
   IF l_file_exists THEN
     dbms_output.put_line('File found, size=' || l_file_len);
   ELSE
     dbms_output.put_line('File not found.');
   END IF;
END;
```

## FOPEN

`FOPEN` 함수는 입출력(I/O)을 위해 파일을 엽니다.

```sql
<filetype> FILE_TYPE FOPEN(<location> VARCHAR2, <filename> VARCHAR2,<open_mode> VARCHAR2
  [, <max_linesize> BINARY_INTEGER ])
```

### 파라미터 (Parameters)

`location`

`pg_catalog.edb_dir.dirname`에 저장된, 열 파일이 있는 디렉터리의 디렉터리 이름입니다.

`filename`

열 파일의 이름입니다.

`open_mode`

```text

- `r` &mdash; read from file.
- `w` &mdash; write to file.
```

최대 줄 크기를 초과하는지 판단할 때 줄 끝 문자가 포함됩니다.
이 프로시저는 Oracle과 호환됩니다.

`filetype`

열린 파일의 파일 핸들을 포함하는 `FILE_TYPE` 타입의 변수입니다.

## GET_NEXTLINE

`GET_NEXTLINE` 프로시저는 `file`로 식별되는 파일에서 다음 텍스트 줄을 읽어 변수 `buffer`에 저장합니다.


### 파라미터 (Parameters)

`file`

## GET_RAW

`GET_RAW` 프로시저는 파일에서 `RAW` 문자열 값을 읽어 읽기 버퍼에 보관하고, 읽은 바이트 수만큼 파일 포인터를 그에 맞게 조정합니다. `GET_RAW`는 파일 끝 종료 문자를 무시합니다. 더 이상 읽을 줄이 없으면 `INVALID_FILEHANDLE`, `INVALID_OPERATION`, `READ_ERROR` 예외가 발생합니다.

```sql
GET_RAW(<file> FILE_TYPE, <buffer> OUT BYTEA [, <len> INTEGER ])
```

### 파라미터 (Parameters)

`file`

열린 파일의 파일 핸들을 포함하는 `FILE_TYPE` 타입의 변수입니다.

`buffer`

파일의 `RAW` 데이터를 읽기 버퍼에 할당합니다.

`len`

파일에서 읽을 바이트 수입니다. 기본값은 `NULL`입니다. `NULL`이면 `len`은 최대 32767 `RAW` 바이트를 읽으려고 시도합니다.

### 예제 (Examples)

이 예제는 파일에서 `RAW` 문자열 값을 읽으려고 시도합니다.

```sql
CREATE DIRECTORY empdir  AS '/TMP/EMPDIR';

CREATE or REPLACE FUNCTION read_bin_file() RETURN void AS

DECLARE
    v_tempfile      UTL_FILE.FILE_TYPE;
    v_filename      VARCHAR2(20) := 'sample.png';
    v_temprec       BYTEA;
    v_count         INTEGER := 0;
BEGIN
    v_tempfile := UTL_FILE.FOPEN('empdir', v_filename, 'rb');
    UTL_FILE.GET_RAW(v_tempfile,v_temprec);
    INSERT INTO emp VALUES (1, v_temprec);
EXCEPTION
    WHEN NO_DATA_FOUND THEN
       RAISE NOTICE 'Finish % ', SQLERRM;
       UTL_FILE.FCLOSE(v_tempfile);
END;

edb=# SELECT read_bin_file();
```

## PUTF

`PUTF` 프로시저는 형식화된 문자열을 파일에 씁니다. `PUTF`는 줄 끝 문자 시퀀스를 쓰지 않습니다.
이 프로시저는 Oracle과 호환됩니다.

```sql
PUTF(<file> FILE_TYPE, <format> VARCHAR2 [, <arg1> VARCHAR2] [, ...])
```

### 파라미터 (Parameters)

`file`

형식화된 줄을 쓸 파일의 파일 핸들을 포함하는 `FILE_TYPE` 타입의 변수입니다.

`format`

파일에 쓰는 텍스트를 형식화하는 문자열입니다. 특수 문자 시퀀스 `%s`는 `arg`의 값으로 치환됩니다. 특수 문자 시퀀스 `\n`은 새 줄을 나타냅니다.

`arg1`

형식 문자열에서 `%s`가 나타날 때마다 치환할 최대 다섯 개의 인수 `arg1`,...`arg5`입니다. 모든 인수의 기본값은 `NULL`입니다.
첫 번째 arg는 `%s`의 첫 번째 발생에 치환되고, 두 번째 arg는 두 번째 발생에 치환되며, 이런 식으로 계속됩니다.

### 예제 (Examples)

다음 익명 블록은 `emp` 테이블의 데이터를 포함하는 형식화된 출력을 생성합니다.

##### 참고 (Note)

형식 문자열에서 줄 끝 문자 시퀀스에 사용된 E 리터럴 구문과 이중 백슬래시는 Oracle 데이터베이스와 호환되지 않습니다.

```sql
DECLARE
    v_empfile       UTL_FILE.FILE_TYPE;
    v_directory     VARCHAR2(50) := 'empdir';
    v_filename      VARCHAR2(20) := 'empfile.csv';
    v_format        VARCHAR2(200);
    CURSOR emp_cur IS SELECT * FROM emp ORDER BY empno;
BEGIN
    v_format := E'%s %s, %s\\nSalary: $%s Commission: $%s\\n\\n';
    v_empfile := UTL_FILE.FOPEN(v_directory,v_filename,'w');
    FOR i IN emp_cur LOOP
        UTL_FILE.PUTF(v_empfile,v_format,i.empno,i.ename,i.job,i.sal,
            NVL(i.comm,0));
    END LOOP;
    DBMS_OUTPUT.PUT_LINE('Created file: ' || v_filename);
    UTL_FILE.FCLOSE(v_empfile);
EXCEPTION
    WHEN OTHERS THEN
        DBMS_OUTPUT.PUT_LINE('SQLERRM: ' || SQLERRM);
        DBMS_OUTPUT.PUT_LINE('SQLCODE: ' || SQLCODE);
END;

Created file: empfile.csv
```

## PUTF_NCHAR

`PUTF_NCHAR` 프로시저는 형식화된 문자열을 유니코드 형식으로 주어진 파일에 씁니다. `PUTF_NCHAR`은 줄 끝 문자 시퀀스를 쓰지 않습니다.
`format`에서 치환할 최대 다섯 개의 치환 파라미터 `arg1,...arg5`를 지정할 수 있습니다. 치환 파라미터의 기본값은 `NULL`입니다.

```sql
PUTF_NCHAR(<file> FILE_TYPE, <format> VARCHAR2 [, <arg1> VARCHAR2] [, ...])
```

### 파라미터 (Parameters)

`file`

형식화된 줄을 쓸 파일의 파일 핸들을 포함하는 `FILE_TYPE` 타입의 변수입니다.

`format`

파일에 쓰는 텍스트를 형식화하는 문자열입니다. 특수 문자 시퀀스 `%s`는 `arg`의 값으로 치환됩니다. 특수 문자 시퀀스 `\n`은 새 줄을 나타냅니다.

`arg1`

형식 문자열에서 `%s`가 나타날 때마다 치환할 최대 다섯 개의 인수 `arg1`,...`arg5`입니다. 모든 인수의 기본값은 `NULL`입니다.
첫 번째 arg는 `%s`의 첫 번째 발생에 치환되고, 두 번째 arg는 두 번째 발생에 치환되며, 이런 식으로 계속됩니다.

### 예제 (Examples)

## PUT_NCHAR

`PUT_NCHAR` 프로시저는 `buffer`를 주어진 파일에 쓰고 데이터를 유니코드로 변환합니다. `PUT_NCHAR`은 줄 끝 문자 시퀀스를 쓰지 않습니다.

```sql
PUT_NCHAR(<file> FILE_TYPE, <buffer> NVARCHAR2)
```

### 파라미터 (Parameters)

`file`

줄을 쓸 파일의 파일 핸들을 포함하는 `FILE_TYPE` 타입의 변수입니다.

`buffer`

출력 버퍼에 `RAW` 데이터를 쓸 변수입니다.

### 예제 (Examples)

이 예제는 `buffer`를 파일 `empfile.csv`에 쓰고 데이터를 유니코드로 변환합니다.

```sql
declare
    f utl_file.file_type;
    t text;
    v_empfile       UTL_FILE.FILE_TYPE;
    v_directory     VARCHAR2(50) := 'empdir';
    v_filename      VARCHAR2(20) := 'empfile1.csv';
    txt1            text;
begin
  f := utl_file.fopen_nchar(v_directory, v_filename, 'w');
  utl_file.put_nchar(f, 'Hello - 1'::text);
  utl_file.put_nchar(f, 100::numeric);
  utl_file.put_nchar(f, '2006-08-13 12:34:56'::timestamp);
  utl_file.put_nchar(f, '2001-12-27 04:05:06.789-08'::pg_catalog.date);
  utl_file.put_nchar(f, '2001-12-27 04:05:06.789-08'::time);
  utl_file.fclose(f);

  f := utl_file.fopen_nchar(v_directory, v_filename, 'r');
  loop
    utl_file.get_line_nchar(f, txt1);
    raise notice '%', txt1;
  end loop;
exception
  when no_data_found then
    raise notice 'finish % ', sqlerrm;
    utl_file.fclose(f);

end;
NOTICE:  Hello - 110013-AUG-06 12:34:5627-DEC-01 00:00:00 +00:0004:05:06.789
NOTICE:  finish no data found
```

## PUT_RAW

`PUT_RAW` 프로시저는 `RAW` 데이터 값을 받아 그 값들을 출력 버퍼에 씁니다. `PUT_RAW`는 줄 끝 문자 시퀀스를 쓰지 않습니다.

```sql
PUT_RAW(<file> FILE_TYPE, <buffer> BYTEA [, <autoflush> BOOLEAN ])
```

### 파라미터 (Parameters)

`file`

줄을 쓸 파일의 파일 핸들을 포함하는 `FILE_TYPE` 타입의 변수입니다.

`buffer`

출력 버퍼에 `RAW` 데이터를 쓸 변수입니다.

`autoflush`

`TRUE`이면 값을 출력 버퍼에 쓴 후 플러시를 수행합니다. 기본적으로 `autoflush`는 `FALSE`입니다.

### 예제 (Examples)

이 예제는 `emp` 테이블의 `RAW` 데이터 값을 씁니다.

```sql
CREATE or REPLACE FUNCTION write_bin_file() RETURN void AS

DECLARE
    v_tempfile      UTL_FILE.FILE_TYPE;
    v_filename      VARCHAR2(20) := 'sample.png';
    v_temprec       BYTEA;
BEGIN
SELECT imagerawdata INTO v_temprec from emp;
    v_tempfile := UTL_FILE.FOPEN('empdir', v_filename, 'wb');
    UTL_FILE.PUT_RAW(v_tempfile,v_temprec, TRUE);
    UTL_FILE.FCLOSE(v_tempfile);
END;

edb=# SELECT write_bin_file();
```
