# BIND_ARRAY — EPAS 18 내장 패키지 DBMS_SQL
> 원문: [EPAS v18 — Reference › Oracle compatibility › Built-in packages › DBMS_SQL › BIND_ARRAY](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_bip_guide/03_built-in_packages/17_dbms_sql/001_bind_array/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 패키지·프로시저·함수 이름은 원문 그대로 보존했습니다.

`BIND_ARRAY` 프로시저는 변수의 이름을 기준으로, 커서 내의 변수에 하나의 값 또는 값의 집합을 바인딩합니다.

```sql
BIND_ARRAY (<c> IN NUMBER, <name> IN VARCHAR2,
  <table_variable> IN { FLOAT_TABLE | BLOB_TABLE | CLOB_TABLE | VARCHAR2_TABLE | NUMBER_TABLE | TIMESTAMP_TABLE |
  INTEGER_TABLE | ROWID_TABLE | TEXT_TABLE } [,<index1> IN NUMBER, <index2> IN NUMBER]);
```

## 파라미터 (Parameters)

`c`

바인딩할 값이 있는 SQL 명령에 대한 커서의 커서 ID입니다.

`name`

컬렉션의 이름입니다. 이름은 30바이트 이하여야 합니다.

`table_variable`

다음 데이터타입 중 하나로 선언된 로컬 변수입니다.

| Datatype | Description |
| --- | --- |
| <bflt_tab> | FLOAT_TABLE |
| <bl_tab> | BLOB_TABLE |
| <cl_tab> | CLOB_TABLE |
| <c_tab> | VARCHAR2_TABLE |
| <n_tab> | NUMBER_TABLE |
| <tms_tab> | TIMESTAMP_TABLE |
| <int_tab> | INTEGER_TABLE |
| <rid_tab> | ROWID_TABLE |
| <txt_tab> | TEXT_TABLE |

`index1`

범위를 바인딩하는 경우, 범위의 하한을 표시하는 테이블 요소의 인덱스입니다. 이 값은 `index2`의 값보다 작거나 같아야 합니다. `index1`과 `index2` 사이의 모든 요소가 바인드에 사용됩니다. 이는 선택적 파라미터로, 세 개의 파라미터 또는 다섯 개의 파라미터와 함께 사용할 수 있으나 네 개의 파라미터와는 사용할 수 없습니다.

`index2`

범위의 상한을 표시하는 테이블 요소의 인덱스입니다. 이는 선택적 파라미터로, 세 개의 파라미터 또는 다섯 개의 파라미터와 함께 사용할 수 있으나 네 개의 파라미터와는 사용할 수 없습니다.

## 참고 (Notes)

바인드 호출에서 인덱스를 지정하지 않았고 하나의 문에서 서로 다른 두 바인드가 서로 다른 개수의 요소를 포함하는 테이블을 지정하는 경우, 실제로 사용되는 요소의 개수는 모든 테이블 중 최소 개수입니다. 인덱스를 지정하는 경우에도 마찬가지입니다. 모든 테이블에 대해 두 인덱스 사이의 최소 범위가 선택됩니다.

쿼리의 모든 바인드 변수가 배열 바인드여야 하는 것은 아닙니다. 일부는 일반 바인드일 수 있으며, 이 경우 표현식 평가 등에서 컬렉션의 각 요소에 대해 동일한 값이 사용됩니다.

## 예제 (Example)

```sql
CREATE TABLE tab_test (col_int INTEGER, col_charactervarying VARCHAR(40));

-- BIND_ARRAY (used for multiple insert/update/delete in single command
DECLARE
   c            INTEGER;
   dbms_return  INTEGER;
   res          NUMBER;
   fetch_ret    INTEGER;
   varint       DBMS_SQL.INTEGER_TABLE;
BEGIN
   c := DBMS_SQL.OPEN_CURSOR;
   DBMS_SQL.PARSE (c,'INSERT into tab_test(col_int, col_charactervarying) values ( :bvarint, :bvarname )',
            DBMS_SQL.NATIVE);
   varint(1) := 10;
   varint(2) := 11;
   varint(4) := 12;
   DBMS_SQL.BIND_ARRAY (c, 'bvarint', varint);
   DBMS_SQL.BIND_VARIABLE (c, 'bvarname', 'edb_user');
   dbms_return := DBMS_SQL.EXECUTE(c);
   DBMS_OUTPUT.PUT_LINE(' RETURN VALUE ...' || dbms_return );
   COMMIT;
   DBMS_SQL.CLOSE_CURSOR (c);
END;
/

-- this inserts three rows using bind_array so verify them in the table.
SELECT * FROM tab_test;
 col_int | col_charactervarying
---------+----------------------
      10 | edb_user
      11 | edb_user
      12 | edb_user
-- For col_int we are passing bind_array with the size of 3 elements, and as col_charactervarying we are
-- passing bind_variable. So for all the insertions, we are using same bind_variable (edb_user).

(3 rows)
```
