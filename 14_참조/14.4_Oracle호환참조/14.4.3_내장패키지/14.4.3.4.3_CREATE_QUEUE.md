> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 패키지·프로시저·함수 이름은 원문 그대로 보존했습니다.

# CREATE_QUEUE

기존 큐 테이블에 큐를 생성하려면 `CREATE_QUEUE` 프로시저를 사용합니다. 시그니처는 다음과 같습니다.

```sql
CREATE_QUEUE(
  <queue_name> IN VARCHAR2
  <queue_table> IN VARCHAR2,
  <queue_type> IN BINARY_INTEGER DEFAULT NORMAL_QUEUE,
  <max_retries> IN NUMBER DEFAULT 5,
  <retry_delay> IN NUMBER DEFAULT 0
  <retention_time> IN NUMBER DEFAULT 0,
  <dependency_tracking> IN BOOLEAN DEFAULT FALSE,
  <comment> IN VARCHAR2 DEFAULT NULL,
  <auto_commit> IN BOOLEAN DEFAULT TRUE)
```

## 매개변수 (Parameters)

`queue_name`

새 큐의 이름입니다.

`queue_table`

새 큐가 위치하는 테이블의 이름입니다.

`queue_type`

새 큐의 유형입니다. `queue_type`에 유효한 값은 다음과 같습니다.

`DBMS_AQADM.NORMAL_QUEUE` — 이 값은 일반 큐(normal queue)를 지정합니다(기본값).

`DBMS_AQADM.EXCEPTION_QUEUE` — 이 값은 새 큐가 예외 큐(exception queue)임을 지정합니다. 예외 큐는 디큐(dequeue) 작업만 지원합니다.

`max_retries`

`max_retries`는 디큐(dequeue) 문으로 메시지를 제거하려는 시도의 최대 횟수를 지정합니다. `max_retries` 값은 각 `ROLLBACK` 문마다 증가합니다. 실패한 시도 횟수가 `max_retries`로 지정한 값에 도달하면 해당 메시지는 예외 큐로 이동됩니다. 시스템 테이블의 기본값은 `0`입니다. 사용자가 생성한 테이블의 기본값은 `5`입니다.

`retry_delay`

`retry_delay`는 `ROLLBACK` 이후 메시지가 재처리되도록 예약되기까지의 시간을 초 단위로 지정합니다. 메시지를 즉시 재시도하려면 `0`(기본값)을 지정합니다.

`retention_time`

`retention_time`은 메시지가 디큐된 후 저장되는 시간의 길이(초 단위)를 지정합니다. 디큐 후 메시지를 보존하지 않으려면 `0`(기본값)을 지정할 수 있고, 메시지를 영구히 보존하려면 `INFINITE`를 지정할 수 있습니다.

`dependency_tracking`

이 매개변수는 호환성을 위해 허용되며 무시됩니다.

`comment`

`comment`는 큐와 연결된 주석을 지정합니다.

`auto_commit`

이 매개변수는 호환성을 위해 허용되며 무시됩니다.

## 예제 (Example)

다음 익명 블록은 `work_order_table` 테이블에 `work_order`라는 이름의 큐를 생성합니다.

```sql
BEGIN
DBMS_AQADM.CREATE_QUEUE ( queue_name => 'work_order', queue_table =>
'work_order_table', comment => 'This queue contains pending work orders.');
END;
```
