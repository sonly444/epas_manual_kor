# UTL_HTTP

`UTL_HTTP` 패키지는 HTTP 또는 HTTPS 프로토콜을 사용하여 URL에 있는 정보를 검색하는 방법을 제공합니다. EDB Postgres Advanced Server는 다음 함수와 프로시저를 지원합니다.

| 함수/프로시저                                        | 반환 타입                 | 설명                                                                |
| ---------------------------------------------------- | ------------------------- | ------------------------------------------------------------------- |
| `BEGIN_REQUEST(url, method, http_version)`         | `UTL_HTTP.REQ`          | 새 HTTP 요청을 시작합니다.                                          |
| `END_REQUEST(r IN OUT)`                            | 해당 없음                 | HTTP 요청을 완료하기 전에 종료합니다.                               |
| `END_RESPONSE(r IN OUT)`                           | 해당 없음                 | HTTP 응답을 종료합니다.                                             |
| `GET_BODY_CHARSET`                                 | `VARCHAR2`              | 이후 HTTP 요청 본문의 기본 문자 집합을 반환합니다.                  |
| `GET_BODY_CHARSET(charset OUT)`                    | 해당 없음                 | 이후 HTTP 요청 본문의 기본 문자 집합을 반환합니다.                  |
| `GET_FOLLOW_REDIRECT(max_redirects OUT)`           | 해당 없음                 | 허용되는 최대 리디렉션 횟수에 대한 현재 설정입니다.                 |
| `GET_HEADER(r IN OUT, n, name OUT, value OUT)`     | 해당 없음                 | HTTP 응답의 n번째 헤더를 반환합니다.                                |
| `GET_HEADER_BY_NAME(r IN OUT, name, value OUT, n)` | 해당 없음                 | 지정된 이름에 대한 HTTP 응답 헤더를 반환합니다.                     |
| `GET_HEADER_COUNT(r IN OUT)`                       | `INTEGER`               | HTTP 응답 헤더의 수를 반환합니다.                                   |
| `GET_RESPONSE(r IN OUT)`                           | `UTL_HTTP.RESP`         | HTTP 응답을 반환합니다.                                             |
| `GET_RESPONSE_ERROR_CHECK(enable OUT)`             | 해당 없음                 | 응답 오류 검사가 설정되어 있는지 여부를 반환합니다.                 |
| `GET_TRANSFER_TIMEOUT(timeout OUT)`                | 해당 없음                 | HTTP 요청에 대한 전송 타임아웃 설정을 반환합니다.                   |
| `READ_LINE(r IN OUT, data OUT, remove_crlf)`       | 해당 없음                 | 줄 끝까지 HTTP 응답 본문을 텍스트 형식으로 반환합니다.              |
| `READ_RAW(r IN OUT, data OUT, len)`                | 해당 없음                 | 지정된 바이트 수만큼 HTTP 응답 본문을 바이너리 형식으로 반환합니다. |
| `READ_TEXT(r IN OUT, data OUT, len)`               | 해당 없음                 | 지정된 문자 수만큼 HTTP 응답 본문을 텍스트 형식으로 반환합니다.     |
| `REQUEST(url)`                                     | `VARCHAR2`              | 웹 페이지의 내용을 반환합니다.                                      |
| `REQUEST_PIECES(url, max_pieces)`                  | `UTL_HTTP. HTML_PIECES` | URL에서 검색한 2000바이트 세그먼트의 테이블을 반환합니다.           |
| `SET_BODY_CHARSET(charset)`                        | 해당 없음                 | 이후 HTTP 요청 본문의 기본 문자 집합을 설정합니다.                  |
| `SET_FOLLOW_REDIRECT(max_redirects)`               | 해당 없음                 | 리디렉션 명령을 따라갈 최대 횟수를 설정합니다.                      |
| `SET_FOLLOW_REDIRECT(r IN OUT, max_redirects)`     | 해당 없음                 | 개별 요청에 대해 리디렉션 명령을 따라갈 최대 횟수를 설정합니다.     |
| `SET_HEADER(r IN OUT, name, value)`                | 해당 없음                 | HTTP 요청 헤더를 설정합니다.                                        |
| `SET_RESPONSE_ERROR_CHECK(enable)`                 | 해당 없음                 | HTTP 4xx 및 5xx 상태 코드를 오류로 취급할지 여부를 결정합니다.      |
| `SET_TRANSFER_TIMEOUT(timeout)`                    | 해당 없음                 | HTTP 요청에 대한 기본 전송 타임아웃 값을 설정합니다.                |
| `SET_TRANSFER_TIMEOUT(r IN OUT, timeout)`          | 해당 없음                 | 개별 HTTP 요청에 대한 전송 타임아웃 값을 설정합니다.                |
| `WRITE_LINE(r IN OUT, data)`                       | 해당 없음                 | CRLF로 종료되는 데이터를 HTTP 요청 본문에 TEXT 형식으로 씁니다.     |
| `WRITE_RAW(r IN OUT, data)`                        | 해당 없음                 | 데이터를 HTTP 요청 본문에 BINARY 형식으로 씁니다.                   |
| `WRITE_TEXT(r IN OUT, data)`                       | 해당 없음                 | 데이터를 HTTP 요청 본문에 TEXT 형식으로 씁니다.                     |

EDB Postgres Advanced Server의 `UTL_HTTP` 구현은 Oracle 버전과 비교할 때 부분 구현입니다. 표에 나열된 함수와 프로시저만 지원됩니다.

##### 참고 (Note)

해당 응답들은 SET_RESPONSE_ERROR_CHECK를 TRUE로 설정한 경우에 Oracle에서 이 옵션을 구성할 수 있으며, 기본값은 `FALSE`입니다. TRUE로 설정한 경우에 EDB Postgres Advanced Server에서 `HTTP 4xx` 또는 `HTTP 5xx` 응답은 데이터베이스 오류를 발생시킵니다. 

EDB Postgres Advanced Server에서 `UTL_HTTP` 텍스트 인터페이스는 다운로드된 데이터가 데이터베이스 인코딩으로 되어 있을 것으로 기대합니다. 현재 사용 가능한 모든 인터페이스는 텍스트 인터페이스입니다. Oracle에서는 HTTP 헤더에서 인코딩이 감지됩니다. 헤더가 없으면 기본값을 구성할 수 있으며 기본값은 `ISO-8859-1`입니다.

EDB Postgres Advanced Server는 수신하는 모든 쿠키를 무시합니다.

Oracle에서 발생할 수 있는 `UTL_HTTP` 예외는 EDB Postgres Advanced Server에서 인식되지 않습니다. 또한 EDB Postgres Advanced Server가 반환하는 오류 코드는 Oracle이 반환하는 것과 동일하지 않습니다.

## HTML_PIECES

`UTL_HTTP` 패키지는 `HTML_PIECES`라는 타입을 선언하며, 이는 `BINARY INTEGER`로 인덱싱된 `VARCHAR2 (2000)` 타입의 테이블입니다. 이 타입의 값은 `REQUEST_PIECES` 함수에 의해 반환됩니다.

```sql
TYPE html_pieces IS TABLE OF VARCHAR2(2000) INDEX BY BINARY_INTEGER;
```

## REQ

`REQ` 레코드 타입은 각 HTTP 요청에 대한 정보를 담고 있습니다.

```sql
TYPE req IS RECORD (
    url             VARCHAR2(32767),    -- URL to be accessed
    method          VARCHAR2(64),       -- HTTP method
    http_version    VARCHAR2(64),       -- HTTP version
    private_hndl    INTEGER             -- Holds handle for this request
);
```

## RESP

`RESP` 레코드 타입은 각 HTTP 요청의 응답에 대한 정보를 담고 있습니다.

```sql
TYPE resp IS RECORD (
    status_code     INTEGER,            -- HTTP status code
    reason_phrase   VARCHAR2(256),      -- HTTP response reason phrase
    http_version    VARCHAR2(64),       -- HTTP version
    private_hndl    INTEGER             -- Holds handle for this response
);
```

## BEGIN_REQUEST

`BEGIN_REQUEST` 함수는 새 HTTP 요청을 시작합니다. 지정된 URL로 웹 서버에 네트워크 연결이 설정됩니다. 시그니처는 다음과 같습니다.

```sql
BEGIN_REQUEST(<url> IN VARCHAR2, <method> IN VARCHAR2 DEFAULT
'GET ', <http_version> IN VARCHAR2 DEFAULT NULL) RETURN
UTL_HTTP.REQ
```

`BEGIN_REQUEST` 함수는 `UTL_HTTP.REQ` 타입의 레코드를 반환합니다.

### 파라미터 (Parameters)

`url`

`url`은 `UTL_HTTP`가 콘텐츠를 반환하는 URL(Uniform Resource Locator)입니다.

`method`

`method`는 사용할 HTTP 메서드입니다. 기본값은 `GET`입니다.

`http_version`

`http_version`은 요청을 보내는 HTTP 프로토콜 버전입니다. `HTTP/1.0` 또는 `HTTP/1.1` 중 하나를 지정합니다. 기본값은 null입니다. 이 경우 `UTL_HTTP` 패키지가 지원하는 최신 HTTP 프로토콜 버전인 1.1이 사용됩니다.

## END_REQUEST

`END_REQUEST` 프로시저는 HTTP 요청을 종료합니다. 요청을 완료하고 응답을 기다리지 않고 HTTP 요청을 종료하려면 `END_REQUEST` 프로시저를 사용합니다. 정상적인 프로세스는 요청을 시작하고, 응답을 받은 다음, 응답을 닫는 것입니다. 시그니처는 다음과 같습니다.

```sql
END_REQUEST(<r> IN OUT UTL_HTTP.REQ)
```

### 파라미터 (Parameters)

`r`

`r`은 HTTP 요청 레코드입니다.

## END_RESPONSE

`END_RESPONSE` 프로시저는 HTTP 응답을 종료합니다. `END_RESPONSE` 프로시저는 HTTP 요청과 응답을 완료합니다. 이것은 요청과 응답 프로세스를 종료하는 정상적인 방법입니다. 시그니처는 다음과 같습니다.

```sql
END_RESPONSE(<r> IN OUT UTL_HTTP.RESP)
```

### 파라미터 (Parameters)

`r`

`r`은 `HTTP` 응답 레코드입니다.

## GET_BODY_CHARSET

`GET_BODY_CHARSET` 프로그램은 프로시저와 함수 두 가지 형식으로 제공됩니다. `GET_BODY_CHARSET` 호출은 이후 HTTP 요청 본문의 기본 문자 집합을 반환합니다.

프로시저 시그니처는 다음과 같습니다.

```sql
GET_BODY_CHARSET(<charset> OUT VARCHAR2)
```

함수 시그니처는 다음과 같습니다.

```sql
GET_BODY_CHARSET() RETURN VARCHAR2
```

이 함수는 `VARCHAR2` 값을 반환합니다.

### 파라미터 (Parameters)

`charset`

`charset`은 본문의 문자 집합입니다.

### 예제 (Examples)

이 예제는 `GET_BODY_CHARSET` 함수의 사용을 보여줍니다.

```sql
edb=# SELECT UTL_HTTP.GET_BODY_CHARSET() FROM DUAL;
```

출력(Output)

```text
 get_body_charset
------------------
 ISO-8859-1
(1 row)
```

## GET_FOLLOW_REDIRECT

`GET_FOLLOW_REDIRECT` 프로시저는 허용되는 최대 리디렉션 횟수에 대한 현재 설정을 반환합니다. 시그니처는 다음과 같습니다.

```sql
GET_FOLLOW_REDIRECT(<max_redirects> OUT INTEGER)
```

### 파라미터 (Parameters)

`max_redirects`

`max_redirects`는 허용되는 최대 리디렉션 횟수입니다.

## GET_HEADER

`GET_HEADER` 프로시저는 HTTP 응답의 `nth`(n번째) 헤더를 반환합니다. 시그니처는 다음과 같습니다.

```sql
GET_HEADER(<r> IN OUT UTL_HTTP.RESP, <n> INTEGER, <name> OUT
VARCHAR2, <value> OUT VARCHAR2)
```

### 파라미터 (Parameters)

`r`

`r`은 HTTP 응답 레코드입니다.

`n`

`n`은 검색할 HTTP 응답 레코드의 `nth`(n번째) 헤더입니다.

`name`

`name`은 응답 헤더의 이름입니다.

`value`

`value`는 응답 헤더의 값입니다.

### 예제 (Examples)

이 예제는 헤더 수를 검색한 다음 헤더를 검색합니다.

```sql
DECLARE
    v_req           UTL_HTTP.REQ;
    v_resp          UTL_HTTP.RESP;
    v_name          VARCHAR2(30);
    v_value         VARCHAR2(200);
    v_header_cnt    INTEGER;
BEGIN
 -- Initiate request and get response
    v_req := UTL_HTTP.BEGIN_REQUEST('www.enterprisedb.com');
    v_resp := UTL_HTTP.GET_RESPONSE(v_req);

 -- Get header count
    v_header_cnt := UTL_HTTP.GET_HEADER_COUNT(v_resp);
    DBMS_OUTPUT.PUT_LINE('Header Count: ' || v_header_cnt);

 -- Get all headers
    FOR i IN 1 .. v_header_cnt LOOP

        DBMS_OUTPUT.PUT_LINE(v_name || ': ' || v_value);
    END LOOP;

 -- Terminate request
    UTL_HTTP.END_RESPONSE(v_resp);
END;
```

## WRITE_TEXT

`WRITE_TEXT` 프로시저는 데이터를 HTTP 요청 본문에 텍스트 형식으로 씁니다. 시그니처는 다음과 같습니다.

```sql
WRITE_TEXT(<r> IN OUT UTL_HTTP.REQ, <data> IN VARCHAR2)
```

### 파라미터 (Parameters)

`r`

`r`은 HTTP 요청 레코드입니다.

`data`

`data`는 텍스트 형식의 요청 본문입니다.

### 예제 (Example)

이 예제는 HTTP `POST` 메서드를 사용하여 보낼 요청 본문에 데이터(`Account balance $500.00`)를 텍스트 형식으로 씁니다. 데이터는 데이터를 수락하고 처리하는 웹 애플리케이션(`post.php`)으로 전송됩니다.

```sql
DECLARE
    v_req           UTL_HTTP.REQ;
    v_resp          UTL_HTTP.RESP;
BEGIN
    v_req := UTL_HTTP.BEGIN_REQUEST('http://www.example.com/post.php',
       'POST');
    UTL_HTTP.SET_HEADER(v_req, 'Content-Length', '23');
    UTL_HTTP.WRITE_TEXT(v_req, 'Account balance $500.00');
    v_resp := UTL_HTTP.GET_RESPONSE(v_req);
    DBMS_OUTPUT.PUT_LINE('Status Code: ' || v_resp.status_code);
    DBMS_OUTPUT.PUT_LINE('Reason Phrase: ' || v_resp.reason_phrase);
    UTL_HTTP.END_RESPONSE(v_resp);
END;
```

웹 애플리케이션이 `POST` 메서드를 성공적으로 처리하면, 다음 출력(Output)이 표시됩니다.

```text
Status Code: 200
Reason Phrase: OK
```

## END_OF_BODY

`END_OF_BODY` 예외는 HTTP 응답 본문의 끝에 도달하면 발생합니다.

### 예제 (Example)

이 예제는 예외를 처리하고 HTTP `POST` 메서드를 사용하여 보낼 요청 본문에 `Exception caught`를 텍스트 형식으로 씁니다. 데이터는 데이터를 수락하고 처리하는 웹 애플리케이션(`post.php`)으로 전송됩니다.

```sql
DECLARE
    req UTL_HTTP.REQ;
    resp UTL_HTTP.RESP;
    value VARCHAR2(32768);
BEGIN
    req := UTL_HTTP.BEGIN_REQUEST('https://www.google.com/');
    resp := UTL_HTTP.GET_RESPONSE(req);
LOOP
    UTL_HTTP.READ_LINE(resp, value, TRUE);
END LOOP;
    UTL_HTTP.END_RESPONSE(resp);
EXCEPTION
    WHEN UTL_HTTP.END_OF_BODY THEN
        DBMS_OUTPUT.PUT_LINE('Exception caught');
        UTL_HTTP.END_RESPONSE(resp);
END;
```

웹 애플리케이션이 `POST` 메서드를 성공적으로 처리하면, 다음 출력(Output)이 표시됩니다.

```text
Output is:
Exception caught
```
