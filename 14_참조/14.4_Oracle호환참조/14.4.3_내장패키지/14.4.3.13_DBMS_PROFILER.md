# DBMS_PROFILER — EPAS 18 내장 패키지

> 원문: [EPAS v18 — Reference › Oracle compatibility › Built-in packages › DBMS_PROFILER](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_bip_guide/03_built-in_packages/11_dbms_profiler/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 패키지·프로시저·역할 이름은 원문 그대로 보존했습니다.

`DBMS_PROFILER` 패키지는 성능 프로파일링 세션 동안 실행되는 PL/pgSQL 및 SPL 문에 대한 성능 정보를 수집하고 저장합니다. 프로파일링 도구를 제어하려면 이러한 함수와 프로시저를 사용하십시오.

| 함수/프로시저 | 반환 타입 | 설명 |
| --- | --- | --- |
| `FLUSH_DATA` | Status Code 또는 Exception | 세션을 종료하지 않고 현재 세션에서 수집된 성능 데이터를 플러시합니다. 프로파일링은 계속됩니다. |
| `GET_VERSION(major OUT, minor OUT)` | 해당 없음 | 이 패키지의 버전 번호를 반환합니다. |
| `INTERNAL_VERSION_CHECK` | Status Code | 현재 버전의 프로파일러가 현재 데이터베이스에서 작동하는지 확인합니다. |
| `PAUSE_PROFILER` | Status Code 또는 Exception | 데이터 수집을 일시 중지합니다. |
| `RESUME_PROFILER` | Status Code 또는 Exception | 데이터 수집을 재개합니다. |
| `START_PROFILER(run_comment, run_comment1 [, run_number OUT ])` | Status Code 또는 Exception | 데이터 수집을 시작합니다. |
| `STOP_PROFILER` | Status Code 또는 Exception | 데이터 수집을 중지하고 성능 데이터를 `PLSQL_PROFILER_RAWDATA` 테이블로 플러시합니다. |

`DBMS_PROFILER` 패키지의 함수는 성공 또는 실패를 나타내는 상태 코드를 반환합니다. `DBMS_PROFILER` 프로시저는 실패가 발생한 경우에만 예외를 발생시킵니다. 다음 표는 함수가 반환하는 상태 코드와 메시지, 그리고 프로시저가 발생시키는 예외를 보여줍니다.

| 상태 코드 | 메시지 | 예외 | 설명 |
| --- | --- | --- | --- |
| `-1` | `error version` | `version_mismatch` | 프로파일러 버전과 데이터베이스가 호환되지 않습니다. |
| `0` | `success` | 해당 없음 | 작업이 성공적으로 완료되었습니다. |
| `1` | `error_param` | `profiler_error` | 작업이 잘못된 매개변수를 받았습니다. |
| `2` | `error_io` | `profiler_error` | 데이터 플러시 작업이 실패했습니다. |

## FLUSH_DATA

`FLUSH_DATA` 함수/프로시저는 프로파일러 세션을 종료하지 않고 현재 세션에서 수집된 데이터를 플러시합니다. 데이터는 EDB Postgres Advanced Server Performance Features Guide에 설명된 테이블로 플러시됩니다. 함수 및 프로시저 시그니처는 다음과 같습니다.

```sql
<status> INTEGER FLUSH_DATA

FLUSH_DATA
```

### 매개변수 (Parameters)

`status`

작업이 반환하는 상태 코드입니다.

## GET_VERSION

`GET_VERSION` 프로시저는 `DBMS_PROFILER`의 버전을 반환합니다. 프로시저 시그니처는 다음과 같습니다.

```sql
GET_VERSION(<major> OUT INTEGER, <minor> OUT INTEGER)
```

## DBMS_PROFILER 사용

`DBMS_PROFILER` 패키지는 프로파일링 세션 동안 실행되는 PL/pgSQL 및 SPL 문에 대한 성능 정보를 수집하고 저장합니다. 프로파일러가 제공하는 테이블과 뷰에서 성능 정보를 검토할 수 있습니다.

`DBMS_PROFILER`는 프로파일링 세션에서 실행되는 PL/pgSQL 또는 SPL 문의 각 행에 대해 성능 관련 카운터와 타이머 집합을 기록하는 방식으로 작동합니다. 카운터와 타이머는 `SYS.PLSQL_PROFILER_DATA`라는 이름의 테이블에 저장됩니다. 프로파일링 세션을 완료하면 `DBMS_PROFILER`는 세션에서 실행된 PL/pgSQL 또는 SPL 코드의 각 행에 대해 성능 통계 테이블에 하나의 행을 기록합니다. 예를 들어 다음 함수를 실행한다고 가정합니다.

```sql
1 - CREATE OR REPLACE FUNCTION getBalance(acctNumber INTEGER)
2 - RETURNS NUMERIC AS $$
3 - DECLARE
4 -   result NUMERIC;
5 - BEGIN
6 -   SELECT INTO result balance FROM acct WHERE id = acctNumber;
7 -
8 -   IF (result IS NULL) THEN
9 -       RAISE INFO 'Balance is null';
10-   END IF;
11-
12-   RETURN result;
13- END;
14- $$ LANGUAGE 'plpgsql';
```

`DBMS_PROFILER`는 빈 행과 주석을 포함하여 `getBalance()` 함수의 각 코드 행에 대해 하나의 `PLSQL_PROFILER_DATA` 항목을 추가합니다. `SELECT` 문에 해당하는 항목은 정확히 한 번 실행되었으며 실행에 매우 짧은 시간이 필요했습니다. 반면 `RAISE INFO` 문에 해당하는 항목은 `balance` 열의 값에 따라 한 번 실행되었거나 전혀 실행되지 않았습니다.

이 함수의 일부 행에는 실행 가능한 코드가 없으므로 해당 행의 성능 통계에는 항상 0 값이 포함됩니다.

프로파일링 세션을 시작하려면 `DBMS_PROFILER.START_PROFILER` 함수 또는 프로시저를 호출하십시오. `START_PROFILER`를 호출하면 EDB Postgres Advanced Server는 `STOP_PROFILER` 또는 `PAUSE_PROFILER`를 호출하여 프로파일러를 중지하거나 일시 중지할 때까지 세션이 실행하는 모든 PL/pgSQL 또는 SPL 함수, 프로시저, 트리거 또는 익명 블록을 프로파일링합니다.

##### 참고 (Note)

프로파일러를 시작하거나 재개하면 프로파일러는 `START_PROFILER`(또는 `RESUME_PROFILER`) 호출 이후에 시작되는 함수/프로시저/트리거에 대해서만 성능 통계를 수집합니다.

프로파일러가 활성화되어 있는 동안 EDB Postgres Advanced Server는 메모리에 많은 타이머와 카운터 집합을 기록합니다. `STOP_PROFILER` 또는 `FLUSH_DATA` 함수/프로시저를 호출하면 `DBMS_PROFILER`는 해당 타이머와 카운터를 세 개의 테이블 집합에 기록합니다.

- `SYS.PLSQL_PROFILER_RAWDATA`

세션에서 실행된 각 문에 대한 성능 카운터와 타이머를 포함합니다.

- `SYS.PLSQL_PROFILER_RUNS`

`PLSQL_PROFILER_RAWDATA`에서 찾은 정보를 집계하여 각 실행의 요약을 포함합니다.

- `SYS.PLSQL_PROFILER_UNITS`

세션에서 실행된 각 코드 단위(함수, 프로시저, 트리거 또는 익명 블록)의 요약을 포함합니다.


또한 `DBMS_PROFILER`는 `PLSQL_PROFILER_RAWDATA` 테이블의 하위 집합을 포함하는 `SYS.PLSQL_PROFILER_DATA` 뷰를 정의합니다.

슈퍼유저가 아닌 사용자는 프로파일링 정보를 수집할 수 있지만, 슈퍼유저가 `SYS` 스키마에 저장된 프로파일링 테이블에 대한 특정 권한을 부여하지 않는 한 해당 프로파일링 정보를 볼 수 없습니다. 이를 통해 권한이 없는 사용자는 관리자가 비밀로 유지하려는 정보를 노출하지 않고 성능 통계를 수집할 수 있습니다.

### DBMS_PROFILER 테이블 및 뷰 쿼리하기

다음 예제는 `DBMS_PROFILER`를 사용하여 EDB Postgres Advanced Server와 함께 배포되는 샘플 데이터에 포함된 프로시저, 함수 및 트리거에 대한 성능 정보를 검색합니다.

1. EDB-PSQL 명령줄을 열고 EDB Postgres Advanced Server 데이터베이스에 연결을 설정합니다. `EXEC` 문을 사용하여 프로파일링 세션을 시작합니다.

```sql
acctg=# EXEC dbms_profiler.start_profiler('profile list_emp');

EDB-SPL Procedure successfully completed
```

### DBMS_PROFILER 참조

EDB Postgres Advanced Server 설치 프로그램은 PL/SQL 성능 프로파일 정보를 검토하기 위해 쿼리할 수 있는 다음 테이블과 뷰를 생성합니다.

| 테이블 이름 | 설명 |
| --- | --- |
| `PLSQL_PROFILER_RUNS` | `runid`로 구성된 모든 프로파일러 실행에 대한 정보를 포함하는 테이블입니다. |
| `PLSQL_PROFILER_UNITS` | 단위별로 구성된 모든 프로파일러 실행에 대한 정보를 포함하는 테이블입니다. |
| `PLSQL_PROFILER_DATA` | 성능 통계를 포함하는 뷰입니다. |
| `PLSQL_PROFILER_RAWDATA` | 성능 통계와 DRITA 카운터 및 타이머에 대한 확장 성능 통계를 포함하는 테이블입니다. |

#### PLSQL_PROFILER_RUNS

`PLSQL_PROFILER_RUNS` 테이블에는 다음 열이 포함됩니다.

| 열 | 데이터 타입 | 설명 |
| --- | --- | --- |
| `runid` | `INTEGER (NOT NULL)` | 고유 식별자 (`plsql_profiler_runnumber`) |
