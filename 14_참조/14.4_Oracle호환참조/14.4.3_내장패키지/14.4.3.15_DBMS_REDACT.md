# DBMS_REDACT — EPAS 18 내장 패키지

> 원문: [EPAS v18 — Reference › Oracle compatibility › Built-in packages › DBMS_REDACT](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_bip_guide/03_built-in_packages/13_dbms_redact/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 패키지·프로시저·역할 이름은 원문 그대로 보존했습니다.

`DBMS_REDACT` 패키지를 사용하면 쿼리가 반환하는 데이터를 편집(redact)하거나 마스킹할 수 있습니다. `DBMS_REDACT` 패키지는 정책을 생성, 변경, 활성화, 비활성화 및 삭제하는 프로시저를 제공합니다. `DBMS_REDACT` 패키지에서 사용할 수 있는 프로시저는 다음 표에 나열되어 있습니다.

| 함수/프로시저 | 함수 또는 프로시저 | 반환 타입 | 설명 |
| --- | --- | --- | --- |
| `ADD_POLICY(object_schema, object_name, policy_name, policy_description, column_name, column_description, function_type, function_parameters, expression, enable, regexp_pattern, regexp_replace_string, regexp_position, regexp_occurence, regexp_match_parameter, custom_function_expression)` | 프로시저 | 해당 없음 | 데이터 편집 정책을 추가합니다. |
| `ALTER_POLICY(object_schema, object_name, policy_name, action, column_name, function_type, function_parameters, expression, regexp_pattern, regexp_replace_string, regexp_position, regexp_occurence, regexp_match_parameter, policy_description, column_description, custom_function_expression)` | 프로시저 | 해당 없음 | 기존 데이터 편집 정책을 변경합니다. |
| `DISABLE_POLICY(object_schema, object_name, policy_name)` | 프로시저 | 해당 없음 | 기존 데이터 편집 정책을 비활성화합니다. |
| `ENABLE_POLICY(object_schema, object_name, policy_name)` | 프로시저 | 해당 없음 | 이전에 비활성화된 데이터 편집 정책을 활성화합니다. |
| `DROP_POLICY(object_schema, object_name, policy_name)` | 프로시저 | 해당 없음 | 데이터 편집 정책을 삭제합니다. |
| `UPDATE_FULL_REDACTION_VALUES(number_val, binfloat_val, bindouble_val, char_val, varchar_val, nchar_val, nvarchar_val, datecol_val, ts_val, tswtz_val, blob_val, clob_val, nclob_val)` | 프로시저 | 해당 없음 | 지정된 데이터 타입에 대한 전체 편집 기본값을 업데이트합니다. |

데이터 편집 기능은 `DBMS_REDACT` 패키지를 사용하여 테이블 열 타입과 편집 타입에 따라 열의 데이터를 편집하는 정책 또는 조건을 정의합니다.

데이터 편집 정책을 생성하거나 변경하려면 테이블의 소유자여야 합니다. 사용자는 모든 열 편집 정책에서 면제되며, 기본적으로 테이블 소유자 또는 슈퍼유저가 이에 해당합니다.

## DBMS_REDACT 상수 및 함수 매개변수 사용

`DBMS_REDACT` 패키지는 상수를 사용하며 데이터 편집 타입 중 하나를 사용하여 열 데이터를 편집합니다. 편집 타입은 `dbms_redact.add_policy` 및 `dbms_redact.alter_policy` 프로시저의 `function_type` 매개변수를 기반으로 결정할 수 있습니다. 다음 표는 `dbms_redact.add_policy` 및 `dbms_redact.alter_policy`의 `function_type` 매개변수 값을 강조합니다.

| 상수 | 타입 | 값 | 설명 |
| --- | --- | --- | --- |
| `NONE` | `INTEGER` | `0` | 편집 없음, 테이블에 대한 쿼리 결과에 아무런 영향이 없습니다. |
| `FULL` | `INTEGER` | `1` | 전체 편집, 열 데이터의 전체 값을 편집합니다. |
| `PARTIAL` | `INTEGER` | `2` | 부분 편집, 열 데이터의 일부를 편집합니다. |
| `RANDOM` | `INTEGER` | `4` | 임의(random) 편집, 각 쿼리는 열의 데이터 타입에 따라 서로 다른 임의의 값을 반환합니다. |
| `REGEXP` | `INTEGER` | `5` | 정규 표현식 기반 편집, 편집할 데이터의 패턴을 검색합니다. |
| `CUSTOM` | `INTEGER` | `99` | 사용자 정의 편집 타입입니다. |

다음 표는 `dbms_redact.alter_policy`의 `action` 매개변수 값을 보여줍니다.

| 상수 | 타입 | 값 | 설명 |
| --- | --- | --- | --- |
| `ADD_COLUMN` | `INTEGER` | `1` | 편집 정책에 열을 추가합니다. |
| `DROP_COLUMN` | `INTEGER` | `2` | 편집 정책에서 열을 삭제합니다. |
| `MODIFY_EXPRESSION` | `INTEGER` | `3` | 편집 정책의 표현식을 수정합니다. 표현식이 `BOOLEAN` 값 `TRUE`로 평가될 때 편집이 적용됩니다. |
| `MODIFY_COLUMN` | `INTEGER` | `4` | 편집 함수 타입 또는 함수 매개변수를 변경하기 위해 편집 정책의 열을 수정합니다. |
| `SET_POLICY_DESCRIPTION` | `INTEGER` | `5` | 편집 정책 설명을 설정합니다. |
| `SET_COLUMN_DESCRIPTION` | `INTEGER` | `6` | 열에 수행된 편집에 대한 설명을 설정합니다. |

부분 데이터 편집을 사용하면 열 데이터의 일부만 편집할 수 있습니다. 부분 편집을 사용하려면 `dbms_redact.add_policy` 프로시저의 `function_type` 매개변수를 `dbms_redact.partial`로 설정하고 `function_parameters` 매개변수를 사용하여 부분 편집 동작을 지정해야 합니다.

데이터 편집 기능은 다음 데이터 타입을 사용하는 정책을 구성하기 위한 사전 정의된 형식을 제공합니다.

- `Character`
- `Number`
- `Datetime`

다음 표는 데이터 타입에 대한 부분 편집의 형식 설명자(format descriptor)를 강조합니다. 이 예제는 문자열 데이터 타입(이 시나리오에서는 미국 사회보장번호(SSN)), `Number` 데이터 타입 및 `DATE` 데이터 타입에 대해 편집을 수행하는 방법을 보여줍니다.

| 데이터 타입 | 형식 설명자 | 설명 | 예제 |
| --- | --- | --- | --- |
| Character | `REDACT_PARTIAL_INPUT_FORMAT` | 입력 형식을 지정합니다. 입력 문자열에서 편집될 수 있는 각 문자에 대해 `V`를 입력합니다. 입력 문자열에서 공백이나 하이픈과 같은 구분자로 간주될 수 있는 각 문자에 대해 `F`를 입력합니다. | `123-45-6789`와 같은 SSN 문자열의 처음 5자리를 마스킹하고 하이픈을 추가하여 형식을 지정하여 `XXX-XX-6789`와 같은 문자열을 생성하기 위해 `'VVVFVVFVVVV,VVV-VV-VVVV,X,1,5'`를 고려하십시오. 필드 값 `VVVFVVFVVVV`는 `123-45-6789`와 같은 SSN 문자열을 매칭하기 위한 것입니다. |
|  | `REDACT_PARTIAL_OUTPUT_FORMAT` | 출력 형식을 지정합니다. 입력 문자열에서 편집될 수 있는 각 문자에 대해 `V`를 입력합니다. 입력 형식의 각 `F` 문자를 하이픈이나 기타 구분자와 같은 문자로 바꿉니다. | 필드 값 `VVV-VV-VVVV`는 SSN 문자열을 `XXX-XX-6789`로 편집하는 데 사용할 수 있으며, 여기서 `X`는 `REDACT_PARTIAL_MASKCHAR` 필드에서 옵니다. |
|  | `REDACT_PARTIAL_MASKCHAR` | 편집에 사용할 문자를 지정합니다. | SSN 문자열을 `XXX-XX-6789`로 편집하기 위한 값 `X`. |
|  | `REDACT_PARTIAL_MASKFROM` | 입력 형식에서 편집을 시작할 `V`를 지정합니다. | `VVVFVVFVVVV` 입력 형식의 첫 번째 `V`부터 시작하여 SSN 문자열을 `XXX-XX-6789`와 같은 문자열로 편집하기 위한 값 `1`. |
|  | `REDACT_PARTIAL_MASKTO` | 입력 형식에서 편집을 종료할 `V`를 지정합니다. | `VVVFVVFVVVV` 입력 형식의 다섯 번째 `V`까지 포함하여 SSN 문자열을 `XXX-XX-6789`와 같은 문자열로 편집하기 위한 값 `5`. |
| Number | `REDACT_PARTIAL_MASKCHAR` | 0에서 9 사이 범위에서 표시할 문자를 지정합니다. | 사회보장번호 `123456789`의 처음 5자리를 `999996789`로 편집하기 위한 `‘9, 1, 5’`. |
|  | `REDACT_PARTIAL_MASKFROM` | 편집을 위한 시작 자릿수 위치를 지정합니다. |  |
|  | `REDACT_PARTIAL_MASKTO` | 편집을 위한 종료 자릿수 위치를 지정합니다. |  |
| Datetime | `REDACT_PARTIAL_DATE_MONTH` | `‘m’`은 월을 편집합니다. 특정 월을 마스킹하려면 `‘m#’`를 지정하며, 여기서 #는 `1`에서 `12` 사이의 번호로 지정된 월을 나타냅니다. | `m3`은 March(3월)로 표시됩니다. |
|  | `REDACT_PARTIAL_DATE_DAY` | `‘d’`는 해당 월의 일을 편집합니다. 특정 일로 마스킹하려면 소문자 `d`에 `1-31`을 추가합니다. | `d3`은 `03`으로 표시됩니다. |
|  | `REDACT_PARTIAL_DATE_YEAR` | `‘y’`는 연도를 편집합니다. 특정 연도로 마스킹하려면 소문자 `y`에 `1-9999`를 추가합니다. | `y1960`은 `60`으로 표시됩니다. |
|  | `REDACT_PARTIAL_DATE_HOUR` | `‘h’`는 시간을 편집합니다. 특정 시간으로 마스킹하려면 소문자 `h`에 `0-23`을 추가합니다. | `h18`은 `18`로 표시됩니다. |
|  | `REDACT_PARTIAL_DATE_MINUTE` | `‘m’`은 분을 편집합니다. 특정 분으로 마스킹하려면 소문자 `m`에 `0-59`를 추가합니다. | `m20`은 `20`으로 표시됩니다. |
|  | `REDACT_PARTIAL_DATE_SECOND` | `‘s’`는 초를 편집합니다. 특정 초로 마스킹하려면 소문자 `s`에 `0-59`를 추가합니다. | `s40`은 `40`으로 표시됩니다. |

## ADD_POLICY

`add_policy` 프로시저는 테이블에 대한 새 데이터 편집 정책을 생성합니다.

```sql
PROCEDURE add_policy (
  <object_schema>                IN VARCHAR2 DEFAULT NULL,
  <object_name>                  IN VARCHAR2,
  <policy_name>                  IN VARCHAR2,
  <policy_description>           IN VARCHAR2 DEFAULT NULL,
  <column_name>                  IN VARCHAR2 DEFAULT NULL,
  <column_description>           IN VARCHAR2 DEFAULT NULL,
  <function_type>                IN INTEGER DEFAULT DBMS_REDACT.FULL,
  <function_parameters>          IN VARCHAR2 DEFAULT NULL,
  <expression>                   IN VARCHAR2,
  <enable>                       IN BOOLEAN DEFAULT TRUE,
  <regexp_pattern>               IN VARCHAR2 DEFAULT NULL,
  <regexp_replace_string>        IN VARCHAR2 DEFAULT NULL,
  <regexp_position>              IN INTEGER DEFAULT DBMS_REDACT.RE_BEGINNING,
  <regexp_occurrence>            IN INTEGER DEFAULT DBMS_REDACT.RE_ALL,
  <regexp_match_parameter>       IN VARCHAR2 DEFAULT NULL,
  <custom_function_expression>   IN VARCHAR2 DEFAULT NULL
  )
```

### 매개변수 (Parameters)

`object_schema`

객체가 위치하며 데이터 편집 정책이 적용되는 스키마의 이름을 지정합니다. `NULL`을 지정하면 주어진 객체는 `search_path` 설정으로 지정된 순서로 검색됩니다.

`object_name`

데이터 편집 정책이 생성되는 테이블의 이름입니다.

`policy_name`

추가할 정책의 이름입니다. 정책이 생성되는 테이블에 대해 `policy_name`이 고유한지 확인하십시오.

`policy_description`

편집 정책의 설명을 지정합니다.

`column_name`

편집 정책이 적용되는 열의 이름입니다. 두 개 이상의 열을 편집하려면 `alter_policy` 프로시저를 사용하여 더 많은 열을 추가하십시오.

`column_description`

편집할 열의 설명입니다. `column_description`은 지원되지 않지만, 열에 대한 설명을 지정하면 경고 메시지가 나타납니다.

`function_type`

사용할 편집 함수의 타입입니다. 가능한 값은 `NONE`, `FULL`, `PARTIAL`, `RANDOM`, `REGEXP` 및 `CUSTOM`입니다.

`function_parameters`

파티션 편집에 대한 함수 매개변수를 지정하며 부분 편집에만 적용됩니다.

`expression`

테이블에 대한 Boolean 표현식을 지정하고 정책을 적용하는 방법을 결정합니다. 이 정책 표현식이 `TRUE`로 평가되면 편집이 발생합니다.

`enable`

`TRUE`로 설정하면 생성 시 정책이 활성화됩니다. 기본값은 `TRUE`입니다. `FALSE`로 설정하면 정책이 비활성화되지만, `enable_policy` 프로시저를 호출하여 정책을 활성화할 수 있습니다.

`regexp_pattern`

데이터를 편집할 정규 표현식 패턴을 지정합니다. `regexp_pattern`이 일치하지 않으면 `NULL` 값이 반환됩니다.

`regexp_replace_string`

대체 문자열 값을 지정합니다.

`regexp_position`

검색을 시작해야 하는 문자의 위치를 지정합니다. 기본적으로 함수 매개변수는 `RE_BEGINNING`입니다.

`regexp_occurrence`

부분 문자열의 대체 발생을 지정합니다. 상수가 `RE_ALL`이면 일치하는 각 부분 문자열이 대체됩니다. 상수가 `RE_FIRST`이면 첫 번째 일치하는 부분 문자열이 대체됩니다.

`regexp_match_parameter`

함수의 기본 매칭 동작을 변경합니다. 가능한 `regexp_match_parameter` 상수는 `‘RE_CASE_SENSITIVE’`, `‘RE_CASE_INSENSITIVE’`, `‘RE_MULTIPLE_LINES’`, `‘RE_NEWLINE_WILDCARD’` 및 `‘RE_IGNORE_WHITESPACE’`일 수 있습니다.

##### 참고 (Note)

`constants`, `function_parameters` 또는 `regexp`에 대한 자세한 내용은 [Using DBMS_REDACT Constants and Function Parameters](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_bip_guide/03_built-in_packages/13_dbms_redact/#using-dbms_redact-constants-and-function-parameters)를 참조하십시오.

`custom_function_expression`

`custom_function_expression`은 `CUSTOM` 편집 타입에만 적용됩니다. `custom_function_expression`은 함수 표현식으로, 즉 `schema_name.function_name (argument1, …)`와 같은 매개변수를 가진 스키마 정규화된 함수이며, 사용자가 열 데이터를 편집하기 위해 자신의 편집 로직을 사용할 수 있게 합니다.

### 예제 (Example)

이 예제는 정책을 생성하고 `payment_details_tab` 테이블 `customer id` 열의 값에 대해 전체 편집을 사용하는 방법을 보여줍니다.

```sql
edb=# CREATE TABLE payment_details_tab (
customer_id NUMBER       NOT NULL,
card_string VARCHAR2(19) NOT NULL);
CREATE TABLE

edb=# BEGIN
  INSERT INTO payment_details_tab VALUES (4000, '1234-1234-1234-1234');
  INSERT INTO payment_details_tab VALUES (4001, '2345-2345-2345-2345');
END;

EDB-SPL Procedure successfully completed

edb=# CREATE USER redact_user;
CREATE ROLE
edb=# GRANT SELECT ON payment_details_tab TO redact_user;
GRANT

\c edb base_user

BEGIN
  DBMS_REDACT.add_policy(
     object_schema              => 'public',
     object_name                => 'payment_details_tab',
     policy_name                => 'redactPolicy_001',
     policy_description         => 'redactPolicy_001 for payment_details_tab table',
     column_name                => 'customer_id',
     function_type              => DBMS_REDACT.full,
     expression                 => '1=1',
     enable                     => TRUE);
END;
```

```sql

```

## ALTER_POLICY

`alter_policy` 프로시저는 테이블에 대한 기존 데이터 편집 정책을 변경하거나 수정합니다.

```sql
PROCEDURE alter_policy (
  <object_schema>                IN VARCHAR2 DEFAULT NULL,
  <object_name>                  IN VARCHAR2,
  <policy_name>                  IN VARCHAR2,
  <action>                       IN INTEGER DEFAULT DBMS_REDACT.ADD_COLUMN,
  <column_name>                  IN VARCHAR2 DEFAULT NULL,
  <function_type>                IN INTEGER DEFAULT DBMS_REDACT.FULL,
  <function_parameters>          IN VARCHAR2 DEFAULT NULL,
  <expression>                   IN VARCHAR2 DEFAULT NULL,
  <regexp_pattern>               IN VARCHAR2 DEFAULT NULL,
  <regexp_replace_string>        IN VARCHAR2 DEFAULT NULL,
  <regexp_position>              IN INTEGER DEFAULT DBMS_REDACT.RE_BEGINNING,
  <regexp_occurrence>            IN INTEGER DEFAULT DBMS_REDACT.RE_ALL,
  <regexp_match_parameter>       IN VARCHAR2 DEFAULT NULL,
  <policy_description>           IN VARCHAR2 DEFAULT NULL,
  <column_description>           IN VARCHAR2 DEFAULT NULL,
  <custom_function_expression>   IN VARCHAR2 DEFAULT NULL
  )
```

### 매개변수 (Parameters)

`object_schema`

객체가 위치하며 데이터 편집 정책을 변경할 스키마의 이름을 지정합니다. `NULL`을 지정하면 주어진 객체는 `search_path` 설정으로 지정된 순서로 검색됩니다.

`object_name`

데이터 편집 정책을 변경할 테이블의 이름입니다.

`policy_name`

변경할 정책의 이름입니다.

`action`

수행할 작업입니다. action 매개변수에 대한 자세한 내용은 [Using DBMS_REDACT Constants and Function Parameters](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_bip_guide/03_built-in_packages/13_dbms_redact/#using-dbms_redact-constants-and-function-parameters)를 참조하십시오.

`column_name`

편집 정책이 적용되는 열의 이름입니다.

`function_type`

사용할 편집 함수의 타입입니다. 가능한 값은 `NONE`, `FULL`, `PARTIAL`, `RANDOM`, `REGEXP` 및 `CUSTOM`입니다.

`function_parameters`

편집 함수에 대한 함수 매개변수를 지정합니다.

`expression`

테이블에 대한 Boolean 표현식을 지정하고 정책을 적용하는 방법을 결정합니다. 이 정책 표현식이 `TRUE`로 평가되면 편집이 발생합니다.

`regexp_pattern`

데이터를 편집하기 위해 정규 표현식을 사용할 수 있게 합니다. `regexp_pattern`이 데이터와 일치하지 않으면 `NULL` 값이 반환됩니다.

`regexp_replace_string`

대체 문자열 값을 지정합니다.

`regexp_position`

검색을 시작해야 하는 문자의 위치를 지정합니다. 기본적으로 함수 매개변수는 `RE_BEGINNING`입니다.

`regexp_occurence`

부분 문자열의 대체 발생을 지정합니다. 상수가 `RE_ALL`이면 일치하는 각 부분 문자열이 대체됩니다. 상수가 `RE_FIRST`이면 첫 번째 일치하는 부분 문자열이 대체됩니다.

`regexp_match_parameter`

함수의 기본 매칭 동작을 변경합니다. 가능한 `regexp_match_parameter` 상수는 `‘RE_CASE_SENSITIVE’`, `‘RE_CASE_INSENSITIVE’`, `‘RE_MULTIPLE_LINES’`, `‘RE_NEWLINE_WILDCARD’` 및 `‘RE_IGNORE_WHITESPACE’`일 수 있습니다.

##### 참고 (Note)

`constants`, `function_parameters` 또는 `regexp`에 대한 자세한 내용은 [Using DBMS_REDACT Constants and Function Parameters](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_bip_guide/03_built-in_packages/13_dbms_redact/#using-dbms_redact-constants-and-function-parameters)를 참조하십시오.

`policy_description`

편집 정책의 설명을 지정합니다.

`column_description`

편집할 열의 설명입니다. `column_description`은 지원되지 않지만, 열에 대한 설명을 지정하면 경고 메시지가 나타납니다.

`custom_function_expression`

`custom_function_expression`은 `CUSTOM` 편집 타입에만 적용됩니다. `custom_function_expression`은 함수 표현식으로, 즉 `schema_name.function_name (argument1, …)`와 같은 매개변수를 가진 스키마 정규화된 함수이며, 사용자가 열 데이터를 편집하기 위해 자신의 편집 로직을 사용할 수 있게 합니다.

### 예제 (Example)

이 예제는 `payment_details_tab` 테이블 `card_string`(일반적으로 신용카드 번호) 열의 값에 대해 부분 편집을 사용하여 정책을 변경하는 방법을 보여줍니다.

```sql
\c edb base _user

BEGIN
  DBMS_REDACT.alter_policy (
     object_schema               => 'public',
     object_name                 => 'payment_details_tab',
     policy_name                 => 'redactPolicy_001',
     action                      => DBMS_REDACT.ADD_COLUMN,
     column_name                 => 'card_string',
     function_type               => DBMS_REDACT.partial,
     function_parameters         => DBMS_REDACT.REDACT_CCN16_F12);
END;
```

편집된 결과:

```sql
edb=# \c - redact_user
You are now connected to database "edb" as user "redact_user".
edb=> SELECT * FROM payment_details_tab;
```

출력(Output)

```text
 customer_id |     card_string
-------------+---------------------
           0 | ****-****-****-1234
           0 | ****-****-****-2345
(2 rows)
```

## DISABLE_POLICY

`disable_policy` 프로시저는 기존 데이터 편집 정책을 비활성화합니다.

```sql
PROCEDURE disable_policy (
  <object_schema>       IN VARCHAR2 DEFAULT NULL,
  <object_name>         IN VARCHAR2,
  <policy_name>         IN VARCHAR2
  )
```

### 매개변수 (Parameters)

`object_schema`

객체가 위치하며 데이터 편집 정책을 적용할 스키마의 이름을 지정합니다. `NULL`을 지정하면 주어진 객체는 `search_path` 설정으로 지정된 순서로 검색됩니다.

`object_name`

데이터 편집 정책을 비활성화할 테이블의 이름입니다.

`policy_name`

비활성화할 정책의 이름입니다.

### 예제 (Example)

이 예제는 정책을 비활성화하는 방법을 보여줍니다.

```sql
\c edb base_user

BEGIN
  DBMS_REDACT.disable_policy(
     object_schema => 'public',
     object_name => 'payment_details_tab',
     policy_name => 'redactPolicy_001');
END;
```

편집된 결과: 정책을 비활성화한 후에는 데이터가 더 이상 편집되지 않습니다.

## UPDATE_FULL_REDACTION_VALUES

`update_full_redaction_values` 프로시저는 데이터 편집 정책에 대해 표시되는 기본값을 업데이트합니다. 전체 편집 타입을 사용하는 `redaction_values_for_type_full` 뷰를 사용하여 이러한 기본값을 볼 수 있습니다.

```sql
PROCEDURE update_full_redaction_values (
  <number_val>        IN NUMBER            DEFAULT NULL,
  <binfloat_val>      IN FLOAT4            DEFAULT NULL,
  <bindouble_val>     IN FLOAT8            DEFAULT NULL,
  <char_val>          IN CHAR              DEFAULT NULL,
  <varchar_val>       IN VARCHAR2          DEFAULT NULL,
  <nchar_val>         IN NCHAR             DEFAULT NULL,
  <nvarchar_val>      IN NVARCHAR2         DEFAULT NULL,
  <datecol_val>       IN DATE              DEFAULT NULL,
  <ts_val>            IN TIMESTAMP         DEFAULT NULL,
  <tswtz_val>         IN TIMESTAMPTZ       DEFAULT NULL,
  <blob_val>          IN BLOB              DEFAULT NULL,
  <clob_val>          IN CLOB              DEFAULT NULL,
  <nclob_val>         IN CLOB              DEFAULT NULL
  )
```

### 매개변수 (Parameters)

`number_val`

`NUMBER` 데이터 타입의 열에 대한 기본값을 업데이트합니다.

`binfloat_val`

`FLOAT4` 데이터 타입은 임의의 값입니다. binary float 데이터 타입은 지원되지 않습니다.

`bindouble_val`

`FLOAT8` 데이터 타입은 임의의 값입니다. binary double 데이터 타입은 지원되지 않습니다.

`char_val`

`CHAR` 데이터 타입의 열에 대한 기본값을 업데이트합니다.

`varchar_val`

`VARCHAR2` 데이터 타입의 열에 대한 기본값을 업데이트합니다.

`nchar_val`

`nchar_val`은 `CHAR` 데이터 타입에 매핑되며 `CHAR` 값을 반환합니다.

`nvarchar_val`

`nvarchar_val`은 `VARCHAR2` 데이터 타입에 매핑되며 `VARCHAR` 값을 반환합니다.

`datecol_val`

`DATE` 데이터 타입의 열에 대한 기본값을 업데이트합니다.

`ts_val`

`TIMESTAMP` 데이터 타입의 열에 대한 기본값을 업데이트합니다.

`tswtz_val`

`TIMESTAMPTZ` 데이터 타입의 열에 대한 기본값을 업데이트합니다.

`blob_val`

`BLOB` 데이터 타입의 열에 대한 기본값을 업데이트합니다.

`clob_val`

`CLOB` 데이터 타입의 열에 대한 기본값을 업데이트합니다.

`nclob_val`

`nclob_val`은 `CLOB` 데이터 타입에 매핑되며 `CLOB` 값을 반환합니다.

### 예제 (Example)

이 예제는 전체 편집 값을 업데이트하는 방법을 보여줍니다. 값을 업데이트하기 전에 `redaction_values_for_type_full` 뷰를 사용하여 기본값을 볼 수 있습니다.

```sql
edb=# \x
Expanded display is on.
edb=# SELECT number_value, char_value, varchar_value, date_value,
       timestamp_value, timestamp_with_time_zone_value, blob_value,
clob_value
FROM redaction_values_for_type_full;
```
