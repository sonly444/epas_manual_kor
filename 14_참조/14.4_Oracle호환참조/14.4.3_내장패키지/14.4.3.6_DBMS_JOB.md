# DBMS_JOB v18

`DBMS_JOB` 패키지의 작업(job)은 `edb_job_scheduler` 확장 기능에 의해 백그라운드에서 스케줄링되고 실행됩니다. 자세한 내용은 [EDB Job Scheduler extension](https://www.enterprisedb.com/docs/pg_extensions/edb_job_scheduler/)을 참조하세요.

`DBMS_JOB` 패키지를 사용하면 작업을 생성, 스케줄링 및 관리할 수 있습니다. 작업은 이전에 데이터베이스에 저장된 저장 프로시저를 실행합니다. `SUBMIT` 프로시저는 작업 정의를 생성하고 저장합니다. 작업 식별자는 저장 프로시저와 작업을 언제 얼마나 자주 실행할지 설명하는 속성과 함께 작업에 할당됩니다.

EDB Postgres Advanced Server의 `DBMS_JOB` 구현은 Oracle 버전과 비교했을 때 부분적인 구현입니다. 다음 표는 지원되는 `DBMS_JOB` 프로시저를 나열합니다.

| 함수/프로시저 | 반환 유형 | 설명 |
| --- | --- | --- |
| `BROKEN(job, broken [, next_date ])` | n/a | 지정된 작업이 broken 상태인지 아닌지를 지정합니다. |
| `CHANGE(job, what, next_date, interval, instance, force)` | n/a | 작업의 매개변수를 변경합니다. |
| `INTERVAL(job, interval)` | n/a | 작업이 실행될 때마다 재계산되는 날짜 함수를 통해 실행 빈도를 설정합니다. 이 값이 다음 실행 날짜/시간이 됩니다. |
| `NEXT_DATE(job, next_date)` | n/a | 작업을 실행할 다음 날짜/시간을 설정합니다. |
| `REMOVE(job)` | n/a | 데이터베이스에서 작업 정의를 삭제합니다. |
| `RUN(job)` | n/a | 작업이 broken으로 표시되어 있더라도 작업 실행을 강제합니다. |
| `SUBMIT(job OUT, what [, next_date [, interval [, no_parse ]]])` | n/a | 작업을 생성하고 그 정의를 데이터베이스에 저장합니다. |
| `WHAT(job, what)` | n/a | 작업이 실행하는 저장 프로시저를 변경합니다. |

작업이 언제 얼마나 자주 실행되는지는 상호작용하는 두 매개변수 `next_date`와 `interval`에 따라 달라집니다. `next_date` 매개변수는 작업을 실행할 다음 날짜/시간을 지정하는 날짜/시간 값입니다. `interval` 매개변수는 날짜/시간 값으로 평가되는 날짜 함수를 담은 문자열입니다.

작업이 실행되기 전에 `interval` 매개변수의 표현식이 평가됩니다. 그 결과 값이 작업과 함께 저장된 `next_date` 값을 대체합니다. 그런 다음 작업이 실행됩니다. `interval`의 표현식은 각 작업이 실행되기 전에 반복적으로 재평가되어 다음 실행을 위한 `next_date` 날짜/시간을 제공합니다.

이 예제들은 저장 프로시저 `job_proc`를 사용합니다. 이 프로시저는 단일 컬럼 `VARCHAR2`를 담고 있는 테이블 `jobrun`에 타임스탬프를 삽입합니다.

```sql
CREATE TABLE jobrun (
    runtime VARCHAR2(40)
);

CREATE OR REPLACE PROCEDURE job_proc
IS
BEGIN
    INSERT INTO jobrun VALUES ('job_proc run at ' || TO_CHAR(SYSDATE,
        'yyyy-mm-dd hh24:mi:ss'));
END;
```
