# DBMS_UTILITY

`DBMS_UTILITY` 패키지는 다음 유틸리티 프로그램을 지원합니다. EDB Postgres Advanced Server의 `DBMS_UTILITY` 구현은 Oracle 버전과 비교할 때 부분 구현입니다. 표에 나열된 함수와 프로시저만 지원됩니다.

| 함수/프로시저 | 함수 또는 프로시저 | 반환 유형 | 설명 |
| --- | --- | --- | --- |
| `ANALYZE_DATABASE(method [, estimate_rows [, estimate_percent [, method_opt ]]])` | 프로시저 | n/a | 데이터베이스 테이블을 분석합니다. |
| `ANALYZE_PART_OBJECT(schema, object_name [, object_type [, command_type [, command_opt [, sample_clause ]]]])` | 프로시저 | n/a | 파티션된 테이블을 분석합니다. |
| `ANALYZE_SCHEMA(schema, method [, estimate_rows [, estimate_percent [, method_opt ]]])` | 프로시저 | n/a | 스키마 테이블을 분석합니다. |
| `CANONICALIZE(name, canon_name OUT, canon_len)` | 프로시저 | n/a | 문자열을 정규화합니다(예: 공백 제거). |
| `COMMA_TO_TABLE(list, tablen OUT, tab OUT)` | 프로시저 | n/a | 쉼표로 구분된 이름 목록을 이름 테이블로 변환합니다. |
| `DB_VERSION(version OUT, compatibility OUT)` | 프로시저 | n/a | 데이터베이스 버전을 가져옵니다. |
| `EXEC_DDL_STATEMENT (parse_string)` | 프로시저 | n/a | DDL 문을 실행합니다. |
| `EXPAND_SQL_TEXT(input_sql_text, output_sql_text)` | 함수 | `TEXT` | 뷰에 대한 SQL 참조를 확장하여 반환합니다. |
| `FORMAT_CALL_STACK` | 함수 | `TEXT` | 현재 호출 스택을 포맷합니다. |
| `FORMAT_ERROR_BACKTRACE` | 함수 | `TEXT` | 현재 오류 호출 백트레이스를 포맷합니다. |
| `FORMAT_ERROR_STACK` | 함수 | `TEXT` | 예외 이름을 가져옵니다. |
| `GET_CPU_TIME` | 함수 | `NUMBER` | 현재 CPU 시간을 가져옵니다. |
| `GET_DEPENDENCY(type, schema, name)` | 프로시저 | n/a | 지정된 객체에 의존하는 객체를 가져옵니다. |
| `GET_HASH_VALUE(name, base, hash_size)` | 함수 | `NUMBER` | 해시 값을 계산합니다. |
| `GET_PARAMETER_VALUE(parnam, intval OUT, strval OUT)` | 프로시저 | `BINARY_INTEGER` | 데이터베이스 초기화 매개변수 설정을 가져옵니다. |
| `GET_TIME` | 함수 | `NUMBER` | 현재 시간을 가져옵니다. |
| `NAME_TOKENIZE(name, a OUT, b OUT, c OUT, dblink OUT, nextpos OUT)` | 프로시저 | n/a | 지정된 이름을 구성 요소로 파싱합니다. |
| `TABLE_TO_COMMA(tab, tablen OUT, list OUT)` | 프로시저 | n/a | 이름 테이블을 쉼표로 구분된 목록으로 변환합니다. |

## LNAME_ARRAY

`LNAME_ARRAY`는 정규화된 이름(fully qualified names)을 포함한 긴 이름 목록을 저장하기 위한 것입니다.

```sql
TYPE lname_array IS TABLE OF VARCHAR2(4000) INDEX BY BINARY_INTEGER;
```

## UNCL_ARRAY

`UNCL_ARRAY`는 사용자 및 이름 목록을 저장하기 위한 것입니다.

```sql
TYPE uncl_array IS TABLE OF VARCHAR2(227) INDEX BY BINARY_INTEGER;
```

## ANALYZE_DATABASE, ANALYZE SCHEMA and ANALYZE PART_OBJECT

`ANALYZE_DATABASE(), ANALYZE_SCHEMA() and ANALYZE_PART_OBJECT()` 프로시저는 데이터베이스의 테이블에 대한 통계를 수집합니다. `ANALYZE` 문을 실행하면 Postgres는 테이블의 데이터를 샘플링하여 분포 통계를 `pg_statistics system` 테이블에 기록합니다.

`ANALYZE_DATABASE`, `ANALYZE_SCHEMA`, `ANALYZE_PART_OBJECT`는 주로 처리되는 테이블 수에서 차이가 있습니다.

- `ANALYZE_DATABASE`는 현재 데이터베이스의 모든 스키마에 있는 모든 테이블을 분석합니다.
- `ANALYZE_SCHEMA`는 (현재 데이터베이스의) 지정된 스키마에 있는 모든 테이블을 분석합니다.
- `ANALYZE_PART_OBJECT`는 단일 테이블을 분석합니다.

`ANALYZE` 명령의 구문은 다음과 같습니다.

```sql
ANALYZE_DATABASE(<method> VARCHAR2 [, <estimate_rows> NUMBER\
  [, <estimate_percent> NUMBER [, <method_opt> VARCHAR2 ]]])

ANALYZE_SCHEMA(<schema> VARCHAR2, <method> VARCHAR2
  [, <estimate_rows> NUMBER [, <estimate_percent> NUMBER\
  [, <method_opt> VARCHAR2 ]]])

ANALYZE_PART_OBJECT(<schema> VARCHAR2, <object_name> VARCHAR2
  [, <object_type> CHAR [, <command_type> CHAR\
  [, <command_opt> VARCHAR2 [, <sample_clause> ]]]])
```

### `ANALYZE_DATABASE`와 `ANALYZE_SCHEMA`의 매개변수 (Parameters for `ANALYZE_DATABASE` and `ANALYZE_SCHEMA`)

`method`

`ANALYZE` 프로시저가 `pg_statistics` 테이블을 채울지 아니면 `pg_statistics` 테이블에서 항목을 제거할지 결정합니다. method로 `DELETE`를 지정하면 `ANALYZE` 프로시저는 `pg_statistics`에서 관련 행을 제거합니다. method로 `COMPUTE` 또는 `ESTIMATE`를 지정하면 `ANALYZE` 프로시저는 테이블(또는 여러 테이블)을 분석하고 분포 정보를 `pg_statistics`에 기록합니다. `COMPUTE`와 `ESTIMATE` 사이에는 차이가 없습니다. 두 method 모두 Postgres `ANALYZE` 문을 실행합니다. 다른 모든 매개변수는 검증된 후 무시됩니다.

`estimate_rows`

추정 통계의 기반이 되는 행 수입니다. method가 `ESTIMATE`인 경우 `estimate_rows` 또는 `estimate_percent` 중 하나를 반드시 지정해야 합니다.

이 인수는 무시되지만 호환성을 위해 포함되어 있습니다.

`estimate_percent`

추정 통계의 기반이 되는 행의 백분율입니다. method가 `ESTIMATE`인 경우 `estimate_rows` 또는 `estimate_percent` 중 하나를 반드시 지정해야 합니다.

이 인수는 무시되지만 호환성을 위해 포함되어 있습니다.

`method_opt`

분석할 객체 유형입니다. 다음의 조합 중 어느 것이든 가능합니다.

```text
[ FOR TABLE ]

[ FOR ALL [ INDEXED ] COLUMNS ] [ SIZE n ]

[ FOR ALL INDEXES ]
```

이 인수는 무시되지만 호환성을 위해 포함되어 있습니다.

### `ANALYZE_PART_OBJECT`의 매개변수 (Parameters for `ANALYZE_PART_OBJECT`)

`schema`

객체를 분석할 스키마의 이름입니다.

`object_name`

분석할 파티션된 객체의 이름입니다.

`object_type`

분석할 객체의 유형입니다. 유효한 값은 `T` – table, `I` – index입니다.

이 인수는 무시되지만 호환성을 위해 포함되어 있습니다.

`command_type`

수행할 분석 기능의 유형입니다. 유효한 값은 다음과 같습니다.

- `E`— `sample_clause` 절에 지정된 행 수 또는 행의 백분율을 기반으로 추정 통계를 수집합니다.

- `C`— 정확한 통계를 계산합니다.

- `V`— 파티션의 구조와 무결성을 검증합니다.

이 인수는 무시되지만 호환성을 위해 포함되어 있습니다.

`command_opt`

`command_type`이 `C` 또는 `E`인 경우, 다음의 조합 중 어느 것이든 가능합니다.

```text
[ FOR TABLE ]

[ FOR ALL COLUMNS ]

[ FOR ALL LOCAL INDEXES ]
```

`command_type`이 `V`인 경우, `object_type`이 `T`이면 `CASCADE`가 될 수 있습니다.

이 인수는 무시되지만 호환성을 위해 포함되어 있습니다.

`sample_clause`

`command_type`이 `E`인 경우, 추정의 기반이 되는 행 수 또는 행의 백분율을 지정하는 다음 절을 포함합니다.

`SAMPLE n { ROWS | PERCENT }`

이 인수는 무시되지만 호환성을 위해 포함되어 있습니다.

## CANONICALIZE

`CANONICALIZE` 프로시저는 입력 문자열에 대해 다음 작업을 수행합니다.

- 문자열이 큰따옴표로 묶여 있지 않으면 유효한 식별자의 문자를 사용하는지 검증합니다. 그렇지 않으면 예외가 발생합니다. 문자열이 큰따옴표로 묶여 있으면 모든 문자가 허용됩니다.
- 문자열이 큰따옴표로 묶여 있지 않고 마침표를 포함하지 않으면 모든 알파벳 문자를 대문자로 변환하고 앞뒤 공백을 제거합니다.
- 문자열이 큰따옴표로 묶여 있고 마침표를 포함하지 않으면 큰따옴표를 제거합니다.
- 문자열이 마침표를 포함하고 문자열의 어떤 부분도 큰따옴표로 묶여 있지 않으면 문자열의 각 부분을 대문자로 변환하고 각 부분을 큰따옴표로 묶습니다.
- 문자열이 마침표를 포함하고 문자열의 일부가 큰따옴표로 묶여 있으면 다음을 반환합니다.
  - 큰따옴표로 묶인 부분은 큰따옴표를 포함하여 변경되지 않은 채로.
  - 큰따옴표로 묶이지 않은 부분은 대문자로 변환되어 큰따옴표로 묶인 채로.

```sql
CANONICALIZE(<name> VARCHAR2, <canon_name> OUT VARCHAR2,
  <canon_len> BINARY_INTEGER)
```

### 매개변수 (Parameters)

`name`

정규화할 문자열입니다.

`canon_name`

정규화된 문자열입니다.

`canon_len`

첫 번째 문자부터 시작하여 정규화할 `name`의 바이트 수입니다.

### 예제 (Examples)

이 프로시저는 입력 매개변수에 `CANONICALIZE` 프로시저를 적용하고 결과를 표시합니다.

```sql
CREATE OR REPLACE PROCEDURE canonicalize (
    p_name      VARCHAR2,
    p_length    BINARY_INTEGER DEFAULT 30
)
IS
    v_canon     VARCHAR2(100);
BEGIN
    DBMS_UTILITY.CANONICALIZE(p_name,v_canon,p_length);
    DBMS_OUTPUT.PUT_LINE('Canonicalized name ==>' || v_canon || '<==');
    DBMS_OUTPUT.PUT_LINE('Length: ' || LENGTH(v_canon));
EXCEPTION
    WHEN OTHERS THEN
        DBMS_OUTPUT.PUT_LINE('SQLERRM: ' || SQLERRM);
        DBMS_OUTPUT.PUT_LINE('SQLCODE: ' || SQLCODE);
END;

EXEC canonicalize('Identifier')
Canonicalized name ==>IDENTIFIER<==
Length: 10

EXEC canonicalize('"Identifier"')
Canonicalized name ==>Identifier<==
Length: 10

EXEC canonicalize('"_+142%"')
Canonicalized name ==>_+142%<==
Length: 6

EXEC canonicalize('abc.def.ghi')
Canonicalized name ==>"ABC"."DEF"."GHI"<==
Length: 17

EXEC canonicalize('"abc.def.ghi"')
Canonicalized name ==>abc.def.ghi<==
Length: 11

EXEC canonicalize('"abc".def."ghi"')
Canonicalized name ==>"abc"."DEF"."ghi"<==
Length: 17

EXEC canonicalize('"abc.def".ghi')
Canonicalized name ==>"abc.def"."GHI"<==
Length: 15
```

## COMMA_TO_TABLE

`COMMA_TO_TABLE` 프로시저는 쉼표로 구분된 이름 목록을 이름 테이블로 변환합니다. 목록의 각 항목은 테이블 항목이 됩니다. 이름은 유효한 식별자 형식으로 지정하세요.

```sql
COMMA_TO_TABLE(<list> VARCHAR2, <tablen> OUT BINARY_INTEGER,
  <tab> OUT { LNAME_ARRAY | UNCL_ARRAY })
```

### 매개변수 (Parameters)

`list`

쉼표로 구분된 이름 목록입니다.

`tablen`

`tab`의 항목 수입니다.

`tab`

`list`의 개별 이름을 포함하는 테이블입니다.

`LNAME_ARRAY`

[LNAME_ARRAY](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_bip_guide/03_built-in_packages/18_dbms_utility/#lname_array)에 설명된 `DBMS_UTILITY LNAME_ARRAY`입니다.

`UNCL_ARRAY`

[UNCL_ARRAY](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_bip_guide/03_built-in_packages/18_dbms_utility/#uncl_array)에 설명된 `DBMS_UTILITY UNCL_ARRAY`입니다.

### 예제 (Examples)

이 프로시저는 `COMMA_TO_TABLE` 프로시저를 사용하여 이름 목록을 테이블로 변환합니다. 그런 다음 테이블 항목을 표시합니다.

```sql
CREATE OR REPLACE PROCEDURE comma_to_table (
    p_list      VARCHAR2
)
IS
    r_lname     DBMS_UTILITY.LNAME_ARRAY;
    v_length    BINARY_INTEGER;
BEGIN
    DBMS_UTILITY.COMMA_TO_TABLE(p_list,v_length,r_lname);
    FOR i IN 1..v_length LOOP
        DBMS_OUTPUT.PUT_LINE(r_lname(i));
    END LOOP;
END;

EXEC comma_to_table('edb.dept, edb.emp, edb.jobhist')

edb.dept
edb.emp
edb.jobhist
```

## DB_VERSION

`DB_VERSION` 프로시저는 데이터베이스의 버전 번호를 반환합니다.

```sql
DB_VERSION(<version> OUT VARCHAR2, <compatibility> OUT VARCHAR2)
```

### 매개변수 (Parameters)

`version`

데이터베이스 버전 번호입니다.

`compatibility`

데이터베이스의 호환성 설정입니다(그 의미는 구현에 따라 정의됨).

### 예제 (Examples)

다음 익명 블록은 데이터베이스 버전 정보를 표시합니다.

```sql
DECLARE
```

## EXEC_DDL_STATEMENT

`EXEC_DDL_STATEMENT`는 `DDL` 명령을 실행합니다.

```sql
EXEC_DDL_STATEMENT(<parse_string> VARCHAR2)
```

### 매개변수 (Parameters)

`parse_string`

실행할 DDL 명령입니다.

### 예제 (Examples)

다음 익명 블록은 `job` 테이블을 생성합니다.

```sql
BEGIN
    DBMS_UTILITY.EXEC_DDL_STATEMENT(
        'CREATE TABLE job (' ||
          'jobno NUMBER(3),' ||
          'jname VARCHAR2(9))'
    );
END;
```

`parse_string`이 유효한 DDL 문을 포함하지 않으면 EDB Postgres Advanced Server는 오류를 반환합니다.

```sql
edb=#  exec dbms_utility.exec_ddl_statement('select rownum from dual');
ERROR:  EDB-20001: 'parse_string' must be a valid DDL statement
```

이 경우 EDB Postgres Advanced Server의 동작은 Oracle과 다릅니다. Oracle은 유효하지 않은 `parse_string`을 문제없이 받아들입니다.

## EXPAND_SQL_TEXT

`EXPAND_SQL_TEXT` 함수는 뷰 참조를 그 정의로 대체하여 지정된 SQL 쿼리의 확장된 버전을 반환합니다.

```sql
DBMS_UTILITY.EXPAND_SQL_TEXT(<input_sql_text> CLOB, <output_sql_text> OUT CLOB)
```

### 매개변수 (Parameters)

`input_sql_text`

확장할 SQL 쿼리입니다.

`output_sql_text`

지정된 SQL 쿼리의 확장된 버전입니다.

### 예제 (Example)

다음 익명 블록은 SQL 쿼리 `SELECT * from vemp`의 확장된 버전을 반환합니다.

```sql
BEGIN
DBMS_UTILITY.expand_sql_text (    input_sql_text  => 'SELECT * from vemp',    output_sql_text => result  );
DBMS_OUTPUT.put_line(result);
END;
 SELECT empno,
    ename,
    job,
    mgr,
    hiredate,
    sal,
    comm,
    deptno
   FROM ( SELECT emp.empno,
            emp.ename,
            emp.job,
            emp.mgr,
            emp.hiredate,
            emp.sal,
            emp.comm,
            emp.deptno
           FROM emp) vemp

EDB-SPL Procedure successfully completed
```

## FORMAT_CALL_STACK

`FORMAT_CALL_STACK` 함수는 현재 호출 스택의 포맷된 내용을 반환합니다.

```sql
DBMS_UTILITY.FORMAT_CALL_STACK
return VARCHAR2
```

이 함수를 저장 프로시저, 함수 또는 패키지에서 사용하여 현재 호출 스택을 읽기 쉬운 형식으로 반환할 수 있습니다. 이 함수는 디버깅에 유용합니다.

## FORMAT_ERROR_BACKTRACE

## GET_HASH_VALUE

`GET_HASH_VALUE` 함수는 지정된 문자열에 대한 해시 값을 계산합니다.

```sql
<hash> NUMBER GET_HASH_VALUE(<name> VARCHAR2, <base> NUMBER,
   <hash_size> NUMBER)
```

### 매개변수 (Parameters)

`name`

해시 값을 계산할 문자열입니다.

`base`

해시 값을 생성하기 시작할 시작 값입니다.

`hash_size`

원하는 해시 테이블의 해시 값 개수입니다.

`hash`

생성된 해시 값입니다.

### 예제 (Examples)

다음 익명 블록은 `emp` 테이블의 `ename` 열을 사용하여 해시 값 테이블을 생성한 다음 키와 해시 값을 함께 표시합니다. 해시 값은 100에서 시작하며 최대 1024개의 고유 값을 가집니다.

```sql
DECLARE
    v_hash          NUMBER;
    TYPE hash_tab IS TABLE OF NUMBER INDEX BY VARCHAR2(10);
    r_hash          HASH_TAB;
    CURSOR emp_cur IS SELECT ename FROM emp;
BEGIN
    FOR r_emp IN emp_cur LOOP
        r_hash(r_emp.ename) :=
            DBMS_UTILITY.GET_HASH_VALUE(r_emp.ename,100,1024);
    END LOOP;
    FOR r_emp IN emp_cur LOOP
        DBMS_OUTPUT.PUT_LINE(RPAD(r_emp.ename,10) || ' ' ||
            r_hash(r_emp.ename));
    END LOOP;
END;
```

## NAME_TOKENIZE

`NAME_TOKENIZE` 프로시저는 이름을 구성 요소로 파싱합니다. 큰따옴표가 없는 이름은 대문자로 변환됩니다. 큰따옴표가 있는 이름에서는 큰따옴표가 제거됩니다.

```sql
NAME_TOKENIZE(<name> VARCHAR2, <a> OUT VARCHAR2,
  <b> OUT VARCHAR2, <c> OUT VARCHAR2, <dblink> OUT VARCHAR2,
  <nextpos> OUT BINARY_INTEGER)
```

### 매개변수 (Parameters)

`name`

다음 형식의 이름을 포함하는 문자열입니다.

`a[.b[.c]][@dblink ]`

`a`

가장 왼쪽 구성 요소를 반환합니다.

`b`

두 번째 구성 요소가 있으면 반환합니다.

`c`

세 번째 구성 요소가 있으면 반환합니다.

`dblink`

데이터베이스 링크 이름을 반환합니다.

`nextpos`

name에서 파싱된 마지막 문자의 위치입니다.

### 예제 (Examples)

이 저장 프로시저는 다양한 이름에 대한 `NAME_TOKENIZE` 프로시저의 반환 매개변수 값을 표시합니다.

```sql
CREATE OR REPLACE PROCEDURE name_tokenize (
    p_name          VARCHAR2
)
IS
    v_a             VARCHAR2(30);
    v_b             VARCHAR2(30);
    v_c             VARCHAR2(30);
    v_dblink        VARCHAR2(30);
    v_nextpos       BINARY_INTEGER;
BEGIN
    DBMS_UTILITY.NAME_TOKENIZE(p_name,v_a,v_b,v_c,v_dblink,v_nextpos);
    DBMS_OUTPUT.PUT_LINE('name   : ' || p_name);
    DBMS_OUTPUT.PUT_LINE('a      : ' || v_a);
    DBMS_OUTPUT.PUT_LINE('b      : ' || v_b);
    DBMS_OUTPUT.PUT_LINE('c      : ' || v_c);
    DBMS_OUTPUT.PUT_LINE('dblink : ' || v_dblink);
    DBMS_OUTPUT.PUT_LINE('nextpos: ' || v_nextpos);
END;
```

## TABLE_TO_COMMA

`TABLE_TO_COMMA` 프로시저는 이름 테이블을 쉼표로 구분된 이름 목록으로 변환합니다. 각 테이블 항목은 목록 항목이 됩니다. 이름은 유효한 식별자 형식으로 지정하세요.

```sql
TABLE_TO_COMMA(<tab> { LNAME_ARRAY | UNCL_ARRAY },
  <tablen> OUT BINARY_INTEGER, <list> OUT VARCHAR2)
```

### 매개변수 (Parameters)

`tab`

이름을 포함하는 테이블입니다.

`LNAME_ARRAY`

[LNAME ARRAY](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_bip_guide/03_built-in_packages/18_dbms_utility/#lname_array)에 설명된 `DBMS_UTILITY LNAME_ARRAY`입니다.

`UNCL_ARRAY`

[UNCL_ARRAY](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_bip_guide/03_built-in_packages/18_dbms_utility/#uncl_array)에 설명된 `DBMS_UTILITY UNCL_ARRAY`입니다.

`tablen`

`list`의 항목 수입니다.

`list`

`tab`의 이름을 쉼표로 구분한 목록입니다.

### 예제 (Examples)

이 예제는 먼저 `COMMA_TO_TABLE` 프로시저를 사용하여 쉼표로 구분된 목록을 테이블로 변환합니다. 그런 다음 `TABLE_TO_COMMA` 프로시저가 테이블을 다시 쉼표로 구분된 목록으로 변환하여 표시합니다.

```sql
CREATE OR REPLACE PROCEDURE table_to_comma (
    p_list      VARCHAR2
)
IS
    r_lname     DBMS_UTILITY.LNAME_ARRAY;
    v_length    BINARY_INTEGER;
    v_listlen   BINARY_INTEGER;
    v_list      VARCHAR2(80);
BEGIN
    DBMS_UTILITY.COMMA_TO_TABLE(p_list,v_length,r_lname);
    DBMS_OUTPUT.PUT_LINE('Table Entries');
    DBMS_OUTPUT.PUT_LINE('-------------');
    FOR i IN 1..v_length LOOP
        DBMS_OUTPUT.PUT_LINE(r_lname(i));
    END LOOP;
    DBMS_OUTPUT.PUT_LINE('-------------');
    DBMS_UTILITY.TABLE_TO_COMMA(r_lname,v_listlen,v_list);
    DBMS_OUTPUT.PUT_LINE('Comma-Delimited List: ' || v_list);
END;

EXEC table_to_comma('edb.dept, edb.emp, edb.jobhist')

Table Entries
-------------
edb.dept
edb.emp
edb.jobhist
-------------
Comma-Delimited List: edb.dept, edb.emp, edb.jobhist
```
