# UTL_SMTP

`UTL_SMTP` 패키지는 SMTP(Simple Mail Transfer Protocol)를 통해 이메일을 보냅니다.

##### 참고 (Note)

관리자는 각 사용자나 그룹이 이 패키지를 사용하기 전에 실행 권한을 부여해야 합니다.

| 함수/프로시저 | 함수 또는 프로시저 | 반환 타입 | 설명 |
| --- | --- | --- | --- |
| `AUTH(c IN OUT, username, password [, schemes ])` | 둘 다 | `Reply` | SMTP 서버로 인증하기 위해 `AUTH` 명령을 보냅니다. |
| `CLOSE_DATA(c IN OUT)` | 둘 다 | `REPLY` | 이메일 메시지를 종료합니다. |
| `COMMAND(c IN OUT, cmd [, arg ])` | 둘 다 | `REPLY` | SMTP 명령을 실행합니다. |
| `COMMAND_REPLIES(c IN OUT, cmd [, arg ])` | 함수 | `REPLIES` | 여러 응답 줄이 예상되는 SMTP 명령을 실행합니다. |
| `DATA(c IN OUT, body)` | 둘 다 | `REPLY` | 이메일 메시지의 본문을 지정합니다. |
| `EHLO(c IN OUT, domain)` | 둘 다 | `REPLIES` | SMTP 서버와 초기 핸드셰이킹을 수행하고 확장 정보를 반환합니다. |
| `HELO(c IN OUT, domain)` | 둘 다 | `REPLY` | SMTP 서버와 초기 핸드셰이킹을 수행합니다. |
| `HELP(c IN OUT [, command ])` | 함수 | `REPLIES` | `HELP` 명령을 보냅니다. |
| `MAIL(c IN OUT, sender [, parameters ])` | 둘 다 | `REPLY` | 메일 트랜잭션을 시작합니다. |
| `NOOP(c IN OUT)` | 둘 다 | `REPLY` | null 명령을 보냅니다. |
| `OPEN_CONNECTION(host, port, tx_timeout, wallet_path, wallet_password, secure_connection_before_smtp, secure_host, ssl_cert_path)` | 함수 | `CONNECTION` | 연결을 엽니다. |
| `OPEN_DATA(c IN OUT)` | 둘 다 | `REPLY` | `DATA` 명령을 보냅니다. |
| `QUIT(c IN OUT)` | 둘 다 | `REPLY` | SMTP 세션을 종료하고 연결을 끊습니다. |
| `RCPT(c IN OUT, recipient [, parameters ])` | 둘 다 | `REPLY` | 이메일 메시지의 수신자를 지정합니다. |
| `RSET(c IN OUT)` | 둘 다 | `REPLY` | 현재 메일 트랜잭션을 종료합니다. |
| `STARTTLS(c IN OUT connection [, secure_host ])` | 둘 다 | `REPLY` | 연결을 보안 TLS 연결로 업그레이드하기 위해 STARTTLS 명령을 시작합니다. |
| `VRFY(c IN OUT, recipient)` | 함수 | `REPLY` | 이메일 주소를 검증합니다. |
| `WRITE_DATA(c IN OUT, data)` | 프로시저 | 해당 없음 | 이메일 메시지의 일부를 씁니다. |

EDB Postgres Advanced Server의 `UTL_SMTP` 구현은 Oracle 버전과 비교할 때 부분 구현입니다. 표에 나열된 함수와 프로시저만 지원됩니다.

다음 표는 `UTL_SMTP` 패키지에서 사용할 수 있는 public 변수를 나열합니다.

| Public 변수 | 데이터 타입 | 값 | 설명 |
| --- | --- | --- | --- |
| `connection` | `RECORD` |  | SMTP 연결에 대한 설명입니다. |
| `reply` | `RECORD` |  | SMTP 응답 줄입니다. |

## CONNECTION

`CONNECTION` 레코드 타입은 SMTP 연결에 대한 설명을 제공합니다.

```sql
TYPE connection IS RECORD(
   host            VARCHAR2(255),
   port            PLS_INTEGER,
   tx_timeout      PLS_INTEGER
);
```

## REPLY/REPLIES

`REPLY` 레코드 타입은 SMTP 응답 줄에 대한 설명을 제공합니다. `REPLIES`는 여러 SMTP 응답 줄의 테이블입니다.

```sql
TYPE reply IS RECORD(
   code  INTEGER,
   text  VARCHAR2(508)
);

TYPE replies IS TABLE OF reply INDEX BY BINARY_INTEGER;
```

## AUTH

이 하위 프로그램들은 SMTP 서버로 인증하기 위해 AUTH 명령을 보냅니다. UTL_SMTP 패키지는 사용자가 선택한 인증 스킴을 순서대로 자동으로 시도하며, 서버가 지원하는 첫 번째 스킴을 선택합니다.

```sql
# Procedure
AUTH(
   c        IN OUT  connection,
   username VARCHAR2,
   password VARCHAR2,
   schemes  VARCHAR2 DEFAULT NON_CLEARTEXT_PASSWORD_SCHEMES
);

# Function
AUTH(
   c        IN OUT connection,
   username VARCHAR2,
   password VARCHAR2,
   schemes  VARCHAR2 DEFAULT NON_CLEARTEXT_PASSWORD_SCHEMES
) RETURN reply;
```

### 파라미터 (Parameters)

`c`

인증할 SMTP 연결입니다.

`username`

인증을 위한 사용자 이름입니다.

`password`

인증을 위한 비밀번호입니다.

`schemes`

시도할 인증 스킴입니다. 기본값은 `NON_CLEARTEXT_PASSWORD_SCHEMES`입니다. 허용되는 값은 `ALL_SCHEMES`와 `NON_CLEARTEXT_PASSWORD_SCHEMES`입니다.

`reply`

명령에 대한 SMTP 응답입니다. SMTP가 여러 응답을 반환하면 마지막 응답만 `reply`에 반환됩니다.

`REPLY`와 `REPLIES`에 대한 설명은 [Reply/Replies](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_bip_guide/03_built-in_packages/24_utl_smtp/#replyreplies)를 참조하세요.

##### 참고 (Note)

- `NON_CLEARTEXT_PASSWORD_SCHEMES`는 SMTP를 통해 비밀번호를 평문으로 전송하지 않는 CRAM-MD5 인증 스킴을 지원합니다.
이러한 스킴은 연결이 SSL/TLS로 보호되지 않은 경우에도 사용할 수 있습니다.
이러한 스킴은 평문 전송을 피하지만, 보안되지 않은 SMTP 연결을 통해 사용될 경우 전체적인 보안이 여전히 손상될 수 있습니다.

- `ALL_SCHEMES`는 `PLAIN`, `LOGIN`, `CRAM-MD5` 인증 스킴을 지원합니다. `PLAIN` 및 `LOGIN` 스킴은 SMTP를 통해 비밀번호를 평문으로 전송하므로 보안 SSL/TLS 연결에서만 사용해야 합니다.

## EHLO

`EHLO` 하위 프로그램은 연결을 설정한 후 SMTP 서버와 초기 핸드셰이킹을 수행합니다. `EHLO` 프로시저를 사용하면 클라이언트가 RFC 821에 따라 SMTP 서버에 자신을 식별할 수 있습니다. RFC 1869는 서버의 응답에서 반환되는 정보의 형식을 지정합니다. `HELO` 프로시저는 동등한 기능을 수행하지만 서버에 대한 정보를 더 적게 반환합니다.

```sql
# Procedure
EHLO(
   c      IN OUT CONNECTION,
   domain VARCHAR2
);

# Function
EHLO(
   c      IN OUT CONNECTION,
   domain VARCHAR2
) RETURN replies;
```

### 파라미터 (Parameters)

`c`

핸드셰이킹을 수행할 SMTP 서버에 대한 연결입니다.

`domain`

보내는 호스트의 도메인 이름입니다.

`replies`

명령에 대한 SMTP 응답 줄입니다. `REPLY`와 `REPLIES`에 대한 설명은 [Reply/Replies](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_bip_guide/03_built-in_packages/24_utl_smtp/#replyreplies)를 참조하세요.

## OPEN_CONNECTION

`OPEN_CONNECTION` 함수는 SMTP 서버에 대한 연결을 엽니다.

```sql
OPEN_CONNECTION(
    host                          VARCHAR2(255),
    port                          INTEGER DEFAULT 25,
    tx_timeout                    INTEGER DEFAULT NULL,
    wallet_path                   VARCHAR2(255) DEFAULT NULL,
    wallet_password               VARCHAR2(255) DEFAULT NULL,
    secure_connection_before_smtp BOOLEAN DEFAULT FALSE,
    secure_host                   VARCHAR2(255) DEFAULT NULL,
    ssl_cert_path                 VARCHAR2(255) DEFAULT NULL
) RETURN connection;
```

### 파라미터 (Parameters)

`host`

SMTP 서버의 이름입니다.

`port`

SMTP 서버가 수신 대기 중인 포트 번호입니다. 기본값은 `25`입니다.

`tx_timeout`

초 단위의 타임아웃 값입니다. 기다리지 않으려면 `0`을 지정합니다. 무한정 기다리려면 이 값을 null로 설정합니다. 기본값은 null입니다.

`wallet_path`

Oracle 호환성을 위해 추가되었습니다. 기본값은 `NULL`이며 항상 `NULL`이어야 합니다.

`wallet_password`

Oracle 호환성을 위해 추가되었습니다. 기본값은 `NULL`이며 항상 `NULL`이어야 합니다.

`secure_connection_before_smtp`

`TRUE`이면 SMTP 통신을 하기 전에 보안 SSL/TLS 연결을 설정합니다. `FALSE`이면 연결이 표준 SMTP 연결로 시작됩니다. 기본값은 `FALSE`입니다.

`secure_host`

SMTP 서버의 SSL 인증서의 common name과 매칭할 호스트 이름입니다. "*.example.com"과 같은 도메인 이름일 수도 있습니다. `NULL`이면 SMTP 호스트 이름이 연결에 사용됩니다.

`ssl_cert_path`

SSL 인증서의 경로입니다.

`connection`

새로 설정된 SMTP 연결을 반환합니다.

## 종합 예제

이 프로시저는 `UTL_SMTP` 패키지를 사용하여 텍스트 이메일 메시지를 구성하고 보냅니다.

```sql
CREATE OR REPLACE PROCEDURE send_mail (
    p_sender        VARCHAR2,
    p_recipient     VARCHAR2,
    p_subj          VARCHAR2,
    p_msg           VARCHAR2,
    p_mailhost      VARCHAR2
)
IS
    v_conn          UTL_SMTP.CONNECTION;
    v_crlf          CONSTANT VARCHAR2(2) := CHR(13) || CHR(10);
    v_port          CONSTANT PLS_INTEGER := 25;
BEGIN
    v_conn := UTL_SMTP.OPEN_CONNECTION(p_mailhost,v_port);
    UTL_SMTP.HELO(v_conn,p_mailhost);
    UTL_SMTP.MAIL(v_conn,p_sender);
    UTL_SMTP.RCPT(v_conn,p_recipient);
    UTL_SMTP.DATA(v_conn, SUBSTR(
        'Date: ' || TO_CHAR(SYSDATE,
        'Dy, DD Mon YYYY HH24:MI:SS') || v_crlf
        || 'From: ' || p_sender || v_crlf
        || 'To: ' || p_recipient || v_crlf
        || 'Subject: ' || p_subj || v_crlf
        || p_msg
        , 1, 32767));
    UTL_SMTP.QUIT(v_conn);
END;

EXEC send_mail('asmith@enterprisedb.com','pjones@enterprisedb.com','Holiday
Party','Are you planning to attend?','smtp.enterprisedb.com');
```

이 예제는 `DATA` 프로시저 대신 `OPEN_DATA`, `WRITE_DATA`, `CLOSE_DATA` 프로시저를 사용합니다. 또한 `AUTH`를 사용하여 서버로 인증하고 `STARTTLS`를 사용하여 연결을 보안합니다.

```sql
CREATE OR REPLACE PROCEDURE send_mail_2 (
    p_sender        VARCHAR2,
    p_recipient     VARCHAR2,
    p_subj          VARCHAR2,
    p_msg           VARCHAR2,
    p_mailhost      VARCHAR2,
    p_ssl_cert_path	VARCHAR2,
    p_username		VARCHAR2,
    p_password		VARCHAR2
)
IS
    v_conn          UTL_SMTP.CONNECTION;
    v_crlf          CONSTANT VARCHAR2(2) := CHR(13) || CHR(10);
    v_port          CONSTANT PLS_INTEGER := 25;
BEGIN
    v_conn := UTL_SMTP.OPEN_CONNECTION(p_mailhost,v_port,ssl_cert_path => p_ssl_cert_path);
    UTL_SMTP.STARTTLS(v_conn);
    UTL_SMTP.HELO(v_conn,p_mailhost);
    UTL_SMTP.AUTH(v_conn,p_username,p_password,UTL_SMTP.NON_CLEARTEXT_PASSWORD_SCHEMES);
    UTL_SMTP.MAIL(v_conn,p_sender);
    UTL_SMTP.RCPT(v_conn,p_recipient);
    UTL_SMTP.OPEN_DATA(v_conn);
    UTL_SMTP.WRITE_DATA(v_conn,'From: ' || p_sender || v_crlf);
    UTL_SMTP.WRITE_DATA(v_conn,'To: ' || p_recipient || v_crlf);
    UTL_SMTP.WRITE_DATA(v_conn,'Subject: ' || p_subj || v_crlf);
    UTL_SMTP.WRITE_DATA(v_conn,v_crlf || p_msg);
    UTL_SMTP.CLOSE_DATA(v_conn);
    UTL_SMTP.QUIT(v_conn);
END;

EXEC send_mail_2('asmith@enterprisedb.com','pjones@enterprisedb.com','Holiday
Party','Are you planning to attend?','smtp.enterprisedb.com','/etc/ssl/certs/sendmail.pem','edb','edb');
```
