# EVALUATE_CALENDAR_STRING — EPAS 18 내장 패키지 DBMS_SCHEDULER
> 원문: [EPAS v18 — Reference › Oracle compatibility › Built-in packages › DBMS_SCHEDULER › EVALUATE_CALENDAR_STRING](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_bip_guide/03_built-in_packages/15_dbms_scheduler/12_evaluate_calendar_string/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 패키지·프로시저·함수 이름은 원문 그대로 보존했습니다.

`EVALUATE_CALENDAR_STRING` 프로시저를 사용하여 `CREATE_SCHEDULE` 프로시저로 스케줄을 생성할 때 지정한 `repeat_interval` 값을 평가합니다. `EVALUATE_CALENDAR_STRING` 프로시저는 실제로 작업을 스케줄하지 않고 지정한 스케줄이 실행되는 날짜와 시각을 반환합니다.

`EVALUATE_CALENDAR_STRING` 프로시저의 시그니처는 다음과 같습니다.

```sql
EVALUATE_CALENDAR_STRING(
  <calendar_string> IN VARCHAR2,
  <start_date> IN TIMESTAMP WITH TIME ZONE,
  <return_date_after> IN TIMESTAMP WITH TIME ZONE,
  <next_run_date> OUT TIMESTAMP WITH TIME ZONE)
```

## 파라미터 (Parameters)

`calendar_string`

`calendar_string`은 평가되는 `repeat_interval`을 설명하는 캘린더 문자열입니다.

`start_date IN TIMESTAMP WITH TIME ZONE`

`start_date`는 `repeat_interval`이 유효해지는 날짜와 시각입니다.

`return_date_after`

`return_date_after` 파라미터를 사용하여 `EVALUATE_CALENDAR_STRING`이 `repeat_interval`을 평가할 때 시작 날짜로 사용할 날짜와 시각을 지정합니다.

예를 들어 `return_date_after` 값으로 `01-APR-13 09.00.00.000000`을 지정하면 `EVALUATE_CALENDAR_STRING`은 2013년 4월 1일 이후 스케줄의 첫 번째 반복 날짜와 시각을 반환합니다.

`next_run_date OUT TIMESTAMP WITH TIME ZONE`

`next_run_date`는 `return_date_after` 파라미터로 지정한 날짜 이후 스케줄의 첫 번째 발생을 담는 `OUT` 파라미터입니다.

## 예제 (Example)

이 예제는 캘린더 문자열을 평가하여 2013년 6월 15일 이후 스케줄이 실행될 첫 번째 날짜와 시각을 반환합니다.

```sql
DECLARE
  result     TIMESTAMP;
BEGIN

  DBMS_SCHEDULER.EVALUATE_CALENDAR_STRING
  (
    'FREQ=DAILY;BYDAY=MON,TUE,WED,THU,FRI;BYHOUR=17;',
    '15-JUN-2013', NULL, result
  );

    DBMS_OUTPUT.PUT_LINE('next_run_date: ' || result);
END;
/

next_run_date: 17-JUN-13 05.00.00.000000 PM
```

2013년 6월 15일은 토요일이므로 스케줄은 2013년 6월 17일 월요일 오후 5시에 실행됩니다.
