# 예제: PARTITION BY RANGE — EPAS 18 Reference

> 원문: [EPAS v18 — Reference › Oracle 호환 › 파티셔닝 명령 › CREATE TABLE...PARTITION BY › Example: PARTITION BY RANGE](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/04_partitioning_commands_compatible_with_oracle_databases/01_create_table_partition_by/03_example_partition_by_range/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·코드 이름은 원문 그대로 보존했습니다.

이 예제는 `PARTITION BY RANGE` 절을 사용하여 파티션 테이블 `sales`를 생성합니다. `sales` 테이블은 정보를 `q1_2012`, `q2_2012`, `q3_2012`, `q4_2012` 네 개의 파티션에 저장합니다.

```sql
CREATE TABLE sales
(
  dept_no     number,
  part_no     varchar2,
  country     varchar2(20),
  date        date,
  amount      number
)
PARTITION BY RANGE(date)
(
  PARTITION q1_2012
    VALUES LESS THAN('2012-Apr-01'),
  PARTITION q2_2012
    VALUES LESS THAN('2012-Jul-01'),
  PARTITION q3_2012
    VALUES LESS THAN('2012-Oct-01'),
  PARTITION q4_2012
    VALUES LESS THAN('2013-Jan-01')
);
```

생성된 테이블은 `date` 열에 지정된 값에 따라 파티셔닝됩니다:

```sql
edb=# SELECT partition_name, high_value from ALL_TAB_PARTITIONS;
```

출력(Output)

```text
 partition_name |      high_value
----------------+----------------------
 Q1_2012        | '01-APR-12 00:00:00'
 Q2_2012        | '01-JUL-12 00:00:00'
 Q3_2012        | '01-OCT-12 00:00:00'
 Q4_2012        | '01-JAN-13 00:00:00'
(4 rows)
```

- `date` 열의 값이 2012년 4월 1일 이전인 행은 `q1_2012`라는 파티션에 저장됩니다.
- `date` 열의 값이 2012년 7월 1일 이전인 행은 `q2_2012`라는 파티션에 저장됩니다.
- `date` 열의 값이 2012년 10월 1일 이전인 행은 `q3_2012`라는 파티션에 저장됩니다.
- `date` 열의 값이 2013년 1월 1일 이전인 행은 `q4_2012`라는 파티션에 저장됩니다.

서버는 다음 문을 파티셔닝 규칙에 대해 평가하고 그 행을 `q3_2012` 파티션에 저장합니다:

`INSERT INTO sales VALUES (10, '9519a', 'FRANCE', '18-Aug-2012', '650000');`

※ postgresql.auto.conf에 edb_audit = 'csv'가 설정되어 있으며 이 상태에서 edb_audit_statement에 ddl이 포함되어 있을 경우, RANGE 파티션(VALUES LESS THAN)을 지정한 Oracle 호환 파티션 테이블 생성 시, 예상치 못한 경고문 'WARNING: unrecognized node type: 337' 이 출력됩니다 (2026-08-31). 이는 'Oracle 스타일 PARTITION BY RANGE 축약 구문을 내부 파티셔닝 노드로 변환할 때 내부 디버깅 코드가 활성화되어 발생하는 엔진 레벨 경고'입니다. 단순한 경고 메세지로 동작·성능에 영향 없으며 표준 PostgreSQL 방식 PARTITION BY RANGE 구문 사용 시에는 경고가 발생하지 않습니다. 다음 제품 릴리즈 시 패치될 예정입니다.
