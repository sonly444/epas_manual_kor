# CREATE TABLE...PARTITION BY — EPAS 18 Reference

> 원문: [EPAS v18 — Reference › Oracle 호환 › 파티셔닝 명령 › CREATE TABLE...PARTITION BY](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/04_partitioning_commands_compatible_with_oracle_databases/01_create_table_partition_by/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·코드 이름은 원문 그대로 보존했습니다.

`CREATE TABLE` 명령의 `PARTITION BY` 절을 사용하여 데이터가 하나 이상의 파티션과 서브파티션에 분산된 파티션 테이블을 생성합니다. 구문은 여러 형태를 취할 수 있습니다.

## 리스트 파티셔닝 구문 (List partitioning syntax)

리스트 파티션 테이블을 생성하려면 이 형태를 사용합니다:

```sql
CREATE TABLE [ schema. ]<table_name>
   <table_definition>
   PARTITION BY LIST(<column>) [ AUTOMATIC ]
   [SUBPARTITION BY {RANGE|LIST|HASH} (<column>[, <column> ]...)
   [SUBPARTITION TEMPLATE (<subpartition_template_description>)]]
   (<list_partition_definition>[, <list_partition_definition>]...)
   [ENABLE ROW MOVEMENT];

여기서 list_partition_definition은:

      PARTITION [<partition_name>]
        VALUES (<value>[, <value>]...)
        [TABLESPACE <tablespace_name>]
        [(<subpartition>, ...)]

여기서 subpartition_template_description는:

      SUBPARTITION [<subpartition_name>]
        VALUES (<value>[, <value>]...)
        [TABLESPACE <tablespace_name>], ...
```

## 범위 파티셔닝 구문 (Range partitioning syntax)

범위 파티션 테이블을 생성하려면 이 형태를 사용합니다:

```sql
CREATE TABLE [ schema. ]<table_name>
   <table_definition>
   PARTITION BY RANGE(<column>[, <column> ]...)
   [INTERVAL (<constant> | <expression>)]
   [SUBPARTITION BY {RANGE|LIST|HASH} (<column>[, <column> ]...)
   [SUBPARTITION TEMPLATE (<subpartition_template_description>)]]
   (<range_partition_definition>[, <range_partition_definition>]...)
   [ENABLE ROW MOVEMENT];

여기서 range_partition_definition은:

      PARTITION [<partition_name>]
        VALUES LESS THAN (<value>[, <value>]...)
        [TABLESPACE <tablespace_name>]
        [(<subpartition>, ...)]

여기서 subpartition_template_description는:

      SUBPARTITION [<subpartition_name>]
        VALUES LESS THAN (<value>[, <value>]...)
        [TABLESPACE <tablespace_name>], ...
```

## 해시 파티셔닝 구문 (Hash partitioning syntax)

해시 파티션 테이블을 생성하려면 이 형태를 사용합니다:

```sql
CREATE TABLE [ schema. ]<table_name>
   <table_definition>
   PARTITION BY HASH(<column>[, <column> ]...)
   [SUBPARTITION BY {RANGE|LIST|HASH} (<column>[, <column> ]...)
   [SUBPARTITION TEMPLATE (<subpartition_template_description>)]]
   [SUBPARTITIONS <num>] [STORE IN ( <tablespace_name> [, <tablespace_name>]... ) ]]
   [PARTITIONS <num>] [STORE IN ( <tablespace_name> [, <tablespace_name>]... ) ] |
   (<hash_partition_definition>[, <hash_partition_definition>]...)
   [ENABLE ROW MOVEMENT];

여기서 hash_partition_definition은:

      PARTITION [<partition_name>]
        [TABLESPACE <tablespace_name>]
        [(<subpartition>, ...)]

여기서 subpartition_template_description는:

      SUBPARTITION [<subpartition_name>]
        [TABLESPACE <tablespace_name>], ...
```

## 서브파티셔닝 구문 (Subpartitioning syntax)

`subpartition`은 다음 중 하나일 수 있습니다:

```sql
{<list_subpartition> | <range_subpartition> | <hash_subpartition>}

여기서 list_subpartition은:

      SUBPARTITION [<subpartition_name>]
        VALUES (<value>[, <value>]...)
        [TABLESPACE <tablespace_name>]

여기서 range_subpartition은:

      SUBPARTITION [<subpartition_name>]
        VALUES LESS THAN (<value>[, <value>]...)
        [TABLESPACE <tablespace_name>]

여기서 hash_subpartition은:

      SUBPARTITION [<subpartition_name>]
        [TABLESPACE <tablespace_name>] |
      SUBPARTITIONS <num> [STORE IN ( <tablespace_name> [, <tablespace_name>]... ) ]
```

## 설명 (Description)

`CREATE TABLE… PARTITION BY` 명령은 하나 이상의 파티션을 가진 테이블을 생성합니다. 각 파티션은 하나 이상의 서브파티션을 가질 수 있습니다. 정의할 수 있는 파티션 수에는 상한이 없습니다. 다만 `PARTITION BY` 절을 포함하면 적어도 하나의 파티셔닝 규칙을 지정해야 합니다. 결과 테이블은 이를 생성한 사용자가 소유합니다.

### `PARTITION BY LIST` 절

`PARTITION BY LIST` 절을 사용하여 지정된 컬럼에 입력된 값을 기준으로 테이블을 파티션으로 나눕니다. 각 파티셔닝 규칙은 적어도 하나의 리터럴 값을 지정해야 합니다. 다만 지정할 수 있는 값의 수에는 상한이 없습니다. 일치하는 값으로 `DEFAULT`를 지정하는 규칙을 포함하면, 어느 규칙에도 해당하지 않는 행을 해당 파티션으로 보냅니다.

`DEFAULT` 키워드 사용에 대한 자세한 내용은 [LIST 또는 RANGE 파티션 테이블에서 미분류 값 처리](https://www.enterprisedb.com/docs/epas/latest/application_programming/epas_compat_table_partitioning/05_handling_stray_values_in_a_list_or_range_partitioned_table/#handling_stray_values_in_a_list_or_range_partitioned_table)를 참고하십시오.

### `AUTOMATIC` 절

`AUTOMATIC` 절을 사용하여 테이블이 자동 리스트 파티셔닝을 사용하도록 지정합니다. `AUTOMATIC` 절을 지정하면, 기존 파티션에 선언된 어떤 값과도 대응하지 않는 새 데이터가 테이블에 삽입될 때 데이터베이스가 파티션을 생성합니다.

`AUTOMATIC LIST PARTITIONING`에 대한 자세한 내용은 [자동 리스트 파티셔닝](https://www.enterprisedb.com/docs/epas/latest/application_programming/epas_compat_table_partitioning/02_selecting_a_partition_type/02_automatic_list_partitioning/#automatic_list_partitioning)을 참고하십시오.

### `PARTITION BY RANGE` 절

`PARTITION BY RANGE` 절을 사용하여 파티션을 생성할 경계 규칙을 지정합니다. 각 파티셔닝 규칙은 두 개의 연산자(즉, 크거나 같음 연산자와 작음 연산자)를 갖는 데이터 타입의 컬럼을 적어도 하나 포함해야 합니다. 범위 경계는 `LESS THAN` 절에 대해 평가되며 비포함(non-inclusive)입니다. 예를 들어 2013년 1월 1일이라는 날짜 경계는 2012년 12월 31일 이전(당일 포함)에 해당하는 날짜 값만 포함합니다.

범위 파티션 규칙은 오름차순으로 지정하십시오. 파티셔닝 규칙에 `MAXVALUE` 값을 지정하는 경계 규칙이 포함되지 않으면, 범위 파티션 테이블의 최상단 경계를 초과하는 값의 행을 저장하는 `INSERT` 명령은 실패합니다. `MAXVALUE` 파티셔닝 규칙을 포함하지 않으면, 경계 규칙이 지정한 최대 한계를 초과하는 행은 오류를 일으킵니다.

`MAXVALUE` 키워드 사용에 대한 자세한 내용은 [LIST 또는 RANGE 파티션 테이블에서 미분류 값 처리](https://www.enterprisedb.com/docs/epas/latest/application_programming/epas_compat_table_partitioning/05_handling_stray_values_in_a_list_or_range_partitioned_table/#handling_stray_values_in_a_list_or_range_partitioned_table)를 참고하십시오.

### `INTERVAL` 절

`INTERVAL` 절을 사용하여 인터벌 범위 파티션 테이블을 지정합니다. `INTERVAL` 절이 있으면, 기존 범위 파티션을 초과하는 데이터가 테이블에 삽입될 때 데이터베이스가 범위 파티셔닝을 확장하여 지정된 인터벌의 파티션을 생성합니다.

`INTERVAL RANGE PARTITION`에 대한 자세한 내용은 [인터벌 범위 파티셔닝](https://www.enterprisedb.com/docs/epas/latest/application_programming/epas_compat_table_partitioning/02_selecting_a_partition_type/01_interval_range_partitioning/#interval_range_partitioning)을 참고하십시오.

### `PARTITION BY HASH` 절

`PARTITION BY HASH` 절을 사용하여 해시 파티션 테이블을 생성합니다. `HASH` 파티션 테이블에서 데이터는 파티셔닝 구문에 지정된 컬럼의 해시 값을 기준으로 동일 크기의 파티션에 나뉩니다. `HASH` 파티션을 지정할 때는 가능한 한 고유에 가까운 컬럼 또는 컬럼 조합을 선택하십시오. 이 기법은 데이터가 파티션 간에 고르게 분산되도록 돕습니다. 파티셔닝 컬럼(또는 조합)을 선택할 때 최상의 성능을 위해서는 정확히 일치하는 검색을 자주 하는 컬럼을 선택하십시오.

### `STORE IN` 절

`STORE IN` 절을 사용하여 자동 생성된 파티션이나 서브파티션이 저장되는 테이블스페이스 목록을 지정합니다.

##### 참고 (Note)

EDB Postgres Advanced Server를 업그레이드하는 경우, 업그레이드된 버전 서버에서 해시 파티션 테이블을 재구축해야 합니다.

### `TABLESPACE` 키워드

`TABLESPACE` 키워드를 사용하여 파티션이나 서브파티션이 위치하는 테이블스페이스의 이름을 지정합니다. 테이블스페이스를 지정하지 않으면 파티션이나 서브파티션은 기본 테이블스페이스에 위치합니다.

### `SUBPARTITION BY` 절

테이블 정의에 `SUBPARTITION BY` 절이 포함되면, 해당 테이블의 각 파티션은 적어도 하나의 서브파티션을 가져야 합니다. 각 서브파티션을 명시적으로 정의하거나 시스템이 정의하게 할 수 있습니다.

서브파티션이 시스템 정의이면, 서버가 생성한 서브파티션은 기본 테이블스페이스에 위치하고 서브파티션 이름은 서버가 할당합니다. 서버는 다음을 생성합니다:

- `SUBPARTITION BY` 절이 `LIST`를 지정하면 `DEFAULT` 서브파티션.
- `SUBPARTITION BY` 절이 `RANGE`를 지정하면 `MAXVALUE` 서브파티션.

서버는 파티션 테이블 이름과 고유 식별자를 조합한 서브파티션 이름을 생성합니다. `ALL_TAB_SUBPARTITIONS` 테이블을 조회하여 서브파티션 이름의 전체 목록을 확인할 수 있습니다.

### `SUBPARTITION TEMPLATE`

리스트·범위·해시 파티션 테이블과 함께 `ENABLE ROW MOVEMENT`를 사용하면 Oracle 데이터베이스의 유사 구문 테이블 마이그레이션을 지원합니다. 다만 실제 행 이동을 활성화하지는 않습니다. 이 구문은 `ALTER TABLE` 명령에서는 지원되지 않습니다.

## 파라미터 (Parameters)

`table_name` — 생성할 테이블의 이름(선택적으로 스키마 한정).

`table_definition` — PostgreSQL 코어 문서의 [`CREATE TABLE` 문](https://www.postgresql.org/docs/current/static/sql-createtable.html)에 설명된 대로의 컬럼 이름, 데이터 타입, 제약 정보.

`partition_name` — 생성할 파티션의 이름. 파티션 이름은 모든 파티션·서브파티션 중에서 고유해야 하며 객체 식별자 명명 규칙을 따라야 합니다.

`subpartition_name` — 생성할 서브파티션의 이름. 모든 파티션·서브파티션 중에서 고유해야 하며 객체 식별자 명명 규칙을 따라야 합니다.

`num` — `PARTITIONS num` 절을 사용하여 생성할 `HASH` 파티션 수를 지정할 수 있습니다. 또는 파티션 정의를 사용하여 개별 파티션과 그 테이블스페이스를 지정할 수 있습니다.

> **참고:** 테이블 생성 시 `PARTITIONS` 또는 `PARTITION DEFINITION` 중 하나를 사용할 수 있습니다.

`SUBPARTITIONS num` 절은 `HASH` 파티션에만 지원됩니다. 생성할 해시 서브파티션 수를 지정하는 데 사용할 수 있습니다. 또는 서브파티션 정의를 사용하여 개별 서브파티션과 테이블스페이스를 지정할 수 있습니다. `SUBPARTITIONS`나 `SUBPARTITION DEFINITION`을 지정하지 않으면 파티션은 `SUBPARTITION TEMPLATE`를 기준으로 서브파티션을 생성합니다.

`subpartition_template_description` — 서브파티션 이름, 서브파티션 경계, 테이블스페이스 이름이 포함된 서브파티션 상세 목록.

`column` — 파티셔닝 규칙의 기준이 되는 컬럼의 이름. 각 행은 지정된 컬럼의 `value`에 대응하는 파티션에 저장됩니다.

`constant | expression` — `constant`와 `expression`은 `NUMERIC`, `DATE`, `TIME` 값을 지정합니다.

`(value[, value]...)` — 테이블 항목을 파티션으로 그룹화하는 기준이 되는, 따옴표로 묶인 리터럴 값 또는 쉼표로 구분된 리터럴 값 목록을 지정합니다. 각 파티셔닝 규칙은 적어도 하나의 값을 지정해야 합니다. 다만 규칙에 지정하는 값의 수에는 제한이 없습니다. `value`는 `NULL`, `LIST` 파티션 지정 시 `DEFAULT`, `RANGE` 파티션 지정 시 `MAXVALUE`일 수 있습니다.

리스트 파티션 테이블 규칙을 지정할 때, 마지막 파티션 규칙에 `DEFAULT` 키워드를 포함하여 일치하지 않는 행을 해당 파티션으로 보냅니다. `DEFAULT` 값을 포함하는 규칙이 없으면, 적어도 하나의 파티션의 지정된 규칙과 일치하지 않는 행을 추가하려는 `INSERT` 문은 실패하고 오류를 반환합니다.

리스트 파티션 테이블 규칙을 지정할 때, 마지막 파티션 규칙에 `MAXVALUE` 키워드를 포함하여 미분류 행을 해당 파티션으로 보냅니다. `MAXVALUE` 파티션을 포함하지 않으면, 파티셔닝 키가 지정된 최고 값보다 큰 행을 추가하려는 `INSERT` 문은 실패하고 오류를 반환합니다.

`tablespace_name` — 파티션이나 서브파티션이 위치하는 테이블스페이스의 이름.

> **예제 하위 페이지(원문):** PARTITION BY LIST · 자동 LIST 파티션 · PARTITION BY RANGE · 인터벌 RANGE 파티션 · PARTITION BY HASH · 파티션 수 지정 · RANGE+LIST 서브파티션 · 고유 인덱스 생성 · SUBPARTITION TEMPLATE (필요 시 개별 번역 추가 가능)
