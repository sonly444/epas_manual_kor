# 보고 및 로깅/로그할 내용 (Reporting and logging/what to log) — EPAS 18

> 원문: [EPAS v18 — Database administration › Configuration parameters by functionality › Reporting and logging/what to log](https://www.enterprisedb.com/docs/epas/latest/database_administration/01_configuration_parameters/03_configuration_parameters_by_functionality/06_reporting_and_logging_what_to_log/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 파라미터 이름·값·코드는 원문 그대로 보존했습니다.

이 구성 파라미터들은 보고와 로깅을 제어합니다.

## trace_hints

**파라미터 타입:** Boolean
**기본값:** `false`
**범위:** `{true | false}`
**최소 적용 범위:** 세션별(Per session)
**값 변경 적용 시점:** 변경 즉시(Immediate)
**활성화에 필요한 권한:** 세션 사용자

옵티마이저 힌트 기능과 함께 사용하여 플래너가 힌트를 사용했는지 여부에 대한 더 상세한 정보를 제공합니다. `client_min_messages`와 `trace_hints` 구성 파라미터를 다음과 같이 설정합니다.

```sql
SET client_min_messages TO info;
SET trace_hints TO true;
```

이 예는 그 구성 파라미터들을 설정했을 때 `NO_INDEX` 힌트가 있는 `SELECT` 명령이 생성하는 추가 정보를 보여줍니다.

```sql
EXPLAIN SELECT /*+ NO_INDEX(accounts accounts_pkey) */ * FROM accounts
WHERE aid = 100;

INFO: [HINTS] Index Scan of [accounts].[accounts_pkey] rejected because
of NO_INDEX hint.

INFO: [HINTS] Bitmap Heap Scan of [accounts].[accounts_pkey] rejected
because of NO_INDEX hint.
```

출력

```text
                          QUERY PLAN

-------------------------------------------------------------

Seq Scan on accounts (cost=0.00..14461.10 rows=1 width=97)
  Filter: (aid = 100)
(2 rows)
```

## edb_log_every_bulk_value

**파라미터 타입:** Boolean
**기본값:** `false`
**범위:** `{true | false}`
**최소 적용 범위:** 세션별(Per session)
**값 변경 적용 시점:** 변경 즉시(Immediate)
**활성화에 필요한 권한:** 슈퍼유저

대량(bulk) 처리는 결과 문을 EDB Postgres Advanced Server 로그 파일과 EDB Audit 로그 파일 모두에 로깅합니다. 그러나 대량 처리의 모든 문을 로깅하는 것은 비용이 큽니다. `edb_log_every_bulk_value` 구성 파라미터로 로깅되는 대량 처리 문을 제어할 수 있습니다.

이 파라미터가 `true`로 설정되면 대량 처리의 모든 문이 로깅됩니다. 대량 실행 중 `edb_log_every_bulk_value`가 `false`로 설정되면 대량 처리당 한 번 처리된 행 수와 함께 로그 메시지가 기록됩니다. 지속 시간(duration)은 대량 처리당 한 번 발생합니다.

## edb_log_redact_password_statements

**파라미터 타입:** Boolean
**기본값:** `false`
**범위:** `{true | false}`
**최소 적용 범위:** 세션별(Per session)
**값 변경 적용 시점:** 변경 즉시(Immediate)
**활성화에 필요한 권한:** 슈퍼유저

`edb_log_redact_password_statements` 파라미터는 데이터베이스 링크 비밀번호 정보를 포함하는 문이 서버 로그에서 마스킹(redacted)되는지 여부를 제어합니다. 활성화되면 이 파라미터는 CREATE ROLE/USER, ALTER ROLE/USER, CREATE DATABASE LINK, ALTER DATABASE LINK 문에 사용된 민감한 비밀번호 정보가 로그 파일에 평문으로 기록되지 않도록 보장합니다. 대신 그러한 문은 마스킹된 메시지로 대체되어 보안과 컴플라이언스를 강화합니다.

로그에서 비밀번호 문 마스킹을 활성화하려면 파라미터를 `true`로 설정합니다.

```sql
edb=# SET edb_log_redact_password_statements=true;
```

출력

```text
SET
```

이 파라미터를 활성화한 후, 비밀번호 정보를 포함하는 이후의 모든 CREATE DATABASE LINK 또는 ALTER DATABASE LINK 문은 비밀번호가 마스킹된 채 로깅됩니다. 예:

```sql
edb=# CREATE DATABASE LINK my_link CONNECT TO user IDENTIFIED BY 'mypassword' USING 'mydb';
```

출력

```text
CREATE DATABASE LINK
```

```sql
edb=# ALTER DATABASE LINK my_link CONNECT TO user IDENTIFIED BY 'newpassword';
```

출력

```text
ALTER DATABASE LINK
```

해당 로그 항목은 비밀번호가 마스킹된 문을 표시하여 민감한 정보가 로그에 노출되지 않도록 합니다.

```text
2025-07-23 12:19:16 UTC LOG:  statement: redacted CREATE DATABASE LINK command
2025-07-23 12:19:35 UTC LOG:  statement: redacted ALTER DATABASE LINK command
```

##### 참고

- 이 파라미터는 필요에 따라 구성 파일(postgresql.conf)에 추가하거나 세션 수준에서 설정해야 합니다.
- 민감한 정보를 보호하고 보안을 강화하기 위해 데이터베이스 링크가 사용되는 환경에서 이 파라미터를 활성화하는 것이 권장됩니다.
