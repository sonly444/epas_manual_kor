# EDB*Loader 실행 (Running EDB*Loader) — EPAS 18

> 원문: [EPAS v18 — Database administration › EDB*Loader › Invoking EDB*Loader › Running EDB*Loader](https://www.enterprisedb.com/docs/epas/latest/database_administration/02_edb_loader/invoking_edb_loader/running_edb_loader/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·옵션·매개변수·경로·코드는 원문 그대로 보존했습니다.

명령줄에서 EDB*Loader를 호출하려면 다음 명령을 사용합니다.

```sql
edbldr [ -d <dbname> ] [ -p <port> ] [ -h <host> ]
[ USERID={ <username/password> | <username>/ | <username> | / } ]
[ { -c | connstr= } <CONNECTION_STRING> ]
  CONTROL=<control_file>
[ DATA=<data_file> ]
[ BAD=<bad_file>]
[ DISCARD=<discard_file> ]
[ DISCARDMAX=<max_discard_recs> ]
[ HANDLE_CONFLICTS={ FALSE | TRUE } ]
[ LOG=<log_file> ]
[ PARFILE=<param_file> ]
[ DIRECT={ FALSE | TRUE } ]
[ FREEZE={ FALSE | TRUE } ]
[ ERRORS=<error_count> ]
[ PARALLEL={ FALSE | TRUE } ]
[ ROWS=<n> ]
[ SKIP=<skip_count> ]
[ SKIP_INDEX_MAINTENANCE={ FALSE | TRUE } ]
[ edb_resource_group=<group_name> ]
```

## 설명 (Description)

구문 다이어그램에 나열된 매개변수는 *매개변수 파일(parameter file)*에 지정할 수 있습니다. 단, `-d` 옵션, `-p` 옵션, `-h` 옵션, `PARFILE` 매개변수는 예외입니다. edbldr를 호출할 때 명령줄에서 `PARFILE=param_file` 형태로 매개변수 파일을 지정합니다. 일부 매개변수는 컨트롤 파일의 `OPTIONS` 절에 지정할 수 있습니다. 컨트롤 파일에 대한 자세한 내용은 [EDB*Loader 컨트롤 파일 작성(Building the EDB*Loader control file)](https://www.enterprisedb.com/docs/epas/latest/database_administration/02_edb_loader/building_the_control_file/)을 참고하십시오.

`control_file`, `data_file`, `bad_file`, `discard_file`, `log_file`, `param_file`을 지정할 때 파일 이름에 전체 디렉터리 경로 또는 상대 디렉터리 경로를 포함할 수 있습니다. 파일 이름만 지정하거나 상대 디렉터리 경로와 함께 지정한 경우, `control_file`, `data_file`, `param_file`은 edbldr가 호출된 현재 작업 디렉터리를 기준으로 존재한다고 가정합니다. `bad_file`, `discard_file`, `log_file`의 경우에는 파일이 생성됩니다.

`-d` 옵션, `-p` 옵션, `-h` 옵션을 생략하면 데이터베이스·포트·호스트의 기본값은 edb-psql과 같은 다른 EDB Postgres Advanced Server 유틸리티 프로그램과 동일한 규칙으로 결정됩니다.

## 요구 사항 (Requirements)

- 컨트롤 파일은 edbldr가 호출되는 클라이언트의 문자 집합 인코딩으로 존재해야 합니다. 클라이언트가 데이터베이스 인코딩과 다른 인코딩을 사용하는 경우, edbldr를 호출하기 전에 클라이언트에서 `PGCLIENTENCODING` 환경 변수를 클라이언트의 인코딩으로 설정해야 합니다. 이렇게 하면 클라이언트와 데이터베이스 서버 간의 문자 집합 변환이 올바르게 수행됩니다.

- 파일 이름에는 다음 확장자가 포함되어야 합니다.

  - `control_file`은 `.ctl` 확장자를 사용해야 합니다.
  - `data_file`은 `.dat` 확장자를 사용해야 합니다.
  - `bad_file`은 `.bad` 확장자를 사용해야 합니다.
  - `discard_file`은 `.dsc` 확장자를 사용해야 합니다.
  - `log_file`은 `.log` 확장자를 포함해야 합니다.

  제공된 파일 이름에 확장자가 없으면, EDB*Loader는 실제 파일 이름에 적절한 확장자가 포함되어 있다고 가정합니다.

- edbldr를 호출하는 데 사용되는 운영 체제 계정은 `control_file`, `data_file`, `param_file`로 지정된 디렉터리와 파일에 대한 읽기 권한이 있어야 합니다.

- 운영 체제 계정 enterprisedb는 `bad_file`, `discard_file`, `log_file`이 기록되는 디렉터리에 대한 쓰기 권한이 있어야 합니다.

## 매개변수 (Parameters)

**`dbname`**
로드할 테이블이 포함된 데이터베이스의 이름입니다.

**`port`**
데이터베이스 서버가 연결을 수락하는 포트 번호입니다.

**`host`**
데이터베이스 서버가 실행 중인 호스트의 IP 주소입니다.

**`USERID={ <username/password> | <username/> | <username> | / }`**
EDB*Loader는 `<username>`으로 데이터베이스에 연결합니다. `<username>`은 슈퍼유저이거나 필요한 권한을 가진 사용자 이름이어야 합니다. `<password>`는 `<username>`의 비밀번호입니다.

`USERID` 매개변수를 생략하면 EDB*Loader는 `username`과 `password`를 묻습니다. `USERID=username/`을 지정하면 EDB*Loader는 다음 중 하나를 수행합니다.

- `PGPASSFILE`이 설정되어 있으면 환경 변수 `PGPASSFILE`이 지정한 비밀번호 파일을 사용합니다.
- `PGPASSFILE`이 설정되어 있지 않으면 `.pgpass` 비밀번호 파일(Windows 시스템에서는 `pgpass.conf`)을 사용합니다.

`USERID=username`을 지정하면 EDB*Loader는 `password`를 묻습니다. `USERID=/`를 지정하면 운영 체제 계정을 사용자 이름으로 사용하여 연결을 시도합니다.

> **참고**
> EDB*Loader는 EDB Postgres Advanced Server 연결 환경 변수 `PGUSER`와 `PGPASSWORD`를 무시합니다. `PGPASSFILE` 환경 변수와 비밀번호 파일에 대한 자세한 내용은 [PostgreSQL 코어 문서](https://www.postgresql.org/docs/current/libpq-pgpass.html)를 참고하십시오.

**`-c CONNECTION_STRING`**
**`connstr=CONNECTION_STRING`**
`-c` 또는 `connstr=` 옵션으로 libpq가 지원하는 모든 연결 매개변수를 지정할 수 있습니다. 이 옵션으로 SSL 연결 매개변수나 libpq가 지원하는 다른 연결 매개변수도 지정할 수 있습니다. `-d`, `-h`, `-p`, `userid=dbuser/dbpass`와 같은 연결 옵션을 별도로 제공하면, `-c` 또는 `connstr=` 옵션이 제공한 값을 재정의(override)할 수 있습니다.

**`CONTROL=control_file`**
`control_file`은 EDB*Loader 지시어를 포함하는 컨트롤 파일의 이름을 지정합니다. 파일 확장자를 지정하지 않으면 `.ctl` 확장자가 가정됩니다.

컨트롤 파일에 대한 자세한 내용은 [EDB*Loader 컨트롤 파일 작성(Building the EDB*Loader control file)](https://www.enterprisedb.com/docs/epas/latest/database_administration/02_edb_loader/building_the_control_file/)을 참고하십시오.

**`DATA=data_file`**
`data_file`은 대상 테이블에 로드할 데이터가 포함된 파일의 이름을 지정합니다. 파일 확장자를 지정하지 않으면 `.dat` 확장자가 가정됩니다. 명령줄에서 `data_file`을 지정하면 컨트롤 파일에 지정된 `INFILE` 절을 재정의합니다.

`data_file`에 대한 자세한 내용은 [EDB*Loader 컨트롤 파일 작성(Building the EDB*Loader control file)](https://www.enterprisedb.com/docs/epas/latest/database_administration/02_edb_loader/building_the_control_file/)을 참고하십시오.

**`BAD=bad_file`**
`bad_file`은 오류로 인해 로드할 수 없는 입력 데이터 레코드를 받는 파일의 이름을 지정합니다. 명령줄에서 `bad_file`을 지정하면 컨트롤 파일에 지정된 `BADFILE` 절을 재정의합니다.

`bad_file`에 대한 자세한 내용은 [EDB*Loader 컨트롤 파일 작성(Building the EDB*Loader control file)](https://www.enterprisedb.com/docs/epas/latest/database_administration/02_edb_loader/building_the_control_file/)을 참고하십시오.

**`DISCARD=discard_file`**
`discard_file`은 어떤 테이블의 선택 기준에도 맞지 않는 입력 데이터 레코드를 받는 파일의 이름입니다. 명령줄에서 `discard_file`을 지정하면 컨트롤 파일의 `DISCARDFILE` 절을 재정의합니다.

`discard_file`에 대한 자세한 내용은 [EDB*Loader 컨트롤 파일 작성(Building the EDB*Loader control file)](https://www.enterprisedb.com/docs/epas/latest/database_administration/02_edb_loader/building_the_control_file/)을 참고하십시오.

**`DISCARDMAX=max_discard_recs`**
`max_discard_recs`는 EDB*Loader 세션을 종료하기 전까지 입력 데이터 레코드에서 만날 수 있는 폐기(discard) 레코드의 최대 개수입니다. 명령줄에서 `max_discard_recs`를 지정하면 컨트롤 파일의 `DISCARDMAX` 또는 `DISCARDS` 절을 재정의합니다.

`max_discard_recs`에 대한 자세한 내용은 [EDB*Loader 컨트롤 파일 작성(Building the EDB*Loader control file)](https://www.enterprisedb.com/docs/epas/latest/database_administration/02_edb_loader/building_the_control_file/)을 참고하십시오.

**`HANDLE_CONFLICTS={ FALSE | TRUE }`**
어떤 레코드 삽입이 고유 제약 조건(unique constraint) 위반으로 실패하면 EDB*Loader는 전체 작업을 중단합니다. `HANDLE_CONFLICTS`를 `TRUE`로 설정하면, EDB*Loader가 대신 중복 레코드를 `BAD` 파일로 옮기고 처리를 계속하도록 지시할 수 있습니다. 이 동작은 인덱스가 존재하는 경우에만 적용됩니다. 기본적으로 `HANDLE_CONFLICTS`는 `FALSE`로 설정됩니다.

`HANDLE_CONFLICTS`를 `TRUE`로 설정하는 것은 직접 경로 로딩(direct path loading)에서는 지원되지 않습니다. 직접 경로 로딩 중에 이 매개변수를 `TRUE`로 설정하면 EDB*Loader는 오류를 발생시킵니다.

**`LOG=log_file`**
`log_file`은 EDB*Loader가 EDB*Loader 세션의 결과를 기록하는 파일의 이름을 지정합니다.

`LOG` 매개변수를 생략하면 EDB*Loader는 edbldr가 호출된 디렉터리에 `control_file_base.log`라는 이름의 로그 파일을 생성합니다. `control_file_base`는 EDB*Loader 세션에서 사용된 컨트롤 파일의 기본 이름(base name)입니다. 운영 체제 계정 `enterprisedb`는 로그 파일이 기록되는 디렉터리에 대한 쓰기 권한이 있어야 합니다.

**`PARFILE=param_file`**
`param_file`은 EDB*Loader 세션의 명령줄 매개변수를 포함하는 파일의 이름을 지정합니다. 이 섹션에 나열된 명령줄 매개변수를 명령줄 대신 `param_file`에 지정할 수 있습니다. 단, `-d`, `-p`, `-h` 옵션과 `PARFILE` 매개변수는 예외입니다.

`param_file`에 지정된 매개변수는 `PARFILE` 옵션 앞에서 명령줄에 제공된 동일한 매개변수를 재정의합니다. `PARFILE` 옵션 뒤에 나타나는, 명령줄에 제공된 매개변수는 `param_file`에 지정된 동일한 매개변수를 재정의합니다.

> **참고**
> 다른 EDB*Loader 파일과 달리, `param_file`에는 가정되는 기본 파일 이름이나 확장자가 없습니다. 다만 Oracle SQL*Loader 관례에 따라 일반적으로 `.par`를 확장자로 사용합니다. 이는 필수는 아닙니다.

**`DIRECT= { FALSE | TRUE }`**
`DIRECT`가 `TRUE`로 설정되면 EDB*Loader는 일반 경로 로드(conventional path load) 대신 직접 경로 로드(direct path load)를 수행합니다. `DIRECT`의 기본값은 `FALSE`입니다.

복제된(replicated) 테이블에 데이터를 로드할 때는 `DIRECT=true`로 설정하지 마십시오. EDB*Loader로 복제된 테이블에 데이터를 로드하면서 `DIRECT=true`로 설정하면, 인덱스가 테이블에 있는 행을 누락하거나 삭제된 행에 대한 참조를 포함할 수 있습니다. EnterpriseDB는 복제된 테이블에 데이터를 로드하기 위한 직접 삽입(direct insert)을 지원하지 않습니다.

직접 경로 로드에 대한 자세한 내용은 [직접 경로 로드(Direct path load)](https://www.enterprisedb.com/docs/epas/latest/database_administration/02_edb_loader/invoking_edb_loader/direct_path_load/)를 참고하십시오.

**`FREEZE= { FALSE | TRUE }`**
행을 *frozen* 상태로 데이터를 복사하려면 `FREEZE`를 `TRUE`로 설정합니다. 현재 및 미래의 모든 트랜잭션에서 볼 수 있도록 보장된 튜플은, 트랜잭션 ID 랩어라운드(wraparound)를 방지하기 위해 frozen으로 표시됩니다. frozen 튜플에 대한 자세한 내용은 [PostgreSQL 코어 문서](https://www.postgresql.org/docs/current/static/routine-vacuuming.html)를 참고하십시오.

`FREEZE` 옵션을 사용할 때는 컨트롤 파일에서 데이터 로딩 유형을 `TRUNCATE`로 지정해야 합니다. `FREEZE`는 직접 로딩(direct loading)에서는 지원되지 않습니다.

기본적으로 `FREEZE`는 `FALSE`입니다.

**`ERRORS=error_count`**
`error_count`는 EDB*Loader 세션을 중단하기 전까지 허용되는 오류 수를 지정합니다. 기본값은 `50`입니다.

**`PARALLEL= { FALSE | TRUE }`**
`PARALLEL`을 `TRUE`로 설정하면 이 EDB*Loader 세션이 병렬 직접 경로 로드에 참여하는 여러 동시 EDB*Loader 세션 중 하나임을 나타냅니다. `PARALLEL`의 기본값은 `FALSE`입니다.

`PARALLEL`이 `TRUE`이면 `DIRECT` 매개변수도 `TRUE`로 설정해야 합니다.

병렬 직접 경로 로드에 대한 자세한 내용은 [병렬 직접 경로 로드(Parallel direct path load)](https://www.enterprisedb.com/docs/epas/latest/database_administration/02_edb_loader/invoking_edb_loader/parallel_direct_path_load/)를 참고하십시오.

**`ROWS=n`**
`n`은 EDB*Loader가 다음 `n`개 행 집합을 로드하기 전에 커밋하는 행 수를 지정합니다.

**`SKIP=skip_count`**
로드가 시작되기 전에 건너뛸 입력 데이터 파일 시작 부분의 레코드 수입니다. 기본값은 `0`입니다.

**`SKIP_INDEX_MAINTENANCE= { FALSE | TRUE }`**
`TRUE`로 설정하면 직접 경로 로드의 일부로 인덱스 유지 관리가 수행되지 않으며, 로드된 테이블의 인덱스는 무효(invalid)로 표시됩니다. `SKIP_INDEX_MAINTENANCE`의 기본값은 `FALSE`입니다.

병렬 직접 경로 로드 중에는 대상 테이블 인덱스가 갱신되지 않습니다. 로드가 완료된 후 무효로 표시됩니다.

`REINDEX` 명령으로 인덱스를 다시 빌드할 수 있습니다. `REINDEX` 명령에 대한 자세한 내용은 [PostgreSQL 코어 문서](https://www.postgresql.org/docs/current/static/sql-reindex.htm)를 참고하십시오.

**`edb_resource_group=group_name`**
`group_name`은 EDB*Loader 세션을 할당할 EDB Resource Manager 리소스 그룹의 이름을 지정합니다.

세션에 할당된 기본 리소스 그룹은 edbldr 명령줄에 지정된 `edb_resource_group` 매개변수가 제공하는 리소스 그룹으로 재정의됩니다. 그러한 예로는 `ALTER ROLE ... SET edb_resource_group` 명령으로 기본 리소스 그룹을 할당받은 데이터베이스 사용자가 EDB*Loader 세션을 실행하는 경우가 있습니다.

## 예제 (Examples)

이 예제는 데이터베이스 `edb`의 테이블을 로드하기 위해 `emp.ctl`이라는 컨트롤 파일을 사용하여 EDB*Loader를 호출합니다. 파일은 현재 작업 디렉터리에 있습니다.

```shell
$ /usr/edb/as18/bin/edbldr -d edb USERID=enterprisedb/password
CONTROL=emp.ctl
EDB*Loader: Copyright (c) 2007-2021, EnterpriseDB Corporation.

Successfully loaded (4) records
```

이 예제에서는 사용자 이름과 비밀번호를 명령줄에서 생략했기 때문에 EDB*Loader가 이를 묻습니다. 또한 bad 파일과 로그 파일은 `BAD` 및 `LOG` 명령줄 매개변수로 지정합니다.

```shell
$ /usr/edb/as18/bin/edbldr -d edb CONTROL=emp.ctl BAD=/tmp/emp.bad
LOG=/tmp/emp.log
Enter the user name : enterprisedb
Enter the password :
EDB*Loader: Copyright (c) 2007-2021, EnterpriseDB Corporation.

Successfully loaded (4) records
```

이 예제는 현재 작업 디렉터리에 있는 매개변수 파일을 사용하여 EDB*Loader를 실행합니다. `CONTROL`, `BAD`, `LOG` 파일 외에 `SKIP` 및 `ERRORS` 매개변수 기본값이 매개변수 파일에 지정되어 있습니다. 매개변수 파일 `emp.par`의 내용은 다음과 같습니다.

```ini
CONTROL=emp.ctl
BAD=/tmp/emp.bad
LOG=/tmp/emp.log
SKIP=1
ERRORS=10
```

매개변수 파일로 EDB*Loader를 호출합니다.

```shell
$ /usr/edb/as18/bin/edbldr -d edb PARFILE=emp.par
Enter the user name : enterprisedb
Enter the password :
EDB*Loader: Copyright (c) 2007-2021, EnterpriseDB Corporation.

Successfully loaded (3) records
```

이 예제는 현재 작업 디렉터리에 있는 `emp.ctl` 컨트롤 파일을 사용하는 `connstr=` 옵션으로 EDB*Loader를 호출하여 `edb`라는 데이터베이스의 테이블을 로드합니다.

```shell
$ /usr/edb/as18/bin/edbldr connstr=\"sslmode=verify-ca sslcompression=0
host=127.0.0.1 dbname=edb port=5444 user=enterprisedb\" CONTROL=emp.ctl
EDB*Loader: Copyright (c) 2007-2021, EnterpriseDB Corporation.

Successfully loaded (4) records
```

이 예제는 일반 사용자(normal user)를 사용하여 EDB*Loader를 호출합니다. 이 예제에서는 빈 테이블 `bar` 하나를 만들고 일반 사용자 `bob`을 만듭니다. `bob` 사용자에게는 테이블 `bar`에 대한 모든 권한이 부여됩니다. CREATE TABLE 명령은 빈 테이블을 만들고, CREATE USER 명령은 사용자를 만들며, GRANT 명령은 `bar` 테이블에 대한 필요한 권한을 사용자 `bob`에게 부여합니다.

```sql
CREATE TABLE bar(i int);
CREATE USER bob identified by '123';
GRANT ALL on bar TO bob;
```

컨트롤 파일과 데이터 파일:

```shell
## Control file
EDBAS/ - (master) $ cat /tmp/edbldr.ctl
LOAD DATA INFILE '/tmp/edbldr.dat'
truncate into table bar
(
i position(1:1)
)

## Data file
EDBAS/ - (master) $ cat /tmp/edbldr.dat
1
2
3
5
```

EDB*Loader 호출:

```shell
EDBAS/ - (master) $ /usr/edb/as18/bin/edbldr -d edb userid=bob/123 control=/tmp/edbldr.ctl
EDB*Loader: Copyright (c) 2007-2022, EnterpriseDB Corporation.

Successfully loaded (4) records
```

## 종료 코드 (Exit codes)

EDB*Loader가 종료될 때 다음 코드 중 하나를 반환합니다.

| 종료 코드 | 설명 |
|---|---|
| `0` | 모든 행이 성공적으로 로드되었습니다. |
| `1` | EDB*Loader가 명령줄 또는 구문 오류를 만났거나, 복구 불가능한 오류로 인해 로드 작업을 중단했습니다. |
| `2` | 로드는 완료되었지만 일부 또는 모든 행이 거부되거나 폐기되었습니다. |
| `3` | EDB*Loader가 OS 오류와 같은 치명적 오류를 만났습니다. 이 부류의 오류는 PostgreSQL 오류의 `FATAL` 또는 `PANIC` 심각도 수준에 해당합니다. |
