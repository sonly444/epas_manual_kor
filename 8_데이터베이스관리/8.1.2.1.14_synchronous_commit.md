# synchronous_commit — EPAS 18 데이터베이스 관리

> 원문: [EPAS v18 — Database administration › Configuration parameters › Top performance-related parameters › synchronous_commit](https://www.enterprisedb.com/docs/epas/latest/database_administration/01_configuration_parameters/03_configuration_parameters_by_functionality/01_top_performance_related_parameters/14_synchronous_commit/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·코드·파라미터 이름은 원문 그대로 보존했습니다.

**파라미터 타입 (Parameter type):** Boolean

**기본값 (Default value):** `true`

**범위 (Range):** `{true | false}`

**효력의 최소 범위 (Minimum scope of effect):** Per session

**값 변경이 적용되는 시점 (When value changes take effect):** Immediate

**활성화에 필요한 권한 (Required authorization to activate):** Session user

명령이 클라이언트에 `success` 표시를 반환하기 전에 트랜잭션 커밋이 WAL 레코드가 디스크에 기록되기를 기다릴지 여부를 지정합니다. 안전한 설정은 on이며, 이것이 기본값입니다. off인 경우, 클라이언트에 성공이 보고되는 시점과 트랜잭션이 실제로 서버 크래시에 대해 안전하다고 보장되는 시점 사이에 지연이 있을 수 있습니다. (최대 지연은 `wal_writer_delay`의 3배입니다.)

`fsync`와 달리, 이 파라미터를 off로 설정해도 데이터베이스 불일치의 위험은 발생하지 않습니다. 운영 체제나 데이터베이스 크래시로 인해 최근의 일부 "커밋된 것으로 추정되는(allegedly committed)" 트랜잭션이 손실될 수 있습니다. 그러나 데이터베이스 상태는 해당 트랜잭션이 깔끔하게 중단된(abort) 것과 동일합니다.

따라서 트랜잭션의 내구성(durability)에 대한 정확한 확실성보다 성능이 더 중요할 때 `synchronous_commit`을 off로 설정하는 것은 유용한 대안이 될 수 있습니다. 관련 정보는 PostgreSQL 코어 문서의 [`Asynchronous Commit`](https://www.postgresql.org/docs/current/wal-async-commit.html)을 참조하십시오.

이 파라미터는 언제든지 변경할 수 있습니다. 어느 한 트랜잭션의 동작은 그것이 커밋될 때 유효한 설정에 의해 결정됩니다. 따라서 일부 트랜잭션은 동기적으로, 다른 트랜잭션은 비동기적으로 커밋하도록 하는 것이 가능하고 유용합니다. 예를 들어, 기본값이 반대일 때 단일 다중 명령문 트랜잭션을 비동기적으로 커밋하려면, 트랜잭션 내에서 `SET LOCAL synchronous_commit TO OFF`를 실행하십시오.
