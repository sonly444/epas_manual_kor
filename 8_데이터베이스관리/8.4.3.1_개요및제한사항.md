# EDB Clone Schema 핵심 개념 및 제한사항 (Overview and limitations) — EPAS 18

> 원문: [EPAS v18 — Database administration › EDB Clone Schema › Overview and limitations](https://www.enterprisedb.com/docs/epas/latest/database_administration/14_edb_clone_schema/edb_clone_schema_overview/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 함수·파라미터·객체 유형·코드는 원문 그대로 보존했습니다.

## EDB Clone Schema 함수 (EDB Clone Schema functions)

EDB Clone Schema 함수는 `parallel_clone`과 `edb_cloneschema` 확장이 설치될 때 `edb_util` 스키마에 생성됩니다.

## 전제 조건 (Prerequisites)

EDB Clone Schema 함수를 사용하기 전에 다음 조건을 확인하십시오.

- 대상(target) 또는 로컬(local) 데이터베이스의 외부 서버에 대한 `CREATE USER MAPPING` 명령에 정의된 데이터베이스 슈퍼유저로 대상 또는 로컬 데이터베이스에 연결되어 있어야 합니다.

- `edb_util` 스키마가 검색 경로(search path)에 있거나, 클로닝 함수를 `edb_util` 접두사와 함께 호출해야 합니다.

- 대상 스키마가 대상 데이터베이스에 존재하지 않아야 합니다.

- 원격 복사 함수를 사용할 때 `on_tblspace` 파라미터가 `true`로 설정된 경우, 대상 데이터베이스 클러스터에 소스 스키마의 객체가 참조하는 모든 테이블스페이스가 포함되어 있어야 합니다. 그렇지 않으면 해당 데이터베이스 객체에 대한 DDL 문 생성이 대상 스키마에서 실패하고, 이로 인해 클로닝 프로세스가 실패합니다.

- 원격 복사 함수를 사용할 때 `copy_acls` 파라미터를 `true`로 설정한 경우, 소스 스키마의 객체에 `GRANT` 권한을 가진 모든 역할이 대상 데이터베이스 클러스터에 존재해야 합니다. 그렇지 않으면 해당 역할에 대한 권한 부여가 대상 스키마에서 실패하고, 이로 인해 클로닝 프로세스가 실패합니다.

- 클론 스키마를 설치하거나 사용할 데이터베이스의 이름을 `postgresql.conf` 파일에 추가하십시오. 예를 들어 클론 스키마를 `edb` 데이터베이스에 설치하거나 사용하려면 `postgresql.conf` 파일에 다음 항목을 추가합니다.

  ```text
  edb_job_scheduler.database_list='edb'
  ```

  또한 `postgresql.conf` 파일의 공유 라이브러리에 `parallel_clone`과 `edb_job_scheduler`를 추가합니다.

  ```text
  shared_preload_libraries='....,$libdir/parallel_clone, $libdir/edb_job_scheduler'
  ```

  `postgresql.conf` 파일의 변경 사항을 로드하려면 데이터베이스 서버를 재시작합니다.

## 함수 개요 (Overview of the functions)

EDB Clone Schema에서는 다음 함수를 사용합니다.

- `localcopyschema` — 소스 데이터베이스에서 동일한 데이터베이스(대상)로, 원본과 다른 스키마 이름으로 스키마와 그 데이터베이스 객체를 복사합니다. 소스 스키마와 복사본이 동일한 데이터베이스 내에 위치할 때 사용합니다. 자세한 내용은 [localcopyschema](https://www.enterprisedb.com/docs/epas/latest/database_administration/14_edb_clone_schema/copying_a_schema/)를 참고하십시오.
- `localcopyschema_nb` — `localcopyschema`와 동일한 목적을 백그라운드 작업으로 수행하여, 함수를 시작한 터미널을 해제합니다. 이 함수를 *비차단(non-blocking)* 함수라고 합니다. 자세한 내용은 [localcopyschema_nb](https://www.enterprisedb.com/docs/epas/latest/database_administration/14_edb_clone_schema/copying_a_schema/)를 참고하십시오.
- `remotecopyschema` — 소스 데이터베이스에서 다른 대상 데이터베이스로 스키마와 그 데이터베이스 객체를 복사합니다. 소스 스키마와 복사본이 별도의 데이터베이스에 위치할 때 사용합니다. 별도의 데이터베이스는 동일한 EDB Postgres Advanced Server 데이터베이스 클러스터에 있을 수도, 서로 다른 클러스터에 있을 수도 있습니다. 자세한 내용은 [remotecopyschema](https://www.enterprisedb.com/docs/epas/latest/database_administration/14_edb_clone_schema/copying_a_remote_schema/)를 참고하십시오.
- `remotecopyschema_nb` — `remotecopyschema`와 동일한 목적을 백그라운드 작업으로 수행하여, 함수를 시작한 터미널을 해제합니다. 이 함수는 비차단(non-blocking) 함수입니다. 자세한 내용은 [remotecopyschema_nb](https://www.enterprisedb.com/docs/epas/latest/database_administration/14_edb_clone_schema/copying_a_remote_schema/)를 참고하십시오.
- `process_status_from_log` — 클로닝 함수의 상태를 표시합니다. 이 정보는 클로닝 함수를 호출할 때 지정하는 로그 파일에서 가져옵니다. 자세한 내용은 [process_status_from_log](https://www.enterprisedb.com/docs/epas/latest/database_administration/14_edb_clone_schema/checking_the_status/)를 참고하십시오.
- `remove_log_file_and_job` — 클로닝 함수가 생성한 로그 파일을 삭제합니다. 비차단 형태의 함수가 생성한 작업(job)을 삭제하는 데에도 사용할 수 있습니다. 자세한 내용은 [remove_log_file_and_job](https://www.enterprisedb.com/docs/epas/latest/database_administration/14_edb_clone_schema/performing_cleanup_tasks/)를 참고하십시오.

## 지원되는 데이터베이스 객체 목록 (List of supported database objects)

한 스키마에서 다른 스키마로 다음 데이터베이스 객체를 클론할 수 있습니다.

- 데이터 타입(Data types)
- 테이블(파티션된 테이블 포함, 외부 테이블 제외)
- 인덱스(Indexes)
- 제약 조건(Constraints)
- 시퀀스(Sequences)
- 뷰 정의(View definitions)
- 구체화된 뷰(Materialized views)
- 전용 동의어(Private synonyms)
- 테이블 트리거(단, 이벤트 트리거 제외)
- 규칙(Rules)
- 함수(Functions)
- 프로시저(Procedures)
- 패키지(Packages)
- 지원되는 모든 객체 유형에 대한 주석(Comments)
- 지원되는 모든 객체 유형에 대한 접근 제어 목록(ACL)

다음 데이터베이스 객체는 클론할 수 없습니다.

- 라지 오브젝트(Postgres `LOBs` 및 `BFILEs`)
- 테이블의 논리 복제 속성(Logical replication attributes)
- 데이터베이스 링크(Database links)
- 외부 데이터 래퍼(Foreign data wrappers)
- 외부 테이블(Foreign tables)
- 이벤트 트리거(Event triggers)
- 확장(Extensions)

확장에 의존하는 객체 클로닝에 대해서는 아래 제한사항을 참고하십시오.

- 행 수준 보안(Row-level security)
- 정책(Policies)
- 연산자 클래스(Operator class)

## 제한사항 (Limitations)

다음 제한사항이 적용됩니다.

- EDB Clone Schema는 설치 중 EDB Postgres Advanced Server Dialect 대화 상자에서 **Compatible with Oracle** 방언(dialect)을 지정한 EDB Postgres Advanced Server에서 지원됩니다. 텍스트 모드 설치 또는 클러스터 초기화 중에 `--redwood-like` 키워드를 포함한 경우에도 지원됩니다.
- 함수, 프로시저, 트리거, 패키지 등의 소스 코드는 대상 스키마로 복사된 후 수정되지 않습니다. 이러한 프로그램이 스키마 이름이 포함된 객체 참조를 코드에 담고 있고, 그러한 스키마 이름이 대상 스키마에서 더 이상 일관되지 않으면, 대상 스키마에서 호출될 때 프로그램이 실패할 수 있습니다.
- 스키마 간(cross-schema) 객체 의존성은 해결되지 않습니다. 대상 스키마의 객체가 다른 스키마의 객체에 의존하는 경우, 이 의존성은 클로닝 함수에 의해 해결되지 않습니다.
- 원격 클로닝의 경우, 소스 스키마의 객체가 확장에 의존한다면 원격 클로닝 함수를 호출하기 전에 원격 데이터베이스의 public 스키마에 해당 확장을 생성해야 합니다.
- 최대 16개의 복사 작업(copy job)이 스키마를 클론하기 위해 병렬로 실행될 수 있습니다. 각 작업은 테이블 데이터를 병렬로 복사하기 위해 최대 16개의 워커 프로세스를 가질 수 있습니다.
- 백그라운드 워커가 실행하는 쿼리는 취소할 수 없습니다.
- `localcopyschema_nb`, `remotecopyschema_nb`와 같은 비차단 클로닝 함수는 슈퍼유저가 수행해야 합니다. `localcopyschema`, `remotecopyschema`와 같은 차단(blocking) 클로닝 함수만 비슈퍼유저가 수행할 수 있습니다. 이 함수들이 슈퍼유저 요건을 강제하지는 않지만, 비슈퍼유저로 사용하면 예기치 않은 동작이 발생할 수 있습니다.
- `edb_util.remove_log_file_and_job` 함수는 작업 ID 또는 로그 파일 이름으로 로그와 예약된 작업을 제거합니다. 이 함수는 EDB Postgres Advanced Server 17에서는 작업 ID를 사용해 동작하지 않습니다. 이 버전에서는 작업 예약이 pgAgent가 아니라 `edb_job_scheduler`에 의해 수행되기 때문입니다. pgAgent는 버전 14와 15에서 작업 예약에 사용됩니다.
