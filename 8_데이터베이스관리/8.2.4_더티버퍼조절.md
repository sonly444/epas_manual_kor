## 4. 더티 버퍼 조절 (Dirty buffer throttling)

> 원문: [dirty_buffer_throttling](https://www.enterprisedb.com/docs/epas/latest/database_administration/10_edb_resource_manager/dirty_buffer_throttling/)

EDB Resource Manager는 *더티 버퍼 조절(dirty buffer throttling)*을 사용하여 그룹 내 모든 프로세스의 총 공유 버퍼 쓰기 속도를 `dirty_rate_limit` 파라미터로 지정한 한도 근처로 유지합니다. 정의된 한도를 유지하기 위해 그룹 내 프로세스가 잠시 중단되어 짧은 시간 동안 절전 모드에 놓일 수 있습니다. 중단 발생 방식은 EDB Resource Manager의 독점 알고리즘으로 정의됩니다.

공유 버퍼 쓰기를 제어하려면 `dirty_rate_limit` 자원 유형 파라미터를 설정합니다.
- `dirty_rate_limit` 파라미터를, 그룹 내 모든 프로세스가 공유 버퍼에 쓰는(즉 "dirty"하게 만드는) 결합 속도의 초당 킬로바이트 수로 설정합니다. 예시 설정은 초당 3072킬로바이트입니다.
- `dirty_rate_limit` 파라미터의 유효 범위는 0에서 1.67772e+07입니다. 0 설정은 리소스 그룹에 dirty rate limit가 설정되지 않았음을 의미합니다.

### 리소스 그룹의 dirty rate limit 설정
`ALTER RESOURCE GROUP` 명령과 `SET dirty_rate_limit` 절을 사용합니다. 이 예에서 dirty rate limit는 `resgrp_a` 12288, `resgrp_b` 6144, `resgrp_c` 3072 (초당 킬로바이트)로 설정됩니다.
```sql
edb=# ALTER RESOURCE GROUP resgrp_a SET dirty_rate_limit TO 12288;
edb=# ALTER RESOURCE GROUP resgrp_b SET dirty_rate_limit TO 6144;
edb=# ALTER RESOURCE GROUP resgrp_c SET dirty_rate_limit TO 3072;
```
```sql
edb=# SELECT rgrpname, rgrpdirtyratelimit FROM edb_resource_group;
```
```text
 rgrpname  | rgrpdirtyratelimit
-----------+--------------------
 resgrp_a  |         12288
 resgrp_b  |         6144
 resgrp_c  |         3072
(3 rows)
```
리소스 그룹의 `dirty_rate_limit`을 변경하면 새로 할당되는 프로세스와 현재 실행 중인 그룹 구성원 프로세스에 즉시 영향을 줍니다. 즉 12288에서 3072로 변경하면 현재 실행 중인 프로세스가 총 그룹 dirty rate가 12288 대신 약 3072 KB/s가 되도록 하향 조절됩니다.

효과 시연을 위한 집약적 I/O용 테이블:
```sql
CREATE TABLE t1 (c1 INTEGER, c2 CHARACTER(500)) WITH (FILLFACTOR = 10);
```
`FILLFACTOR = 10` 절은 `INSERT` 명령이 페이지당 10%까지만 행을 채우게 하여, 예제 목적상 더 큰 더티 공유 블록 표본을 만듭니다.

### 더티 버퍼 수 표시
`pg_stat_statements` 모듈로 SQL 명령이 더티하게 만든 공유 버퍼 블록 수와 실행 시간을 표시하여 실제 KB/s 쓰기 속도를 계산하고 그룹의 dirty rate limit와 비교합니다.

사용 방법:
1. `postgresql.conf`에서 `shared_preload_libraries`에 `$libdir/pg_stat_statements` 추가:
   ```ini
   shared_preload_libraries = '$libdir/dbms_pipe,$libdir/edb_gen,$libdir/pg_stat_statements'
   ```
2. 데이터베이스 서버 재시작.
3. `CREATE EXTENSION`으로 모듈 생성:
   ```sql
   edb=# CREATE EXTENSION pg_stat_statements SCHEMA public;
   CREATE EXTENSION
   ```
`pg_stat_statements_reset()` 함수는 각 예제의 명확성을 위해 뷰를 초기화합니다.

### 실제 더티 속도 계산(단일 프로세스/단일 그룹 예)
`resgrp_b`(dirty_rate_limit=6144)에서 10,000행을 삽입:
```sql
edb=# INSERT INTO t1 VALUES (generate_series (1,10000), 'aaa');
INSERT 0 10000
edb=# SELECT query, rows, total_time, shared_blks_dirtied FROM pg_stat_statements;
```
```text
 rows                | 10000
 total_time          | 13496.184
 shared_blks_dirtied | 10003
```
실제 더티 속도 계산:
- 밀리초당 더티 블록 수 = 10003 / 13496.184 = 0.74117247 블록/ms.
- ×1000 → 초당 741.17247 블록.
- ×8.192 (1블록=8.192KB) → 약 6072 KB/s.

실제 더티 속도 6072 KB/s는 그룹의 dirty rate limit 6144 KB/s에 근접합니다. 그룹에 속하지 않은 채로 동일 단계를 반복하면 total_time이 2432.165ms로 훨씬 짧고, 실제 더티 속도는 약 33692 KB/s로 훨씬 높습니다.

> 원문에는 이어서 **다중 프로세스/단일 그룹**(두 세션이 `resgrp_b`에서 각각 약 2467·2679 KB/s → 합계 5146 KB/s로 한도 6144 이하)과 **다중 프로세스/다중 그룹**(세션1·2는 `resgrp_b`에서 합계 약 5499 KB/s로 6144 근처, 세션3·4는 `resgrp_c`에서 합계 약 3016 KB/s로 3072 근처) 예제가, 각 세션의 `INSERT`·`pg_stat_statements` 출력과 밀리초당 블록 → 초당 블록 → KB/s 3단계 계산과 함께 상세히 제시됩니다. 결론: EDB Resource Manager는 각 그룹의 총 더티 속도를 그룹별 dirty rate limit에 근접하게 유지합니다.
