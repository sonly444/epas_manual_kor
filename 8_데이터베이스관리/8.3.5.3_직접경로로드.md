# 직접 경로 로드 (Running a Direct Path Load) — EPAS 18

> 원문: [EPAS v18 — Database administration › EDB*Loader › Invoking EDB*Loader › Direct path load](https://www.enterprisedb.com/docs/epas/latest/database_administration/02_edb_loader/invoking_edb_loader/direct_path_load/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·옵션·코드는 원문 그대로 보존했습니다.

직접 경로 로드(direct path load) 중에 EDB*Loader는 데이터를 데이터베이스 페이지에 직접 쓴 다음 디스크에 동기화합니다. 이 방식은 표준 삽입 처리를 우회하여 성능을 향상시키지만 대상 테이블에 허용되는 제약 조건의 유형을 제한합니다.

## 허용되는 제약 조건

대상 테이블은 다음을 포함할 수 있습니다.

- 기본 키 제약 조건
- Not null 제약 조건
- 인덱스(고유 또는 비고유)

## 제한 사항

직접 경로 로드에는 중요한 제한이 있습니다.

**테이블 제한:**
- "트리거는 허용되지 않습니다."
- "체크 제약 조건은 허용되지 않습니다."
- 외래 키 제약 조건(다른 테이블을 참조하는 것과 다른 테이블에 의해 참조되는 것 모두)이 금지됩니다.
- 테이블 파티셔닝이 허용되지 않습니다.
- 규칙(rule)은 존재할 수 있으나 실행되지 않습니다.

**컨트롤 파일 제한:**
- `INTO TABLE` 절 하나만 지원됩니다(다중 테이블 로드 불가).
- 데이터 필드 정의에 SQL 표현식을 사용할 수 없습니다.
- `FREEZE` 옵션이 지원되지 않습니다.

## 중요 경고

"직접 경로를 사용하여 TDE 데이터베이스에 데이터를 로드하지 마십시오. 이는 데이터 블록 수준에서 릴레이션 파일에 영구적이고 복구 불가능한 손상을 일으킵니다."

## 실행 예제

직접 경로 로드를 실행하려면 `DIRECT=TRUE` 옵션을 사용합니다.

```shell
$ /usr/edb/as18/bin/edbldr -d edb USERID=enterprisedb/password
CONTROL=emp.ctl DIRECT=TRUE
```

명령은 성공적으로 완료되면 상태 확인을 반환합니다.
