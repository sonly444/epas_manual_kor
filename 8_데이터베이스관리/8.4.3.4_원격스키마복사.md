# 원격 소스에서 데이터베이스 객체 복사 (Copying database objects from a remote source) — EPAS 18

> 원문: [EPAS v18 — Database administration › EDB Clone Schema › Copying a remote database](https://www.enterprisedb.com/docs/epas/latest/database_administration/14_edb_clone_schema/copying_a_remote_schema/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 함수·파라미터·코드·출력은 원문 그대로 보존했습니다.

EDB Clone Schema로 스키마와 그 데이터베이스 객체의 원격 복사를 수행하는 데 사용할 수 있는 두 가지 함수가 있습니다.

- `remotecopyschema` — 소스 데이터베이스에서 다른 대상 데이터베이스로 스키마와 그 데이터베이스 객체를 복사합니다. 소스 스키마와 복사본이 별도의 데이터베이스에 위치할 때 이 함수를 사용합니다. 별도의 데이터베이스는 동일한 EDB Postgres Advanced Server 데이터베이스 클러스터에 있을 수도 있고 서로 다른 클러스터에 있을 수도 있습니다. 자세한 내용은 아래 [remotecopyschema](#원격-스키마-복사)를 참고하십시오.
- `remotecopyschema_nb` — `remotecopyschema`와 동일한 목적을 백그라운드 작업으로 수행하여, 함수를 시작한 터미널을 해제합니다. 이 함수는 비차단(non-blocking) 함수입니다. 자세한 내용은 아래 [remotecopyschema_nb](#원격-스키마-복사를-배치-작업으로-수행)를 참고하십시오.

## 원격 스키마 복사 (Copying a remote schema)

`remotecopyschema` 함수는 `source_fdw` 외부 서버에 지정된 원격 소스 데이터베이스의 소스 스키마로부터, `target_fdw` 외부 서버에 지정된 로컬 대상 데이터베이스의 대상 스키마로 스키마와 그 데이터베이스 객체를 복사합니다.

```sql
remotecopyschema(
  <source_fdw> TEXT,
  <target_fdw> TEXT,
  <source_schema> TEXT,
  <target_schema> TEXT,
  <log_filename> TEXT
  [, <on_tblspace> BOOLEAN
  [, <verbose_on> BOOLEAN
  [, <copy_acls> BOOLEAN
  [, <worker_count> INTEGER ]]]]
)
```

함수는 Boolean 값을 반환합니다. 함수가 성공하면 `true`를, 실패하면 `false`를 반환합니다.

`source_fdw`, `target_fdw`, `source_schema`, `target_schema`, `log_filename`은 필수 파라미터입니다. 나머지 파라미터는 모두 선택 사항입니다.

### 파라미터 (Parameters)

**`source_fdw`**
데이터베이스 객체를 클론할 원본이 되는, `postgres_fdw` 외부 데이터 래퍼가 관리하는 외부 서버의 이름입니다.

**`target_fdw`**
데이터베이스 객체를 클론해 넣을 대상이 되는, `postgres_fdw` 외부 데이터 래퍼가 관리하는 외부 서버의 이름입니다.

**`source_schema`**
데이터베이스 객체를 클론할 소스 스키마의 이름입니다.

**`target_schema`**
소스 스키마로부터 데이터베이스 객체를 클론해 넣을 대상 스키마의 이름입니다.

**`log_filename`**
함수의 정보가 기록되는 로그 파일의 이름입니다. 로그 파일은 `postgresql.conf` 파일의 `log_directory` 구성 파라미터로 지정된 디렉터리 아래에 생성됩니다.

**`on_tblspace`**
데이터베이스 객체를 그 테이블스페이스에 생성할지 여부를 지정하는 Boolean 값입니다. `false`이면 대상 스키마에 추가할 때 해당 `CREATE` DDL 문에 `TABLESPACE` 절이 포함되지 않습니다. `true`이면 `CREATE` DDL 문에 `TABLESPACE` 절이 포함됩니다. 기본값은 `false`입니다.

> **참고**
> `true`를 지정하고 데이터베이스 객체에 `TABLESPACE` 절이 있는 경우, 해당 테이블스페이스가 대상 데이터베이스 클러스터에 존재해야 합니다. 그렇지 않으면 클로닝 함수가 실패합니다.

**`verbose_on`**
대상 스키마에 객체를 생성할 때 `log_filename`에 DDL을 출력할지 여부를 지정하는 Boolean 값입니다. `false`이면 DDL이 출력되지 않고, `true`이면 출력됩니다. 기본값은 `false`입니다.

**`copy_acls`**
대상 스키마에 객체를 생성할 때 접근 제어 목록(ACL)을 포함할지 여부를 지정하는 Boolean 값입니다. 접근 제어 목록은 `GRANT` 권한 문의 집합입니다. `false`이면 포함되지 않고, `true`이면 포함됩니다. 기본값은 `false`입니다.

> **참고**
> `true`를 지정하는 경우, `GRANT` 권한을 가진 역할이 대상 데이터베이스 클러스터에 존재해야 합니다. 그렇지 않으면 클로닝 함수가 실패합니다.

**`worker_count`**
클론을 병렬로 수행할 백그라운드 워커의 수입니다. 기본값은 `1`입니다.

### 예제 (Example)

이 예제는 데이터베이스 `srcdb`(`src_server`로 정의)의 스키마 `srcschema`를, 데이터베이스 `tgtdb`(`tgt_server`로 정의)의 대상 스키마 `tgtschema`로 클론하는 것을 보여줍니다.

소스 서버 환경:

- 소스 데이터베이스 서버가 실행 중인 호스트: `192.168.2.28`
- 소스 데이터베이스 서버 포트: `5444`
- 클론의 소스 데이터베이스: `srcdb`
- 위 항목의 정보를 담은 외부 서버(`src_server`)와 사용자 매핑
- 소스 스키마: `srcschema`

대상 서버 환경:

- 대상 데이터베이스 서버가 실행 중인 호스트: `localhost`
- 대상 데이터베이스 서버 포트: `5444`
- 클론의 대상 데이터베이스: `tgtdb`
- 위 항목의 정보를 담은 외부 서버(`tgt_server`)와 사용자 매핑
- 대상 스키마: `tgtschema`
- `remotecopyschema`를 호출할 데이터베이스 슈퍼유저: `enterprisedb`

함수를 호출하기 전에, 연결 데이터베이스 사용자 `enterprisedb`가 데이터베이스 `tgtdb`에 연결합니다. 이 함수에는 `worker_count` `4`가 지정되었습니다.

```sql
tgtdb=# SELECT edb_util.remotecopyschema
('src_server','tgt_server','srcschema','tgtschema','clone_rmt_src_tgt',worker_count => 4);
```

## 원격 스키마 복사를 배치 작업으로 수행 (Copying a remote schema using a batch job)

`remotecopyschema_nb` 함수는 `source_fdw` 외부 서버에 지정된 원격 소스 데이터베이스의 소스 스키마로부터, `target_fdw` 외부 서버에 지정된 로컬 대상 데이터베이스의 대상 스키마로 스키마와 그 데이터베이스 객체를 복사합니다. 복사는 DBMS_JOB에 제출된 작업으로서 비차단(non-blocking) 방식으로 수행됩니다.

```sql
remotecopyschema_nb(
  <source_fdw> TEXT,
  <target_fdw> TEXT,
  <source> TEXT,
  <target> TEXT,
  <log_filename> TEXT
  [, <on_tblspace> BOOLEAN
  [, <verbose_on> BOOLEAN
  [, <copy_acls> BOOLEAN
  [, <worker_count> INTEGER ]]]]
)
```

함수는 DBMS_JOB에 제출된 작업의 `INTEGER` 값 작업 ID를 반환합니다. 함수가 실패하면 null을 반환합니다.

`source_fdw`, `target_fdw`, `source`, `target`, `log_filename` 파라미터는 필수입니다. 나머지 파라미터는 모두 선택 사항입니다.

작업이 완료된 후에는 `remove_log_file_and_job` 함수로 작업을 제거합니다.

### 파라미터 (Parameters)

**`source_fdw`**
데이터베이스 객체를 클론할 원본이 되는, `postgres_fdw` 외부 데이터 래퍼가 관리하는 외부 서버의 이름입니다.

**`target_fdw`**
데이터베이스 객체를 클론해 넣을 대상이 되는, `postgres_fdw` 외부 데이터 래퍼가 관리하는 외부 서버의 이름입니다.

**`source`**
데이터베이스 객체를 클론할 소스 스키마의 이름입니다.

**`target`**
소스 스키마로부터 데이터베이스 객체를 클론해 넣을 대상 스키마의 이름입니다.

**`log_filename`**
함수의 정보를 기록할 로그 파일의 이름입니다. 로그 파일은 `postgresql.conf` 파일의 `log_directory` 구성 파라미터로 지정된 디렉터리 아래에 생성됩니다.

**`on_tblspace`**
데이터베이스 객체를 그 테이블스페이스에 생성할지 여부를 지정하는 Boolean 값입니다. `false`이면 대상 스키마에 추가할 때 해당 `CREATE` DDL 문에 `TABLESPACE` 절이 포함되지 않습니다. `true`이면 `CREATE` DDL 문에 `TABLESPACE` 절이 포함됩니다. 기본값은 `false`입니다.

> **참고**
> `true`를 지정하고 데이터베이스 객체에 `TABLESPACE` 절이 있는 경우, 해당 테이블스페이스가 대상 데이터베이스 클러스터에 존재해야 합니다. 그렇지 않으면 클로닝 함수가 실패합니다.

**`verbose_on`**
대상 스키마에 객체를 생성할 때 `log_filename`에 DDL을 출력할지 여부를 지정하는 Boolean 값입니다. `false`이면 DDL이 출력되지 않고, `true`이면 출력됩니다. 기본값은 `false`입니다.

**`copy_acls`**
대상 스키마에 객체를 생성할 때 접근 제어 목록(ACL)을 포함할지 여부를 지정하는 Boolean 값입니다. 접근 제어 목록은 `GRANT` 권한 문의 집합입니다. `false`이면 포함되지 않고, `true`이면 포함됩니다. 기본값은 `false`입니다.

> **참고**
> `true`를 지정하는 경우, `GRANT` 권한을 가진 역할이 대상 데이터베이스 클러스터에 존재해야 합니다. 그렇지 않으면 클로닝 함수가 실패합니다.

**`worker_count`**
클론을 병렬로 수행할 백그라운드 워커의 수입니다. 기본값은 `1`입니다.
