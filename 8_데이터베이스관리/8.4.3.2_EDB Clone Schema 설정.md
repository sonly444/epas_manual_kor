# EDB Clone Schema 설정 (Setting up EDB Clone Schema) — EPAS 18

> 원문: [EPAS v18 — Database administration › EDB Clone Schema › Setting up EDB Clone Schema](https://www.enterprisedb.com/docs/epas/latest/database_administration/14_edb_clone_schema/setting_up_edb_clone_schema/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·확장·파라미터·코드·출력은 원문 그대로 보존했습니다.

EDB Clone Schema를 사용하려면, EDB Clone Schema 함수가 소스 또는 대상 데이터베이스로 사용하는 모든 데이터베이스에 먼저 여러 확장(extension)과 PL/Perl 언어를 설치해야 합니다.

또한 데이터베이스 서버의 `postgresql.conf` 파일에서 일부 구성 파라미터를 수정하는 것이 도움이 될 수 있습니다.

## 전제 조건 (Prerequisites)

전제 조건으로, 먼저 `parallel_clone` 확장 패키지를 설치합니다. 패키지 설치 명령은 다음과 같습니다.

```shell
sudo <package-manager> -y install edb-as<version>-server-parallel-clone
```

여기서:

- `<package-manager>`는 운영체제에서 사용하는 패키지 관리자입니다.

| 패키지 관리자 | 운영체제 |
| :-- | :-- |
| dnf | RHEL 8 및 파생 배포판 |
| zypper | SLES |
| apt-get | Debian 및 파생 배포판 |

- `<version>`은 사용 중인 EPAS 버전입니다.

## 구성 파일 수정 (Modifying the configuration file)

`postgresql.conf` 파일의 `shared_preload_libraries` 구성 파라미터에 `$libdir/parallel_clone`과 `$libdir/edb_job_scheduler`를 추가하여 수정합니다.

```ini
shared_preload_libraries = '$libdir/dbms_pipe,$libdir/dbms_aq,$libdir/parallel_clone,$libdir/edb_job_scheduler'
```

변경 사항을 적용하려면 데이터베이스 서버를 재시작해야 합니다.

## 확장 설치 (Installing extensions)

EDB Clone Schema 함수가 소스 또는 대상 데이터베이스로 사용하는 모든 데이터베이스에 다음 확장을 설치합니다: `postgres_fdw`, `dblink`, `edb_job_scheduler`, `dbms_job`.

```sql
CREATE EXTENSION postgres_fdw SCHEMA public;
CREATE EXTENSION dblink SCHEMA public;
CREATE EXTENSION edb_job_scheduler;
CREATE EXTENSION dbms_job;
```

`CREATE EXTENSION` 명령 사용에 대한 자세한 내용은 [PostgreSQL 코어 문서](https://www.postgresql.org/docs/current/static/sql-createextension.html)를 참고하십시오.

## PL/Perl 설치 (Installing PL/Perl)

1. 데이터베이스에 Perl 절차적 언어(PL/Perl)를 설치하고 `CREATE TRUSTED LANGUAGE plperl` 명령을 실행합니다. Linux의 경우 `edb-as<xx>-server-plperl` RPM 패키지를 사용하여 PL/Perl을 설치합니다(여기서 `<xx>`는 EDB Postgres Advanced Server 버전 번호). Windows의 경우 EDB Postgres Language Pack을 사용합니다. EDB Language Pack에 대한 정보는 [EDB Postgres Language Pack](https://www.enterprisedb.com/docs/language_pack/latest/)을 참고하십시오.

2. 슈퍼유저로 데이터베이스에 연결하여 다음 명령을 실행합니다.

   ```sql
   CREATE TRUSTED LANGUAGE plperl;
   ```

`CREATE LANGUAGE` 명령 사용에 대한 자세한 내용은 [PostgreSQL 코어 문서](https://www.postgresql.org/docs/current/static/sql-createlanguage.html)를 참고하십시오.

## 구성 파라미터 설정 (Setting configuration parameters)

`postgresql.conf` 파일에서 구성 파라미터를 수정해야 할 수 있습니다.

### 성능 구성 파라미터 (Performance configuration parameters)

하나의 트랜잭션으로 대용량 스키마를 복사하기 위해 시스템을 튜닝해야 할 수 있습니다. 구성 파라미터 튜닝은 클로닝 함수에서 참조되는 소스 데이터베이스 서버를 대상으로 합니다.

`postgresql.conf` 파일에서 다음 구성 파라미터를 튜닝해야 할 수 있습니다.

- `work_mem` — 임시 디스크 파일에 쓰기 전에 내부 정렬 작업과 해시 테이블이 사용할 메모리 양을 지정합니다.
- `maintenance_work_mem` — `VACUUM`, `CREATE INDEX`, `ALTER TABLE ADD FOREIGN KEY`와 같은 유지 관리 작업이 사용할 최대 메모리 양을 지정합니다.
- `max_worker_processes` — 시스템이 지원할 수 있는 백그라운드 프로세스의 최대 수를 설정합니다.
- `checkpoint_timeout` — 자동 WAL 체크포인트 사이의 최대 시간(초)입니다.
- `checkpoint_completion_target` — 체크포인트 사이 전체 시간에 대한 비율로 체크포인트 완료 목표를 지정합니다.
- `checkpoint_flush_after` — 체크포인트 수행 중 `checkpoint_flush_after` 바이트보다 많이 기록될 때마다, OS가 이 쓰기를 기반 스토리지에 강제로 발행하도록 시도합니다.
- `max_wal_size` — 자동 WAL 체크포인트 사이에 WAL이 커질 수 있는 최대 크기입니다.
- `max_locks_per_transaction` — 각 트랜잭션에 할당되는 객체 잠금의 평균 수를 제어합니다. 모든 트랜잭션의 잠금이 잠금 테이블에 들어가는 한, 개별 트랜잭션은 더 많은 객체를 잠글 수 있습니다.

구성 파라미터에 대한 자세한 내용은 [PostgreSQL 코어 문서](https://www.postgresql.org/docs/current/static/runtime-config.html)를 참고하십시오.

### 상태 로깅 (Status logging)

클로닝 함수의 상태 로깅은, 클로닝 함수를 호출할 때 연결되어 있는 데이터베이스 서버의 `postgresql.conf` 파일에서 `log_directory` 파라미터로 지정된 디렉터리에 로그 파일을 생성합니다.

기본 위치는 `PGDATA/log`입니다.

```ini
#log_directory = 'log'        # directory where log files are written,
                              # can be absolute or relative to PGDATA
```

이 디렉터리는 클로닝 함수를 실행하기 전에 존재해야 합니다.

로그 파일의 이름은 클로닝 함수를 호출할 때 파라미터 목록에 지정하는 값으로 결정됩니다.

로그 파일의 상태를 표시하려면 `process_status_from_log` 함수를 사용합니다.

로그 파일을 삭제하려면 `remove_log_file_and_job` 함수를 사용하거나, 로그 디렉터리에서 수동으로 삭제합니다.

## EDB Clone Schema 설치 (Installing EDB Clone Schema)

EDB Clone Schema 함수가 소스 또는 대상 데이터베이스로 사용하는 모든 데이터베이스에 EDB Clone Schema를 설치합니다.

1. 패키지 설치 명령은 다음과 같습니다.

   ```shell
   sudo <package-manager> -y install edb-as<version>-server-cloneschema
   ```

   여기서:

   - `<package-manager>`는 운영체제에서 사용하는 패키지 관리자입니다.

     | 패키지 관리자 | 운영체제 |
     | :-- | :-- |
     | dnf | RHEL 8 및 파생 배포판 |
     | zypper | SLES |
     | apt-get | Debian 및 파생 배포판 |

   - `<version>`은 사용 중인 EPAS 버전입니다.

2. 이전에 더 오래된 버전의 `edb_cloneschema` 확장을 설치한 적이 있다면 다음 명령을 실행합니다.

   ```sql
   DROP EXTENSION parallel_clone CASCADE;
   ```

   이 명령은 `edb_cloneschema` 확장도 함께 드롭합니다.

3. 확장을 설치합니다.

   ```sql
   CREATE EXTENSION parallel_clone;

   CREATE EXTENSION edb_cloneschema;
   ```

## 로그 디렉터리 생성 (Creating Log directory)

모든 로그 파일을 저장하기 위해 로그 디렉터리가 필요합니다.

확장을 생성한 후, 로그 디렉터리를 생성하기 위해 슈퍼유저로 다음 문을 실행해야 합니다.

```sql
SELECT edb_util.create_clone_log_dir();
```

성공적으로 실행되면 true 값을 반환합니다.

## 외부 서버와 사용자 매핑 생성 (Creating the foreign servers and user mappings)

로컬 클로닝 함수 `localcopyschema` 또는 `localcopyschema_nb`를 사용할 때, 필수 파라미터 중 하나는 단일 외부 서버(foreign server)입니다. 이 서버는 클론된 스키마의 소스이자 수신처가 되는 데이터베이스 서버와 그 데이터베이스를 식별합니다.

원격 클로닝 함수 `remotecopyschema` 또는 `remotecopyschema_nb`를 사용할 때, 필수 파라미터 중 두 개는 두 개의 외부 서버를 포함합니다. 첫 번째 파라미터로 지정된 외부 서버는 클론된 스키마의 제공자가 되는 소스 데이터베이스 서버와 그 데이터베이스를 식별합니다. 두 번째 파라미터로 지정된 외부 서버는 클론된 스키마의 수신처가 되는 대상 데이터베이스 서버와 그 데이터베이스를 식별합니다.

각 외부 서버에 대해 사용자 매핑(user mapping)을 생성해야 합니다. 선택된 데이터베이스 슈퍼유저가 클로닝 함수를 호출할 때, 그 슈퍼유저는 클로닝 함수에 파라미터로 지정된 외부 서버에 접근할 수 있는 데이터베이스 사용자 이름·비밀번호에 매핑되어 있어야 합니다.

외부 데이터, 외부 서버, 사용자 매핑에 대한 일반적인 정보는 [PostgreSQL 코어 문서](https://www.postgresql.org/docs/current/static/ddl-foreign-data.html)를 참고하십시오.

### 로컬 클로닝 함수용 외부 서버와 사용자 매핑 (Foreign server and user mapping for local cloning functions)

`localcopyschema`와 `localcopyschema_nb` 함수의 경우, 소스와 대상 스키마가 모두 동일한 데이터베이스 서버의 동일한 데이터베이스에 있습니다. 이 함수들에는 외부 서버를 하나만 정의하고 지정해야 합니다. 이 외부 서버는 *로컬 서버(local server)*라고도 하는데, `localcopyschema` 또는 `localcopyschema_nb` 함수를 호출할 때 연결되어 있어야 하는 서버이기 때문입니다.

사용자 매핑은 외부 서버에 대한 연결·인증 정보를 정의합니다. 클로닝이 발생하는 로컬 서버의 데이터베이스에서 이 외부 서버와 사용자 매핑을 생성해야 합니다.

EDB Clone Schema 함수를 호출할 때, 사용자 매핑이 정의된 데이터베이스 사용자는 슈퍼유저여야 하고 로컬 서버에 연결되어 있어야 합니다.

이 예제는 클론할 스키마를 포함하고 클론된 스키마를 수신할 데이터베이스에 대한 외부 서버를 생성합니다.

```sql
CREATE SERVER local_server FOREIGN DATA WRAPPER postgres_fdw
  OPTIONS(
    host 'localhost',
    port '5444',
    dbname 'edb'
);
```

`CREATE SERVER` 명령 사용에 대한 자세한 내용은 [PostgreSQL 코어 문서](https://www.postgresql.org/docs/current/static/sql-createserver.html)를 참고하십시오.

이 서버에 대한 사용자 매핑은 다음과 같습니다.

```sql
CREATE USER MAPPING FOR enterprisedb SERVER local_server
  OPTIONS (
    user 'enterprisedb',
    password 'password'
);
```

`CREATE USER MAPPING` 명령 사용에 대한 자세한 내용은 [PostgreSQL 코어 문서](https://www.postgresql.org/docs/current/sql-createusermapping.html)를 참고하십시오.

다음 psql 명령은 외부 서버와 사용자 매핑을 보여줍니다.

```sql
edb=# \des+
```

출력

```text
List of foreign servers
-[ RECORD 1 ]--------+----------------------------------------------
Name                 | local_server
Owner                | enterprisedb
Foreign-data wrapper | postgres_fdw
Access privileges    |
Type                 |
Version              |
FDW options          | (host 'localhost', port '5444', dbname 'edb')
Description          |
```

```sql
edb=# \deu+
```

출력

```text
                        List of user mappings
    Server    |  User name   |                 FDW options
--------------+--------------+----------------------------------------------
 local_server | enterprisedb | ("user" 'enterprisedb', password 'password')
(1 row)
```

데이터베이스 슈퍼유저 `enterprisedb`가 클로닝 함수를 호출하면, 비밀번호를 가진 데이터베이스 사용자 `enterprisedb`가 포트 `5444`의 `localhost`에 있는 `local_server`의 데이터베이스 `edb`에 연결하는 데 사용됩니다.

이 경우 매핑된 데이터베이스 사용자 `enterprisedb`와, 로컬 `edb` 데이터베이스에 연결하는 데 사용된 데이터베이스 사용자 `enterprisedb`는 동일한 데이터베이스 사용자입니다. 다만 이것이 필수는 아닙니다.

이 외부 서버와 사용자 매핑 예제의 구체적인 사용은 [`localcopyschema`](https://www.enterprisedb.com/docs/epas/latest/database_administration/14_edb_clone_schema/copying_a_schema/)의 예제를 참고하십시오.

### 원격 클로닝 함수용 외부 서버와 사용자 매핑 (Foreign server and user mapping for remote cloning functions)

`remotecopyschema`와 `remotecopyschema_nb` 함수의 경우, 소스와 대상 스키마가 동일하거나 서로 다른 데이터베이스 서버의 서로 다른 데이터베이스에 있습니다. 이 함수들에는 두 개의 외부 서버를 정의하고 지정해야 합니다.

클론할 소스 스키마를 포함하는 원본 데이터베이스 서버와 그 데이터베이스를 정의하는 외부 서버를 *소스 서버(source server)* 또는 *원격 서버(remote server)*라고 합니다.

클론할 스키마를 수신할 데이터베이스 서버와 그 데이터베이스를 정의하는 외부 서버를 *대상 서버(target server)* 또는 *로컬 서버(local server)*라고 합니다. 대상 서버를 로컬 서버라고도 하는 이유는, `remotecopyschema` 또는 `remotecopyschema_nb` 함수를 호출할 때 연결되어 있어야 하는 서버이기 때문입니다.

사용자 매핑은 외부 서버에 대한 연결·인증 정보를 정의합니다. 이 모든 외부 서버와 사용자 매핑을 대상/로컬 서버의 대상 데이터베이스에 생성해야 합니다. EDB Clone Schema 함수를 호출할 때, 사용자 매핑이 정의된 데이터베이스 사용자는 슈퍼유저여야 하고 로컬 서버에 연결된 사용자여야 합니다.

이 예제는 클론된 스키마를 수신하는 로컬 대상 데이터베이스에 대한 외부 서버를 생성합니다.

```sql
CREATE SERVER tgt_server FOREIGN DATA WRAPPER postgres_fdw
  OPTIONS(
    host 'localhost',
    port '5444',
    dbname 'tgtdb'
);
```

이 서버에 대한 사용자 매핑은 다음과 같습니다.

```sql
CREATE USER MAPPING FOR enterprisedb SERVER tgt_server
  OPTIONS (
    user 'tgtuser',
    password 'tgtpassword'
);
```

이 예제는 클론된 스키마의 소스가 되는 원격 소스 데이터베이스에 대한 외부 서버를 생성합니다.

```sql
CREATE SERVER src_server FOREIGN DATA WRAPPER postgres_fdw
  OPTIONS(
    host '192.168.2.28',
    port '5444',
    dbname 'srcdb'
);
```

이 서버에 대한 사용자 매핑은 다음과 같습니다.

```sql
CREATE USER MAPPING FOR enterprisedb SERVER src_server
  OPTIONS (
    user 'srcuser',
    password 'srcpassword'
);
```

> **참고**
> 소스 데이터베이스 `srcdb`를 실행하는 데이터베이스 서버의 `pg_hba.conf` 파일에 적절한 항목이 있는지 확인하십시오. 이 항목은 소스 서버와 데이터베이스를 정의하는 외부 서버 `src_server`의 사용자 매핑에 포함된 데이터베이스 사용자 `srcuser`로, 대상 서버 위치(다음 예의 주소 `192.168.2.27`)에서의 연결을 허용해야 합니다.
