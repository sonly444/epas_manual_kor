# 병렬 직접 경로 로드 (Running a Parallel Direct Path Load) — EPAS 18

> 원문: [EPAS v18 — Database administration › EDB*Loader › Invoking EDB*Loader › Parallel direct path load](https://www.enterprisedb.com/docs/epas/latest/database_administration/02_edb_loader/invoking_edb_loader/parallel_direct_path_load/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·옵션·코드는 원문 그대로 보존했습니다.

로딩을 둘 이상의 동시 세션에 분산하여 직접 경로 로드 성능을 향상시킬 수 있으며, 각 세션은 중복 레코드를 방지하기 위해 자체 데이터 파일로 동일한 테이블을 처리합니다.

## 주요 제한 사항

대상 테이블은 다음 여러 제약 조건을 준수해야 합니다.

- "트리거는 허용되지 않습니다."
- "체크 제약 조건은 허용되지 않습니다."
- "다른 테이블을 참조하는 대상 테이블의 외래 키 제약 조건은 허용되지 않습니다."
- "대상 테이블을 참조하는 다른 테이블의 외래 키 제약 조건은 허용되지 않습니다."
- "테이블을 파티션해서는 안 됩니다."
- 규칙(rule)은 존재할 수 있으나 로드 중 실행되지 않습니다.

또한 각 컨트롤 파일에 `APPEND` 절을 포함해야 합니다.

## 구현 과정

병렬 직접 경로 로드를 실행하려면:

1. 각 참여자에 대해 별도의 EDB*Loader 세션을 실행합니다.
2. 각 호출에 `DIRECT=TRUE`와 `PARALLEL=TRUE` 파라미터를 모두 포함합니다.
3. 각 세션은 독립적으로 작동합니다. 한 세션을 롤백해도 다른 세션에 영향을 주지 않습니다.

각 컨트롤 파일은 동일한 테이블 및 필드 사양을 유지하면서 서로 다른 데이터 파일을 참조해야 합니다. 호출 명령은 다음 패턴을 따릅니다.

```shell
/usr/edb/as18/bin/edbldr -d edb USERID=enterprisedb/password
CONTROL=control_file.ctl DIRECT=TRUE PARALLEL=TRUE
```

## 로드 후 유지 관리

완료 후, "병렬 직접 경로 로드 중에는 대상 테이블의 인덱스가 업데이트되지 않습니다." 인덱스의 유효성을 복원하고 쿼리 최적화를 활성화하려면 `REINDEX` 명령을 사용하여 인덱스를 재구축해야 합니다.
