# 감사 설정 (Auditing settings) — EPAS 18

> 원문: [EPAS v18 — Database administration › Configuration parameters by functionality › Auditing settings](https://www.enterprisedb.com/docs/epas/latest/database_administration/01_configuration_parameters/03_configuration_parameters_by_functionality/07_auditing_settings/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 파라미터 이름·값·범위·기본값은 원문 그대로 보존했습니다.

이 페이지는 EDB Postgres Advanced Server 버전 18의 감사(auditing) 기능에 대한 구성 파라미터를 제공합니다. 이 설정들은 EDB Postgres Advanced Server 데이터베이스 감사 기능과 함께 사용됩니다.

다음 12개의 감사 관련 구성 파라미터로 데이터베이스 감사 동작을 제어합니다: `edb_audit`, `edb_audit_directory`, `edb_audit_filename`, `edb_audit_rotation_day`, `edb_audit_rotation_size`, `edb_audit_rotation_seconds`, `edb_audit_connect`, `edb_audit_disconnect`, `edb_audit_statement`, `edb_audit_tag`, `edb_audit_destination`, `edb_log_every_bulk_value`.

---

## edb_audit

| 항목 | 값 |
|---|---|
| 매개변수 유형 | 열거형 |
| 기본값 | `none` |
| 범위 | `{none \| csv \| xml \| json}` |
| 최소 적용 범위 | 클러스터 |
| 값 변경 적용 시점 | 리로드 |
| 활성화에 필요한 권한 | EDB Postgres Advanced Server 서비스 계정 |

데이터베이스 감사를 활성화하거나 비활성화합니다. `xml`, `csv`, `json` 값은 데이터베이스 감사를 활성화하며, 감사 정보를 어떤 파일 형식으로 저장할지 결정합니다. `none`은 데이터베이스 감사를 비활성화합니다.

## edb_audit_directory

| 항목 | 값 |
|---|---|
| 매개변수 유형 | 문자열 |
| 기본값 | `edb_audit` |
| 범위 | 해당 없음(n/a) |
| 최소 적용 범위 | 클러스터 |
| 값 변경 적용 시점 | 리로드 |
| 활성화에 필요한 권한 | EDB Postgres Advanced Server 서비스 계정 |

감사 로그 파일이 생성되는 디렉터리를 지정합니다. 절대 경로 또는 EDB Postgres Advanced Server `data` 디렉터리를 기준으로 한 상대 경로를 지정합니다.

## edb_audit_filename

| 항목 | 값 |
|---|---|
| 매개변수 유형 | 문자열 |
| 기본값 | `audit-%Y%m%d_%H%M%S` |
| 범위 | 해당 없음(n/a) |
| 최소 적용 범위 | 클러스터 |
| 값 변경 적용 시점 | 리로드 |
| 활성화에 필요한 권한 | EDB Postgres Advanced Server 서비스 계정 |

감사 정보가 저장되는 감사 파일의 파일 이름을 지정합니다. 기본 파일 이름은 `audit-%Y%m%d_%H%M%S`입니다. `%Y`, `%m`과 같은 이스케이프 시퀀스는 시스템 날짜·시간의 적절한 현재 값으로 치환됩니다.

## edb_audit_rotation_day

| 항목 | 값 |
|---|---|
| 매개변수 유형 | 문자열 |
| 기본값 | `every` |
| 범위 | `{none \| every \| sun \| mon \| tue \| wed \| thu \| fri \| sat} ...` |
| 최소 적용 범위 | 클러스터 |
| 값 변경 적용 시점 | 리로드 |
| 활성화에 필요한 권한 | EDB Postgres Advanced Server 서비스 계정 |

감사 파일을 로테이션할 요일을 지정합니다. 유효한 값은 `sun`, `mon`, `tue`, `wed`, `thu`, `fri`, `sat`, `every`, `none`입니다. 로테이션을 비활성화하려면 값을 `none`으로 설정합니다. 파일을 매일 로테이션하려면 `edb_audit_rotation_day` 값을 `every`로 설정합니다. 특정 요일에 파일을 로테이션하려면 값을 원하는 요일로 설정합니다.

| 항목 | 값 |
|---|---|
| 매개변수 유형 | 정수 |
| 기본값 | `0MB` |
| 범위 | `0MB` ~ `5000MB` |
| 최소 적용 범위 | 클러스터 |
| 값 변경 적용 시점 | 리로드 |
| 활성화에 필요한 권한 | EDB Postgres Advanced Server 서비스 계정 |

파일 로테이션이 발생하는 파일 크기 임계값을 메가바이트 단위로 지정합니다. 이 파라미터가 주석 처리되거나 `0`으로 설정되면 크기 기반 파일 로테이션은 발생하지 않습니다.

## edb_audit_connect

| 항목 | 값 |
|---|---|
| 매개변수 유형 | 열거형 |
| 기본값 | `failed` |
| 범위 | `{none \| failed \| all}` |
| 최소 적용 범위 | 클러스터 |
| 값 변경 적용 시점 | 리로드 |
| 활성화에 필요한 권한 | EDB Postgres Advanced Server 서비스 계정 |

사용자의 데이터베이스 연결 시도에 대한 감사를 활성화합니다. 모든 연결 시도 감사를 비활성화하려면 `edb_audit_connect`를 `none`으로 설정합니다. 실패한 모든 연결 시도를 감사하려면 값을 `failed`로 설정합니다. 모든 연결 시도를 감사하려면 값을 `all`로 설정합니다.

## edb_audit_statement

| 항목 | 값 |
|---|---|
| 매개변수 유형 | 문자열 |
| 기본값 | `ddl, error` |
| 범위 | `{none \| ddl \| dml \| insert \| update \| delete \| truncate \| select \| error \| create \| drop \| alter \| grant \| revoke \| rollback \| set \| copy \| all \| { select \| update \| delete \| insert \| copy }@groupname} ...` |
| 최소 적용 범위 | 클러스터 |
| 값 변경 적용 시점 | 리로드 |
| 활성화에 필요한 권한 | EDB Postgres Advanced Server 서비스 계정 |

여러 범주의 SQL 문 및 특정 SQL 명령과 관련된 문에 대한 감사를 지정합니다.

- 오류를 로깅하려면 파라미터 값을 `error`로 설정합니다.
- `CREATE TABLE`, `ALTER TABLE`과 같은 모든 DDL 문을 감사하려면 파라미터 값을 `ddl`로 설정합니다.
- 특정 유형의 DDL 문을 감사하려면 파라미터 값에 해당 SQL 명령(`create`, `drop`, `alter`)을 포함할 수 있습니다. 또한 `create table`, `create view`, `drop role`처럼 명령 뒤에 객체 유형을 지정할 수 있습니다.
- `INSERT`, `UPDATE`, `DELETE`, `TRUNCATE`와 같은 모든 수정 문을 감사하려면 `edb_audit_statement`를 `dml`로 설정합니다.
- 특정 유형의 DML 문을 감사하려면 파라미터 값에 특정 SQL 명령 `insert`, `update`, `delete`, `truncate`를 포함할 수 있습니다. 해당 SQL 명령에 관한 문을 감사하려면 파라미터 값 `select`, `grant`, `revoke`, `rollback`을 포함합니다.
- `SET` 문을 감사하려면 파라미터 값 `SET`을 포함합니다.
- `COPY TO` 및 `COPY FROM` 문을 감사하려면 파라미터 값 `copy`를 포함합니다. 이 옵션은 `edb_audit_group`과 결합할 수도 있습니다. 예: `set edb_audit_statement ='copy@high_security';` (여기서 `high_security`는 edb 감사 그룹 이름).
- 모든 문을 감사하려면 값을 `all`로 설정합니다.
- 이 기능을 비활성화하려면 값을 `none`으로 설정합니다.

객체 단위(per-object) 감사는 지정한 테이블에 대해 `(@)` 포함 및 `(-)` 제외 그룹을 사용하여, 객체 권한이 허용하는 작업(`SELECT`, `UPDATE`, `DELETE`, `INSERT` 문 등)을 감사합니다. 특정 유형의 객체를 감사하려면 감사할 객체 그룹의 이름을 지정합니다. `edb_audit_statement` 파라미터에는 그룹 이름과 연관된 특정 SQL 명령(`select`, `update`, `delete`, `insert`, `copy`)을 `(@)` 포함, `(-)` 제외 기호와 함께 포함할 수 있습니다.

> **참고**
> 버전 17 이하에서는 `edb_audit_statement` 파라미터가 `'dml'`로 설정되면 `COPY FROM` 문이 감사됩니다.
> 버전 18 이상에서는 `edb_audit_statement` 파라미터가 `'copy'`로 설정되면 `COPY FROM` 및 `COPY TO` 문이 감사됩니다.

## edb_audit_tag

| 항목 | 값 |
|---|---|
| 매개변수 유형 | 문자열 |
| 기본값 | none |
| 최소 적용 범위 | 세션 |
| 값 변경 적용 시점 | 즉시 |
| 활성화에 필요한 권한 | 사용자 |

`edb_audit` 파라미터가 `csv`, `xml`, `json`으로 설정된 경우 감사 로그에 포함할 문자열 값을 지정합니다.

## edb_audit_destination

| 항목 | 값 |
|---|---|
| 매개변수 유형 | 열거형 |
| 기본값 | `file` |
| 범위 | `{file \| syslog}` |
| 최소 적용 범위 | 클러스터 |
| 값 변경 적용 시점 | 리로드 |
| 활성화에 필요한 권한 | EDB Postgres Advanced Server 서비스 계정 |

감사 로그 정보를 `edb_audit_directory` 파라미터로 지정된 디렉터리에 기록할지, 아니면 `syslog` 프로세스가 관리하는 디렉터리와 파일에 기록할지 지정합니다. `edb_audit_directory`로 지정된 디렉터리를 사용하려면 `file`로 설정합니다.

`syslog` 프로세스와 `/etc/syslog.conf` 파일에 구성된 위치를 사용하려면 `syslog`로 설정합니다. `syslog` 설정은 Linux 호스트에서 실행되는 EDB Postgres Advanced Server에서만 유효합니다. Windows 시스템에서는 지원되지 않습니다.

> **참고**
> 최근 Linux 버전에서는 `syslog`가 `rsyslog`로 대체되었으며, 구성 파일은 `/etc/rsyslog.conf`에 있습니다.

## edb_log_every_bulk_value

| 항목 | 값 |
|---|---|
| 매개변수 유형 | 불리언 |
| 기본값 | `false` |
| 범위 | `{true \| false}` |
| 최소 적용 범위 | 세션별 |
| 값 변경 적용 시점 | 즉시 |
| 활성화에 필요한 권한 | 슈퍼유저 |

대량(bulk) 처리는 그 결과 문을 EDB Postgres Advanced Server 로그 파일과 EDB 감사 로그 파일 양쪽에 모두 로깅합니다. 그러나 대량 처리에서 모든 문을 로깅하는 것은 비용이 큽니다. `edb_log_every_bulk_value` 구성 파라미터로 로깅되는 대량 처리 문을 제어할 수 있습니다.

이 파라미터가 `true`로 설정되면 대량 처리의 모든 문이 로깅됩니다. 대량 실행 중 `edb_log_every_bulk_value`가 `false`로 설정되면, 처리된 행 수와 함께 대량 처리당 한 번씩 로그 메시지가 기록됩니다. 소요 시간(duration)도 대량 처리당 한 번씩 출력됩니다.

> **참고**
> `edb_log_every_bulk_value`의 정식(canonical) 설명 페이지는 "보고 및 로깅 / 무엇을 로깅할지(Reporting and logging/what to log)"에 있으며, 감사 설정 페이지에서는 해당 페이지를 상호 참조합니다. 위 표와 설명은 정식 페이지의 원문을 옮긴 것입니다.

> **문서 정리 메모 (2026-08-03)**
> 공식 v18 "Auditing settings" 페이지는 위 12개 파라미터(`edb_audit` ~ `edb_log_every_bulk_value`)로 구성됩니다. 이전 목록에 13번째로 포함되어 있던 `edb_audit_nested_statements`는 공식 v18 감사 설정 페이지에 별도 항목으로 존재하지 않아 제외했습니다.
