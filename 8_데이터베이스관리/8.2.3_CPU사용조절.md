## 3. CPU 사용 조절 (CPU usage throttling)

> 원문: [cpu_usage_throttling](https://www.enterprisedb.com/docs/epas/latest/database_administration/10_edb_resource_manager/cpu_usage_throttling/)

EDB Resource Manager는 *CPU 조절(CPU throttling)*을 사용하여 그룹 내 모든 프로세스의 총 CPU 사용량을 `cpu_rate_limit` 파라미터로 지정한 한도 내로 유지합니다. 정의된 한도를 유지하기 위해 그룹 내 프로세스가 잠시 중단되어 짧은 시간 동안 절전(sleep) 모드에 놓일 수 있습니다. 이러한 중단이 언제 어떻게 발생하는지는 EDB Resource Manager가 사용하는 독점 알고리즘에 의해 정의됩니다.

리소스 그룹의 CPU 사용을 제어하려면 `cpu_rate_limit` 자원 유형 파라미터를 설정합니다.
- `cpu_rate_limit` 파라미터를, 그룹 내 모든 프로세스의 결합·동시 CPU 사용량이 초과해서는 안 되는, 벽시계 시간 대비 CPU 시간의 비율로 설정합니다. `cpu_rate_limit`에 할당되는 값은 일반적으로 1 이하입니다.
- 멀티코어 시스템에서는 `cpu_rate_limit`을 1보다 크게 설정하여 둘 이상의 CPU 코어에 적용할 수 있습니다. 예를 들어 `cpu_rate_limit`이 2.0으로 설정되면 두 CPU의 100%를 사용합니다. `cpu_rate_limit` 파라미터의 유효 범위는 0에서 1.67772e+07입니다. 0 설정은 리소스 그룹에 CPU rate limit가 설정되지 않았음을 의미합니다.
- 값에 100을 곱하면 `cpu_rate_limit`을 리소스 그룹의 CPU 사용 백분율로 해석할 수도 있습니다.

### 리소스 그룹의 CPU rate limit 설정
`ALTER RESOURCE GROUP` 명령과 `SET cpu_rate_limit` 절을 사용합니다. 이 예에서 CPU 사용 한도는 `resgrp_a` 50%, `resgrp_b` 40%, `resgrp_c` 30%로 설정됩니다. 즉 `resgrp_a`에 할당된 모든 프로세스의 결합 CPU 사용량은 약 50%로 유지됩니다. 마찬가지로 `resgrp_b`의 모든 프로세스는 약 40%로 유지되는 식입니다.
```sql
edb=# ALTER RESOURCE GROUP resgrp_a SET cpu_rate_limit TO .5;
ALTER RESOURCE GROUP
edb=# ALTER RESOURCE GROUP resgrp_b SET cpu_rate_limit TO .4;
ALTER RESOURCE GROUP
edb=# ALTER RESOURCE GROUP resgrp_c SET cpu_rate_limit TO .3;
ALTER RESOURCE GROUP
```
```sql
edb=# SELECT rgrpname, rgrpcpuratelimit FROM edb_resource_group;
```
```text
 rgrpname | rgrpcpuratelimit
----------+------------------
 resgrp_a |              0.5
 resgrp_b |              0.4
 resgrp_c |              0.3
(3 rows)
```
리소스 그룹의 `cpu_rate_limit`을 변경하면 그룹에 새로 할당되는 프로세스에 영향을 주며, 그룹의 구성원인 현재 실행 중인 프로세스에도 즉시 영향을 줍니다. 즉 `cpu_rate_limit`이 .5에서 .3으로 변경되면 그룹 내 현재 실행 중인 프로세스는 총 그룹 CPU 사용량이 50%가 아닌 약 30%가 되도록 하향 조절됩니다.

리소스 그룹에 대한 CPU rate limit 설정의 효과를 보이기 위해, 다음 `psql` 명령줄 예제는 `SELECT 20000!` 쿼리로 수행되는 20000 팩토리얼(20000 * 19999 * 19998 …의 곱)이라는 CPU 집약적 계산을 사용합니다. 앞 쿼리에 표시된 CPU rate limit 설정을 가진 리소스 그룹을 사용합니다.

> 아래 예제의 `top` 명령 출력은 특정 시점의 스냅샷이며, 결론만 요약하면: 리소스 그룹에 속한 프로세스의 `%CPU`는 해당 그룹의 한도 근처(예: `resgrp_b` → 약 39.9%)로 유지되고, 그룹에서 제거하면 훨씬 높아집니다(약 93.6%). 여러 프로세스가 한 그룹에 있으면 각 프로세스 `%CPU`의 합이 그룹 한도(약 40%)에 근접하며, 여러 그룹이 동시에 돌면 각 그룹의 합이 각자 한도(예: 40%+30%=약 70%)에 근접합니다. (원문에는 단일 프로세스/단일 그룹, 다중 프로세스/단일 그룹, 다중 프로세스/다중 그룹 각각에 대한 `top` 스냅샷과 0.5초 간격 합산 스크립트 출력이 포함되어 있으며, 명령·출력은 아래 대표 예로 보존합니다.)

단일 프로세스/단일 그룹 예:
```sql
edb=# SET edb_resource_group TO resgrp_b;
SET
edb=# SELECT 20000!;
```
```shell
$ while [[ 1 -eq 1 ]]; do  top -d0.5 -b -n2 | grep edb-postgres | awk '{ SUM += $9} END { print SUM / 2 }'; done
37.2
39.1
38.9
...
```
그룹에서 제거 후 다시 계산하면 `%CPU`가 약 93.6으로 크게 높아집니다(그룹에 속했을 때 39.9와 대비).
