# effective_cache_size — EPAS 18 데이터베이스 관리

> 원문: [EPAS v18 — Database administration › Configuration parameters › Top performance-related parameters › effective_cache_size](https://www.enterprisedb.com/docs/epas/latest/database_administration/01_configuration_parameters/03_configuration_parameters_by_functionality/01_top_performance_related_parameters/13_effective_cache_size/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·코드·파라미터 이름은 원문 그대로 보존했습니다.

**파라미터 타입 (Parameter type):** Integer

**기본값 (Default value):** 4GB

**범위 (Range):** 8kB to 17179869176kB

**효력의 최소 범위 (Minimum scope of effect):** Per session

**값 변경이 적용되는 시점 (When value changes take effect):** Immediate

**활성화에 필요한 권한 (Required authorization to activate):** Session user

단일 쿼리에서 사용할 수 있는 디스크 캐시의 유효 크기에 대한 플래너의 가정을 설정합니다. 이 가정은 인덱스 사용 비용의 추정에 반영됩니다. 값이 높을수록 인덱스 스캔이 사용될 가능성이 커집니다. 값이 낮을수록 순차 스캔이 사용될 가능성이 커집니다.

이 파라미터를 설정할 때는 EDB Postgres Advanced Server의 shared buffers와 EDB Postgres Advanced Server 데이터 파일에 사용되는 커널 디스크 캐시의 일부를 모두 고려하십시오. 또한 서로 다른 테이블에 대한 예상 동시 쿼리 수를 고려하십시오. 그것들이 사용 가능한 공간을 공유해야 하기 때문입니다.

이 파라미터는 EDB Postgres Advanced Server가 할당하는 공유 메모리의 크기에 영향을 주지 않으며, 커널 디스크 캐시를 예약하지도 않습니다. 오직 추정 용도로만 사용됩니다.

이 파라미터가 너무 낮게 설정되면, 플래너가 인덱스 사용이 도움이 되는 경우에도 인덱스를 사용하지 않기로 결정할 수 있습니다. `effective_cache_size`를 물리 메모리의 50%로 설정하는 것은 정상적이고 보수적인 설정입니다. 더 공격적인 설정은 물리 메모리의 약 75%입니다.

### 동적 튜닝 참고

위 기본값은 해당 파라미터가 명시적으로 설정되지 않고 `edb_dynatune`의 영향을 받지 않을 때 적용되는 내부 기본값입니다. `edb_dynatune`이 활성화된 환경에서는 서버의 메모리, CPU 자원 및 `edb_dynatune_profile`에 따라 실제 적용값이 달라질 수 있습니다. 명시적으로 설정된 값은 동적 튜닝으로 계산된 값을 재정의합니다.

`edb_dynatune`은 다음 파라미터를 자동 조정할 수 있습니다.

- `shared_buffers`
- `work_mem`
- `maintenance_work_mem`
- `effective_cache_size`
- `random_page_cost`
- `max_connections`
