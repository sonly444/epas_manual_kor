# wal_buffers — EPAS 18 데이터베이스 관리

> 원문: [EPAS v18 — Database administration › Configuration parameters › Top performance-related parameters › wal_buffers](https://www.enterprisedb.com/docs/epas/latest/database_administration/01_configuration_parameters/03_configuration_parameters_by_functionality/01_top_performance_related_parameters/04_wal_buffers/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·코드·파라미터 이름은 원문 그대로 보존했습니다.

**파라미터 타입 (Parameter type):** Integer

**기본값 (Default value):** -1(자동설정)

**범위 (Range):** -1

**효력의 최소 범위 (Minimum scope of effect):** Cluster

**값 변경이 적용되는 시점 (When value changes take effect):** Restart

**활성화에 필요한 권한 (Required authorization to activate):** EDB Postgres Advanced Server service account

WAL 데이터를 위해 공유 메모리에서 사용되는 메모리의 양입니다. 데이터는 매 트랜잭션 커밋 시 디스크에 기록되므로, 이 설정은 하나의 일반적인 트랜잭션이 생성하는 WAL 데이터 양을 담을 수 있을 만큼만 크면 됩니다.

이 파라미터를 증가시키면 EDB Postgres Advanced Server가 운영 체제의 기본 구성이 허용하는 것보다 더 많은 System V 공유 메모리를 요청하게 될 수 있습니다. 해당 파라미터를 조정하는 방법에 대한 정보는 PostgreSQL 코어 문서의 [Shared Memory and Semaphores](https://www.postgresql.org/docs/15/kernel-resources.html#SYSVIPC)를 참조하십시오.

이렇게 매우 작은 설정이 항상 문제를 일으키는 것은 아니지만, 일부 상황에서는 추가적인 `fsync` 호출을 유발하고 전체 시스템 처리량을 저하시킬 수 있습니다. 이 값을 약 1MB로 증가시키면 이 문제를 해결할 수 있습니다. 매우 바쁜 시스템에서는 최대 약 16MB까지 더 높은 값이 필요할 수도 있습니다. `shared_buffers`와 마찬가지로, 이 파라미터는 EDB Postgres Advanced Server의 초기 공유 메모리 할당량을 증가시킵니다. 이 값을 증가시켜 EDB Postgres Advanced Server 시작 실패가 발생하면, 운영 체제 한도를 증가시키십시오.

### 동적 튜닝 참고

위 기본값은 해당 파라미터가 명시적으로 설정되지 않고 `edb_dynatune`의 영향을 받지 않을 때 적용되는 내부 기본값입니다. `edb_dynatune`이 활성화된 환경에서는 서버의 메모리, CPU 자원 및 `edb_dynatune_profile`에 따라 실제 적용값이 달라질 수 있습니다. 명시적으로 설정된 값은 동적 튜닝으로 계산된 값을 재정의합니다.

`edb_dynatune`은 다음 파라미터를 자동 조정할 수 있습니다.

- `shared_buffers`
- `work_mem`
- `maintenance_work_mem`
- `effective_cache_size`
- `random_page_cost`
- `max_connections`
