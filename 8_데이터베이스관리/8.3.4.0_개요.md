## 4. 컨트롤 파일 작성 (Building the control file)

> 원문: [building_the_control_file](https://www.enterprisedb.com/docs/epas/latest/database_administration/02_edb_loader/building_the_control_file/)

EDB*Loader를 호출할 때는 컨트롤 파일 이름을 제공해야 합니다. 이 파일에는 EDB*Loader가 입력 데이터 파일로부터 테이블을 로드하는 데 사용하는 지시가 담깁니다.

### 컨트롤 파일의 내용
컨트롤 파일에는 다음과 같은 정보가 포함됩니다.
- 로드할 데이터를 담은 입력 데이터 파일 이름.
- 데이터 파일에서 로드할 테이블 이름.
- 테이블의 컬럼 이름과 데이터 파일에서의 해당 필드 위치.
- 데이터 파일이 필드 구분에 구분자 문자열을 사용하는지, 아니면 필드가 고정 컬럼 위치를 차지하는지 지정.
- 특정 테이블에 로드할 레코드를 데이터 파일에서 선택하는 선택적 선택 기준.
- 잘못 서식된 레코드를 수집하는 파일 이름.
- 어떤 테이블의 선택 기준도 만족하지 않는 레코드를 수집하는 discard 파일 이름.

### 컨트롤 파일 구문
```
[ OPTIONS (<param=value> [, <param=value> ] ...) ]
LOAD DATA
  [ CHARACTERSET <charset> ]
  [ INFILE '{ <data_file> | <stdin> }' ]
  [ BADFILE '<bad_file>' ]
  [ DISCARDFILE '<discard_file>' ]
  [ { DISCARDMAX | DISCARDS } <max_discard_recs> ]
[ INSERT | APPEND | REPLACE | TRUNCATE ]
[ PRESERVE BLANKS ]
{ INTO TABLE <target_table>
  [ WHEN <field_condition> [ AND <field_condition> ] ...]
  [ FIELDS TERMINATED BY '<termstring>'
    [ OPTIONALLY ENCLOSED BY '<enclstring>' ] ]
  [ RECORDS DELIMITED BY '<delimstring>' ]
  [ TRAILING NULLCOLS ]
   (<field_def> [, <field_def> ] ...)
} ...
```
여기서 `field_def`는 지정된 `data_file`의 필드를 정의합니다. 필드는 `target_table`의 `column_name`에 삽입할 데이터의 위치·데이터 형식·값을 기술합니다. `field_def`의 구문:
```
<column_name> {
  CONSTANT <val> |
  FILLER [ POSITION (<start:end>) ] [ <fieldtype> ] |
  BOUNDFILLER [ POSITION (<start:end>) ] [ <fieldtype> ] |
  [ POSITION (<start:end>) ] [ <fieldtype> ]
  [ NULLIF <field_condition> [ AND <field_condition> ] ...]
  [ PRESERVE BLANKS ] [ "<expr>" ]
}
```
`fieldtype`은 다음 중 하나:
```
CHAR [(<length>)] | DATE [(<length>)] | TIMESTAMP [(<length>)] [ "<datemask>" ] |
INTEGER EXTERNAL [(<length>)] |
FLOAT EXTERNAL [(<length>)] | DECIMAL EXTERNAL [(<length>)] |
ZONED EXTERNAL [(<length>)] | ZONED [(<precision> [,<scale>])]
```

### 변수 설정
`data_file`, `bad_file`, `discard_file` 지정에는 전체 디렉터리 경로 또는 상대 디렉터리 경로를 파일 이름과 함께 포함할 수 있습니다. 파일 이름만 또는 상대 경로와 함께 지정하면, `data_file`의 경우 `edbldr`를 호출한 현재 작업 디렉터리를 기준으로 파일이 존재한다고 가정합니다. `bad_file`·`discard_file`의 경우 해당 위치에 생성됩니다.

컨트롤 파일에서 디렉터리 경로나 파일 이름을 참조할 때 환경 변수 참조를 포함할 수 있습니다. 환경 변수 참조 형식은 Windows와 Linux에서 다릅니다.
- Linux: `$ENV_VARIABLE` 또는 `${ENV_VARIABLE}`.
- Windows: `%ENV_VARIABLE%`.

`EDBLDR_ENV_STYLE` 환경 변수를 설정하면, EDB*Loader가 있는 운영체제와 무관하게 환경 변수 참조를 Windows 스타일 또는 Linux 스타일로 해석합니다. 이를 통해 이식 가능한(portable) 컨트롤 파일을 만들 수 있습니다.
- Windows 시스템: `EDBLDR_ENV_STYLE`을 `linux` 또는 `unix`로 설정하면 컨트롤 파일에서 Linux 스타일 참조를 인식.
- Linux 시스템: `EDBLDR_ENV_STYLE`을 `windows`로 설정하면 Windows 스타일 참조를 인식.

운영체제 계정 enterprisedb는 `data_file`이 지정한 디렉터리·파일에 대한 읽기 권한이 있어야 하고, `bad_file`·`discard_file`이 기록되는 디렉터리에 대한 쓰기 권한이 있어야 합니다.

> **참고**: `data_file`, `bad_file`, `discard_file`의 파일 이름은 각각 확장자 `.dat`, `.bad`, `.dsc`를 가져야 합니다. 제공된 파일 이름에 확장자가 없으면 EDB*Loader는 실제 파일 이름에 적절한 확장자가 포함되어 있다고 가정합니다.

### 예제 시나리오
EDB*Loader 세션에서 데이터 서식 오류가 발생하고 `BADFILE` 절이 지정되지 않았으며 `edbldr` 호출 시 명령줄에 `BAD` 파라미터도 주어지지 않은 경우, `edbldr`를 호출한 디렉터리에 `control_file_base.bad` 이름의 bad 파일이 생성됩니다(`control_file_base`는 세션에 사용된 컨트롤 파일의 기본 이름).

다음 조건이 모두 참이면 EDB*Loader 세션에서 discard 레코드가 발생해도 discard 파일이 생성되지 않습니다.
- 컨트롤 파일에 `DISCARDFILE` 절이 없음.
- 명령줄에 `DISCARD` 파라미터가 없음.
- 컨트롤 파일에 `DISCARDMAX` 절이 없음.
- 컨트롤 파일에 `DISCARDS` 절이 없음.
- 명령줄에 `DISCARDMAX` 파라미터가 없음.

`DISCARDFILE` 절과 `DISCARD` 파라미터로 discard 파일 이름을 명시적으로 지정하지 않았지만 `DISCARDMAX` 또는 `DISCARDS`를 지정한 경우, 세션은 데이터 파일 이름에 `.dsc` 확장자를 붙인 discard 파일을 생성합니다.

> **참고**: 키워드 `DISCARD`와 `DISCARDS`는 다릅니다. `DISCARD`는 discard 파일 이름을 지정하는 EDB*Loader 명령줄 파라미터입니다. `DISCARDS`는 컨트롤 파일에만 나타날 수 있는 `LOAD DATA` 지시자의 절입니다. `DISCARDS`와 `DISCARDMAX`는 세션을 종료하기 전 허용되는 최대 discard 레코드 수를 지정하는 동일 기능을 제공합니다. `DISCARDS` 또는 `DISCARDMAX` 설정 초과로 세션이 종료되기 전에 데이터베이스에 로드된 레코드는 데이터베이스에 유지되며 롤백되지 않습니다.

`INSERT`, `APPEND`, `REPLACE`, `TRUNCATE` 중 하나를 지정하여 대상 테이블에 행을 추가하는 기본 동작을 정합니다. 기본 동작은 `INSERT`입니다.

`FIELDS TERMINATED BY` 절을 지정하면 어떤 `field_def`에도 `POSITION (start:end)` 절을 지정할 수 없습니다. 반대로 `FIELDS TERMINATED BY` 절을 지정하지 않으면 모든 `field_def`에 `POSITION (start:end)` 절, `fieldtype(length)` 절 또는 `CONSTANT` 절이 있어야 합니다.

각 절에 사용 가능한 파라미터의 전체 설명은 참조(Reference) 섹션의 "EDB*Loader 컨트롤 파일 파라미터"를 참조하십시오.
