## A. 파라미터 설정 방법 (Setting configuration parameters)

> 원문: [01_setting_new_parameters](https://www.enterprisedb.com/docs/epas/latest/database_administration/01_configuration_parameters/01_setting_new_parameters/)

각 구성 파라미터는 이름/값 쌍(name/value pair)으로 설정합니다. 파라미터 이름은 대소문자를 구분하지 않습니다. 파라미터 이름은 일반적으로 선택적 등호(`=`)로 값과 구분됩니다.

다음 예는 `postgresql.conf` 파일의 일부 구성 파라미터 설정을 보여줍니다.

```ini
# This is a comment
log_connections = yes
log_destination = 'syslog'
search_path = '"$user", public'
shared_buffers = 128MB
```

### 파라미터 값의 유형 (Types of parameter values)

파라미터 값은 다섯 가지 유형 중 하나로 지정됩니다.

- **Boolean** — 허용 값은 `on`, `off`, `true`, `false`, `yes`, `no`, `1`, `0` 또는 이들의 모호하지 않은 접두사입니다.
- **Integer** — 소수부가 없는 숫자.
- **Floating point** — 소수점으로 구분된 선택적 소수부를 갖는 숫자.
- **String** — 값이 단순 식별자나 숫자가 아닌 경우(즉 공백이나 기타 구두점 같은 특수 문자를 포함하는 경우) 작은따옴표로 감싼 텍스트 값.
- **Enum** — 특정 문자열 값 집합. 허용 값은 시스템 뷰 `pg_settings.enumvals`에서 확인할 수 있습니다. Enum 값은 대소문자를 구분하지 않습니다.

일부 설정은 메모리 또는 시간 값을 지정합니다. 이들 각각은 암묵적 단위(implicit unit)를 가지며, 이는 킬로바이트, 블록(일반적으로 8킬로바이트), 밀리초, 초 또는 분입니다. 기본 단위는 시스템 뷰 `pg_settings.unit`을 참조하여 확인할 수 있습니다. 다른 단위를 명시적으로 지정할 수도 있습니다.

유효한 메모리 단위:

- `kB` (킬로바이트)
- `MB` (메가바이트)
- `GB` (기가바이트)

유효한 시간 단위:

- `ms` (밀리초)
- `s` (초)
- `min` (분)
- `h` (시간)
- `d` (일)

메모리 단위의 곱셈 인자(multiplier)는 1024입니다.

### 구성 파라미터 설정 지정 (Specifying configuration parameter settings)

여러 파라미터 설정은 EDB Postgres Advanced Server 데이터베이스 제품이 빌드될 때 설정됩니다. 이들은 읽기 전용(read-only) 파라미터이며 값을 변경할 수 없습니다. 또한 몇몇 파라미터는 데이터베이스가 생성될 때 각 데이터베이스에 대해 영구적으로 설정됩니다. 이 파라미터들은 읽기 전용이며 이후 해당 데이터베이스에 대해 변경할 수 없습니다. 그러나 구성 파라미터 설정을 지정하는 방법에는 여러 가지가 있습니다.

- 전체 데이터베이스 클러스터에 걸친 거의 모든 구성 가능 파라미터의 초기 설정은 `postgresql.conf` 구성 파일에 나열됩니다. 이 설정들은 데이터베이스 서버 시작 또는 재시작 시 적용됩니다. 이 초기 파라미터 설정 중 일부는 재정의할 수 있습니다. 모든 구성 파라미터는 명시적으로 재정의하지 않는 한 적용되는 내장 기본 설정을 가집니다.

- `postgresql.conf` 파일의 구성 파라미터는 동일 파라미터가 `postgresql.auto.conf` 파일에 포함될 때 재정의됩니다. `postgresql.auto.conf` 파일의 구성 파라미터를 관리하려면 `ALTER SYSTEM` 명령을 사용하십시오.

- 데이터베이스 서버가 실행 중일 때 구성 파일의 파라미터 설정을 수정할 수 있습니다. 그런 다음 구성 파일이 다시 로드되면(즉 SIGHUP 신호가 발생하면), 특정 파라미터 유형의 경우 변경된 파라미터 설정이 즉시 적용됩니다. 이러한 파라미터 유형 중 일부는 다시 로드 직후 현재 실행 중인 세션에서 새 설정을 사용할 수 있습니다. 다른 일부는 새 설정을 사용하려면 새 세션을 시작해야 합니다. 또 다른 일부는 데이터베이스 서버를 중지하고 재시작할 때까지 수정된 설정이 적용되지 않습니다. 구성 파일을 다시 로드하는 방법은 PostgreSQL 코어 문서를 참조하십시오.

- SQL 명령 `ALTER DATABASE`, `ALTER ROLE` 또는 `ALTER ROLE IN DATABASE`를 사용하여 특정 파라미터 설정을 수정할 수 있습니다. 수정된 파라미터 설정은 명령 실행 후 새 세션에 적용됩니다. `ALTER DATABASE`는 지정된 데이터베이스에 연결하는 새 세션에 영향을 줍니다. `ALTER ROLE`은 지정된 역할이 시작한 새 세션에 영향을 줍니다. `ALTER ROLE IN DATABASE`는 지정된 역할이 지정된 데이터베이스에 연결하여 시작한 새 세션에 영향을 줍니다. 이 SQL 명령으로 설정한 파라미터 설정은 데이터베이스 서버 재시작에 걸쳐 무기한 유지되며, 다른 방법으로 설정된 설정을 재정의합니다. `ALTER DATABASE`, `ALTER ROLE` 또는 `ALTER ROLE IN DATABASE` 명령으로 설정한 파라미터 설정은 다음 방법으로 변경할 수 있습니다.

  * 이 명령들을 다른 파라미터 값으로 다시 실행.

  * 이 명령들을 `SET parameter TO DEFAULT` 절 또는 `RESET parameter` 절을 사용하여 실행. 이 절들은 파라미터를 다른 방법으로 설정된 값으로 되돌립니다. 이 SQL 명령들의 구문은 PostgreSQL 코어 문서를 참조하십시오.

- 개별 세션 동안에는 `PGOPTIONS` 환경 변수를 사용하거나 EDB-PSQL 또는 PSQL 명령줄 프로그램에서 `SET` 명령을 사용하여 특정 파라미터 설정을 변경할 수 있습니다. 이 방법으로 설정한 파라미터 설정은 앞서 논의한 어떤 방법으로 설정한 설정보다 우선하지만, 해당 세션 동안에만 적용됩니다.

### postgresql.conf 파일 수정 (Modifying the postgresql.conf file)

`postgresql.conf` 파일의 구성 파라미터는 감사, 인증, 암호화 및 기타 동작에 관한 서버 동작을 지정합니다. Linux 및 Windows 호스트에서 `postgresql.conf` 파일은 EDB Postgres Advanced Server 설치 하위의 `data` 디렉터리에 있습니다.

파운드 기호(#)가 앞에 붙은 파라미터는 기본값으로 설정됩니다. 파라미터 값을 변경하려면 파운드 기호를 제거하고 새 값을 입력하십시오. 파라미터를 설정하거나 변경한 후에는 새 파라미터 값이 적용되도록 서버를 `reload` 또는 `restart` 해야 합니다.

`postgresql.conf` 파일에서 일부 파라미터에는 `change requires restart`(변경하려면 재시작 필요)를 나타내는 주석이 있습니다. 서버 재시작이 필요한 파라미터 목록을 보려면 psql 명령줄에서 다음 쿼리를 사용하십시오.

```sql
SELECT name FROM pg_settings WHERE context = 'postmaster';
```

### pg_hba.conf 파일 수정 (Modifying the pg_hba.conf file)

적절한 인증 방법은 보호와 보안을 제공합니다. `pg_hba.conf` 파일의 항목은 서버가 연결 클라이언트에 대해 사용하는 인증 방법을 지정합니다. 서버에 연결하기 전에 `pg_hba.conf` 파일에 지정된 인증 속성을 수정해야 할 수 있습니다.

클러스터를 생성하기 위해 initdb 유틸리티를 호출하면, 유틸리티는 해당 클러스터에 대해 연결 클라이언트에게 요구되는 인증 유형을 지정하는 `pg_hba.conf` 파일을 생성합니다. 이 파일을 수정할 수 있습니다. `pg_hba.conf` 파일의 인증 설정을 수정한 후에는 서버를 재시작하여 변경 사항을 적용하십시오. 인증 및 `pg_hba.conf` 파일 수정에 대한 자세한 내용은 PostgreSQL 코어 문서를 참조하십시오.

> **참고**: OAUTH 인증 방법은 Windows 플랫폼에서 지원되지 않습니다.

서버가 연결 요청을 받으면, 데이터베이스 연결을 허용하기 전에 제공된 자격 증명을 `pg_hba.conf` 파일의 인증 설정과 대조하여 검증합니다. 서버 연결 인증에 사용된 `pg_hba.conf` 파일 항목을 로그로 남기려면 `postgresql.conf` 파일에서 `log_connections` 파라미터를 `ON`으로 설정하십시오.

레코드는 연결 유형, 데이터베이스 이름, 사용자 이름, 클라이언트 IP 주소, 그리고 `pg_hba.conf` 파일에서 이 파라미터들이 일치할 때 연결을 승인하는 인증 방법을 지정합니다. 서버 연결이 승인되면 일치한 줄 번호와 `pg_hba.conf` 파일의 인증 레코드를 볼 수 있습니다.

다음 예는 성공적인 인증 후 유효한 `pg_hba.conf` 항목에 대한 로그 상세를 보여줍니다.

```shell
2020-05-08 10:42:17 IST LOG:  connection received: host=[local]
2020-05-08 10:42:17 IST LOG:  connection authorized: user=u1 database=edb
application_name=psql
2020-05-08 10:42:17 IST DETAIL:  Connection matched pg_hba.conf line 84:
"local   all             all               md5"
```

### LDAP 비밀번호 난독화 (Obfuscating the LDAP password)

인증에 LDAP를 사용할 때, LDAP 서버 연결에 사용되는 LDAP 비밀번호(ldapbindpasswd 비밀번호)는 `pg_hba.conf` 파일에 저장됩니다. 비밀번호를 난독화된 형태로 저장한 뒤, 사용자가 제공하는 로드 가능 모듈(loadable module)로 역난독화(de-obfuscate)할 수 있습니다. 로드 가능 모듈은 역난독화를 수행하는 훅 함수(hook function)를 제공합니다.

예를 들어, 이 C 로드 가능 모듈은 `rot13_passphrase`를 훅 함수로 사용하여 `pg_hba.conf` 파일의 비밀번호를 역난독화합니다.

```c
#include "postgres.h"

#include <float.h>
#include <stdio.h>

#include "libpq/libpq.h"
#include "libpq/libpq-be.h"
#include "libpq/auth.h"
#include "utils/guc.h"

PG_MODULE_MAGIC;

void		_PG_init(void);
void		_PG_fini(void);

/* hook function */
static char*	rot13_passphrase(char *password);

/*
* Module load callback
*/
void
_PG_init(void)
{
	   ldap_password_hook = rot13_passphrase;
}

void
_PG_fini(void)
{
	  /* do  nothing yet */
}

static char*
rot13_passphrase(char *pw)
{
	  size_t size = strlen(pw) + 1;

	  char* new_pw = (char*) palloc(size);
	  strlcpy(new_pw, pw, size);
	  for (char *p = new_pw; *p; p++)
	  {
		 char		c = *p;

		 if ((c >= 'a' && c <= 'm') || (c >= 'A' && c <= 'M'))
			 *p = c + 13;
		 else if ((c >= 'n' && c <= 'z') || (c >= 'N' && c <= 'Z'))
			 *p = c - 13;
	  }

	 return new_pw;
}
```

`postgresql.conf` 파일의 `shared_preload_libraries` 파라미터에 모듈을 추가하십시오. 예:

```ini
shared_preload_libraries = '$libdir/ldap_password_func'
```

이 파라미터의 변경 사항을 로드하려면 서버를 재시작하십시오.
