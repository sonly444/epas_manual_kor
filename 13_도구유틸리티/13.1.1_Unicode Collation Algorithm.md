# Unicode Collation Algorithm (UCA) — EPAS 18 Tools

> 원문: [EPAS v18 — Tools › Application programmer tools › Unicode Collation Algorithm](https://www.enterprisedb.com/docs/epas/latest/tools_utilities_and_components/application_developer_tools/06_unicode_collation_algorithm/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·속성·코드·출력은 원문 그대로 보존했습니다.

Unicode Collation Algorithm(UCA)은 유니코드 데이터의 콜레이션(collation)과 비교(comparison)를 사용자 정의 가능한 방식으로 정의하는 명세(*Unicode Technical Report #10*)입니다. *콜레이션*은 `SELECT … ORDER BY` 절처럼 데이터가 정렬되는 방식을, *비교*는 미만·초과·같음 연산자를 사용하는 범위 검색에 관련됩니다.

## 이점 (Benefits)
사용자 정의 가능성이 중요한 이유:
- 유니코드는 여러 언어를 지원합니다. 여러 언어에 공통인 문자가 언어에 따라 다른 순서로 콜레이션될 수 있습니다.
- 악센트나 움라우트처럼 특정 언어에서 문자와 함께 나타나는 문자는 언어에 따라 기대되는 콜레이션에 영향을 줍니다.
- 일부 언어에서는 여러 연속 문자의 조합이 콜레이션 순서상 단일 문자로 취급됩니다.
- 대소문자에 따른 콜레이션 선호가 있을 수 있습니다(예: 소문자가 대문자보다 먼저, 또는 그 반대).
- 밑줄·하이픈·공백 같은 구두점을 콜레이션 순서에 포함할지 무시할지 선호가 있을 수 있습니다.

유니코드가 지원하는 많은 언어의 이런 변형을 고려하여 콜레이션 순서 결정 기준을 선택하는 방법이 필요하며, 이를 UCA가 정의합니다.

> **참고**: ICU 콜레이션(UCA 구현)을 사용하는 또 다른 이점은 성능입니다. B-tree 인덱스 생성을 포함한 정렬 작업이 비-ICU 콜레이션보다 절반 이하의 시간에 완료될 수 있습니다. 정확한 성능 향상은 OS 버전·텍스트 데이터 언어 등에 따라 다릅니다.

## 기본 UCA 개념
UCA 공식 정보는 [Unicode Technical Report #10](http://www.unicode.org/reports/tr10/)에, 콜레이션 개념 설명은 [ICU 웹사이트](http://userguide.icu-project.org/collation/concepts)에 있습니다.

UCA의 기본 개념은 다단계 비교(multilevel comparison)입니다. 여러 레벨(level 1~5)이 정의되며 각 레벨은 비교 유형을 정의합니다. 문자열은 먼저 기본 레벨(level 1)로 비교됩니다. 기본 레벨로 순서가 정해지면 알고리즘 종료, 아니면 보조 레벨(level 2) 적용, 그래도 안 되면 tertiary 레벨 적용… 순으로 진행하며, 최종적으로 tie-breaking 레벨로 순서를 결정합니다.

- **Level 1 – 기본 문자(base characters)**: 글자·숫자 같은 기본 문자 순서가 차이를 결정(예: `A < B`).
- **Level 2 – 악센트(accents)**: 기본 레벨 차이가 없으면 악센트 등의 유무가 순서 결정(예: `a < á`).
- **Level 3 – 대소문자(case)**: 1·2 레벨 차이가 없으면 대소문자 차이가 순서 결정(예: `a < A`).
- **Level 4 – 구두점(punctuation)**: 1·2·3 레벨 차이가 없으면 공백·제어 문자·구두점의 유무가 순서 결정(예: `-A < A`).
- **Level 5 – 동일 레벨(tie breaking)**: 1~4 레벨 차이가 없으면 코드 포인트 값 같은 다른 차이가 순서 결정.

## ICU (International Components for Unicode)
UCA는 ICU가 제공하는 오픈소스 소프트웨어(C/C++·Java 라이브러리)로 구현됩니다. EDB Postgres Advanced Server에서 ICU 컴포넌트를 호출해 콜레이션을 생성하면 그 결과를 *ICU 콜레이션*이라 합니다.

### 로케일 콜레이션 (Locale collations)
로케일용 콜레이션 생성 시 보통 해당 로케일에 대한 사전 정의된 *ICU short form* 이름이 제공됩니다. ICU short form은 콜레이션 속성(콜레이션의 성질)을 지정하는 방법입니다. 로케일용 ICU short form은 해당 로케일에 통상 쓰이는 콜레이션 속성 설정을 담고 있어, 전체 속성 목록을 지정할 필요를 없애 콜레이션 생성을 단순화합니다.

시스템 카탈로그 `pg_catalog.pg_icu_collate_names`에 로케일용 ICU short form 이름 목록이 있으며, `icu_short_form` 컬럼에 표시됩니다.
```sql
edb=# SELECT icu_short_form, valid_locale FROM pg_icu_collate_names ORDER BY
valid_locale;
```
```text
 icu_short_form | valid_locale
----------------+--------------
 LAF            | af
 LAR            | ar
 ...
 LFA_RAF        | fa_AF
    .
    .
    .
```
필요하면 특정 로케일의 ICU short form 기본 특성을 콜레이션 속성으로 재정의할 수 있습니다.

### 콜레이션 속성 (Collation attributes)
ICU 콜레이션 생성 시 원하는 특성을 지정해야 합니다. 보통 로케일용 ICU short form으로 지정하지만, 더 구체적으로는 *콜레이션 속성*으로 지정할 수 있습니다. 콜레이션 속성은 텍스트 문자열의 콜레이션 순서를 정하기 위해 문자를 비교하는 규칙을 정의합니다. 정확한 의미·사용법은 ICU 웹사이트의 "Collator Naming Scheme"을 참조하십시오.

각 콜레이션 속성은 대문자 하나로 표현됩니다. 공통 코드: **X**(속성 끔), **O**(속성 켬), **D**(기본값).

- **A – Alternate (N, S, D)**: 공백·구두점·기호 같은 *variable* 문자 처리. non-ignorable(N)이면 variable 문자 차이를 글자 차이와 동등하게 취급, shifted(S)이면 variable 문자 차이를 부차적으로 취급(기본 문자 비교 시 무시).
- **C – Case first (X, L, U, D)**: 소문자가 대문자보다 먼저(L) 정렬할지, 대문자가 먼저(U)일지 제어. 소문자 우선(L)을 원하면 보통 off(X) 지정.
- **E – Case level (X, O, D)**: Strength 속성과 함께 설정. 악센트는 무시하되 대소문자는 무시하지 않을 때 사용.
- **F – French collation (X, O, D)**: on이면 보조 차이(악센트 유무)를 프랑스 캐나다 로케일처럼 문자열 뒤에서부터 정렬.
- **H – Hiragana quaternary (X, O, D)**: 일본어 JIS X 4061 콜레이션 호환을 위해 히라가나·가타카나 구분 레벨 추가.
- **N – Normalization checking (X, O, D)**: 비교를 위한 텍스트 정규화 여부 제어. 아랍어·고대 그리스어·히브리어·힌디어·태국어·베트남어 등은 켬(O)으로 설정.
- **S – Strength (1, 2, 3, 4, I, D)**: 비교에 사용하는 최대 콜레이션 레벨. I는 동일 강도(레벨 5).
- **T – Variable top (16진수)**: Alternate가 non-ignorable(N)이 아닐 때만 적용. 무시할 최고 문자 시퀀스를 지정. 예: 공백은 무시하되 보이는 variable 문자는 포함하려면 Variable Top을 0020으로, Alternate를 S, Strength를 3으로 설정(공백=16진수 0020).

속성/값 쌍은 속성 문자와 값을 연결하고 각 쌍을 밑줄로 잇습니다: `AN_CX_EX_FX_HX_NO_S3`. 로케일의 ICU short form 이름과 함께 지정하여 기본 속성을 재정의할 수 있습니다. 예: `AN_CX_EX_LROOT_NO_S3` — Alternate(A)=non-ignorable(N), Case First(C)=off(X), Case Level(E)=off(X), Normalization(N)=on(O), Strength(S)=tertiary(3), `LROOT`는 수정 대상 ICU short form.

## 콜레이션 사용 (Using a collation)
새로 정의한 ICU 콜레이션은 SQL 명령에서 `COLLATION "collation_name"` 절을 쓸 수 있는 모든 곳(예: `CREATE TABLE`의 컬럼 명세, `SELECT`의 `ORDER BY` 표현식)에서 사용할 수 있습니다.

다음은 미국 영어(`en_US.UTF8`) 기반 ICU 콜레이션 생성·사용 예입니다.
- `icu_collate_lowercase`: 소문자가 대문자보다 먼저 정렬(`CL`).
- `icu_collate_uppercase`: 대문자가 소문자보다 먼저 정렬(`CU`).
- `icu_collate_ignore_punct`: variable 문자(공백·구두점)를 정렬 시 무시(`AS`).
- `icu_collate_ignore_white_sp`: 공백 등 비가시 variable 문자는 무시하되 가시 variable 문자(구두점)는 무시하지 않음(`AS`, `T0020`).

```sql
CREATE COLLATION icu_collate_lowercase (
    LOCALE = 'en_US.UTF8',
    ICU_SHORT_FORM = 'AN_CL_EX_NX_LROOT'
);

CREATE COLLATION icu_collate_uppercase (
    LOCALE = 'en_US.UTF8',
    ICU_SHORT_FORM = 'AN_CU_EX_NX_LROOT'
);

CREATE COLLATION icu_collate_ignore_punct (
    LOCALE = 'en_US.UTF8',
    ICU_SHORT_FORM = 'AS_CX_EX_NX_LROOT_L3'
);

CREATE COLLATION icu_collate_ignore_white_sp (
    LOCALE = 'en_US.UTF8',
    ICU_SHORT_FORM = 'AS_CX_EX_NX_LROOT_L3_T0020'
);
```
> **참고**: 콜레이션 생성 시 `LROOT` 콜레이션을 수정하는 속성이 주어지면 ICU가 notice·warning 메시지를 생성할 수 있습니다.

콜레이션 목록 표시:
```sql
edb=# \dO
```
```text
                                      List of collations
    Schema    |            Name             |  Collate   |   Ctype    |     ICU
--------------+-----------------------------+------------+------------+----------------------------
 enterprisedb | icu_collate_ignore_punct    | en_US.UTF8 | en_US.UTF8 | AS_CX_EX_NX_LROOT_L3
 enterprisedb | icu_collate_ignore_white_sp | en_US.UTF8 | en_US.UTF8 | AS_CX_EX_NX_LROOT_L3_T0020
 enterprisedb | icu_collate_lowercase       | en_US.UTF8 | en_US.UTF8 | AN_CL_EX_NX_LROOT
 enterprisedb | icu_collate_uppercase       | en_US.UTF8 | en_US.UTF8 | AN_CU_EX_NX_LROOT
(4 rows)
```

테스트 테이블 생성·적재:
```sql
CREATE TABLE collate_tbl (
    id              INTEGER,
    c2              VARCHAR(2)
);
INSERT INTO collate_tbl VALUES (1, 'A');
INSERT INTO collate_tbl VALUES (2, 'B');
INSERT INTO collate_tbl VALUES (3, 'C');
INSERT INTO collate_tbl VALUES (4, 'a');
INSERT INTO collate_tbl VALUES (5, 'b');
INSERT INTO collate_tbl VALUES (6, 'c');
INSERT INTO collate_tbl VALUES (7, '1');
INSERT INTO collate_tbl VALUES (8, '2');
INSERT INTO collate_tbl VALUES (9, '.B');
INSERT INTO collate_tbl VALUES (10, '-B');
INSERT INTO collate_tbl VALUES (11, ' B');
```

### 기본 콜레이션 사용
컬럼 `c2`를 기본 콜레이션으로 정렬. variable 문자(id 9·10·11)는 무시되어 `B`와 함께 정렬됩니다.
```sql
edb=# SELECT * FROM collate_tbl ORDER BY c2;
```
```text
 id  | c2
-----+----

 8   | 2
 4   | a
 1   | A
 5   | b
 2   | B
 11  | B
 10  | -B
 9   | .B
 6   | c
 3   | C
(11 rows)
```

### icu_collate_lowercase 사용
소문자가 대문자보다 먼저 정렬. `AN` 속성으로 기본 문자 비교 시 variable 문자를 같은 레벨에 포함하므로 id 9·10·11이 모든 글자·숫자보다 앞에 나옵니다.

edb=# SELECT * FROM collate_tbl ORDER BY c2 COLLATE "icu_collate_lowercase";

### icu_collate_ignore_white_sp 사용
`AS`·`T0020` 속성으로 16진수 `0020` 이하 코드 포인트의 variable 문자는 무시하고 초과 문자는 포함합니다. 공백(0020)으로 시작하는 id 11은 `B`와 함께 정렬되고, 가시 구두점(0020 초과)으로 시작하는 id 9·10은 앞쪽에 나옵니다.
```sql
edb=# SELECT * FROM collate_tbl ORDER BY c2 COLLATE "icu_collate_ignore_white_sp";
```
```text

----+----

 9  | .B
 7  | 1
 8  | 2
 4  | a
 1  | A
 5  | b
 11 |  B
 2  | B
 6  | c
 3  | C
(11 rows)
```
