# 서비스 시작·중지 (Starting and stopping services) — EPAS 18 설치

> 원문: [EPAS v18 — Installing › … › Managing an installation › Starting and stopping services](https://www.enterprisedb.com/docs/epas/latest/installing/linux_install_details/managing_an_advanced_server_installation/starting_and_stopping_services/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·서비스명·경로는 원문 그대로 보존했습니다.

서비스(service)는 백그라운드에서 실행되며 사용자 상호작용이 필요 없는 프로그램입니다. 서비스에는 사용자 인터페이스가 없습니다. 부팅 시 시작하거나 필요 시 수동으로 시작하도록 구성할 수 있습니다. 서비스는 플랫폼별 운영체제 서비스 제어 유틸리티로 제어하는 것이 가장 좋습니다. EDB Postgres Advanced Server 지원 구성 요소 중 다수가 서비스입니다.

## 서비스 목록

다음 표는 EDB Postgres Advanced Server와 그 지원 구성 요소를 제어하는 서비스의 이름을 나열합니다.

| EPAS 구성 요소 이름 | Linux 서비스명 | Debian 서비스명 |
|---|---|---|
| EDB Postgres Advanced Server | edb-as-18 | edb-as@18-main |
| PgBouncer | edb-pgbouncer-1.21 | edb-pgbouncer121 |
| pgPool-II | edb-pgpool-4.4 | edb-pgpool44 |
| Slony | edb-slony-replication-15 | edb-as15-slony-replication |
| EFM | edb-efm-4.0 | edb-efm-4.0 |

Linux 명령줄을 사용하여 EDB Postgres Advanced Server 데이터베이스 서버와 지원 구성 요소의 서비스를 제어할 수 있습니다. Linux 플랫폼에서 EDB Postgres Advanced Server 서비스를 제어하는 명령은 호스트별로 다릅니다.

## RHEL / Rocky Linux / AlmaLinux 8.x | 9.x에서 서비스 제어

EDB Postgres Advanced Server 설치가 RHEL 8.x | 9.x에 있으면 `systemctl` 명령으로 EDB Postgres Advanced Server 서비스와 지원 구성 요소를 제어해야 합니다.

`systemctl` 명령은 검색 경로에 있어야 하며 슈퍼유저 권한으로 호출해야 합니다. 명령줄에서 다음을 입력합니다.

```text
systemctl <action> <service_name>
```

여기서:

- `service_name`은 서비스의 이름을 지정합니다.
- `action`은 서비스 명령이 수행할 동작을 지정합니다.
  - `start` — 서비스 시작
  - `stop` — 서비스 중지
  - `restart` — 서비스 중지 후 시작
  - `status` — 서비스의 현재 상태 확인

## Debian 11.x 또는 Ubuntu 20.04 | 22.04에서 서비스 제어

EDB Postgres Advanced Server 설치가 Debian 11.x 또는 Ubuntu 20.04 | 22.04에 있으면, 슈퍼유저 권한을 얻고 번들 스크립트로 다음 명령을 호출하여 서비스를 관리합니다.

- 서비스의 현재 상태 확인:

```text
/usr/edb/as15/bin/epas_ctlcluster 15 main status
```

- 서비스 중지:

```text
/usr/edb/as15/bin/epas_ctlcluster 15 main stop
```

- 서비스 재시작:

```text
/usr/edb/as15/bin/epas_ctlcluster 15 main restart
```

- 서비스 다시 로드:

```text
/usr/edb/as15/bin/epas_ctlcluster 15 main reload
```

- 구성 요소 서비스 제어:

```text
systemctl restart edb-as@15-main
```

## pg_ctl로 EDB Postgres Advanced Server 제어

pg_ctl 유틸리티로 어떤 플랫폼에서든 명령줄에서 EDB Postgres Advanced Server 서비스를 제어할 수 있습니다. pg_ctl로 다음을 할 수 있습니다.

- EDB Postgres Advanced Server 데이터베이스 서버 시작·중지·재시작
- 구성 파라미터 다시 로드
- 실행 중인 서버의 상태 표시

유틸리티를 호출하려면 클러스터 소유자 신원을 가정합니다. EDB Postgres Advanced Server 홈 디렉터리에서 다음을 입력합니다.

```text
./bin/pg_ctl -D <data_directory> <action>
```

- `data_directory`는 EDB Postgres Advanced Server 클러스터가 제어하는 데이터의 위치입니다.
- `action`은 pg_ctl 유틸리티가 수행할 동작을 지정합니다.
  - `start` — 서비스 시작
  - `stop` — 서비스 중지
  - `restart` — 서비스 중지 후 시작
  - `reload` — 서버에 `SIGHUP` 신호를 보내 구성 파라미터를 다시 로드
  - `status` — 서비스의 현재 상태 확인

pg_ctl 유틸리티 사용이나 사용 가능한 명령줄 옵션에 대한 자세한 내용은 [PostgreSQL 코어 문서](https://www.postgresql.org/docs/current/static/app-pg-ctl.html)를 참고하십시오.

### pg_ctl과 service 명령 중 선택

pg_ctl 유틸리티로 EDB Postgres Advanced Server 클러스터의 상태를 관리할 수 있습니다. 다만 pg_ctl은 서버 상태 변경을 운영체제 서비스 컨트롤러에 알리지 않는다는 점을 알아야 합니다. 가능하면 `service` 명령 사용을 권장합니다.

## 시스템 재부팅 시 구성 요소 서비스 자동 시작 구성

Linux 시스템에서 EDB Postgres Advanced Server 지원 구성 요소의 서비스를 설치·구성·시작한 뒤, 시스템 재시작 시 서비스가 자동 시작되도록 수동으로 구성해야 합니다. Linux 시스템에서 서비스를 자동 시작하도록 구성하려면 명령줄에서 슈퍼유저 권한을 얻고 명령을 입력합니다.

Redhat 호환 Linux 시스템에서는 다음을 입력합니다.

```text
/sbin/chkconfig <service_name> on
```

`service_name`은 서비스의 이름을 지정합니다.
