# 코어 덤프 활성화 (Enabling core dumps) — EPAS 18 설치

> 원문: [EPAS v18 — Installing › Troubleshooting › On Linux › Enabling core dumps](https://www.enterprisedb.com/docs/epas/latest/installing/troubleshooting/linux_troubleshooting/enabling_core_dump/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·경로·설정은 원문 그대로 보존했습니다.

코어 덤프(core dump)를 사용하여 오류를 진단하거나 디버그할 수 있습니다. 코어 덤프는 프로세스가 예기치 않게 종료될 때 그 프로세스의 주소 공간(메모리)을 담은 파일입니다. 코어 덤프는 디버거 등에 의해 필요 시 생성되거나 종료 시점에 생성될 수 있습니다.

## RHEL 또는 Rocky Linux 또는 AlmaLinux 호스트에서 코어 덤프 활성화

RHEL/Rocky Linux/AlmaLinux 8.x | 9.x에서는 코어 파일 생성이 기본적으로 비활성화되어 있습니다. 코어 파일 생성을 활성화하려면:

- `ulimit -c` 또는 `ulimit -a` 명령으로 시스템의 현재 한도를 확인합니다. `0`은 코어 파일 생성이 비활성화되어 있음을 의미합니다.

```text
# ulimit -c
0

# ulimit -a
core file size          (blocks, -c) 0
data seg size           (kbytes, -d) unlimited
scheduling priority             (-e) 0
file size               (blocks, -f) unlimited
pending signals                 (-i) 3756
max locked memory       (kbytes, -l) 64
max memory size         (kbytes, -m) unlimited
open files                      (-n) 1024
pipe size            (512 bytes, -p) 8
POSIX message queues     (bytes, -q) 819200
real-time priority              (-r) 0
stack size              (kbytes, -s) 8192
cpu time               (seconds, -t) unlimited
max user processes              (-u) 3756
virtual memory          (kbytes, -v) unlimited
file locks                      (-x) unlimited
```

- 코어 덤프를 저장할 디렉터리를 만들고, 지정한 디렉터리에 덤프를 저장하도록 `kernel.core_pattern`을 수정합니다.

```text
mkdir -p /var/coredumps
chmod a+w /var/coredumps

sysctl kernel.core_pattern=/var/coredumps/core-%e-%p
kernel.core_pattern = /var/coredumps/core-%e-%p
```

- 재부팅 후에도 `kernel.core_pattern` 설정이 유지되도록 합니다.

```text
echo 'kernel.core_pattern=/var/coredumps/core-%e-%p' >> /etc/sysctl.conf
```

- 사용자가 코어 파일을 생성할 수 있도록 `/etc/security/limits.conf`에서 코어 덤프를 활성화합니다. 각 줄은 다음 형식으로 사용자에 대한 한도를 기술합니다.

```text
<domain>  <type>  <item>  <value>
     *       soft    core    unlimited
```

  `*`를 사용하여 코어 덤프 크기를 unlimited로 설정합니다.

- 코어 파일 크기 한도를 `UNLIMITED`로 설정합니다.

```text
ulimit -c unlimited

ulimit -c
unlimited
```

- 서비스에 대한 코어 한도를 설정하려면 `/usr/lib/systemd/system/edb-as-18.service`에 다음 설정을 추가합니다.

```text
[Service]
LimitCore=Infinity
```

- 서비스 구성을 다시 로드합니다.

```text
systemctl daemon-reload
```

- systemd로 전역 기본 한도를 수정합니다. `/etc/systemd/system.conf`에 다음 설정을 추가합니다.

```text
DefaultLimitCORE=Infinity
```

- systemd를 재시작합니다.

```text
systemctl daemon-reexec
```

- EDB Postgres Advanced Server를 중지한 뒤 다시 시작합니다.

```text
systemctl stop edb-as-18
systemctl start edb-as-18
```

- 이제 코어 덤프가 활성화되었습니다. gdb 도구와 디버그 패키지를 설치합니다.

```text
yum install gdb
debuginfo-install edb-as18 edb-as18-server-contrib edb-as18-server edb-as18-libs
```

- 코어 덤프 파일 경로로 치환한 뒤, `bt` 명령으로 백트레이스를 얻어 출력을 분석합니다.

```text
gdb /usr/edb/as18/bin /var/coredumps/core-edb-postgres-65499
(gdb) bt full
```

## Debian 또는 Ubuntu 호스트에서 코어 덤프 활성화

- `ulimit -c` 또는 `ulimit -a` 명령으로 시스템의 현재 한도를 확인합니다. `0`은 코어 파일 생성이 비활성화되어 있음을 의미합니다.

> **참고(Note)**
>
> - Debian 또는 Ubuntu 호스트에서 디버그 정보 패키지 이름은 다양하며 `-dbgsym` 또는 `-dbg` 접미사를 포함할 수 있습니다. `sources.list` 설정과 디버그 정보 패키지 설치에 대한 자세한 내용은 [Debian wiki](https://wiki.debian.org/HowToGetABacktrace) 또는 [Ubuntu wiki](https://wiki.ubuntu.com/Debug%20Symbol%20Packages)를 참고하십시오.
> - 코어 파일은 메모리 사용량에 따라 매우 커질 수 있습니다. 시스템에서 코어 덤프를 활성화하면 시간이 지나면서 대용량 저장소가 가득 찰 수 있습니다.
