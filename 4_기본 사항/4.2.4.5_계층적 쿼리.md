# 계층적 쿼리 (Hierarchical queries) — EPAS 18 SQL 기본 사항

> 원문: [EPAS v18 — Fundamentals › SQL fundamentals › Advanced concepts › Hierarchical queries](https://www.enterprisedb.com/docs/epas/latest/fundamentals/sql_fundamentals/03_advanced_concepts/05_hierarchical_queries/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·코드 이름은 원문 그대로 보존했습니다.

_계층적 쿼리(hierarchical query)_ 는 부모-자식 관계를 형성하는 데이터를 기반으로 결과 집합의 행을 계층적 순서로 반환하는 쿼리 유형입니다. 계층은 일반적으로 뒤집힌 트리 구조로 표현됩니다. 트리는 상호 연결된 _노드(node)_ 로 구성됩니다. 각 노드는 0개, 1개, 또는 여러 개의 _자식(child)_ 노드와 연결될 수 있습니다. 각 노드는 하나의 _부모(parent)_ 노드와 연결되지만, 부모가 없는 최상위 노드는 예외입니다. 이 노드가 _루트(root)_ 노드입니다. 각 트리에는 정확히 하나의 루트 노드가 있습니다.

자식이 없는 노드를 _리프(leaf)_ 노드라고 합니다. 트리에는 항상 최소한 하나의 리프 노드가 있습니다. 예를 들어 트리가 단일 노드로 구성된 사소한 경우, 그 노드는 루트이자 리프입니다.

계층적 쿼리에서 결과 집합의 행은 하나 이상의 트리의 노드를 나타냅니다.

##### 참고 (Note)

주어진 단일 행이 둘 이상의 트리에 나타날 수 있으므로 결과 집합에 두 번 이상 나타날 수 있습니다.

## 구문 (Syntax)

쿼리의 계층적 관계는 `CONNECT BY` 절로 기술되며, 이 절이 결과 집합에서 행이 반환되는 순서의 기준을 형성합니다. 다음 예제는 `CONNECT BY` 절과 그 연관된 선택적 절이 `SELECT` 명령에서 나타나는 위치의 맥락을 보여줍니다:

```sql
SELECT <select_list> FROM <table_expression> [ WHERE ...]
  [ START WITH <start_expression> ]
    { CONNECT BY <condition> }
  [ ORDER SIBLINGS BY <column1> [ ASC | DESC ]
      [, <column2> [ ASC | DESC ] ] ...
  [ GROUP BY ...]
  [ HAVING ...]
  [ <other> ...]
```

`select_list`는 결과 집합의 필드를 구성하는 하나 이상의 표현식입니다. `table_expression`은 결과 집합의 행이 유래하는 하나 이상의 테이블 또는 뷰입니다. `other`는 그 밖의 유효한 `SELECT` 명령 절입니다.

`CONNECT BY`는 계층에서 부모 레코드와 그 자식 레코드 사이의 관계를 지정합니다.

- `CONNECT BY` 절의 조건에서 `PRIOR` 키워드는 하나의 표현식에만 지정할 수 있습니다. 계층적 쿼리에서 부모 행을 참조하려면 오른쪽 또는 왼쪽 표현식 중 하나에 지정해야 합니다. 예를 들면:

  ```sql
  PRIOR expr = expr
  or
  expr = PRIOR expr
  ```

- `CONNECT BY condition`이 복합 조건인 경우, 여러 개의 `PRIOR` 조건이 있을 수 있지만 하나의 조건에만 `PRIOR` 키워드가 필요합니다.

- `PRIOR` 키워드를 사용하여 계층적 쿼리에서 부모-자식 관계의 부모 행을 평가할 수 있습니다.

- 단항(unary) 표현식에는 `PRIOR` 키워드를 사용할 수 없습니다.

- `PRIOR` 키워드를 사용하여 대상 목록의 표현식에 대응하는 각 레코드에 의사 컬럼(pseudo-column)을 추가할 수 있습니다. 이 의사 컬럼은 자식 쿼리에서 `PRIOR` 표현식을 사용하여 참조될 때 부모 레코드의 실제 값을 나타냅니다.

`CONNECT_BY_ROOT` 연산자를 사용하여 `CONNECT BY [PRIOR]` 조건의 기능을 더욱 확장할 수 있습니다. 이 연산자는 직접 부모 행뿐만 아니라 계층의 모든 조상(ancestor) 행도 반환합니다. 자세한 내용은 [CONNECT_BY_ROOT로 루트 노드 조회(Retrieving the root node with CONNECT_BY_ROOT)](https://www.enterprisedb.com/docs/epas/latest/fundamentals/sql_fundamentals/03_advanced_concepts/05_hierarchical_queries/06_retrieving_the_root_node_with_connect_by_root/#retrieving_the_root_node_with_connect_by_root)를 참고하십시오.

## 예제 (Examples)

이 예제는 `CONNECT BY` 절과 `PRIOR`를 사용하여 직원과 관리자 사이의 관계를 정의합니다. `LEVEL` 값을 사용하여 직원 이름을 들여쓰기함으로써 각 행의 계층 깊이를 강조합니다.

```sql
SELECT LPAD(ename,length(ename)+2 *(LEVEL - 1),' ') AS employee, empno, mgr, LEVEL
FROM emp
CONNECT BY PRIOR empno = mgr AND PRIOR emp.deptno = emp.deptno;
```
