> 상위: # 메이저 버전 업그레이드 (Major Version Upgrade with pg_upgrade) — EPAS 18 Upgrading

## 3. 업그레이드 수행 (Performing an upgrade)

> 원문: [01_performing_an_upgrade](https://www.enterprisedb.com/docs/epas/latest/upgrading/major_upgrade/01_performing_an_upgrade/)

이전 버전의 EDB Postgres Advanced Server를 현재 버전으로 업그레이드하려면 다음과 같이 합니다.

1. 현재 버전의 EDB Postgres Advanced Server를 설치합니다. 새 설치는 이전 설치와 동일한 지원 서버 구성 요소를 포함해야 합니다.
2. 대상 데이터베이스를 비우거나 `initdb`로 새 대상 클러스터를 생성합니다.
3. 인증 충돌을 피하기 위해, 두 데이터베이스의 `pg_hba.conf` 파일을 `trust` 인증 모드로 설정합니다.
4. 이전 및 새 EDB Postgres Advanced Server 서비스를 종료합니다.
5. `pg_upgrade` 유틸리티를 호출합니다.

`pg_upgrade`가 시작되면 필요한 모든 실행 파일이 존재하고 예상 버전 번호를 담고 있는지 확인하는 호환성 검사를 수행합니다. 검증 과정은 또한 이전 및 새 `$PGDATA` 디렉터리를 확인하여 예상되는 파일과 하위 디렉터리가 제자리에 있는지 검사합니다. 검증에 성공하면 `pg_upgrade`는 이전 `postmaster`를 시작하고 `pg_dumpall --schema-only`를 실행하여 이전 클러스터에 담긴 메타데이터를 캡처합니다. `pg_dumpall`이 생성한 스크립트는 이후 새 클러스터에서 모든 사용자 정의 객체를 다시 생성하는 데 사용됩니다.

`pg_dumpall`이 생성한 스크립트는 시스템 정의 객체가 아니라 사용자 정의 객체만 다시 생성합니다. 새 클러스터에는 최신 버전의 EDB Postgres Advanced Server가 생성한 시스템 정의 객체가 이미 포함되어 있습니다.

이전 클러스터에서 메타데이터를 추출한 후, `pg_upgrade`는 새 클러스터를 기존 데이터와 동기화하는 데 필요한 부기(bookkeeping) 작업을 수행합니다.

`pg_upgrade`는 새 클러스터에 대해 `pg_dumpall` 스크립트를 실행하여 이전 클러스터에 있던 것과 동일한 형태·유형의 빈 데이터베이스 객체를 생성합니다. 그런 다음 `pg_upgrade`는 각 테이블과 인덱스를 이전 클러스터에서 새 클러스터로 링크하거나 복사합니다.

EDB Postgres Advanced Server로 업그레이드하는데 `edb_dblink_oci` 또는 `edb_dblink_libpq` 확장을 설치했다면, 업그레이드를 수행하기 전에 해당 확장을 제거하십시오. 확장을 제거하려면 psql 또는 PEM 클라이언트로 서버에 접속하여 다음 명령을 실행합니다.

```sql
DROP EXTENSION edb_dblink_oci;
DROP EXTENSION edb_dblink_libpq;
```

업그레이드를 마친 후에는 `CREATE EXTENSION` 명령으로 현재 버전의 확장을 설치에 추가할 수 있습니다.
