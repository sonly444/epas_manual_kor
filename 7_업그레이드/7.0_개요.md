# 업그레이드 (Upgrading) — EDB Postgres Advanced Server 18

> 원문: [EPAS v18 Documentation — Upgrading](https://www.enterprisedb.com/docs/epas/latest/upgrading/)
> EPAS v18 공식 문서의 한글 번역입니다. 도구·명령·플래그 이름은 원문 그대로 보존했습니다.

EPAS 업그레이드는 크게 두 경로로 나뉩니다: **메이저 버전 업그레이드(pg_upgrade)** 와 **마이너 버전 업그레이드(패키지 관리자)**.

---

## 1. 메이저 버전 업그레이드 — pg_upgrade

`pg_upgrade`는 동일 플랫폼에서 EPAS의 어떤 버전(9.0 이상)에서든 이후 릴리스로의 마이그레이션을 쉽게 해 줍니다. 전통적인 덤프/복원 방식보다 소요 시간과 디스크 공간을 크게 줄일 수 있습니다.

일반 절차(단계별):
1. **새 실행 파일 설치**: 대상 버전(예: EPAS 18)의 서버 패키지 설치.
2. **새 클러스터 초기화**: 대상 버전용 새 데이터 클러스터를 `initdb`로 생성.
3. **pg_upgrade 실행**: 먼저 검증 모드(`--check`)로 사전 점검한 뒤, 실제 마이그레이션 수행.
4. **업그레이드 후 작업**: 데이터베이스 분석(ANALYZE) 실행, 이전 클러스터 삭제 등 정리.

세부 하위 항목으로 업그레이드 고려사항, pg_upgrade 동작 원리, 업그레이드 수행, 유틸리티 호출, 문제 해결, 되돌리기(reversion) 절차가 제공됩니다.

> 참고: 실제 실행 전 반드시 "업그레이드 고려사항(upgrade considerations)"과 요구 사항을 검토하고, 기존 클러스터 백업을 확보하십시오.

---

## 2. 마이너 버전 업그레이드 — 패키지 관리자

마이너 버전 업그레이드는 기존 실행 파일을 갱신하고 데이터베이스 서버를 재시작하는 것으로, 데이터 마이그레이션이 필요 없어 메이저 업그레이드보다 단순합니다. 설치 방식에 따라 세 경로가 있습니다.

- **RPM 설치(RHEL, AlmaLinux, Rocky Linux)**: `dnf` 사용.
- **Debian 설치(Ubuntu, Debian)**: `apt-get` 사용.
- **StackBuilder Plus**: EDB의 StackBuilder Plus 그래픽 설치 도구로 설치한 경우.

운영체제별 정확한 명령·주의사항·서비스 중지/시작 절차는 각 설치 방식에 해당하는 하위 페이지를 참조하십시오. 공통적으로 업그레이드 후 데이터베이스 서버 재시작이 필요합니다.

> 참고: 최신 마이너 버전에는 PostgreSQL 업스트림 보안 수정이 포함되므로(릴리스 노트 참조), 보안 관점에서 마이너 업그레이드를 정기적으로 적용하는 것이 권장됩니다.
