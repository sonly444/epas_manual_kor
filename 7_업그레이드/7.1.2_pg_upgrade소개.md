> 상위: # 메이저 버전 업그레이드 (Major Version Upgrade with pg_upgrade) — EPAS 18 Upgrading

## 2. pg_upgrade 소개 (About pg_upgrade)

> 원문: [how_pg_upgrade_works](https://www.enterprisedb.com/docs/epas/latest/upgrading/major_upgrade/how_pg_upgrade_works/)

`pg_upgrade` 실행 파일은 EDB Postgres Advanced Server의 Database Server 구성 요소의 일부로 함께 제공되며, 별도의 설치나 구성이 필요하지 않습니다.

이 유틸리티는 EDB Postgres Advanced Server와 그 이후 버전 사이의 **제자리(in-place) 데이터 이전**을 수행합니다. 업그레이드 전에 `pg_upgrade`는 이전(old) 클러스터와 새(new) 클러스터 간의 호환성을 검증합니다.

시작 시 `pg_upgrade`는 호환성 검증을 수행하여 필요한 모든 실행 파일이 올바른 버전 번호로 존재하는지 확인합니다. 또한 이전 및 새 `$PGDATA` 디렉터리를 검사하여 예상되는 파일과 하위 디렉터리가 제자리에 있는지 확인합니다. 검증에 성공하면 `pg_upgrade`는 이전 postmaster를 시작하고 `pg_dumpall --schema-only`를 실행하여 이전 클러스터의 메타데이터를 추출합니다. 이 스크립트는 이후 새 클러스터에서 사용자 정의 객체(user-defined objects)를 다시 생성하는 데 사용됩니다.

`pg_dumpall` 스크립트는 시스템 정의 객체(system-defined objects)가 아니라 사용자 정의 객체만 다시 생성합니다. 새 클러스터에는 최신 버전의 EDB Postgres Advanced Server가 생성한 시스템 객체가 이미 포함되어 있기 때문입니다.

메타데이터 추출 후 `pg_upgrade`는 동기화 작업을 수행합니다. 새 클러스터에 대해 `pg_dumpall` 스크립트를 실행하여 이전 클러스터와 동일한 형태(shape)·유형(type)의 빈 데이터베이스 객체를 생성한 다음, 각 테이블과 인덱스를 이전 클러스터에서 새 클러스터로 **링크(link)하거나 복사(copy)**합니다.

EDB Postgres Advanced Server로 업그레이드하기 전에, `edb_dblink_oci` 또는 `edb_dblink_libpq` 확장이 설치되어 있다면 다음 명령으로 제거하십시오.

```sql
DROP EXTENSION edb_dblink_oci;
DROP EXTENSION edb_dblink_libpq;
```

업그레이드 후에는 `CREATE EXTENSION`으로 현재 버전을 다시 설치합니다.

Windows 설치의 경우, 각 데이터베이스에서 adminpack 확장을 삭제하십시오. 이 기능은 대체 없이 제거되었습니다.

```sql
DROP EXTENSION adminpack;
```

업그레이드에 온디스크 표현(on-disk representation)의 변경이나 데이터 타입의 이진(binary) 표현 변경이 포함되면 `pg_upgrade`는 진행할 수 없습니다. 이 경우 대신 이전 데이터를 `pg_dump`로 내보낸 뒤 새 클러스터로 가져와야 합니다.
