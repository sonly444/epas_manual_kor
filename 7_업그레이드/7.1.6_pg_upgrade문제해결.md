> 상위: # 메이저 버전 업그레이드 (Major Version Upgrade with pg_upgrade) — EPAS 18 Upgrading

## 5. pg_upgrade 문제 해결 (Troubleshooting pg_upgrade)

> 원문: [05_pg_upgrade_troubleshooting](https://www.enterprisedb.com/docs/epas/latest/upgrading/major_upgrade/05_pg_upgrade_troubleshooting/)

다음 문제 해결 팁은 `pg_upgrade` 사용 시 만날 수 있는 문제를 다룹니다.

### 업그레이드 오류 — There seems to be a postmaster servicing the cluster
`pg_upgrade`가 postmaster가 클러스터를 서비스하고 있다고 보고하면, 모든 EDB Postgres Advanced Server 서비스를 중지하고 업그레이드를 다시 시도하십시오.

### 업그레이드 오류 — fe_sendauth: no password supplied
`pg_upgrade`가 비밀번호 누락과 관련된 인증 오류를 보고하면, 이전 및 새 클러스터의 `pg_hba.conf` 파일을 수정하여 `trust` 인증을 활성화하거나, 시스템이 `pgpass.conf` 파일을 사용하도록 구성하십시오.

### 업그레이드 오류 — New cluster is not empty; exiting
`pg_upgrade`가 새 클러스터가 비어 있지 않다고 보고하면, 새 클러스터를 비우십시오. 대상 클러스터에는 사용자 정의 데이터베이스가 없어야 합니다.

### 업그레이드 오류 — Failed to load library
원래 EDB Postgres Advanced Server 클러스터에 포함되었던 라이브러리가 새 EDB Postgres Advanced Server 클러스터에 포함되지 않은 경우, `pg_upgrade`는 일관성 검사 중에 이를 알리며, `pg_upgrade`를 호출한 디렉터리의 `loadable_libraries.txt` 파일에 항목을 기록합니다. 일반적으로 메이저 구성 요소 업그레이드에 속하지 않는 누락 라이브러리의 경우 다음과 같이 합니다.

1. EDB Postgres Advanced Server 서비스를 재시작합니다.
2. StackBuilder Plus를 사용하여 누락된 모듈을 다운로드·설치합니다.
3. EDB Postgres Advanced Server 서비스를 중지합니다.
4. 업그레이드 과정을 재개합니다. `pg_upgrade`를 호출하여 일관성 검사를 수행합니다.
5. 일관성 검사에서 지적된 남은 문제를 모두 해결한 후, `pg_upgrade`를 호출하여 이전 클러스터에서 새 클러스터로 데이터 마이그레이션을 수행합니다.

> **참고**: adminpack 확장은 이 버전에서 대체 없이 제거되었습니다. 위 단계를 적용하는 대신, 업그레이드 전에 이전 버전에서 이 확장을 제거해야 합니다.
