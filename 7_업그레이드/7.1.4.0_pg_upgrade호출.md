> 상위: # 메이저 버전 업그레이드 (Major Version Upgrade with pg_upgrade) — EPAS 18 Upgrading

## 4. pg_upgrade 호출 (Invoking pg_upgrade)

> 원문: [02_invoking_pg_upgrade](https://www.enterprisedb.com/docs/epas/latest/upgrading/major_upgrade/02_invoking_pg_upgrade/)

`pg_upgrade`를 호출할 때는 이전 및 새 클러스터의 `PGDATA`와 실행 파일(`/bin`) 디렉터리 위치, EDB Postgres Advanced Server 슈퍼유저 이름, 그리고 각 설치가 리스닝하는 포트를 지정해야 합니다. EDB Postgres Advanced Server 16에서 EDB Postgres Advanced Server 18로 마이그레이션하기 위해 `pg_upgrade`를 호출하는 일반적인 형태는 다음과 같습니다.

```shell
pg_upgrade
--old-datadir <path_to_16_data_directory>
--new-datadir <path_to_18_data_directory>
--user <superuser_name>
--old-bindir <path_to_16_bin_directory>
--new-bindir <path_to_18_bin_directory>
--old-port <16_port> --new-port <18_port>
```

각 옵션의 의미:

**`--old-datadir path_to_16_data_directory`**
`--old-datadir` 옵션으로 EDB Postgres Advanced Server 16 설치의 `data` 디렉터리 전체 경로를 지정합니다.

**`--new-datadir path_to_18_data_directory`**
`--new-datadir` 옵션으로 EDB Postgres Advanced Server 18 설치의 `data` 디렉터리 전체 경로를 지정합니다.

**`--username superuser_name`**
`--username` 옵션으로 EDB Postgres Advanced Server 슈퍼유저 이름을 지정합니다. 슈퍼유저 이름은 두 버전의 EDB Postgres Advanced Server에서 동일해야 합니다. 기본적으로 EDB Postgres Advanced Server가 Oracle 모드로 설치되면 슈퍼유저 이름은 `enterprisedb`이고, PostgreSQL 모드로 설치되면 `postgres`입니다.
> EDB Postgres Advanced Server 슈퍼유저 이름이 두 클러스터에서 동일하지 않으면 클러스터는 `pg_upgrade` 일관성 검사를 통과하지 못합니다.

**`--old-bindir path_to_16_bin_directory`**
`--old-bindir` 옵션으로 EDB Postgres Advanced Server 16 설치의 `bin` 디렉터리 전체 경로를 지정합니다.

**`--new-bindir path_to_18_bin_directory`**
`--new-bindir` 옵션으로 EDB Postgres Advanced Server 18 설치의 `bin` 디렉터리 전체 경로를 지정합니다.

**`--old-port 16_port`**
`--old-port` 옵션으로 EDB Postgres Advanced Server 16이 연결을 리스닝하는 포트를 지정합니다.

**`--new-port 18_port`**
`--new-port` 옵션으로 EDB Postgres Advanced Server 18이 연결을 리스닝하는 포트를 지정합니다.

> 참고: 이 밖에도 `--check`(실제 이전 없이 사전 점검만 수행), `--link`(데이터 파일을 복사 대신 링크로 연결) 옵션을 사용할 수 있습니다. 이들 옵션의 영향은 아래 "이전 클러스터로 되돌리기"를 참고하십시오.
