## 3.1 링크 대 복사 (Linking versus copying)

> 원문: [01_performing_an_upgrade/01_linking_versus_copying](https://www.enterprisedb.com/docs/epas/latest/upgrading/major_upgrade/01_performing_an_upgrade/01_linking_versus_copying/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·옵션·경로는 원문 그대로 보존했습니다.

`pg_upgrade`를 호출할 때, 명령줄 옵션을 사용하여 이전 클러스터의 각 테이블과 인덱스를 새 클러스터로 복사(copy)할지 링크(link)할지 지정할 수 있습니다.

링크(linking)는 훨씬 빠릅니다. `pg_upgrade`가 클러스터의 각 파일에 대해 두 번째 이름(하드 링크)을 생성하기 때문입니다. 또한 링크는 `pg_upgrade`가 원본 데이터의 복사본을 만들지 않으므로 추가 작업 공간이 필요 없습니다. 이전 클러스터와 새 클러스터를 링크하면 이전 클러스터와 새 클러스터가 데이터를 공유합니다. 새 클러스터를 시작한 후에는 이전 버전의 EDB Postgres Advanced Server로 데이터를 더 이상 사용할 수 없습니다.

이전 클러스터에서 새 클러스터로 데이터를 복사(copy)하기로 선택하더라도, `pg_upgrade`는 전통적인 `dump/restore` 절차에 비해 업그레이드에 필요한 시간을 여전히 단축합니다. `pg_upgrade`는 `dump/restore`가 사용하는 행 단위(row-by-row) 방식 대신, 파일 단위(file-at-a-time) 방식으로 이전 클러스터에서 새 클러스터로 데이터 파일을 복사합니다. `pg_upgrade`를 사용하면 새 클러스터에서 인덱스를 다시 빌드하지 않아도 됩니다. 대신 각 인덱스가 이전 클러스터에서 새 클러스터로 복사됩니다. 마지막으로, `dump/restore` 절차로 업그레이드하면 모든 데이터의 중간 텍스트 기반 덤프를 담기 위한 많은 작업 공간이 필요하지만, `pg_upgrade`는 아주 적은 추가 작업 공간만 필요합니다.

사용자 정의 테이블스페이스(user-defined tablespace)에 저장된 데이터는 새 클러스터로 복사되지 않습니다. 이 데이터는 파일 시스템의 동일한 위치에 그대로 남지만, 새 클러스터의 버전 번호를 나타내는 이름의 하위 디렉터리로 복사됩니다. 업그레이드 후 테이블스페이스에 저장된 파일을 수동으로 재배치하려면, 파일을 새 위치로 옮기고 심볼릭 링크가 해당 파일을 가리키도록 갱신합니다. 심볼릭 링크는 클러스터의 `data` 디렉터리 아래 `pg_tblspc` 디렉터리에 위치합니다.
