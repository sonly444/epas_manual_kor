# 스탠바이에서 논리 디코딩 구성 (Configuring logical decoding on standby) — EPAS 18 향상된 SQL

> 원문: [EPAS v18 — Application programming › Enhanced SQL › Configuring logical decoding on standby](https://www.enterprisedb.com/docs/epas/latest/application_programming/15_enhanced_sql_and_other_misc_features/logical_decoding/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 파라미터·값·함수 이름은 원문 그대로 보존했습니다.

스탠바이 서버에서의 논리 디코딩(logical decoding)은 `get`, `peek`, `advance` 같은 API 작업에 응답할 수 있는 논리 복제 슬롯(logical replication slot)의 생성을 가능하게 합니다.

## 주요 구성 요구 사항

**hot_standby_feedback 파라미터:**
스탠바이 서버에서 `hot_standby_feedback` 파라미터를 `ON`으로 설정해야 합니다. 이 설정은 기존 논리 복제 슬롯이 필요로 하는 최근에 삭제된(dead) 행을 VACUUM이 제거하지 못하도록 방지합니다. 슬롯 충돌(slot conflict)이 발생하면 영향을 받은 슬롯은 삭제됩니다.

**wal_level 설정:**
주(primary) 서버와 스탠바이 서버 모두 `wal_level`을 `logical`로 설정해야 합니다. 다른 값으로 설정된 경우:
- 슬롯이 생성되지 않습니다.
- 스탠바이의 기존 논리 슬롯이 삭제됩니다.
- 새 슬롯을 생성할 수 없습니다.

## 운영상의 고려 사항

주 서버에 트랜잭션이 기록되면 스탠바이의 논리 슬롯이 트리거됩니다. 다만, 주 서버가 유휴(idle) 상태이면 스탠바이에서 논리 슬롯을 생성하는 데 눈에 띄는 시간이 걸릴 수 있습니다.

자세한 내용은 PostgreSQL 코어 문서의 [논리 디코딩 설명](https://www.postgresql.org/docs/current/logicaldecoding-explanation.html)과 [복제 함수](https://www.postgresql.org/docs/current/functions-admin.html#FUNCTIONS-REPLICATION)를 참조하십시오.
