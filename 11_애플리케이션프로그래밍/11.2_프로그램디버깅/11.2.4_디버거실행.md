# 디버거 실행 (Running the debugger) — EPAS 18 Application Programming

> 원문: [EPAS v18 — Application programming › Debugging programs › Running the debugger](https://www.enterprisedb.com/docs/epas/latest/application_programming/12_debugger/debugging_a_program/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. UI 항목명·명령·SQL·출력은 원문 그대로 보존했습니다.

프로그램을 디버깅하기 위해 다음 작업을 수행할 수 있습니다.

- 프로그램을 한 번에 한 줄씩 스텝(step)합니다.
- 중단점(breakpoint)에 도달할 때까지 프로그램을 실행합니다.
- 프로그램 내 지역 변수 값을 보고 변경합니다.

## 프로그램 사용 시 고려 사항 (Considerations when using the program)

- 이 지침은 독립 실행형(standalone) 디버깅 방법을 사용합니다. 인컨텍스트(in-context) 디버깅을 위해 디버거를 시작하려면 아래 "인컨텍스트 디버깅을 위한 전역 중단점 설정"을 참고하십시오.
- 독립 실행형 디버깅으로는 트리거를 디버깅할 수 없습니다. 인컨텍스트 디버깅을 사용해야 합니다. 자세한 내용은 아래 "인컨텍스트 디버깅을 위한 전역 중단점 설정"을 참고하십시오.

## 코드 스텝 진행 (Stepping through the code)

도구 모음 아이콘을 사용하여 디버거로 프로그램을 스텝 진행합니다. 아이콘은 다음 용도로 사용됩니다.

- **Step into.** 현재 강조된 코드 줄을 실행합니다.
- **Step over.** 코드 한 줄을 실행하되, 그 코드가 호출하는 서브함수(subfunction)를 건너뜁니다. 서브함수는 실행되지만, 중단점을 포함하는 경우에만 디버깅됩니다.
- **Continue/Start.** 강조된 코드를 실행하고, 프로그램이 중단점을 만나거나 완료될 때까지 계속합니다.
- **Stop.** 프로그램을 중지합니다.

## 중단점 사용 (Using breakpoints)

디버거가 프로그램을 실행하다가 중단점에 도달하면 일시 정지합니다. 디버거가 일시 정지하면 지역 변수를 관찰하거나 변경할 수 있고, 호출 스택의 항목으로 이동하여 변수를 관찰하거나 다른 중단점을 설정할 수 있습니다. 다음 step into, step over, 또는 continue 작업은 디버거가 중단점 다음 코드 줄부터 실행을 재개하도록 합니다.

중단점에는 두 가지 유형이 있습니다.

- **지역 중단점(Local breakpoint)** — 프로그램의 실행 가능한 코드 줄 어디에나 지역 중단점을 설정할 수 있습니다. 디버거는 지역 중단점이 설정된 줄에 도달하면 실행을 일시 정지합니다.
- **전역 중단점(Global breakpoint)** — 전역 중단점은 어떤 세션이든 그 중단점에 도달하면 트리거됩니다. 프로그램의 인컨텍스트 디버깅을 수행하려면 전역 중단점을 설정합니다. 프로그램에 전역 중단점을 설정하면, 전역 중단점을 설정한 디버깅 세션은 다른 세션에서 그 프로그램이 호출될 때까지 대기합니다. 슈퍼유저만 전역 중단점을 설정할 수 있습니다.

### 지역 중단점 설정 (Setting a local breakpoint)

지역 중단점을 생성하려면, 중단점을 설정하려는 코드 줄의 왼쪽에 있는 회색 음영 여백(margin)을 선택합니다. 선택하는 지점은, 소스 코드 12번째 줄에 중단점 점(dot)이 표시된 지점처럼 여백의 오른쪽에 가까워야 합니다. 중단점이 생성되면 디버거는 여백에 진한 점을 표시하여 선택한 코드 줄에 중단점이 설정되었음을 나타냅니다.

![Set a breakpoint by clicking in left-hand margin](https://www.enterprisedb.com/docs/static/543eddb8a5ab57720afb00b7eb9ca94a/302a4/setting_global_breakpoint_from_left-hand_margin.png)

원하는 만큼 많은 지역 중단점을 설정할 수 있습니다. 지역 중단점은 제거하기 전까지 디버깅 세션의 나머지 동안 유효합니다.

### 지역 중단점 제거 (Removing a local breakpoint)

지역 중단점을 제거하려면 중단점 점을 선택합니다. 점이 사라집니다.

현재 Program Body 프레임에 나타나는 프로그램의 모든 중단점을 제거하려면 **Clear all breakpoints** 아이콘을 선택합니다.

> **참고**
> 이 작업들을 수행하면, 현재 Program Body 패널에 나타나는 프로그램의 중단점만 제거됩니다. 호출된 서브프로그램의 중단점이나, 현재 Program Body 패널에 나타나는 프로그램을 호출하는 프로그램의 중단점은 제거되지 않습니다.

### 인컨텍스트 디버깅을 위한 전역 중단점 설정 (Setting a global breakpoint for in-context debugging)

인컨텍스트 디버깅을 위한 전역 중단점을 설정하려면 다음과 같이 합니다.

1. Browser 패널에서 중단점을 설정하려는 저장 프로시저, 함수, 또는 트리거를 선택합니다.
2. **Object > Debugging > Set Breakpoint**를 선택합니다.

트리거에 전역 중단점을 설정하려면 다음과 같이 합니다.

1. 트리거를 포함하는 테이블 노드를 확장합니다.
2. 디버깅하려는 특정 트리거를 선택합니다.
3. **Object > Debugging > Set Breakpoint**를 선택합니다.

패키지에 전역 중단점을 설정하려면 다음과 같이 합니다.

1. 디버깅하려는 패키지의 패키지 노드 아래에서 특정 프로시저 또는 함수를 선택합니다.
2. **Object > Debugging > Set Breakpoint**를 선택합니다.

**Set Breakpoint**를 선택하면 Debugger 창이 열리고 애플리케이션이 디버깅할 프로그램을 호출하기를 기다립니다.

PSQL 클라이언트가 전역 중단점이 설정된 `select_emp` 함수를 호출합니다.

```sql
$ psql edb enterprisedb
psql.bin (18.1.0, server 18.1.0)
Type "help" for help.

edb=# SELECT select_emp(7900);
```

`select_emp` 함수는 디버거에서 프로그램을 스텝 진행할 때까지 완료되지 않습니다.

![Program on which a global breakpoint was set](https://www.enterprisedb.com/docs/static/2ae3a05e9ed4a9079bbf237b326aeb04/302a4/parameters_tab.png)

이제 step into, step over, continue 같은 작업을 사용하여 프로그램을 디버깅할 수 있습니다. 또는 지역 중단점을 설정할 수 있습니다. 프로그램 실행을 스텝 진행하고 나면, 호출한 애플리케이션(PSQL)이 제어를 되찾고, `select_emp` 함수가 실행을 완료하며, 그 출력이 표시됩니다.

```sql
$ psql edb enterprisedb
psql.bin (18.1.0, server 18.1.0)
Type "help" for help.

edb=# SELECT select_emp(7900);
```

출력

```text
INFO: Number    : 7900
INFO: Name      : JAMES
INFO: Hire Date : 12/03/1981
INFO: Salary    : 950.00
INFO: Commission: 0.00
INFO: Department: SALES
 select_emp
------------
(1 row)
```

이 시점에서 디버거 세션을 종료할 수 있습니다. 디버거 세션을 종료하지 않으면, 다음에 그 프로그램을 호출하는 애플리케이션이 전역 중단점을 만나 디버깅 주기가 다시 시작됩니다.
