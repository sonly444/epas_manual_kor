# 접근 방식 힌트 (Access method hints) — EPAS 18 옵티마이저 힌트

> 원문: [EPAS v18 — Optimizing code › Using optimizer hints › Access method hints](https://www.enterprisedb.com/docs/epas/latest/application_programming/optimizing_code/05_optimizer_hints/02_access_method_hints/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 힌트·명령은 원문 그대로 보존했습니다.

## 개요

이 문서는 EDB Postgres Advanced Server에서 쿼리 최적화에 영향을 주기 위해 접근 방식 힌트(access method hint)를 사용하는 방법을 설명합니다. 이 힌트는 옵티마이저가 결과 집합을 구축할 때 릴레이션(relation)에 접근하는 방식을 제어합니다.

## 사용 가능한 주요 힌트

세 가지 주요 힌트가 문서화되어 있습니다.

- **FULL(table)**: "`table`에 대해 전체 순차 스캔(full sequential scan)을 수행합니다."
- **INDEX(table [ index ] [...])**: "릴레이션에 접근하기 위해 `table`의 `index`를 사용합니다."
- **NO_INDEX(table [ index ] [...])**: "릴레이션에 접근하기 위해 `table`의 `index`를 사용하지 않습니다."

추가로 `ALL_ROWS`, `FIRST_ROWS`, `FIRST_ROWS(n)` 힌트도 사용할 수 있습니다.

## 파티션 테이블 지원

"파티션 테이블에 대한 INDEX 및 NO_INDEX 힌트는 내부적으로 해당하는 상속된 자식 인덱스를 포함하도록 확장되며 이후 처리에 적용됩니다."

## 포함된 실제 예제

문서는 200만 개의 계좌 레코드를 가진 `pgbench` 은행 데이터베이스를 사용한 광범위한 예제를 제공합니다. 다음을 시연합니다.

- 인덱스 사용 대신 순차 스캔을 강제하기 위한 `FULL` 힌트 사용
- 특정 인덱스가 사용되지 않도록 하는 `NO_INDEX` 사용
- 힌트 효과를 디버깅하기 위한 `trace_hints` 구성 활성화
- 힌트가 무시되는 시나리오 처리(대개 구문 오류 때문)
- 파티션 테이블에 대한 힌트 작업

예제는 `EXPLAIN` 명령 출력을 통해 힌트가 쿼리 실행 계획에 어떻게 영향을 주는지 보여 줍니다.
