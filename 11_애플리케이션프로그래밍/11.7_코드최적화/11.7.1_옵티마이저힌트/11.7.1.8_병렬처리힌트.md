# 병렬 처리 힌트 (Parallelism hints) — EPAS 18 옵티마이저 힌트

> 원문: [EPAS v18 — Optimizing code › Using optimizer hints › Parallelism hints](https://www.enterprisedb.com/docs/epas/latest/application_programming/optimizing_code/05_optimizer_hints/07_parallelism_hints/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 힌트·파라미터·명령은 원문 그대로 보존했습니다.

## 개요

문서에 따르면 "*병렬 스캔(Parallel scanning)*은 여러 백그라운드 워커(background worker)를 사용하여 테이블 스캔을 동시에 수행"하여 쿼리 성능을 향상시키는 것입니다.

## 주요 힌트

시스템은 병렬 실행을 제어하는 두 가지 옵티마이저 힌트를 제공합니다.

1. **PARALLEL 힌트** — 지정된 테이블의 병렬 스캔을 강제
2. **NO_PARALLEL 힌트** — 병렬 스캔 사용을 방지

## 구문 (Syntax)

```sql
PARALLEL (<table> [ <parallel_degree> | DEFAULT ])
NO_PARALLEL (<table>)
```

## 구성 파라미터

`parallel_degree` 파라미터는 다음을 받습니다.
- 원하는 워커 수를 지정하는 양의 정수
- 최대 허용 워커를 사용하기 위한 `DEFAULT` 키워드
- 옵티마이저가 정도(degree)를 결정하도록 생략(설정된 경우 테이블의 `parallel_workers` 저장 파라미터를 존중)

실제 워커 수는 `max_parallel_workers_per_gather` 구성 설정을 결코 초과하지 않습니다.

## 실제 동작

정도 값 없이 `PARALLEL(pgbench_accounts)`를 지정하고 테이블에 `parallel_workers=3`이 설정되어 있으면, 쿼리 플래너는 3개의 워커를 사용합니다. 정도를 명시적으로 지정하거나 `DEFAULT`를 지정하면 이 테이블 수준 설정을 재정의합니다.

문서는 힌트에 명시적 병렬 정도나 `DEFAULT`를 지정하면 `parallel_workers` 저장 파라미터 구성을 대체함을 강조합니다.
