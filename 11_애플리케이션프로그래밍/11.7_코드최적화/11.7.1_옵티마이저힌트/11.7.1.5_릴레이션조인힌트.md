# 릴레이션 조인 힌트 (Joining relations hints) — EPAS 18 옵티마이저 힌트

> 원문: [EPAS v18 — Optimizing code › Using optimizer hints › Joining relations hints](https://www.enterprisedb.com/docs/epas/latest/application_programming/optimizing_code/05_optimizer_hints/04_joining_relations_hints/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 힌트·명령은 원문 그대로 보존했습니다.

## 개요

테이블을 조인할 때 EDB Postgres Advanced Server는 세 가지 조인 전략을 지원합니다. 문서에 따르면 다음이 포함됩니다.

- **중첩 루프 조인(Nested loop join)** — "한 테이블이 다른 조인된 테이블의 모든 행마다 한 번씩 스캔됩니다."
- **병합 정렬 조인(Merge sort join)** — "조인이 시작되기 전에 각 테이블이 조인 속성으로 정렬됩니다."
- **해시 조인(Hash join)** — "한 테이블이 스캔되고 그 조인 속성이 해시 테이블에 로드됩니다."

## 사용 가능한 옵티마이저 힌트

시스템은 조인 동작을 제어하는 여섯 가지 힌트를 제공합니다.

| 힌트 | 목적 |
|------|---------|
| `USE_HASH(table [...])` | 해시 조인 사용을 강제 |
| `NO_USE_HASH(table [...])` | 해시 조인 사용을 방지 |
| `USE_MERGE(table [...])` | 병합 정렬 조인 사용을 강제 |
| `NO_USE_MERGE(table [...])` | 병합 정렬 조인 사용을 방지 |
| `USE_NL(table [...])` | 중첩 루프 조인 사용을 강제 |
| `NO_USE_NL(table [...])` | 중첩 루프 조인 사용을 방지 |

## 실제 적용

문서는 이 힌트들이 쿼리 실행 계획을 어떻게 수정하는지 보여 줍니다. 예를 들어 두 테이블 조인에서 `/*+ USE_HASH(b) */`를 사용하면 해시 조인 전략이 생성되고, `NO_USE_HASH(a b)`는 플래너를 병합 조인 같은 대체 방법으로 유도합니다.

다중 테이블 조인은 단일 쿼리 내에서 서로 다른 릴레이션 쌍에 대해 서로 다른 조인 방법을 지정하기 위해 여러 힌트를 조합할 수 있습니다.
