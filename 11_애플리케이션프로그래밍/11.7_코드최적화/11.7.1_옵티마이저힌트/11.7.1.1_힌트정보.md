# 옵티마이저 힌트 정보 (About optimizer hints) — EPAS 18 옵티마이저 힌트

> 원문: [EPAS v18 — Optimizing code › Using optimizer hints › About optimizer hints](https://www.enterprisedb.com/docs/epas/latest/application_programming/optimizing_code/05_optimizer_hints/about_optimizer_hints/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 힌트·파라미터·명령·코드는 원문 그대로 보존했습니다.

옵티마이저 힌트(optimizer hint)는 `DELETE`, `INSERT`, `SELECT`, `UPDATE` 명령 바로 뒤에 오는 주석 형태의 구문에 포함된 하나 이상의 지시어(directive)입니다. 키워드는 결과 집합을 생성할 때 서버가 특정 계획을 사용하거나 피하도록 지시합니다.

## 개요 구문 (Synopsis)

```sql
{ DELETE | INSERT | SELECT | UPDATE } /*+ { <hint> [ <comment> ] } [...] */
  <statement_body>

{ DELETE | INSERT | SELECT | UPDATE } --+ { <hint> [ <comment> ] } [...]
  <statement_body>
```

`/*` 또는 `--` 여는 주석 기호 바로 뒤에 공백 없이 더하기 기호(+)가 와야 합니다. 그렇지 않으면 서버는 뒤따르는 토큰을 힌트로 해석하지 않습니다.

첫 번째 형식에서 힌트와 선택적 주석은 여러 줄에 걸칠 수 있습니다. 두 번째 형식에서는 모든 힌트와 주석이 한 줄에 있어야 합니다. 문(statement)의 나머지는 새 줄에서 시작해야 합니다.

## 설명 (Description)

**참고:**

- 데이터베이스 서버는 가능한 한 항상 지정된 힌트를 사용하려고 시도합니다.
- 플래너 메서드 파라미터가 특정 계획 유형을 비활성화하도록 설정되어 있으면, 힌트에 지정되어 있더라도 플래너에 다른 가능한 옵션이 없는 경우가 아니라면 그 계획은 사용되지 않습니다. 예로는 `enable_indexscan`, `enable_seqscan`, `enable_hashjoin`, `enable_mergejoin`, `enable_nestloop`이 있습니다. 이들은 모두 불리언 파라미터입니다.
- 힌트는 주석에 포함됩니다. 따라서 힌트의 철자가 틀리거나, 뷰·테이블·컬럼 이름 같은 힌트의 파라미터가 SQL 명령에서 잘못 쓰이거나 존재하지 않으면, 오류가 발생했다는 표시가 없습니다. 구문 오류가 제공되지 않습니다. 전체 힌트가 조용히 무시됩니다.
- SQL 명령에서 테이블 이름에 별칭(alias)을 사용한 경우, 힌트에서 원래 테이블 이름이 아니라 별칭 이름을 사용해야 합니다. 예를 들어 `SELECT /*+ FULL(acct) */ * FROM accounts acct ...` 명령에서는 `FULL` 힌트에 테이블 이름 `accounts`가 아니라 `accounts`의 별칭을 지정해야 합니다.

힌트가 올바르게 구성되었고 플래너가 힌트를 사용하고 있는지 확인하려면 `EXPLAIN` 명령을 사용하십시오.

일반적으로 애플리케이션의 수명 동안 테이블 데이터가 변경되는 프로덕션 애플리케이션에서는 옵티마이저 힌트 사용을 피하십시오. 동적으로 변하는 컬럼이 `ANALYZE` 명령을 통해 자주 분석되도록 하면, 값 변화를 반영하도록 컬럼 통계가 최신 상태로 유지됩니다. 플래너는 그러한 정보를 사용하여 주어진 명령 실행에 대해 가장 비용이 적은 계획을 생성합니다. 옵티마이저 힌트를 사용하면 이 과정이 무력화되어, 테이블 데이터가 어떻게 변하든 동일한 계획이 나오게 됩니다.

## 파라미터 (Parameters)

`hint`

옵티마이저 힌트 지시어.

`comment`

추가 정보를 담은 문자열. 주석에는 포함할 수 있는 문자에 제한이 있습니다. 일반적으로 `comment`는 알파벳, 숫자, 언더스코어, 달러 기호, 숫자 기호(#), 공백 문자로만 구성될 수 있습니다. 또한 식별자(identifier) 구문을 따라야 합니다. 주석이 이 형식이 아니면 이후의 모든 힌트가 무시됩니다.

`statement_body`

`DELETE`, `INSERT`, `SELECT`, 또는 `UPDATE` 명령의 나머지 부분.
