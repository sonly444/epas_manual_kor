# 전역 힌트 (Global hints) — EPAS 18 옵티마이저 힌트

> 원문: [EPAS v18 — Optimizing code › Using optimizer hints › Global hints](https://www.enterprisedb.com/docs/epas/latest/application_programming/optimizing_code/05_optimizer_hints/05_global_hints/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 힌트·명령·코드는 원문 그대로 보존했습니다.

## 개요

점 표기법(dot notation)을 사용하여 뷰나 하위 쿼리(subquery)에서 참조되는 테이블에 힌트를 적용할 수 있습니다. 힌트는 뷰 자체가 아니라 뷰를 참조하는 SQL 명령에 나타납니다.

## 개요 구문 (Synopsis)

```sql
<hint>(<view>.<table>)
```

## 파라미터 (Parameters)

| 파라미터 | 설명 |
|-----------|-------------|
| `hint` | 접근 방식 힌트 또는 릴레이션 조인 힌트 범주의 모든 힌트 |
| `view` | 대상 테이블을 포함하는 뷰의 이름 |
| `table` | 힌트를 적용할 테이블 |

## 예제: 저장된 뷰에 힌트 적용

세 테이블 조인으로 `tx`라는 뷰가 생성됩니다.

```sql
CREATE VIEW tx AS SELECT h.mtime, h.delta, b.bid, a.aid FROM pgbench_history
h, pgbench_branches b, pgbench_accounts a WHERE h.bid = b.bid AND h.aid =
a.aid;
```

점 표기법을 사용하여 힌트를 적용할 수 있습니다.

```sql
EXPLAIN SELECT /*+ USE_MERGE(tx.h tx.b) USE_HASH(tx.a) */ * FROM tx;
```

이는 history와 branches 테이블 간의 병합 조인 뒤에 accounts와의 해시 조인이 이어지는 쿼리 계획을 생성합니다.

## 하위 쿼리의 테이블에 힌트 적용

힌트는 하위 쿼리에서도 유사하게 동작합니다. `emp` 테이블을 사용한 이 예제에서:

```sql
EXPLAIN SELECT /*+ INDEX(b.emp emp_pk) */ a.empno, a.ename, b.empno "mgr
empno", b.ename "mgr ename" FROM emp a, (SELECT * FROM emp) b WHERE a.mgr =
b.empno;
```

이는 하위 쿼리 테이블에 대해 순차 스캔 대신 `emp_pk`를 사용한 인덱스 스캔을 강제합니다.
