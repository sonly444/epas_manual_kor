# 오류 처리 (Error handling) — EPAS 18 ECPGPlus

> 원문: [EPAS v18 — Application programming › Including embedded SQL commands › Error handling](https://www.enterprisedb.com/docs/epas/latest/application_programming/ecpgplus_guide/06_error_handling/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·지시어·구조체·멤버·코드·값은 원문 그대로 보존했습니다.

ECPGPlus는 임베디드 SQL 코드에서 오류를 감지하고 처리하는 두 가지 방법을 제공합니다. 클라이언트 애플리케이션은 다음을 할 수 있습니다.

- `sqlca` 데이터 구조에서 오류 메시지를 검사하고, 클라이언트 애플리케이션에 맞는 사용자 지정 오류 처리를 제공합니다.
- `EXEC SQL WHENEVER` 지시어를 포함하여 ECPGPlus 컴파일러가 오류 처리 코드를 추가하도록 지시합니다.

## sqlca를 이용한 오류 처리 (Error handling with sqlca)

SQL 통신 영역(`sqlca`, SQL communications area)은 `ecpglib`가 서버에서 클라이언트 애플리케이션으로 정보를 전달하는 데 사용하는 전역 변수입니다. `INSERT`나 `SELECT` 같은 SQL 문을 실행한 후, `sqlca`의 내용을 검사하여 문이 성공적으로 완료되었는지 또는 실패했는지 확인할 수 있습니다.

`sqlca`는 다음 구조를 갖습니다.

```c
struct
{
    char sqlcaid[8];
    long sqlabc;
    long sqlcode;
    struct
    {
        int sqlerrml;
        char sqlerrmc[SQLERRMC_LEN];
    } sqlerrm;
    char sqlerrp[8];
    long sqlerrd[6];
    char sqlwarn[8];
    char sqlstate[5];

} sqlca;
```

`sqlca` 기능을 구현하려면 다음 지시어를 사용합니다.

```sql
EXEC SQL INCLUDE sqlca;
```

이 `ecpg` 지시어를 포함하면 클라이언트 애플리케이션의 헤더 선언에서 `sqlca.h` 파일을 `#include`할 필요가 없습니다.

EDB Postgres Advanced Server `sqlca` 구조체는 다음 멤버를 포함합니다.

- `sqlcaid` — 문자열 `"SQLCA"`를 담습니다.

- `sqlabc` — `sqlabc`는 `sqlca` 구조체의 크기를 담습니다.

- `sqlcode` — `sqlcode` 멤버는 SQL 92에서 사용 중단(deprecated)되었습니다. EDB Postgres Advanced Server는 하위 호환성을 위해 `sqlcode`를 지원합니다. 새 코드를 작성할 때는 `sqlstate` 멤버를 사용하십시오.

`sqlcode`는 정수 값입니다. 양수 `sqlcode` 값은 클라이언트 애플리케이션이 무해한 처리 조건을 만났음을 나타냅니다. 음수 값은 경고 또는 오류를 나타냅니다.

문이 오류 없이 처리되면 `sqlcode`는 값 `0`을 담습니다. 클라이언트 애플리케이션이 문 실행 중 오류나 경고를 만나면 `sqlcode`는 마지막으로 반환된 코드를 담습니다. `MODE` = `-C PROC`를 사용할 때, 행을 하나도 삽입하지 않은 INSERT 문도 여전히 `sqlcode` = `0`을 반환하여 성공적 실행을 나타냅니다. 이 반환 코드는 실제로 행이 삽입되었는지 여부와 관계없이 문이 오류 없이 처리되었음을 반영합니다.

SQL 표준은 양수 값 100만 정의하는데, 이는 가장 최근에 처리된 SQL 문이 어떤 행도 반환하거나 영향을 주지 않았음을 나타냅니다. SQL 표준이 다른 `sqlcode` 값을 정의하지 않으므로, 각 조건에 할당되는 값은 데이터베이스마다 다를 수 있음에 유의하십시오.

`MODE = -C PROC`를 사용할 때, FETCH 문이 요청한 것보다 적은 행을 조회하면 `sqlcode` = `100`이 반환되어, 커서가 결과 집합의 끝에 도달했고 더 이상 사용 가능한 데이터가 없음을 나타냅니다.

`sqlerrm`은 `sqlca`에 내장된 구조체로, 두 멤버로 구성됩니다.

- `sqlerrml` — `sqlerrmc`에 현재 저장된 오류 메시지의 길이를 담습니다.

- `sqlerrmc` — `sqlstate`에 저장된 코드와 연관된, null로 종료되는 메시지 텍스트를 담습니다. 메시지가 149자를 초과하면 `ecpglib`가 오류 메시지를 자릅니다.

- `sqlerrp` — 문자열 `"NOT SET"`을 담습니다.

`sqlerrd`는 6개의 요소를 담는 배열입니다.

- `sqlerrd[1]` — 처리된 행의 OID를 담습니다(해당하는 경우).

- `sqlerrd[2]` — 처리되거나 반환된 행의 수를 담습니다.

- `sqlerrd[0]`, `sqlerrd[3]`, `sqlerrd[4]`, `sqlerrd[5]`는 미사용입니다.

`sqlwarn`은 8개의 문자를 담는 배열입니다.

- `sqlwarn[0]` — `sqlwarn`의 다른 요소 중 하나라도 `'W'`로 설정되어 있으면 값 `'W'`를 담습니다.

- `sqlwarn[1]` — 데이터 값이 호스트 변수에 저장될 때 잘렸으면 값 `'W'`를 담습니다.

- `sqlwarn[2]` — 클라이언트 애플리케이션이 치명적이지 않은(nonfatal) 경고를 만나면 값 `'W'`를 담습니다.

- `sqlwarn[3]`, `sqlwarn[4]`, `sqlwarn[5]`, `sqlwarn[6]`, `sqlwarn[7]`은 미사용입니다.

`sqlstate`는 클라이언트 애플리케이션의 문 실행 후 SQL 준수 상태 코드(SQL-compliant status code)를 담는 5자 배열입니다. 문이 오류 없이 처리되면 `sqlstate`는 값 `00000`을 담습니다. `sqlstate`는 null로 종료되는 문자열이 아닙니다.

`sqlstate` 코드는 계층적 체계로 할당됩니다.

- `sqlstate`의 처음 두 문자는 조건의 일반 클래스를 나타냅니다.
- `sqlstate`의 마지막 세 문자는 클래스 내의 특정 상태를 나타냅니다.

클라이언트 애플리케이션이 SQL 문 실행 중 여러 오류(또는 경고)를 만나면 `sqlstate`는 마지막으로 반환된 코드를 담습니다.

## 클라이언트 애플리케이션을 위한 간단한 오류 처리 구현 (Implementing simple error handling for client applications)

ECPGPlus로 컴파일된 클라이언트 애플리케이션에 대한 간단한 오류 처리를 구현하려면 `EXEC SQL WHENEVER` 지시어를 사용합니다. 지시어의 구문은 다음과 같습니다.

```sql
EXEC SQL WHENEVER <condition> <action>;
```

이 지시어는 ECPG 컴파일러가 프로그램에 오류 처리 코드를 삽입하도록 지시합니다.

이 코드는 클라이언트 애플리케이션이 주어진 조건(condition)을 감지하면 지정된 동작(action)을 수행하도록 지시합니다. *condition*은 다음 중 하나일 수 있습니다.

`SQLERROR`

`sqlca.sqlcode`가 0보다 작으면 `SQLERROR` 조건이 존재합니다.

`SQLWARNING`

`sqlca.sqlwarn[0]`이 `'W'`를 담고 있으면 `SQLWARNING` 조건이 존재합니다.

`NOT FOUND`

`sqlca.sqlcode`가 `ECPG_NOT_FOUND`이면(쿼리가 데이터를 반환하지 않으면) `NOT FOUND` 조건이 존재합니다.

앞의 조건 중 하나를 만나면 클라이언트 애플리케이션이 수행할 *action*으로 다음 중 하나를 지정할 수 있습니다.

`CONTINUE`

현재 `condition`을 무시하고 처리를 계속하도록 클라이언트 애플리케이션에 지시하려면 `CONTINUE`를 지정합니다. `CONTINUE`가 기본 동작입니다.

`DO CONTINUE`

`DO CONTINUE` 동작은 방출된(emitted) C 코드에 `CONTINUE` 문을 생성합니다. 조건을 만나면 루프의 나머지 코드를 건너뛰고 다음 반복을 계속합니다. 루프에서만 사용할 수 있습니다.

`GOTO label` 또는 `GO TO label`

C `goto` 문을 사용하여 지정된 `label`로 점프합니다.

`SQLPRINT`

`sqlprint()` 함수를 사용하여 `stderr`(표준 오류)에 오류 메시지를 출력합니다. `sqlprint()` 함수는 `sql error`에 이어 `sqlca.sqlerrm.sqlerrmc`의 내용을 출력합니다.

`STOP`

`exit(1)`을 호출하여 오류를 알리고 프로그램을 종료합니다.

`DO BREAK`

C `break` 문을 실행합니다. 이 동작은 루프나 `switch` 문에서 사용합니다.

`CALL name(args)` 또는 `DO name(args)`

`args` 파라미터에 지정된 파라미터를 사용하여, `name` 파라미터로 지정된 C 함수를 호출합니다.

## 예제 (Example)

다음 코드 조각은 클라이언트 애플리케이션이 경고를 만나면 메시지를 출력하고, 오류를 만나면 애플리케이션을 중단합니다.

```sql
EXEC SQL WHENEVER SQLWARNING SQLPRINT;
EXEC SQL WHENEVER SQLERROR STOP;
```

> **참고**
> ECPGPlus 컴파일러는 클라이언트 애플리케이션이 위에서 아래로 실행되지 않더라도, 프로그램을 위에서 아래로 처리합니다. 컴파일러 지시어는 각 줄에 순서대로 적용되며, 컴파일러가 다른 지시어를 만날 때까지 유효합니다. 프로그램의 흐름 제어가 위에서 아래가 아니라면, 컴파일 중 누락될 수 있는 프로그램의 부분에 오류 처리 지시어를 추가하는 것을 고려하십시오.
