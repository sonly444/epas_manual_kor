# 동적 SQL 문 작성 및 실행 (Building and executing dynamic SQL statements) — EPAS 18 ECPGPlus

> 원문: [EPAS v18 — Application programming › Including embedded SQL commands › Building and executing dynamic SQL statements](https://www.enterprisedb.com/docs/epas/latest/application_programming/ecpgplus_guide/05_building_executing_dynamic_sql_statements/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·지시어·이름·코드는 원문 그대로 보존했습니다.

다음 예제는 동적 SQL 문을 작성하고 실행하는 네 가지 기법을 보여줍니다. 각 예제는 서로 다른 문과 입력 유형의 조합을 처리하는 방법을 보여줍니다.

- 첫 번째 예제는 `SELECT` 문을 포함하지 않고 입력 변수가 필요 없는 SQL 문을 처리하고 실행하는 방법을 보여줍니다. 이 예제는 Oracle Dynamic SQL Method 1에서 사용하는 기법에 해당합니다.
- 두 번째 예제는 `SELECT` 문을 포함하지 않고 알려진 수의 입력 변수를 포함하는 SQL 문을 처리하고 실행하는 방법을 보여줍니다. 이 예제는 Oracle Dynamic SQL Method 2에서 사용하는 기법에 해당합니다.
- 세 번째 예제는 `SELECT` 문을 포함할 수 있고 알려진 수의 입력 변수를 포함하는 SQL 문을 처리하고 실행하는 방법을 보여줍니다. 이 예제는 Oracle Dynamic SQL Method 3에서 사용하는 기법에 해당합니다.
- 네 번째 예제는 `SELECT` 문을 포함할 수 있고 알 수 없는 수의 입력 변수를 포함하는 SQL 문을 처리하고 실행하는 방법을 보여줍니다. 이 예제는 Oracle Dynamic SQL Method 4에서 사용하는 기법에 해당합니다.

## 예제: 파라미터 없는 비쿼리 문 실행 (Executing a nonquery statement without parameters)

이 예제는 애플리케이션을 실행하기 전까지 문의 텍스트를 알 수 없는 SQL 문을 실행하기 위해 `EXECUTE IMMEDIATE` 명령을 사용하는 방법을 보여줍니다. 결과 집합을 반환하는 문을 실행하는 데는 `EXECUTE IMMEDIATE`를 사용할 수 없습니다. 파라미터 자리 표시자(placeholder)를 포함하는 문을 실행하는 데도 `EXECUTE IMMEDIATE`를 사용할 수 없습니다.

`EXECUTE IMMEDIATE` 문은 실행할 때마다 SQL 문을 파싱하고 계획(plan)하므로 애플리케이션 성능에 부정적인 영향을 줄 수 있습니다. 동일한 문을 반복적으로 실행할 계획이라면, 아래 "지정된 수의 자리 표시자를 가진 비쿼리 문 실행"에서 설명하는 `PREPARE/EXECUTE` 기법을 사용하는 것을 고려하십시오.

```c
/***********************************************************/
#include <stdio.h>
#include <string.h>
#include <stdlib.h>

static void handle_error(void);

int main(int argc, char *argv[])
{
  char    *insertStmt;

  EXEC SQL WHENEVER SQLERROR DO handle_error();

  EXEC SQL CONNECT :argv[1];

  insertStmt = "INSERT INTO dept VALUES(50, 'ACCTG', 'SEATTLE')";

  EXEC SQL EXECUTE IMMEDIATE :insertStmt;

  fprintf(stderr, "ok\n");

  EXEC SQL COMMIT RELEASE;

  exit(EXIT_SUCCESS);
}

static void handle_error(void)
{
  fprintf(stderr, "%s\n", sqlca.sqlerrm.sqlerrmc);

  EXEC SQL WHENEVER SQLERROR CONTINUE;
  EXEC SQL ROLLBACK RELEASE;

  exit(EXIT_FAILURE);
}

/***********************************************************/
```

## 예제: 지정된 수의 자리 표시자를 가진 비쿼리 문 실행 (Executing a nonquery statement with a specified number of placeholders)

알려진 수의 파라미터 자리 표시자를 포함하는 비쿼리 명령을 실행하려면, 먼저 문을 `PREPARE`(문 핸들(statement handle) 제공)한 다음 그 문 핸들을 사용하여 문을 `EXECUTE`해야 합니다. 애플리케이션이 문을 실행할 때, 문에서 발견된 각 자리 표시자에 대한 값을 제공해야 합니다.

애플리케이션이 `PREPARE/EXECUTE` 메커니즘을 사용하면, 각 SQL 문은 한 번 파싱·계획되지만 매번 다른 값을 제공하며 여러 번 실행될 수 있습니다.

ECPGPlus는 가능하면 각 파라미터 값을 SQL 문이 요구하는 타입으로 변환합니다. 그렇지 않으면 ECPGPlus는 오류를 보고합니다.

```c
/***********************************************************/
#include <stdio.h>
#include <string.h>
#include <stdlib.h>
#include <sqlca.h>

static void handle_error(void);

int main(int argc, char *argv[])
{
  char *stmtText;

  EXEC SQL WHENEVER SQLERROR DO handle_error();

  EXEC SQL CONNECT :argv[1];

  stmtText = "INSERT INTO dept VALUES(?, ?, ?)";

  EXEC SQL PREPARE stmtHandle FROM :stmtText;

  EXEC SQL EXECUTE stmtHandle USING :argv[2], :argv[3], :argv[4];

  fprintf(stderr, "ok\n");

  EXEC SQL COMMIT RELEASE;

  exit(EXIT_SUCCESS);

{
```

## 예제: 알려진 수의 자리 표시자를 가진 쿼리 실행 (Executing a query with a known number of placeholders)

이 예제는 알려진 수의 입력 파라미터와 알려진 수의 결과 집합 컬럼을 가진 쿼리를 실행하는 방법을 보여줍니다. 이 방법은 `PREPARE` 문을 사용하여 쿼리를 파싱·계획한 다음, 커서를 열고 결과 집합을 반복합니다.

> **저장 프로시저 호출에 관하여**
> 저장 프로시저는 `EXEC SQL PREPARE/EXECUTE`를 사용하는 동적 쿼리의 일부일 때 `CALL` 쿼리를 사용하여 실행할 수 없습니다. `CALL` 쿼리를 포함하려면 정적 SQL에서만 사용해야 합니다. 또한 SQL이 커뮤니티 버전의 PostgreSQL이 아니라 EPAS를 대상으로 하는지 확인하십시오.

```c
/***********************************************************/
#include <stdio.h>
#include <string.h>
#include <stdlib.h>
#include <stdbool.h>
#include <sqlca.h>

static void handle_error(void);

int main(int argc, char *argv[])
{
  VARCHAR  empno[10];
  VARCHAR  ename[20];

  EXEC SQL WHENEVER SQLERROR DO handle_error();

  EXEC SQL CONNECT :argv[1];

  EXEC SQL PREPARE queryHandle
    FROM "SELECT empno, ename FROM emp WHERE deptno = ?";

  EXEC SQL DECLARE empCursor CURSOR FOR queryHandle;

  EXEC SQL OPEN empCursor USING :argv[2];

  EXEC SQL WHENEVER NOT FOUND DO break;

  while(true)
  {

    EXEC SQL FETCH empCursor INTO :empno, :ename;

    printf("%-10s %s\n", empno.arr, ename.arr);
  }

  EXEC SQL CLOSE empCursor;

  EXEC SQL COMMIT RELEASE;

  exit(EXIT_SUCCESS);
}

static void handle_error(void)
{
  printf("%s\n", sqlca.sqlerrm.sqlerrmc);

  EXEC SQL WHENEVER SQLERROR CONTINUE;
  EXEC SQL ROLLBACK RELEASE;

  exit(EXIT_FAILURE);
}

/***********************************************************/
```

## 예제: 알 수 없는 수의 변수를 가진 쿼리 실행 (Executing a query with an unknown number of variables)

이 예제는 알 수 없는 수의 입력 파라미터 또는 결과 집합 컬럼을 가진 쿼리를 실행하는 것을 보여줍니다. 이런 유형의 쿼리는 쿼리 텍스트를 사용자에게 묻거나, 사용자가 여러 조건(즉, 필터) 중에서 선택하는 폼에서 쿼리가 조립될 때 발생할 수 있습니다.

```c
/***********************************************************/
#include <stdio.h>
#include <stdlib.h>
#include <sqlda.h>
#include <sqlcpr.h>

SQLDA *params;
SQLDA *results;

static void allocateDescriptors(int count,
                                int varNameLength,
                                int indNameLenth);
static void bindParams(void);
static void displayResultSet(void);

int main(int argc, char *argv[])
{
  EXEC SQL BEGIN DECLARE SECTION;
    char   *username = argv[1];
    char   *password = argv[2];
    char   *stmtText = argv[3];
  EXEC SQL END DECLARE SECTION;

  EXEC SQL WHENEVER SQLERROR sqlprint;

  EXEC SQL CONNECT TO test
    USER :username
    IDENTIFIED BY :password;

  params  = sqlald(20, 64, 64);
  results = sqlald(20, 64, 64);

  EXEC SQL PREPARE stmt FROM :stmtText;

  EXEC SQL DECLARE dynCursor CURSOR FOR stmt;

  bindParams();

  EXEC SQL OPEN dynCursor USING DESCRIPTOR params;

  displayResultSet();
}

static void bindParams(void)
{
  EXEC SQL DESCRIBE BIND VARIABLES FOR stmt INTO params;

  if (params->F < 0)
     fprintf(stderr, "Too many parameters required\n");
  else
  {
     int i;

     params->N = params->F;

     for (i = 0; i < params->F; i++)
     {
       char *paramName = params->S[i];
       int   nameLen   = params->C[i];
       char  paramValue[255];

       printf("Enter value for parameter %.*s: ",
               nameLen, paramName);

       fgets(paramValue, sizeof(paramValue), stdin);

       params->T[i] = 1;     /* Data type = Character (1) */
       params->L[i] = strlen(paramValue) - 1;
       params->V[i] = strdup(paramValue);
     }
  }
}

static void displayResultSet(void)
{
  EXEC SQL DESCRIBE SELECT LIST FOR stmt INTO results;

  if (results->F < 0)
     fprintf(stderr, "Too many columns returned by query\n");
  else if (results->F == 0)
     return;
  else
  {
     int col;

     results->N = results->F;

     for (col = 0; col < results->F; col++)
     {
       int null_permitted, length;

       sqlnul(&results->T[col],
              &results->T[col],
              &null_permitted);

       switch (results->T[col])
       {
          case 2:        /* NUMERIC */
          {
            int precision, scale;

            sqlprc(&results->L[col], &precision, &scale);

            if (precision == 0)
               precision = 38;

            length = precision + 3;
            break;
           }

          case 12:   /* DATE */
          {
            length = 30;
            break;
          }

          default:   /* Others */
          {
            length = results->L[col] + 1;
            break;
          }
       }

       results->V[col] = realloc(results->V[col], length);
       results->L[col] = length;
       results->T[col] = 1;
     }

     EXEC SQL WHENEVER NOT FOUND DO break;

     while (1)
     {
       const char *delimiter = "";

       EXEC SQL FETCH dynCursor USING DESCRIPTOR results;

       for (col = 0; col < results->F; col++)
       {
          if (*results->I[col] == -1)
            printf("%s%s", delimiter, "<null>");
          else
            printf("%s%s", delimiter, results->V[col]);
          delimiter = ", ";
       }

 printf("\n");
      }
  }
}
/***********************************************************/
```

코드 샘플은 먼저 C `stdio`와 `stdlib` 라이브러리의 프로토타입과 타입 정의를 포함합니다. 또한 프로그램은 `sqlda.h`와 `sqlcpr.h` 헤더 파일을 포함합니다. `sqlda.h`는 이 예제 전반에서 사용되는 SQLDA 구조를 정의합니다. `sqlcpr.h`는 SQLDA 구조에서 발견된 메타데이터를 조회하는 데 사용되는 작은 함수 집합을 정의합니다.

```c
#include <stdio.h>
#include <stdlib.h>
#include <sqlda.h>
#include <sqlcpr.h>
```

다음으로, 프로그램은 두 개의 SQLDA 구조에 대한 포인터를 선언합니다. 첫 번째 SQLDA 구조(`params`)는 동적 쿼리 텍스트에서 발견된 파라미터 마커에 대한 메타데이터를 기술하는 데 사용됩니다. 두 번째 SQLDA 구조(`results`)는 동적 쿼리를 실행하여 얻은 메타데이터와 결과 집합을 모두 담습니다.

```sql
SQLDA *params;
SQLDA *results;
```

그런 다음 프로그램은 코드 샘플 끝부분에 정의된 두 개의 헬퍼 함수를 선언합니다.

```c
static void bindParams(void);
static void displayResultSet(void);
```

다음으로, 프로그램은 세 개의 호스트 변수를 선언합니다. 처음 두 개(`username`과 `password`)는 데이터베이스 서버에 연결하는 데 사용됩니다. 세 번째 호스트 변수(`stmtTxt`)는 실행할 쿼리의 텍스트를 담는 NULL로 종료되는 C 문자열입니다. 이 세 호스트 변수의 값은 명령줄 인수에서 파생됩니다. 프로그램이 실행을 시작하면 오류 핸들러를 설정한 다음 데이터베이스 서버에 연결합니다.

```c
int main(int argc, char *argv[])
{
  EXEC SQL BEGIN DECLARE SECTION;
    char *username = argv[1];
    char *password = argv[2];
    char *stmtText = argv[3];
  EXEC SQL END DECLARE SECTION;

  EXEC SQL WHENEVER SQLERROR sqlprint;
  EXEC SQL CONNECT TO test
    USER :username
    IDENTIFIED BY :password;
```

다음으로, 프로그램은 `sqlald()` 함수를 호출하여 각 디스크립터에 필요한 메모리를 할당합니다. 각 디스크립터는 다음 배열에 대한 포인터를 담습니다.

- 컬럼 이름
- 지시자 이름
- 데이터 타입
- 길이
- 데이터 값

`SQLDA` 디스크립터를 할당할 때, 결과 집합에서 예상하는 최대 컬럼 수(`SELECT`-목록 디스크립터의 경우) 또는 동적 쿼리 텍스트에서 예상하는 최대 파라미터 수(바인드-변수 디스크립터의 경우)를 지정합니다. 이 경우 20개 이하의 컬럼과 20개 이하의 파라미터를 예상한다고 지정합니다. 또한 각 컬럼 또는 파라미터 이름과 각 지시자 변수 이름의 최대 길이를 지정해야 합니다. 이 경우 이름이 64바이트 이하일 것으로 예상합니다.

`SQLDA` 구조에 대한 전체 설명은 [SQLDA 구조(SQLDA structure)](https://www.enterprisedb.com/docs/epas/latest/reference/application_programmer_reference/07_reference/)를 참고하십시오.

```c
params = sqlald(20, 64, 64);
results = sqlald(20, 64, 64);
```

`SELECT`-목록 및 바인드 디스크립터를 할당한 후, 프로그램은 동적 문을 준비하고 결과 집합에 대한 커서를 선언합니다.

```sql
EXEC SQL PREPARE stmt FROM :stmtText;

EXEC SQL DECLARE dynCursor CURSOR FOR stmt;
```

다음으로, 프로그램은 `bindParams()` 함수를 호출합니다. `bindParams()` 함수는 바인드 디스크립터(`params`)를 검사하고, 동적 쿼리에서 발견된 각 파라미터 마커 대신 대입할 값을 사용자에게 묻습니다.

```c
bindParams();
```

마지막으로, 프로그램은 (사용자가 제공한 파라미터 값을 사용하여) 커서를 열고, 쿼리가 생성한 결과 집합을 출력하기 위해 `displayResultSet()` 함수를 호출합니다.

```sql
EXEC SQL OPEN dynCursor USING DESCRIPTOR params;

displayResultSet();
}
```

`bindParams()` 함수는 동적 쿼리에 파라미터 마커가 포함되어 있는지 확인합니다. 포함되어 있으면 각 파라미터에 대한 값을 사용자에게 묻고 그 값을 해당 마커에 바인딩합니다. `DESCRIBE BIND VARIABLE` 문은 각 파라미터 마커를 기술하는 정보로 `params` SQLDA 구조를 채웁니다.

```c
static void bindParams(void)
{
  EXEC SQL DESCRIBE BIND VARIABLES FOR stmt INTO params;
```

문에 파라미터 마커가 없으면 `params->F`는 0을 담습니다. 문에 디스크립터에 들어갈 수 있는 것보다 많은 파라미터가 포함되어 있으면 `params->F`는 음수를 담습니다. 이 경우 `params->F`의 절댓값이 문에서 발견된 파라미터 마커의 수를 나타냅니다. `params->F`가 양수를 담고 있으면 그 수가 문에서 발견된 파라미터 마커의 수를 나타냅니다.

```c
if (params->F < 0)
   fprintf(stderr, "Too many parameters required\n");
else
{
   int i;

   params->N = params->F;
```

다음으로, 프로그램은 문에서 발견된 각 파라미터 마커에 대해 한 번씩 반복하며 사용자에게 값을 묻는 루프를 실행합니다.

```c
for (i = 0; i < params->F; i++)
{
  char *paramName = params->S[i];
  int nameLen = params->C[i];
  char paramValue[255];

  printf("Enter value for parameter %.*s: ",
          nameLen, paramName);

  fgets(paramValue, sizeof(paramValue), stdin);
```

주어진 파라미터에 대한 값을 사용자에게 물은 후, 프로그램은 다음을 설정하여 그 값을 파라미터에 바인딩합니다.

- `params->T[i]` — 값의 데이터 타입을 나타냅니다.
- `params->L[i]` — 값의 길이(`fgets()`가 추가한 끝의 개행 문자를 잘라내기 위해 1을 뺍니다).
- `params->V[i]` — 사용자가 제공한 NULL로 종료되는 문자열의 복사본을 가리킵니다.

```c
     params->T[i] = 1;        /* Data type = Character (1) */
     params->L[i] = strlen(paramValue) + 1;
     params->V[i] = strdup(paramValue);
    }
  }
}
```

`displayResultSet()` 함수는 결과 집합의 각 행을 반복하며 각 컬럼에서 발견된 값을 출력합니다. `displayResultSet()`은 먼저 `DESCRIBE SELECT LIST` 문을 실행합니다. 이 문은 결과 집합의 각 컬럼에 대한 설명으로 SQLDA 디스크립터(`results`)를 채웁니다.

```c
static void displayResultSet(void)
{
  EXEC SQL DESCRIBE SELECT LIST FOR stmt INTO results;
```

동적 문이 컬럼을 반환하지 않으면(즉, 동적 문이 `SELECT` 문이 아니면) `results->F`는 0을 담습니다. 문이 디스크립터에 들어갈 수 있는 것보다 많은 컬럼을 반환하면 `results->F`는 음수를 담습니다. 이 경우 `results->F`의 절댓값이 문이 반환한 컬럼의 수를 나타냅니다. `results->F`가 양수를 담고 있으면 그 수가 쿼리가 반환한 컬럼의 수를 나타냅니다.

```c
if (results->F < 0)
   fprintf(stderr, "Too many columns returned by query\n");
else if (results->F == 0)
   return;
else
{
   int col;

   results->N = results->F;
```

다음으로, 프로그램은 결과 집합의 각 컬럼에 대해 한 번씩 반복하는 루프에 진입합니다.

```c
for (col = 0; col < results->F; col++)
{
  int null_permitted, length;
```

`results->T`에서 발견된 타입 코드를 디코딩하기 위해, 프로그램은 `sqlnul()` 함수를 호출합니다([SQLDA 구조(The SQLDA structure)](https://www.enterprisedb.com/docs/epas/latest/reference/application_programmer_reference/07_reference/)의 `T` 멤버 설명 참조). 이 `sqlnul()` 호출은 `results->T[col]`을 타입 코드만 담도록 수정합니다(널 허용 여부 플래그는 `null_permitted`로 복사됩니다). 이 단계는 `DESCRIBE SELECT LIST` 문이 각 컬럼의 타입과 각 컬럼의 널 허용 여부를 `T` 배열에 인코딩하기 때문에 필요합니다.

```c
sqlnul(&results->T[col],
       &results->T[col],
       &null_permitted);
```

컬럼의 실제 데이터 타입을 디코딩한 후, 프로그램은 ECPGPlus가 각 값을 NULL로 종료되는 문자열 형태로 반환하도록 results 디스크립터를 수정합니다. 디스크립터를 수정하기 전에, 프로그램은 각 값을 담는 데 필요한 공간의 양을 계산해야 합니다. 이 계산을 위해, 프로그램은 각 컬럼의 최대 길이(`results->V[col]`)와 각 컬럼의 데이터 타입(`results->T[col]`)을 검사합니다.

숫자 값(`results->T[col] = 2`)의 경우, 프로그램은 `sqlprc()` 함수를 호출하여 컬럼 길이에서 정밀도(precision)와 스케일(scale)을 추출합니다. 문자열 형태로 숫자 값을 담는 데 필요한 바이트 수를 계산하기 위해, `displayResultSet()`은 정밀도(즉, 최대 자릿수)에서 시작하여 부호 문자, 소수점, NULL 종료 문자를 위해 3바이트를 추가합니다.

```c
switch (results->T[col])
{
   case 2:          /* NUMERIC */
   {
     int precision, scale;

     sqlprc(&results->L[col], &precision, &scale);

     if (precision == 0)
        precision = 38;
     length = precision + 3;
     break;
   }
```

날짜 값의 경우, 프로그램은 하드코딩된 길이 30을 사용합니다. 실제 애플리케이션에서는 필요한 공간의 양을 더 신중하게 계산하고 싶을 수 있습니다.

```c
case 12:     /* DATE */
{
  length = 30;
  break;
}
```

날짜나 숫자 이외의 타입 값의 경우, `displayResultSet()`은 `DESCRIBE SELECT LIST`가 보고한 최대 컬럼 너비에서 시작하여 NULL 종료 문자를 위해 1바이트를 추가합니다. 마찬가지로, 실제 애플리케이션에서는 다른 데이터 타입에 대해 더 신중한 계산을 포함하고 싶을 수 있습니다.

```c
default:    /* Others */
{
  length = results->L[col] + 1;
  break;
}
}
```

주어진 컬럼을 담는 데 필요한 공간의 양을 계산한 후, 프로그램은 다음을 수행합니다.

- 값을 담기에 충분한 메모리를 할당합니다.
- `results->L[col]`을 `results->V[col]`에서 발견된 바이트 수를 나타내도록 설정합니다.
- 컬럼의 타입 코드(`results->T[col]`)를 `1`로 설정하여, 다가오는 `FETCH` 문이 값을 NULL로 종료되는 문자열 형태로 반환하도록 지시합니다.

```c
  results->V[col] = malloc(length);
  results->L[col] = length;
  results->T[col] = 1;
}
```

이 시점에서 results 디스크립터는 `FETCH` 문이 각 값을 NULL로 종료되는 문자열 형태로 적절한 크기의 버퍼에 복사할 수 있도록 구성됩니다.

다음으로, 프로그램은 커서가 소진되었을 때 다가오는 루프에서 빠져나오기 위한 새 오류 핸들러를 정의합니다.

```sql
EXEC SQL WHENEVER NOT FOUND DO break;

while (1)
{
  const char *delimiter = "";
```

프로그램은 `FETCH` 문을 실행하여 커서의 다음 행을 `results` 디스크립터로 페치합니다. `FETCH` 문이 (커서가 소진되어) 실패하면, 루프 시작 부분 앞에 있는 `EXEC SQL WHENEVER` 지시어 때문에 제어가 루프 끝으로 이동합니다.

`EXEC SQL FETCH dynCursor USING DESCRIPTOR results;`

`FETCH` 문은 results 디스크립터의 다음 멤버를 채웁니다.

- `*results->I[col]` — 컬럼이 NULL 값(`-1`)을 담는지 NULL이 아닌 값(`0`)을 담는지 나타냅니다. 값이 NULL이 아니지만 제공된 공간에 맞지 않을 만큼 크면 값이 잘리고, `*results->I[col]`은 양수 값을 담습니다.
- `results->V[col]` — 주어진 컬럼에 대해 페치된 값을 담습니다(`*results->I[col]`이 컬럼 값이 NULL임을 나타내는 경우 제외).
- `results->L[col]` — 주어진 컬럼에 대해 페치된 값의 길이를 담습니다.

마지막으로, `displayResultSet()`은 결과 집합의 각 컬럼을 반복하며 해당 NULL 지시자를 검사하고 값을 출력합니다. 결과 집합은 정렬되지 않습니다. 대신 각 값은 이전 값과 쉼표로 구분됩니다.

```c
for (col = 0; col < results->F; col++)
{
   if (*results->I[col] == -1)
     printf("%s%s", delimiter, "<null>");
   else
     printf("%s%s", delimiter, results->V[col]);
   delimiter = ", ";
}

printf("\n");
}
}
}
```
