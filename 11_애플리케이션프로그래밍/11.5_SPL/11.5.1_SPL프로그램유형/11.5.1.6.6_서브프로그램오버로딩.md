# 서브프로그램 오버로딩 (Overloading subprograms) — EPAS 18 SPL

> 원문: [EPAS v18 — SPL › Subprograms › Overloading subprograms](https://www.enterprisedb.com/docs/epas/latest/application_programming/epas_compat_spl/02_spl_programs/07_subprograms_subprocedures_and_subfunctions/06_overloading_subprograms/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 타입·키워드 이름은 원문 그대로 보존했습니다.

일반적으로, 동일한 타입(서브프로시저 또는 서브함수)이면서 동일한 이름과 동일한 형식 매개변수 사양을 가진 서브프로그램은, 형제 블록이 아닌 한(즉, 서브프로그램이 동일한 지역 블록에 선언되지 않은 한) 동일한 독립 프로그램 안에 여러 번 나타날 수 있습니다.

한정자의 사용과 서브프로그램 호출이 이루어지는 위치에 따라 각 서브프로그램을 개별적으로 호출할 수 있습니다.

그러나 형식 매개변수의 특정 측면이 다르다면, 형제로서라도 동일한 서브프로그램 타입과 이름을 가진 서브프로그램을 선언하는 것이 가능합니다. 이러한 특성(서브프로그램 타입, 이름, 형식 매개변수 사양)은 일반적으로 프로그램의 _시그니처(signature)_ 로 알려져 있습니다.

형식 매개변수 사양의 특정 측면을 제외하고 시그니처가 동일한 여러 서브프로그램을 선언하는 것을 서브프로그램 _오버로딩(overloading)_ 이라고 합니다.

## 요구 사항

호출할 특정 오버로딩 서브프로그램은 서브프로그램 호출로 지정된 실제 매개변수와 오버로딩된 서브프로그램들의 형식 매개변수 목록 간의 일치에 의해 결정됩니다.

다음 차이 중 하나라도 있으면 서브프로그램 오버로딩이 허용됩니다.

- 형식 매개변수의 개수가 다른 경우
- 대응하는 형식 매개변수(즉, 형식 매개변수 목록에서 동일한 출현 순서에 따라 비교됨)의 데이터 타입 쌍 중 적어도 하나가 다르지만 별칭(alias)이 아닌 경우

다음 차이만으로는 서브프로그램 오버로딩이 허용되지 않습니다.

- 형식 매개변수 이름이 다름
- 대응하는 형식 매개변수의 매개변수 모드(`IN`, `IN OUT`, `OUT`)가 다름
- 서브함수의 경우, `RETURN` 절의 데이터 타입이 다름

서브프로그램 오버로딩을 허용하는 차이 중 하나는 데이터 타입이 다른 것입니다.

## 별칭 사용

특정 데이터 타입에는 _별칭(alias)_ 이라고 하는 대체 이름이 있으며, 이는 테이블 정의에 사용할 수 있습니다.

예를 들어, 고정 길이 문자 데이터 타입은 `CHAR` 또는 `CHARACTER`로 지정할 수 있습니다. 가변 길이 문자 데이터 타입은 `CHAR VARYING`, `CHARACTER VARYING`, `VARCHAR`, 또는 `VARCHAR2`로 지정할 수 있습니다. 정수의 경우 `BINARY_INTEGER`, `PLS_INTEGER`, `INTEGER` 데이터 타입이 있습니다. 숫자의 경우 `NUMBER`, `NUMERIC`, `DEC`, `DECIMAL` 데이터 타입이 있습니다.

EDB Postgres Advanced Server가 지원하는 데이터 타입에 대한 자세한 내용은 [Data types](https://www.enterprisedb.com/docs/epas/latest/reference/sql_reference/02_data_types/)를 참조하십시오.

따라서 오버로딩된 서브프로그램을 생성하려고 할 때, 지정된 데이터 타입이 서로의 별칭이면 형식 매개변수 데이터 타입은 다른 것으로 간주되지 않습니다.

특정 데이터 타입이 다른 타입의 별칭인지 여부는 해당 데이터 타입을 포함하는 테이블 정의를 표시하여 확인할 수 있습니다.

## 예제: 데이터 타입과 별칭

다음 테이블 정의에는 일부 데이터 타입과 그 별칭이 포함되어 있습니다.

```sql
CREATE TABLE data_type_aliases (
    dt_BLOB             BLOB,
    dt_LONG_RAW         LONG RAW,
    dt_RAW              RAW(4),
    dt_BYTEA            BYTEA,
    dt_INTEGER          INTEGER,
    dt_BINARY_INTEGER   BINARY_INTEGER,
    dt_PLS_INTEGER      PLS_INTEGER,
    dt_REAL             REAL,
    dt_DOUBLE_PRECISION DOUBLE PRECISION,
    dt_FLOAT            FLOAT,
    dt_NUMBER           NUMBER,
    dt_DECIMAL          DECIMAL,
    dt_NUMERIC          NUMERIC,
    dt_CHAR             CHAR,
    dt_CHARACTER        CHARACTER,
    dt_VARCHAR2         VARCHAR2(4),
    dt_CHAR_VARYING     CHAR VARYING(4),
    dt_VARCHAR          VARCHAR(4)
);
```

PSQL `\d` 명령을 사용하여 테이블 정의를 표시하면, Type 열은 테이블 정의의 데이터 타입에 기반하여 각 열에 내부적으로 할당된 데이터 타입을 표시합니다.

```sql
\d data_type_aliases
       Column        |         Type         | Modifiers
---------------------+----------------------+-----------
 dt_blob             | bytea                |
 dt_long_raw         | bytea                |
 dt_raw              | bytea(4)             |
 dt_bytea            | bytea                |
 dt_integer          | integer              |
 dt_binary_integer   | integer              |
 dt_pls_integer      | integer              |
 dt_real             | real                 |
 dt_double_precision | double precision     |
 dt_float            | double precision     |
 dt_number           | numeric              |
 dt_decimal          | numeric              |
 dt_numeric          | numeric              |
 dt_char             | character(1)         |
 dt_character        | character(1)         |
 dt_varchar2         | character varying(4) |
 dt_char_varying     | character varying(4) |
 dt_varchar          | character varying(4) |
```

이 예제에서 데이터 타입의 기본 집합은 `bytea`, `integer`, `real`, `double precision`, `numeric`, `character`, `character varying`입니다.

오버로딩된 서브프로그램을 선언하려고 할 때, 별칭인 형식 매개변수 데이터 타입 쌍은 서브프로그램 오버로딩을 허용하기에 충분하지 않습니다. 따라서 데이터 타입 `INTEGER`와 `PLS_INTEGER`를 가진 매개변수는 서브프로그램 쌍을 오버로딩할 수 없습니다. 그러나 데이터 타입 `INTEGER`와 `REAL`, `INTEGER`와 `FLOAT`, 또는 `INTEGER`와 `NUMBER`는 서브프로그램을 오버로딩할 수 있습니다.

> **참고**
>
> 형식 매개변수 데이터 타입에 기반한 오버로딩 규칙은 Oracle 데이터베이스와 호환되지 않습니다. 일반적으로 EDB Postgres Advanced Server의 규칙이 더 유연하며, Oracle 데이터베이스에서 프로시저나 함수를 생성하려고 할 때 오류를 발생시키는 특정 조합이 EDB Postgres Advanced Server에서는 허용됩니다.
>
> 오버로딩에 사용되는 특정 데이터 타입 쌍의 경우, 서브프로그램 실행 중에 발생하는 오류를 피하기 위해 서브프로그램 호출로 지정된 인수를 캐스팅해야 할 수 있습니다. 서브프로그램을 호출하려면 데이터 타입을 구체적으로 식별할 수 있는 실제 매개변수 목록을 포함해야 합니다. 특정 오버로딩된 데이터 타입 쌍은 데이터 타입을 명시적으로 식별하기 위해 `CAST` 함수가 필요할 수 있습니다. 예를 들어 호출 중에 캐스팅이 필요할 수 있는 오버로딩된 데이터 타입 쌍은 `CHAR`와 `VARCHAR2`, 또는 `NUMBER`와 `REAL`입니다.

## 예제: 오버로딩된 서브함수

이 예제는 익명 블록에서 호출되는 오버로딩된 서브함수 그룹을 보여 줍니다. 익명 블록의 실행 섹션에는 특정 데이터 타입으로 오버로딩된 함수를 호출하기 위한 `CAST` 함수의 사용이 포함되어 있습니다.

```sql
DECLARE
    FUNCTION add_it (
        p_add_1     IN BINARY_INTEGER,
        p_add_2     IN BINARY_INTEGER
    ) RETURN VARCHAR2
    IS
    BEGIN
        RETURN 'add_it BINARY_INTEGER: ' || TO_CHAR(p_add_1 + p_add_2,9999.9999);
    END add_it;
    FUNCTION add_it (
        p_add_1     IN NUMBER,
        p_add_2     IN NUMBER
    ) RETURN VARCHAR2
    IS
    BEGIN
        RETURN 'add_it NUMBER: ' || TO_CHAR(p_add_1 + p_add_2,999.9999);
    END add_it;
    FUNCTION add_it (
        p_add_1     IN REAL,
        p_add_2     IN REAL
    ) RETURN VARCHAR2
    IS
    BEGIN
        RETURN 'add_it REAL: ' || TO_CHAR(p_add_1 + p_add_2,9999.9999);
    END add_it;
    FUNCTION add_it (
        p_add_1     IN DOUBLE PRECISION,
        p_add_2     IN DOUBLE PRECISION
    ) RETURN VARCHAR2
    IS
    BEGIN
        RETURN 'add_it DOUBLE PRECISION: ' || TO_CHAR(p_add_1 + p_add_2,9999.9999);
    END add_it;
BEGIN
    DBMS_OUTPUT.PUT_LINE(add_it (25, 50));
    DBMS_OUTPUT.PUT_LINE(add_it (25.3333, 50.3333));
    DBMS_OUTPUT.PUT_LINE(add_it (TO_NUMBER(25.3333), TO_NUMBER(50.3333)));
    DBMS_OUTPUT.PUT_LINE(add_it (CAST('25.3333' AS REAL), CAST('50.3333' AS REAL)));
    DBMS_OUTPUT.PUT_LINE(add_it (CAST('25.3333' AS DOUBLE PRECISION),
        CAST('50.3333' AS DOUBLE PRECISION)));
END;
```

익명 블록에서 표시되는 출력은 다음과 같습니다.

Output

```text
add_it BINARY_INTEGER:    75.0000
add_it NUMBER:   75.6666
add_it NUMBER:   75.6666
add_it REAL:    75.6666
add_it DOUBLE PRECISION:    75.6666
```
