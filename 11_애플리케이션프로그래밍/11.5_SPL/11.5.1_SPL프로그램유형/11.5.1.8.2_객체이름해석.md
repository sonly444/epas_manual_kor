# 데이터베이스 객체 이름 해석 (Database object name resolution) — EPAS 18 SPL

> 원문: [EPAS v18 — SPL › Program security › Database object name resolution](https://www.enterprisedb.com/docs/epas/latest/application_programming/epas_compat_spl/02_spl_programs/09_program_security/02_database_object_name_resolution/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·식별자 이름은 원문 그대로 보존했습니다.

SPL 프로그램 내부에서 데이터베이스 객체를 참조할 때는 정규화된 이름(qualified name) 또는 정규화되지 않은 이름(unqualified name)으로 참조할 수 있습니다. 정규화된 이름은 `schema.name` 형식이며, 여기서 `schema`는 식별자 `name`을 가진 데이터베이스 객체가 존재하는 스키마의 이름입니다. 정규화되지 않은 이름에는 `schema.` 부분이 없습니다. 정규화된 이름으로 참조하면 어떤 데이터베이스 객체를 의도하는지에 대한 모호함이 없습니다. 지정된 스키마에 해당 객체가 존재하거나 존재하지 않을 뿐입니다.

하지만 정규화되지 않은 이름으로 객체를 찾으려면 현재 사용자의 검색 경로(search path)를 사용해야 합니다. 사용자가 세션의 현재 사용자가 되면, 항상 기본 검색 경로가 해당 사용자와 연결됩니다. 검색 경로는 정규화되지 않은 데이터베이스 객체 참조를 찾기 위해 왼쪽에서 오른쪽 순서로 검색되는 스키마 목록으로 구성됩니다. 검색 경로의 어떤 스키마에서도 객체를 찾을 수 없으면 그 객체는 존재하지 않는 것으로 간주됩니다. PSQL에서 `SHOW search_path` 명령을 사용하여 기본 검색 경로를 표시할 수 있습니다.

```sql
edb=# SHOW search_path;
```

출력

```text
   search_path
-----------------
 "$user", public
(1 row)
```

검색 경로의 `$user`는 현재 사용자를 가리키는 일반 자리 표시자(placeholder)입니다. 따라서 이 세션의 현재 사용자가 `enterprisedb`라면, 정규화되지 않은 데이터베이스 객체는 다음 순서로 스키마에서 검색됩니다. 먼저 `enterprisedb`에서, 그다음 `public`에서 검색됩니다.

검색 경로에서 정규화되지 않은 이름이 해석되고 나면, 현재 사용자가 해당 특정 객체에 대해 원하는 작업을 수행할 적절한 권한을 가지고 있는지 판단할 수 있습니다.

> **참고**
>
> 검색 경로 개념은 Oracle 데이터베이스와 호환되지 않습니다. 정규화되지 않은 참조의 경우, Oracle은 명명된 데이터베이스 객체를 현재 사용자의 스키마에서 찾습니다. 또한 Oracle에서는 사용자와 그 스키마가 동일한 엔터티입니다. EDB Postgres Advanced Server에서는 사용자와 스키마가 서로 다른 두 개의 객체입니다.
