# 보안 예제 (Security example) — EPAS 18 SPL

> 원문: [EPAS v18 — SPL › Program security › Security example](https://www.enterprisedb.com/docs/epas/latest/application_programming/epas_compat_spl/02_spl_programs/09_program_security/05_security_example/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·식별자 이름은 원문 그대로 보존했습니다.

이 예제에서는 두 명의 사용자와 함께 새 데이터베이스를 생성합니다.

- `– hr_mgr`. 스키마 `hr_mgr`에 전체 샘플 애플리케이션의 복사본을 소유합니다.
- `sales_mgr`. `sales_mgr`라는 스키마를 소유하며, 이 스키마에는 영업 부서에서 근무하는 직원만 포함하는 `emp` 테이블의 복사본만 들어 있습니다.

이 예제에서는 프로시저 `list_emp`, 함수 `hire_clerk`, 패키지 `emp_admin`을 사용합니다. 샘플 애플리케이션을 설치할 때 부여되는 모든 기본 권한을 제거한 다음, 더 안전한 환경을 제시하기 위해 명시적으로 다시 부여합니다.

프로그램 `list_emp`와 `hire_clerk`는 기본값인 정의자 권한(definer's rights)에서 호출자 권한(invoker's rights)으로 변경됩니다. 그러면 `sales_mgr`가 이 프로그램들을 실행할 때, 이름 해석과 권한 검사에 `sales_mgr`의 검색 경로와 권한이 사용되므로 이 프로그램들은 `sales_mgr` 스키마의 `emp` 테이블에 대해 작동합니다.

그런 다음 `emp_admin` 패키지의 프로그램 `get_dept_name`과 `hire_emp`를 `sales_mgr`가 실행합니다. 이 경우, `hr_mgr`가 정의자 권한을 사용하는 `emp_admin` 패키지의 소유자이므로 `hr_mgr` 스키마의 `dept` 테이블과 `emp` 테이블에 접근합니다. `$user` 자리 표시자(placeholder)를 사용하는 기본 검색 경로가 적용되므로, 사용자와 일치하는 스키마(이 경우 `hr_mgr`)를 사용하여 테이블을 찾습니다.

## 1단계: 데이터베이스와 사용자 생성

사용자 `enterprisedb`로, `hr` 데이터베이스를 생성합니다.

```sql
CREATE DATABASE hr;
```

hr 데이터베이스로 전환하고 사용자를 생성합니다.

```sql
\c hr enterprisedb
CREATE USER hr_mgr IDENTIFIED BY password;
CREATE USER sales_mgr IDENTIFIED BY password;
```

## 2단계: 샘플 애플리케이션 생성

`hr_mgr` 스키마에, `hr_mgr`가 소유하는 전체 샘플 애플리케이션을 생성합니다.

```sql
\c - hr_mgr
\i /usr/edb/as18/share/edb-sample.sql

BEGIN
CREATE TABLE
CREATE TABLE
CREATE TABLE
CREATE VIEW
CREATE SEQUENCE
        .
        .
        .
CREATE PACKAGE
CREATE PACKAGE BODY
COMMIT
```

## 3단계: 스키마 sales_mgr에 emp 테이블 생성

`sales_mgr` 스키마에 `sales_mgr`가 소유하는 `emp` 테이블의 부분 집합을 생성합니다.

```sql
\c – hr_mgr
GRANT USAGE ON SCHEMA hr_mgr TO sales_mgr;
\c – sales_mgr
CREATE TABLE emp AS SELECT * FROM hr_mgr.emp WHERE job = 'SALESMAN';
```

`GRANT USAGE ON SCHEMA` 명령은 `sales_mgr`가 `hr_mgr`의 스키마에 접근하여 `hr_mgr`의 `emp` 테이블 복사본을 만들 수 있도록 허용합니다. 이 단계는 EDB Postgres Advanced Server에서 필요하며 Oracle 데이터베이스와는 호환되지 않습니다. Oracle에는 사용자와 구별되는 스키마라는 개념이 없습니다.

## 4단계: 기본 권한 제거

나중에 필요한 최소 권한을 설명하기 위해 모든 권한을 제거합니다.

```sql
\c – hr_mgr
REVOKE USAGE ON SCHEMA hr_mgr FROM sales_mgr;
REVOKE ALL ON dept FROM PUBLIC;
REVOKE ALL ON emp FROM PUBLIC;
REVOKE ALL ON next_empno FROM PUBLIC;
REVOKE EXECUTE ON FUNCTION new_empno() FROM PUBLIC;
REVOKE EXECUTE ON PROCEDURE list_emp FROM PUBLIC;
REVOKE EXECUTE ON FUNCTION hire_clerk(VARCHAR2,NUMBER) FROM PUBLIC;
REVOKE EXECUTE ON PACKAGE emp_admin FROM PUBLIC;
```

## 5단계: list_emp를 호출자 권한으로 변경

사용자 `hr_mgr`로 연결된 상태에서, `list_emp` 프로그램에 `AUTHID CURRENT_USER` 절을 추가하고 EDB Postgres Advanced Server에 다시 저장합니다. 이 단계를 수행할 때는 반드시 `hr_mgr`로 로그인되어 있는지 확인하세요. 그렇지 않으면 수정된 프로그램이 `hr_mgr` 스키마 대신 `public` 스키마에 저장될 수 있습니다.

```sql
CREATE OR REPLACE PROCEDURE list_emp
AUTHID CURRENT_USER
IS
    v_empno         NUMBER(4);
    v_ename         VARCHAR2(10);
    CURSOR emp_cur IS
        SELECT empno, ename FROM emp ORDER BY empno;
BEGIN
    OPEN emp_cur;
    DBMS_OUTPUT.PUT_LINE('EMPNO    ENAME');
    DBMS_OUTPUT.PUT_LINE('-----    -------');
    LOOP
        FETCH emp_cur INTO v_empno, v_ename;
        EXIT WHEN emp_cur%NOTFOUND;
        DBMS_OUTPUT.PUT_LINE(v_empno || '     ' || v_ename);
    END LOOP;
    CLOSE emp_cur;
END;
```

## 6단계: hire_clerk를 호출자 권한으로 변경하고 new_empno 호출을 정규화

사용자 `hr_mgr`로 연결된 상태에서, `hire_clerk` 프로그램에 `AUTHID CURRENT_USER` 절을 추가합니다.

또한 `BEGIN` 문 뒤에서, `hire_clerk` 함수의 `new_empno` 함수 호출이 `hr_mgr` 스키마로 해석되도록 참조 `new_empno`를 `hr_mgr.new_empno`로 완전히 정규화합니다.

프로그램을 다시 저장할 때는 반드시 `hr_mgr`로 로그인되어 있는지 확인하세요. 그렇지 않으면 수정된 프로그램이 `hr_mgr` 스키마 대신 `public` 스키마에 저장될 수 있습니다.

```sql
CREATE OR REPLACE FUNCTION hire_clerk (
    p_ename         VARCHAR2,
    p_deptno        NUMBER
) RETURN NUMBER
AUTHID CURRENT_USER
IS
    v_empno         NUMBER(4);
    v_ename         VARCHAR2(10);
    v_job           VARCHAR2(9);
    v_mgr           NUMBER(4);
    v_hiredate      DATE;
    v_sal           NUMBER(7,2);
    v_comm          NUMBER(7,2);
    v_deptno        NUMBER(2);
BEGIN
    v_empno := hr_mgr.new_empno;
    INSERT INTO emp VALUES (v_empno, p_ename, 'CLERK', 7782,
        TRUNC(SYSDATE), 950.00, NULL, p_deptno);
    SELECT empno, ename, job, mgr, hiredate, sal, comm, deptno INTO
        v_empno, v_ename, v_job, v_mgr, v_hiredate, v_sal, v_comm, v_deptno
        FROM emp WHERE empno = v_empno;
    DBMS_OUTPUT.PUT_LINE('Department : ' || v_deptno);
    DBMS_OUTPUT.PUT_LINE('Employee No: ' || v_empno);
    DBMS_OUTPUT.PUT_LINE('Name       : ' || v_ename);
    DBMS_OUTPUT.PUT_LINE('Job        : ' || v_job);
    DBMS_OUTPUT.PUT_LINE('Manager    : ' || v_mgr);
    DBMS_OUTPUT.PUT_LINE('Hire Date  : ' || v_hiredate);
    DBMS_OUTPUT.PUT_LINE('Salary     : ' || v_sal);
    DBMS_OUTPUT.PUT_LINE('Commission : ' || v_comm);
    RETURN v_empno;
EXCEPTION
    WHEN OTHERS THEN
        DBMS_OUTPUT.PUT_LINE('The following is SQLERRM:');
        DBMS_OUTPUT.PUT_LINE(SQLERRM);
        DBMS_OUTPUT.PUT_LINE('The following is SQLCODE:');
        DBMS_OUTPUT.PUT_LINE(SQLCODE);
        RETURN -1;
END;
```

## 7단계: 필요한 권한 부여

사용자 `hr_mgr`로 연결된 상태에서, `sales_mgr`가 `list_emp` 프로시저, `hire_clerk` 함수, `emp_admin` 패키지를 실행할 수 있도록 필요한 권한을 부여합니다. `sales_mgr`가 접근할 수 있는 유일한 데이터 객체는 `sales_mgr` 스키마의 `emp` 테이블입니다. `sales_mgr`는 `hr_mgr` 스키마의 어떤 테이블에도 권한이 없습니다.

```sql
GRANT USAGE ON SCHEMA hr_mgr TO sales_mgr;
GRANT EXECUTE ON PROCEDURE list_emp TO sales_mgr;
GRANT EXECUTE ON FUNCTION hire_clerk(VARCHAR2,NUMBER) TO sales_mgr;
GRANT EXECUTE ON FUNCTION new_empno() TO sales_mgr;
GRANT EXECUTE ON PACKAGE emp_admin TO sales_mgr;
```

## 8단계: list_emp와 hire_clerk 프로그램 실행

사용자 `sales_mgr`로 연결하고, 다음 익명 블록을 실행합니다.

```sql
\c – sales_mgr
DECLARE
    v_empno         NUMBER(4);

    hr_mgr.list_emp;
    DBMS_OUTPUT.PUT_LINE('*** Adding new employee ***');

    DBMS_OUTPUT.PUT_LINE('*** After new employee added ***');
    hr_mgr.list_emp;
END;
```

익명 블록의 프로그램들이 접근하는 테이블과 시퀀스가 다음 다이어그램에 나타나 있습니다. 회색 타원은 `sales_mgr`와 `hr_mgr`의 스키마를 나타냅니다. 각 프로그램 실행 중의 현재 사용자는 굵은 빨간색 글꼴로 괄호 안에 표시되어 있습니다.

```sql

hr_mgr.emp_admin.get_dept_name(deptno) FROM sales_mgr.emp;
```

## 9단계: emp_admin 패키지의 hire_emp 프로그램 실행

사용자 `sales_mgr`로 연결된 상태에서, `emp_admin` 패키지의 `hire_emp` 프로시저를 실행합니다.

```sql
EXEC hr_mgr.emp_admin.hire_emp(9001,
'ALICE','SALESMAN',8000,TRUNC(SYSDATE),1000,7369,40);
```

이 다이어그램은 `emp_admin` 정의자 권한 패키지의 `hire_emp` 프로시저가 `hr_mgr`에 속한 `emp` 테이블을 업데이트함을 보여줍니다. `hr_mgr`의 객체 권한이 사용되며 `$user` 자리 표시자를 사용하는 기본 검색 경로 설정에 따라 `hr_mgr`의 스키마로 해석됩니다.
