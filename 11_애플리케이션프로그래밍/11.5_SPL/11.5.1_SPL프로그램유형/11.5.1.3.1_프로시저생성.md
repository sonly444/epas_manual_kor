# 프로시저 생성 (Creating a procedure) — EPAS 18 SPL

> 원문: [EPAS v18 — SPL › Procedures overview › Creating a procedure](https://www.enterprisedb.com/docs/epas/latest/application_programming/epas_compat_spl/02_spl_programs/04_procedures_overview/01_creating_a_procedure/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·키워드·코드는 원문 그대로 보존했습니다.

`CREATE PROCEDURE` 명령은 데이터베이스에 저장되는 독립형(standalone) 프로시저를 정의하고 이름을 부여합니다.

스키마 이름을 포함하면 지정한 스키마에 프로시저가 생성됩니다. 그렇지 않으면 현재 스키마에 생성됩니다. 새 프로시저의 이름은 동일한 스키마 내에서 동일한 입력 인자 타입을 가진 기존 프로시저와 일치하지 않아야 합니다. 다만, 입력 인자 타입이 서로 다른 프로시저는 이름을 공유할 수 있습니다. 이를 _오버로딩(overloading)_ 이라고 합니다.

> **참고**
>
> 프로시저 오버로딩은 EDB Postgres Advanced Server 기능입니다. 저장된 독립형 프로시저의 오버로딩은 Oracle 데이터베이스와 호환되지 않습니다.

## 기존 프로시저의 정의 업데이트

기존 프로시저의 정의를 업데이트하려면 `CREATE OR REPLACE PROCEDURE`를 사용합니다. 이 방법으로는 프로시저의 이름이나 인자 타입을 변경할 수 없습니다. 변경을 시도하면 새로운 별개의 프로시저가 생성됩니다. `OUT` 파라미터를 사용하는 경우, 프로시저를 삭제하지 않고서는 어떤 `OUT` 파라미터의 타입도 변경할 수 없습니다.

```sql
CREATE [OR REPLACE] PROCEDURE <name> [ (<parameters>) ]
   [
          IMMUTABLE
        | STABLE
        | VOLATILE
        | DETERMINISTIC
        | [ NOT ] LEAKPROOF
        | CALLED ON NULL INPUT
        | RETURNS NULL ON NULL INPUT
        | STRICT
        | [ EXTERNAL ] SECURITY INVOKER
        | [ EXTERNAL ] SECURITY DEFINER
        | AUTHID DEFINER
        | AUTHID CURRENT_USER
        | PARALLEL { UNSAFE | RESTRICTED | SAFE }
        | COST <execution_cost>
        | ROWS <result_rows>
        | SET <configuration_parameter>
          { TO <value> | = <value> | FROM CURRENT }
   ...]
{ IS | AS }
    [ PRAGMA AUTONOMOUS_TRANSACTION; ]
    [ <declarations> ]
  BEGIN
    <statements>
  END [ <name> ];
```

각 항목의 의미는 다음과 같습니다.

`name`

`name`은 프로시저의 식별자입니다.

`parameters`

`parameters`는 형식 파라미터(formal parameter)의 목록입니다.

`declarations`

`declarations`는 변수, 커서, 타입, 또는 서브프로그램 선언입니다. 서브프로그램 선언을 포함하는 경우, 다른 모든 변수·커서·타입 선언 뒤에 선언해야 합니다.

`statements`

`statements`는 SPL 프로그램 문입니다. `BEGIN - END` 블록은 `EXCEPTION` 섹션을 포함할 수 있습니다.

`IMMUTABLE`

`STABLE`

`VOLATILE`

이 속성들은 프로시저의 동작에 대해 쿼리 옵티마이저에 정보를 제공합니다. 하나만 지정할 수 있습니다. 기본 동작은 `VOLATILE`입니다.

- `IMMUTABLE`은 프로시저가 데이터베이스를 수정할 수 없으며, 동일한 인자 값이 주어지면 항상 같은 결과에 도달함을 나타냅니다. 데이터베이스 조회를 수행하지 않으며, 그 밖에 인자 목록에 직접 존재하지 않는 정보를 사용하지도 않습니다. 이 절을 포함하면, 모든 인자가 상수인 프로시저 호출은 즉시 프로시저 값으로 대체할 수 있습니다.

- `STABLE`은 프로시저가 데이터베이스를 수정할 수 없음을 나타냅니다. 또한 단일 테이블 스캔 내에서는 동일한 인자 값에 대해 일관되게 같은 결과를 반환하지만, SQL 문 사이에서는 결과가 달라질 수 있음을 나타냅니다. 데이터베이스 조회나 파라미터 변수(예: 현재 시간대) 등에 의존하는 프로시저에는 이 선택지를 사용합니다.

- `VOLATILE`은 단일 테이블 스캔 내에서도 프로시저 값이 변할 수 있으므로 최적화를 수행할 수 없음을 나타냅니다. 부작용(side effect)이 있는 함수는 결과가 예측 가능하더라도 호출이 최적화로 제거되지 않도록 반드시 volatile로 분류해야 합니다.

`DETERMINISTIC`

`DETERMINISTIC`은 `IMMUTABLE`의 동의어입니다. `DETERMINISTIC` 프로시저는 데이터베이스를 수정할 수 없으며, 동일한 인자 값이 주어지면 항상 같은 결과에 도달합니다. 데이터베이스 조회를 수행하지 않으며, 그 밖에 인자 목록에 직접 존재하지 않는 정보를 사용하지도 않습니다. 이 절을 포함하면, 모든 인자가 상수인 프로시저 호출은 즉시 프로시저 값으로 대체할 수 있습니다.

`[ NOT ] LEAKPROOF`

`LEAKPROOF` 프로시저는 부작용이 없으며, 프로시저를 호출하는 데 사용된 값에 대한 정보를 노출하지 않습니다.

`CALLED ON NULL INPUT`

`RETURNS NULL ON NULL INPUT`

`STRICT`

- `CALLED ON NULL INPUT`(기본값)은 일부 인자가 `NULL`일 때에도 프로시저가 정상적으로 호출됨을 나타냅니다. 필요하다면 `NULL` 값을 확인하고 적절히 대응하는 것은 작성자의 책임입니다.

- `RETURNS NULL ON NULL INPUT` 또는 `STRICT`는 인자 중 하나라도 `NULL`이면 프로시저가 항상 `NULL`을 반환함을 나타냅니다. 이 절들을 지정하면 `NULL` 인자가 있을 때 프로시저가 실행되지 않고, 대신 자동으로 `NULL` 결과가 가정됩니다.

`[ EXTERNAL ] SECURITY DEFINER`

`SECURITY DEFINER`는 프로시저가 그것을 생성한 사용자의 권한으로 실행되도록 지정합니다. 이것이 기본값입니다. `EXTERNAL` 키워드는 SQL 표준 준수를 위해 허용되지만 선택 사항입니다.

`[ EXTERNAL ] SECURITY INVOKER`

`SECURITY INVOKER` 절은 프로시저가 그것을 호출하는 사용자의 권한으로 실행되도록 지정합니다. `EXTERNAL` 키워드는 SQL 표준 준수를 위해 허용되지만 선택 사항입니다.

`AUTHID DEFINER`

`AUTHID CURRENT_USER`

- `AUTHID DEFINER` 절은 `[EXTERNAL] SECURITY DEFINER`의 동의어입니다. `AUTHID` 절을 생략하거나 `AUTHID DEFINER`를 지정하면, 프로시저 소유자의 권한이 데이터베이스 객체에 대한 접근 권한을 결정합니다.

- `AUTHID CURRENT_USER` 절은 `[EXTERNAL] SECURITY INVOKER`의 동의어입니다. `AUTHID CURRENT_USER`를 지정하면, 프로시저를 실행하는 현재 사용자의 권한이 접근 권한을 결정합니다.

`PARALLEL { UNSAFE | RESTRICTED | SAFE }`

`PARALLEL` 절은 병렬 순차 스캔(parallel sequential scan), 즉 병렬 모드의 사용을 활성화합니다. 병렬 순차 스캔은 직렬 순차 스캔과 달리 쿼리 중에 여러 워커(worker)를 사용하여 릴레이션을 병렬로 스캔합니다.

- 값이 `UNSAFE`로 설정되면 프로시저를 병렬 모드에서 실행할 수 없습니다. 이러한 프로시저가 존재하면 직렬 실행 계획이 강제됩니다. 이것이 기본 설정입니다.

- 값이 `RESTRICTED`로 설정되면 프로시저를 병렬 모드에서 실행할 수 있지만, 실행은 병렬 그룹 리더로 제한됩니다. 특정 릴레이션의 조건(qualification)에 병렬 제한(parallel restricted) 요소가 있으면, 해당 릴레이션은 병렬 처리 대상으로 선택되지 않습니다.

- 값이 `SAFE`로 설정되면 프로시저를 제한 없이 병렬 모드에서 실행할 수 있습니다.

`COST execution_cost`

`execution_cost`는 프로시저의 추정 실행 비용을 `cpu_operator_cost` 단위로 나타내는 양수입니다. 프로시저가 집합(set)을 반환하는 경우 이는 반환된 행당 비용입니다. 값이 클수록 플래너(planner)는 필요 이상으로 함수를 평가하지 않으려 합니다.

`ROWS result_rows`

`result_rows`는 플래너가 프로시저의 반환을 예상해야 할 추정 행 수를 나타내는 양수입니다. 이 설정은 프로시저가 집합을 반환하도록 선언된 경우에만 허용됩니다. 기본값은 1000행입니다.

`SET configuration_parameter { TO value | = value | FROM CURRENT }`

`SET` 절은 프로시저 진입 시 지정한 구성 파라미터를 지정한 값으로 설정하고, 프로시저 종료 시 이전 값으로 복원합니다. `SET FROM CURRENT`는 세션의 현재 파라미터 값을 프로시저 진입 시 적용할 값으로 저장합니다.

프로시저에 `SET` 절이 부착되면, 프로시저 내부에서 동일한 변수에 대해 실행된 `SET LOCAL` 명령의 효과는 해당 프로시저로 제한됩니다. 구성 파라미터의 이전 값은 프로시저 종료 시 복원됩니다. `LOCAL`이 없는 일반 `SET` 명령은, 이전의 `SET LOCAL` 명령에 대해서와 마찬가지로, `SET` 절을 재정의합니다. 이 명령의 효과는 현재 트랜잭션이 롤백되지 않는 한 프로시저 종료 후에도 지속됩니다.

`PRAGMA AUTONOMOUS_TRANSACTION`

`PRAGMA AUTONOMOUS_TRANSACTION`은 프로시저를 자율 트랜잭션(autonomous transaction)으로 설정하는 지시어입니다.

> **참고**
>
> - `STRICT`, `LEAKPROOF`, `PARALLEL`, `COST`, `ROWS`, `SET` 키워드는 EDB Postgres Advanced Server를 위한 확장 기능을 제공하며 Oracle에서는 지원되지 않습니다.
>
> - 기본적으로 저장 프로시저는 `SECURITY DEFINERS`로 생성되지만, plpgsql로 작성된 경우 저장 프로시저는 `SECURITY INVOKERS`로 생성됩니다.

## 예제 (Example)

이 예제는 파라미터를 받지 않는 단순한 프로시저를 보여줍니다.

```sql
CREATE OR REPLACE PROCEDURE simple_procedure
IS
BEGIN
   DBMS_OUTPUT.PUT_LINE('That''s all folks!');
END simple_procedure;
```

EDB Postgres Advanced Server에 프로시저 코드를 입력하여 프로시저를 데이터베이스에 저장합니다.

이 예제는 프로시저 선언에서 `AUTHID DEFINER` 절과 `SET` 절을 사용하는 방법을 보여줍니다. `update_salary` 프로시저는 프로시저가 실행되는 동안 프로시저를 정의한 역할(role)의 권한을 프로시저를 호출하는 역할에 전달합니다.

```sql
CREATE OR REPLACE PROCEDURE update_salary(id INT, new_salary NUMBER)
  SET SEARCH_PATH = 'public' SET WORK_MEM = '1MB'
  AUTHID DEFINER IS
BEGIN
  UPDATE emp SET salary = new_salary WHERE emp_id = id;
END;
```

`SET` 절을 포함하여 프로시저의 검색 경로(search path)를 `public`으로, 작업 메모리(work memory)를 `1MB`로 설정합니다. 이 설정들은 다른 프로시저, 함수, 객체에는 영향을 주지 않습니다.

이 예제에서 `AUTHID DEFINER` 절은 원래는 프로시저의 문을 실행할 수 없을 수도 있는 역할에 일시적으로 권한을 부여합니다. 서버가 프로시저를 호출하는 역할에 연결된 권한을 사용하도록 하려면, `AUTHID DEFINER` 절을 `AUTHID CURRENT_USER` 절로 교체합니다.
