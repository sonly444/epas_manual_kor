# 함수 생성 (Creating a function) — EPAS 18 SPL

> 원문: [EPAS v18 — SPL › Functions overview › Creating a function](https://www.enterprisedb.com/docs/epas/latest/application_programming/epas_compat_spl/02_spl_programs/05_functions_overview/01_creating_a_function/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·키워드·코드는 원문 그대로 보존했습니다.

`CREATE FUNCTION` 명령은 데이터베이스에 저장할 독립형 함수를 정의하고 이름을 부여합니다.

스키마 이름을 포함하면 함수가 지정된 스키마에 생성됩니다. 그렇지 않으면 현재 스키마에 생성됩니다. 새 함수의 이름은 동일한 스키마 내에서 같은 입력 인자 타입을 가진 기존 함수와 일치하면 안 됩니다. 다만 입력 인자 타입이 다른 함수는 이름을 공유할 수 있습니다. 이렇게 이름을 공유하는 것을 _오버로딩(overloading)_ 이라고 합니다.

> **참고**
>
> 함수 오버로딩은 EDB Postgres Advanced Server의 기능입니다. **저장된 독립형 함수의 오버로딩은 Oracle 데이터베이스와 호환되지 않습니다.**

## 기존 함수 정의 업데이트

기존 함수의 정의를 업데이트하려면 `CREATE OR REPLACE FUNCTION`을 사용합니다. 이 방법으로는 함수의 이름이나 인자 타입을 변경할 수 없습니다. 변경을 시도하면 대신 새로운 별개의 함수가 생성됩니다. 또한 `CREATE OR REPLACE FUNCTION`으로는 기존 함수의 반환 타입을 변경할 수 없습니다. 반환 타입을 변경하려면 함수를 삭제하고 다시 생성해야 합니다. `OUT` 파라미터를 사용하는 경우, 함수를 삭제하지 않고는 `OUT` 파라미터의 타입을 변경할 수 없습니다.

```sql
CREATE [ OR REPLACE ] FUNCTION <name> [ (<parameters>) ]
  RETURN <data_type>
   [
           IMMUTABLE
        | STABLE
        | VOLATILE
        | DETERMINISTIC
        | [ NOT ] LEAKPROOF
        | CALLED ON NULL INPUT
        | RETURNS NULL ON NULL INPUT
        | STRICT
        | [ EXTERNAL ] SECURITY INVOKER
        | [ EXTERNAL ] SECURITY DEFINER
        | AUTHID DEFINER
        | AUTHID CURRENT_USER
        | PARALLEL { UNSAFE | RESTRICTED | SAFE }
        | COST <execution_cost>
        | ROWS <result_rows>
        | SET <configuration_parameter>
          { TO <value> | = <value> | FROM CURRENT }
   ...]
{ IS | AS }
    [ PRAGMA AUTONOMOUS_TRANSACTION; ]
    [ <declarations> ]
  BEGIN
    <statements>
  END [ <name> ];
```

여기서:

`name`은 함수의 식별자입니다.

`parameters`는 형식 파라미터(formal parameter) 목록입니다.

`data_type`은 함수의 `RETURN` 문이 반환하는 값의 데이터 타입입니다.

`declarations`는 변수, 커서, 타입 또는 서브프로그램 선언입니다. 서브프로그램 선언을 포함하는 경우, 다른 모든 변수, 커서, 타입 선언 이후에 선언해야 합니다.

`statements`는 SPL 프로그램 문입니다. `BEGIN - END` 블록에는 `EXCEPTION` 섹션을 포함할 수 있습니다.

`IMMUTABLE`

`STABLE`

`VOLATILE`

이 속성들은 함수의 동작에 대해 쿼리 옵티마이저에 알려 줍니다. 이 중 하나만 지정할 수 있습니다. 기본 동작은 `VOLATILE`입니다.

- `IMMUTABLE`은 함수가 데이터베이스를 수정할 수 없으며 동일한 인자 값이 주어졌을 때 항상 같은 결과에 도달함을 나타냅니다. 데이터베이스 조회를 수행하지 않으며, 인자 목록에 직접 존재하지 않는 정보를 사용하지 않습니다. 이 절을 포함하면 모든 인자가 상수인 함수 호출을 즉시 함수 값으로 대체할 수 있습니다.

- `STABLE`은 함수가 데이터베이스를 수정할 수 없음을 나타냅니다. 또한 단일 테이블 스캔 내에서는 동일한 인자 값에 대해 일관되게 같은 결과를 반환하지만 그 결과가 SQL 문 간에는 달라질 수 있음을 나타냅니다. 데이터베이스 조회, 파라미터 변수(예: 현재 시간대) 등에 의존하는 함수에는 이 속성을 선택합니다.

- `VOLATILE`은 함수 값이 단일 테이블 스캔 내에서도 변할 수 있어 어떠한 최적화도 수행할 수 없음을 나타냅니다. 결과가 예측 가능하더라도 부작용(side effect)이 있는 모든 함수는 volatile로 분류하여 호출이 최적화되어 제거되는 것을 방지합니다.

`DETERMINISTIC`

`DETERMINISTIC`은 `IMMUTABLE`의 동의어입니다. `DETERMINISTIC` 함수는 데이터베이스를 수정할 수 없으며 동일한 인자 값이 주어졌을 때 항상 같은 결과에 도달합니다. 데이터베이스 조회를 수행하지 않으며, 인자 목록에 직접 존재하지 않는 정보를 사용하지 않습니다. 이 절을 포함하면 모든 인자가 상수인 함수 호출을 함수 값으로 대체할 수 있습니다.

`[ NOT ] LEAKPROOF`

`LEAKPROOF` 함수는 부작용이 없으며 함수를 호출하는 데 사용된 값에 대한 정보를 드러내지 않습니다.

`CALLED ON NULL INPUT`

`RETURNS NULL ON NULL INPUT`

`STRICT`

- `CALLED ON NULL INPUT`(기본값)은 일부 인자가 `NULL`일 때 프로시저가 정상적으로 호출되도록 지시합니다. 필요한 경우 `NULL` 값을 확인하고 적절하게 대응하는 것은 작성자의 책임입니다.

- `RETURNS NULL ON NULL INPUT` 또는 `STRICT`는 인자 중 하나라도 `NULL`이면 프로시저가 항상 `NULL`을 반환하도록 지시합니다. 이 절들을 지정하면 `NULL` 인자가 있을 때 프로시저가 실행되지 않습니다. 대신 `NULL` 결과가 자동으로 가정됩니다.

`[ EXTERNAL ] SECURITY DEFINER`

`SECURITY DEFINER`(기본값)는 함수를 생성한 사용자의 권한으로 함수를 실행하도록 지정합니다. 키워드 `EXTERNAL`은 SQL 표준 준수를 위해 허용되지만 선택 사항입니다.

`[ EXTERNAL ] SECURITY INVOKER`

`SECURITY INVOKER` 절은 함수를 호출하는 사용자의 권한으로 함수를 실행하도록 지시합니다. 키워드 `EXTERNAL`은 SQL 표준 준수를 위해 허용되지만 선택 사항입니다.

`AUTHID DEFINER`

`AUTHID CURRENT_USER`

- `AUTHID DEFINER` 절은 `[EXTERNAL] SECURITY DEFINER`의 동의어입니다. `AUTHID` 절이 생략되거나 `AUTHID DEFINER`가 지정되면, 함수 소유자의 권한이 데이터베이스 객체에 대한 접근 권한을 결정합니다.

- `AUTHID CURRENT_USER` 절은 `[EXTERNAL] SECURITY INVOKER`의 동의어입니다. `AUTHID CURRENT_USER`가 지정되면, 함수를 실행하는 현재 사용자의 권한이 접근 권한을 결정합니다.

`PARALLEL { UNSAFE | RESTRICTED | SAFE }`

`PARALLEL` 절은 병렬 순차 스캔, 즉 병렬 모드의 사용을 가능하게 합니다. 병렬 순차 스캔은 직렬 순차 스캔과 달리 쿼리 중 여러 워커를 사용하여 릴레이션을 병렬로 스캔합니다.

- 이 값이 `UNSAFE`로 설정되면 함수를 병렬 모드에서 실행할 수 없습니다. SQL 문에 이러한 함수가 존재하면 직렬 실행 계획이 강제됩니다. 이것이 기본 설정입니다.

- 이 값이 `RESTRICTED`로 설정되면 함수를 병렬 모드에서 실행할 수 있지만, 실행은 병렬 그룹 리더로 제한됩니다. 특정 릴레이션에 대한 조건에 병렬 제한된(parallel restricted) 요소가 있으면 해당 릴레이션은 병렬 처리 대상으로 선택되지 않습니다.

- 이 값이 `SAFE`로 설정되면 제한 없이 함수를 병렬 모드에서 실행할 수 있습니다.

`COST execution_cost`

`execution_cost`는 `cpu_operator_cost` 단위로 표현된 함수의 추정 실행 비용을 나타내는 양수입니다. 함수가 집합을 반환하는 경우 이는 반환되는 행당 비용입니다. 값이 클수록 플래너가 함수를 필요 이상으로 자주 평가하지 않으려고 합니다.

`ROWS result_rows`

`result_rows`는 플래너가 함수가 반환할 것으로 예상하는 추정 행 수를 나타내는 양수입니다. 이는 함수가 집합을 반환하도록 선언된 경우에만 허용됩니다. 기본 가정은 1000행입니다.

`SET configuration_parameter { TO value | = value | FROM CURRENT }`

`SET` 절은 함수에 진입할 때 지정된 구성 파라미터를 지정된 값으로 설정한 다음, 함수가 종료될 때 이전 값으로 복원합니다. `SET FROM CURRENT`는 세션의 현재 파라미터 값을 함수 진입 시 적용할 값으로 저장합니다.

함수에 `SET` 절이 첨부되면, 함수 내부에서 동일한 변수에 대해 실행된 `SET LOCAL` 명령의 효과가 함수로 제한됩니다. 구성 파라미터의 이전 값은 함수 종료 시 복원됩니다. `LOCAL`이 없는 `SET` 명령은, 이전의 `SET LOCAL` 명령에 대해서와 마찬가지로 `SET` 절을 재정의합니다. 이러한 명령의 효과는 현재 트랜잭션이 롤백되지 않는 한 프로시저 종료 후에도 유지됩니다.

`PRAGMA AUTONOMOUS_TRANSACTION`

`PRAGMA AUTONOMOUS_TRANSACTION`은 함수를 자율 트랜잭션(autonomous transaction)으로 설정하는 지시어입니다.

> **참고**
>
> `STRICT`, `LEAKPROOF`, `PARALLEL`, `COST`, `ROWS`, `SET` 키워드는 EDB Postgres Advanced Server의 확장 기능을 제공하며 Oracle에서는 지원되지 않습니다.

## 예제

이 예제는 파라미터를 받지 않는 단순한 함수를 보여 줍니다.

```sql
CREATE OR REPLACE FUNCTION simple_function
    RETURN VARCHAR2
IS
BEGIN
    RETURN 'That''s All Folks!';
END simple_function;
```

이 함수는 두 개의 입력 파라미터를 받습니다.

```sql
CREATE OR REPLACE FUNCTION emp_comp (
    p_sal           NUMBER,
    p_comm          NUMBER
) RETURN NUMBER
IS
BEGIN
    RETURN (p_sal + NVL(p_comm, 0)) * 24;
END emp_comp;
```

이 예제는 함수 선언에서 `AUTHID CURRENT_USER` 절과 `STRICT` 키워드를 사용합니다.

```sql
CREATE OR REPLACE FUNCTION dept_salaries(dept_id int) RETURN NUMBER
  STRICT
  AUTHID CURRENT_USER
BEGIN
  RETURN QUERY (SELECT sum(salary) FROM emp WHERE deptno = id);
END;
```

전달된 입력 파라미터 중 하나라도 `NULL`이면 서버가 `NULL`을 반환하도록 지시하려면 `STRICT` 키워드를 포함합니다. `NULL` 값이 전달되면 함수가 실행되지 않습니다.

`dept_salaries` 함수는 함수를 호출하는 롤(role)의 권한으로 실행됩니다. 현재 사용자가 `emp` 테이블을 조회하는 `SELECT` 문(직원 급여를 표시하기 위한)을 수행할 권한이 없으면 함수가 오류를 보고합니다. 서버가 함수를 정의한 롤과 연결된 권한을 사용하도록 지시하려면 `AUTHID CURRENT_USER` 절을 `AUTHID DEFINER` 절로 바꿉니다.
