# 서브프로그램 호출 (Invoking subprograms) — EPAS 18 SPL

> 원문: [EPAS v18 — SPL › Subprograms › Invoking subprograms](https://www.enterprisedb.com/docs/epas/latest/application_programming/epas_compat_spl/02_spl_programs/07_subprograms_subprocedures_and_subfunctions/04_invoking_subprograms/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 용어·코드는 원문 그대로 보존했습니다.

독립 프로시저나 함수를 호출하는 것과 동일한 방식으로, 서브프로그램의 이름과 실제 매개변수를 지정하여 서브프로그램을 호출합니다.

서브프로그램은 한정자(qualifier)를 0개, 1개 또는 여러 개 사용하여 호출할 수 있습니다. 한정자는 서브프로그램이 선언된 조상 계층을 구성하는 부모 서브프로그램이나 레이블이 붙은 익명 블록의 이름입니다.

## 서브프로그램 개요

한정자를 점(dot)으로 구분한 목록 뒤에 서브프로그램 이름과 그 인수를 붙여 서브프로그램을 호출합니다.

```text
[[<qualifier_1>.][...]<qualifier_n>.]<subprog> [(<arguments>)]
```

### 한정자 지정

`qualifier_n`을 지정하는 경우, 이는 `subprog`이 자신의 선언 섹션에서 선언된 서브프로그램입니다. 선행하는 한정자 목록은 `qualifier_n`에서 `qualifier_1`까지 계층을 따라 올라가는 연속된 경로 상에 존재해야 합니다. `qualifier_1`은 해당 경로 상의 임의의 조상 서브프로그램일 수 있으며, 다음 중 하나일 수도 있습니다.

- 서브프로그램을 포함하는 독립 프로시저 이름
- 서브프로그램을 포함하는 독립 함수 이름
- 서브프로그램을 포함하는 패키지 이름
- 오브젝트 타입 메서드에서 서브프로그램을 포함하는 오브젝트 타입 이름
- 선언 섹션이 존재하는 경우 `DECLARE` 키워드 앞에, 선언 섹션이 없는 경우 `BEGIN` 키워드 앞에 포함된 익명 블록 레이블

> **참고**
>
> `qualifier_1`은 스키마 이름일 수 없습니다. 스키마 이름이면 서브프로그램을 호출할 때 오류가 발생합니다. 이 EDB Postgres Advanced Server의 제약은 스키마 이름을 한정자로 사용할 수 있는 Oracle 데이터베이스와 호환되지 않습니다.

`arguments`는 서브프로시저나 서브함수에 전달할 실제 매개변수의 목록입니다.

### 서브프로그램 검색

서브프로그램을 호출하면 서브프로그램에 대한 검색이 다음과 같이 이루어집니다.

- 호출된 서브프로그램의 타입(즉, 서브프로시저 또는 서브함수)에 따른 이름과, 지정된 순서의 임의의 한정자(호출 목록이라고 함)를 사용하여 동일한 계층 순서로 존재하는 블록 집합을 찾습니다. 검색은 가장 낮은 레벨이 서브프로그램이 호출되는 블록인 블록 계층에서 시작됩니다. 코드를 위에서 아래로 살펴볼 때, 서브프로그램의 선언은 그것이 호출되는 코드 라인보다 앞선 SPL 코드에 있어야 합니다. (전방 선언을 사용하면 이 요구 사항의 예외를 달성할 수 있습니다. [전방 선언 사용](https://www.enterprisedb.com/docs/epas/latest/application_programming/epas_compat_spl/02_spl_programs/07_subprograms_subprocedures_and_subfunctions/05_using_forward_declarations/#using_forward_declarations)을 참조하십시오.)
- 서브프로그램이 호출되는 블록에서 시작하여 호출 목록이 블록 계층과 일치하지 않으면, 이전 시작 블록의 부모에서 시작하여 호출 목록을 대조합니다. 즉, 비교가 계층을 따라 위쪽으로 진행됩니다.
- 조상의 형제 블록이 있는 경우, 호출 목록 비교는 형제 블록의 계층도 포함하지만 항상 위쪽 레벨에서 비교합니다. 형제 블록의 후손은 비교하지 않습니다.
- 이 비교 과정은 첫 번째 완전한 일치가 발견될 때까지 계층을 따라 계속 위로 진행되며, 일치가 발견되면 찾아낸 서브프로그램이 호출됩니다. 일치한 서브프로그램의 형식 매개변수 목록은 호출된 서브프로그램에 지정된 실제 매개변수 목록을 준수해야 합니다. 그렇지 않으면 서브프로그램을 호출할 때 오류가 발생합니다.
- 독립 프로그램까지 검색한 후에도 일치가 발견되지 않으면 서브프로그램을 호출할 때 오류가 발생합니다.

> **참고**
>
> 서브프로그램 호출에 대한 EDB Postgres Advanced Server의 검색 알고리즘은 Oracle 데이터베이스와 완전히 호환되지 않습니다. Oracle의 경우, 검색은 첫 번째 한정자(즉, `qualifier_1`)의 첫 번째 일치를 찾습니다. 그러한 일치가 발견되면, 나머지 모든 한정자, 서브프로그램 이름, 서브프로그램 타입, 그리고 호출의 인수가 일치하는 첫 번째 한정자가 발견된 계층 내용과 일치해야 합니다. 그렇지 않으면 오류가 발생합니다. EDB Postgres Advanced Server의 경우, 호출의 모든 한정자, 서브프로그램 이름, 서브프로그램 타입이 계층 내용과 일치하지 않으면 일치가 발견되지 않습니다. 그러한 정확한 일치가 처음에 발견되지 않으면, EDB Postgres Advanced Server는 계층을 따라 위로 진행하며 검색을 계속합니다.

호출이 이루어지는 블록을 기준으로 다음과 같은 위치의 서브프로그램에 접근할 수 있습니다.

- 지역 블록에 선언된 서브프로그램은 같은 블록의 실행 섹션 또는 예외 섹션에서 호출할 수 있습니다.
- 부모 또는 기타 조상 블록에 선언된 서브프로그램은 부모 또는 기타 조상의 자식 블록에서 호출할 수 있습니다.
- 형제 블록에 선언된 서브프로그램은 형제 블록 또는 그 형제의 임의의 후손 블록에서 호출할 수 있습니다.

그러나 호출이 이루어지는 블록을 기준으로 다음과 같은 위치의 서브프로그램에는 접근할 수 없습니다.

- 호출이 시도되는 블록의 후손인 블록에 선언된 서브프로그램
- 호출이 시도되는 블록의 형제 블록의 후손인 블록에 선언된 서브프로그램

## 지역 선언된 서브프로그램 호출

이 예제는 독립 프로시저 `level_0`에 포함된 단일 블록 계층을 포함합니다. 프로시저 `level_1a`의 실행 섹션에서 지역 프로시저 `level_2a`를 한정자를 사용하거나 사용하지 않고 호출하는 방법을 보여 줍니다.

지역 프로시저 `level_2a`의 후손인 프로시저 `level_3a`에 대한 접근은 한정자를 사용하든 사용하지 않든 허용되지 않습니다. 이러한 호출은 예제에서 주석 처리되어 있습니다.

```sql
CREATE OR REPLACE PROCEDURE level_0
IS
    PROCEDURE level_1a
    IS
        PROCEDURE level_2a
        IS
            PROCEDURE level_3a
            IS
            BEGIN
                DBMS_OUTPUT.PUT_LINE('........ BLOCK level_3a');
                DBMS_OUTPUT.PUT_LINE('........ END BLOCK level_3a');
            END level_3a;
        BEGIN
            DBMS_OUTPUT.PUT_LINE('...... BLOCK level_2a');
            DBMS_OUTPUT.PUT_LINE('...... END BLOCK level_2a');
        END level_2a;
    BEGIN
        DBMS_OUTPUT.PUT_LINE('.. BLOCK level_1a');
        level_2a;                              -- Local block called
        level_1a.level_2a;                     -- Qualified local block called
        level_0.level_1a.level_2a;             -- Double qualified local block called
--        level_3a;                            -- Error - Descendant of local block
--        level_2a.level_3a;                   -- Error - Descendant of local block
        DBMS_OUTPUT.PUT_LINE('.. END BLOCK level_1a');
    END level_1a;
BEGIN
    DBMS_OUTPUT.PUT_LINE('BLOCK level_0');
    level_1a;
    DBMS_OUTPUT.PUT_LINE('END BLOCK level_0');
END level_0;
```

독립 프로시저를 호출하면 출력은 다음과 같습니다. 이 출력은 프로시저 `level_2a`가 프로시저 `level_1a`의 실행 섹션에 있는 호출로부터 성공적으로 호출되었음을 나타냅니다.

```sql
BEGIN
    level_0;
END;
```

Output

```text
BLOCK level_0
.. BLOCK level_1a
...... BLOCK level_2a
...... END BLOCK level_2a
...... BLOCK level_2a
...... END BLOCK level_2a
...... BLOCK level_2a
...... END BLOCK level_2a
.. END BLOCK level_1a
END BLOCK level_0
```

후손 블록에 대한 호출 중 어느 하나라도 주석을 해제한 채로 프로시저 `level_0`을 실행하려고 하면 오류가 발생합니다.

## 조상 블록에 선언된 서브프로그램 호출

이 예제는 호출이 이루어지는 블록을 기준으로 부모 및 기타 조상 블록에 선언된 서브프로그램을 호출하는 방법을 보여 줍니다.

이 예제에서 프로시저 `level_3a`의 실행 섹션은 자신의 부모 블록인 프로시저 `level_2a`를 호출합니다. `v_cnt`는 무한 루프를 방지하는 데 사용됩니다.

```sql
CREATE OR REPLACE PROCEDURE level_0
IS
  v_cnt           NUMBER(2) := 0;
  PROCEDURE level_1a
  IS
      PROCEDURE level_2a
      IS
          PROCEDURE level_3a
          IS
          BEGIN
              DBMS_OUTPUT.PUT_LINE('........ BLOCK level_3a');
              v_cnt := v_cnt + 1;
              IF v_cnt < 2 THEN
                  level_2a;                  -- Parent block called
              END IF;
              DBMS_OUTPUT.PUT_LINE('........ END BLOCK level_3a');
          END level_3a;
      BEGIN
          DBMS_OUTPUT.PUT_LINE('...... BLOCK level_2a');
          level_3a;                          -- Local block called
          DBMS_OUTPUT.PUT_LINE('...... END BLOCK level_2a');
      END level_2a;
  BEGIN
      DBMS_OUTPUT.PUT_LINE('.. BLOCK level_1a');
      level_2a;                              -- Local block called
      DBMS_OUTPUT.PUT_LINE('.. END BLOCK level_1a');
  END level_1a;
BEGIN
    DBMS_OUTPUT.PUT_LINE('BLOCK level_0');
    level_1a;
    DBMS_OUTPUT.PUT_LINE('END BLOCK level_0');
END level_0;
```

출력은 다음과 같습니다.

```sql
BEGIN
    level_0;
END;
```

Output

```text
BLOCK level_0
.. BLOCK level_1a
...... BLOCK level_2a
........ BLOCK level_3a
...... BLOCK level_2a
........ BLOCK level_3a
........ END BLOCK level_3a
...... END BLOCK level_2a
........ END BLOCK level_3a
...... END BLOCK level_2a
.. END BLOCK level_1a
END BLOCK level_0
```

유사한 예제에서, 프로시저 `level_3a`의 실행 섹션은 조상 계층에서 더 위에 있는 프로시저 `level_1a`를 호출합니다. `v_cnt`는 다시 무한 루프를 방지하는 데 사용됩니다.

```sql
CREATE OR REPLACE PROCEDURE level_0
IS
    v_cnt           NUMBER(2) := 0;
    PROCEDURE level_1a
    IS
        PROCEDURE level_2a
        IS
            PROCEDURE level_3a
            IS
            BEGIN
                DBMS_OUTPUT.PUT_LINE('........ BLOCK level_3a');
                v_cnt := v_cnt + 1;
                IF v_cnt < 2 THEN
                    level_1a;                  -- Ancestor block called
                END IF;
                DBMS_OUTPUT.PUT_LINE('........ END BLOCK level_3a');
            END level_3a;
        BEGIN
            DBMS_OUTPUT.PUT_LINE('...... BLOCK level_2a');
            level_3a;                          -- Local block called
            DBMS_OUTPUT.PUT_LINE('...... END BLOCK level_2a');
        END level_2a;
    BEGIN
        DBMS_OUTPUT.PUT_LINE('.. BLOCK level_1a');
        level_2a;                              -- Local block called
        DBMS_OUTPUT.PUT_LINE('.. END BLOCK level_1a');
    END level_1a;
BEGIN
    DBMS_OUTPUT.PUT_LINE('BLOCK level_0');
    level_1a;
    DBMS_OUTPUT.PUT_LINE('END BLOCK level_0');
END level_0;
```

출력은 다음과 같습니다.

```sql
BEGIN
    level_0;
END;
```

Output

```text
BLOCK level_0
.. BLOCK level_1a
...... BLOCK level_2a
........ BLOCK level_3a
.. BLOCK level_1a
...... BLOCK level_2a
........ BLOCK level_3a
........ END BLOCK level_3a
...... END BLOCK level_2a
.. END BLOCK level_1a
........ END BLOCK level_3a
...... END BLOCK level_2a
.. END BLOCK level_1a
END BLOCK level_0
```

## 형제 블록에 선언된 서브프로그램 호출

이 예제들은 서브프로그램의 호출이 이루어지는 지역, 부모 또는 기타 조상 블록을 기준으로 형제 블록에 선언된 서브프로그램을 호출하는 방법을 보여 줍니다.

이 예제에서 프로시저 `level_1b`의 실행 섹션은 자신의 형제 블록인 프로시저 `level_1a`를 호출합니다. 둘 다 독립 프로시저 `level_0`에 대해 지역입니다.

프로시저 `level_1b`에서 `level_2a` 또는 이와 동등한 `level_1a.level_2a`를 호출하는 것은 이 호출이 오류를 발생시키므로 주석 처리되어 있습니다. 형제 블록(`level_1a`)의 후손 서브프로그램(`level_2a`)을 호출하는 것은 허용되지 않습니다.

```sql
CREATE OR REPLACE PROCEDURE level_0
IS
    v_cnt     NUMBER(2) := 0;
    PROCEDURE level_1a
    IS
        PROCEDURE level_2a
        IS
        BEGIN
            DBMS_OUTPUT.PUT_LINE('...... BLOCK level_2a');
            DBMS_OUTPUT.PUT_LINE('...... END BLOCK level_2a');
        END level_2a;
    BEGIN
        DBMS_OUTPUT.PUT_LINE('.. BLOCK level_1a');
        DBMS_OUTPUT.PUT_LINE('.. END BLOCK level_1a');
    END level_1a;
    PROCEDURE level_1b
    IS
    BEGIN
        DBMS_OUTPUT.PUT_LINE('.. BLOCK level_1b');
        level_1a;                              -- Sibling block called
--      level_2a;                              -- Error – Descendant of sibling block
--      level_1a.level_2a;                     -- Error - Descendant of sibling block
        DBMS_OUTPUT.PUT_LINE('.. END BLOCK level_1b');
    END level_1b;
BEGIN
    DBMS_OUTPUT.PUT_LINE('BLOCK level_0');
    level_1b;
    DBMS_OUTPUT.PUT_LINE('END BLOCK level_0');
END level_0;
```

출력은 다음과 같습니다.

```sql
BEGIN
    level_0;
END;
```

Output

```text
BLOCK level_0
.. BLOCK level_1b
.. BLOCK level_1a
.. END BLOCK level_1a
.. END BLOCK level_1b
END BLOCK level_0
```

이 예제에서 프로시저 `level_1a`는 성공적으로 호출됩니다. 이는 프로시저 `level_3b`의 조상인 프로시저 `level_1b`의 형제입니다.

```sql
CREATE OR REPLACE PROCEDURE level_0
IS
    PROCEDURE level_1a
    IS
    BEGIN
        DBMS_OUTPUT.PUT_LINE('.. BLOCK level_1a');
        DBMS_OUTPUT.PUT_LINE('.. END BLOCK level_1a');
    END level_1a;
    PROCEDURE level_1b
    IS
        PROCEDURE level_2b
        IS
            PROCEDURE level_3b
            IS
            BEGIN
                DBMS_OUTPUT.PUT_LINE('........ BLOCK level_3b');
                level_1a;                      -- Ancestor's sibling block called
                level_0.level_1a;              -- Qualified ancestor's sibling block
                DBMS_OUTPUT.PUT_LINE('........ END BLOCK level_3b');
            END level_3b;
        BEGIN
            DBMS_OUTPUT.PUT_LINE('...... BLOCK level_2b');
            level_3b;                          -- Local block called
            DBMS_OUTPUT.PUT_LINE('...... END BLOCK level_2b');
        END level_2b;
    BEGIN
        DBMS_OUTPUT.PUT_LINE('.. BLOCK level_1b');
        level_2b;                              -- Local block called
        DBMS_OUTPUT.PUT_LINE('.. END BLOCK level_1b');
    END level_1b;
BEGIN
    DBMS_OUTPUT.PUT_LINE('BLOCK level_0');
    level_1b;
    DBMS_OUTPUT.PUT_LINE('END BLOCK level_0');
END level_0;
```

출력은 다음과 같습니다.

```sql
BEGIN
    level_0;
END;
```

Output

```text
BLOCK level_0
.. BLOCK level_1b
...... BLOCK level_2b
........ BLOCK level_3b
.. BLOCK level_1a
.. END BLOCK level_1a
.. BLOCK level_1a
.. END BLOCK level_1a
........ END BLOCK level_3b
...... END BLOCK level_2b
.. END BLOCK level_1b
END BLOCK level_0
```
