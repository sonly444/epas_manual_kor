# EXECUTE 권한 (EXECUTE privilege) — EPAS 18 SPL

> 원문: [EPAS v18 — SPL › Program security › EXECUTE privilege](https://www.enterprisedb.com/docs/epas/latest/application_programming/epas_compat_spl/02_spl_programs/09_program_security/01_execute_privilege/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·권한 이름은 원문 그대로 보존했습니다.

SPL 프로그램(함수, 프로시저, 또는 패키지)은 다음 중 하나라도 참이면 실행을 시작할 수 있습니다.

- 현재 사용자가 슈퍼유저(superuser)입니다.
- 현재 사용자에게 SPL 프로그램에 대한 `EXECUTE` 권한이 부여되었습니다.
- 현재 사용자가 이 권한을 가진 그룹의 멤버이기 때문에 SPL 프로그램에 대한 `EXECUTE` 권한을 상속합니다.
- `EXECUTE` 권한이 `PUBLIC` 그룹에 부여되었습니다.

EDB Postgres Advanced Server에서 SPL 프로그램이 생성될 때마다, `EXECUTE` 권한은 기본적으로 `PUBLIC` 그룹에 부여됩니다. 따라서 어떤 사용자든 즉시 프로그램을 실행할 수 있습니다.

`REVOKE EXECUTE` 명령을 사용하여 이 기본 권한을 제거할 수 있습니다. 예를 들면 다음과 같습니다.

```sql
REVOKE EXECUTE ON PROCEDURE list_emp FROM PUBLIC;
```

그런 다음 개별 사용자나 그룹에 프로그램에 대한 명시적 `EXECUTE` 권한을 부여할 수 있습니다.

```sql
GRANT EXECUTE ON PROCEDURE list_emp TO john;
```

이제 사용자 `john`은 `list_emp` 프로그램을 실행할 수 있습니다. 필요한 조건 중 어느 것도 충족하지 않는 다른 사용자는 실행할 수 없습니다.

프로그램이 실행을 시작하면, 그다음 보안 측면은 프로그램이 데이터베이스 객체에 대해 작업을 수행하려 할 때 발생하는 권한 검사입니다. 여기에는 다음이 포함됩니다.

- 테이블 또는 뷰 데이터 읽기 또는 수정
- 테이블, 뷰, 인덱스, 시퀀스와 같은 데이터베이스 객체 생성, 수정, 또는 삭제
- 시퀀스에서 현재 값 또는 다음 값 얻기
- 다른 프로그램(함수, 프로시저, 또는 패키지) 호출

이러한 각 작업은 데이터베이스 객체에 대한 권한으로 보호될 수 있으며, 사용자에게 허용되거나 허용되지 않을 수 있습니다.

데이터베이스에는 같은 유형에 같은 이름을 가진 객체가 둘 이상 존재할 수 있으며, 이때 각 객체는 데이터베이스의 서로 다른 스키마에 속합니다. 이런 경우, SPL 프로그램이 참조하는 객체는 어느 것일까요? 자세한 내용은 [데이터베이스 객체 이름 해석(Database object name resolution)](https://www.enterprisedb.com/docs/epas/latest/application_programming/epas_compat_spl/02_spl_programs/09_program_security/02_database_object_name_resolution/)을 참조하세요.
