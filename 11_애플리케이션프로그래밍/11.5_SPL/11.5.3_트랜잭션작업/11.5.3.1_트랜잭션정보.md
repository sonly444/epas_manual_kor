# 트랜잭션 정보 (About transactions) v18

트랜잭션은 SPL 프로그램에서 첫 번째 SQL 명령이 만나질 때 시작됩니다. 이후의 모든 SQL 명령은 해당 트랜잭션의 일부로 포함됩니다.

트랜잭션은 다음 중 하나가 발생하면 종료됩니다.

- 처리되지 않은 예외(unhandled exception)가 발생합니다. 이 경우 트랜잭션 중에 이루어진 모든 데이터베이스 업데이트의 효과가 롤백되고 트랜잭션이 중단됩니다.
- `COMMIT` 명령이 만나집니다. 이 경우 트랜잭션 중에 이루어진 모든 데이터베이스 업데이트의 효과가 영구적으로 됩니다.
- `ROLLBACK` 명령이 만나집니다. 이 경우 트랜잭션 중에 이루어진 모든 데이터베이스 업데이트의 효과가 롤백되고 트랜잭션이 중단됩니다. 새로운 SQL 명령이 만나지면 새로운 트랜잭션이 시작됩니다.
- 제어가 Java 또는 PSQL과 같은 호출 애플리케이션으로 반환됩니다. 이 경우 애플리케이션의 동작에 따라 트랜잭션이 커밋되거나 롤백될지 결정됩니다. 예외는 트랜잭션이 `PRAGMA AUTONOMOUS_TRANSACTION`이 선언된 블록 안에 있을 때입니다. 이 경우 트랜잭션의 커밋 또는 롤백은 호출 프로그램과 독립적으로 발생합니다.

##### 참고 (Note)

Oracle과 달리 `CREATE TABLE`과 같은 DDL 명령은 자체 트랜잭션에서 암시적으로 발생하지 않습니다. 따라서 DDL 명령은 Oracle에서처럼 즉각적인 데이터베이스 커밋을 유발하지 않으며, DML 명령과 마찬가지로 DDL 명령을 롤백할 수 있습니다.

트랜잭션은 하나 이상의 `BEGIN/END` 블록에 걸칠 수 있으며, 또는 단일 `BEGIN/END` 블록이 하나 이상의 트랜잭션을 포함할 수 있습니다.
