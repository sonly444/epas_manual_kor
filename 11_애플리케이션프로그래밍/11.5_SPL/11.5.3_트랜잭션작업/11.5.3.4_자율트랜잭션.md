# PRAGMA AUTONOMOUS_TRANSACTION v18

저장 프로시저 언어(stored procedural language, SPL) 프로그램은 SPL 블록의 선언 섹션에 다음 지시어(directive)를 지정하여 _자율 트랜잭션(autonomous transaction)_ 으로 선언할 수 있습니다. 자율 트랜잭션은 호출 프로그램에 의해 시작되는 독립적인 트랜잭션입니다.

```sql
PRAGMA AUTONOMOUS_TRANSACTION;
```

자율 트랜잭션에서 SQL 명령을 커밋하거나 롤백해도 호출 프로그램의 어떤 트랜잭션의 커밋 또는 롤백에도 영향을 미치지 않습니다. 호출 프로그램에서의 커밋 또는 롤백은 자율 트랜잭션의 SQL 명령의 커밋 또는 롤백에 영향을 미치지 않습니다.

## 요구 사항 및 제한 사항 (Requirements and restrictions)

다음 SPL 프로그램은 `PRAGMA AUTONOMOUS_TRANSACTION`을 포함할 수 있습니다.

- 독립 실행형(standalone) 프로시저 및 함수
- 익명 블록(anonymous block)
- 패키지 및 기타 호출 프로시저, 함수, 익명 블록에서 서브프로그램으로 선언된 프로시저 및 함수
- 트리거
- 객체 타입 메서드(object type method)

다음은 자율 트랜잭션과 관련된 문제 및 제한 사항입니다.

- 각 자율 트랜잭션은 진행 중인 동안 연결 슬롯(connection slot)을 하나 소비합니다. 경우에 따라 `postgresql.conf` 파일의 `max_connections` 파라미터를 높여야 할 수 있습니다.
- 대부분의 측면에서 자율 트랜잭션은 완전히 별도의 세션인 것처럼 동작하지만, GUC(`SET`으로 설정된 설정)는 의도적인 예외입니다. 자율 트랜잭션은 주변 값을 흡수하며, 커밋한 값을 외부 트랜잭션으로 전파할 수 있습니다.
- 자율 트랜잭션은 중첩될 수 있지만, 단일 세션에서 자율 트랜잭션은 16단계로 제한됩니다.
- 자율 트랜잭션에서는 병렬 쿼리(parallel query)가 지원되지 않습니다.
- EDB Postgres Advanced Server의 자율 트랜잭션 구현은 Oracle 데이터베이스와 완전히 호환되지는 않습니다. EDB Postgres Advanced Server의 자율 트랜잭션은 SPL 블록 끝에 커밋되지 않은 트랜잭션이 있어도 오류를 발생시키지 않습니다.

## 예제에 관하여 (About the examples)

다음 예제 세트는 자율 트랜잭션을 사용합니다. 이 첫 번째 시나리오 세트는 자율 트랜잭션이 없을 때의 기본 동작을 보여줍니다.

각 시나리오 전에 `dept` 테이블은 다음 초기값으로 재설정됩니다.

```sql
SELECT * FROM dept;
```

Output

```text
 deptno |   dname    |   loc
--------+------------+----------
     10 | ACCOUNTING | NEW YORK
     20 | RESEARCH   | DALLAS
     30 | SALES      | CHICAGO
     40 | OPERATIONS | BOSTON
(4 rows)
```

## 시나리오 1a: 자율 트랜잭션 없이 최종 COMMIT만 있는 경우 (Scenario 1a: No autonomous transactions with only a final COMMIT)

이 첫 번째 시나리오 세트는 세 개의 행을 삽입하는 것을 보여줍니다.

- 트랜잭션의 초기 `BEGIN` 명령 직후 시작
- 시작 트랜잭션 내의 익명 블록에서
- 익명 블록에서 실행되는 저장 프로시저에서

저장 프로시저는 다음과 같습니다.

```sql
CREATE OR REPLACE PROCEDURE insert_dept_70 IS
BEGIN
    INSERT INTO dept VALUES (70,'MARKETING','LOS ANGELES');
END;
```

PSQL 세션은 다음과 같습니다.

```sql
BEGIN;
INSERT INTO dept VALUES (50,'HR','DENVER');
BEGIN
    INSERT INTO dept VALUES (60,'FINANCE','CHICAGO');
    insert_dept_70;
END;
COMMIT;
```

최종 커밋 후 세 행이 모두 삽입됩니다.

```sql
SELECT * FROM dept ORDER BY 1;
```

Output

```text
 deptno |   dname    |     loc
--------+------------+-------------
     10 | ACCOUNTING | NEW YORK
     20 | RESEARCH   | DALLAS
     30 | SALES      | CHICAGO
     40 | OPERATIONS | BOSTON
     50 | HR         | DENVER
     60 | FINANCE    | CHICAGO
     70 | MARKETING  | LOS ANGELES
(7 rows)
```

## 시나리오 1b: 자율 트랜잭션은 없지만 최종 ROLLBACK이 있는 경우 (Scenario 1b: No autonomous transactions but a final ROLLBACK)

다음 시나리오는 모든 삽입 후 최종 `ROLLBACK` 명령이 세 삽입 모두의 롤백을 초래함을 보여줍니다.

```sql
BEGIN;
INSERT INTO dept VALUES (50,'HR','DENVER');
BEGIN
    INSERT INTO dept VALUES (60,'FINANCE','CHICAGO');
    insert_dept_70;
END;
ROLLBACK;

SELECT * FROM dept ORDER BY 1;
```

Output

```text
 deptno |   dname    |   loc
--------+------------+----------
     10 | ACCOUNTING | NEW YORK
     20 | RESEARCH   | DALLAS
     30 | SALES      | CHICAGO
     40 | OPERATIONS | BOSTON
(4 rows)
```

## 시나리오 1c: 자율 트랜잭션은 없지만 익명 블록 ROLLBACK이 있는 경우 (Scenario 1c: No autonomous transactions, but anonymous block ROLLBACK)

익명 블록 끝에 주어진 `ROLLBACK` 명령 또한 이전의 세 삽입을 모두 제거합니다.

```sql
BEGIN;
INSERT INTO dept VALUES (50,'HR','DENVER');
BEGIN
    INSERT INTO dept VALUES (60,'FINANCE','CHICAGO');
    insert_dept_70;
    ROLLBACK;
END;
COMMIT;

SELECT * FROM dept ORDER BY 1;
```

Output

```text
 deptno |   dname    |   loc
--------+------------+----------
     10 | ACCOUNTING | NEW YORK
     20 | RESEARCH   | DALLAS
     30 | SALES      | CHICAGO
     40 | OPERATIONS | BOSTON
(4 rows)
```

다음 시나리오 세트는 다양한 위치에서 `PRAGMA AUTONOMOUS_TRANSACTION`을 사용하여 자율 트랜잭션을 사용하는 효과를 보여줍니다.

## 시나리오 2a: COMMIT이 있는 익명 블록의 자율 트랜잭션 (Scenario 2a: Autonomous transaction of anonymous block with COMMIT)

프로시저는 처음 생성된 그대로입니다.

```sql
CREATE OR REPLACE PROCEDURE insert_dept_70 IS
BEGIN
    INSERT INTO dept VALUES (70,'MARKETING','LOS ANGELES');
END;
```

`PRAGMA AUTONOMOUS_TRANSACTION`은 익명 블록 끝의 `COMMIT` 명령과 함께 익명 블록에 지정됩니다.

```sql
BEGIN;
INSERT INTO dept VALUES (50,'HR','DENVER');
DECLARE
    PRAGMA AUTONOMOUS_TRANSACTION;
BEGIN
    INSERT INTO dept VALUES (60,'FINANCE','CHICAGO');
    insert_dept_70;
    COMMIT;
END;
ROLLBACK;
```

트랜잭션 끝의 `ROLLBACK` 후, 트랜잭션 시작 부분의 첫 번째 행 삽입만 폐기됩니다. `PRAGMA AUTONOMOUS_TRANSACTION`이 있는 익명 블록의 나머지 두 행 삽입은 독립적으로 커밋되었습니다.

```sql
SELECT * FROM dept ORDER BY 1;
```

Output

```text
 deptno |   dname    |     loc
--------+------------+-------------
     10 | ACCOUNTING | NEW YORK
     20 | RESEARCH   | DALLAS
     30 | SALES      | CHICAGO
     40 | OPERATIONS | BOSTON
     60 | FINANCE    | CHICAGO
     70 | MARKETING  | LOS ANGELES
(6 rows)
```

## 시나리오 2b: COMMIT이 있는 자율 트랜잭션 익명 블록에, ROLLBACK이 있지만 자율 트랜잭션 프로시저는 아닌 프로시저를 포함하는 경우 (Scenario 2b: Autonomous transaction anonymous block with COMMIT, including procedure with ROLLBACK but not an autonomous transaction procedure)

이 프로시저는 끝에 `ROLLBACK` 명령이 있습니다. 그러나 `PRAGMA ANONYMOUS_TRANSACTION`은 이 프로시저에 포함되어 있지 않습니다.

```sql
CREATE OR REPLACE PROCEDURE insert_dept_70 IS
BEGIN
    INSERT INTO dept VALUES (70,'MARKETING','LOS ANGELES');
    ROLLBACK;
END;
```

프로시저의 롤백은 익명 블록의 최종 `COMMIT` 명령 전에 익명 블록에 삽입된 두 행(`deptno` 60과 70)을 제거합니다.

```sql
BEGIN;
INSERT INTO dept VALUES (50,'HR','DENVER');
DECLARE
    PRAGMA AUTONOMOUS_TRANSACTION;
BEGIN
    INSERT INTO dept VALUES (60,'FINANCE','CHICAGO');
    insert_dept_70;
    COMMIT;
END;
COMMIT;
```

트랜잭션 끝의 최종 커밋 후, 삽입된 유일한 행은 트랜잭션 시작 부분의 첫 번째 행입니다. 익명 블록이 자율 트랜잭션이므로, 포함된 프로시저의 롤백은 익명 블록이 실행되기 전에 발생하는 삽입에는 영향을 미치지 않습니다.

```sql
SELECT * FROM dept ORDER by 1;
```

Output

```text
 deptno |   dname    |   loc
--------+------------+----------
     10 | ACCOUNTING | NEW YORK
     20 | RESEARCH   | DALLAS
     30 | SALES      | CHICAGO
     40 | OPERATIONS | BOSTON
     50 | HR         | DENVER
(5 rows)
```

## 시나리오 2c: COMMIT이 있는 자율 트랜잭션 익명 블록에, ROLLBACK이 있으면서 자율 트랜잭션 프로시저이기도 한 프로시저를 포함하는 경우 (Scenario 2c: Autonomous transaction anonymous block with COMMIT, including procedure with ROLLBACK that is also an autonomous transaction procedure)

끝에 `ROLLBACK` 명령이 있는 프로시저에 `PRAGMA ANONYMOUS_TRANSACTION`도 포함되어 있습니다. 이는 프로시저의 `ROLLBACK` 명령의 효과를 격리시킵니다.

```sql
CREATE OR REPLACE PROCEDURE insert_dept_70 IS
    PRAGMA AUTONOMOUS_TRANSACTION;
BEGIN
    INSERT INTO dept VALUES (70,'MARKETING','LOS ANGELES');
    ROLLBACK;
END;
```

프로시저의 롤백은 프로시저가 삽입한 행을 제거하지만 익명 블록에 삽입된 다른 행은 제거하지 않습니다.

```sql
BEGIN;
INSERT INTO dept VALUES (50,'HR','DENVER');
DECLARE
    PRAGMA AUTONOMOUS_TRANSACTION;
BEGIN
    INSERT INTO dept VALUES (60,'FINANCE','CHICAGO');
    insert_dept_70;
    COMMIT;
END;
COMMIT;
```

트랜잭션 끝의 최종 커밋 후, 삽입된 행은 트랜잭션 시작 부분의 첫 번째 행과 익명 블록 시작 부분에 삽입된 행입니다. 롤백된 유일한 삽입은 프로시저 내의 삽입입니다.

```sql
SELECT * FROM dept ORDER by 1;
```

Output

```text
 deptno |   dname    |   loc
--------+------------+----------
     10 | ACCOUNTING | NEW YORK
     20 | RESEARCH   | DALLAS
     30 | SALES      | CHICAGO
     40 | OPERATIONS | BOSTON
     50 | HR         | DENVER
     60 | FINANCE    | CHICAGO
(6 rows)
```

다음 예제는 몇 가지 다른 SPL 프로그램 유형에서의 `PRAGMA AUTONOMOUS_TRANSACTION`을 보여줍니다.

## 자율 트랜잭션 트리거 (Autonomous transaction trigger)

이 예제는 `PRAGMA AUTONOMOUS_TRANSACTION`으로 트리거를 선언한 효과를 보여줍니다.

`emp` 테이블에 대한 변경 사항을 로깅하기 위해 다음 테이블이 생성됩니다.

```sql
CREATE TABLE empauditlog (
    audit_date      DATE,
    audit_user      VARCHAR2(20),
    audit_desc      VARCHAR2(20)
);
```

이러한 변경 사항을 `empauditlog` 테이블에 삽입하는, `emp` 테이블에 연결된 트리거는 다음과 같습니다. `PRAGMA AUTONOMOUS_TRANSACTION`이 선언 섹션에 포함되어 있습니다.

```sql
CREATE OR REPLACE TRIGGER emp_audit_trig
    AFTER INSERT OR UPDATE OR DELETE ON emp
DECLARE
    PRAGMA AUTONOMOUS_TRANSACTION;
    v_action        VARCHAR2(20);
BEGIN
    IF INSERTING THEN
        v_action := 'Added employee(s)';
    ELSIF UPDATING THEN
        v_action := 'Updated employee(s)';
    ELSIF DELETING THEN
        v_action := 'Deleted employee(s)';
    END IF;
    INSERT INTO empauditlog VALUES (SYSDATE, USER,
        v_action);
END;
```

`BEGIN` 명령으로 시작된 트랜잭션에서 다음 두 삽입이 `emp` 테이블에 이루어집니다.

```sql
BEGIN;
INSERT INTO emp VALUES (9001,'SMITH','ANALYST',7782,SYSDATE,NULL,NULL,10);
INSERT INTO emp VALUES (9002,'JONES','CLERK',7782,SYSDATE,NULL,NULL,10);
```

다음은 `emp` 테이블의 두 새 행과 `empauditlog` 테이블의 두 항목을 보여줍니다.

```sql
SELECT * FROM emp WHERE empno > 9000;
```

Output

```text
 empno | ename |   job   | mgr  |      hiredate      | sal | comm | deptno
-------+-------+---------+------+--------------------+-----+------+--------
  9001 | SMITH | ANALYST | 7782 | 23-AUG-18 07:12:27 |     |      |     10
  9002 | JONES | CLERK   | 7782 | 23-AUG-18 07:12:27 |     |      |     10
(2 rows)
```

```sql
SELECT TO_CHAR(AUDIT_DATE,'DD-MON-YY HH24:MI:SS') AS "audit date",
 audit_user, audit_desc FROM empauditlog ORDER BY 1 ASC;
```

Output

```text
  audit date        |  audit_user  |    audit_desc
--------------------+--------------+-------------------
 23-AUG-18 07:12:27 | enterprisedb | Added employee(s)
 23-AUG-18 07:12:27 | enterprisedb | Added employee(s)
(2 rows)
```

그러나 그런 다음 이 세션 중에 `ROLLBACK` 명령이 주어집니다. `emp` 테이블은 더 이상 두 행을 포함하지 않지만, `empauditlog` 테이블은 여전히 두 항목을 포함합니다. 트리거는 암시적으로 커밋을 수행했으며, `PRAGMA AUTONOMOUS_TRANSACTION`은 호출 트랜잭션에서 주어진 롤백과 독립적으로 이러한 변경 사항을 커밋합니다.

```sql
ROLLBACK;

SELECT * FROM emp WHERE empno > 9000;
```

Output

```text
 empno | ename | job | mgr | hiredate | sal | comm | deptno
-------+-------+-----+-----+----------+-----+------+--------
(0 rows)
```

```sql
SELECT TO_CHAR(AUDIT_DATE,'DD-MON-YY HH24:MI:SS') AS "audit date",
    audit_user, audit_desc FROM empauditlog ORDER BY 1 ASC;
```

Output

```text
     audit date     |  audit_user  |    audit_desc
--------------------+--------------+-------------------
 23-AUG-18 07:12:27 | enterprisedb | Added employee(s)
 23-AUG-18 07:12:27 | enterprisedb | Added employee(s)
(2 rows)
```

## 자율 트랜잭션 객체 타입 메서드 (Autonomous transaction object type method)

이 예제는 `PRAGMA AUTONOMOUS_TRANSACTION`으로 객체 메서드를 선언한 효과를 보여줍니다.

다음 객체 타입과 객체 타입 본문(object type body)이 생성됩니다. 객체 타입 본문의 멤버 프로시저는 선언 섹션에 `PRAGMA AUTONOMOUS_TRANSACTION`을, 프로시저 끝에 `COMMIT`을 포함합니다.

```sql
CREATE OR REPLACE TYPE insert_dept_typ AS OBJECT (
    deptno          NUMBER(2),
    dname           VARCHAR2(14),
    loc             VARCHAR2(13),
    MEMBER PROCEDURE insert_dept
);

CREATE OR REPLACE TYPE BODY insert_dept_typ AS
    MEMBER PROCEDURE insert_dept
    IS
        PRAGMA AUTONOMOUS_TRANSACTION;
    BEGIN
        INSERT INTO dept VALUES (SELF.deptno,SELF.dname,SELF.loc);
        COMMIT;
    END;
END;
```

다음 익명 블록에서는 `dept` 테이블에 삽입이 수행되고, 이어서 객체의 `insert_dept` 메서드가 호출되며, 익명 블록의 `ROLLBACK` 명령으로 끝납니다.

```sql
BEGIN;
DECLARE
    v_dept          INSERT_DEPT_TYP :=
                      insert_dept_typ(60,'FINANCE','CHICAGO');
BEGIN
    INSERT INTO dept VALUES (50,'HR','DENVER');
    v_dept.insert_dept;
    ROLLBACK;
END;
```

`insert_dept`가 자율 트랜잭션으로 선언되었으므로, 부서 번호 60의 삽입은 테이블에 남아 있지만 롤백은 부서 50의 삽입을 제거합니다.

```sql
SELECT * FROM dept ORDER BY 1;
```

Output

```text
 deptno |   dname    |   loc
--------+------------+----------
     10 | ACCOUNTING | NEW YORK
     20 | RESEARCH   | DALLAS
     30 | SALES      | CHICAGO
     40 | OPERATIONS | BOSTON
     60 | FINANCE    | CHICAGO
(5 rows)
```
