# Varray 사용 (Using varrays) — EPAS 18 SPL 컬렉션

> 원문: [EPAS v18 — SPL › Working with collection types › Using varrays](https://www.enterprisedb.com/docs/epas/latest/application_programming/epas_compat_spl/10_collections/03_varrays/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 타입·구문·예외는 원문 그대로 보존했습니다.

*varray* 또는 *가변 크기 배열(variable-size array)*은 양의 정수를 값과 연관시키는 컬렉션 타입입니다. 여러 면에서 중첩 테이블과 유사합니다.

## Varray 개요

varray는 다음과 같은 특성을 가집니다.

- 최대 크기 제한을 가진 *varray 타입(varray type)*을 정의해야 합니다. varray 타입을 정의한 후에는 해당 varray 타입의 *varray 변수(varray variables)*를 선언할 수 있습니다. 데이터 조작은 varray 변수(간단히 varray라고도 함)를 사용하여 이루어집니다. varray의 요소 수는 varray 타입 정의에서 설정한 최대 크기 제한을 초과할 수 없습니다.
- varray 변수를 선언하면 varray는 처음에 null 컬렉션입니다. null varray는 *생성자(constructor)*로 초기화해야 합니다. 할당문의 오른쪽이 동일한 타입의 초기화된 varray인 할당문을 사용하여 varray를 초기화할 수도 있습니다.
- 키는 양의 정수입니다.
- 생성자는 varray의 요소 수를 설정하며, 이는 최대 크기 제한을 초과해서는 안 됩니다. `EXTEND` 메서드는 최대 크기 제한까지 varray에 요소를 추가할 수 있습니다. 자세한 내용은 [Collection methods](https://www.enterprisedb.com/docs/epas/latest/reference/application_programmer_reference/stored_procedural_language_reference/11_collection_methods/#collection_methods)를 참조하십시오.
- 중첩 테이블과 달리 varray는 희소(sparse)할 수 없습니다. 키에 값을 할당할 때 간격이 없습니다.
- 초기화되거나 확장된 크기를 넘지만 최대 크기 제한 이내에서 varray 요소를 참조하려고 하면 `SUBSCRIPT_BEYOND_COUNT` 예외가 발생합니다.
- 최대 크기 제한을 넘어 varray 요소를 참조하거나 최대 크기 제한을 넘어 varray를 확장하려고 하면 `SUBSCRIPT_OUTSIDE_LIMIT` 예외가 발생합니다.

## Varray 타입 정의

SPL 프로그램의 선언 섹션에서 `TYPE IS VARRAY` 문을 사용하여 varray 타입을 정의합니다.

```sql
TYPE <varraytype> IS { VARRAY | VARYING ARRAY }(<maxsize>)
  OF { <datatype> | <objtype> };
```

여기서:

`varraytype`은 varray 타입에 할당된 식별자입니다.

`datatype`은 `VARCHAR2`나 `NUMBER` 같은 스칼라 데이터 타입입니다.

`maxsize`는 해당 타입의 varray에 허용되는 최대 요소 수입니다.

`objtype`은 이전에 정의된 객체 타입입니다.

`CREATE TYPE` 명령을 사용하여 데이터베이스의 모든 SPL 프로그램에서 사용할 수 있는 varray 타입을 정의할 수 있습니다. varray를 사용하려면 그 varray 타입의 *변수(variable)*를 선언해야 합니다. 다음은 varray 변수를 선언하는 구문입니다.

```text
<varray> <varraytype>
```

여기서:

`varray`는 varray에 할당된 식별자입니다.

`varraytype`은 이전에 정의된 varray 타입의 식별자입니다.

## Varray 초기화

varray 타입의 생성자를 사용하여 varray를 초기화합니다.

```text
<varraytype> ([ { <expr1> | NULL } [, { <expr2> | NULL } ]\
  [, ...] ])
```

여기서:

`varraytype`은 varray 타입의 생성자 식별자로, varray 타입과 동일한 이름을 가집니다.

`expr1, expr2, …`는 varray의 요소 타입과 타입 호환되는 표현식입니다. `NULL`을 지정하면 해당 요소는 null로 설정됩니다. 파라미터 목록이 비어 있으면 빈 varray가 반환되며, 이는 varray에 요소가 없음을 의미합니다. varray가 객체 타입으로부터 정의된 경우, `exprn`은 해당 객체 타입의 객체를 반환해야 합니다. 이 객체는 함수의 반환 값이거나 객체 타입의 생성자의 반환 값일 수 있습니다. 이 객체는 또한 동일한 varray 타입의 다른 varray의 요소일 수도 있습니다.

초기화되지 않은 varray에 `EXISTS` 이외의 컬렉션 메서드를 적용하면 `COLLECTION_IS_NULL` 예외가 발생합니다. 자세한 내용은 [Collection methods](https://www.enterprisedb.com/docs/epas/latest/reference/application_programmer_reference/stored_procedural_language_reference/11_collection_methods/#collection_methods)를 참조하십시오.

다음은 varray의 생성자 예제입니다.

```sql
DECLARE
    TYPE varray_typ IS VARRAY(2) OF CHAR(1);
    v_varray        varray_typ := varray_typ('A','B');
```

## Varray 요소 참조

다음 구문을 사용하여 varray의 요소를 참조합니다.

```text
<varray>(<n>)[<.element> ]
```

여기서:

`varray`는 이전에 선언된 varray의 식별자입니다.

`n`은 양의 정수입니다.

`varray`의 varray 타입이 객체 타입으로부터 정의된 경우, `[.element ]`는 varray 타입이 정의된 객체 타입의 속성을 참조해야 합니다. 또는 `[.element ]`를 생략하여 전체 객체를 참조할 수 있습니다.

이 예제는 요소가 4개인 것으로 알려진 varray를 보여 줍니다.

```sql
DECLARE
    TYPE dname_varray_typ IS VARRAY(4) OF VARCHAR2(14);
    dname_varray    dname_varray_typ;
    CURSOR dept_cur IS SELECT dname FROM dept ORDER BY dname;
    i               INTEGER := 0;
BEGIN
    dname_varray := dname_varray_typ(NULL, NULL, NULL, NULL);
    FOR r_dept IN dept_cur LOOP
        i := i + 1;
        dname_varray(i) := r_dept.dname;
    END LOOP;
    DBMS_OUTPUT.PUT_LINE('DNAME');
    DBMS_OUTPUT.PUT_LINE('----------');
    FOR j IN 1..i LOOP
        DBMS_OUTPUT.PUT_LINE(dname_varray(j));
    END LOOP;
END;
```

다음은 이 예제의 출력입니다.

출력

```text
DNAME
----------
ACCOUNTING
OPERATIONS
RESEARCH
SALES
```
