# 트리거 생성 (Creating triggers) — EPAS 18 SPL 트리거

> 원문: [EPAS v18 — SPL › Working with triggers › Creating triggers](https://www.enterprisedb.com/docs/epas/latest/application_programming/epas_compat_spl/13_triggers/03_creating_triggers/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·키워드·구문은 원문 그대로 보존했습니다.

`CREATE TRIGGER` 명령은 데이터베이스에 저장되는 트리거를 정의하고 이름을 지정합니다. 단순(simple) 트리거 또는 복합(compound) 트리거를 생성할 수 있습니다.

## 단순 트리거 생성 (Creating a simple trigger)

`CREATE TRIGGER` — 단순 트리거를 정의합니다.

```sql
CREATE [ OR REPLACE ] TRIGGER <name>
  { BEFORE | AFTER | INSTEAD OF }
  { INSERT | UPDATE | DELETE | TRUNCATE }
      [ OR { INSERT | UPDATE | DELETE | TRUNCATE } ] [, ...]
    ON <table>
  [ REFERENCING { OLD AS <old> | NEW AS <new> } ...]
  [ FOR EACH ROW ]
  [ WHEN <condition> ]
  [ DECLARE
      [ PRAGMA AUTONOMOUS_TRANSACTION; ]
      <declaration>; [, ...] ]
    BEGIN
      <statement>; [, ...]
  [ EXCEPTION
    { WHEN <exception> [ OR <exception> ] [...] THEN
        <statement>; [, ...] } [, ...]
  ]
    END
```

## 복합 트리거 생성 (Creating a compound trigger)

`CREATE TRIGGER` — 복합 트리거를 정의합니다.

```sql
CREATE [ OR REPLACE ] TRIGGER <name>
  FOR { INSERT | UPDATE | DELETE | TRUNCATE }
        [ OR { INSERT | UPDATE | DELETE | TRUNCATE } ] [, ...]
           ON <table>
       [ REFERENCING { OLD AS <old> | NEW AS <new>. } ...]
       [ WHEN <condition> ]
       COMPOUND TRIGGER
       [ <private_declaration>; ] ...
       [ <procedure_or_function_definition> ] ...
       <compound_trigger_definition>
         END
```

여기서 `private_declaration`은 임의의 프로시저나 함수가 접근할 수 있는 비공개 변수의 식별자입니다. 비공개 변수는 0개, 1개, 또는 여러 개일 수 있습니다. `private_declaration`은 다음 중 어느 것이든 될 수 있습니다.

- 변수 선언(Variable declaration)
- 레코드 선언(Record declaration)
- 컬렉션 선언(Collection declaration)
- `REF CURSOR` 및 커서 변수 선언(cursor variable declaration)
- 레코드, 컬렉션, `REF CURSOR`에 대한 `TYPE` 정의
- 예외(Exception)
- 객체 변수 선언(Object variable declaration)

여기서 `procedure_or_function_definition :=`

`procedure_definition | function_definition`

여기서 `procedure_definition :=`

```sql
PROCEDURE proc_name[ argument_list ]
  [ options_list ]
  { IS | AS }
    procedure_body
  END [ proc_name ] ;
```

여기서 `procedure_body :=`

```sql
[ <declaration>; ] [, ...]
BEGIN
  <statement>; [...]
[ EXCEPTION
   { WHEN <exception> [OR <exception>] [...]] THEN <statement>; }
   [...]
]
```

여기서 `function_definition :=`

```sql
FUNCTION func_name [ argument_list ]
  RETURN rettype [ DETERMINISTIC ]
  [ options_list ]
  { IS | AS }
    function_body
  END [ func_name ] ;
```

여기서 `function_body :=`

```sql
[ <declaration>; ] [, ...]
BEGIN
  <statement>; [...]
[ EXCEPTION
  { WHEN <exception> [ OR <exception> ] [...] THEN <statement>; }
  [...]
]
```

여기서 `compound_trigger_definition`은 다음과 같습니다.

```sql
{ compound_trigger_event } { IS | AS }
  compound_trigger_body
END [ compound_trigger_event ] [ ... ]
```

여기서 `compound_trigger_event:=`

```sql
[ BEFORE STATEMENT | BEFORE EACH ROW | AFTER EACH ROW | AFTER STATEMENT  | INSTEAD OF EACH ROW ]
```

여기서 `compound_trigger_body:=`

```sql
[ <declaration>; ] [, ...]
BEGIN
  <statement>; [...]
[ EXCEPTION
   { WHEN <exception> [OR <exception>] [...] THEN <statement>; }
   [...]
]
```

## 설명 (Description)

`CREATE TRIGGER`는 새 트리거를 정의합니다. `CREATE OR REPLACE TRIGGER`는 새 트리거를 생성하거나 기존 정의를 대체합니다.

`CREATE TRIGGER` 키워드를 사용하여 트리거를 생성하는 경우, 새 트리거의 이름은 동일한 테이블에 정의된 기존 트리거와 일치해서는 안 됩니다. 새 트리거는 트리거 발생 이벤트가 정의된 테이블과 동일한 스키마에 생성됩니다.

기존 트리거의 정의를 업데이트하는 경우 `CREATE OR REPLACE TRIGGER` 키워드를 사용합니다.

Oracle 데이터베이스와 호환되는 구문을 사용하여 트리거를 생성하면, 트리거는 `SECURITY DEFINER` 함수로 실행됩니다.

## 파라미터 (Parameters)

`name`

생성할 트리거의 이름입니다.

`BEFORE | AFTER`

트리거가 트리거 발생 이벤트의 전에 발생할지 후에 발생할지를 결정합니다.

`INSTEAD OF`

업데이트 가능한 뷰(updatable view)를 수정하는 트리거입니다. 이 트리거는 기반 테이블을 적절하게 업데이트하기 위해 실행됩니다. `INSTEAD OF` 트리거는 업데이트되거나 수정되는 뷰의 각 행에 대해 실행됩니다.

`INSERT | UPDATE | DELETE | TRUNCATE`

트리거 발생 이벤트를 정의합니다.

`table`

트리거 발생 이벤트가 발생하는 테이블 또는 뷰의 이름입니다.

`condition`

트리거가 실제로 실행될지를 결정하는 불리언 표현식입니다. `condition`이 `TRUE`로 평가되면 트리거가 발생합니다.

- 단순 트리거 정의에 `FOR EACH ROW` 키워드가 포함되어 있으면, `WHEN` 절은 각각 `OLD.column_name` 또는 `NEW.column_name`을 작성하여 이전(old) 또는 새(new) 행 값의 컬럼을 참조할 수 있습니다. `INSERT` 트리거는 `OLD`를 참조할 수 없고, `DELETE` 트리거는 `NEW`를 참조할 수 없습니다.

- 복합 트리거 정의에 `WHEN` 절을 가진 문 수준 트리거가 포함되어 있으면, 트리거는 `WHEN` 절의 표현식을 평가하지 않고 실행됩니다. 마찬가지로, 복합 트리거 정의에 `WHEN` 절을 가진 행 수준 트리거가 포함되어 있으면, 표현식이 `TRUE`로 평가될 경우 트리거가 실행됩니다.

- 트리거에 `INSTEAD OF` 키워드가 포함되어 있으면 `WHEN` 절을 포함할 수 없습니다. `WHEN` 절은 서브쿼리를 포함할 수 없습니다.

`REFERENCING { OLD AS old | NEW AS new } ...`

이전 행과 새 행을 참조하기 위한 `REFERENCING` 절이지만, `old`는 오직 `old`라는 이름의 식별자 또는 모두 소문자로 저장되는 동등한 식별자로만 대체할 수 있다는 제한이 있습니다. 예로는 `REFERENCING OLD AS old`, `REFERENCING OLD AS OLD`, 또는 `REFERENCING OLD AS "old"`가 있습니다. 또한 `new`는 오직 `new`라는 이름의 식별자 또는 모두 소문자로 저장되는 동등한 식별자로만 대체할 수 있습니다. 예로는 `REFERENCING NEW AS new`, `REFERENCING NEW AS NEW`, 또는 `REFERENCING NEW AS "new"`가 있습니다.

`REFERENCING` 절에서는 `OLD AS old`와 `NEW AS new` 두 구문 중 하나 또는 둘 다를 지정할 수 있으며, 예를 들어 `REFERENCING NEW AS New OLD AS Old`처럼 지정할 수 있습니다. 이 절은 `old` 또는 `new` 이외의 식별자를 사용할 수 없다는 점에서 Oracle 데이터베이스와 호환되지 않습니다.

`FOR EACH ROW`

트리거를 트리거 발생 이벤트의 영향을 받는 모든 행마다 한 번씩 발생시킬지 아니면 SQL 문마다 한 번씩 발생시킬지를 결정합니다. 지정하면 영향을 받는 모든 행마다 한 번씩 트리거가 발생합니다(행 수준 트리거). 그렇지 않으면 트리거는 문 수준 트리거가 됩니다.

`PRAGMA AUTONOMOUS_TRANSACTION`

`PRAGMA AUTONOMOUS_TRANSACTION`은 트리거를 자율 트랜잭션(autonomous transaction)으로 설정하는 지시어입니다.

`declaration`

변수, 타입, `REF CURSOR`, 또는 서브프로그램 선언입니다. 서브프로그램 선언을 포함하는 경우, 다른 모든 변수, 타입, `REF CURSOR` 선언 뒤에 선언해야 합니다.

`statement`

SPL 프로그램 문입니다. `DECLARE - BEGIN - END` 블록은 하나의 SPL 문으로 간주됩니다. 따라서 트리거 본문은 중첩된 블록을 포함할 수 있습니다.

`exception`

`NO_DATA_FOUND`와 같은 예외 조건 이름입니다.
