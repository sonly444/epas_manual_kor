# Object type specification syntax — EPAS 18 SPL 객체 타입

> 원문: [EPAS v18 — SPL › Using object types and objects › Object type components › Object type specification syntax](https://www.enterprisedb.com/docs/epas/latest/application_programming/epas_compat_spl/15_object_types_and_objects/02_object_type_components/01_object_type_specification_syntax/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·코드 이름은 원문 그대로 보존했습니다.

객체 타입 명세(object type specification)의 구문은 다음과 같습니다.

```sql
CREATE [ OR REPLACE ] TYPE <name>
  [ AUTHID { DEFINER | CURRENT_USER } ]
  { IS | AS } OBJECT
( { <attribute> { <datatype> | <objtype> | <collecttype> } }
    [, ...]
  [ <method_spec> ] [, ...]
  [ <constructor> ] [, ...]
) [ [ NOT ] { FINAL | INSTANTIABLE } ] ...;
```

여기서 `method_spec`은 다음과 같습니다.

```sql
[ [ NOT ] { FINAL | INSTANTIABLE } ] ...
[ OVERRIDING ]
  <subprogram_spec>
```

여기서 `subprogram_spec`은 다음과 같습니다.

```sql
{ MEMBER | STATIC }
{ PROCEDURE <proc_name>
    [ ( [  SELF [ IN | IN OUT ] <name> ]\
        [, <parm1> [ IN | IN OUT | OUT ] <datatype1>\
                   [ DEFAULT <value1> ] ]\
        [, <parm2> [ IN | IN OUT | OUT ] <datatype2>\
                   [ DEFAULT <value2> ]\
        ] ...)\
    ]
|
  FUNCTION <func_name>
    [ ( [  SELF [ IN | IN OUT ] <name> ]\
        [, <parm1> [ IN | IN OUT | OUT ] <datatype1>\
                   [ DEFAULT <value1> ] ]\
        [, <parm2> [ IN | IN OUT | OUT ] <datatype2>\
                   [ DEFAULT <value2> ]\
        ] ...)\
    ]
  RETURN <return_type>
}
```

여기서 `constructor`는 다음과 같습니다.

```sql
CONSTRUCTOR FUNCTION <func_name>
  [ ( [ <parm1> [ IN | IN OUT | OUT ] <datatype1>\
                 [ DEFAULT <value1> ] ]\
      [, <parm2> [ IN | IN OUT | OUT ] <datatype2>\
                 [ DEFAULT <value2> ]\
      ] ...)\
  ]
RETURN <return_type>;
```

##### 참고 (Note)

- 기존 객체 타입의 속성을 추가, 삭제 또는 수정하기 위해 `OR REPLACE` 옵션을 사용할 수는 없습니다. 먼저 `DROP TYPE` 명령을 사용하여 기존 객체 타입을 삭제해야 합니다. 기존 객체 타입의 메서드를 추가, 삭제 또는 수정하기 위해서는 `OR REPLACE` 옵션을 사용할 수 있습니다.

- PostgreSQL 형식의 `ALTER TYPE ALTER ATTRIBUTE` 명령을 사용하여 기존 객체 타입에서 속성의 데이터 타입을 변경할 수 있습니다. 그러나 `ALTER TYPE` 명령으로는 객체 타입에서 속성을 추가하거나 삭제할 수 없습니다.

`name`은 객체 타입에 할당된 식별자(선택적으로 스키마로 한정 가능)입니다.

`AUTHID` 절을 생략하거나 `DEFINER`를 지정하면, 데이터베이스 객체에 대한 접근 권한을 결정하는 데 객체 타입 소유자의 권한이 사용됩니다. `CURRENT_USER`를 지정하면, 객체 안의 메서드를 실행하는 현재 사용자의 권한이 접근 권한을 결정합니다.

## 구문 (Syntax)

`attribute`는 객체 타입의 속성에 할당된 식별자입니다.

`datatype`은 기본 데이터 타입입니다.

`objtype`은 이전에 정의된 객체 타입입니다.

`collecttype`은 이전에 정의된 컬렉션 타입입니다.

`CREATE TYPE` 정의의 닫는 괄호 뒤에 오는 `[ NOT ] FINAL`은 이 객체 타입으로부터 서브타입(subtype)을 파생시킬 수 있는지 여부를 지정합니다. 기본값인 `FINAL`은 이 객체 타입으로부터 어떤 서브타입도 파생시킬 수 없음을 의미합니다. 이 객체 타입 아래에 서브타입을 정의할 수 있도록 허용하려면 `NOT FINAL`을 지정하십시오.

##### 참고 (Note)

`CREATE TYPE` 명령에서 `NOT FINAL`의 지정이 허용되기는 하지만, SPL은 현재 서브타입 생성을 지원하지 않습니다.

`CREATE TYPE` 정의의 닫는 괄호 뒤에 오는 `[ NOT ] INSTANTIABLE`은 이 객체 타입의 객체 인스턴스를 생성할 수 있는지 여부를 지정합니다. 기본값인 `INSTANTIABLE`은 이 객체 타입의 인스턴스를 생성할 수 있음을 의미합니다. 이 객체 타입을 다른 특수화된 서브타입들이 정의되는 상위 "템플릿"으로만 사용하려면 `NOT INSTANTIABLE`을 지정하십시오. `NOT INSTANTIABLE`을 지정하는 경우에는 `NOT FINAL`도 함께 지정해야 합니다. 객체 타입의 어떤 메서드에 `NOT INSTANTIABLE` 한정자가 포함되어 있으면, 그 객체 타입은 `NOT INSTANTIABLE`과 `NOT FINAL`로 정의되어야 합니다.

##### 참고 (Note)

`CREATE TYPE` 명령에서 `NOT INSTANTIABLE`의 지정이 허용되기는 하지만, SPL은 현재 서브타입 생성을 지원하지 않습니다.

## method_spec

`method_spec`은 멤버 메서드 또는 정적 메서드의 명세를 나타냅니다.

메서드를 정의하기 전에, `[ NOT ] FINAL`을 사용하여 그 메서드를 서브타입에서 재정의(override)할 수 있는지 여부를 지정합니다. 기본값은 `NOT FINAL`이며, 이는 그 메서드를 서브타입에서 재정의할 수 있음을 의미합니다.

메서드를 정의하기 전에, 그 메서드가 슈퍼타입(supertype)의 동일한 이름을 가진 메서드를 재정의하는 경우 `OVERRIDING`을 지정합니다. 재정의하는 메서드는 슈퍼타입에 정의된 것과 동일한 개수의, 동일한 이름을 가진 메서드 매개변수를, 동일한 데이터 타입과 매개변수 모드로, 동일한 순서로, 그리고 (메서드가 함수인 경우) 동일한 반환 타입으로 가져야 합니다.

메서드를 정의하기 전에, `[ NOT ] INSTANTIABLE`을 사용하여 그 객체 타입 정의가 해당 메서드에 대한 구현을 제공하는지 여부를 지정합니다. `INSTANTIABLE`을 지정하면, 그 객체 타입에 대한 `CREATE TYPE BODY` 명령에서 해당 메서드의 구현을 반드시 지정해야 합니다. `NOT INSTANTIABLE`을 지정하면, 그 객체 타입에 대한 `CREATE TYPE BODY` 명령에 해당 메서드의 구현이 포함되어서는 안 됩니다. 후자의 경우, 서브타입이 해당 메서드의 구현을 포함하여 이 객체 타입의 메서드를 재정의한다고 가정합니다. 객체 타입에 `NOT INSTANTIABLE` 메서드가 하나라도 있으면, 그 객체 타입 정의는 객체 타입 명세의 닫는 괄호 뒤에 `NOT INSTANTIABLE`과 `NOT FINAL`을 지정해야 합니다. 기본값은 `INSTANTIABLE`입니다.

## subprogram_spec

`subprogram_spec`은 프로시저 또는 함수의 명세를 나타내며 `MEMBER` 또는 `STATIC` 중 하나의 지정으로 시작합니다. 멤버 서브프로그램은 특정 객체 인스턴스와 관련하여 호출되어야 하는 반면, 정적 서브프로그램은 어떤 객체 인스턴스와도 관련 없이 호출됩니다.

`proc_name`은 프로시저의 식별자입니다. `SELF` 매개변수를 지정하는 경우, `name`은 `CREATE TYPE` 명령에서 주어진 객체 타입 이름입니다. 지정되는 경우, `parm1, parm2, …`는 프로시저의 형식 매개변수(formal parameter)입니다. `datatype1, datatype2, …`는 각각 `parm1, parm2, …`의 데이터 타입입니다. `IN`, `IN OUT`, `OUT`은 각 형식 매개변수에 가능한 매개변수 모드입니다. 기본값은 `IN`입니다. `value1, value2, …`는 `IN` 매개변수에 대해 지정할 수 있는 기본값입니다.

## CONSTRUCTOR

생성자 함수를 정의하려면 `CONSTRUCTOR FUNCTION` 키워드와 함수 정의를 포함하십시오.

`func_name`은 함수의 식별자입니다. 지정되는 경우, `parm1, parm2, …`는 함수의 형식 매개변수입니다. `datatype1, datatype2, …`는 각각 `parm1, parm2, …`의 데이터 타입입니다. `IN`, `IN OUT`, `OUT`은 각 형식 매개변수에 가능한 매개변수 모드입니다. 기본값은 `IN`입니다. `value1, value2, …`는 `IN` 매개변수에 대해 지정할 수 있는 기본값입니다. `return_type`은 함수가 반환하는 값의 데이터 타입입니다.

객체 타입 명세에 대해 다음 사항에 유의하십시오.

- 객체 타입에는 최소한 하나의 속성이 정의되어야 합니다.

- 객체 타입에는 0개, 1개, 또는 여러 개의 메서드가 정의될 수 있습니다.

- 정적 메서드는 재정의할 수 없습니다. `method_spec`에서 `OVERRIDING`과 `STATIC`을 함께 지정할 수 없습니다.

- 정적 메서드는 인스턴스화 가능(instantiable)해야 합니다. `method_spec`에서 `NOT INSTANTIABLE`과 `STATIC`을 함께 지정할 수 없습니다.
