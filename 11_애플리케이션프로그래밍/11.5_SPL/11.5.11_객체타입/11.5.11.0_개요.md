# 객체 타입과 객체 사용 (Using object types and objects) — EPAS 18 SPL

> 원문: [EPAS v18 — SPL › Using object types and objects](https://www.enterprisedb.com/docs/epas/latest/application_programming/epas_compat_spl/15_object_types_and_objects/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 용어·명령은 원문 그대로 보존했습니다.

SPL에서 객체 지향 프로그래밍(object-oriented programming) 기법을 사용할 수 있습니다. Java나 C++ 같은 프로그래밍 언어에서 볼 수 있는 객체 지향 프로그래밍은 _객체(object)_ 개념을 중심으로 합니다. 객체는 사람, 장소, 사물 같은 실세계 엔티티를 나타냅니다. 예를 들어 사람 같은 특정 객체의 일반적 설명 또는 정의를 _객체 타입(object type)_ 이라고 합니다. "Joe"나 "Sally" 같은 특정 사람은 person _객체 타입의 객체(objects of object type)_ 라고 합니다. 이들은 person 객체 타입의 _인스턴스(instance)_, 또는 간단히 person 객체라고도 합니다.

SPL에서 객체와 객체 타입을 만들 수 있습니다.

##### 참고

- "데이터베이스 객체(database objects)"와 "객체(objects)"라는 용어는 객체 지향 프로그래밍에서 사용하는 "객체 타입(object type)"과 "객체(object)"라는 용어와 다릅니다. 데이터베이스 객체는 테이블, 뷰, 인덱스, 사용자와 같이 데이터베이스에서 생성할 수 있는 엔티티입니다. 객체 지향 프로그래밍의 맥락에서 객체 타입과 객체는 객체 지향 개념을 구현하기 위해 SPL 프로그래밍 언어가 지원하는 특정 데이터 구조를 가리킵니다.

- Oracle에서 _추상 데이터 타입(abstract data type, ADT)_ 이라는 용어는 PL/SQL의 객체 타입을 설명합니다. SPL의 객체 타입 구현은 Oracle 추상 데이터 타입과 호환되도록 만들어졌습니다.

- EDB Postgres Advanced Server는 객체 지향 프로그래밍 언어의 일부 기능은 아직 구현하지 않았습니다.
