# RANGE 파티션 테이블의 다중 파티셔닝 키 지정 (Specifying multiple partitioning keys in a RANGE partitioned table) — EPAS 18 테이블 파티셔닝

> 원문: [EPAS v18 — Table partitioning › Specifying multiple partitioning keys in a RANGE partitioned table](https://www.enterprisedb.com/docs/epas/latest/application_programming/epas_compat_table_partitioning/06_specifying_multiple_partitioning_keys_in_a_range_partitioned_table/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·코드는 원문 그대로 보존했습니다.

이 문서는 특히 쿼리가 제한된 컬럼 집합에 대해 비교 연산자로 자주 필터링하는 경우, `RANGE` 파티션 테이블에서 여러 키 컬럼을 사용하면 성능이 향상될 수 있음을 설명합니다.

## 구현

다중 키 범위 파티션을 만들려면 `PARTITION BY RANGE` 절 뒤에 쉼표로 구분된 목록으로 컬럼 이름을 포함합니다. 예제는 `sale_year`와 `sale_month`로 파티션된 sales 테이블을 보여 줍니다.

```sql
CREATE TABLE sales
(
  dept_no      number,
  part_no      varchar2,
  country      varchar2(20),
  sale_year    number,
  sale_month   number,
  sale_day     number,
  amount       number
)
PARTITION BY RANGE(sale_year, sale_month)
(
  PARTITION q1_2012
    VALUES LESS THAN(2012, 4),
  PARTITION q2_2012
    VALUES LESS THAN(2012, 7),
  PARTITION q3_2012
    VALUES LESS THAN(2012, 10),
  PARTITION q4_2012
    VALUES LESS THAN(2013, 1)
);
```

## 파티션 프루닝 이점

테이블이 여러 파티셔닝 키를 사용할 때, 모든 키 값을 지정하는 쿼리는 효과적인 파티션 프루닝을 가능하게 합니다. 제공된 예제는 `sale_year`와 `sale_month` 모두로 필터링하는 쿼리가 여러 파티션을 확인하는 대신 관련 파티션(`sales_q3_2012`)만 스캔함을 보여 줍니다.
