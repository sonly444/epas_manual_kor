# MAXVALUE 파티션 정의 (Defining a MAXVALUE partition) — EPAS 18 테이블 파티셔닝

> 원문: [EPAS v18 — Application programming › Table partitioning › Handling stray values › Defining a MAXVALUE partition](https://www.enterprisedb.com/docs/epas/latest/application_programming/epas_compat_table_partitioning/05_handling_stray_values_in_a_list_or_range_partitioned_table/defining_a_maxvalue_partition/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 명령·코드 이름은 원문 그대로 보존했습니다.

`MAXVALUE` 파티션 또는 서브파티션은 범위 파티션 또는 서브파티션 테이블에서 다른 어떤 파티션에도 맞지 않는 행을 포착합니다. `MAXVALUE` 규칙을 포함하지 않으면 파티셔닝 규칙에 지정된 최대 한도를 초과하는 행은 오류를 발생시킵니다. 각 파티션 또는 서브파티션은 자체 `MAXVALUE` 파티션을 가질 수 있습니다.

`MAXVALUE` 규칙의 구문은 다음과 같습니다:

```sql
PARTITION [<partition_name>] VALUES LESS THAN (MAXVALUE)
```

여기서 `partition_name`은 다른 파티션에 지정된 규칙과 일치하지 않는 행을 저장하는 파티션의 이름을 지정합니다.

[이 예제](https://www.enterprisedb.com/docs/epas/latest/application_programming/epas_compat_table_partitioning/06_specifying_multiple_partitioning_keys_in_a_range_partitioned_table/)는 `date` 열의 값을 기준으로 데이터가 파티셔닝된 범위 파티션 테이블을 생성했습니다. 파티셔닝 제약조건에 나열된 날짜를 초과하는 `date` 값을 가진 행을 추가하려고 하면 EDB Postgres Advanced Server는 오류를 보고합니다.

```sql
edb=# INSERT INTO sales VALUES
edb-#   (40, '3000x', 'IRELAND', '01-Mar-2013', '45000');
ERROR:  no partition of relation "sales" found for row
DETAIL:  Partition key of the failing row contains (date) = (01-MAR-13 00:00:00).
```

이 `CREATE TABLE` 명령은 동일한 테이블을 생성하되 `MAXVALUE` 파티션을 포함합니다. 오류를 발생시키는 대신, 서버는 이전 파티셔닝 제약조건과 일치하지 않는 행을 `others` 파티션에 저장합니다.

```sql
CREATE TABLE sales
(
  dept_no     number,
  part_no     varchar2,
  country     varchar2(20),
  date        date,
  amount      number
)
PARTITION BY RANGE(date)
(
  PARTITION q1_2012 VALUES LESS THAN('2012-Apr-01'),
  PARTITION q2_2012 VALUES LESS THAN('2012-Jul-01'),
  PARTITION q3_2012 VALUES LESS THAN('2012-Oct-01'),
  PARTITION q4_2012 VALUES LESS THAN('2013-Jan-01'),
  PARTITION others VALUES LESS THAN (MAXVALUE)
);
```

`MAXVALUE` 파티션을 테스트하려면 파티셔닝 규칙에 나열된 마지막 날짜 값을 초과하는 값을 `date` 열에 담은 행을 추가합니다. 서버는 그 행을 `others` 파티션에 저장합니다.

```sql
INSERT INTO sales VALUES
  (40, '3000x', 'IRELAND', '01-Mar-2013', '45000');
```

`sales` 테이블의 내용을 조회하여 이전에 거부되었던 행이 이제 `sales_others` 파티션에 저장되었는지 확인합니다:

```sql
edb=# SELECT tableoid::regclass, * FROM sales;
```

EDB Postgres Advanced Server는 `MAXVALUE` 파티션 또는 서브파티션의 내용을 재할당하는 방법을 제공하지 않습니다.

- `MAXVALUE` 규칙이 있는 테이블에는 `ALTER TABLE… ADD PARTITION` 문을 사용하여 파티션을 추가할 수 없습니다. 그러나 `ALTER TABLE… SPLIT PARTITION` 문을 사용하여 기존 파티션을 분할할 수는 있습니다.
- `MAXVALUE` 규칙이 있는 테이블에는 `ALTER TABLE… ADD SUBPARTITION` 문을 사용하여 서브파티션을 추가할 수 없습니다. 그러나 `ALTER TABLE… SPLIT SUBPARTITION` 문을 사용하여 기존 서브파티션을 분할할 수는 있습니다.
