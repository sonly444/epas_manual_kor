# 파티션 유형 선택 (Selecting a partition type) — EPAS 18 테이블 파티셔닝

> 원문: [EPAS v18 — Table partitioning › Selecting a partition type](https://www.enterprisedb.com/docs/epas/latest/application_programming/epas_compat_table_partitioning/02_selecting_a_partition_type/)
> EPAS v18 공식 문서의 한글 **전문 번역**입니다. 키워드·명령은 원문 그대로 보존했습니다.

파티션 테이블을 만들 때 `LIST`, `RANGE`, 또는 `HASH` 파티셔닝 규칙을 지정합니다. 파티셔닝 규칙은 각 파티션에 저장되는 데이터를 정의하는 제약 조건 집합을 제공합니다. 파티션 테이블에 행을 추가하면 서버는 파티셔닝 규칙을 사용하여 어느 파티션이 각 행을 포함할지 결정합니다.

EDB Postgres Advanced Server는 또한 파티셔닝 규칙을 사용하여 파티션 프루닝(partition pruning)을 강제할 수 있으며, 이는 사용자 쿼리에 응답할 때 성능을 향상시킵니다. 테이블의 파티셔닝 유형과 파티셔닝 키를 선택할 때는 테이블에 저장된 데이터가 어떻게 질의되는지 고려하고, 자주 질의되는 컬럼을 파티셔닝 규칙에 포함하십시오.

## 리스트 파티셔닝 (List Partitioning)

리스트 파티션 테이블을 만들 때 단일 파티셔닝 키 컬럼을 지정합니다. 테이블에 행을 추가할 때 서버는 파티셔닝 규칙에 지정된 키 값을 행의 해당 컬럼과 비교합니다. 컬럼 값이 파티셔닝 규칙의 값과 일치하면 행은 규칙에 명명된 파티션에 저장됩니다.

**참고:** 리스트 파티셔닝은 다중 컬럼 리스트 파티셔닝(multi-column list partitioning)을 지원하지 않습니다.

리스트 파티셔닝 키의 새로운 고유 값에 대해 데이터베이스가 자동으로 파티션을 생성하게 하는 `LIST` 파티셔닝 확장에 대한 정보는 자동 리스트 파티셔닝(Automatic list partitioning)을 참조하십시오.

## 범위 파티셔닝 (Range Partitioning)

범위 파티션 테이블을 만들 때 하나 이상의 파티셔닝 키 컬럼을 지정합니다. 테이블에 행을 추가할 때 서버는 파티셔닝 키의 값을 테이블 항목의 해당 컬럼과 비교합니다. 컬럼 값이 파티셔닝 규칙에 지정된 조건을 만족하면 행은 규칙에 명명된 파티션에 저장됩니다.

삽입된 데이터가 기존 파티션의 범위를 초과할 때 데이터베이스가 파티션을 생성하게 하는 범위 파티셔닝 확장에 대한 정보는 인터벌 범위 파티셔닝(Interval range partitioning)을 참조하십시오.

## 해시 파티셔닝 (Hash Partitioning)

해시 파티션 테이블을 만들 때 하나 이상의 파티셔닝 키 컬럼을 지정합니다. 데이터는 지정된 파티션들 사이에 대략 동일한 크기의 파티션으로 나뉩니다. 해시 파티션 테이블에 행을 추가하면 서버는 지정된 컬럼의 데이터에 대한 해시 값을 계산하고 해시 값에 따라 행을 파티션에 저장합니다.

**참고:** EDB Postgres Advanced Server를 업그레이드할 때, 업그레이드된 버전 서버에서 각 해시 파티션 테이블을 다시 빌드해야 합니다.

## 서브파티셔닝 (Subpartitioning)

서브파티셔닝은 파티션 테이블을 더 작은 부분 집합으로 나눕니다. 모든 부분 집합은 동일한 데이터베이스 서버 클러스터에 저장해야 합니다. 테이블은 일반적으로 다른 컬럼 집합으로 서브파티션됩니다. 부모 파티션과 다른 서브파티셔닝 유형을 가질 수 있습니다. 한 파티션을 서브파티션하면 각 파티션은 최소한 하나의 서브파티션을 가집니다.

테이블을 서브파티션하면 어떤 파티션 테이블에도 데이터가 저장되지 않습니다. 대신 데이터는 해당 서브파티션에 저장됩니다.
